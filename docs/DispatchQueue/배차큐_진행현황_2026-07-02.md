# 배차 큐 프로젝트 진행 현황 (2026-07-02)

## 목적
이 문서는 외부 AI/신규 참여자가 현재 배차 큐 프로젝트의 구현 범위와 남은 작업을 빠르게 파악할 수 있도록 작성되었다.

---

## 1. 현재 아키텍처 요약

- 원본 도메인 분리 유지
  - 화물: `화주운송의뢰`
  - 음식: `Hongdal.FoodApi`의 `음식주문`
- 공통 배차 엔진
  - 공통 큐 엔터티: `배차대기`
  - 공통 상태머신: 계획배차 → 배차추천 → 공개배차 → 확정
- 업무별 분리
  - `배차업무유형` 필드로 화물/음식 큐를 논리적으로 분리
  - 후보선정은 전략 패턴(`I배차업무정책`)으로 분기

---

## 2. 완료된 핵심 구현

### 2.1 큐 상태머신/전환
- `배차큐단계`, `배차노출상태` 상태 상수 도입
- `배차큐전환Service`에서 상태 전이 단일화
  - 추천시작/거절/만료/공개전환/확정 처리

### 2.2 추천/수락/거절 보강
- 추천 조회 필터 강화
  - 추천중 + 현재추천대상기사 + 업무유형(용달운송)
- 수락 처리 동시성 보강
- 거절 처리 시 재추천/공개전환 흐름 연결

### 2.3 Quartz + 추천 알림 아웃박스
- Quartz Job 도입
  - `배차큐스캔Job`
  - `추천만료정리Job`
  - `배차추천알림발송Job`
- 추천 알림 outbox 도입
  - 엔터티: `배차추천알림Outbox`
  - 서비스: `배차추천알림Service`
- FCM 추상화 도입
  - `IFcmPushService`
  - `FirebaseFcmPushService` (현재 ServerKey 기반)

### 2.4 업무유형 분리 기반
- `배차대기`에 아래 필드 반영
  - `배차업무유형`
  - `원본의뢰유형`
  - `원본의뢰Id`
- 화물 큐 생성 경로에 기본값 반영
  - `배차업무유형=용달운송`
  - `원본의뢰유형=CargoTransport`
- 전략 패턴 적용
  - 인터페이스: `I배차업무정책`
  - 구현체: `용달운송배차업무정책`, `음식배달배차업무정책(스켈레톤)`

## 3. 이번 반영: 음식 주문(FoodApi) → 배차 큐 생성 연동

요청 범위(1번 작업)만 우선 진행함.

### 3.1 연동 방식
- FoodApi에서 주문을 `배차대기` 상태로 전환하는 엔드포인트 추가
- 전환 시 Hongdal API의 배차대기 생성 엔드포인트를 HTTP 호출
- Hongdal 쪽 배차대기 생성 요청에 `배차업무유형=음식배달` 전달

### 3.2 추가/변경 파일

#### FoodApi
- `Hongdal.FoodApi/Options/배차연동Options.cs` (신규)
- `Hongdal.FoodApi/Services/I음식배차큐연동Service.cs` (신규)
- `Hongdal.FoodApi/Services/음식배차큐연동Service.cs` (신규)
- `Hongdal.FoodApi/Controllers/Common/음식주문Controller.cs`
  - `POST /api/v1/food-orders/{orderNo}/dispatch-wait` 추가
- `Hongdal.FoodApi/Services/음식샘플Store.cs`
  - `배차대기전환`, `음식점조회` 메서드 추가
- `Hongdal.FoodApi/appsettings.json`, `appsettings.Development.json`
  - `DispatchIntegration` 섹션 추가

#### Hongdal API
- `Hongdal.Contracts/Admin/Inbound/배차대기Dtos.cs`
  - `배차업무유형`, `원본의뢰유형`, `원본의뢰Id` 요청 필드 추가
- `Hongdal/Application/Admin/Inbound/Commands/배차대기생성Command.cs`
- `Hongdal/Application/Admin/Inbound/Commands/배차대기수정Command.cs`
- `Hongdal/Controllers/Admin/02_유입/배차대기Controller.cs`
  - 확장된 필드 전달
- `Hongdal/Application/Admin/Inbound/Handlers/배차대기생성CommandHandler.cs`
  - 중복 생성 방지(`의뢰Id` 기준)
  - 요청 기반 업무유형/원본필드 반영
- `Hongdal/Application/Admin/Inbound/Handlers/배차대기수정CommandHandler.cs`
  - 업무유형/원본필드 수정 지원

## 4. 운영/호출 가이드

### 4.1 FoodApi 설정
```json
"DispatchIntegration": {
  "Enabled": true,
  "BaseUrl": "https://localhost:5001",
  "DispatchWaitPath": "/api/v1/dispatch/wait"
}
```

### 4.2 음식 주문 배차대기 전환 호출
- `POST /api/v1/food-orders/{orderNo}/dispatch-wait`
- 성공 시 FoodApi가 Hongdal의 배차대기 생성 API를 호출

### 4.3 생성되는 큐 메타
- `배차업무유형 = 음식배달(10)`
- `원본의뢰유형 = FoodDelivery`
- `원본의뢰Id = 주문번호`

## 5. 현재 의도적으로 보류한 항목

요청에 따라 아래는 이번 범위에서 제외함.

1) 음식배달 정책의 실제 후보선정 로직 고도화
- 현재 `음식배달배차업무정책`은 스켈레톤(null 반환)

2) FCM payload의 `businessType` 기반 기사앱 상세 화면 분기
- 현재 앱 상세 분기 고도화는 미진행
