# 지도 신청 개인정보 동의 철회와 원장 보류

## 변경 요약

- 지도에서 시작해 제출된 물류대행·운송대행·개별 주문 신청 상세에서 본인 원장을 운영 신청 ID로 다시 찾습니다.
- 읽기 전용 텍스트 상자에 동의 철회의 영향, 운영 신청 자동 취소 금지, 최소 기록 보존과 운영 전 법률 검토 경계를 한국어·영어로 표시합니다.
- 사용자가 철회 영향을 확인한 뒤 동의를 철회하면 원장은 `보류` 및 `privacy-consent-withdrawn` 단계로 전환됩니다.
- 동의 철회는 기존 입고·운송·주문 신청을 자동 취소하거나 결제·계약·배차 효과를 만들지 않습니다.
- 개인정보 동의 철회 후 원장 갱신이 실패하면 운영 신청을 다시 제출하지 않고 원장 반영만 재시도하도록 안내합니다.
- 별도의 운영 신청 취소 패널에서 입고 예정 요청과 비구속 개별 주문 요청을 명시적으로 취소·철회한 뒤 원장을 `닫힘`으로 전환합니다.
- 운송 의뢰의 기존 사용자용 `DELETE`는 상태 취소가 아니라 물리 삭제이므로 화면에서 차단합니다. 대신 사용자가 취소 사유를 원장에 남기면 `transport-cancellation-review` 보류 상태가 되고, 서버관리자 전용 검토 목록에서 연결된 운송 의뢰 ID를 다시 확인해 승인 또는 거절합니다.
- 승인 시 기존 관리자 취소·환불 명령을 먼저 실행하고 성공한 뒤 공동 원장을 닫습니다. 이 명령은 현재 `SsalddelExecution:Mode=Simulation`에서만 허용되며 외부 PG 호출이나 물리 삭제를 하지 않습니다. 거절 시 운송 신청과 운영 인계를 유지합니다.
- 관리자 승인 명령과 원장 결과 기록은 동일 요청 재시도에서 이벤트나 원장 Revision을 중복 생성하지 않도록 멱등 경계를 둡니다.

## 화면 확인

- 간접 확인: `Ssalddel.v3.5.slnx` 빌드와 관련 테스트로 Razor 계약과 세 상세 화면 연결을 확인했습니다.
- 실제 화면은 인증된 사용자, MongoDB 원장 및 연결된 운영 신청 fixture가 함께 필요한 상태여서 이번 작업에서는 PNG를 만들지 않았습니다.
- 운영 전에는 한국어·영어 전환, 철회 성공, 부분 실패 후 재시도, 원장이 없는 일반 신청에서 패널이 숨겨지는 상태를 브라우저로 확인해야 합니다.
- 입고 취소와 개별 주문 철회는 재시도 가능하도록 멱등 경계를 검증했으며, 실제 인증·DB 연동 화면 검증은 남아 있습니다.
- 관리자 검토는 일반 사용자 WebApp의 중복 페이지가 아니라 `SsalddelAdmin`의 기존 `/admin/freight-delivery/requests` 목록과 `/requests/{RequestId}` 상세에 병합했습니다. 목록에서 사용자 취소 사유와 공동 원장 Revision을 확인하고, 상세에서 승인·거절한 뒤 운송 원장과 공동 원장을 다시 조회합니다.
- 서버관리자 인증, MongoDB 공동 원장, RDB 운송 fixture를 함께 둔 브라우저 검증은 남아 있습니다.

## 검증 경계

- 법적 문구는 제품 검토 초안이며 법률 자문이나 준수 인증이 아닙니다.
- 실제 파기·보존 집행, 정보주체 권리 처리 및 신청별 취소 절차는 별도 운영 검증이 필요합니다.
- Operational 모드의 실제 결제 취소·환불 연동은 아직 열지 않았으며, 해당 모드에서는 관리자 승인 명령이 실패하고 공동 원장도 승인 완료로 전환되지 않습니다.
