# 공식 재료별 대표 레시피 관계

## 변경 요약

| 변경 | 시각 영향 | 확인 |
| --- | --- | --- |
| 표준 재료 조회 응답에 실제 사용 관계에서 고른 대표 레시피를 최대 3개 포함 | 화면 없음 — 관리자 재료 API의 `RelatedRecipes` 계약 확장 | 관련 단위 테스트와 서버 빌드로 간접 확인 |
| 저장된 표준 재료·공공가격·대표 레시피를 공개 읽기 API로 제공 | 화면 없음 — `GET /api/v1/agricultural-fisheries/food-ingredients` 추가 | 공개 route 특성 테스트와 서버 빌드로 간접 확인 |
| 공개 재료 검색 client/ViewModel과 공동구매용 안전한 deep-link seed 추가 | 간접 확인 — 실제 컴포넌트 렌더링은 후속 시각 검증 커밋으로 분리 | query 인코딩·50건 상한·비HTTP URL 제거·초안 문구 테스트 |

## 선택 규칙

1. 원천에서 제거되지 않았고 음식 검토 상태가 `Excluded`가 아닌 실제 재료 사용 행만 후보로 삼는다.
2. 승인된 음식, 대표 음식, freshness가 유효한 레시피, 최근 수집 레시피 순으로 우선한다.
3. 같은 음식의 출처별 변형만 연속해서 보이지 않도록 서로 다른 음식을 먼저 최대 3개 고른다.
4. 서로 다른 음식이 3개 미만이면 아직 선택하지 않은 실제 레시피 변형으로만 보충한다.
5. 실제 관계가 3개 미만이면 있는 만큼만 반환하며 유사 재료나 같은 분류의 레시피를 추정하지 않는다.

각 관계에는 음식·레시피 Key, 원천과 제공기관, 국가·지역·분류, 원천 재료명·묶음·수량·단위·손질 메모, 원문 URL, 최근 수집 시각과 freshness를 포함한다.

공개 API는 DB에 이미 보관된 값을 최대 50개까지 읽을 뿐 외부 공공 API 수집이나 분류·가격 매핑을 실행하지 않는다. 정확한 공공가격 매핑이나 실제 레시피 사용 관계가 없으면 해당 목록은 비워 둔다.
