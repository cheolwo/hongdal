# 기사 운송대금 지급 준비 API

## 결과

- 화주 운송 의뢰의 `기사지급예정운임`을 `운임구성.driver_expected_payout`에 별도 저장한다.
- 화주가 결제하는 최종운임과 기사에게 지급하기로 한 예정 운임을 같은 금액으로 추정하지 않는다.
- `GET /api/v1/driver/payout-preparations?year={year}&month={month}`에서 기사 본인의 월별 완료 운송만 조회한다.
- 운송 완료 시각은 `운송실행투영.도착`을 기준으로 고정한다.
- 지급 준비 상태는 원천 의뢰, 기사 지급 예정 운임, 현장수금 여부, 화주 수납 상태, 기사 정산계좌 등록·확인 상태를 순서대로 검증한다.
- 화주 결제 완료는 기사 지급 완료로 표시하지 않고 `ReadyForPayoutPreparation`까지만 표시한다.
- 현장지급은 플랫폼 지급 대상과 분리하고 현장수금 확인 금액으로 별도 합산한다.
- 지급 예정 운임이 없으면 화주의 결제예정금액이나 최종운임으로 대체하지 않고 `ExpectedPayoutMissing`으로 표시한다.
- 현재 API는 읽기 전용이며 실제 송금·자동 지급 효과를 발생시키지 않는다.

## 화면

- 화면 없음 — 이번 변경은 서버 계약, 지급 준비 조회 UseCase, 운임 영속화와 테스트만 포함한다.
- `DriverApp`과 `FDriverApp`은 수정하지 않았다.

## 검증

- 기사 본인·월별 완료 운송만 조회하는지 확인한다.
- 화주 수납 완료와 기사 지급 완료를 구분하는지 확인한다.
- 확인된 정산계좌, 미확인 계좌, 현장수금, 지급 예정 운임 누락 상태를 각각 검증한다.
- MySQL 마이그레이션 `AddDriverExpectedPayoutFare`는 `운임구성`에 nullable 기사 지급 예정 운임 컬럼 하나만 추가한다.
