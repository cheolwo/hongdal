# 공동구매 비구속 수요 수명주기

## 목적

`1.0 공동구매·주문자 집단화`에서 로그인 사용자가 같은 재료·배송권 수요를 안전하게 등록·변경·철회하고, 서버가 그 결과를 결정적 집단에 반영하도록 첫 실행 단면을 완성합니다.

## 구현

- 공개 자동집단 목록 `GET /api/v1/orderer/group-purchase-auto-groups`는 익명 탐색을 허용하되 집계 정보만 반환합니다.
- 인증된 비구속 수요 저장은 `PUT /api/v1/orderer/group-purchase-auto-groups/demands/{demandSourceKey}`를 사용합니다.
- 인증된 비구속 수요 철회는 같은 자원 경로의 `DELETE`를 사용합니다.
- 두 변경 명령은 `Idempotency-Key`를 필수로 사용하고, 경로의 수요출처키와 인증 사용자를 서버가 덮어씁니다.
- 같은 수요의 최근 명령 이력을 Mongo 문서에 최대 32건 보존해 같은 키·같은 입력은 재실행하지 않고, 같은 키·다른 입력은 거부합니다.
- 철회된 수요는 집단 참여자 수·희망 수량·목표 계산과 공개 응답에서 제외합니다.
- 수요출처키 조회를 위한 Mongo 멀티키 인덱스를 추가했습니다.

## 1.0 실행 경계

- 비구속 저장은 클라이언트가 결제·주소·창고 값을 보내도 관심 수요와 미결제 상태로 정규화합니다.
- 수령 주소, 결제 금액, 창고와 입고 원장은 생성하거나 공개하지 않습니다.
- 이미 결제 또는 주문 원장에 연결된 수요와 확정된 공동구매는 이 철회 API로 취소하지 않습니다.
- 철회는 주문·계약·수입 신고·운송 의뢰·배차를 발생시키지 않습니다.

## 검증

- 공동구매 유스케이스·Controller·집단화 Engine·멱등 정책·버전·미국 판매 화면 관련 회귀 테스트 108개 통과
- `Ssalddel` 서버 빌드 경고 0개·오류 0개
- 화면 변경 없음 — 서버 API와 Mongo 문서 경계만 변경
