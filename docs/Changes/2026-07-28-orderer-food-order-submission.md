# 주문자 공개 메뉴 기반 음식 주문 제출

- 날짜: 2026-07-28
- 대상: `OrdererApp`, 음식 주문 contract·Command·RDB 원장
- 화면 확인: Windows MAUI 직접 실행 실패, 코드·빌드 간접 확인

## 변경

- 음식점 공개 상세의 메뉴마다 수량을 선택할 수 있게 했다.
- 로그인 주문자는 수령인, 연락처, 배달 주소, 상세 주소와 전달 요청사항을 입력해 음식 주문을 제출한다.
- 등록 성공 뒤 서버가 반환한 정확한 주문번호를 사용해 `/orders/food?orderNo=...` 상세로 이동한다.
- 현재 결제 방식은 `현장결제` 메모만 저장한다. 온라인 결제 승인이나 결제 완료 상태를 만들지 않는다는 경계를 화면에 표시한다.

## 서버 신뢰 경계

- 주문 항목은 공개 메뉴 ID와 수량을 기준으로 받는다.
- 검증한 공개 메뉴 ID를 RDB 음식 주문 상품 스냅샷에도 저장한다.
- 서버가 음식점 공개·주문 가능 여부, 메뉴 소속·공개·품절 여부를 다시 확인한다.
- 메뉴명, 단가, 총 주문 금액과 최소 주문 충족 여부는 서버의 최신 공개 메뉴 가격으로 계산한다.
- 클라이언트가 보낸 메뉴명과 단가는 주문 금액의 근거로 사용하지 않는다.
- 주문자와 `클라이언트요청Id`의 고유 인덱스를 추가해 같은 제출 재시도가 새 주문을 만들지 않게 했다.

## 실제 화면 확인 제한

빌드 산출물의 `OrdererApp.exe`를 실제 Windows 창으로 실행했다. `살뜰 주문`
창은 열렸지만 Hybrid WebView 본문이 흰 화면으로 남아 새 주문 작성 화면을
직접 확인하지 못했다. 따라서 대표 PNG를 저장하지 않았고 화면 변경을
배포 가능 렌더로 판정하지 않는다.

다음 검증에서는 Orderer Hybrid 시작 경로의 흰 화면 원인을 먼저 분리한 뒤,
별도 실제 DB와 테스트 계정으로 공개 메뉴 조회→주문 제출→주문번호 상세
재조회까지 확인해야 한다.
