# DbContext 경계와 입고 수명주기 리팩터링

## 변경 범위

- 중앙 `SsalddelContext`가 농수산물·전통시장 전용 Context 구성을 다시 가져오지 않도록 소유권 표식을 추가했다.
- 커뮤니티 게시글 aggregate의 FK와 삭제 정책을 런타임 모델 테스트로 고정했다.
- 입고요청·입고상품·재고이력·재고이동을 서로 다른 수명주기의 scalar 원장 참조로 문서화하고 `입고상품.입고요청Id`, `(재고이동.입고상품Id, 발생일시)` 조회 index를 추가했다.
- 입고 완료의 상태 변경, 입고상품, 최초 재고이력과 재고이동을 한 transaction으로 묶고 동일 내용 재시도를 멱등 처리했다.
- 입고상품 수령 PageViewModel을 공통 페이지 상태로 전환해 창고·정확한 입고 ID 조회 실패와 취소를 준비 완료로 숨기지 않게 했다.
- 입고 검수를 serializable transaction과 수량·불량·메모의 정확한 멱등 판정으로 보강하고, 예약 수량보다 정상 수량이 작아지는 검수 결과를 거부한다.
- 입고 검수 PageViewModel도 공통 페이지 상태로 전환해 최초 목록·정확한 입고상품 ID 실패와 취소를 일관되게 표시한다.

## 화면 변화

간접 확인 — 수령·검수 정상 화면의 배치와 문구는 유지한다. 초기 진입 조회가 실패할 때 무한 loading 대신 기존 오류 영역과 다시 조회 동작을 표시한다.

## 검증

- EF Core Context 소유권·커뮤니티 관계·입고 scalar 참조 모델 테스트
- 입고 완료 동일 요청 재시도·다른 내용 거부·두 번째 저장 실패 rollback 테스트
- 입고상품 수령·검수 PageViewModel 성공·목록/창고 실패·정확한 ID 없음·재시도 복구 상태 테스트
- 입고 검수 동일 요청 재시도·다른 메모 거부·예약 수량 보호·감사/Event 중복 방지 테스트
- 세 Context migration drift 검사
