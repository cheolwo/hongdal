# FDriver 추천 응답성과 주소 공개 경계

## 결과

- FDriver 업무 화면이 앱에 보이는 동안 SignalR로 배차 알림을 즉시 받고, 연결 지연이나 끊김에 대비해 업무공간을 30초마다 보조 조회한다.
- 저장된 갱신 토큰으로 앱 재진입과 API 요청 직전 액세스 토큰을 자동 갱신하고, 서버 `401` 응답에도 강제 갱신 뒤 한 번만 다시 요청한다.
- 운행 중에는 2분마다 기사 위치를 서버에 보내 오래된 위치 때문에 추천 후보에서 빠지는 상황을 줄인다.
- 추천 카드에 응답 만료 카운트다운과 거절 행동을 추가하고, 만료된 추천은 수락할 수 없게 했다.
- 진행 중 배달이 여러 건이면 선택한 배달을 유지하고 지도 마커나 진행 배달 목록에서 작업 대상을 바꿀 수 있다.
- 로그아웃 전에 서버의 추천 대기를 먼저 종료하며, 서버 종료가 실패하면 유령 대기 상태를 남기지 않도록 로그아웃을 보류한다.
- 자동 배차 배치가 실행 가능한지 `Operational` 모드와 국내 운송 기능 플래그를 기준으로 업무 화면에 알린다.
- 추천 전에는 고객 전달지를 행정 권역과 약 1km 좌표로 축약하고, 기사 수락 뒤에만 전체 주소와 정밀 좌표를 반환한다.
- 기사 수락 뒤 진행 업무에는 실제 수령자 이름·연락처·전달 요청을 연결하되 추천 카드에는 수령자 개인정보를 싣지 않는다.
- 전체 후보 검색 반경뿐 아니라 기사 본인이 설정한 음식점 접근 반경도 실제 후보 판정에 적용한다.

## 화면 확인

간접 확인이다. `FDriverApp` Windows 대상 XAML과 코드 빌드는 오류 없이 완료했지만, 인증된 기사 계정과 실제 추천 원장이 준비된 실행 환경이 없어 추천 카드·카운트다운·다건 진행 배달을 실제 렌더링한 PNG는 만들지 않았다. 샘플 데이터로 성공 화면을 대체하지 않았다.

## 검증

- `FDriverApp` Windows 대상 빌드: 경고 0개, 오류 0개
- FDriver 화면 구성·실시간 수신·주소 공개 경계 대상 테스트: 25개 통과
- `eng/validate-changes.ps1 -Level Fast`: 통과
- `eng/validate-changes.ps1 -Level Task`: 통과
