# 게시판별 공공데이터·조사 관계 카탈로그

## 변경

- 일반·업무·보호 게시판 전체에 공공데이터, 공식 조사와 내부 공개 투영의 관계를 안정 key로 연결했다. YouTube는 이 관계와 배치 계획에서 제외했다.
- 각 관계에 제공기관, 원천 종류, connector 구현 상태, 갱신 주기, 배치 상태와 소유 모듈, 게시 정책, 사용 목적과 한계를 기록했다.
- 배치 상태를 `scheduled`, `ready-to-schedule`, `on-demand`, `not-applicable`, `planned`로 분리해 구현된 connector와 연계 예정 원천이 섞이지 않게 했다.
- `정보·시세`에 KAMIS·USDA NASS·식약처 중국/미국 수입식품 누적·관세청 HS·전통시장 관계를 연결했다.
- 모집·판매·화물 관계는 참고 전용으로 두고 자동 모집·상대 선택·배차·계약·가격 확정을 금지했다.
- `서원`, `개선 제안`, 보호된 `신고·분쟁`은 연결 원천이 없다는 사실과 수집 금지 경계를 명시했다.
- 기존 16개 업무 게시판 편집 계획은 새 관계 카탈로그에서 파생하도록 바꿔 두 기준이 어긋나지 않게 했다.
- 서버관리자가 `GET /api/v1/admin/content/information/board-relations`에서 전체 또는 `boardKey`별 관계를 조회할 수 있게 했다.
- 실제 반복 모듈이 있는 관계만 `PeriodicBatchPlans()`로 원천·소유 모듈당 한 번 얻고, 연결 게시판과 발행 Source를 함께 반환하도록 했다. 이 목록은 배치 등록 입력이며 실행·게시 설정을 자동으로 켜지 않는다.
- 서버관리자는 `GET /api/v1/admin/content/information/board-relations/batch-plans`에서 반복 배치 계획을 조회할 수 있다.
