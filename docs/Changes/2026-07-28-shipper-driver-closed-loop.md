# 화주·용달기사 운송 폐쇄 루프 보완

- 날짜: 2026-07-28
- 화면 확인: 간접 확인
- 대상: `SsalddelApp` 화주 운송 업무, `DriverApp` 추천 목록·진행 중 운송

## 변경

- 화주 운송 목록과 기사 추천·진행 화면이 공통 30초 보완 조회 정책으로 서버 원장을 다시 확인한다.
- 일시적인 화주 목록 조회 실패 시 마지막 정상 결과를 유지한다.
- 기사 앱은 Access Token 만료 전 Refresh Token으로 갱신하고, API가 401을 반환하면 한 번 갱신한 뒤 같은 요청을 다시 보낸다.
- 진행 중 운송 화면은 고정 전화번호 대신 배정된 운송 의뢰의 실제 수령자명·연락처·전달 요청을 사용한다. 요약 영역에서는 전화번호를 마스킹하고 민감 정보 펼침 영역에서만 전체 값을 표시한다.
- 완료된 운송은 진행 중 운송 카드에서 제외한다.
- 화주 상세는 배차 확정 뒤 운송원장의 현재 상태, 배정 기사명·차량, 진행 중인 운송의 최근 기사 위치와 기록 시각을 표시한다. 운송 종료 뒤에는 마지막 위치 좌표를 반환하지 않는다.
- 인증된 화주·기사 사용자 전용 SignalR 그룹으로 결제·배차 수락·상차·하차·인수 완료와 기사 위치 갱신을 알리고, 수신 앱은 같은 의뢰 ID를 즉시 서버에서 다시 조회한다.
- 실시간 연결이 끊겨도 기존 30초 보완 조회는 유지한다.
- 화주 앱도 Access Token 만료 전 Refresh Token으로 갱신한 뒤 API와 실시간 연결을 시작한다.
- 서버관리자 계정은 별도 관리자 SignalR 그룹으로 모든 운송원장 변경을 수신하고, 모바일 운영 개요·운송 관제 화면이 즉시 서버를 다시 조회한다.
- 기사 위치가 10분 이상 갱신되지 않으면 지연 상태와 경고를 표시하며, 경로·교통 정보가 없는 상태에서 ETA를 임의 계산하지 않는다.
- 기존 운송 상태 Push Outbox의 수신자는 업무상 화주 ID보다 인증된 `주문자UserId`를 우선해 실제 모바일 설치 토큰과 연결한다.
- 화주 앱에 공통 Push 설치 등록 client를 연결했다. Firebase 토큰 공급자가 없는 현재 설정에서는 서버를 호출하지 않고 안전하게 건너뛰며, Android Firebase 설정이 제공되면 같은 공통 설치 endpoint를 사용한다.

## 함께 보완한 서버 경계

- FakePG 결제도 실제 결제와 같은 결제승인완료 Outbox를 생성한다.
- 일반 사용자가 요청 본문의 다른 `화주Id`로 의뢰를 만들 수 없도록 인증 사용자 기준으로 소유권을 고정한다.
- 배차 수락 시 기사 운송 진행 정보와 화주 배차 상태를 핵심 상태 변경과 함께 저장한다.
- 운송 상태 Event 후처리가 실패해도 화주 RDB 원장은 기사 운송 상태와 함께 갱신된다.
