# 독립 판매자 앱의 서버 원장 기반 업무 흐름

## 결과

- 기존 `SsalddelApp`의 화주·판매자 혼합 화면과 별도로 `SellerApp` MAUI Blazor Hybrid 프로젝트를 추가했다.
- 앱의 판매채널·판매상품·채널 출품·판매 주문은 `Ssalddel.Ui.Common`의 서버 API Client와 공통 원장 컴포넌트를 사용하며 `InMemoryShipperStore`를 사용하지 않는다.
- 판매자·화주·서버관리자 역할을 확인하는 로그인, 보안 저장소의 access·refresh token 복구와 시작 시 자동 갱신을 연결했다.
- 기존 `OperatingMarketProfileCatalog`를 재사용해 대한민국과 미국 시장의 통화·중량·거리 단위와 선호 판매채널을 구분한다.
- 홈에서 `판매 페이지 → 판매채널 → 판매 가능 재고 → 판매상품 → 채널 출품 → 판매 주문`의 사용자 여정을 한 흐름으로 보여 준다.
- 판매 주문은 서버에 영속된 출고 후보만 읽고 앱이 열려 있는 동안 30초마다 보완 조회한다.
- 외부 채널 자격증명은 서버 암호화 저장까지 지원한다. 상품 발행과 실제 주문 수집은 채널 adapter가 구현·활성화되기 전에는 실행하지 않는다.

## 화면 확인

간접 확인이다. Windows MAUI 앱을 실제로 실행해 접근성 렌더 트리에서 판매자 홈의 전체 업무 단계, KR·KRW 시장 표시, 하단 탐색과 판매자 로그인 화면 전환을 확인했다. 현재 Windows Graphics Capture에서는 WebView2 표면이 흰색으로 캡처되어 개인정보가 없는 대표 PNG를 장기 보존하지 않았다.

## 검증

- `SellerApp` Windows 대상 빌드: 경고 0개, 오류 0개
- `SellerApp` Android 대상 빌드: 경고 0개, 오류 0개
- 판매자 앱 구성·서버 공용 판매 모듈·운영시장·인증 경계 조립 테스트
- 실제 Windows 앱 실행과 홈·로그인 화면 접근성 트리 확인
