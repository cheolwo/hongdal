# 창고 범위의 읽기 전용 재고 현황

커밋 상태: 미커밋

## 변경 기록

| 변경 축 | 화면 변경 여부 | 결과 |
| --- | --- | --- |
| 재고 접근 범위 | 화면·서버 변경 | 상품 소유자·판매자 여부가 아니라 창고 소유자 또는 배정 사용자 범위만 조회 |
| 최소 목록 계약 | 화면·서버 변경 | 사용자 ID와 계약·정산 내용을 제외하고 상품·수량·위치·원장 연결 여부만 반환 |
| 정확한 상세 | 화면·서버 변경 | 사용자가 고른 `inboundItemId` 한 건의 입고·보관·주문 참조·공동 원장 근거만 재조회 |
| 단일 책임 분리 | 화면·구조 변경 | 목록·집계, 정확한 상세, 페이지 선택 조정, host 인증/capability를 각각 분리 |
| 실행 경계 | 화면 변경 | 재고 차감·이동·판매·운송·결제·정산을 수행하지 않는 `Beta/ReadOnly` 경계 표시 |

개발용 상품명·SKU·주문 참조와 창고명만 포함하며 실제 사용자 ID, 주소, 연락처, 계좌, 결제 식별자와 계약·정산 내용은 포함하지 않았습니다.

## 브라우저 검증

- 개발 계정 `shipper1` 로그인과 창고관리자 역할 판정 성공
- 접근 가능한 서버 재고 2건, 가용 125개, 예약 24개, 위치 미배정 0건 집계 확인
- 첫 항목 자동 선택 없이 상세 선택 안내 표시
- 선택한 `inboundItemId=1`이 URL query와 상세에 동일하게 표시
- `V1-DEV-LIVING-BOX` 검색 뒤 목록 1건, 가용 96개, 예약 20개로 서버 집계 재계산
- browser console 경고·오류 0건

## 검증

- 창고 소유·배정 범위와 범위 밖 404
- 검색·상태 필터와 동일 조건 서버 집계
- 첫 목록 항목 자동 선택 금지와 URL의 정확한 ID 상세 조회
- 재고 관련 capability·공용 DI 포함 집중 테스트 76개 통과
- `Ssalddel`, `Ssalddel.Ui.Common`, `Ssalddel.WebApp`, `WarehouseManagerApp`, `SsalddelAdminApp` 빌드 경고 0개·오류 0개
- 전체 테스트 1,837개 통과
