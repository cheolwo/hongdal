# 01~05 Operational API 세로 슬라이스

## 변경

- 서버와 Azure 버전 조립의 기본 실행 모드를 `Operational`로 전환했다.
- Operational 시작에는 기존과 동일하게 Toss 비밀키를 요구하며 키를 source에 저장하지 않는다.
- 주문자 공동구매 상품 후보를 서버 Catalog UseCase와 Controller에서 조회한다.
- 화주 판매채널 주문 화면이 서버 동기화 Command 후 같은 출고 원장을 다시 조회한다.
- 기사 알림함이 배차추천 알림 원장과 읽음 시각을 서버에서 조회·변경한다.
- 창고 작업자 진입은 서버 HR 역할, 입고 수령과 피킹은 `warehouse-operations` 원장을 사용한다.
- 클라이언트의 샘플 fallback 기본값을 비활성화했다.

## 화면 확인

- 주문자 상품 목록, 화주 판매채널 동기화, 기사 알림함, 창고 입고·피킹 화면의 데이터 경계가 변경됐다.
- 이번 변경의 컴파일과 route/API 조립은 자동 테스트로 확인했다.
- 인증된 운영 계정과 외부 판매채널 자격 증명이 필요한 실제 화면 캡처는 아직 수행하지 않았다.

## 운영 주의

- `Operational`은 외부 효과를 허용하므로 배포 환경에서 Toss, 판매채널, 데이터 보호와 JWT 비밀값을 먼저 주입해야 한다.
- 판매채널 동기화는 계정별 `ISalesChannelOrderFeedClient` 공급자 구현과 자격 증명이 없으면 가져올 주문이 없다.
- 기사 알림 읽음 상태용 `read_at` 마이그레이션을 배포 전에 적용해야 한다.
