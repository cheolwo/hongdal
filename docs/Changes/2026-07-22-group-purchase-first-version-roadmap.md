# 공동구매 우선 제품 버전 재정렬

## 결정

제품 버전의 업무 순서를 다음과 같이 변경했습니다.

| 버전 | 변경 전 | 변경 후 |
| --- | --- | --- |
| `1.0` | 국내 화물·용달 | 공동구매·주문자 집단화 |
| `1.5` | 창고·판매 물류 | 공급·가격·무역 준비 |
| `2.0` | 통관·HS | 국내 화물·운송 이행 |
| `2.5` | 공동주문·같이 수입 | 창고·판매 이행 |

`0.0` 커뮤니티·공공데이터 기반과 `3.0` 음식 배달, `3.5` 마트·도심 물류는 유지합니다.

## 이유

운송 역량을 먼저 확장하기보다 실제 구매 의사가 모이고 공급·비용·무역 조건이 확인된 뒤 운송으로 넘기는 편이 제품 흐름과 사업 검증 순서에 맞습니다.

## 코드 반영

- `SsalddelProductRoadmapCatalog`를 제품 순서의 단일 계약으로 추가했습니다.
- 공동구매 자동집단화·수요·운영 주체 API를 `1.0`으로 분류했습니다.
- 공급·HS·같이 수입 준비 API를 `1.5`로 분류했습니다.
- 화주 운송·Driver·배차·증빙·정산 API를 `2.0`으로 분류했습니다.
- 창고 작업 API를 `2.5`로 분류했습니다.
- 대표 페이지 capability와 서원 버전 카탈로그를 같은 순서로 맞췄습니다.

## 호환성

- HTTP `/api/v1/...` route는 변경하지 않습니다.
- 기존 원장·요청 ID와 DB 스키마는 이번 재분류로 변경하지 않습니다.
- `CargoYongdalV1`, `WarehouseV15`, `CustomsHsV20`, `OrdererGroupOrderV25` 등 기존 설정 키는 호환 별칭으로 유지합니다.
- 신규 설정과 문서에는 버전 중립적인 workflow 키를 사용합니다.

## 화면

화면 구조 변경 없음. 버전 표시와 현재 개발 우선순위가 변경됩니다.
