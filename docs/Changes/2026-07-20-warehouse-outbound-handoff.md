# 포장 완료 재고를 잇는 출고 인계 준비

## 변경

- 기존 `/warehouse/general/transport-handoff`의 직접 운송 생성 폼을 출고예정 원장 준비 페이지로 교체했다.
- 목록, 정확한 `inboundItemId` 상세, 인계 준비 Command, 완료 후 같은 ID 재조회 책임을 분리했다.
- 창고 소유자 또는 배정 사용자 범위의 `포장완료-*` 재고만 조회·처리한다.
- 전체 가용수량, 포장 봉인과 운송 조건을 확인하면 기존 `출고예정` 원장을 `출고준비중`으로 한 번만 기록한다.
- 동일 수량 재시도는 멱등 처리하고 부분 인계 및 준비 완료 뒤 수량 변경은 별도 조정 업무로 분리한다.
- 기존 범용 재위탁 API는 호환성을 위해 유지하되 새 페이지에서는 호출하지 않는다.
- `Beta / Simulation` 경계에서 재고 예약·차감, 운송의뢰, 배차, 하차지·차량, 결제, 정산을 실행하지 않는다.

## 실제 확인

- `shipper1` 로그인
- 입고상품 `#1` 검수·적재·냉장포장 완료 후 출고 인계 준비 실행
- 출고예정 원장 `출고준비중` 생성과 같은 `inboundItemId=1` 재조회
- 가용 29개·예약 4개 유지
- 브라우저 콘솔 오류 없음
- 검증 뒤 개발 시드 재실행으로 초기 상태 원복, 테스트 서버 종료
