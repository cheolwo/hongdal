# 음식·화물 공통 운송 실행 프로필

## 결과

- 기존 RDB `운송원장`을 공통 운송 실행 투영으로 유지했다.
- `배차업무유형`과 `원본의뢰유형`에서 음식점 음식 배달, 마트 라스트마일, 일반 화물, 창고 출고 화물, 같이 주문 국내 배송, 같이 수입 국내 인계 상세 프로필을 파생한다.
- 배차대기·추천·수락·이동·완료 생명주기는 공유하되 조리 상태, 화물 제원과 창고 선행 작업 필요 여부는 상세 프로필로 분리했다.
- 일반 기사 추천과 음식 배달 업무공간 응답에 같은 실행 프로필을 포함했다.
- `DriverApp`과 `FDriverApp`은 고정된 픽업·전달 문구 대신 서버 프로필의 행동 용어를 사용한다.
- 기존 원장 DB schema와 `원본의뢰유형` 호환값은 변경하지 않았다.

## 역할별 용어

| 상세 유형 | 픽업 행동 | 완료 행동 |
| --- | --- | --- |
| 음식점 음식 배달 | 음식점 픽업 | 고객 전달 |
| 마트 라스트마일 | 포장 상품 픽업 | 주문 전달 |
| 일반 화물 | 화물 상차 | 화물 하차 |
| 창고 출고 화물 | 출고 화물 상차 | 화물 하차 |
| 같이 주문 국내 배송 | 공동 주문 화물 상차 | 집결지·세대 인계 |
| 같이 수입 국내 인계 | 보세·창고 화물 상차 | 국내 목적지 인계 |

## 화면 확인

간접 확인 — `DriverApp`과 `FDriverApp`의 음식 배달 화면이 공통 contract의 `픽업행동명`, `완료행동명`을 소비하도록 변경하고 `Ssalddel.v3.5.slnx` 조립 빌드로 두 앱의 컴파일 호환성을 확인했다.

이번 변경에서는 실제 기기나 Windows 화면을 새로 캡처하지 않았다. 다음 실제 렌더 검증에서는 인증된 음식 배달 추천의 `음식점 픽업/고객 전달` 문구와 일반 화물 추천의 `화물 상차/화물 하차` 문구를 각각 확인해야 한다.
