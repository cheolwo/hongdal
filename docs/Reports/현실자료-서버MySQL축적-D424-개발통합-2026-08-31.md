## 개발 서비스 변경

동일 내용의 입수 시각만 바뀌면 기존 행/원문/입수 시각/SourceSetHash를 덮거나 새 판본을 만들지 않는다. 기존 SourceSetHash 산식과 과거 저장값을 유지하고, 내용 비교에만 입수 시각을 제외한 별도 내부 fingerprint를 사용한다. A→B→A는 과거 A행으로 돌아가지 않고 세 번째 내용 판본으로 보관한다. 별도 재관측 사건 기록은 이번에 추가하지 않았다.

감자 StableId·작업군210005·콘텐츠30699·Unlinked 품목 관계, 원천 hash/상태를 확인하며 손상/거부 자료를 자동 승인하지 않는다. 최신 자료가 보류/거부이면 과거 승인본으로 fallback하지 않는다. 승인 조회는 추적 없는 읽기다. 이 검사는 현실 자료의 검토/보관 경계이며 게임 규칙·품목 관계·효능·E 승격이 아니다.

## 초기 코드 검증 당시 조건 — 위 r6 실행 전 이력

현재 실행환경에서 `SSALDDEL_TEST_MYSQL_CONNECTION`의 존재만 확인했고 미설정이었다. 연결 문자열/비밀값 내용은 읽지 않았다. 기존 인프라 시험은 미설정이면 return하므로 그것을 MySQL 성공으로 사용하지 않았고 실행하지 않았다. 다른 호스트/비밀저장소 전체에 설정이 없다는 뜻은 아니다.

다음 실행 전 개발이 정확한 격리 AgriculturalFisheries 시험 DB·스키마 준비 상태, 승인 관리자 실행주소/인증, 농사로 자격의 안전설정 및 Profile+재해 조회 범위를 결속해야 한다. 보류 자료의 저장 확인은 승인 GET을 완화하지 않고 내부 읽기 전용 검증 경계로 별도 결속한다. 이후 자료 담당이 작은 실제 수신→저장→새 조회 문맥의 재조회→동일 내용 재수집 중복 방지를 수행한다. 환경 미설정을 보고서 완료로 대체하지 않으며, 운영 DB를 시험용으로 추정하거나 자동 마이그레이션하지 않는다.

식약처는 별도 공급원이다. 사용자가 노출된 기존 키의 계속 사용을 선택했으므로 재발급을 필수 조건으로 유지하지 않는다. 그러나 과거 노출 위험이 제거된 것은 아니며, 전용 옵션/안전 입력·실행 범위가 결속되기 전 키 탐색/전달/임의 공용키 덮어쓰기/호출은 하지 않는다. 이번 농사로 검증에 식약처 브라우저 성공을 사용하지 않았다.

D422 공간 슬롯은 미실행 대기 그대로 반환된 뒤 소비 빌드를 시작했다. D422 새 baseline/Observe/Play, Unity/Scene/Save/운영 DB/외부 호출/정기대량수집/commit/push는 이번 검증에서 모두0이다.
