# 누적 변경 정합화와 맥락별 커밋

- 요청: D448. 누적 작업의 변경된 기준·책임·구현을 검토하고 필요한 리팩토링 뒤 맥락별로 커밋한다. 푸시는 요청하지 않았다.
- 범위: Hongdal과 연계 Unity 저장소의 소유가 확인된 기존 변경. 새 게임 기능·권위 규칙·실행 E·운영 데이터·Scene 일괄 저장은 포함하지 않는다.
- 상태: 검토 범위의 정합화·검증·커밋 분류 완료. 이 문서를 포함하는 마지막 통합 커밋까지 Hongdal 11개와 Unity 2개로 나눈다. 아래 시작 기준선과 최종 결과를 구분한다.

기획은 문서 기준·Git 분류와 최종 stage/commit을 소유하고, 개발은 코드·시험·생성물 정합화의 정확 경로와 전문 담당의 소유를 확인한다. 진행 중인 실행은 안전 경계에서 조율하며 강제 종료·저장/폐기·DB/Provider 실행은 하지 않는다. 기존 파일은 사용자 또는 다른 담당의 변경으로 취급하며 소유 미확인·혼합 변경은 별도 보존한다.

## 확인한 정합화

- README의 ‘10개 질문 기본’을 D398의 단일 질문 심화로 정정하고 D447 E6 공식 절차의 단일 기준으로 연결한다.
- 문답 정밀화 체계의 잔존 `Active` 최대 하나 문구를 현행 Goal 운영 체계의 비중첩 병렬·실제 의존성 조율로 정합화한다. 대기 WI 자동 활성화는 하지 않는다.
- 코드/검색/생성물은 담당의 대조 결과와 원 시험 결과를 인수해 정합화했다. 과거 승인 hash를 일괄 치환하거나 실패한 검사를 완화하지 않았다.
- 개발은 중복된 SHA256 형식 검사를 기존 공통 검사로 모으고 모델의 PK/FK/고유 인덱스 생성 회귀를 추가했다. 현재 원문과 다른 공간 관계·조회 제목을 정합화하며 과거 결정과 실제 실행 상태는 구분한다.
- 구판 두 명세는 외부 사본의 검사를 먼저 통과시킨 뒤 `protocolRevision` 한 필드씩만 r4→r5로 갱신했다. E·승격·계획 내용을 바꾸는 마이그레이션이 아니다.

첫 정적 검토에서는 기획 수정 4문서의 로컬 링크 361개가 모두 존재하고, 시작 변경 목록의 JSON 27개가 해독 가능함을 확인했다. 이는 링크 대상의 실행 성공이나 JSON의 모든 의미 검증은 아니다. 텍스트 247파일에 대한 비밀정보 패턴 검사의 유일한 후보는 `개체시각대응Tests`의 연결하지 않는 시험용 `not-used` 값이었다. 이 검사는 휴리스틱 점검이지 보안 감사를 대체하지 않는다.

## 커밋 분류와 제외 원칙

코드·직접 시험·관련 계약은 같은 맥락으로 묶고 공통 기반을 소비자보다 먼저 기록한다. 공유 생성물과 원장은 최종 통합 맥락으로 분리하되 중간 커밋의 검증 범위와 의존성을 명시한다. 기획·자료 조사·현재 상태 문서는 실제 구현 완료와 구별한다.

미확인 Unity Scene/Samples/과거 이미지, 다운로드한 LlamaLib 네이티브 산출물, `test-results.xml`, `artifacts/local`의 원자료·시험/촬영 결과는 일괄 stage하지 않는다. 필요한 대표 근거만 소유·출처·변경 맥락을 확인한 뒤 포함한다. API 키·비밀번호·연결문자열·실제 개인/운영 원자료가 들어가지 않는지 점검한다.

Hongdal의 분류는 ① 기획·공통 기준, ② 경관 패턴·그래프, ③ Nature 상태 조회, ④ 표현 준비·연결 사전검사, ⑤ 공공자료 수집, ⑥ 현실자료 검토, ⑦ 게임객체·시각자산 관계형 목록, ⑧ 기획 판본 반입, ⑨ 조회·증거 관리 도구, ⑩ 자료조사 근거, ⑪ 최종 통합 기록이다. 변경 내역을 결정 번호마다 억지로 나누지 않고 공유 파일과 빌드 의존성을 우선한다. 최종 합쳐진 상태의 시험 결과를 각 중간 커밋에서 독립 실행한 것으로 표현하지 않는다.

Unity는 D337 독립 검증 출력 격리와 D358 Blender 환경 준비를 우선 독립 묶음으로 대조한다. D358 네 파일은 기존 환경 보고의 hash와 일치하며 실제 캐릭터·Clip 제작물이 아니다. `.meta` 빈값의 끝공백은 GUID·내용 의미를 보존하는 정규화만 허용하고 원본 보고의 과거 hash는 변경하지 않는다.

Unity 두 커밋은 완료했다. `3015893d`는 출력 격리 2파일, `094f225d`는 Blender 준비 4파일이다. NPC 독립 Core 32/32·Vendor 9/9 TRX를 기획에서도 직접 파싱했다. 이후 남은 655경로는 시작 시점과 상태·내용 hash가 모두 같고 인덱스는 비어 있다. 다운로드/기존 Scene·샘플/미소유 변경을 제거하거나 같이 커밋하지 않았다.

최종 개발 인수의 파일 22개와 검증 산출물 9개는 기획에서 길이·SHA256을 각각 직접 대조해 모두 일치했다. 최종 텍스트 252파일의 비밀정보 패턴 재검사에서는 연결하지 않는 `Password=not-used` 시험 값 2건만 후보로 남았다. 최초 점검과 마찬가지로 완전한 보안 감사는 아니다. 인수 뒤 CURRENT_WORK·통합상태판에는 Git 마감 문단만 추가하며, 개발의 `final-audit`는 추가 전 인수 시점의 hash로 보존한다.

서버 실패 7건은 이전 `20260831-205049` TRX에서도 이름·오류 메시지가 같음을 기획이 독립 대조했다. 다만 이것만으로 이번 모든 누적 변경과 인과적으로 무관함을 증명한 것은 아니다. Controller 업무 메타데이터, 화면 경로 capability, 명명 규칙, UI 높이 조건의 실패는 [개발 상세 보고](누적변경-D448-개발정합화-2026-08-31.md#2-실행-검증)에 남겼으며 필터로 숨기거나 임의 수정하지 않았다.

**남은 실제 문제:** 분류 테이블의 3열 고유 인덱스 누락, 방문자 과거 E4 패키지의 현재 코드 hash 불일치. DB 확인은 허용된 인덱스 메타데이터 읽기뿐이며 행 조회·DDL 적용은 하지 않았다. 과거 증거 hash를 새 코드 값으로 치환하거나 E를 승격하지 않았다. 이에 따라 전체 개발시스템 관리 검증도 미통과이며 첫 차단 이후 모든 관문을 확인했다고 주장하지 않는다.

**기존 공백 보존:** `Simulation배치적합성검사.cs`와 H1 문답 검증·시각목록 보고 2개의 마지막 빈행은 시작 hash와 동일했다. 특히 보고의 기존 근거 연결을 불필요하게 무효화하지 않도록 원문을 보존하고, 해당 3경로의 `new blank line at EOF` 진단만 커밋 인수 기록에 명시했다. 이 예외가 일반 공백 검사·관리 관문 전체 통과를 뜻하지 않는다. 다른 경로/오류는 예외로 허용하지 않는다.

빌드/자동시험을 실제 Unity 플레이·Game View 또는 운영 DB 적용 증거로 설명하지 않는다. 새 게임 기능·Scene/Save/Provider/게시·배포·push는 없으며 이번에는 승인된 정합화와 누적 변경의 Git 커밋을 수행했다.
