## 2. 개발 소비 계약

namespace는 `Ssalddel.Unity.Presentation.NatureWoodcutting`이다. 자동 Scene 검색/부착과 `Update/LateUpdate`는 없다.

1. `Resources.Load<벌목AnimationSources>(벌목AnimationSources.ResourceKey)`로 참조 묶음을 가져온다. 개발이 실제 Actor 아래 Animator를 찾아 `bool Configure(Animator, sources)`로 연결한다. Configure는 이전 자체 Graph를 해제하고 안전한 미재생 상태부터 검사하며 **Graph를 활성화하지 않는다**.
2. 개발 공용 lease로 기존 뼈 쓰기를 중지하고 Animator `enabled=true`, `applyRootMotion=false`, `runtimeAnimatorController=null`을 준비한다. 전문이 공용 컴포넌트의 enabled를 왕복하거나 기준 자세를 다시 수집하지 않는다.
3. `bool Acquire(string ownershipToken)` 후 같은 Presenter 한 곳에서 `TickPresentation(float deltaTime)`을 호출한다. 같은 토큰 재Acquire는 Graph/위상을 재생성하지 않고, 다른 토큰 Acquire는 거절한다.
4. `ApplySnapshot(벌목AnimationSnapshot)` 또는 Load/재연결용 `Reconstruct(snapshot)`을 전달한다. 생성자 순서는 `sessionStableId, actorStableId, targetStableId, observationGeneration, revision, requiredSeconds, completedSeconds, phase, progressToken=0, returnIntent=Idle`이다. 세대/revision/token은 long, 진행/요구 초는 int다.
5. `TryConsumeContact(out 벌목ContactCue)`는 표현 알림을 한 번 꺼낸다. `cue.Snapshot`에 그 토큰이 확인된 상태 버전이 들어 있으므로 최신 상태 버전과 혼동하지 않는다. `StableId`는 Session/Actor/Target/세대/토큰 기반이다. 서버 진행·보상·Save를 호출하지 않는다.
6. 완료/취소 뒤 `ReadState().ReturnReady`를 확인하고 **전문 Release → 개발 공용 lease 해제** 순서로 반환한다. 전문 Release는 자신의 출력만 `SetTarget(null)`로 분리한 뒤 Graph를 Destroy한다. 실패/예외 경로도 개발 finally에서 이 순서를 보장한다. 잘못된 토큰 Release는 false/no-op다. 전문 OnDisable/Dispose는 자신 Graph만 정리한다.

`벌목WorkPhase`는 Idle/Working/Completed/Cancelled, `벌목ReturnIntent`는 Idle/Walk다. Walk는 기존 이동 표현으로 반환하라는 의도이며 전문 Walk Clip은 없다. `InterruptToIdle()`는 대기/미소비 알림을 폐기하고 복귀를 시작한다. 중단 뒤 다시 Working을 시작하려면 새 관측 세대 또는 명시 Reconstruct 기준선을 제공한다.

`ReadState()`는 Configured/HasOwnership/GraphActive/Diagnostic와 Playback을 반환한다. Playback에는 Snapshot/Segment/NormalizedTime/PendingProgressToken/ConsumedProgressToken/ReturnReady/Diagnostic가 있다. Adapter 소유권 진단과 상태 입력 진단을 각각 읽는다.

### 상태 소비 규칙

| 입력 상황 | 결과 |
| --- | --- |
| 첫 입력·Reconstruct·새 관측 세대 | 현재 token을 기준으로 수용, 과거 접촉/대기 큐 비움 |
| 동일 revision·완전히 같은 입력 | true, 위상/Graph 재시작 없음 |
| 동일 revision인데 내용 변경 | false, 이전 상태 유지 |
| 낮은 revision/세대·진행 역행 | false; Load 등 의도적 복원은 Reconstruct |
| 같은 세대에서 Target/요구 시간 변경 | false; 새 세대 필요 |
| Session/Actor 변경 | Apply는 거부; 명시 Reconstruct 또는 Configure 필요 |
| 증가한 진행 초와 새 양수 토큰 | 최신 대기 1개 보유, 해당 Hit 중간에 1회 알림 |
| 여러 진행 초 건너뜀 | 과거 스윙 나열 없이 최신 토큰 한 건으로 합류 |
| 이미 관측한 토큰 재사용 | 추가 접촉 없음; 0은 새 토큰 없음 |
| 취소/명시 중단 | 미소비 알림/대기/진행 중 타격 폐기, 복귀 |
| 최종 Completed | 제공된 최종 토큰만 처리 후 복귀; 성공 보상 호출 없음 |

기본 재생 구간은 WindUp 0.35초 → 진행 대기 → Hit 0.20초 → FollowThrough 0.20초 → Return 0.25초다. 진행 대기가 없다면 1초이며 접촉 알림은 Hit의 50% 지점이다. 취소 복귀는 0.15초, Clip 간 가중치 전환은 0.08초다. 원본 곡선을 이 시간으로 평가할 뿐 새 프레임/이벤트를 굽지 않는다. 한 Tick의 표현 시간은 최대0.25초로 제한해 장시간 정지 후 일괄 과거 재생을 막는다. 입력 진행이 없으면 준비 말미에 머무르며 권위 시간을 만들지 않는다.
