# AreaSet·H 계층·플레이 기획 — 기존 자료 조사

- 조사일: 2026-08-31, 약 09:50~10:05 KST의 저장소 파일 기준
- 목적: 새 AreaSet 플레이 기획을 작성하기 전에 재사용할 자료, 현행 기준과 다른 설명, 미연결 부분을 확인한다.
- 범위: 기획 문서·H 정의/구성 대장·생성 결과·문답 색인·최근 개발 보고의 파일 기반 조사. 새 기획 승인이나 실행 작업 명세가 아니다.
- 변경: 이 조사 문서만 신규 작성. 원문·대장·생성물·게임 코드·Scene은 수정하지 않는다.

## 1. 조사 결론

**필요한 기획 틀은 이미 상당 부분 존재한다. 새 AreaSet/H 체계를 만들기보다, 기존 지역 구성 패턴과 플레이 문답을 연결하는 편이 적절하다.**

특히 [AreaSet 구성 패턴](../Architecture/AreaSet구성패턴.md)은 이미 H4의 지역 의도를 H3/H2 역할 슬롯·배치·연결·시작→결과→복귀로 번역하도록 정의한다. 사용자가 원하는 「지역에 어떤 공간이 들어가고 어떤 플레이가 가능한가」의 직접적인 출발점이다.

현재 부족한 것은 다음 세 가지다.

1. 공간 재고의 역할·WI와 후속 문답의 플레이 선택을 **같은 지역·같은 판본으로 대조한 기획 연결**.
2. 전체 구성안 중 **처음 필요한 공간, 플레이로 확장할 공간, 선택적 공간**의 구체적인 구분.
3. 탐색 재고·자동 생성 구성·실제 제품 연결을 혼동하지 않는 **현재 준비 상태와 실행 의존성의 표시**.

조사 중 수량 요약·옛 안내 문구·참조 hash 차이를 확인했다. 따라서 기존 파일을 모두 최신 승인안으로 간주해 그대로 개발에 넘기지는 않는다. 아래에서 재사용 범위를 구분한다.

### Farm의 기존 참조를 실제로 따라가 본 예

아래는 새 제안이 아니라 현행 정의 파일의 참조 일부다.

```text
H4 farm-production-processing-region — 농업 생산·후처리권
├─ H3 highland-farm — 고지대 농장 경관
│  ├─ H2 highland-production — 고지대 생산 블록
│  │  ├─ H1 farm-production — 농업 생산구획 → WI-FARM-01~04
│  │  └─ H1 nature-farm-edge
│  ├─ H2 farm-processing-shipping
│  └─ H2 forest-edge-farm
├─ H3 farm-processing-campus
├─ H3 farm-incident-recovery
└─ H3 farm-seasonal-production-loop
```

직접 대조한 파일은 [H4 Farm 청사진](../../eng/world-seedbeds/synty-bottom-up-inventory/definitions/h4/farm-production-processing-region.v3.json), [H3 고지대 농장](../../eng/world-seedbeds/synty-bottom-up-inventory/definitions/h3/highland-farm.v2.json), [H2 고지대 생산](../../eng/world-seedbeds/synty-bottom-up-inventory/definitions/h2/highland-production.v2.json), [H1 농업 생산](../../eng/world-seedbeds/synty-bottom-up-inventory/definitions/h1/farm-production.v2.json)이다.

H4/H3/H2 예시는 `ExploratoryInventory`, H1 농업 생산은 `ApprovedReference`다. H1에 WI와 능력이 연결돼 있어도, 상위 후보가 실제 세계에 배치되어 작동한다는 증거는 아니다. H2에는 내부 연결·도달 가능성 검토가 미해결로 남아 있다. **이 트리는 재사용할 구조이지, 그대로 승인 완료로 복사할 배치도가 아니다.**

## 6. 플레이 문답과 자산 연구를 어디서 가져올지

### 문답

검색의 출발점은 [문답 파일 데이터베이스 안내](../../eng/planning-inquiries/README.md)와 [색인](../AI/generated/planning-inquiry-search.json)이다. 답변의 권위는 색인 자체가 아니라 연결된 주제 원문·후속 결정에 있다.

| 첫 골격·자유 이동·밭 경계·건물/공간 | [건물·공간·배치 문답](../Architecture/PlayableLoops/PlanningSessions/건물공간배치/building-spatial-placement.inquiry.r1.md): Q077~079를 포함한 기존 선택 |

## 8. 새 기획 전에 채울 연결과 추천 순서

새 지역 구성이나 수치를 지금 확정하지 않는다. 다음 기획에 들어갈 때 아래 순서로 기존 자료를 채택·연결하면 된다.

1. **지역별 플레이 약속**: 기존 Nature·Farm·Town·Hub 의도와 별도 City 의도를 가져오고, 시작·선택·결과·회복·귀환 문답을 연결한다.
2. **기존 H 구조 선택**: 기존 역할 슬롯·H3/H2/H1을 먼저 재사용한다. 재고 상태가 후보인지 승인 참조인지 함께 적는다.
3. **첫 필수/성장 확장/선택적 공간 구분**: 이미 답한 결정은 재질문하지 않는다. 지역 전체 기준의 `required`와 첫 작은 실제 성립 단위의 필수 의존성을 혼동하지 않는다.
4. **H1–WI–상태–표현 대응**: 어떤 WI가 어떤 장소에서 가능하고, 필요한 상태·접근·자산·실패/복귀가 무엇인지 연결한다. 자산 미연결은 새 게임 선택인지 기술 공백인지 구별한다.
5. **남은 플레이 선택만 질문**: 최초 제공 공간, 활동 간 발견 계기, 확장 선택과 다른 활동으로 돌아갈 방법 등 기존 원문으로 채워지지 않는 부분만 검토 묶음으로 제시한다.

권장 산출물은 새 DB가 아니라 **기존 AreaSet 문서의 역할 슬롯·H 참조에 주제 문답과 WI/상태/표현 근거를 연결한 기획안**이다. Farm은 연결을 추적할 기존 자료가 풍부하고, Nature는 귀환·회복 비교 자료가 있다. 이는 조사상 장점이지 다음 구현 영역을 자동으로 Farm으로 지정하는 결정은 아니다.

## 9. 수행 범위와 미수행

- 수행: 파일 탐색·선정 자료 읽기, JSON 배열 집계, 문답 입력 22hash 대조, H 정의/문서 296경로의 바이트 및 정규화 hash 비교, 생성기 입출력 경로 조사.
- 미수행: H 전체 의미/연결 그래프의 자동 검증, 생성물 재생성, 빌드·게임 시험, Unity/Scene/Prefab 실행, 실제 플레이/캡처, 437문답 전수 의미 재심사.
- 기존 소스·원문·원장·승인 hash·E·중지 상태는 보존한다. 새 게임 기획 확정·구현/복구·commit/push는 없다.
- 조사 결과를 개발에 전달하더라도 위 불일치의 자동 수정·생성 재개를 뜻하지 않는다. 이번 요청은 기획 전 자료 조사다.
