# LS01 데이터 후보 인수와 배치 소비 경계

기준: 2026-08-30 / 개발 정적 검토. [전문 최종 인계](Farm경관-LS01-전문인계-2026-08-30.md)와 [D363 배치 고도화 우선순위](../Architecture/지도구성과세계자산배치분리.md)를 따른다. 이 보고서는 후보 승인·새 실행 명세·실제 배치 증거가 아니다.

## 인수한 자료

- Unity `artifacts/local/validation/farm-landscape-ls01/comparison-preparation/handoff-manifest.json`: `B3AE1C730AD3C9D115ED6D409DA22092D313CA7F05402B5719F3E4DBD0E22CE2`. 개발이 등록11파일의 현재 hash 일치를 확인했다.
- `frozen-r1/validation.json`, `repeat-r1/validation.json`을 직접 읽어 각각34개 `pass=true`/실패0을 확인했다. 개발이 시험이나 격리 빌드를 다시 실행한 것은 아니다.
- 두 실행의 `B.delta.json` 파일 SHA256은 모두 `3E2D3C7B395CB4B1622D5B7B38971CB84A66B69B1D3CA50ACC4F8062C79C97DE`다. 정식 소비 검토 기준은 `frozen-r1/`이며 `run-01/`은 중간 이력이다.
- A는 기존 확대 Barn01 후보, B는 `farm-landscape-ls01.flat-ab.r1`의 6종8장식/nativeScale1 변화분이다. B input/output hash는 각각 `e8c00fb8e51b70ad9a178889c7b09733bbb42483bb8c29663c77424b10afa0de` / `63a08b079c947b9370a32f8d45af0044e4fab16abbd80df683aa723ffe2eb704`다.

B는 `UnapprovedCandidate`, Core 소비 불가다. 기존 검사에 B 외곽을 임시 장애물로 넣은 통로·객체 진단은 B의 H/구성 키/지지면을 검증한 것이 아니다. Partition/LH 시험은 A에만 적용됐다. 도로·마당 표면2개는 기존 `RouteObstacle` 거부로 보류하며 검사 완화·자동 축소·Collider 제거로 통과시키지 않는다.

## 담당별 다음 작업

1. 공간 담당: 기존 전문 보고서의 새 후속절에 B6종8개 VisualKey/단일 Prefab/Composition 후보, Cell·상위 H 계보, Renderer·Collider·지지면 입력 대응표를 작성한다. 기존 동결 자료·Accepted 연구는 변경하지 않는다. Editor/Scene/공통 코드 쓰기는 배분하지 않았다.
2. 개발 담당: 대응표를 받아 기존 공통 배치 검증 재사용 범위와 LS01 전용 입력 검증의 책임을 정하고 명세·쓰기 경로를 결속한다. 미등록 키·소유 누락·잘못된 측정hash·지지 없음·통로/보호영역 침범 거부 및 A 불변 회귀가 첫 코드 수용 기준이다. 이는 승인된 경관을 연결하는 기술 작업이며 미해결 기술 선택을 사용자 미승인으로 돌리지 않는다.
3. 검증된 배치 계획 이후에만 LH 준비/활성/캐시/해제/재진입을 좁게 확인하고, Unity 조립과 공간 담당의 동일 카메라/시간대 A/B Game View 검증을 연결한다. B 현재 카메라·Sky·Session 동결과 실제 화면은 미검증이다.

현재 새 플레이 의미 결정 요청은 없다. Q392 표면의 통로 의미 변경이나 생산·충돌 규칙 변경이 필요해지는 경우에만 그 영향 범위를 따로 반환한다. Q393~396 수관/조명/기상/실제 생활 상태 공급은 해결됐다고 가정하지 않는다.

## D363 진행 요청 이후 첫 코드 결속

D364의 통합 실행/해제 방향도 읽었다. 이번 사전검사 구현을 멈추지 않고 다음 연결의 기준으로 사용한다. 정적 대조상 Unity `공간LHStreamingEngine.RequestWindowAsync`에는 요청 세대·취소 후 낡은 응답 거부가 이미 있고, `NotifyAuthorityRevision`·`ApplyPreparedCell`·`CacheCell`·`ActivateCell`·`ReleaseCell` 호출 경로도 있다. 새 대형 조율자를 추가해야 한다고 판단하지 않는다. `SimulationLhAssetPlanPresentationReconciler`는 별도의 순수 Prepare/Activate/Cache/Release 명령 계산이며, 이번에 검색한 Unity Assets/Ssalddel 및 Ssalddel.Unity 범위에서는 Streaming의 직접 소비를 찾지 못했다. 두 경로를 동시에 연결하기 전에 기존 요청/관심 소유·해제 기준을 대조해야 한다. 공유 관심의 최종 해제, 최신 사본 재진입·성공 명령의 표현 실패 비롤백은 후속 시험이며 정적 존재만으로 통과 처리하지 않는다. 셀 표현 해제는 작물/NPC 상태 삭제나 Session 종료가 아니다.

사용자의 후속 진행 요청에 따라 Farm 명세 `1D8E74DBC4F53CB6245AB2508BAF5251B9C2C29C21C84B1730E6D223B994ABD9`와 Goal r60의 `work:farm-crop-cycle:landscape-binding-guard`를 결속했다. Goal Write·작업 명세·주제 Validate 및 전달 Check·문답 파생 Write가 통과했다. 승인 원문/연구 hash와 기존 E는 유지한다.

- 개발 소유 신규 경로: `Ssalddel.Simulation.Application/Simulation경관배치소비검증Service.cs`, `Ssalddel.Simulation.Tests/Simulation경관배치소비검증Tests.cs`.
- 첫 코드 책임: 기존 공통 계획과 기준 A, 기대 추가장식 목록, 지도/H 계보, 실제 해결기의 등록 키를 입력받아 정규형 hash·원A 불변·기대 집합·소유·Scale1/유한 좌표·비권위를 검증한다. 결과는 `BindingVerified`와 실제 조립에서 확인할 기대ID 사본이다.
- B JSON을 읽어 공통 계획을 만드는 변환기나 실제 Unity 소비자는 아직 아니다. 합성 결속 Fixture 시험은 실제 B 지면·통행·발현 시험과 구분한다. 새로운 Save/LH/게임 WI는 만들지 않는다.

공간 대응표 후속 보고서 SHA `1A15EF8940E2A8CE2D2F53BAB0C10E96BCB3C444F96F65977AF2CBBD5062EBFC`를 직접 읽고 hash를 확인했다. 이전 manifest11/11 일치는 수신 당시 기록이며, 이 보고서가 후속 변경된 현재에도 이전 manifest 전체가 일치한다고 주장하지 않는다. frozen B와 연구는 별개로 보존한다. 표의 단일6자산 키는 미등록 후보이며 기존 다중 수목 구성과 교체하지 않는다. `CollisionEligible`는 현재 Unity Configure에서 Collider 제어에 사용되지 않으므로 그 필드만으로 실제 물리 조건을 증명하지 않는다.

이번 코드의 다음 연결은 실제 등록 키 해결→동결 B 변환→기존 외곽/지지/통로 검증→조립 결과의 기대ID 대조다. LH는 검증된 계획의 수명주기만 소비한다. 승인 경관을 다시 문답 대기로 돌리지 않는다. 과거 Graph2 잔존과 Console 기록은 이번에 재조회하거나 해소한 것이 아니다. Scene/Save/E 변경·commit/push 없음.
