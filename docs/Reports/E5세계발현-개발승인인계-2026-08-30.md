## 개발이 등록할 명세와 작업

- 기존 `nature-basic-herbal-recovery.e7-work-order.json`은 WI-ACTOR-03의 E5 전달로 개정한다. 공간/배치는 지식 연구 Required/Accepted, 건물/애니메이션은 기획 사유로 NotRequired다.
- 기존 `nature-camp-visitor-stay.e7-work-order.json`은 WI-COMMUNITY-VISITOR-STAY E5 전달로 개정한다. 공간/배치/애니메이션은 방문자 r2 연구 Required/Accepted, 건물은 NotRequired다.
- Farm은 `farm-crop-cycle.e7-work-order.json`을 첫 승인 명세로 사용한다. 기존 파일이 있으면 보존·개정하고 없으면 현행 v2 템플릿으로 만든다. WI01~04의 실제 의존 순서를 기록하고 WI별 작업은 같은 주제 기획/연구에 결속한다. 공간/배치/최소 행위 표현은 Farm 연구 Required/Accepted, 건물은 NotRequired다.
- 명세의 수직 target은 E7, 이번 `deliveryCap.currentDispatchTargetStage`와 workItem 목표는 E5, `promotionBeyondStageAllowed=false`다. 현재 통과한 upwardValidation/E4 근거는 보존하고 E5는 Pending으로 열어 실제 실행 후 Passed로 변경한다. 입력/화면 검사는 이번 E5 검증에 포함하되 E7 전체 폐루프 증거로 확대하지 않는다.
- E7→E1 영향 검토에는 Session 소유·명령/행위·저장 변경, E4 H/자산/조건 모듈, E5 같은 revision 실행/결과/반환을 적는다. Save 변경으로 영향을 받은 하위 E는 재검증한다. 금지 문구는 역사적 r4/r2 범위와 현재 승인 범위를 구별해 갱신한다.
- 개발은 Loop planningGate/Required 연구/승인 hash, Goal workItems, 전달 우선순위, 문답 및 엔진/표현 프로필을 같은 기준으로 결속하고 생성·검증한다. 기획서 하나의 hash만 갱신하고 다른 결속을 낡은 상태로 두지 않는다. 통합 E나 개별 WI의 실제 구현 상태를 승인만으로 올리지 않는다.
- 공통 Runtime/Save/원장·생성물/Unity 통합은 개발 writer다. 공간/애니 담당의 전용 경로·공유 계약 소유를 먼저 정한 뒤 배분한다. 외부 Unity 저장소 경로는 별도 인계로 관리하고 `../` workItem 경로로 넣지 않는다.

## 병렬 배분과 첫 실행

1. 이미 완료된 [회귀 기준선 복구](D285-기존회귀2건-기대값정합성-2026-08-30.md)는 집중27/27, 전체1178/1178 근거로 재사용한다. 게임 실행 증거는 아니다.
2. 개발은 지식/방문자의 실제 Session/Save 연결을 우선 구현한다. 지식 습득은 Runtime 포트가 있으나 자체 메모리 원장을 사용하고 방문자는 아직 Runtime 연결이 없다. 임시 원장만 만들어 E5를 주장하지 않는다.
3. 공간 담당은 기존 Farm 후보를 현행 호환 소스·명시적 변환으로 통합 준비한다. 원본 인계 hash를 유지하고 소비 프로젝트/Partition/LH 시험을 개발에 반환한다. 새 패턴 상태 변경 WI나 Scene 임의 승인 없이 검토 인스턴스를 만든다.
4. 애니메이션 담당은 방문자 연구의 Starter 남성 Actor 한 개와 Idle/Walk/선택적 Greet를 구현·검증한다. Editor 읽기 검사, 프로젝트 소유 Wrapper/Controller 및 필요한 좁은 Adapter 변경은 이번 승인에 포함한다. 기존 Nature 벌목을 검 공격으로 대체하거나 vendor 전체 importer를 변경하지 않는다.
5. Farm 연결 시 발견한 WI01~03 Pipeline 누락, Host RemoteHost 고정, 같은 밭 다음 파종 Preview/Confirm 고정 ID 충돌은 기존 계약 결함으로 교정한다. 이전 수확 Lot을 지우지 않고 두 번째 주기까지 회귀한다. CropCare 완료가 성장 상태를 전환하는 기존 규칙을 자동 시간 성장으로 바꾸지 않는다.
6. E4 측정·같은 revision 논리 E5가 준비된 범위부터 독립 Prefab/Builder를 canonical Scene에 통합한다. 작업별 실제 실행·Save/Load·대표 Game View를 검증하고 다른 범위의 대기를 이유로 모두 정지하지 않는다.

## 반환과 중지 경계

기획은 승인 문서 7개를 더 수정하지 않고 개발이 hash를 확인한 뒤 공통 writer를 계속 소유한다. `CURRENT_WORK.md`와 통합 상태판의 이후 실행 상태 갱신도 개발에 반환한다. 코드 착수 전에 Goal/명세/전달/주제 기획·연구 관문을 통과시키고 등록 결과를 기획에 알려 준다.

실제 미정 설계·범위 밖 권위·공통 계약 충돌은 해당 작업만 차단하고 가장 이른 E/필요 결정을 반환한다. 배치 좌표·Rig 오류 같은 기술 검증을 사용자에게 임의 숫자 선택으로 떠넘기지 않는다. 전문 결과는 개발이 먼저 통합·검증한 뒤 기획으로 반환한다. 모든 작업 종료를 기다릴 필요는 없다. commit/push는 하지 않는다.
