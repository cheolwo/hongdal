## 저장과 실패 경계

- 기존 canonical dirty 상태의 임의 저장·폐기·해제·재로드는 금지한다. 기존 UI 변경의 소유가 아직 확정되지 않았으며 오래된 폐기 허가는 현재 dirty 상태에 적용하지 않는다.
- 승인 변경과 기존 dirty를 안전하게 분리할 수 없으면 저장·재진입만 차단으로 보고하고 비파괴 검증 가능 범위는 따로 판단한다. 저장하지 못한 화면을 저장 Scene 재진입 증거로 표시하지 않는다.
- clamp 확대·자산 축소·보호영역 변경·실내 추가로 실패를 숨기지 않는다. 필요한 변경은 정확한 책임 경로와 가장 이른 재개 E로 반환한다.
- 코드·자동 시험·Scene 배선·Game View·저장 재진입은 각각 독립 결과로 기록한다. 새로운 WI·게임 규칙·건설 취소 정책·E 자동 승격·commit/push는 범위 밖이다.

## 반환 양식

각 검증 항목의 `Passed / Failed / NotRun / Blocked`, 소스·후보·상태 판본/hash, 시각, 실제 입력 순서, Play Mode 여부, Game View 경로, Console, Scene 저장/dirty 보존 여부, 남은 차단과 다음 책임을 기록한다. Scene View는 보조 자료다.
