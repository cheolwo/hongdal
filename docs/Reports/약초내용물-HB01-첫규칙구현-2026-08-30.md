# 약초 내용물 HB01 — 첫 순수 규칙 구현

## 실제 인수와 한계

[D356 승인 보완](../Architecture/PlayableLoops/Nature약초차-HB01개발승인보완.md) 전체와 SHA256 `745BFB5519B0C9BD545B2687130AFA92549B807ACF85C2BEE73762F6EE4A87B6`를 직접 확인했다. 문답 r30 hash `FA70418FED88A05BC2C6792F59FB25A8326B0AF25DA7419F74BB59D767BC2F4B`도 일치했다. 기존 기획 r5를 수정하지 않고 부모 명세의 추가 승인·[지원 명세](../../eng/execution-ledgers/work-orders/nature-herbal-hb01-contents.e7-work-order.json)·기존 Goal의 독립 workItem에 결속했다.

이번 실제 구현은 **용기 내용물 계약과 순수 전송 계산**이다. 독립 시험 **44/44**가 통과했다. Application의 Confirm·멱등·경합·행위 기록이 없으므로 전체 WI Logic E3 완료로 보고하지 않는다. 부모 Logic E4/Presentation E4/통합 E4는 기존 지식 기능의 사본이지 이번 기능의 증거가 아니다. E5Pending·beyond=false와 기존 E를 유지한다.

두 Runtime 소스의 Unity `.meta`만 함께 추가했다. 외부 데이터·Unity·기존 물품 재고/열원 코드·Save는 수정하지 않았다.

- 냄비1000/병500/컵200mL는 첫 시험 최대량이며 음용 행동량과 구분한다.
- 같은 종류·처방·효과 판본만 합친다. 원천보다 큰 요청은 거부하고 대상 여유 공간보다 큰 요청은 여유 공간만 전송한다. 나머지는 원천에 남는다.
- 온도는 게임용 정수 milli°C의 양 가중 평균이며 소수부는 0 방향 버림이다. 분할 정산이 필요한 후속 가열/냉각 시간 규칙과는 별개다.
- 제조 출처는 양에 비례해 나누고 정수 잔여는 최대나머지/Ordinal 동률 순서로 배분한다. 각 출처의 총량이 보존된다. 중간 곱셈·합 검증은 `BigInteger`로 넘침을 방지한다.
- 전량 이동 뒤 빈 용기·능력·최대량은 남는다. 입력과 반환 배열은 복사하여 외부 변경으로 계산 상태가 바뀌지 않는다.
- 물을 차/약효로 바꾸지 않으며, 소유권·Actor/거리·Session 검증을 순수 계산 성공으로 대체하지 않는다. 실제 열 안전/현실 용량 근거도 아니다.

## 다음 기술 연결 / 기획 선택

1. 전송 책임을 기존 등록 WI와 대조해 단일 책임 ID·명세·파이프라인에 결속한다. 현재 부모 WI-ACTOR-03은 지원 작업 소속 표시이며 전송/섭취 명령으로 호출하지 않는다. 질문마다 WI를 만들지 않는다.
2. 같은 원천/대상/Actor를 잠그는 Application Preview/ExpectedRevision/Confirm/멱등/행위 기록을 구현하고 전송↔섭취 경합을 시험한다. 실제 권한·최신 상태 검사는 이 단계에서 필요하다.
3. 승인된 부분 음용·효과 시간 비합산·완료 전 취소, 보편 데우기와 열원/연료·달임 완료를 분리 구현한다. 첫 묶음에 아직 포함하지 않았다.
4. Session 권위 시간·공동 Save 예약·Local/Remote·Required 표현 연구/실제 배치/음용 중단·화면으로 이어간다. 기존 공간/애니메이션 담당이 완성한 자산 조사만으로 실행 성공을 주장하지 않는다.

현재 새 사용자 선택이 필요한 차단은 없다. 미완료는 승인 범위의 기술 연결이며 FB01 검토 중인 농사/위임 답안을 끌어오지 않는다. 커밋·푸시·Scene 저장·E 승격 없음.
