## 2. 확정하지 않은 입력

- Q-347 물 운반 용기는 답변 대기다. 냄비·컵 활용 추천을 승인으로 취급하지 않는다.
- 직전 제안 ‘쉬거나 다른 곳에 다녀와도 건설 재료·진척을 보존하고 직접 재개’에는 이번 턴에서 답변하지 않았다. 기존 Q/코드에 같은 결정이 있는지는 먼저 조사하되, 이 제안을 새 승인 근거로 추가하지 않는다.
- 체력·마나 r32의 남은 수치·공통 시간/상태 연결·일부 안전/열원 조건·마나 소비 등은 확정 절과 구분한다. 개발이 시험 조정하도록 이미 승인된 수치는 숫자마다 재승인을 요구하지 않는다.
- 기존 E5 승인 원문 7개를 이 인계 때문에 조용히 변경하지 않는다. 새 범위에 핵심 기획 공백이 있다면 해당 범위만 기획에 반환한다.

## 3. 개발의 첫 처리와 병렬 배분

1. 아래 입력 hash와 현재 작업 목록을 대조하고 이미 구현/인계된 것은 재작성하지 않는다. 현행 상태판의 과거 요약보다 실제 승인 명세·코드·증거를 우선한다.
2. 기존 승인 E5 작업은 유지하면서 Q-340~346·후속 체력/마나 결정의 WI 대응, 기존 코드 재사용, 누락·미정·의존성을 정리한다. 새 게임 규칙 구현은 승인 기획/명세 결속 후 진행한다.
3. 개발은 공통 Runtime·Session·Save·WI/Goal/문답 원장·생성물의 통합 writer를 맡는다. 기존 Save v30 예약 및 쓰기 소유권은 실제 현행 파일에서 재확인하고 중복 판본을 만들지 않는다.
4. 월드·공간·배치에는 승인 범위의 H·실내외 배치·실제 자산 측정과 View 캡처를 배분한다. 후보 조사와 실제 배치 증거를 구분하며 canonical Scene/Editor 점유는 조정한다.
5. 애니메이션에는 동일 WI 상태·행위 신호에 연결되는 좁은 동작/Actor/Rig·접촉·중단 복귀 검증을 배분한다. 전용 동작이 없으면 대체 표현과 미검증을 명시하고 공급사 원본을 무단 개편하지 않는다.
6. 파일 경로·공유 계약·선행 통합이 겹치지 않는 작업은 병렬로 진행한다. 하나의 차단을 전체 대기로 확대하지 않으며 전문 담당은 결과를 개발에 반환한다.

## 4. 개발 → 기획 반환 요청

기존 [개발 통합 상태판](../AI/개발통합상태판.md)에 아래를 정리하고 기획으로 반환한다. 중복된 별도 실행 대장은 만들지 않는다.

- 문답/결정 식별자 → 기존 또는 신규 예정 WI → 담당 → 현재 증거 → 다음 작업.
- 이미 구현됨 / 승인 범위에서 진행 / 전문 조사 필요 / 기획 선택 필요 / 보류·원문 복구 필요를 구분한다.
- 이번에 실제 달라진 플레이, 코드·시험·Runtime·Scene·Game View 검증 범위와 미통합 준비물을 분리한다.
- 새 범위의 승인 요청은 필요한 플레이어 선택만 압축하고, 독립적으로 계속할 수 있는 개발은 병행한다.

통합 E는 Logic·Presentation 중 낮은 값이다. 자료 전달이나 시험 통과만으로 승격하지 않는다. 이번 요청은 commit·push 승인이 아니다.
