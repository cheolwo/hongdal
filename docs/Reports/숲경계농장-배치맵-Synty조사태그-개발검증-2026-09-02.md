# 숲 경계 농장 배치 맵·Synty 조사 태그 개발 검증

## 결론

`PLAN-PLACEMENT-FOREST-EDGE-FARM-001`의 `forest-edge-farm-placement-map-planning.r21`을 기존 한스 생활 농장 배치 준비 프로필에 반영했다. 한스 생활 농장의 주 표현 팩은 `Farm`, 보조 팩은 `Construction`·`Nature`·`AlpineMountain`으로 구분했다. 다섯 배치 대상은 기존 보유 재고의 팩·기능 모듈·H 표현 카드·자산 계열 근거까지만 `InventoryMatched`로 기록했다.

정확 Prefab GUID·fingerprint가 확인된 후보는 이번 범위에 없으므로 `candidateRefs`는 다섯 항목 모두 비어 있다. `VisualReviewed`, `StaticCompatible`, `UnityVerified`, 자동 Prefab 할당, E5 승격은 수행하거나 주장하지 않는다.

Graph Map 본체는 기존 다른 작업의 부분 통합 상태 때문에 이번에 수정하지 않았다. 따라서 최종 결과는 **배치 준비 프로필 통합 / Graph Map 시각 태그 결속 차단**이다.

## 작은 지붕 구멍과 Blender 결손 조사

한스 생활 주택은 `BlenderPlanRequiredCandidate`로만 기록했다. 제작 순서는 `ExistingPrefab` → `CompositionOnly` → `ProjectOwnedVariant` → `BlenderPlanRequired` → `BlenderValidatedCopy`로 고정했고, 이번에는 어느 단계도 실행하지 않았다.

첫 손상 단서는 `SmallRoofHoleVisibleFromForestTrail` 하나뿐이다. 벽체·출입구·주요 지붕 구조와 생활 가능성을 유지해야 한다. 향후 정확 후보가 정해지면 다음을 별도로 확인해야 한다.

- 기존 Prefab과 Construction·생활 소품 조립만으로 낡음과 운영 흔적을 만들 수 있는지
- 지붕 구멍·깨진 가장자리·노출 단면 중 실제 메시 변경이 필요한 결손이 무엇인지
- 정확 입력 FBX, 원본 Prefab GUID·fingerprint, 프로젝트 소유 출력 경로·ID·계보
- 축·단위·피벗·재질 슬롯·법선·UV·Collider·Bounds
- 같은 카메라·거리에서 수리 전후 지붕 윤곽 또는 보강 흔적이 판독되는지

Synty 원본 변경과 Blender 실행·가공은 승인되지 않았다.

## Graph Map 차단

현재 [북부 생활권 Graph Map](../../eng/world-seedbeds/graph-maps/northern-life-hub-discovery.v1.json)은 `mirror-graph-map-plan.northern-life-hub-discovery.r11`이다. 그러나 본체가 기대하는 partition 판본은 r8인 반면 실제 partition은 r7이고, partition과 normalization의 원본 Graph Map 기대 판본은 r10이다. 이는 기존 Graph Map 소유자의 부분 통합 경계다.

또한 기획이 요구하는 `gm-node:hans-house`는 현행 Graph Map 노드 목록에 없다. 배치 프로필은 존재하지 않는 노드를 실제 결속으로 위장하지 않고 `graphNodeRef: null`, `intendedGraphNodeRef: gm-node:hans-house`, `PendingStableNode`로 기록했다. 나머지 네 대상은 현행 기존 노드만 참조한다.

이 상태에서 Graph Map 판본을 올리거나 `visualRequirementTags`를 덧붙이면 다른 partial 통합을 함께 소유하게 되므로 이번 작업에서는 본체·partition·normalization을 읽기 전용으로 유지했다. 후속 Graph Map 소유자가 현재 partial 판본을 먼저 통합한 뒤 다섯 역할 태그와 한스 집 안정 노드의 생성 또는 기존 노드 재사용을 결정해야 한다.
