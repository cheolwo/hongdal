## 백업 보존과 Editor 검증

사용자 추가 승인 후 실제 `Recovering Scene Backups`의 “copy and preserve ... Assets/_Recovery/” 문구를 확인하고 Yes를 한 번 선택했다. `Assets/_Recovery/0 (5).unity` 사본 SHA256 `EC409D9D756E4F5082BD2EE40394F731D23C174CDED6499DF867650ED2BBD787`을 확인했다. **백업 사본 확보이지 해당 사본을 canonical에 적용하거나 메모리 상태를 완전히 복원한 증거가 아니다.** canonical 저장 파일 SHA256 `B270E1CC1DDAAE219D56D3F2D15B127A05743718DC0903D93D833DB17FF1F849` 불변을 확인했다.

초기 패키지 미설치 시 연결부 UndreamAI/LLMService CS0246 두 건이 발생해 Safe Mode로 진입했다. UPM 해석 뒤에도 package assembly가 컴파일 목록에 없던 상태를 분리 조사했다. 오류가 남은 채 Exit Anyway 하는 경고는 취소했다. 설치 순환을 끊기 위해 신규 vendor 어셈블리와 해당 시험만 임시 제외했으며 최종 포함 재검증 전에는 Editor 컴파일 성공으로 판정하지 않는다. [Unity Safe Mode 문서](https://docs.unity3d.com/2023.2/Documentation/Manual/SafeMode.html)의 오류 해결 경계를 따른다.

최종 임시 제외를 모두 제거했다. vendor MonoScript37개가 실제 읽히지만 컴파일 대상에는 0개로 잡히는 현상이 재등록·좁은 import·CleanScriptCompilation·script reload 후에도 남았다. 현재 Scene dirty=false를 확인하고 Alt+F4 정상 종료(저장 대화 없음) 후 Hidden 정상 재시작 한 번으로 해소했다. 강제종료나 캐시 디렉터리 수동 삭제를 사용하지 않았다. 재시작 로그 `d337-editor-restart.log`는 `Tundra build success (4.80 seconds)`이며 새 Core/Adapter/두 시험·vendor Runtime/Editor 어셈블리 실제 로드, stopped/ready/compiling=false를 확인했다. Scene은 canonical 단일/root2/dirty=false이며 복구 사본을 적용/저장하지 않았다. 새 Pipeline error 조회는 0건(cursor7), 초기 컴파일 오류와 vendor 밖 AI Assistant/Synty 경고 로그는 지우지 않았다.
