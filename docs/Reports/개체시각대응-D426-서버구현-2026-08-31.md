창고 물리 시설/정보 구별의 직접 조회, 운영자 선반, 농업 센서, 전통시장·물류거점/음식점·메뉴/차량·운송/커뮤니티·교육은 아직 이 Reader에 등록하지 않았다. 이 여섯 종류를 전체 개체 지원으로 보고하지 않는다.

## 2. 공통 선택·검토·저장

`권한 있는 대상 조회 → 정확 문맥의 개별 승인 → 정확 문맥의 종류 기본 승인 → Unmapped`

- 문맥: 종류, 원천, 접근 범위, 원천 상태, 표현 목적, 표현 종류, 개별 ID 또는 기본형 표식. 개별 대응은 현재 원천 revision도 일치해야 한다.
- 기본형 반환은 `IsFallback=true`와 개별 부재/미검토/판본변경 이유를 함께 제공한다. 인증·원천 조회 실패, 원천 충돌, 대응 중복/자산 대장 충돌은 기본형으로 숨기지 않는다.
- 자산 검토 사본은 배포자가 제공하는 읽기 전용 `EntityVisualBindings:Entries`다. HTTP로 등록/승인 근거를 주입하는 API는 없다. 현재 제품 설정에는 새 승인 사본을 넣지 않았으므로 실제 후보 승인은 아직 없다.
- 자산 키·대장 revision/fingerprint·자산 fingerprint·적합성 근거 ref/fingerprint의 일치를 요구한다. 개별 전용 `RecordStableId`가 있으면 다른 품목이나 종류 기본으로 확대할 수 없다. 종류 기본은 별도 `AllowTypeDefault=true`가 필요하다. 기본값은 false다.
- `SaveDraft → SubmitReview → Approve`, 또는 `Exclude`. 초안 수정은 기존 승인을 무효화한다. 과거 상태 대응은 같은 권한/대상 아래 이력 조회·제외할 수 있지만 과거 문맥을 현재 상태로 바꾸지 않는다.
- `ExpectedRevision`, 주체+대응 ID+요청 키에 결속된 멱등, 같은 키/다른 내용 거부, 문맥 고유 인덱스, EF 동시성 토큰, 상태·이력의 단일 `SaveChanges` 트랜잭션을 구현했다. 멱등 재반환은 과거 저장 결과이지 현재 사용 승인 보증이 아니다.
- 읽을 때도 저장 행과 JSON의 ID/revision/문맥/검토상태 정합성을 검사한다. 저장/원천 오류를 빈 자료나 성공으로 반환하지 않는다.

전용 [DbContext](../../Ssalddel.Infrastructure/Persistence/WorldProjection/개체시각대응DbContext.cs)는 기존 연결 설정을 쓰되 `world_entity_visual_bindings`, `world_entity_visual_binding_history` 두 테이블만 소유한다. 원천 Context의 마이그레이션에 끼워 넣거나 자동 `Migrate/EnsureCreated`하지 않는다. 새 API는 기본 `EntityVisualBindings:Enabled=false`다. 이는 기술 기능 공개 관문이며 기존 업무 실행의 Simulation/Operational 구분을 대체하지 않는다.

## 6. 다음 작은 범위

1. 허용된 Docker 접근이 복구되면 정확 대상/테이블·원천 자료를 읽기 대조하고 두 테이블만 제한 적용한다. 기존 각 분야 레코드가 있으면 초안 저장·독립 재조회, 없으면 부재로 반환한다. 수를 채우는 새 원천 레코드 생성은 하지 않는다.
2. 기존 자산 대장의 검토된 동일 판본 사본을 배포 설정에 결속한다. 현재 파일 후보와 실제 목적 적합성을 구분하고 승인되지 않은 Entries를 만들어 통과시키지 않는다.
3. 동일 공통 선택기를 유지해 미등록 선반·센서·물리 시설과 후속 분야를 기존 권한 조회 단위로 추가한다. 실제 Unity 소비는 기존 배치 구조·제약/계획/검사 경로에 별도 결속한다.
