# 농장 생활 주택 H1·한스 배치 준비 개발 검증

## 결론

`h1-stock:farm-residential-home`을 일반 농장 주거 건물 H1로 등록하고, `h2-candidate:forest-edge-farm`에는 선택 H1으로만 연결했다. 한스 생활 농장 표본은 별도 배치 준비 프로필에서 이 H1의 정확 인스턴스와 기존 `gm-node:hans-house`를 대응시켰다.

현재 결과는 파일 기반 준비와 회귀 검사까지다. 동결 배치 맵, 정확 좌표·거리·수량, Prefab fingerprint, Unity Scene·실제 입력·Game View는 없으므로 프로필은 `BalancedDraft / Blocked`이며 E5로 승격하지 않는다.

## 반영 범위

- 일반 H1: `eng/world-seedbeds/synty-bottom-up-inventory/definitions/h1/farm-residential-home.v2.json`
- 사람이 읽는 H1: `eng/world-seedbeds/synty-bottom-up-inventory/authored/h1/farm-residential-home.v2.md`
- 일반 H2의 선택 관계: `eng/world-seedbeds/synty-bottom-up-inventory/definitions/h2/forest-edge-farm.v2.json`
- 한스 전용 준비 프로필: `eng/world-seedbeds/placement-map-profiles/forest-edge-farm-hans-living-farm.v1.json`
- 기준 기획: `docs/AI/숲경계농장-H1-H2-배치맵-기획-2026-09-02.md`의 `forest-edge-farm-placement-map-planning.r11`, SHA-256 `E09128B2E8371F5AF6ABD3F36BCA611330A3D60DC48D8F97D7D6EC740BF7E97B`

H1은 건물 정체성, 점유 외곽, 출입구, 안팎 경계, 시야 단서, 소유·사용 허용만 소유한다. 휴식·도구 보관·생산·작업 행위는 기존 H1·WI 책임으로 남겼다. 일반 `forest-edge-farm`의 모든 인스턴스에 주택을 강제하지 않고 한스 프로필에서만 `RequiredForThisProfile`로 요구한다.

## 산출물 괘상과 추적성

기존 WI의 `actionGwae`·`operationGwae`·`targetGwae`·`supportGwae`는 변경하지 않았다. 산출물용 비권위 메타데이터만 다음처럼 분리했다.

- 계획을 세우는 행위: `GAN`
- 검토·승인되어 동결된 기획 결과물: `RI`
- Graph Map 산출물: `GAN`
- 배치 맵 산출물: `TAE`

Graph Map 기획 인계 원장과 관리기에 `RI / GAN / TAE` 대응 및 오입력 거부 검사를 준비했고, 한스 배치 준비 프로필에는 `artifactGwaeCode: TAE`를 기록했다. 이 값은 실행 명령, 개발 순서, 상태 권위, 자동 Evidence 승격을 뜻하지 않는다.

괘상은 객체의 고정 본질로 쓰지 않는다. 한스 프로필은 수동 기획 입력이므로 `dataSourceKindCode: ManualPlanning`을 기록했지만, 실제 이동·운송·관측 관계를 수집한 자료가 아니므로 `relationGwaeCode`는 `null`로 유지했다. 숲길 진입이나 집↔밭 이동에 `GAM`을 붙이려면 출발·도착 안정 ID와 실제 근거 revision·hash·시각·계보가 있는 별도 관계 레코드가 먼저 필요하다.

공식 Graph Map 생성물 재생성은 완료로 세지 않았다. 현재 `docs/AI/PLANNING.md`와 진행 중 `eng/world-seedbeds/graph-maps/northern-life-hub-discovery.v1.json`이 기존 통합 인계 원장의 기대 hash와 달라 관리기가 `PlanningSource:graph-map-handoff:northern-life-hub-discovery:r10:HashMismatch`에서 조기 중단했다. 해당 기획·Graph Map 변경의 소유권과 의미를 확인하지 않은 채 기대 hash를 갱신하거나 진행 중 Graph Map을 수정하지 않았다.

## 검증

통과:

- 공간 지식 v2: `H1=53; H2=38; H3=20`
- 공간 지식 v3: `H1=85(기능 53 + 표현 32); H2=38; H3=20; H4=6`
- 공간 자원 재고: `H1=85/8; H2=39/0; H3=20/5; H4=6/1`
- 공간 지식 회귀: 새 H1의 휴식·보관 책임 흡수 금지, H2 선택 관계, 한스 인스턴스·Graph 노드·r11 hash·`TAE`·`ManualPlanning`·관계 괘상 미적용·`Blocked` 확인
- 공간 자원 재고 회귀 통과

부분 통과·차단:

- Graph Map 관리기는 새 괘상 필드 자체를 읽고 정확 코드 검사를 지난 뒤 기존 기획 source hash 불일치에서 중단했다.
- 공식 Graph Map JSON·Markdown 생성물 재생성과 전체 Graph Map 인계 회귀는 미완료다.

## 가장 이른 후속

1. Graph Map 소유자가 현재 기획 목차 변경과 진행 중 Graph Map 변경을 별도 검토해 기존 r10 통합 결과를 새 판본으로 다시 동결한다.
2. 그 판본의 source·plan·generated·report hash를 함께 갱신한 뒤 Graph Map 기획 인계 생성·회귀를 다시 수행한다.
3. 한스 배치 맵의 정확 제약, 인스턴스 수, 자산 후보 fingerprint를 동결하기 전까지 프로필은 `Blocked`를 유지한다.
4. Unity 적용·Scene 저장·Play Mode·Game View는 별도 승인과 단독 실행 증거가 있을 때만 수행한다.

이번 작업에서 commit·push는 수행하지 않았다.
