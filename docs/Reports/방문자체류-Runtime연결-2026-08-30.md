# 방문자 체류 Runtime 연결 — D286

## 범위와 현재 판정

기존 `playable-loop:nature-camp-visitor-stay.v1 / WI-COMMUNITY-VISITOR-STAY`의 승인된 E5 구현 중 연결부 한 묶음이다. **Logic E4 / Presentation E4 / 통합 E4, E5Pending**을 유지한다. 독립 원장 시험을 실제 Session·저장·세계 배치 완료로 보고하지 않는다.

- [승인 기획](../Architecture/PlayableLoops/Nature야영지방문자임시체류.md) r3: `87F6CF282753D70908BEC278441122F5B6DD094713C599F305BB91E504AEC920` 직접 일치.
- [Accepted 연구](../Architecture/PlayableLoops/Nature야영지방문자임시체류-E5표현연구.r2.md) r2: `847D2A57CA215CD9B3310B2AD70331CF3A8F2D7586492E1964621E98346C67E0` 직접 일치.
- [작업 명세](../../eng/execution-ledgers/work-orders/nature-camp-visitor-stay.e7-work-order.json): 최종 E7 목표·이번 E5 상한·beyond=false 유지. 기존 workItem에 수정 경로와 이번 시험 범위만 추가한다.

## 실제 코드 통합

- Application `RuntimeCore/Simulation방문자체류Runtime.cs`: 조회·Preview·Confirm 포트. 기존 `ISimulationRuntimeModules`에 `CommunityVisitors`를 추가하고 `LocalSimulationRuntime`의 직렬 실행/취소 경계를 재사용한다. 기존 기본 `ISimulationRuntime` 계약은 그대로다.
- Local Runtime은 기존 `Simulation공동체방문자체류Service`를 호출한다. 규칙 복제·UI 전용 성공 처리 없이 같은 원장의 상태 사본을 반환한다.
- Server DI와 `Controllers/Simulation방문자체류Controller.cs`: `api/simulation/v1/community-visitor-stay-ledgers/{ledgerStableId}`의 GET 및 `previews`, `confirmations` POST가 같은 서비스로 연결된다. 기존 공통 오류 필터를 재사용한다.
- 서버 메모리 원장 생성은 이번 API로 노출하지 않았다. 실제 Session의 Actor 권한 검증·원장 생성/귀속이 아직 없으므로 이 연결을 운영용 또는 실제 Hosted 플레이 완료로 사용하면 안 된다.
- 전문 애니메이션 산출물은 변경하지 않았다. 상태→이동/애니메이션 연결, 동일 상태 반복 조회 시 Greet 재발행 방지는 후속 표현 통합 사항이다.

## 남은 기술 연결과 기획 판단

1. 실제 Session/Actor에 방문자 원장을 귀속하고 권한·현재 Session 개정 검사를 결속한다. 독립 원장 개정을 Session 세계 개정으로 오인하지 않는다.
2. Session 상태·행위 기록·명령 결과를 원자적으로 결속하고 지식과 공동 예약한 Save 판본을 실제 현행 기준으로 확인한다. 과거 읽기/hash 의미·Replay·Load 재조회가 필요하다.
3. 최신 상태 사본을 대기/휴식/귀환 위치와 단일 Actor에 연결하고 전문 Adapter의 최초 인사·복원·중단·실제 이동을 검증한다.

이번 연결부에 새 플레이어 선택은 필요하지 않다. 위 항목은 기존 승인 범위의 기술 작업이다. HB-01은 별도 D356 추가 승인을 따르며 방문자 규칙이나 신규 NPC 선정·고용으로 확대하지 않는다. 새 E 승격·Scene 변경·commit/push 없음.
