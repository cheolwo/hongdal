## 작업 등록과 실제 상태

현재는 연구 5.1 A Accepted 결속 뒤 코드 통합 중이다. 개발 변경은 Unity 공용AnimationAdapter.cs와 신규 공용AnimationOwnershipTests.cs(+meta) 3파일이다. `TryAcquireExternalPose`/`ReleaseExternalPose`/`HasExternalPoseOwner`로 fallback 뼈 쓰기를 잠시 넘기고 원래 Animator 활성 상태·기준 자세·최신 이동 의도를 보존한다. 남아 있는 Graph/다른 Controller가 있으면 복귀를 거부한다. 통합 Editor 컴파일 통과 보고를 수신했다. 첫 전문 시험22/23의 정지 EditMode lifecycle 가정을 수정했고 공용8/9에서 Graph.Destroy 직후에도 Animator 연결이 남는 경계를 확인했다. 전문 소유 output을 SetTarget(null)로 먼저 분리한 뒤 Graph.Destroy하도록 수정, 공용 시험도 같은 실제 해제 계약을 검증한다. 보호조건 완화 없이 최종 전문23/23·공용9/9 정식 EditMode 시험을 통과했다. 개발은 `artifacts/local/validation/nature-woodcutting-d359/specialist-final.xml` 및 `shared-final.xml`을 직접 읽어 Passed/failed0/skipped0을 확인했다. Nature Presenter/Bootstrap의 실제 Task 소비 연결은 미완료다.

현재 개발 소스 hash: Adapter `CA44CA909C3117787DAB1FEB60BC1550F017822649F24167B3F9E06734B8B5F3`, 시험 `46A8564DD874DA4A12B777667DC2084FE9823DC9343D1540E8C079B1C6497565`(분리 전 시험 hash72751856…EF69는 첫 실행 이력). 명세의 외부 시험2경로 예약 추가 후 hash `774CCA01E9C4725B013B7CFE75092ED520FFEF120DB94C44FE46D6A350BF92B1`로 작업 목록을 동기화했다. 아래 이전 hash/거부 기록은 각 시점 이력이다.

최초 Goal r54 등록에서 기존 주제기획 공란으로 Active 검사가 거부됐다. D360의 [정식 기획](../Architecture/PlayableLoops/Nature도끼벌목오두막기초.md) SHA256 `27FA2C4E1945A9BF68E38D517BF28F1D2482FE098A7379662CDDCEFA81BB7407`을 직접 대조해 Loop r38의 기획 관문/출처와 명세에 결속했다. ## 담당과 쓰기 경계

최종 Editor lease는 애니 담당이 반환했다. 전문 보고 기준 stopped/compilefalse, canonical dirtyfalse/root2/선택[]/저장 Scene hash 불변·기존 Preview1, 전문 Graph/Adapter0이다. 그러나 첫 공용 실패시험의 `D359_Ownership_Test` 2개가 Utility에서 valid=true/output1/Animator 대상 null로 남았다. 출력 분리/Destroy 후 로컬 핸들은 false였으나 잔존 원인은 미확정이다. 전체 Graph0/완전 정리 통과로 세지 않으며 강제 Play/재시작/Scene reload는 하지 않았다. Console에는 초기 컴파일 및 TestResultCollector 중복완료 예외가 남아 무오류라고 보고하지 않는다. 이 잔여 baseline을 공간 담당에게 전달한 뒤 LS01 읽기 슬롯을 인계했다.

최종 [전문 인계](Nature벌목동작-D359-제작인계-2026-08-30.md) SHA256 `94E3B5645A48EB1417EC1D5E8CD19F3C1AA1674E26DC344A8BDBFD861040CCEF`를 직접 확인하고 전체 내용을 검토했다. `delivery-files.json`의 전문 전달20파일을 현행 파일과 대조해20/20 일치했다. 최종 Runner XML 텍스트 보존본2개도 보고서 hash와 일치하고23/23·9/9 Passed를 재확인했다. 보존본은 개행 정규화된 사본이며 생성 파일의 원시 byte hash와 동일하다는 뜻은 아니다. 이 검토는 A 코드·시험 산출물 인수이고 실제 WI 통합 승인/Goal Integrated/E 승격이 아니다. 개발의 이번 최종 대조에서는 Editor를 조회하거나 조작하지 않았다.

## 개발이 확인한 연결 위험

- `공용AnimationAdapter` SHA256 `CCFDE217940F3493E907A469123540A2423DE36C7F7EA2C1C88153FB4AA198BF`: fallback Configure는 Animator controller를 비우고 뼈 확보 뒤 평가를 끈다. LateUpdate에서 전신 절차형 자세를 기록한다. Clip만 추가하면 자동 재생되지 않는다.
- `Nature감각표현Presenter` SHA256 `F08A8E2753CB671D8745E7373313AFD59E89E959C4EEAB2DBD1EEDE90F07C404`: Working 동안 별도 LateUpdate가 팔/척추를 기록한다. 공용 Adapter와 같은 뼈를 경쟁 작성할 수 있으므로 새 연결에서 작성자를 하나로 정한다. 실제 화면 충돌 재현 판정은 아니다.
- `Nature감각표현Models` SHA256 `413E473C6783AFE7E5A230537609E73DF04875299B991DF9C07B726255A52C62`: 접촉 Audio/FX Cue는 CompletedSeconds 증가를 읽고, 기존 도구 회전은 `unscaledTime × 1.55`로 별도 진행한다. 새 Clip 접촉과 시간/상태 연결이 필요하다.
- 표현 WorkState에는 Kind/Target/RequiredSeconds/CompletedSeconds만 있다. 별도 Task ID가 있다고 가정하지 않는다. 같은 Session/상태 판본·대상·시작/복원/취소를 구분해 중복 시작/접촉/완료 재생을 막되 권위 완료나 시간을 Animation Event로 생성하지 않는다.
