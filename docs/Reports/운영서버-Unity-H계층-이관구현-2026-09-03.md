# 운영 서버 0.0~3.5 → Mirror Unity·H 계층 선별 이관 구현

## 결과

운영 서버의 페이지·저장 경계를 그대로 Unity 객체로 복제하지 않고, 실제 플레이 가능성에 따라 선별하는 재생성 가능한 대장을 구현했다.

| 조사 모수 | 현행 수 | 의미 |
| --- | ---: | --- |
| 페이지 기능 규칙 | 241 | 0.0~3.5와 역할 앱의 실제 기능 진입점 |
| EF Core `DbSet` 선언 | 271 | 서버·공공데이터·Simulation 투영의 저장 후보. H 자동 생성 근거 아님 |
| MongoDB `GetCollection` 사용 지점 | 28 | 공동 원장·증적·내부 문서의 사용 지점. 물리 collection 확정 수와 구별 |
| 기존 Unity 대표 경로 | 18 | 이미 수동으로 World·Panel·Action·Web 인계가 분류된 대표 route |

페이지 기능 241개는 다음처럼 판정됐다.

| 이관 등급 | 수 | 처리 원칙 |
| --- | ---: | --- |
| `PlayableAction` | 67 | 명시적 선택·확인 뒤 서버 권위 결과를 재조회 |
| `ReadOnlyContext` | 111 | 선택형 상세·근거·이력을 Panel 또는 World Object에서 조회 |
| `AmbientSimulation` | 59 | 저장 없는 NPC·차량·상태 흐름으로 표현 |
| `ServerOnly` | 4 | 관리자·인사·민감 정보는 Unity 직접 실행 금지 |

이 숫자는 구현 완료 수가 아니라 **이관 검토 모수와 기본 판정**이다.

## H1·H2 대응 원칙

- H1은 DB 행이 아니라 플레이어가 식별·접근하는 과업 공간 또는 상호작용 지점이다.
- H2는 둘 이상의 H1을 시작·선택·결과·귀환으로 연결하는 독립 업무 블록이다.
- 페이지와 H는 다대다 후보 관계다.
- `MappedCandidate`는 의미 후보일 뿐 Prefab 적합성, 실제 배치, 입력, E5를 증명하지 않는다.
- H가 부족한 기능은 기존 H를 억지로 재사용하지 않고 `HMappingRequired` 또는 `Optional`로 남긴다.

현행 H 대장의 실제 안정 ID는 H1 85, H2 38, H3 20, H4 6이다. 대장 안의 선언 요약 H2 18, H3 10, H4 5와 차이가 있어 생성기가 경고한다. 이번 작업은 다른 작업이 수정 중인 중앙 H 대장을 덮어쓰지 않았다.

## 첫 독립 표본

첫 표본은 `playable-loop:hub-inbound-putaway.v1`의 Hub 입고·검수·적치다.

- WI: `WI-001`, `WI-002`
- H1: `h1-stock:hub-receiving-storage`
- H2: `h2-candidate:hub-inbound-storage`, `h2-candidate:hub-internal-warehouse`
- 서버 route: `api/v1/warehouse-operations/world/zones/warehouse`
- 서버 계약·조회와 Unity Repository·Interpreter·Presenter: 기존 구현 재사용
- 기획 관문: `operations-unity-transfer.r1`로 결속
- 현행 Presentation: E1
- 다음 준비 목표: E4
- E5: 실제 Prefab·World 배치·Renderer/Collider/Bounds·입력·동일 revision 관측 전까지 차단

Hub를 먼저 택한 이유는 서버 Snapshot과 Unity 소비 계약이 이미 양쪽에 있어 새 API를 만들지 않고도 권위 경계를 검증할 수 있기 때문이다. 이것은 게임의 강제 첫 방문 순서가 아니다.

## 검증

- 생성기 프로젝트 빌드: 경고 0, 오류 0
- 전용 구조 회귀: 20/20
- 생성 후 `Check`: 동일 출력 확인

현행 전체 주제 기획 검사는 이번 Hub 관문이 아니라 기존 활성 `work:farm-crop-cycle:landscape-binding-guard`의 `landscape-composition.inquiry.r1.md` 기준 hash 불일치에서 먼저 차단된다. 해당 다른 작업의 원문·기준 hash는 이번 범위에서 고치지 않았다.

Unity Editor, Play Mode, Game View, Scene 저장, Prefab 배치, 서버 실제 연결, 운영 DB 변경은 실행하지 않았다. 따라서 이번 결과는 전수 조사·선별 정책·기획 결속·E4 이전 준비 도구의 구현이며 E5 또는 플레이 완성 증거가 아니다.
