# WI 애니메이션 — 보유 자산 대조와 제작 우선순위

- 기준: [D361 운영 원문](../Architecture/PlayableLoops/WI애니메이션보완제작운영.md) `wi-animation-gap-production.r1`, SHA256 `1850CC51B12D3BE0AD2A733AAC9E5495B16837FC96E5B731A81A9ECD382CFAA9` 전체 읽기·일치 확인.
- 조사일: 2026-08-30. D359 벌목 첫 작업을 유지한다. 이 문서는 읽기 조사/최소 제작 후보이며 다른 동작 제작·새 구매·공유 코드 수정 지시가 아니다.
- 반환: 애니메이션→개발 통합 담당→기획. 코드·원장·Scene·공급사 원본·방문자 산출물은 수정하지 않았다.

## 결론

**이동용 Clip이 없는 것이 아니라 현재 Nature 플레이어에 연결되지 않은 부분이 있고, 벌목은 기존 검술 Clip을 그대로 쓸 수 없는 접촉/자세 문제가 있다.** 먼저 D359와 작업 취소의 뼈 소유/진행 동기화를 해결하고, 이동 전환은 보유 Clip 연결을 우선한다. 줍기·농사·운반·컵 동작은 최소 동작 후보이지만 아직 모든 내장 Clip을 실제 평가하지 않았으므로 전부 '자산 없음'으로 확정하지 않는다.

실제 플레이 사용 횟수 로그/텔레메트리는 수집하지 않았다. 아래 우선순위는 현재 상태 소비 코드, 활성 작업 목록, 반복 호출 경로와 연결 실패의 영향에 근거한 **정성적 순위**다. 측정하지 않은 사용 빈도 숫자나 전체 미구현 WI 수를 Clip 제작 수로 바꾸지 않는다.

## 5. 개발 배분 제안

1. **D359/P0**: 연구5.1의 비생성 기존 Clip 소비와 중단/복귀를 먼저 Accepted 결속한다. 원본 hash·진행 토큰·작성자 소유·Load/재시작을 전문 독립 시험하고 개발이 실제 Task로 통합한다. 손잡이·발·나무 접촉 통과 전 '벌목 제작 완료'라 부르지 않는다.
2. **이동/P1**: 현재 보유 Idle/Walk/Run/Turn을 동일 실제 Actor에서 시험하고 각도·속도·정지 전환을 연결한다. 기존 방문자 산출물을 다시 만들지 말고 소비 계약을 비교한다.
3. **줍기·농사/P2**: 관찰 범위에서 사용할 전용 Clip이 확인되지 않은 실제 활성 행위 하나를 골라 높이/그립/도구/취소 기준을 명세화한다. 뜻이 비슷한 검술 Clip을 억지로 모든 작업에 대입하지 않는다.
4. **운반·컵/P3**: 실제 진행/완료/중단 상태 공급과 손 점유 계약이 준비되는 순서로 한 동작군씩 배분한다. 현재 D359를 중단하고 미래 동작 수십 개를 먼저 만들지 않는다.
