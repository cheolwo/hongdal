## 입력·출력 계약

`SimulationFarmH2PlacementAdapter.Convert(request, surfaceReader)`를 호출한다. 입력은 호출자가 고정한 사본이어야 하며 변환 중 병렬 수정하지 않는다.

- `CandidateJson`, `ExpectedCandidateHashSha256`: 원후보 결과. r1 schema/패턴·입력 hash·표면 hash·전체 결과 hash 및 거부 사유를 확인한다. hash 정상이어도 기존 급경사 거부 결과는 변환하지 않는다.
- `MapPlan`: 실제 지도 정규형 hash, CellX/CellY, CellStableId, SourceWorldRevision, H 결속·허용 Anchor를 갖는 현행 사본. 원후보 Revision 0을 실제 세션 Revision으로 쓰지 않는다.
- `OwnerCellStableId`, `AreaSetStableId`, `H2StableId`: 같은 Cell 및 지도 안의 H4 AreaSet/H2 소유를 요구한다. AreaSet은 승인 연구의 `area-set:sim:pyeongchang:farm-production.v1`이다. 각 출력 배치의 H1과 CompositionKey가 지도 H1/Anchor에 존재해야 한다.
- Cell 월드 원점과 후보의 셀 내부 원점은 각각 명시한다. 단위는 m, 축은 XRight/YUp/ZForward, 전체 방향은 0/90/180/270도, Scale은 양의 균일 Scale이다. CellX/CellY로 임의 원점을 추측하지 않는다. 변환된 외곽·보존 영역·통로가 소유 셀을 넘으면 거부한다.
- `Bindings`: 원후보 배치 ID → 실제 배치 ID/H1/의미 VisualKey/자산 계열/CompositionKey의 전수 연결. 중복 ID·누락·알 수 없는 역할/키는 거부한다. 생산 구획은 기존 `farm:감자밭 두렁:A/B/C`만 허용한다. 나머지 키도 호출자가 실제 resolver에서 확인한 목록에 있어야 한다.
- `ResolverRevision/HashSha256`는 실제 resolver 출처 fingerprint이며 `ResolvedCompositionKeys`는 그 소비 결과다. Adapter가 Unity 대장을 직접 읽거나 이름이 비슷한 Prefab을 찾지 않는다. 호출자는 목록과 fingerprint를 같은 대장 판본에서 제공해야 한다. 시험의 Well/풀 키는 `fixture-resolved:*`라는 명시적 합성 키이며 실제 resolver에 등록됐다는 뜻이 아니다.
- `Measurement`: 회전0/Scale1에서 **pivot 상대 활성 외곽 중심/크기**, 적용 균일 Scale, Renderer/Collider 활성, 자산 fingerprint·측정 revision·근거 위치와 측정 내용 hash를 제공한다. `ComputeMeasurementHash`로 내용 봉인을 계산한다. `SyntheticFixture`와 `MeasuredWrapper`는 출처 표시이며 후자를 입력했다는 이유로 E5를 승인하지 않는다.
- `WorkAreaWidth/DepthMeters`, `WorkAreaEvidenceRef`: 생산 표시 외곽과 구별되는 통행 포함 H1 작업공간 치수다. 기존 모판 최소14/12·최대56/48m 및 표시 외곽 포함을 검사한다. 이 수치는 생산 면적100㎡나 수확량의 계산 입력이 아니다. 실제 WorkArea의 세밀한 통행/점유 배선은 통합 검증 대상이다.
- `Policy`: 측정/기존 Player 설정 출처와 함께 호출자가 값을 제공한다. 기본 게임 수치는 없다. trial 여부를 출력에 보존한다.
- `ISimulationFarmH2SurfaceReader`: 명시한 revision/hash의 **읽기 전용** 월드 높이·경사·지지 가능 표본 공급자다. 실제 LH/Collider 표면 Adapter는 Unity 통합 담당이 제공한다. 새 noise 엔진 또는 장기 복제 계산기를 추가하지 않았다.

## 변환과 검증 의미

실제 로컬 배치 중심은 `후보 외곽 중심 × 전체 Scale → 전체 회전 → 셀 내부 원점`이다. 출력 pivot X/Z는 이 중심에서 회전·Scale을 적용한 **측정 외곽 중심 offset**을 뺀 값이며 Y는 `변환된 후보 Bottom - (측정 CenterY - SizeY/2) × 적용 Scale`이다. 후보 AABB 중심을 Prefab pivot이라고 가정하지 않는다.

측정 외곽이 후보 예약 외곽을 넘으면 임의 축소·이동·대체하지 않고 거부한다. 활성 외곽의 9개 지지점에서 지지·경사·높이 편차·최고 지면 대비 매몰/부유를 검사한다. 객체 이격, 보존/마당 침범, 보호통로의 전체 중앙/양쪽 표본, 높이 단차와 graph 연결도 검사한다. 표면 읽기가 같은 좌표에서 바뀌거나 읽기 도중 revision/hash가 달라지면 거부한다. 표면 보정·평탄화 API는 없다.

출력에는 원후보 Seed/PatternRevision/InputHash/SurfaceHash/ResultHash, 별도 변환 입력 정규형 hash, 실제 조회한 표본의 hash, 현행 배치 계획 hash, 전체 반환 묶음 hash가 있다. 매핑 입력 배열 순서와 문화권 변화는 같은 정규형 hash를 유지한다. 원후보 r1 hash는 기존 직렬화 순서를 존중하며 손상 JSON·중복 속성을 거부한다. 원후보 hash를 현행 배치 hash 필드에 복사하지 않는다.

현행 Plan의 `ChangeProjectionHashSha256`, `SpawnDecisionPlanHashSha256`, `SourceChangeStableIds`에 가짜 WI/Spawn 계보를 넣지 않는다. 변환 계보는 반환 묶음이 소유한다. 측정 fingerprint만 바뀌고 위치·의미가 같으면 배치 내용 hash는 같을 수 있으나 변환 입력/반환 묶음 hash는 바뀐다. 소비자는 **반환 묶음 hash도 함께 고정**해야 한다.

`PartitionFrozen(result)`는 반환 묶음과 현행 계획 hash를 재검사하고, 기존 분리 서비스가 입력 배열을 공유하는 경계를 고려해 복사본을 넘긴다. 반환된 현행 분리 계획을 기존 LH `Prepare`, 이어 `Transition(Active/Cached/Released/Prepared)`에 넘긴다. 이 단계에는 후보 생성기·표면 reader·자산 선택 호출이 없다. 실내는 연구대로 빈/비적용 계획이다. LH 표현 Revision과 SourceWorldRevision은 별개다.
