# 현재 구현 기준 플레이어 진행 가능성 보고서

작성일: 2026-08-28
판정 기준: 현재 저장소의 PlayableLoop 대장, 증거 묶음, canonical Unity Scene과 실제 입력 시험 코드

## 1. 먼저 알아야 할 결론

현재 Ssalddel은 여러 영역을 자유롭게 오가는 완성 게임이라기보다, **Nature 생활거점의 첫날을 실제로 조작할 수 있는 Solo 프로토타입**에 가장 가깝다.

플레이어가 현재 가장 확실하게 진행할 수 있는 흐름은 다음 두 폐루프다.

1. 도끼를 얻고 장착한다.
2. 나무를 베고 지면에 떨어진 통나무를 획득한다.
3. 오두막을 배치·건설하고 안전한 선택 상태로 돌아온다.
4. 황혼 위협을 확인한다.
5. 관찰 운영, 직접 개입 또는 후퇴 중 하나로 대응한다.
6. 전투 또는 후퇴 결과를 남기고 거점으로 돌아온다.

이 두 묶음은 논리와 표현이 모두 E7이며 `PlayClosed`로 판정되어 있다. 실제 Input System 입력, 저장·Scene 재진입, LocalProcess·RemoteHost 동등성 근거도 보유한다. 다만 새 `simulation-save.v28` 행위 원장 기준의 E8 반복 안정성은 다시 검증해야 하므로, **현재 플레이 가능**과 **최신 판본에서 장기간 고정된 완성 후보**를 같은 의미로 보아서는 안 된다.

그 다음 흐름인 자원 보관 → 수면 → Day2 → 확장 계획과 작업대 건설은 코드와 과거 Play Mode 실행 근거가 있지만 현재 통합 관문에서는 다시 열려 있다. Farm·Hub·Town·City는 플레이 약속과 Simulation 규칙의 일부가 마련되어 있으나, 지금 플레이어가 설명 없이 화면에서 끝까지 진행할 수 있는 영역은 아니다.

## 2. 현재 실행 형태

| 구분 | 현재 상태 | 플레이어 관점의 의미 |
| --- | --- | --- |
| 공식 Unity 진입점 | `SimulationWorldShell` 하나 | 기능별 공식 Scene을 고르는 방식이 아니라 한 Scene에서 영역 모듈을 조립한다. |
| Solo | `LocalProcess` | 서버 연결 없이 동일 Simulation Core를 로컬에서 실행하는 것이 기본 방향이며 Nature 시험이 이 경로를 사용한다. |
| Hosted | `RemoteHost` | 같은 권위 규칙과 저장 결과의 동등성 시험은 있으나, 이번 보고서에서 실제 멀티플레이 화면을 확인한 것은 아니다. |
| 배포 형태 | Unity Editor Play Mode 근거 | 일반 사용자용 실행 파일, 시작 메뉴, 튜토리얼을 포함한 배포 빌드의 완성은 주장할 수 없다. |
| 외부 자료 | 플레이 중 Provider 호출을 기본 경로로 삼지 않음 | 플레이 도중 인터넷 자료를 기다리며 세계 상태를 결정하는 구조가 아니다. |

따라서 지금 직접 확인하려면 Unity 프로젝트 `C:\Users\user\ssalddel`에서 canonical Scene인 `Assets/Ssalddel/Scenes/SimulationWorldShell.unity`를 여는 개발자 실행 경로가 기준이다. 이번 보고서 작성에서는 Unity를 다시 실행하거나 Game View를 새로 캡처하지 않았고, 저장된 코드·시험·기존 증거를 조사했다.

## 3. 플레이어가 실제로 진행할 수 있는 Nature 첫날

### 3.1 시작과 시점 선택

플레이어 표현 계층에는 다음 시점 입력이 있다.

| 입력 | 기능 |
| --- | --- |
| `F1` | 플레이어 시점에서 나가기 |
| `F2` | 1인칭 탐색 시점 |
| `F3` | 3인칭 운영 시점 |

1인칭에서는 `WASD` 또는 방향키로 이동하고, `Shift`로 빠르게 이동하며, 마우스로 시선을 돌린다. 3인칭에서는 플레이어를 왼쪽 클릭으로 선택하고 오른쪽 클릭으로 이동 목적지를 정한다. `WASD`는 전술 카메라 이동, 마우스 가운데 버튼은 시점 회전, 휠은 확대·축소, `F`는 선택한 플레이어에 카메라 초점을 맞추는 입력이다.

같은 키가 상황에 따라 다른 의미를 가질 수 있다. 예를 들어 황혼 조우가 활성화되면 `F`는 카메라 초점보다 전투 개입 문맥이 우선한다.

### 3.2 도끼 획득과 명시적 장착

플레이어는 화면의 도끼 배치 객체를 왼쪽 클릭해 획득한다. 도끼를 단순히 보유하는 것만으로는 벌목할 수 없으며, 다음 과정을 거친다.

1. `I`로 장착 상태창을 연다.
2. 보유 도끼를 눌러 `MainHand`에 장착한다.
3. 손 도끼 표현이 생성된 것을 확인한다.
4. 필요하면 장비 슬롯을 눌러 해제할 수 있다.
5. 도끼를 해제한 채 벌목을 시도하면 작업이 차단된다.

이 흐름은 장비를 숫자 보유량으로만 처리하지 않고, **획득 → 장착 → 세계 행위 허용**을 분리해 실제 입력 시험으로 검증한 부분이다.

### 3.3 벌목과 통나무 획득

장착 후 나무를 왼쪽 클릭하면 상호작용 거리까지 보조 접근할 수 있다. 벌목은 왼쪽 버튼을 유지하는 작업이며, `C`로 진행 중 작업을 취소할 수 있다. 취소하면 나무와 자원 수량이 원상태로 남는다.

벌목이 끝나면 통나무가 단순 HUD 숫자로 즉시 지급되는 것이 아니라 지면 획득물로 생성되고, 플레이어가 다시 획득한다. 현재 논리 근거에는 중복 획득 방지, 용량 차단, Save/Replay 복원이 포함되어 있다.

### 3.4 오두막 배치와 건설

필요한 통나무를 확보한 뒤 `B`로 건설 문맥에 들어가 오두막 위치를 정하고 건설한다. 진행 중인 건설 또는 작업은 `C`로 취소할 수 있고, 취소된 예약 자원은 반환되어야 한다. 완성된 오두막은 생활거점이 되며 `E`로 내부·외부 전이 문맥을 사용한다.

이 단계가 끝나면 플레이어는 단순히 건물을 한 개 만든 상태가 아니라, 다음 위협에 대응하거나 보관·수면을 선택할 수 있는 안전 거점으로 돌아온다.

### 3.5 황혼 위협 대응

황혼 조우가 열리면 다음 실제 입력 경로가 검증되어 있다.

| 선택 | 입력 예 | 현재 의미 |
| --- | --- | --- |
| 위협 확인 | `O` | 조우를 관찰하고 대응 문맥을 확정한다. |
| 안전 후퇴 | `O` → `R` | 조우를 `Retreat` 결과로 끝내고 거점 선택으로 돌아온다. |
| 직접 개입 | `O` → `F` → 전투 왼쪽 클릭 | `DirectAction` 전투를 생성하고 플레이어가 직접 공격에 개입한다. |
| 관찰 운영 | 관찰 운영 참여 방식으로 전투 진행 | 플레이어가 전술 상황을 관찰하는 경로가 있으며 직접 개입과 별도 결과 계보를 가진다. |

직접 개입과 후퇴는 단순 화면 효과가 아니라 Simulation의 권위 전투 결과, 최종 `WorldRevision`, 저장 및 재진입 상태로 이어진다. 현재 근거는 승리뿐 아니라 후퇴도 유효한 폐루프 복귀로 취급한다.

## 4. 이어서 할 수 있지만 현재 재검증 중인 흐름

### 4.1 자원 보관 → 수면 → Day2 확장 계획

현재 코드 입력은 다음과 같다.

| 입력 | 기능 |
| --- | --- |
| `G` | 오두막에 자원 보관 |
| `T` | 오두막에서 수면 |
| `1`, `2`, `3` | Day2 확장 계획 선택 |
| `F8` | 개발용 진단 표시 |

과거 실제 입력 시험에서는 자원 보관, 황혼 후퇴, 수면, 새벽 전환, 숫자 `1`을 통한 작업대 계획 선택과 저장 재진입이 동작했다. 그러나 현재 `simulation-save.v28`의 행위 원장·분야 성장·표현 엔진 cursor 인계가 추가되면서 기존 표현 E6/E7 근거가 현재 승격 근거로는 무효화되었다.

현재 판정은 Logic E5, Presentation E4, 통합 E4다. 즉 **기능이 사라졌다는 뜻은 아니지만, 최신 구조에서 플레이어가 끝까지 진행한 현재 증거가 아직 없다는 뜻**이다.

### 4.2 Day2 작업대

작업대는 위치·비용 확인, 지면 Preview·Confirm, `C` 취소와 자원 반환, 재배치, 20초 건설, Synty Construction 표현까지 과거 Play Mode에서 검증되었다. 현재 판정은 Logic E7, Presentation E6, 통합 E6다.

따라서 논리적으로는 거의 닫혔지만, 현재 행위 기록 구조와 같은 판본에서 최신 Game View 판독·실제 입력·표현 인계를 다시 확인해야 `PlayClosed`라고 부를 수 있다.

## 6. 플레이어 상태와 성장

현재 Simulation에는 성공한 플레이어 행위를 기록하고, 그 계보를 분야 성장으로 해석하는 기반이 있다. 첫 카탈로그는 16개 분야를 가지며, 직접 수행에서 생기는 `현장 숙련도`와 명시적 위임·완료·검토 계보에서 생기는 `운영 숙련도`를 구분한다.

중요한 경계는 다음과 같다.

- NPC가 일을 완료했다는 이유만으로 플레이어 숙련도가 자동 증가하지 않는다.
- 취소되었거나 권위 세계 변화로 확정되지 않은 입력은 성장 근거가 아니다.
- LH·Sky·실외 배치·실내 배치 엔진은 행위 기록을 필요할 때 읽는 소비자이며, 플레이어 파이프라인에 종속되어 즉시 세계를 임의 변경하지 않는다.
- 현재 Unity에는 도끼 장착 상태창이 있지만, 16개 분야 성장과 개인화 결과를 플레이어가 읽는 통합 상태창은 아직 구현·Game View 검증되지 않았다.

따라서 현재 플레이의 보상은 오두막 완성, 자원 상태, 조우 결과와 귀환처럼 세계 안에서 보이는 결과가 중심이다. 장기 성장 수치는 저장 기반이 마련되었지만 아직 완성된 플레이어 피드백 화면은 아니다.

## 7. 현재 게임을 한 문장으로 체험하면

> 플레이어는 Nature 안전 빈터에서 도끼를 획득·장착하고 나무를 베어 생활거점을 세운 뒤, 황혼 위협을 관찰하거나 직접 싸우거나 후퇴하여 결과를 저장하고 다시 거점 선택으로 돌아올 수 있다.

그 뒤의 의도된 연속 흐름은 다음과 같지만, 굵은 앞부분만 현재 E7로 닫혀 있다.

**도끼 → 벌목 → 통나무 → 오두막 → 황혼 대응 → 귀환** → 보관 → 수면 → Day2 계획 → 작업대 → 현장 보급 → 다음 원정

Farm·Hub·Town·City는 이 Nature 흐름 다음에 자동으로 이어지는 선형 캠페인이 아니다. 각 영역은 독립된 내부 폐루프를 먼저 완성한 뒤 명시적인 영역 간 연결 작업에서 이어져야 한다.

## 8. 기획서를 쓰기 전에 구분해야 할 것

현재 코드에 기능과 계약이 많아도, 플레이어가 체감하는 게임 기준선은 아직 Nature 첫날 두 폐루프다. 다음 기획서는 다음 세 층을 혼동하지 않는 것이 좋다.

1. **지금 플레이 가능한 것**: 도끼·장착·벌목·통나무·오두막, 황혼 대응·귀환.
2. **현재 Goal에서 닫아야 할 것**: 보관·수면·Day2 계획의 최신 행위 원장과 표현 인계.
3. **다음 승인 기획을 거쳐야 할 것**: 작업대 이후 보급·학습, Farm·Hub·Town·City 독립 폐루프.

현재 Goal은 `playable-loop:nature-night-day2.v1`이고, 과거 진행분을 보존하는 `LegacyActiveMigration` 상태다. 그 다음 Goal부터는 하나의 PlayableUnit에 대응하는 승인된 주제 기획서가 있어야 활성화된다. 현재 16개 후보 중 `Approved` 기획은 0개이므로, 새 기능 수를 늘리기 전에 **플레이어가 Nature 첫날을 왜 반복하고 싶은지, Day2에 어떤 의미 있는 다음 선택을 얻는지**를 다음 주제 기획에서 먼저 확정하는 것이 현재 개발 체계와 맞는다.
