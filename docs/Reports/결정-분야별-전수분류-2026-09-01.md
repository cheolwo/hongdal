## 결론

`DECISIONS.md`에 실제 존재하는 결정 제목 **486개**를 모두 조사해 **11개 주분야·63개 세부주제** 중 하나에 대응했다. 각 결정은 기존 전역 이력 번호, 새 분야별 ID, 자연어 제목과 검토 깊이를 함께 가진다.

분야별 ID는 아래 세 층을 한 이름에 담는다.

```text
주분야 → 세부주제 → 그 세부주제 안의 누적 순번
D-GAMEPLAY-PLAYER-RECOVERY-RESOURCES-033
```

따라서 사용자는 전체 작성 순서를 알려면 `D-###`를, 특정 분야의 결정 축적량과 상세 내용을 보려면 분야별 ID와 자연어 제목을 사용한다.

## 전수성에서 발견한 원장 문제

- 최댓값은 `D-489`이지만 고유 전역 번호는 485개다.
- `D-422`, `D-423`, `D-424`, `D-425`는 원장에 존재하지 않는다. 과거 공백을 새 결정으로 소급 채우지 않는다.
- `D-096`은 카메라 결정과 타로 결정이 같은 전역 번호를 사용한다. 기존 앵커를 조용히 바꾸지 않고 `D-096#1`, `D-096#2`로 색인하며 각각 `D-PRESENTATION-WORLD-CAMERA-STREAMING-001`, `D-GAMEPLAY-TAROT-001`을 부여했다.
- 분야별 ID 486개에는 중복이 없다.

## 검토 깊이

| 검토 상태 | 수 | 의미 |
| --- | ---: | --- |
| `BodyReviewed` | 16 | D-474~D-489는 이번 요동성·결정 명명·WI 관계·Graph Map 인계 기획에서 본문까지 직접 재검토했다. |
| `TitleReviewed` | 470 | 제목과 인접한 결정 흐름을 전수 대조해 1차 분야를 확정했다. 개별 본문의 대체 관계·현재 유효 범위까지 모두 다시 판정했다는 뜻은 아니다. |

이번 결과는 **전수 목록·분야 분류 완료**다. 과거 470개까지 전부 현재 정책으로 재승인하거나 구현 상태를 다시 판정한 것은 아니다. 앞으로 Farm, Nature, 데이터, 월드처럼 특정 분야를 다시 기획할 때 해당 세부주제의 `TitleReviewed` 항목을 본문 검토하고 필요하면 분류를 수정한다. 수정해도 분야별 번호를 재사용하거나 다른 결정을 앞 번호로 끼워 넣지 않는다.

## 조회와 유지 절차

1. [결정 분야별 전수 색인](../AI/generated/decision-field-index.md)에서 주분야와 세부주제의 수를 본다.
2. 전체 대응표에서 분야별 ID나 자연어 제목으로 원하는 결정을 찾는다.
3. `TitleReviewed` 결정이 현재 기획에 직접 영향을 주면 원문 본문·대체 관계·상태를 다시 읽는다.
4. 새 결정은 기존 전역 `D-###`와 분야별 ID를 함께 기록한다.
5. `generate-decision-field-index.ps1 -Mode Write`로 산출물을 갱신하고 `-Mode Validate`로 누락·중복·현재 원문 일치를 검사한다.

이 색인은 기획 결정의 탐색 체계다. 결정 수가 많다는 사실을 구현 완료, Unity 배치, Game View 검증 또는 E 성숙도로 해석하지 않는다.
