# Graph Map 배치 규칙 통합

- 날짜: 2026-09-01
- 범위: 북부 생활권 Graph Map 레벨 2와 기존 배치 구조·제약 체계의 파일 기반 결속
- 결과: 구현·자동 회귀 완료, Unity 실제 적용 미수행

## 결과

Graph Map이 자체 배치 규칙을 새로 소유하지 않고 기존 `h5-world-layout-policy.r4`의 5개 Area 프로필과 21개 `placementRuleCodes`를 판본째 읽도록 통합했다. H1~H4 공간 계층과 `LhComposed | PlayerComposed | HybridEvolving` 형성 방식도 함께 대조하지만, Graph Map은 H 성립이나 배치 계획 계산을 수행하지 않는다.

현재 Graph Map 제약과 직접 연결된 규칙은 5개다.

- Farm `ProductionProcessingSeparation` → `gm-constraint:farm-flow-separation`
- Hub `VehicleTurningRadius` → `gm-constraint:route-capability-separation`
- Hub `InboundInspectionPutawaySequence`, `OutboundStagingSeparation` → `gm-constraint:hub-entry-contact-exit`
- Town `ServiceTrafficControl` → `gm-constraint:route-capability-separation`

나머지는 대상·수치·실측이 없는 `AvailableNotSelected` 또는 현재 Graph Map 밖 City의 `OutsideCurrentGraph`로 남겼다. 계보·증거·계절 표현·자산 후보·영역 독립 제약은 장소별 규칙을 억지로 붙이지 않고 `GovernanceOnly`로 분리했다.

## 변경 구조

- 단일 결속 원본: `eng/world-seedbeds/graph-maps/placement-rule-bindings.v1.json`
- Graph Map 계획: 레벨 2에서 위 카탈로그 판본을 참조
- 계획 관리자: 원본 Area·규칙 코드 1:1 대조, H 계층·형성 방식 drift, 규칙→제약 대상 Area, 전체 제약 분류를 검사
- 생성 조회: Area별 규칙의 적용·미선택·맵 밖 상태와 제약별 규칙/관리 경계를 표시
- 개발 인계: 선택 제약과 직접 연결된 `placementRuleRefs`만 함께 전달

## 증거 경계

이번 결과는 문서·JSON·PowerShell 관리 도구의 구조와 회귀 근거다. 배치 계획 계산, Prefab 선택·생성, Scene 저장, Play Mode, Game View, 실제 지지·통행·입력, H 성립, E5/E6 승격을 수행하지 않았다. `AvailableNotSelected` 규칙은 구현 대기열이나 자동 개발 명령이 아니다.
