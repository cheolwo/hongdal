## 식별과 현재 위치

- 문답 고유 식별자: `inquiry:[playable-loop-name].r1`
- 대상 주제: `topic:[name].v1`
- 대상 PlayableLoop: `playable-loop:[name].v1`
- 기록 revision: `[name].inquiry.r1`
- 상태: `Open`
- 현재 주제 Code: `[짧은 한국어 주제]`
- 현재 탐구 깊이: `D1 | D2 | D3 | D4 | D5`
- 현재 질문 ID: `Q-[주제]-D1-01`
- 현재 전체 호환 번호: `Q-001`
- 마지막 확인 질문 ID: `없음`
- 마지막 확인 전체 호환 번호: `없음`
- 반영 대상 기획 revision: `[name].design.r1`

탐구 깊이는 Evidence와 동일한 단계가 아니지만 어떤 E 구현을 준비할 수 있는지 보여 주는 예상 관계를 가진다. 질문 답변만으로 E를 승격하지 않으며 실제 E는 작업 명세와 EvidencePackage에서만 가져온다. 기존 전체 `Q-001` 번호는 재번호화하지 않는다.

| 깊이 | 범위 | 예상 E 준비 | 상태 | 확인된 결과 | 다음 공백 |

| `D4` | 건물·H·배치·자산·표현 | Presentation `E4`, 양 궤적 `E5` 착수 | `대기` |  |  |

상태는 `대기 | 진행 중 | 확인 | 재개 필요 | NotApplicable` 중 하나를 사용한다. D1→D5는 선형 완료 단계가 아니며 뒤 질문에서 누락이 발견되면 앞 깊이를 다시 연다.
