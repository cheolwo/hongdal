# HIOPS AI 판단 사례집

이 문서는 HIOPS에 붙일 AI 판단 보조를 만들기 전에, 사람이 먼저 검토할 수 있는 구체적인 판단 사례를 쌓기 위한 문서다.

AI를 바로 학습시키기보다 먼저 여러 상황을 만들어 보고, 각 참여자의 입장과 충돌 지점을 적고, AI 초안 판단을 작성한 뒤 사용자가 판정을 내린다. 사용자의 판정이 쌓이면 나중에 RAG, 프롬프트 개선, 규칙 보정, 모델 학습 데이터의 기준이 된다.

문화교통 1.0에서는 [HIOPS AI 우선 도입 기준](../Architecture/HIOPSAI.md)에 따라 공동구매 참여 의사와 집단화 설명 사례를 먼저 쌓는다. `국내 화물 운송 배차 조율 AI` 사례는 살뜰 2.0 운송 자산으로 보존하며, 실제 자동 배차 판단은 허가·운영 경계가 준비되기 전 활성화하지 않는다.

현재 서버 코드에서는 `배차AI판단근거조회Service`가 이 사례집의 일부 사례를 구조화된 seed로 참조한다. 처음에는 키워드 기반 조회로 플랫폼 수익 묶음 AI와 기사 배정 AI에 판단 근거 ID를 붙이고, 이후 사용자 판정과 실제 운송 결과가 쌓이면 같은 사례 형식을 임베딩 검색이나 RAG 원장으로 확장한다.

## 사례 작성 형식

| 항목 | 내용 |
| --- | --- |
| 사례 ID | OS와 번호를 조합한다. 예: `DCT-001` |
| 관련 OS | 국내 화물 운송 OS, 공동주문 수입 OS, 창고·커머스 이행 OS 등 |
| 상황 | 화물, 장소, 시간, 비용, 증빙, 참여자 상태를 구체적으로 적는다. |
| 참여자 입장 | 화주, 기사, 수령자, 운영자 등 각자의 기대와 부담을 나눈다. |
| 충돌 지점 | 빠른 처리, 비용, 거리, 대기, 책임, 증빙이 어디서 충돌하는지 적는다. |
| AI 초안 판단 | AI가 제안할 배정, 보류, 제외, 운영자 확인 판단을 적는다. |
| 설명 문구 | 앱이나 운영 화면에 보여줄 수 있는 짧은 이유를 적는다. |
| 사용자 판정 | `동의`, `수정 필요`, `반대`, `보류` 중 하나로 사용자가 판단한다. |
| 중용 판정 | `중용 적중`, `화주 중심 과다`, `기사 중심 과다`, `비용 중심 과다`, `증빙 부족`, `운영자 확인 필요`, `판정 보류` 중 하나로 표시한다. |
| 최종 판단 | 사용자가 조정한 최종 판단을 적는다. AI 초안과 같을 수도 있고 다를 수도 있다. |
| 학습 가치 | `학습 우선`, `참고`, `제외`, `보류` 중 하나로 표시한다. |
| 사용자 메모 | 사용자가 보정해야 할 기준을 적는다. |

## 판정 기준

1. 한 참여자의 편의만 과하게 우선하지 않는다.
2. 법적 책임, 증빙, 정산이 흐려지는 판단은 운영자 확인으로 보낸다.
3. 차량 적합성, 온도 조건, 상하차 장비처럼 필수 조건은 거리보다 먼저 본다.
4. 오래 기다린 기사나 의뢰는 Aging으로 보정하되, 필수 조건을 깨지는 않는다.
5. AI 판단은 사람이 납득할 수 있는 이유를 남겨야 한다.

## 중용 판정 기준

| 판정 | 의미 |
| --- | --- |
| 중용 적중 | 여러 참여자의 입장, 책임, 비용, 시간, 증빙을 균형 있게 고려한 판단 |
| 화주 중심 과다 | 화주의 편의나 비용 절감만 과하게 반영하고 기사 부담이나 증빙 위험을 낮게 본 판단 |
| 기사 중심 과다 | 기사 수익, 거리, 대기 보정만 과하게 반영하고 화주 조건이나 수령자 확인을 낮게 본 판단 |
| 비용 중심 과다 | 비용 절감만 우선해 품질, 책임, 증빙, 신뢰를 약화시킨 판단 |
| 증빙 부족 | 판단 자체는 가능해 보이나 사진, 서명, POD, 문서, 로그가 부족해 나중에 분쟁 위험이 있는 판단 |
| 운영자 확인 필요 | AI나 규칙만으로 확정하면 위험하고 운영자가 책임 경계나 예외를 확인해야 하는 판단 |
| 판정 보류 | 아직 사용자가 판단하지 않았거나 정보가 부족한 상태 |
