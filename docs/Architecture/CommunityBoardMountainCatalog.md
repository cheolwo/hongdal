# 간괘 게시판 산맥과 Command·Event·Page 묶음

## 결정

커뮤니티 게시판은 두 층으로 확정한다.

1. 사람이 글의 목적을 선택하는 일반 게시판
2. 성공한 Command와 발생한 Event를 비식별 글로 관찰하는 버전 업무 게시판

업무 게시판은 Command/Event 하나마다 새 게시판을 만들지 않는다. `0.0`, `1.0`, `1.5`, `2.0`, `2.5`, `3.0`, `3.5`의 일곱 버전 흐름을 각각 하나의 게시판으로 묶는다.

각 게시판은 간괘 `☶`의 산으로 표현한다. 산은 독립된 책임 경계를, 능선은 여러 Command·Event와 관련 단일책임 페이지가 한 업무 목적 아래 이어짐을 뜻한다.

## 확정한 일반 게시판

| 그룹 | 게시판 |
| --- | --- |
| 사람과 정보 | 서원, 자유·생활, 질문·도움, 정보·시세, 음식, 반야 |
| 함께하는 일 | 화물, 모집·함께하기, 판매·공급, 진행·공동 원장, 완료 사례·후기 |
| 서비스 운영 | 공지·이용안내, 개선 제안 |
| 보호 영역 | 신고·분쟁 — 공개 게시판이 아니라 안전센터에서 보호 |

관리자가 만든 확장 게시판은 별도로 유지할 수 있지만, 아래 일곱 시스템 게시판의 Command/Event 연결을 대신하거나 분할하지 않는다.

## 확정한 일곱 업무 게시판

| 버전 | 게시판 카드 | Command | Event | 관련 페이지 | 핵심 범위 |

| 1.0 | 문화교통 1.0 · 공동구매 | 0 | 1 | 4 | 개별 원함, 집단화, 공동 원장 |
| 1.5 | 문화교통 1.5 · 공급·무역 준비 | 1 | 5 | 6 | 공급, HS 검토, 통관 동의·수임·절차 |

| 2.5 | 살뜰 2.5 · 창고·판매 이행 | 0 | 7 | 6 | 출고, 입고, 검수, 적재, 피킹, 인계 |

실제 이름과 Route의 기준은 `CommunityActivityBoardCatalog.Bundles`다. 게시판 모음에서 각 카드를 펼치면 연결된 Command, Event, Web·App 페이지를 확인한다. Web에서 실제 제공되는 목록 Route만 바로 열고 stable-ID 템플릿이나 전용 App Route는 점검 대상으로만 표시한다.

## 글 생성과 조회

- Command pipeline은 성공 응답 뒤 등록된 Command 활동만 발행한다.
- Event handler는 등록된 Event 발생 사실만 발행한다.
- 두 활동 모두 해당 버전 업무 게시판의 같은 Category를 사용한다.
- 게시판 상단 고정 안내 글은 그 산에 속한 전체 Command, Event와 관련 페이지를 열거한다.
- 예전에 Command/Event별 게시판 이름이나 key로 작성된 글은 새 버전 게시판의 별칭으로 함께 조회한다.

## 공개 경계

- 공개 글에는 사용자·업체 식별자, 연락처, 상세 주소, 위치, 금액, 결제 정보, 첨부와 원본 payload를 넣지 않는다.
- 신고·분쟁, 결제 승인 상세, 파일 업로드와 법적·민감 Event는 활동 게시판 발행 대상에서 제외한다.
- 게시판 글은 업무 발생을 관찰하는 투영이며 원장 상태를 확정하거나 다음 Command를 자동 실행하지 않는다.
