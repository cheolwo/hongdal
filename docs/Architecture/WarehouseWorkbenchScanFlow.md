# Warehouse Workbench Scan Flow

창고 업무는 작업자 확인만으로 바로 공정에 들어가지 않는다. 공정에 따라 실제 작업대까지 확인해야 한다. 이 문서는 입고/포장 시작 흐름과 입고 상품 확인 개념을 고정한다.

## 핵심 개념

### 작업자 확인

작업자가 휴대폰 번호 뒤 8자리를 입력해 본인이 누구인지 확인하는 단계다. 이 단계는 사람과 공정 역할을 확인한다.

### 작업대 확인

작업자가 실제로 어느 작업대에서 일하는지 작업대 바코드로 확인하는 단계다. 같은 입고 담당자라도 검수대, 입고대, 포장대가 다를 수 있으므로 사람 확인과 분리한다.

### 입고 확인

상품이 실제로 창고에 들어왔다는 사실과 실제 입고 수량을 확인하는 단계다. 입고 확인은 검수와 다르다. 입고 확인은 "들어왔다"는 상태 변경이고, 검수는 "정상인지 확인한다"는 품질/수량 판단이다.

### 검수

입고 확인된 상품을 대상으로 수량 차이, 파손, 유통기한, 보관 조건을 확인하는 단계다. 수량 차이가 있으면 검수 단계에서 사유를 남기고 후속 조치를 연결한다.

## 현재 적용

`WarehouseManagerApp`에서 다음 공정은 휴대폰 번호 뒤 8자리로 작업자를 확인한 뒤 작업대 바코드를 추가로 확인한다.

- 입고: `/work/inbound` -> `/work/inbound/workbench`
- 포장: `/work/packing` -> `/work/packing/workbench`

입고 작업대 확인 후에는 상품 바코드 확인 화면(`/work/inbound/products`)으로 이동한다. 포장 작업대 확인 후에는 현재 현장 작업 보드(`/work-board`)로 이동한다.

## 입고 흐름

현재 연결된 조회·작성 흐름은 다음 순서로 진행한다.

1. 휴대폰 번호 뒤 8자리로 작업자를 확인한다.
2. 입고 작업대 바코드를 입력한다.
3. 상품 바코드를 입력한다.
4. 선택한 창고에서 상품 바코드와 정확히 일치하는 `입고예정` 원장을 조회한다.
5. 일치 원장이 있으면 사용자가 선택한 같은 입고 ID를 서버에서 다시 조회한다.
6. 일치 원장이 없고 상품이 실제 현장에 반입된 경우에만 안내를 확인하고 현장 입고 요청을 저장한다.
7. 저장 결과의 같은 입고 ID와 `입고예정` 상태를 다시 조회한다.

실제 입고 수량 확정, 입고 완료, 재고 생성과 검수 항목 생성은 아직 이 페이지의 책임이 아니다. 이 작업은 별도 P3 서버 상태 전이에서 현재 상태와 권한을 다시 검증한 뒤 연결한다.

## 리팩터링 상태

`/work/inbound/products` 입고상품 수령 화면은 화면 안의 샘플 상품과 클라이언트 상태 변경을 제거했다. 다음 책임으로 분리한다.

- `입고상품수령창고ViewModel`: 접근 가능한 창고 목록과 선택
- `입고예정상품검색ViewModel`: 한 창고와 정확한 SKU 조회
- `현장입고요청작성ViewModel`: 최소 입력, 안내 동의와 멱등 요청 ID
- `입고상품수령상세ViewModel`: 선택하거나 생성한 같은 입고 ID 재조회
- `입고상품수령PageViewModel`: 위 책임의 순서 조정
- `SsalddelInboundReceivingWorkspace`: 공용 렌더링과 사용자 event 전달
- `I입출고작업Service`: 보호된 Controller API 호출

`IInboundReceivingWorkflowService`와 `SampleInboundReceivingWorkflowService`는 아직 다른 창고 prototype에 남아 있지만 이 라우트에서는 사용하지 않는다. 이 페이지는 서버 RDB의 입고요청만 조회·저장하며 API 실패를 샘플 성공으로 바꾸지 않는다.

## 바코드 형식

현재 UI에서 허용하는 작업대 바코드 예시 형식:

- `WB:IN-01`
- `WB:PK-03`
- `BENCH:A-01`
- `TABLE:P-02`

상품 바코드 예시:

- `SKU:MILK-001`
- `SKU:SALAD-SET`
- `SKU:WATER-6P`
- `ITEM:BOX-TAPE`

## 확장 방향

- 서버에서 작업자, 공정, 작업대 배정 가능 여부를 함께 검증한다.
- 작업대 바코드와 창고/구역/공정 권한을 연결한다.
- 입고 작업대, 포장 작업대, 검수대, 라벨 출력대 같은 작업대 유형을 DB로 관리한다.
- 작업대 확인 기록을 필수 업무 로그로 남긴다.
- 현장 입고 요청을 담당자가 검토하고 수락·취소하는 P3 상태 전이를 별도 Command로 추가한다.
- 입고 확인 상태 전환 뒤 검수 작업 항목을 멱등 생성하고 같은 입고 ID를 다시 조회한다.
- 검수·적재가 끝난 경우에만 재고를 생성하며 요청 저장만으로 재고를 만들지 않는다.
