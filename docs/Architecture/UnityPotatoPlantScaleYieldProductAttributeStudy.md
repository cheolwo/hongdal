# 감자 재배체 심층 연구: 재배 규모·생산 능력·품목 속성

## 1. 목적

이 문서는 모판 배치 객체 `seedbed-object:farm.potato-plant-visual.a`를 다음 세 갈래로 나누어 연구한다.

1. 재배 규모: Unity의 감자 재배체 하나가 현실과 Simulation에서 어느 단위를 대표하는가
2. 생산 능력: 재배 규모와 환경·투입·시설이 턴당 생육과 최종 생산량에 어떻게 반영되는가
3. 품목 속성: 감자가 수확된 뒤 포장·Pallet 적재·보관·운송·마트 진열로 넘어갈 수 있는 조건은 무엇인가

세 갈래는 순서대로 검토한다. 대표 단위를 정하지 않고 생산량을 계산하면 단위가 흔들리고, 생산 결과 단위를 정하지 않고 포장·운송 속성을 붙이면 화물 수량이 흔들리기 때문이다.

이 문서는 설계 연구다. 기존 서버 계약, 저장 데이터, API, 고유 식별자와 현재 Simulation Fixture를 변경하지 않는다.

## 2. 현재 코드에서 확인된 기준선

| 갈래 | 현재 구현된 사실 | 아직 없는 것 |
| --- | --- | --- |
| 재배 규모 | 재배 작기는 `PlotStableId`와 단일 `TileStableId`에 연결된다. 토양은 `GridWidth × GridHeight` Tile로 구성된다 | Tile의 물리 면적, 한 Tile의 포기 수·이랑 수, 재배체 Prefab 하나와 Tile 사이의 표현 배수 |
| 생산 능력 | 재배 규칙에 `BaseHarvestQuantityKg`가 있고 현재 감자 Fixture는 300kg이다. 수확 시 이 값을 그대로 수확 Lot 수량으로 사용한다 | 면적·포기 수·Tile 수에 따른 규모 계산, 환경 생육 결과와 최종 수확량 연결, 비료·시설 보정 |
| 환경 생육 | 기온·햇빛·토양수분 중 가장 낮은 계수와 토양 적합도로 일일 생육점수를 계산한다. 관수량은 토양수분 계산에 들어간다 | 관수가 최종 생산량에 미치는 규칙, 비료·병해·노동·시설 용량, 실제 운영 관수 제어 |
| 포장·운송 | 감자 전용 Fixture에 20kg 상자와 400kg 차량 용량이 있고 수량 보존을 검증한다 | 공통 품목 취급 Profile, Pallet 적재 규칙, 보관 조건, 운송 조건, 마트 진열 가능 조건 |

따라서 현재 300kg은 **한 포기·한 이랑·밭 전체 중 무엇의 생산량인지 계약으로 확정되지 않은 Fixture**다. 실제 수확량이나 운영 기준으로 해석하지 않는다.

## 3. 첫 번째 갈래: 재배 규모

### 3.1 먼저 답할 질문

1. 감자 재배체 하나는 실제 감자 한 포기인가
2. 한 이랑 또는 한 Tile의 작물 군집인가
3. 밭 전체 상태를 대표하는 표본인가
4. Unity에 보이는 식물 Mesh 수와 Simulation의 포기 수를 같게 볼 것인가
5. 밭을 넓힌다는 것은 Tile을 추가하는 것인가, Tile 면적을 키우는 것인가, 별도 재배 구역을 추가하는 것인가
6. 서로 다른 파종일·품종·토양·관수 상태를 가진 구역을 하나의 재배체로 합칠 수 있는가

### 3.2 후보 비교

| 후보 | 장점 | 문제 | 판정 |
| --- | --- | --- | --- |
| 실제 한 포기 | 현실 대응이 직관적이고 개체별 생육 표현 가능 | 넓은 밭에서 GameObject와 데이터 수가 과도하게 증가하고 현재 Tile 계약과 맞지 않음 | 기본 단위로 사용하지 않음 |
| 한 이랑 | 농작업 단위와 시각 구성이 자연스러움 | 이랑 길이·폭·포기 수가 없고 토양 Tile과 경계가 중복될 수 있음 | 물리 구성 단위 후보 |
| 한 Tile의 재배 군집 | 현재 `TileStableId`와 직접 연결되고 확장·집계가 쉬움 | Tile 물리 면적과 실제 식재 밀도가 아직 없음 | **첫 기준 단위로 권장** |
| 밭 전체 대표 | GameObject 수가 적고 멀리서 읽기 쉬움 | 구역별 생육 차이와 확장 효과를 숨김 | 멀리 보기 집계 표현으로만 사용 |

### 3.3 권장 해석

감자 재배체 배치 객체 하나는 실제 한 포기가 아니라 **한 재배 단위의 작물 군집을 표현하는 시각 모듈**로 본다. 현재 첫 재배 단위는 단일 `TileStableId`에 대응시킨다.

```text
Simulation 재배 단위 1개
    = 현재는 토양 Tile 1개
    = 재배 작기 0개 또는 1개
    = Unity에서는 여러 감자 Mesh로 표현 가능
    ≠ 실제 감자 한 포기
    ≠ 밭 전체 집계
```

Unity의 Mesh 개수는 표현 밀도일 뿐 생산량 계산의 입력이 아니다. 카메라 거리와 성능에 따라 세 개 또는 열 개의 식물을 보여줘도 같은 재배 단위를 뜻할 수 있다.

### 3.4 향후 계약에서 필요한 값

| 값 | 의미 | 주의점 |
| --- | --- | --- |
| 재배 단위 고유 식별자 | 생산량과 생육 상태를 묶는 기준 | 기존 `TileStableId`를 즉시 이름 변경하지 않음 |
| 면적 `m²` | 생산량의 규모 기준 | Grid 칸 수를 면적으로 추정하지 않음 |
| 유효 재배 면적 비율 | 통로·시설·미사용 공간을 제외한 비율 | 0~1 범위와 근거 필요 |
| 품종·재배 방식 | 같은 품목 안의 규칙 차이 | 기준 상품과 품종을 혼동하지 않음 |
| 파종일·작기 | 같은 밭의 시간 차이 | 다른 작기는 별도 재배 단위로 유지 |
| 표현 밀도 정책 | Mesh 수·성장 단계별 시각 Variant | 생산량과 분리된 Unity 표현 설정 |

### 3.5 규모 확장 규칙의 첫 원칙

밭을 넓히는 첫 Simulation 규칙은 **같은 면적의 재배 단위를 추가하는 것**으로 정의하는 편이 안전하다.

```text
밭 확장
    → 재배 단위 추가
    → 각 단위가 토양·작기·환경 상태를 독립 보존
    → 수확 시 단위별 수확 Lot 또는 명시적인 합산 Lot 생성
```

Tile 수만 늘었다고 생산량을 즉시 늘리지 않는다. 새 Tile이 실제 재배 중이고, 해당 작기가 수확 조건을 충족해야 생산량 집계에 포함한다.

### 3.6 첫 번째 갈래의 잠정 결론

이 배치 객체가 보여주는 것:

- 단일 재배 단위에 속한 감자 군집
- 해당 재배 단위의 생육 단계와 환경 스트레스 요약
- 여러 재배 단위 중 선택된 위치

이 배치 객체가 결정하지 않는 것:

- 실제 포기 수
- 실제 면적
- 생산량
- 밭 확장 완료
- 수확 가능 여부

미확정 사항은 Tile 한 칸의 현실 기준 면적과 유효 재배 면적 비율의 공식 출처다. `POTATO-PRODUCTION-RULE-1`에서는 이 값을 규칙에 고정하지 않고 재배 단위 상태에서 명시적으로 받으며, 단일 Tile마다 별도 수확 Lot을 만드는 첫 계약을 구현했다. 테스트의 100m²는 기존 300kg Fixture 호환을 검증하기 위한 값이지 실제 면적 결정이 아니다.

## 4. 두 번째 갈래: 생산 능력

생산 능력은 감자만의 고립된 보너스 표가 아니라 [Simulation 생산·소비 공통 규칙](SimulationProductionConsumptionRuleModelProposal.md)의 자원 변동 유형과 효과 묶음을 사용한다. 밭 확장·관수·비료·온실은 생산량 플러스만 만드는 것이 아니라 현금·노동·물·에너지·용량의 감소 또는 예약을 함께 남긴다.

### 4.1 현재 규칙의 한계

현재 재배 생애주기는 생육 단계에 도달하면 `BaseHarvestQuantityKg`를 그대로 수확 Lot에 기록한다. 별도의 환경 생육 계산기는 기온·햇빛·물·토양 적합도로 일일 생육점수를 계산하지만 이 결과가 최종 수확량을 증감시키지는 않는다.

즉 현재 구조는 다음과 같다.

```text
경과일 또는 환경 생육점수
    → 생육 단계

고정 BaseHarvestQuantityKg
    → 수확 Lot 수량
```

규모·환경·투입이 생산량에 미치는 규칙은 아직 연결되지 않았다.

### 4.2 생산 능력을 구성할 층

| 층 | 질문 | 권장 책임 |
| --- | --- | --- |
| 기준 생산성 | 이 품목·품종·재배 방식은 단위 면적에서 얼마를 생산하는가 | 개정 번호와 출처가 있는 Simulation 규칙 |
| 재배 규모 | 실제 재배 중인 유효 면적은 얼마인가 | 재배 단위 상태 |
| 환경 충족 | 기온·햇빛·수분·토양이 생육 기간 동안 얼마나 충족됐는가 | 일일 환경 결과의 누적값 |
| 투입 효과 | 관수·비료 같은 투입이 부족을 얼마나 완화했는가 | 확인된 Simulation Command와 효과 규칙 |
| 시설 효과 | 온실 등이 환경 변동·기간·손실을 어떻게 바꾸는가 | 시설 Profile과 재배 단위 연결 |
| 손실·한계 | 침수·가뭄·병해·작업 부족·수용량 한계가 얼마를 줄이는가 | 별도 손실 규칙과 근거 |

### 4.3 권장 계산 구조

생산량을 보너스의 단순 합으로 무한히 키우지 않는다. 기준 규모를 먼저 계산하고, 출처가 있는 제한된 계수를 곱하는 구조를 권장한다.

```text
기준 생산량
    = 단위면적 기준 생산성(kg/m²)
    × 유효 재배 면적(m²)

예상 수확량
    = 기준 생산량
    × 누적 환경 충족 계수
    × 확인된 투입 효과 계수
    × 시설 효과 계수
    × 손실 계수
```

각 계수는 Simulation 규칙의 범위 안에서 상한·하한을 가져야 한다. 실제 농업 수치가 확인되지 않은 동안에는 Fixture임을 표시하고 운영 생산량으로 사용하지 않는다.

### 4.4 밭 확장과 턴당 생산 능력

밭 확장은 즉시 수확량을 지급하는 효과가 아니라 **동시에 운영할 수 있는 재배 단위 수와 잠재 생산 면적을 늘리는 효과**로 해석한다.

| 변화 | 즉시 달라지는 것 | 수확 시 달라지는 것 |
| --- | --- | --- |
| 재배 단위 추가 | 사용 가능한 면적·파종 후보 증가 | 실제 파종·생육·수확을 마친 단위만 생산량 추가 |
| 관수 설비 연결 | 관수 가능 범위·작업 후보 증가 | 물 부족 완화가 누적 환경 계수에 반영될 수 있음 |
| 비료 투입 | 비용·작업·투입 기록 증가 | 검증된 규칙이 있을 때만 생산성 또는 손실 계수 변경 |
| 온실 연결 | 보호 재배 가능 면적·환경 제어 후보 증가 | 검증된 시설 규칙이 있을 때 변동·손실·작기 변화 반영 |

### 4.5 플러스 규칙의 경계

- 관수는 물 부족을 완화할 수 있지만 충분한 강수 뒤에도 무조건 생산량을 더하는 보너스가 아니다.
- 비료는 품목·토양·투입량·시기에 따른 규칙 없이 고정 `+10%`로 두지 않는다.
- 온실은 모든 품목에 같은 생산량 보너스를 주지 않고 환경 범위·작기·시설 수용량을 통해 영향을 준다.
- 같은 효과를 환경 계수와 투입 계수에서 두 번 계산하지 않는다.
- Unity의 물 효과, 비료 자루, 온실 애니메이션은 생산 효과가 확정됐다는 근거가 아니다.
- 생산·소비·예약·이동·변환·손실은 같은 부호라도 서로 다른 규칙 유형으로 기록한다.

### 4.6 생산 능력 연구 질문 순서

1. 기준 생산성의 단위는 kg/포기, kg/이랑, kg/Tile, kg/m² 중 무엇인가
2. 재배 단위 면적과 유효 재배 면적 비율은 어디에서 오는가
3. 환경 생육점수를 생육 속도와 최종 수확량에 각각 어떻게 사용할 것인가
4. 가뭄·침수·저온·고온·저일사 스트레스는 회복 가능한가, 누적 손실인가
5. 관수는 어떤 조건에서 물 부족만 보완하는가
6. 비료는 어떤 별도 입력·토양 근거·상한을 가져야 하는가
7. 온실은 환경값 자체, 변동 폭, 작기 또는 손실 중 무엇을 바꾸는가
8. 여러 재배 단위의 생산량을 언제 하나의 수확 Lot으로 합칠 수 있는가

## 5. 세 번째 갈래: 품목 속성

### 5.1 품목 속성을 재배체에 넣지 않는 이유

포장·Pallet 적재·보관·운송·마트 진열 조건은 감자 재배체 Prefab의 속성이 아니다. 수확 전에는 작물 생육을 설명하고, 수확 뒤에는 기준 상품과 취급 Profile이 다음 업무 가능 여부를 설명해야 한다.

```text
감자 재배체
    → 생육 상태 표현

기준 상품
    → 품목·품종·기본 단위

품목 취급 Profile
    → 포장·Pallet·보관·운송·진열 조건

실제 Lot·화물·재고
    → 해당 Profile과 실제 수량·상태를 참조
```

### 5.2 공통 품목 취급 Profile 후보

| 속성 묶음 | 필요한 질문 | 예시 필드 후보 |
| --- | --- | --- |
| 포장 적합성 | 상자 포장이 가능한가, 허용 포장 형태와 단위는 무엇인가, 나머지 수량은 어떻게 처리하는가 | 허용 포장 유형, 포장당 순중량, 최소·최대 수량, 나머지 허용 정책 |
| Pallet 적재 적합성 | 어떤 포장을 몇 층·몇 개까지 적재할 수 있는가 | 층당 개수, 최대 층, 최대 중량, 높이·부피 한계 |
| 보관 적합성 | 어떤 시설과 환경에서 얼마 동안 보관할 수 있는가 | 시설 유형, 온도·습도 범위, 환기·광 차단, 최대 기간, 혼재 제한 |
| 운송 적합성 | 어떤 차량·용기·시간 조건이 필요한가 | 차량 유형, 온도 범위, 최대 이동 시간, 충격·압착·혼재 제한 |
| 마트 진열 적합성 | 어떤 상태와 포장·표시를 갖춰야 공개 판매 위치에 놓을 수 있는가 | 판매 단위, 포장·라벨 요건, 등급·상태, 진열 기간, 공개 가능 여부 |

숫자와 실제 감자 취급 조건은 공식 근거와 사람 검토 전에는 채우지 않는다. 현재 20kg 상자·400kg 차량은 Simulation Fixture로만 유지한다.

### 5.3 속성의 세 층 분리

| 층 | 예 | 변경 이유 |
| --- | --- | --- |
| 품목 고유 특성 | 품목 형태, 기본 질량 단위, 부패·압착 민감도 분류 | 품목이 바뀔 때 달라짐 |
| 취급 Profile | 국내 출하 상자, 특정 Pallet, 상온/저온 보관 방식 | 시장·시설·계약·규정에 따라 달라짐 |
| 실제 Lot 상태 | 실제 포장 수, 현재 온도, 현재 위치, 검수 결과 | 각 수확·화물·재고마다 달라짐 |

이 세 층을 분리하면 다른 작물도 같은 구조를 사용하고, 감자 전용 숫자를 공통 상품 속성으로 오인하는 일을 막을 수 있다.

### 5.4 업무 단계별 통과 조건

| 업무 전이 | 확인할 품목 속성 | 최종 결정 주체 |
| --- | --- | --- |
| 수확 Lot → 포장 Lot | 포장 유형·단위·나머지 처리·품질 상태 | 서버의 포장 미리보기와 확정 Command |
| 포장 Lot → Pallet | 포장 수·층·중량·외곽 범위 | 창고·출하 작업 원장 |
| Pallet → 차량 | 총중량·부피·혼재·차량 조건 | 운송 배차·상차 원장 |
| 화물 → 창고 보관 | 시설·환경·기간·검수 상태 | 창고 입고·보관 원장 |
| 창고 재고 → 마트 진열 | 판매 단위·라벨·상태·공개 범위 | 마트 재고·진열 작업 원장 |

Unity에서 상자가 Pallet 위에 놓이거나 상품이 Shelf에 나타난 것만으로 위 전이가 완료되지는 않는다. 실제 완료 여부는 서버의 기준 원장을 다시 조회해 확인한다.

### 5.5 품목 속성 연구 질문 순서

1. 포장 가능 여부는 품목 전체, 품종, 등급, 실제 Lot 중 어디에서 달라지는가
2. 포장 단위가 나누어떨어지지 않을 때 부분 포장·잔량·폐기 중 무엇을 허용하는가
3. Pallet 적재 가능 여부는 포장 Profile에서 파생되는가, 별도 Profile인가
4. 보관 조건은 품목 특성과 시설 능력을 어떻게 맞춰 판정하는가
5. 운송 조건은 보관 조건을 그대로 쓰는가, 이동 시간·충격·혼재를 별도로 보는가
6. 마트 진열 가능은 물리적 적합성과 판매·공개 권한을 어떻게 분리하는가
7. 같은 품목이라도 낱개·상자·Pallet·벌크 형태를 어떻게 구분하는가
8. 실제 Lot가 어떤 Profile 개정 번호와 근거를 사용했는지 어떻게 추적하는가

## 6. 세 갈래가 다시 만나는 지점

```text
재배 규모
    재배 단위·면적·작기
        ↓
생산 능력
    기준 생산성·환경·투입·시설·손실
        ↓
수확 Lot
    실제 수량·품질·출처
        ↓
품목 속성
    포장·Pallet·보관·운송·진열 적합성
        ↓
포장 Lot → 화물 → 창고 재고 → 마트 재고
```

감자 재배체는 이 가운데 재배 규모의 선택 단위와 생육 상태까지만 표현한다. 수확량·포장·운송·진열 상태를 재배체 하나에 모두 붙이지 않는다.

## 7. 다음 질문과 승격 조건

다음 대화와 연구는 첫 번째 갈래인 재배 규모부터 확정한다.

> 감자 재배체 하나를 `Tile 1개에 연결된 재배 군집`으로 볼 때, 그 Tile은 고정된 물리 면적을 가져야 하는가? 아니면 첫 Simulation에서는 면적 없는 추상 재배 단위로 유지할 것인가?

이 질문의 답이 정해져야 기준 생산성을 kg/Tile로 둘지 kg/m²로 둘지 결정할 수 있다.

세 갈래 연구가 끝나기 전에는 다음을 하지 않는다.

- 현재 300kg Fixture를 실제 면적 생산량으로 해석
- 비료·관수·온실에 임의의 고정 생산량 보너스 부여
- 20kg 상자·400kg 차량 Fixture를 운영 취급 기준으로 승격
- 감자 재배체 Prefab에 포장·보관·운송·진열 권한 저장
- Mesh 수를 포기 수 또는 생산량으로 사용
