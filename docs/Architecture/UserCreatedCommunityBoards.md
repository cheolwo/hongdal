# 사용자 개설 커뮤니티 게시판

홍달의 고정 목적별 게시판은 기본 정보 구조로 유지한다. 사용자가 새로운 주제 공간을 원하면 로그인 계정으로 개설을 신청하고, 서버 관리자가 목적과 운영 가능성을 검토해 승인한 뒤에만 실제 게시판으로 공개한다.

## 흐름

```mermaid
flowchart LR
    A["로그인 사용자"] --> B["게시판 이름·설명·개설 이유 신청"]
    B --> C["승인 대기"]
    C -->|"관리자 승인"| D["공개 게시판 목록"]
    C -->|"관리자 반려"| E["반려 기록"]
    D --> F["게시글 작성 가능"]
```

## 권한과 공개 범위

- 공개 게시판 목록은 익명으로 읽을 수 있지만 승인 완료 게시판만 반환한다.
- 개설 신청은 로그인 사용자만 할 수 있다. 신청 계정 ID는 서버 인증 Claim에서 가져오며 요청 본문 값으로 대체하지 않는다.
- 신청자가 입력한 이름은 공개용 별칭으로 취급하고 실제 계정 ID와 분리한다.
- 승인 대기·반려 사유·운영 메모 목록은 `서버관리자전용` 정책을 통과한 관리자만 조회한다.
- 승인과 반려에는 검토한 관리자 계정 ID를 감사 정보로 남긴다.
- 한 신청을 승인한 뒤 다시 반려하는 식의 중복 상태 전이는 허용하지 않는다.

## 남용 방지

- 한 사용자가 동시에 승인 대기 상태로 둘 수 있는 신청은 최대 3개다.
- 기존 고정 게시판과 같은 이름은 신청할 수 없다.
- 같은 앱에서 이미 승인되었거나 승인 대기인 게시판 이름은 다시 신청할 수 없다.
- 게시글 생성·수정 시에도 고정 게시판 또는 승인된 사용자 게시판인지 서버가 다시 검사한다. 클라이언트가 임의의 카테고리 문자열을 보내 승인 절차를 우회할 수 없다.

## API

| 용도 | 경로 | 권한 |
| --- | --- | --- |
| 승인 게시판 공개 목록 | `GET /api/v1/community/boards` | 익명 허용 |
| 관리자 신청 목록 | `GET /api/v1/community/boards/requests` | 서버 관리자 |
| 게시판 개설 신청 | `POST /api/v1/community/boards` | 로그인 사용자 |
| 승인 | `POST /api/v1/community/boards/{id}/approve` | 서버 관리자 |
| 반려 | `POST /api/v1/community/boards/{id}/reject` | 서버 관리자 |

승인된 게시판의 신청자는 초기 운영 주체로 해석할 수 있도록 계정 식별자를 보존한다. 게시판별 부관리자 지정, 운영권 이전, 폐쇄·휴면과 이의 신청은 별도 상태 전이와 감사 Event를 갖춘 후속 기능으로 둔다.
