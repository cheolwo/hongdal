# Ssalddel 게임 기획 통합 기준

- 기준일: 2026-08-24
- 문서 성격: 게임 세계·카드·사건·플레이어 경험의 단일 개념 기준
- 현재 우선 플레이: `Nature 생존 생활거점`
- 적용 범위: Simulation과 Unity의 게임 기획 의미
- 비적용 범위: 운영 서버의 실제 계약·결제·발주·재고 효과

## 목적과 문서 권위

이 문서는 여러 기획서에 흩어진 타로, 광복기·암흑기, 심리 영역, 업무 영역, 세계 사건, WI와 플레이어 선택의 **상호 관계**를 한곳에서 관리한다. 세부 카드 수치, 공간 조립법, E/G/H 완료 관문과 구현 현황은 각 전문 문서가 계속 소유한다.

문서나 코드가 충돌하면 다음 순서로 판단한다.

1. 실제 계약·Domain·시험과 저장·재생 형식
2. [확정 결정](../AI/DECISIONS.md)
3. 이 통합 기획 기준
4. 카드·공간·시나리오별 세부 설계
5. 과거 제안서와 변경 기록

이 문서는 기존 세부 문서를 삭제하거나 내용을 모두 복제하지 않는다. 대신 공통 개념의 이름, 관계와 책임을 소유하고 세부 문서가 어느 질문에 답하는지를 고정한다.

## 게임의 중심 약속

> 플레이어는 Nature에서 생존 기반을 만들고 여러 업무 영역에서 선택과 작업을 수행한다. 그 결과는 세계의 회복과 위협에 누적되고, 카드와 사건은 달라진 상황을 해석할 새로운 선택을 제안한다. Simulation은 조건·비용·시간·결과를 판정하고 Unity는 이를 탐색하고 이해하고 조작할 수 있게 표현한다.

현재 첫 실제 플레이 폐루프는 다음과 같다.

```text
안전 빈터 등장
  └─ 도끼 획득
     └─ 벌목과 통나무 획득
        └─ 오두막 건설
           └─ 황혼 위협
              ├─ 전투
              └─ 후퇴
                 └─ 회복과 재출발
```

과거의 `14일 동안 감자 300kg을 농장에서 마트까지 공급` 시나리오는 일반 타로와 경영 규칙을 검증하는 참고 세로 조각이다. 현재 게임 전체의 시작 조건이나 Farm·Hub·City의 의존 순서를 뜻하지 않는다.

## 세계 영역과 인과

### 심리 영역

Nature 중심의 상시 체류 세계를 `심리 영역`이라 부른다. 이것은 외부 세계가 플레이어의 마음에서 만들어진다는 설정이 아니다. 업무와 생존 결과가 플레이어의 회복력과 위협 상태에 남긴 영향을 공간과 플레이로 읽을 수 있게 만든 영역이다.

회복과 위협은 하나의 양끝 점수가 아니라 별도 축이다.

- 좋은 확정 결과는 회복을 강화하고 위협을 완화할 수 있다.
- 나쁜 확정 결과와 기한 초과는 회복을 약화하고 위협을 강화할 수 있다.
- Preview 차단, 단순 취소와 아직 일어나지 않은 제안은 회복·위협 입력이 아니다.
- 심리 영역의 행동은 피해 확산을 완충할 수 있지만 업무 사건의 직접 원인을 종료하지 않는다.

### 업무 영역

Farm·Town·Hub·City는 각각 독립적인 `업무 영역`이다. 각 영역은 내부 선택 폐루프, Fixture, 상태·저장 경계와 완료 증거를 먼저 가진다. 한 영역의 결과를 다른 영역 개발의 필수 시작 상태로 사용하지 않는다.

업무 사건의 원인 해결은 사건이 발생한 업무 영역의 WI가 담당한다. 그 확정 결과만 심리 영역의 회복·위협에 전달한다.

### 평시·광복기·암흑기

세 상태는 전 세계에 일괄 적용되는 역사 시대가 아니라 **플레이어별 심리 기간 상태**다.

| 상태 | 뜻 | 현재 규칙 |
| --- | --- | --- |
| 평시 | 회복과 위협 어느 쪽도 기간 전환 기준을 충족하지 않음 | 기본 상태 |
| 광복기 | 회복이 우세해 복구·확장 기회가 열리는 시기 | 회복 비중 `80% 이상` 진입, `75% 미만` 이탈 |
| 암흑기 | 위협이 우세해 생존·방어·복구가 중심이 되는 시기 | 위협 비중 `80% 이상` 진입, `75% 미만` 이탈 |

`광복기`는 역사적 시대 재현을 뜻하지 않도록 사람이 읽는 문서와 UI에서 처음 한 번 `광복기(회복 우세기)`로 병기한다. `암흑기`도 단순한 화면 색상이나 분위기가 아니라 Simulation이 판정한 위협 우세 기간이다.

현재 `80% / 75%`는 구현된 정책 개정의 값이다. 이후 플레이테스트로 변경할 수 있지만, 변경할 때는 규칙 개정·저장 호환·결정성 시험을 함께 갱신한다.

### 두 발전소

`회복 발전소`와 `위협 발전소`는 회복·위협 상태를 읽고 대응할 수 있게 만드는 심리 영역의 H2 복합 공간 후보다.

- 발전소는 업무 성공이나 실패의 원인을 만들지 않는다.
- 발전소 표현이 업무 원장을 변경하지 않는다.
- 회복·위협 상태를 같은 수치나 하나의 발전소로 합치지 않는다.
- 실제 H1 등록, H2/H3 조립, Scene 배치와 Game View는 각각 별도 증거가 필요하다.

## 카드 체계

### 카드의 공통 역할

카드는 세계 상태를 직접 확정하는 버튼이 아니라 상황을 읽고 선택을 구성하는 게임 문법이다.

```text
카드 또는 문맥 제안
  → 플레이어가 의미와 대가를 비교
  → 허용된 대응 선택
  → WI Preview
  → 명시적 Confirm
  → Task 또는 WorldTick
  → 확정 상태 재조회
```

카드가 자원·생산량·재고·사건·H 공간을 직접 생성해서는 안 된다. 권한, 수량 보존, 단위, 용량, 상태 전이와 Simulation·Operational 경계를 우회할 수도 없다.

### 타로 여정 의미

- `바보`는 항상 활성인 `JourneyRoot`다. 뽑기 결과나 능력치 보정 카드로 사용하지 않는다.
- 다른 메이저 아르카나는 현재 상황을 해석하는 `ActiveMajorArcana` 프레임이다.
- 기존 `learning:hongik.fool.beginner-mind` 고유 식별자는 저장 호환을 위해 유지하지만 일반 타로 전체를 학당 콘텐츠로 만들지는 않는다.
- 여정 루트와 현재 아르카나는 제안·사건·Effect를 직접 만들지 않는다.

### 일반 경영 타로

첫 규칙 뼈대는 여제·전차·정의·절제다.

| 카드 | 중심 질문 |
| --- | --- |
| 여제 | 무엇을 돌보고 길러야 하는가? |
| 전차 | 얼마나 빠르게, 어떤 통제로 이동할 것인가? |
| 정의 | 무엇을 같은 기준으로 검증하고 나눌 것인가? |
| 절제 | 어떤 자원을 섞고 아껴 균형을 맞출 것인가? |

Simulation은 seed·턴·덱 개정·선택 이력으로 세 장을 결정한다. 기존 세션은 호환을 위해 seed 기반 방향 판정을 기본으로 유지한다. 세계 문맥형 프로필에서는 플레이어가 메이저 아르카나의 정체성만 선택하고, 방향은 활성화 시점의 권위 세계 상태로 Simulation이 판정한다. 정방향과 역방향은 같은 값을 단순 반전하지 않고 서로 다른 기회·부담 묶음을 가진다. 선택한 카드는 허용된 하위 업무 규칙에 보정선을 제공하며 실제 결과는 하위 규칙과 불변 조건 검증을 통과해야 한다.

### 메이저 아르카나 활성화와 방향 가변성

- 카드의 정체성은 지속되지만 정·역방향은 카드 고유 식별자의 영구 속성이 아니다. 방향은 각 `MajorArcanaActivationStableId`에 귀속된다.
- 같은 카드도 서로 다른 활성화에서는 판정 당시 세계 상태에 따라 다른 방향이 될 수 있다. 활성화 중에는 Tick·NPC 상태·심리 기간이 바뀌어도 방향을 다시 계산하지 않는다.
- 카드 교체·해제·향후 재방향 판정은 기존 활성화 값을 수정하지 않는다. 기존 활성화를 종료하고 새 활성화·판정·상속 계보를 만든다.
- 첫 세계 문맥형 정책 `RecoveryShare51`은 `회복 출력 ÷ (회복 출력 + 위협 출력)`을 백만분율 고정 정밀도로 판정한다. `510000` 이상은 정방향, `509999` 이하는 역방향이며 분모가 0이거나 근거 hash가 없으면 활성화를 거부한다.
- 방향은 하위 카드 계층을 재귀 순회하지 않는다. 활성화에서 각 최종 카드로 `Numeric | Interpretive | Ordering | DirectionOnly` 영향을 한 번만 펼치고, 결정적 상속 고유 식별자의 중복은 오류로 처리한다.
- 수치 영향은 허용된 Effect 연결점에만 적용한다. 첫 Town 생활복구 Fixture는 `기본값 × 하위 카드 × 방향 × 심리 기간`을 조립한 뒤 `0.75~1.30` 제한을 정확히 한 번 적용하고 계산 계보를 저장한다.
- 활성 아르카나가 없으면 저장용 중립 상속 객체를 만들지 않는다. 계산 시에만 중립 방향과 `1.0` 기본값을 사용한다.

첫 Town 자동시험 Fixture는 공동상점 직원 1명, 주민 2명과 비상식량·휴대용 배터리·방수포를 사용한다. 욕구 평가는 `WorldDerived`, 주문·수령·소비는 `NpcDriven`, 아르카나 선택은 `PlayerDriven`으로 구분하며 배터리 경쟁은 욕구 심각도→요청 개정→NPC 고유 식별자 순으로 결정한다. `WI-ORDER-01~07` 이후 소비 Effect가 욕구를 바꾸고 다음 목표 평가로 돌아간다. 이 물품은 브랜드·가격·실구매를 포함하지 않는 Simulation 전용 Fixture이며 플레이어에게 NPC 예약·수령·소비·목표 덮어쓰기 명령을 노출하지 않는다.

### 생존 타로

생존 타로는 주기와 식량 위기 같은 Session 조건에서 기회를 제안한다. 안전 거점에 참여자가 모이고 같은 제안에 합의한 뒤에만 확정하며, 효과는 다음 Tick에 한 번 적용한다. 재고를 새로 만들거나 접근·용량 규칙을 우회하지 않는다.

| 수집 보상 카드 | 탐험·농사 결과의 개인 수집과 표현 | 초기 규칙에서 수치 효과·기능 해제 |
| 학당·문화 카드 | 철학·문화·교육의 선택형 콘텐츠 | 일반 타로 기본 덱 대체 |
| 근거·지식 카드 | 출처·관측 시각·판본·한계 설명 | 사건이나 Effect 직접 생성 |

카드군 사이에는 고유 식별자, 저장 의미와 승격 절차를 공유하지 않는다. 같은 그림이나 원형을 사용하더라도 게임 역할이 다르면 별도 정의로 관리한다.

## 현실 문맥·사건·WI·Effect

다음 다섯 단계를 섞지 않는다.

| 단계 | 의미 |
| --- | --- |
| 현실·관측 문맥 | 세션 시작 때 승인 자료에서 동결한 읽기 전용 근거 |
| 상황 제안 | 사건 또는 행동 후보를 검토하도록 제공한 미확정 문맥 |
| 세계 사건 | Simulation Session에서 조건과 개정이 확정된 기회·문제 |
| WI | 주체가 사건이나 목표에 대응하는 실행 단위 |
| Effect | Confirm·Task·WorldTick을 통과해 세계 상태에 남은 결과 |

현실자료는 `ContextProposal`이며 `Incident`나 `Effect`가 아니다. 자료의 값만으로 생산량·수익·사건·공간 배치를 바꾸지 않는다.

WI 실행 인스턴스의 발생원은 네 가지다.

```text
데이터 발생 DataDriven
플레이어 발생 PlayerDriven
NPC 발생 NpcDriven
세계 종합 발생 WorldDerived
```

WI 정의는 허용 발생원 목록을 갖고, 실행 인스턴스는 실제 발생원을 기록한다. 공개 Confirm 요청에서 클라이언트가 발생원 코드를 임의 선택하지 않는다. 발의·수행·진행·권위 같은 실행 상세는 발생원과 별도로 보존한다.

## 공간과 플레이의 연결

영역 안의 건물 발전은 [영역별 건물 발전 테크트리 계획](영역별건물발전테크트리계획.md)을 따른다. Nature·Farm·Town·Hub·City는 독립된 누적 테크트리를 가지며, 플레이어의 H1 건설이 H2·H3 성장을 유도하더라도 상위 공간 성립은 Simulation 규칙이 별도로 판정한다. 첫 실제 세로 조각은 Nature이고 다른 네 영역은 현재 공통 카탈로그 기준선이다.

H는 카드 등급이나 증거 성숙도가 아니라 공간의 의미 깊이다.

| H | 게임 기획 의미 |
| --- | --- |
| H1 | 플레이어가 직접 사용·배치·복구하는 작업공간과 객체 |
| H2 | 여러 H1이 기능과 연결구를 갖춰 형성한 블록 |
| H3 | H2 사이의 이동·위협·회복·생산 폐루프가 닫힌 경관 |
| H4 | Nature·Farm·Town·Hub·City 같은 AreaSet |
| H5 | AreaSet과 전이 관계를 배치한 세계 |

카드 제안이나 발전소 이미지가 존재한다는 이유만으로 H1~H3가 성립하지 않는다. H 공간은 필요한 WI, 자원·시간·배치 조건, 연결구, 귀환 경로와 Simulation 계보를 함께 가져야 한다.

## 실행 권위와 저장

- Solo는 Unity 프로세스의 `LocalProcess`, Hosted는 Simulation 서버의 `RemoteHost`에서 같은 Simulation Core를 실행한다.
- Unity는 선택 입력과 표현을 담당하지만 운영 원장이나 Simulation 결과를 독자적으로 확정하지 않는다.
- `Proposal != Incident != Effect`를 유지한다.
- 상태 변경은 `Preview → Confirm → Task/WorldTick → 기준 상태 재조회`를 따른다.
- 카드 제안, 방향, 선택, 기간 상태, WI 발생원과 확정 결과는 해당 저장 판본의 Save/Replay 정규형에 포함한다.
- 새 관측이나 Provider 응답은 이미 시작한 세션의 동결 문맥과 재생 결과를 바꾸지 않는다.

## 현재 기획 우선순위

1. Nature 생존 생활거점의 선택·대가·귀환 폐루프를 실제 플레이로 닫는다.
2. 회복·위협과 평시·광복기·암흑기의 피드백을 플레이어가 이해할 수 있게 연결한다.
3. 카드가 사건과 WI 사이에서 어떤 선택을 여는지 좁은 세로 조각으로 검증한다.
4. Farm·Town·Hub·City의 독립 내부 폐루프를 각각 완성한다.
5. 독립 영역 준비가 확인된 뒤 Nature↔Farm 같은 영역 간 통합을 연결한다.

다음 항목은 현재 통합 기준의 완료를 뜻하지 않는다.

- 타로 78장 전체 데이터와 최종 밸런스
- 여러 활성 타로의 중첩 우선순위
- 두 발전소의 실제 H 승격과 최종 Scene 배치
- 광복기·암흑기의 최종 UI·음향·환경 연출
- 전체 카드군의 Play Mode·Game View 검증
- 운영 Provider 호출이나 운영 상태 변경

## 구현·증거 구분

| 구분 | 현재 확인 범위 |
| --- | --- |
| 소스·자동시험 기반 존재 | 일반 타로 뽑기·상위 규칙·객체 반응, 활성화별 51% 방향 판정·단일 Fan-out, Town 욕구·물품 경쟁·주문·소비·다음 목표 Fixture, `simulation-save.v16`, 생존 타로, 팀 역할·수집 카드, 회복·위협 균형, 평시·광복기·암흑기, WI 네 발생원 |
| 부분 구현 또는 통합 증거 필요 | 카드와 현재 세계 객체의 Unity 표현, 현재 아르카나와 판정 근거 표시, Town 실제 H 이동·WI 발현, LocalProcess·RemoteHost 동등성, 기간 상태의 실제 플레이 피드백 |

위 표의 `소스·자동시험 기반 존재`는 관련 코드와 시험 파일이 있다는 뜻이다. 이 문서 통합만으로 최신 전체 시험 통과, 저장 Scene 배선, Play Mode 또는 Game View를 새로 증명하지 않는다.

## 변경 관리

새 카드·시기·영역·사건 개념을 추가할 때는 다음 순서를 따른다.

1. 이 문서의 기존 개념으로 설명 가능한지 확인한다.
2. 새 개념이 플레이어에게 여는 선택과 다음 선택을 적는다.
3. `상황 제안 / 세계 사건 / WI / Effect` 중 어디에 속하는지 정한다.
4. 권위 소유자와 Save/Replay 영향을 정한다.
5. 필요한 H 공간과 E 증거 목표를 분리해 적는다.
6. 세부 수치·자산·API는 해당 전문 문서와 코드에 둔다.
7. 장기 결정이 바뀌면 `DECISIONS.md`에 대체 관계를 남긴다.

기존 전문 문서를 삭제할 때는 이 문서가 그 세부 책임까지 실제로 흡수했는지, 외부 링크와 확정 결정이 새 경로를 가리키는지 먼저 확인한다. 단순 중복처럼 보여도 구현 이력과 호환 근거를 가진 문서는 바로 삭제하지 않고 `세부 기준`, `구현 기록` 또는 `대체됨`으로 역할을 먼저 표시한다.
