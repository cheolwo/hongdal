# 게임플레이 계획 V7 현행화

## 적용 원칙

`ssalddel_gameplay_plan_v7.zip`의 문서는 실행 명령이 아니라 기획 입력으로 사용한다. 실제 계약·원장·시험과 충돌하는 부분은 현재 저장소를 기준으로 조정하며, 서버가 최종 사실과 상태 전이를 소유하고 Unity는 서버가 확정한 상태를 표현한다.

- 실행 순서는 `P0 잠금 → P1 선택 → P2 건설 → P3 단독 플레이 → P4 심리 → P5 시대 → P6 세계 확장 → P7 호스팅 → P8 협동 → P9 최종 관문`으로 고정한다. 이 문서의 과거 `G4` 표기는 [E 성숙도와 G 관리 체계](E성숙도와G관리체계.md)의 G4와 무관한 단독 플레이 관문 이름이었으므로 사용하지 않는다.
- 모든 상태 변경은 `Preview → Confirm → WorldTick → 재조회`를 따른다.
- 클라이언트는 선택 고유 식별자와 예상 개정만 보내며 수량·단위·비용·효과를 만들지 않는다.
- 기존 `SimulationRealityContext`와 감자 현실자료 동결·저장·재생 hash를 보존한다.
- 기존 Scene·병행 작업의 변경은 되돌리지 않고, 공식 진입점은 `SimulationWorldShell` 하나를 유지한다.

## 현재 목적에 맞춘 책임 경계

- 세션 생명주기 API·응용 서비스는 생성·조회·Tick·저장·복원·재생만 소유한다. 심리, AreaSet 이동, Hosted, 협동 건설과 플레이 관측은 세계 게임플레이 API·응용 서비스가 소유한다.
- 기존 HTTP route와 `경영SimulationSessionService` 공개 호출 표면은 호환 facade로 유지한다. 이번 리팩토링은 외부 계약·고유 식별자·저장 형식을 바꾸는 이름 정리가 아니다.
- Controller의 동일한 오류 변환은 공통 기반에 모으되, 상태 전이와 권한 판단은 계속 응용·도메인 경계에서 수행한다.
- 공식 Unity 조립은 서버 권위를 명시적으로 선택한다. 정착지 선택과 턴 마감은 서버 연결이 없을 때 Fixture가 자동으로 대신 실행되지 않으며, Fixture는 시험 또는 검토 조립에서만 명시적으로 주입한다.
- 전시관·모판처럼 결과를 확정하지 않는 검토 전용 Fixture는 유지한다. 이를 실제 서버 플레이 완료 증거로 해석하지 않는다.

## 현행화한 단계와 구현 결과

| 단계 | 현재 저장소에서 확인한 최초 결손 | 적용 결과 |
| --- | --- | --- |
| P0 잠금 | 문서의 가정과 실제 구현 범위가 섞여 있음 | 기존 감자 현실자료·Save/Replay·서버 권위 경계를 선행 조건으로 고정하고 단계별 집중 시험을 기준선으로 삼았다. |
| P1 선택 | 기존 판로 엔진은 있었지만 실제 Farm 수확 Lot과 선택 문맥이 결속되지 않음 | 실제 `CollectedAtYard` 감자 Lot을 서버가 찾아 판로 문맥을 만들고, Preview·Confirm에서 Lot 개정·품목·수량·단위·계보를 다시 검증한다. Unity는 서버 문맥 재조회 뒤 선택만 제출한다. |
| P2 건설 | 건설 시설이 다음 보관 선택의 용량과 상호작용을 열지 않음 | 작은 Farm 창고를 실제 자재 Lot 예약·소비와 건설 단계에 연결하고, 운영 완료 때 저장 용량 `+500 KGM`과 `WI-FARM-STORE-01`을 정확히 한 번 활성화한다. |
| P3 단독 플레이 | 기존 판로별 효과는 있었지만 앞 단계의 실제 폐루프 증거가 부족함 | 실제 수확 Lot 선택과 창고 건설을 기존 4개 판로 효과·Save/Replay에 연결하고 단독 플레이 회귀를 고정했다. |
| P4 심리 | 같은 업무 사실과 플레이어별 해석의 분리가 부족함 | 업무 사실은 불변으로 유지하고 플레이어별 회복·위협·해석 상태를 별도 원장과 hash로 계산한다. |
| P5 시대 | 심리 상태와 시대 규칙이 실제 행동 결과에 이어지지 않음 | `Gwangbok`과 `DarkAge` 규칙을 결정적으로 적용하고 같은 사실에 대한 시대별·플레이어별 해석 차이를 저장·재생한다. |
| P6 세계 확장 | Farm에서 Hub로 넘어가는 권위 있는 접근 상태와 상호작용이 없음 | 서버 소유 AreaSet 접근 상태, Farm→Hub 연결, 접근 Preview·Confirm·Tick과 세계 상호작용을 추가했다. |
| P7 호스팅 | 단독 세션을 호스팅 세계로 전환하고 참가자 권한을 제한하는 원장이 없음 | Solo→Hosted 전환과 참가자 합류·권한을 서버가 확정하며, Unity 일시 메뉴는 세계 Tick을 멈추지 않고 호스팅 상태를 재조회한다. |
| P8 협동 | 플레이어별 실제 자재 Lot과 건설 진척·보호·복원의 원자적 연결이 없음 | 소유자·참가자 Lot을 각각 예약하고 기여를 원자적으로 확정한다. 단계별 건설, 운영 창고 생성, 보호 지점, 소유자 전용 철거, 보상 복원을 Save/Replay와 Unity 조작에 연결했다. |
| P9 최종 | 접근성 표현과 전 구간 관측 계보가 부족함 | 심리 표현 강도를 `Full / Reduced / Minimal`로 전환하고, 사실과 감정 해석을 분리한 플레이 추적 계약을 추가했다. 최종 HTTP 기준작은 실제 수확·선택·Hub 이동·심리·시대·Hosted·협동·복원·저장 재생을 한 세션 계보로 검증한다. |

## 검증 기준

- Simulation 전체 시험: `708/708` 통과.
- 세계 게임플레이 책임 경계·HTTP route 집중 시험: 통과.
- 최종 HTTP 통합 기준작: 통과.
- Unity 신규 호스팅 시험: `1/1` 통과.
- Unity 신규 협동 창고 시험: `2/2` 통과.
- Unity EditMode 어셈블리 빌드: 오류 없음.
- 새 정착지·턴 마감 권위 경계 시험은 컴파일됐지만, 열린 Editor의 분리된 Test Runner 입력 문제로 이번 리팩토링 뒤 실행 결과를 받지 못했다.
- 직전 전체 Unity EditMode 기준선은 `447 성공 / 37 실패`다. 남은 실패는 기존 저장 Scene·조립 상태 계열이며 이번 신규 호스팅·협동 기능의 집중 시험과 분리한다.

## 완료로 간주하지 않는 범위

- 운영 배포, 실제 Provider 호출, 운영 DB 변경 적용, commit과 push는 수행하지 않았다.
- 최종 P7~P9 흐름의 실제 서버 프로세스 연결 Play Mode 수동 조작과 최종 Game View 마감은 별도 실행 증거다.
- 기존 저장 Scene의 병행 변경과 실패를 이번 기능이 해결한 것으로 간주하지 않는다.
