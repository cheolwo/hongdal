# 기획 문서 독립 관리 체계

## 목적

게임 기획의 본문과 전역 결정을 분리한다. 플레이어 상황·선택·대가·실패·회복·귀환, 이야기 분기, 미정 질문과 Graph Map 영향은 기획 문서가 소유한다. `DECISIONS.md`는 여러 기획에 장기간 공통 적용되는 원칙·권위 경계·호환 규칙만 소유한다.

이 분리는 기존 `D-###` 이력을 삭제하거나 다시 번호 매기기 위한 것이 아니다. 과거 결정은 당시 기획 근거를 찾는 링크로 보존하고, 앞으로 기획 답변 하나마다 새 D를 만드는 관행을 중단하기 위한 것이다.

## 문서별 책임

| 문서 | 소유하는 것 | 소유하지 않는 것 |
| --- | --- | --- |
| 기획 문서 | 지금·여기·나·너·이렇게, 결과·다음 선택, 사건 순서, 분기, 대가·실패·회복·귀환, 미정 질문, 판본·상태, Graph Map 영향 | 코드·Scene·Runtime 결과, 전역 호환 정책 |
| [기획 목차](../AI/PLANNING.md) | 안정 기획 ID, 상·하위 기획, 현재 판본·상태, 기준 문서, 다음 질문, 인계 상태 | 각 기획 본문 복제 |
| [결정 원장](../AI/DECISIONS.md) | 여러 기획에 공통인 장기 원칙, 권위·안전·호환·명명·증거 경계, 대체 관계 | 개별 장면의 세부 대사·순서·후보·미정 수치 누적 |
| [현재 작업](../AI/CURRENT_WORK.md) | 지금 활성인 기획·개발·검증 상태와 차단 | 완료 이력과 장기 기획 본문 |
| Graph Map | 승인된 기획 판본의 레벨 1·2·3 구조와 미결속 | 기획 선택의 임의 창작 |

## 안정 기획 ID

기획 문서는 전역 D 번호 대신 다음 안정 ID를 사용한다.

```text
PLAN-{분야}-{주제}-{순번}
```

예:

```text
PLAN-STORY-MIRROR-MAIN-001
PLAN-STORY-YODONG-DEFENSE-001
PLAN-GRAPH-NORTHERN-LIFE-001
PLAN-GAMEPLAY-FIRST-PERSON-FOCUS-001
```

기획 ID는 문서의 정체성을 나타내고 판본은 별도로 증가한다. 파일명을 바꾸거나 내용을 개정해도 같은 기획이면 ID를 유지한다. 전혀 다른 플레이 약속을 독립적으로 검토할 때만 새 기획 ID를 만든다.

## 기획 문서 필수 머리말

새 기획이나 의미 있는 개정에는 다음을 둔다.

```text
기획 ID
기획 판본
상태
상위 기획
관련 하위 기획
관련 결정
관련 WI·PlayableLoop
Graph Map 영향
다음 질문 또는 인계 상태
```

모든 항목을 억지로 채우지 않는다. 관련 WI나 Graph Map이 아직 없으면 `미등록`, `NoImpact`, `Unresolved`처럼 사실을 적는다.

## 상태

| 상태 | 의미 |
| --- | --- |
| `Draft` | 문답 중이며 인계 기준선이 아님 |
| `ReadyForReview` | 현재 내용의 검토가 가능함 |
| `ApprovedPlanningBaseline` | 플레이어 약속과 주요 경계가 승인됨 |
| `ApprovedForHandoff` | 판본·해시·영향·제외 범위를 동결해 Graph Map 또는 개발 인계 가능 |
| `Blocked` | 기획 선택이나 필수 근거가 없어 다음 단계 중단 |
| `Superseded` | 새 판본이나 다른 기획이 대체함 |
| `Archived` | 더 이상 현행 기획에서 사용하지 않음 |

`ApprovedPlanningBaseline`은 코드 구현 승인이나 E 승격이 아니다. `ApprovedForHandoff`도 인계 가능 상태일 뿐 자동 실행 명령이 아니다.

## 언제 D 결정을 만드는가

다음 중 하나에 해당할 때만 새 D를 고려한다.

- 둘 이상의 기획이 함께 따라야 하는 장기 원칙
- 서버·Simulation·Unity 권위 경계
- 저장·공개·권리·안전·호환 규칙
- E/H/WI/Graph Map 같은 공통 판정 체계 변경
- 기존 결정을 명시적으로 대체해야 하는 정책

다음은 기획 문서만 개정한다.

- 한 장면의 등장인물·장소·사건 순서
- 선택 카드의 후보와 다음 질문
- 한 퀘스트의 대가·실패·회복·귀환
- 특정 자산 후보나 미확보 상태
- 아직 미정인 수치·대사·거리·연출
- Graph Map에 옮길 개별 노드·엣지 후보

기획 개정에서 여러 기획에 공통되는 새 원칙이 발견되면, 기획 본문을 먼저 확정한 뒤 필요한 원칙만 D로 요약하고 기획 ID·판본을 근거로 연결한다.

## 기획→Graph Map→개발

```text
기획 문답
  → 기획 문서 판본 갱신
  → 기획 목차 상태 갱신
  → ApprovedForHandoff 판본·해시 동결
  → Graph Map 레벨 1·2·3 반영
  → 개발 가능한 작은 slice만 개발 인계
  → 최종 결과를 기획 문서의 인계 상태에 반환
```

Graph Map 또는 개발의 중간 진행을 기획 문서에 누적하지 않는다. 기획에는 최종 반영·차단과 다음 질문만 돌아온다.

## 기존 D 기록 이관 원칙

기존 D 항목은 다음처럼 처리한다.

1. 삭제·재번호화하지 않는다.
2. 현재 기획에 필요한 항목은 기획 문서의 `관련 결정`에서 참조한다.
3. 세부 기획 내용은 기획 문서가 소유하도록 다음 판본에서 정리한다.
4. D 원문은 당시 이력이며 최신 기획 본문으로 사용하지 않는다.
5. 기존 D와 현행 기획이 다르면 대체 관계 또는 현행 기획 판본을 명시하고 조용히 덮지 않는다.
