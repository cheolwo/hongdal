# 공식 지속 세계와 비공개 협동방 체계

## 목적

Ssalddel의 명상 숙련은 혼자 하는 플레이에서도 성립하지만, 서로 다른 플레이어가 집중 경험을 공유하고 협동할 수 있는 온라인 기반도 제공한다. 온라인 방식은 다음 두 가지이며 Solo 로컬 실행을 없애지 않는다.

| 실행 방식 | 권위 위치 | 세계 수명 | 첫 수용 기준 | 공유 범위 |
| --- | --- | --- | --- | --- |
| Solo 로컬 세계 | 사용자 프로세스의 공통 Simulation Core | 로컬 저장에 귀속 | 1명 | 온라인 계정 원장과 분리 |
| 비공개 협동방 | 개발사 Simulation 서버 | 소유자가 만들고 전원 이탈 시 정지 | 2~4명 | 방 세계 상태와 검증된 명상 기여 |
| 공식 지속 세계 | 개발사 Simulation 서버 | 접속자가 없어도 상태 사본 유지 | AreaSet당 32명, 첫 4개 AreaSet 총 128명 | 공식 세계 상태·공동 목표와 검증된 명상 기여 |

비공개 협동방은 플레이어 PC가 권위 서버가 되는 P2P Host가 아니다. 플레이어가 방을 만들고 초대하지만 실제 권위 판정과 저장은 개발사 Simulation 서버가 담당한다. 기존 `HostedMultiplayer` 세션 계약은 호환을 위해 유지하며 새 온라인 세계 Directory가 이를 즉시 삭제하거나 기존 저장에 흡수하지 않는다.

## 세계와 계정 상태의 분리

온라인 세계마다 다음 상태를 독립적으로 보관한다.

- 참가자, AreaSet 소속, 파티, 고정 신호
- 공식 세계의 공동 목표와 기여 기록
- 향후 연결할 자원, 장비, 분야 숙련, 건축물, 위협과 세계 시간

계정 사이에 공유할 수 있는 첫 항목은 서버가 권위 행위 기록으로 검증한 명상 경험뿐이다. `SourceActionRecordStableId`, 원본 행위 세계 revision, 적용 온라인 세계 revision과 명상 규칙 revision이 있는 기여만 계정 명상 원장에 멱등 추가한다. 공개 동기화 요청은 온라인 세계·세션·행위 기록 고유 식별자와 예상 온라인 세계 revision만 받는다. 명상 증가량과 플레이어 고유 식별자는 서버가 활성 세션의 행위 원장·플레이어 성장 원장과 JWT 주체를 대조해 결정한다.

한 행위 기록은 계정 전체에서 한 번만 기여한다. 같은 행위 기록을 같은 세계에 재전송하면 기존 결과를 반환하고, 다른 온라인 세계에 다시 제출하거나 다른 JWT 주체로 제출하면 충돌로 거부한다. 현재 연결은 실제 `WI-NATURE-06 벌목`의 완료 행위 기록과 명상 기여를 읽는 명시적 동기화 Command이며, 모든 WI 완료 시 자동 전송하는 기능은 아니다.

다음 항목은 서로 다른 세계로 가져가지 않는다.

- Solo 저장, 아이템, 재료와 장비
- 분야 이해도·현장 숙련도·운영 숙련도
- 건축물, NPC, 위협, 세계 시각과 사건
- 공식 세계의 공동 목표 진행도

현재 온라인 상태 사본에는 이 격리를 깨는 import 계약이 없다. 실제 Nature WI를 온라인 세계에 연결할 때도 세계별 세션 원장과 계정 명상 원장을 별도 transaction 경계로 유지한다.

## AreaSet 수용과 파티 전환

공식 Nature 기준 세계는 다음 네 AreaSet으로 시작한다.

- `area-set:sim:nature-official:north.v1`
- `area-set:sim:nature-official:east.v1`
- `area-set:sim:nature-official:south.v1`
- `area-set:sim:nature-official:west.v1`

각 AreaSet은 32명을 수용한다. 개별 합류에서 수용 인원을 넘은 참가자는 대기 상태가 되며 자리가 생기면 결정적인 합류 revision 순서와 플레이어 고유 식별자 순서로 한 명을 승격한다.

2~4명 파티는 같은 AreaSet의 연결된 참가자로만 만든다. 파티 AreaSet 전환은 리더가 요청하고, 목표 AreaSet에 파티 전원 자리가 있을 때만 같은 revision에서 전원을 옮긴다. 자리가 부족하면 아무도 이동하지 않는다. 이것은 LH의 실제 지형·셀 handover를 완료했다는 뜻이 아니라, 상위 온라인 소속 전환에서 파티가 갈라지지 않게 하는 권위 관문이다.

## AreaSet 권위 세션 결속

각 온라인 AreaSet은 하나의 결정적인 `RemoteHost` Simulation 세션 식별자를 예약한다. 식별자는 `온라인 세계 고유 식별자 + AreaSet 고유 식별자 + 온라인 규칙 revision`에서 계산하므로 서버 재기동과 상태 사본 복원 뒤에도 바뀌지 않고, 서로 다른 AreaSet이나 비공개방이 같은 세션을 우연히 공유하지 않는다.

AreaSet 상태 사본은 다음을 함께 봉인한다.

- `AuthoritySessionStableId`: 해당 AreaSet의 권위 Simulation 세션 식별자
- `AuthorityLocationCode = RemoteHost`: 플레이어 PC가 권위 Host가 아님
- `SessionBindingStateCode = AuthoritySessionReserved`: 온라인 상태 사본은 Runtime 수명과 분리된 결정적 식별자 예약 상태를 보관함
- `SessionBindingRevision`: 결속 계약의 revision

명상 동기화는 JWT 플레이어가 현재 연결된 AreaSet을 찾고, 요청한 세션이 그 AreaSet의 `AuthoritySessionStableId`와 일치하는지 먼저 검증한다. 따라서 다른 로컬 세션이나 다른 AreaSet 세션에서 만든 행위 기록을 현재 온라인 세계 기여로 제출할 수 없다. World·AreaSet 전환이 동시에 발생하면 예상 온라인 World revision 검사가 동기화를 거부한다.

연결된 참가자는 `POST /{worldStableId}/authority-session-provisions`를 명시적으로 호출해 현재 AreaSet의 세션을 준비한다. Provisioner는 예상 온라인 World revision, JWT 참가자의 연결 상태와 현재 AreaSet을 검증하고, 세션이 없으면 예약 식별자와 결정적인 시스템 Actor로 Nature r5 Fixture를 생성한다. 같은 AreaSet 참가자와 재기동 뒤 빈 프로세스는 같은 세션·시스템 Actor 식별자를 얻는다. 이미 있는 세션은 AreaSet 결속이 일치할 때만 재사용한다.

Runtime 응답의 `RuntimeStateCode = AuthoritySessionRuntimeReadyCooperativeLogging`와 `SupportsMultipleActors = true`는 같은 세션에 연결 참가자의 Actor를 등록했음을 나타낸다. 각 Actor는 독립 인벤토리와 도끼, Nature Mind 상태를 가지며 첫 허용 WI는 `WI-NATURE-06 벌목`이다. 세계에는 하나의 권위 `ActiveWork`만 있으므로 먼저 시작한 Actor가 대상 나무와 집중 Challenge를 확보하고, 뒤의 Actor가 같은 revision에서 같은 나무를 시작하면 권위 충돌로 거부된다.

Provision 결과는 같은 AreaSet의 연결 참가자를 `ParticipantActors`로 정렬해 제공한다. 참가자 Actor 고유 식별자는 `세계 + AreaSet + 플레이어 + 규칙 revision`에서 계산하므로 같은 checkpoint를 읽은 재기동 프로세스에서도 같다. 현재 `ParticipantActorRegistered`, `HasAuthorityInventory=true`, `CanExecuteNatureWorldInteraction=true`이며 등록 목록은 v29 세션 생성 상태와 저장 사본에 함께 봉인되어 Command 재생보다 먼저 복원된다. 플레이어별 분야·명상 Profile 배열도 함께 저장해 Actor A와 B가 순서대로 벌목을 완료해도 각자 `250 Milli` 계보를 유지한다.

공개 온라인 벌목 API는 JWT 플레이어를 본문의 Actor ID로 신뢰하지 않고 현재 AreaSet의 결정적 Actor로 변환한다. 시작은 대상 나무와 Session revision을, 집중은 Challenge ID·revision과 입력 offset을, 완료는 Session revision만 받는다. 완료 시간과 보상량은 서버가 활성 작업과 집중 결과에서 정하며, 완료 직후 같은 행위 기록을 계정 명상 원장으로 자동 인계한다.

## 비공개 협동방 수명

비공개방 생성자는 소유자이며 1~3명을 초대한다. 초대받지 않은 플레이어는 합류할 수 없다. 소유자가 나가도 다른 참가자가 남아 있으면 가장 먼저 합류한 참가자를 임시 리더로 정하고 방을 유지한다. 소유자가 돌아오면 소유 권한을 복원한다. 연결 참가자가 모두 나가면 방 상태를 `Suspended`로 보관한다.

## 소통과 공동 목표

첫 온라인 소통은 자유 텍스트와 음성을 포함하지 않는다. 허용된 고정 신호만 사용한다.

- 도움 필요
- 여기 집결
- 위협 발견
- 자원 발견
- 공동 목표 준비

HTTP로 확정한 신호만 SignalR 세계 그룹에 전달한다. 클라이언트 표시나 전송 성공만으로 세계 revision을 바꾸지 않는다.

공식 세계의 첫 공동 목표는 `objective:nature-common-survival-base.v1`이다. 목표 기여는 서버 내부의 검증된 행위 결과만 적용하며 공개 클라이언트 수치 입력 API를 제공하지 않는다. 현재 구현은 목표 원장과 멱등 합산 기반이며 실제 Nature 건설·벌목 WI와의 자동 결속은 후속 단계다.

## 인증과 권위

- 온라인 HTTP와 SignalR은 `SimulationIdentity` JWT 인증을 요구한다.
- 플레이어 고유 식별자는 요청 본문이 아니라 JWT `NameIdentifier` 또는 `sub`에서 확정한다.
- 온라인 기능이 비활성인 개발 기본 설정에서는 외부에서 재현할 수 없는 임시 서명 키를 사용해 온라인 route 접근을 닫는다.
- 운영 DB, 결제, 계약, 실제 물류 상태를 읽거나 쓰지 않는다.
- 모든 상태 변경은 예상 World·AreaSet revision을 검사하고 명령 ID와 payload hash로 멱등 처리한다.

배포 환경은 `SimulationIdentity:Enabled=true`, issuer, audience와 32자 이상의 secret을 비밀 설정으로 제공해야 한다. secret은 source와 추적 설정 파일에 넣지 않는다.

## 저장과 복원

온라인 세계는 기존 개인 세션 저장 wrapper와 섞지 않고 `simulation-online-world-checkpoint.v1` 상태 사본으로 저장한다. 상태 사본에는 다음을 넣는다.

- 세계 Directory revision
- 공식 세계와 비공개방 전체 상태와 각 hash
- 계정 명상 원장과 hash
- 명령 멱등 영수증
- 전체 checkpoint SHA-256

Simulation Session DB를 사용하면 `시뮬레이션온라인세계_상태사본` 표에 현재 checkpoint를 보관하고, 비활성 개발 환경에서는 같은 계약의 메모리 저장소를 사용한다. hash 불일치, 낮은 revision 덮어쓰기와 변조 복원은 거부한다.

## HTTP·실시간 계약

기준 경로는 `/api/simulation/v1/online-worlds`다.

| 기능 | 경로 |
| --- | --- |
| 세계 Directory·세계 조회 | `GET /`, `GET /{worldStableId}` |
| 내 명상 계정 조회 | `GET /me/meditation` |
| 비공개방 생성 | `POST /private-rooms` |
| 합류·퇴장 | `POST /{worldStableId}/joins`, `POST /{worldStableId}/leaves` |
| 파티 생성 | `POST /{worldStableId}/parties` |
| AreaSet 원자 전환 | `POST /{worldStableId}/area-set-transfers` |
| 고정 신호 | `POST /{worldStableId}/signals` |
| 검증된 명상 행위 동기화 | `POST /{worldStableId}/meditation-syncs` |
| AreaSet 권위 Runtime 준비 | `POST /{worldStableId}/authority-session-provisions` |
| 협동 벌목 시작 | `POST /{worldStableId}/logging/begins` |
| 협동 벌목 집중 입력 | `POST /{worldStableId}/logging/focus-attempts` |
| 협동 벌목 완료·명상 자동 인계 | `POST /{worldStableId}/logging/completions` |
| 협동 벌목 재접속 cursor 조회 | `POST /{worldStableId}/logging/reconnects` |
| 실시간 세계 그룹 | `/hubs/simulation-online-world` |

명상 동기화 route는 보상 수치를 받지 않고 활성 세션의 권위 행위 기록을 다시 검증한다. 공동 목표 기여와 검증 완료 명상 적용 함수는 여전히 Simulation Application 내부 경계이며, 일반 플레이어가 수치를 제출하는 route는 제공하지 않는다.

이 기반과 협동 벌목 자체는 새 PlayableLoop Goal이나 E 승격이 아니다. 온라인 작업은 저장소의 현재 활성 Goal을 변경하지 않는다. 서버 세로 조각은 같은 `RemoteHost` 세션의 여러 Actor, 권위 충돌, 순차 완료, Save/Replay, 재접속 cursor까지 검증했다. 실제 멀티플레이 승격에는 네트워크에서 동시에 들어오는 입력, 온라인 Runtime 운영 재기동, LH 실제 AreaSet 전환, Unity 다중 입력 Play Mode와 Game View를 별도로 검증해야 한다.
