# E8 NPC 생활세계 폐루프 정의

## 목적

E8은 NPC가 Unity 장면에 보이거나 정해진 경로를 이동하는지를 판정하는 단계가 아니다.

E8은 선정된 E7 세계 안에서 NPC가 지속되는 정체성·역할·생활 상태를 바탕으로 다음 목표를 결정하고, 실제 H 공간과 경관 그래프 경로를 선택해 이동하며, 공간·자원을 예약하고 세계 상호작용 단위(WI)를 수행한 결과가 NPC·공간·자원 상태와 다음 행동에 반영되는 연속 폐루프를 서버·저장·재생·Unity에서 검증한 단계다.

```text
E5  공간과 이동 관계가 논리적으로 존재한다.
 ↓
E6  그 공간에 현실 자료와 계보가 연결된다.
 ↓
E7  플레이어가 실제 서버와 저장 장면에서 세계를 플레이한다.
 ↓
E8  NPC도 그 세계에서 지속적인 생활·업무 주체로 행동한다.
```

E8은 모든 WI의 공통 목표 단계가 아니다. NPC 생활세계에 참여하는 `AreaSet + H 경로 + WI 묶음 + NPC 역할군`을 하나의 판정 단위로 삼는다.

E7에서 E8로 올리는 NPC 정체성·목표·이동·경쟁·협력·연속성 작업은 [E 성숙도와 G 관리 체계](E성숙도와G관리체계.md)의 `G3 NPC 생활세계 관리`로 관리한다. G3 작업 완료와 E8 증거는 같은 값이 아니며 아래 완료 관문을 모두 통과해야 한다.

## 완료 관문

선정된 NPC 생활세계 단위는 다음 조건을 모두 만족해야 한다.

1. **지속되는 NPC**
   - NPC 고유 식별자, 소속, 역할, 역량, 현재 위치, 생활 상태, 목표와 진행 중 작업이 여러 `WorldTick`에 걸쳐 유지된다.
   - Unity GameObject의 생존 여부가 NPC 지속성의 권위가 아니다.

2. **자율적인 다음 행동 선택**
   - Simulation 서버가 NPC 상태·역할·세계 상황·정책·우선순위로 가능한 행동 후보를 만들고 결정적으로 하나를 선택한다.
   - 같은 초기 상태, seed, 정책, Command와 Tick 순서에서는 같은 선택이 재현되어야 한다.

3. **생활 이동과 업무 이동의 구분**
   - `NpcTraversal`: 출근, 대기, 휴식, 시장 방문, 대피, 순찰과 같은 일반 생활 이동이다.
   - `WorkTraversal`: 확정된 WI·Task를 수행하기 위한 업무 이동이다.
   - `CargoLogistics`: 화물 자체의 물류 이동이다.
   - 연결 경로가 없거나 준비되지 않았을 때 순간이동, 임의 좌표 또는 Scenario 공간으로 조용히 대체하지 않는다.

4. **실제 H 공간 사용**
   - NPC는 H1 작업공간의 공간 능력·용량·접근 상태를 판정하고 H2 블록 내부 관계와 H3 경관 연결을 통해 목적 공간을 선택한다.
   - Prefab 이름, Unity 자산 경로, GameObject와 NavMesh는 공간 선택 권위가 아니다.

5. **WI·Task·Effect 참여**
   - NPC 행동은 기존 `Decision → Task → Effect`와 `Scheduled → Navigating → Working → Completed` 계약을 재사용한다.
   - 이동 도착이나 애니메이션 완료가 업무 완료를 확정하지 않는다. 서버 `WorldTick`과 Effect만 Simulation 상태를 변경한다.

6. **사회적 경쟁 또는 협력**
   - 최소 두 NPC가 작업공간·시설 용량·화물·차량 중 하나를 공유한다.
   - 예약 충돌, 대기, 작업 인계 또는 협력 중 하나가 실제로 판정되어야 한다.

7. **행동의 연속성**
   - 첫 행동의 Effect가 같은 NPC 또는 인계받은 NPC의 다음 행동 후보와 선택을 바꿔야 한다.
   - 하나의 배정 작업을 완료하거나 미리 작성된 연출 순서를 한 번 재생한 것만으로는 폐루프가 아니다.

8. **저장·재생 결정성**
   - NPC 상태, 목표, 의미 경로, 예약, 작업, Effect와 다음 행동 선택을 저장·재생 대상에 포함한다.
   - 저장 후 복원하거나 같은 명령 기록을 재생했을 때 최종 상태와 재생 hash가 같아야 한다.

9. **실제 실행 증거**
   - 실제 Simulation 서버, 저장된 canonical `SimulationWorldShell`, Play Mode, Game View와 Console에서 폐루프를 확인한다.
   - 자동 시험이나 Scenario Fixture만으로 E8을 주장하지 않는다.

## 최소 대표 증거

E8 증거 하나는 최소한 다음을 포함한다.

```text
NPC 2명 이상
+ 업무 WI 1종 이상
+ 비업무 생활 이동 1종 이상
+ 공유 공간·자원 경쟁 또는 인계 1건 이상
+ 선행 Effect가 후속 행동을 바꾸는 연속 행동 2회 이상
+ Save / Replay 동일성
+ 실제 서버·저장 장면 실행
```

예를 들어 농장 생활세계는 다음처럼 닫힐 수 있다.

```text
작업자 대기
  → 농기구 준비
  → 생산구획 이동과 작업영역 예약
  → 수확 WI 수행
  → HarvestLot 생성
  → 운반 NPC 인계 또는 작업자 휴식
  → 다음 목표 선택
```

## E8로 판정하지 않는 것

- NPC 수만 늘린 상태
- 무작위 배회나 단순 NavMesh 이동 성공
- Idle·Walk·작업 애니메이션 재생
- 미리 정한 연출 순서를 한 번 재생한 상태
- NPC가 하나의 배정 작업만 완료한 상태
- 자동 시험이나 Scenario Fixture만 통과한 상태
- Unity 도착·충돌·Animator Event가 Simulation 상태를 직접 변경한 상태

대화형 AI, 감정 모델, 관계 Simulation과 대규모 군중은 E8의 필수 조건이 아니다.

## 권위와 운영 경계

- NPC 목표·행동·예약·완료의 최종 권위는 Simulation 서버가 가진다.
- Unity는 서버가 결정한 의미 경로와 행동 상태를 표현한다.
- NPC 자율 행동은 Simulation 시나리오와 정책이 허용한 WI 범위에서만 발생한다.
- 실제 계약, 결제, 운영 배차, 발주와 정산 같은 외부 효과는 NPC가 자율 실행하지 않는다.
- 기존 Preview·Confirm·예상 개정·멱등 Command 경계가 필요한 행위는 E8을 이유로 우회하지 않는다.
- E8은 선정된 NPC 생활세계 단위에만 증거를 부여하며 모든 WI의 `targetStage`를 E8로 일괄 변경하지 않는다.

## 현재 구현과의 경계

현재 저장소에는 Simulation NPC 조직·역량·정책, 결정적 업무 배정, `Scheduled → Navigating → Working → Completed`, 업무 기록과 저장·재생 기반이 있다. 이 기반은 E8의 업무 수행 부분에 재사용할 수 있다.

다만 다음은 아직 E8 완료 증거가 아니다.

- 생활 상태를 포함한 지속 목표 선택
- `NpcTraversal` 의미 이동 계약
- H1~H3 공간을 이용한 NPC 목적지 해석
- 생활 이동과 업무 WI가 이어지는 다중 행동 폐루프
- 여러 NPC의 공유 공간 경쟁·협력 종단 검증
- 실제 서버·저장 장면에서의 E8 Play Mode·Game View 증거

따라서 이 문서는 E8의 정의와 판정 관문만 확정한다. E0~E7 실행 원장, API, Simulation 계약과 Unity 구현은 별도 후속 작업에서 호환성을 유지하며 확장한다.
