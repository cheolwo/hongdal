# 게임·현실 상품 자료 운영 기반

- 판본: `game-reality-product-curation.design.r1`, 2026-08-30, D374.
- 상태: `ApprovedFoundationScope`. 사용자 요청에 따른 운영 서버의 비활성 준비 구조 범위 승인이다. 실제 수집·게시·사용자 통지·구매는 제외한다.

## 목적과 순서

게임 상품을 먼저 만들고 추후 확보하는 현실 상품 자료와 연결한다. 보온병·병 같은 게임 상품의 고유 식별자에 현실 상품 후보를 대응시키고 운영자가 비교 근거를 검토해 무엇을 사용자에게 제공할지 선택한다. 게임 제작은 현실 자료 확보를 필수 선행 조건으로 삼지 않는다.

Apify는 사용자가 제시한 향후 수집 경로 후보다. 기존 [Apify 조사 모듈](ApifySocialMediaResearch.md)의 공통 Gateway/허용 목록/비용·비밀 경계를 재사용 검토하되 Amazon·Alibaba 상품 Adapter의 현재 지원·권리·가격·실제 호출 성공을 확인한 것으로 쓰지 않는다. 이번 작업은 Actor 조회·실행, 토큰 확인, 플랫폼 접속/수집을 하지 않는다.

## 운영자가 관리할 정보

- 게임 상품 식별자와 현실 후보의 별도 식별자. 이름/외형 유사만으로 같은 상품이라고 확정하지 않는다.
- 플랫폼·판매자·상품 URL·원천 식별자·관측 시각·규격·가격/통화·수량/MOQ·배송 조건·출처와 사용 조건. 미확보 값은 미확보로 유지한다.
- 상품 대응 후보/근거, 비교 가능성과 부족한 비용·조건, 운영자의 검토 상태/메모/판본.
- 사용자에게 보여줄 제목·요약·출처·한계의 초안과 별도 검토 승인/제외 상태. 자료 수집 성공, 대응 승인, 공개 승인, 실제 사용자 노출은 서로 다르다.

## 첫 개발 범위

개발 담당이 기존 상품·원천 카탈로그/가격비교/운영 검수 계약을 조사하고 중복을 피하는 최소 계약·상태 전이·검증 골격을 구현한다. 세부 경로는 개발이 소유 등록 후 정하며 기존 공개 API/원장을 일괄 변경하지 않는다.

1. 가상의 보온병/병 Fixture와 수집되지 않은 현실 상품 후보로 초안→검토→승인/제외를 시험한다. 실제 Amazon/Alibaba 가격인 것처럼 꾸미지 않는다.
2. 검토는 운영자 권한·최신 판본 검사·중복 요청 방지·감사 근거를 갖도록 기존 패턴을 재사용한다. UI에서 승인 문구를 보냈다는 이유만으로 승인하지 않는다.
3. 비교 불가·출처/이용조건 미확인·품목 대응 미확정은 공개 준비 통과로 판정하지 않는다. 누락 가격/비용을 0으로 간주하지 않는다.
4. 외부 수집과 실제 공개/알림 전달은 기본 비활성이다. 검토 완료도 실제 게시·push 발송이 아니다. 이번 범위에서는 운영 DB 실데이터 변경 없이 Fake/격리 시험으로 검증한다.
5. 게임은 향후 승인된 읽기 전용 자료 사본을 소비한다. 기존 SimulationRealityContext/저장 계약의 변경은 이번 준비 골격에 포함하지 않는다.

## 사용자 경험과 미정

D372/D373의 상품·거래 결과 상세 안의 선택형 '현실 자료 살펴보기'를 유지한다. 사용자 표현의 '통지'는 제공할 자료의 운영자 선정을 뜻하는 방향으로 기록하며 별도 push·강제 팝업/알림 빈도 승인은 아니다. 정확한 공개/알림 방식·검토 UI·Actor 선정·예산·자료 갱신·보관/재배포 조건은 후속이다.

## 검증과 인계

초안과 승인 분리, 권한 거부, 낡은 판본 거부, 중복 처리, 자료 누락/비교 불가 거부, 승인만으로 외부 호출·게시·게임 상태 변경이 없는 것을 집중 시험한다. 규칙 시험·API 연결·영속 통합·실제 화면을 각각 구분한다. 개발이 최소 코드 묶음·시험·남은 연결을 기획에 반환하고 자료 조사 담당은 요청받은 출처/조건 조사만 지원한다. 기존 게임 개발을 막거나 새 게임 WI/E를 자동 활성화하지 않는다. 실제 수집/게시/운영 배포/commit/push는 이번 승인 범위가 아니다.
