# H1~H5 공간 포함 계층 조사

## 목적

저장소에 흩어진 H1~H5의 정의, 포함 관계, 현재 재고와 실행 증거를 한곳에서 찾을 수 있도록 조사 결과를 정리한다. 이 문서는 기존 JSON 대장·생성기·결정 문서를 대체하는 새 권위가 아니라, 각 권위 원본으로 안내하는 현황 지도다.

조사 기준 시점은 2026-08-21의 현재 작업 트리다. 작업 트리에는 다른 작업의 미완료 변경이 함께 있으므로 수량과 검증 결과를 확정 릴리스 상태로 해석하지 않는다.

## 한눈에 보는 결론

H는 공간의 **포함 깊이**다. 작은 행동 공간을 블록으로, 블록을 경관으로, 경관을 지역으로, 지역과 물리 회랑을 하나의 세계 배치로 상향 조립한다.

```text
H5 세계 배치 (WorldLayout)
├─ H4 지역 (AreaSet)
│  └─ H3 경관 (LandscapeGraph)
│     └─ H2 블록 (LandscapeBlock)
│        └─ H1 행동·작업 공간 (WI 공간 부품)
└─ H3 물리 회랑
```

H1~H4는 위치 독립적으로 재사용할 수 있는 공간 의미와 조립 재고다. H5는 H4 지역 인스턴스와 H3 물리 회랑을 특정 Scenario 세계의 상대 좌표에 실제로 배치한다.

H 번호가 높아지는 것만으로 구현·실행·화면 검증이 완료되지는 않는다. H와 별개로 E 증거 단계가 존재하며, 현재 첫 H5는 `ScenarioRelative` 공간 권위를 가지지만 E7 실제 플레이 완료를 뜻하지 않는다.

## 계층별 정의

| 계층 | 한국어 의미 | 포함하는 것 | 판단 질문 | 권위 경계 |
| --- | --- | --- | --- | --- |
| `H1` | 행동·작업 공간 | 없음 | 플레이어 또는 Actor가 여기서 어떤 행위를 수행·관찰하며, 앞뒤 공간과 어떻게 이어지는가? | 위치 독립 공간 부품이다. 실제 지역 좌표·도로·Graph를 소유하지 않는다. 팩 표현만 있고 게임 행위와 연결되지 않으면 `IdeaInventory`로 격리한다. |
| `H2` | 블록 | H1 여러 개 | 여러 H1을 어떤 상대 위치·위상·내부 관계·입출구로 묶어 한 단위로 놓는가? | 첫 공간 조합 판단 단위다. 결정적 상대 배치와 연결구를 정의하지만 실제 AreaSet 배치나 공공데이터 결속을 뜻하지 않는다. |
| `H3` | 경관 | H2 여러 개 | 여러 블록 사이 이동·업무·위협·회복 흐름과 시작→결과→복귀가 닫히는가? | 위치 독립 `LandscapeGraph` 설계다. H3 분류만으로 E5 실제 인스턴스가 되지 않는다. H5에 직접 놓이는 물리 회랑도 H3 인스턴스다. |
| `H4` | 지역 | H3 여러 개와 관계 | 한 게임 기획 역할을 수행하는 지역 세계가 여러 경관과 내부 관계로 완결되는가? | 위치 독립 `AreaSet` 청사진이다. 실제 AreaSet 인스턴스는 E5에서 별도로 결속한다. |
| `H5` | 세계 배치 | H4 AreaSet 인스턴스와 H3 물리 회랑 | 여러 지역과 회랑이 한 Scenario 세계에서 어디에 놓이고 어떻게 물리적으로 연결되는가? | `WorldLayoutDefinition`이 `ScenarioLocalMeters` 상대 배치를 소유한다. 이동 가능성과 경로 선택은 `AreaSetNetwork`가 소유한다. 현실 GIS 결속은 별도 E6 축이며 H5 상대 배치를 조용히 바꿀 수 없다. |

### H1 — 행동·작업 공간

H1은 가장 작은 의미 단위다. 단순 Prefab이나 장식 조합이 아니라, 게임 행위 또는 예상 플레이와 연결되는 공간 역할을 기록한다. 현재 정책은 상호작용 H1에 기존 WI 또는 명시된 예상 플레이를 요구한다.

예시는 자연 탐색 시작점, 위협 감시, 긴급 후퇴, 안전 회복 캠프, 농장 생산, 수확 집하, 세척·선별, 출하 관문 등이다. Synty 팩의 시각 표현 후보는 연결 가능한 상호작용 H1이 있어야 공식 조립 우선순위에 들어갈 수 있다.

### H2 — 블록

H2는 H1 두 개 이상을 실제 계획기에서 함께 배치할 수 있게 묶는 첫 조합 단위다. 필수 H1, 상대 좌표, 위상, 내부 관계, 크기 변형과 외부 연결구가 핵심이다.

예시는 `자연 위협 추적·대피 블록`, `농장 세척·선별·포장 블록`, `Hub 입고·보관 블록`, `마트 주문 이행 블록`이다. 자동 이론 적격과 사람의 시각 검토 승인은 서로 다른 상태다.

### H3 — 경관

H3는 여러 H2를 Node·Edge·Connector로 묶은 경관 단위다. 한 방향 진행만 있는 장식 경관이 아니라, 플레이 시작·결과 표현·복귀 또는 다음 지역 인계가 연결되어야 한다.

예시는 `Nature 생활핵·조우·방어 경관`, `고지대 농장 경관`, `Farm 후처리 경관`, `Hub 물류 운영 경관`, `Town 시장 주문 이행 경관`이다. Nature–Farm, Farm–City/Hub, City/Hub–Town을 잇는 실제 물리 회랑도 H3로 모델링한다.

### H4 — 지역

H4는 여러 H3를 하나의 게임 기획 역할로 묶는 위치 독립 지역 청사진이다. 현재 주요 역할은 다음 네 AreaSet 축이다.

- 심리 영역: Nature 생활·위협·회복
- 업무 영역: Farm 생산·생존
- 업무 영역: City/Hub 물류 회복력
- 업무 영역: Town 생활·시장 안전

H4 청사진이 존재하는 것과 특정 Scenario에 실제 AreaSet 인스턴스가 배치되는 것은 다르다.

### H5 — 세계 배치

H5는 H4 AreaSet 인스턴스와 H3 물리 회랑을 하나의 `ScenarioLocalMeters` 좌표계에 배치한다. H4 아래 H3·H2·H1은 바로 위 부모 기준 `ParentLocalMeters`를 사용하며, 최종 위치는 부모 회전까지 합성한다.

현재 첫 H5는 `world-layout:sim:pyeongchang:nature-farm-hub-town.v1`이다. Nature·Farm·City/Hub·Town AreaSet 4개와 다음 물리 회랑 3개를 가진다.

1. Nature → Farm
2. Farm → City/Hub
3. City/Hub → Town

직접 Nature → City/Hub, Nature → Town 등의 관계는 이동 의미를 유지하되 물리 회랑을 꾸며내지 않고 `AbstractTravel`로 남긴다. 현실 결속 정책은 `Optional`, 현재 적용 상태는 `NotApplied`다.

## H와 E를 혼동하지 않는 법

| 축 | 답하는 질문 | 예시 |
| --- | --- | --- |
| H 공간 포함 깊이 | 공간이 무엇을 포함하며 어느 조립 단위인가? | H1 행동 공간 → H2 블록 → H3 경관 → H4 지역 → H5 세계 배치 |
| E 증거 깊이 | 코드·공간·자료·Runtime에서 어디까지 실제로 검증했는가? | E3 행위 구현, E4 H1 모판 재실행, E5 실제 공간 조립, E6 플레이 전 정제·선택형 현실 결속, E7 실제 플레이 |

따라서 다음 표현은 서로 다르다.

- `H4 청사진 존재`: 위치 독립 지역 설계가 있다.
- `Actual E5 AreaSet`: 그 청사진의 경관과 이동이 특정 Scenario 공간에 실제 결속됐다.
- `H5 ScenarioRelative`: 여러 Actual E5 지역과 회랑이 하나의 상대 세계 배치에 놓였다.
- `E6 ImmersionQualified`: E5 AreaSet의 장소·Actor·물건·WI·상태 변화와 교차 H3 인과 폐루프를 정제 질문표로 검토하고 E7 전에 남은 결함과 필요한 근거를 설명할 수 있다. 상태 코드는 호환을 위해 유지한다.
- `E7 완료`: 실제 서버·저장 Scene에서 사람이 폐루프를 수행하고 Play Mode·Game View 증거가 있다.

## 현재 수량은 관점별로 읽어야 한다

저장소에는 승인 기준 대장, 상향식 설계 재고, 실제 E5 인스턴스가 함께 존재한다. 같은 H 번호라도 집계 대상이 다르므로 숫자를 한 줄로 합치면 안 된다.

| 관점 | H1 | H2 | H3 | H4 | H5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 공간 포함 계층 대장의 승인·정의 기준 | 5 | 0 | 5 | 1 | 미포함 |
| 최신 상향식 설계 재고의 참조 배열 | 84 = 상호작용 52 + 표현 32 | 37 | 20 | 6 | 대상 아님 |
| Actual E5 생성 결과 | 직접 WI 30 + 문맥 WI 5 + 비공간 WI 6 + E5 배치 대기 WI 7 | 하위 계보로 포함 | 내부 16 + 회랑 3 = 19 | AreaSet 4 | 세계 배치 입력 |
| 첫 H5 생성 결과 | 하위 계보로 포함 | 하위 계보로 포함 | 물리 회랑 3과 AreaSet 내부 경관 | AreaSet 인스턴스 4 | 1 |

### 발견한 수량 드리프트

`catalog.v3.json`의 실제 참조 배열 길이는 H2 37, H3 20, H4 6인데 같은 파일의 `counts` 요약은 H2 18, H3 10, H4 5로 남아 있다. 생성 스크립트의 기대 출력은 H1 84, H2 37, H3 20, H4 6이다. 현재 작업 트리에서는 관련 검증도 통과하지 않으므로, 이 문서는 배열 길이를 **관찰값**으로만 기록하고 요약 수량을 자동 수정하지 않았다.

이 네 실패는 현재 작업 트리의 동기화 대기 상태다. 다른 작업의 소유 변경을 보존하기 위해 이번 조사에서는 생성기의 `Write`, hash 갱신, 단계 목표 수정이나 H5 재생성을 수행하지 않았다.

## 게임 기획에서 H를 사용하는 순서

`Nature↔Farm 왕복 플레이`를 기준으로 다음 순서를 지킨다.

1. 플레이어 약속, 행동, 선택, 결과와 귀환 분기를 먼저 쓴다.
2. 각 행동이 일어날 H1과 결과를 보여줄 H1을 연결한다.
3. 이동과 인계가 닫히도록 H1을 H2 블록으로 조립한다.
4. 정상·기회·위협·회복 분기와 복귀가 닫히도록 H2를 H3 경관으로 조립한다.
5. Nature와 Farm의 역할·인과를 H4 AreaSet에 묶는다.
6. H5에서 두 AreaSet과 물리 회랑을 배치한다.
7. 실제 배치는 E5, 필요한 현실 문맥은 E6, 서버 재조회·Save/Replay·사람 조작은 E7로 따로 증명한다.

Nature/Farm 게임플레이 추적 누락은 차단 조건으로, Town/Hub 누락은 초기 경고로 다룬다. 누락된 게임플레이 근거를 새 H 카드 수량으로 감추지 않는다.

## 후속 정리 제안

1. 병행 변경이 안정되면 네 `Check` 실패를 각 소유 작업에서 해소한다.
2. `spatial-hierarchy-levels.json`의 H1~H4 기준과 최신 설계 재고의 관점 차이를 기계 대장에 명시하고 H5 링크를 추가한다.
3. `catalog.v3.json`의 배열과 `counts` 요약을 같은 생성 결과로 다시 봉인한다.
4. H5는 H1~H4 위치 독립 재고와 다른 “Scenario 배치 계층”임을 유지하고, H5 존재를 E7 완료로 승격하지 않는다.
