# 플레이어 감각 표현축

## 목적

플레이어가 보는 배치 객체는 위치와 크기만 맞는 것으로 완성되지 않는다. 카메라로 발견할 수 있고, 조명 아래에서 읽히며, 행동 Animation과 FX가 권위 상태에 맞고, 효과음과 UI가 같은 순간을 설명해야 한다.

이 기준은 H 의미 계층이나 E 증거 단계를 추가하지 않는다. 기존 배치 통제의 상향식 성립축과 하향식 제약축을 보존하면서 배치 결과를 플레이어 관점에서 검증하는 교차 표현축을 둔다.

```text
상향식 공간 성립축: H1 → H2 → H3 → H4 준비도
하향식 배치 제약축: World → Area → 건물 → 구역 → 통로 → 설비 → 소품
플레이어 감각 표현축: Graphics / Camera / Animation / Lighting / Audio / UI
```

## 책임 분리

`placement-presentation-bindings.v1`은 공간에 붙는 표현 기준점만 소유한다.

- Camera Focus와 가림·Cutaway 기준점
- Actor Work Anchor와 Tool Socket
- 3D Audio Emitter와 FX Anchor
- 배치 객체·H1 소속과 요청·적용 위치
- `placement-control-hierarchy.v4`와 구조 배치 근거 hash

`wi-presentation-plan.v1`은 권위 상태 사본을 시간에 따라 표현하는 방법을 소유한다.

- WI별 `Available`, `Acquired`, `Working`, `Cancelled`, `Completed` 표현 단계
- 단계별 필수 Graphics·Camera·Animation·Lighting·Audio·UI 영역
- Animation Intent, Audio Cue, FX Cue와 UI Cue
- Area Ambient와 BGM의 선택 채널
- 표현 plan revision/hash와 무효화 조건

배치 계층은 Animation 재생 순서나 BGM 상태를 소유하지 않는다. WI 표현 계획도 Transform·충돌·통로 검증을 다시 계산하지 않는다.

## 음향 범위

PlayableLoop 문답에서 발견되는 개별 효과음·환경음·배경음·음성 요구와 실제 자산·결속·청취 상태는 [PlayableLoop 오디오 요구사항 대장](PlayableLoops/오디오요구사항대장.md)에서 누적 관리한다. 이 문서는 음향 책임과 증거 경계를 소유하고, 대장은 구체적인 Cue 재고와 출처 계보를 소유한다.

| 범위 | 예 | 결속 위치 |
| --- | --- | --- |
| 객체·접촉 효과음 | 도끼 타격, 나무 낙하 | 배치 객체의 3D Audio Emitter |
| Player·UI Cue | 도구 획득, 차단 알림 | Player 또는 UI의 2D Audio Source |
| 공간 Ambient | 바람, 새, 창고 기계음 | H1~H3 환경 표현 기준점 |
| BGM | Nature 탐사 음악, Hub 작업 음악 | AreaSet·플레이 세션 문맥 |

BGM은 개별 도끼나 나무의 속성이 아니며 WI 완료 증거도 아니다. 음원 자산이 없거나 license·출처가 확인되지 않으면 선택 채널을 `Pending`으로 남기고 다른 임의 파일로 대체하지 않는다.

## Animation·Audio 동기화와 권위

```text
Simulation 상태 사본
→ WI 감각 표현 상태 투영
→ Animation / Audio / FX / Camera Intent
→ Unity Adapter
→ Player가 보고 듣는 결과
```

- Animation Event, Audio 완료와 ParticleSystem 종료는 Command·WorldTick·Task 완료를 호출하지 않는다.
- 작업 진행 상태의 `TargetStableId`, 완료 초와 권위 revision을 읽어 타격 Cue 순번을 만든다.
- 같은 상태 사본을 다시 적용해도 같은 Cue를 중복 재생하지 않는다.
- 저장 복원 첫 상태에서는 과거 타격음이나 낙하음을 재생하지 않고 현재 자세와 가시성만 복원한다.
- 취소 상태는 Animation·Loop·FX를 멈추지만 나무·재고·예약 결과를 역으로 변경하지 않는다.

## Nature 첫 적용

`WI-NATURE-05`는 안전 빈터의 도끼를 Camera Focus와 Tool Socket에 결속한다. 도끼 획득 권위 상태를 확인한 뒤에만 1인칭·3인칭 도구 View와 획득 Cue를 활성화한다.

`WI-NATURE-06`은 나무별 Camera Focus, Actor Work, Audio Emitter와 FX Anchor를 사용한다. 벌목 진행 초가 증가할 때 도끼 휘두르기·타격음·나무 파편을 표현하고, 권위 상태가 `Stump`가 된 뒤에만 나무 낙하 표현과 낙하음을 재생한다.

현재 저장소에는 승인된 Nature Ambient·BGM 음원 파일이 없으므로 객체 효과음은 `ProceduralFallback`으로 출처를 명시하고, Ambient와 BGM은 선택 채널의 미결 상태로 남긴다.

## 증거 경계

- E4는 WI와 H·표현 요구의 결속을 검토한다.
- E5는 권위 상태 전이와 결정적 세계 발현을 검증한다.
- E6는 기준점, 자산, 카메라·조명, Animation·Audio·FX fallback과 품질 예산을 정제한다.
- E7은 canonical `SimulationWorldShell`의 실제 입력, Game View, Animation 중단·복귀, 들리는 Audio와 Console을 별도 EvidencePackage로 검증한다.

계약·EditMode·자동 PlayMode 통과만으로 실제 사람이 보고 들은 E7 증거를 선언하지 않는다.
