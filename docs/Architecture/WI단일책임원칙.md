# WI 단일 책임 원칙

## 1. 목적

WI(World Interaction)는 절차의 한 칸이나 특정 Actor 전용 함수가 아니다. WI 하나는 다음 두 가지를 함께 만족하는 가장 작은 권위 행동 단위다.

- 한 행위자의 한 가지 의도
- 그 의도가 성공했음을 나타내는 하나의 주요 권위 결과

플레이어와 NPC가 같은 대상에 같은 의도를 실행해 같은 결과를 만든다면 같은 WI를 사용한다. 누가 실행했는지는 WI 정의가 아니라 실행 인스턴스의 발생원·Actor 결속에 기록한다.

기계 원본은 다음 두 대장이다.

- 단일 책임 판정: `eng/execution-ledgers/world-interaction-responsibilities.json`
- 여러 WI의 순서·분기·반복 조립: `eng/execution-ledgers/world-interaction-flows.json`

실행의 행동 목적과 실제 Player/NPC 수행 주체는 [WI 음양·수행주체 사분면 체계](WI음양수행주체사분면체계.md)가 별도로 분류한다. 사분면이 달라도 WI의 의도와 주요 결과는 바뀌지 않는다.

## 2. 책임 분리

| 구성 | 소유 책임 | 소유하지 않는 것 |
| --- | --- | --- |
| WI | 한 의도, 하나의 `primaryOutcomeCode`, 권한·취소·멱등 경계 | 전체 업무 절차, 다음 WI 강제 실행, 특정 Actor 종류 |
| 실행 인스턴스 | Player/NPC/World 발생원, Actor·대상·자원·시간·공간 결속 | WI의 업무 의미 변경 |
| Preview | 같은 WI를 실행할 수 있는지 읽기 전용 판정 | 예약·상태 변경 |
| Confirm | 같은 WI의 의도와 필요한 예약 확정 | 여러 후속 WI의 완료 |
| Task | 같은 WI의 시간 진행과 취소 가능 상태 | 다른 WI의 결과 대행 |
| Effect | 주요 결과와 원자성을 지키는 부수 상태 변경 | 독립적으로 선택·실패할 수 있는 별도 행위 |
| WI 조립 흐름 | 여러 WI의 선택 가능한 순서·분기·반복·귀환 | 개별 WI의 정체성·권위 결과 |

Preview → Confirm → Task → Effect는 네 개의 절차 WI가 아니라 한 책임의 실행 생명주기다.

## 3. 단일 책임 판정 질문

새 WI 또는 기존 WI를 검토할 때 다음 순서로 판정한다.

1. 이 WI를 시작한 행위자의 의도를 한 문장으로 말할 수 있는가?
2. 완료 사실을 하나의 `primaryOutcomeCode`로 말할 수 있는가?
3. 포함된 효과 중 하나를 별도로 선택·취소·실패·재시도할 수 있는가?
4. Actor를 Player에서 NPC로 바꿔도 의도와 결과가 같은가?
5. 선행·후속 WI가 없어도 이 WI의 의미를 설명할 수 있는가?

3번이 “예”이면 별도 WI로 분리한다. 4번이 “예”이면 Actor별 WI를 새로 만들지 않고 같은 WI의 실행 문맥만 바꾼다. 5번이 “아니오”이면 WI가 절차 위치를 정체성으로 삼고 있으므로 이름과 책임을 다시 정의한다.

## 4. 여러 효과가 허용되는 경우

단일 책임은 Effect가 반드시 한 개여야 한다는 뜻이 아니다. 하나의 주요 결과가 깨지지 않도록 같은 트랜잭션에서 함께 성공하거나 실패해야 하는 부수 효과는 허용한다.

| WI | 주요 결과 | 허용되는 원자적 부수 효과 |
| --- | --- | --- |
| `WI-FARM-04` 익은 농작물 수확 | `HarvestLotCreated` | 재배 단위를 수확 완료로 닫는다. 수확물만 생기거나 재배 단위만 사라지는 상태를 허용하지 않는다. |
| `WI-002` 검수 완료 화물 창고 적재 | `PutAwayCompleted` | 보관 용량 소비와 작업 영역 해제를 같은 적재 트랜잭션에 남긴다. |
| `WI-NATURE-12` 진행 중 작업 취소 | `WorkCancelled` | 해당 작업이 소유한 예약과 미사용 자원을 함께 반환한다. |
| `WI-CARD-01` 메이저 아르카나 활성화 | `MajorArcanaActivated` | 방향과 영향 상태 사본을 같은 활성화 인스턴스에 동결한다. |

성공과 실패처럼 서로 배타적인 결과는 `AlternativeOutcomes`로 분류한다. 하나의 판정이 정확히 한 결과만 만들 때는 한 WI로 유지할 수 있다.

## 5. 분리해야 하는 경우

다음은 별도 책임이다.

- 업무 위임과 위임받은 NPC의 실제 작업
- 활동 시작과 활동 종료
- 대응 방식 선택과 전투 엔진 인계와 전투 결과 반영
- 수면 시작과 세계 시간 진행과 수면 종료
- 아이템 제작과 나중의 아이템 사용 효과

현재 호환 때문에 즉시 식별자를 바꾸지 못하는 복합 WI는 `LegacyCompositeMigrationRequired`로 표시한다. 이 상태는 완료나 승격이 아니라 다음 Runtime migration의 차단 증거다.

| 기존 WI | 분리 대상 |
| --- | --- |
| `WI-001` | 입고 화물 검수 완료 / 운송 화물 인수 확정 |
| `WI-NATURE-11` | 대응 방식 확정 / 전투·후퇴 인계 / 조우 결과 반영 |
| `WI-NATURE-14` | 수면 시작 / 세계 시간 진행 / 수면 종료 |
| `WI-NATURE-16` | 현장 보급 제작 / 원정에서 보급 효과 사용 |
| `WI-NATURE-17` | 제작 업무 위임 / NPC의 실제 제작 |
| `WI-WORLD-07` | 세계 활동 시작 / 세계 활동 종료 |

독립 의도 없이 부모 작업의 진행 상태만 나타내는 기존 WI는 Task 단계나 Effect로 내린다.

| 기존 WI | 이동할 책임 |
| --- | --- |
| `WI-LOG-02` | 운송 Task의 출발 단계 |
| `WI-LOG-03` | 운송 Task 진행도 |
| `WI-LOG-04` | 운송 Task의 도착·자동 하차 단계. 실제 하차 Actor를 도입하면 별도 행동 WI로 만든다. |
| `WI-LOG-05` | 입고 검수 또는 별도 인수 Command의 Effect |
| `WI-ORDER-02` | 주문 확정의 재고 예약 Effect |
| `WI-ORDER-05` | 주문 포장의 수령 준비 Effect |

반대로 실제 Actor가 시간·공간·자원을 사용해 수행하는 일을 `WorldAutomatic` 절차로 숨기지 않는다.

| 기존 WI | 목표 책임 |
| --- | --- |
| `WI-HUB-04` | NPC의 출고 재고 피킹 |
| `WI-HUB-05` | NPC의 출고 화물 포장 |
| `WI-ORDER-03` | NPC의 주문 상품 피킹 |
| `WI-ORDER-04` | NPC의 주문 상품 포장 |

기존 API·Event·save·replay 계보를 제자리에서 다른 의미로 바꾸지 않는다. 새 실행 판본에서 책임별 Command·Transition을 추가하고, 과거 판본은 당시 결과를 그대로 읽는다.

## 6. 절차 조립 규칙

`predecessorWiIds`와 `successorWiIds`는 기존 대장의 읽기 호환용 힌트이며 새 권위가 아니다. 실제 조립 권위는 `world-interaction-flows.json`이 가진다.

- Farm·Hub·City 같은 독립 영역 내부 흐름은 `IndependentAreaLoop`로 관리한다.
- Farm→Hub나 Hub→Market 연결은 `OptionalAreaConnector`이며 어느 한 영역의 성립 조건이 아니다.
- Nature처럼 선택·후퇴·반복이 있는 흐름은 `BranchingAreaLoop`로 관리한다.
- 같은 WI는 여러 흐름에 참여할 수 있다.
- 흐름 안의 위치나 대장 순번은 WI 이름·ID·책임을 바꾸지 않는다.

## 7. 이름과 코드 규칙

- 사람에게는 `한국어 작업군 · 한국어 기능명 (안정 WI ID)` 순으로 표시한다.
- `sequence`는 대장 탐색 순번이며 “1단계·2단계”로 표시하지 않는다.
- 이름은 행위를 나타내는 동작과 대상을 중심으로 짓는다.
- `준비·처리·관리`처럼 여러 행동을 숨기는 이름은 주요 결과가 무엇인지 다시 확인한다.
- 기술 역할은 영어, 업무 의미와 사람이 읽는 변수는 한국어 중심으로 작성한다.

예:

```text
자연 탐사·생활 거점 · 오두막을 지을 터 선정 (WI-NATURE-07)
물류 거점 창고 · 입고 화물 검수 (WI-001)
```

## 8. 완료 경계

이번 기준선은 60개 WI의 주요 결과·다중 효과·자동 절차를 감사하고 조립 흐름을 분리한 E3 구조 증거다. 복합 책임 6개, 절차 강등 6개, Actor 행동 전환 4개의 Runtime·저장 migration과 실제 Play Mode·지속 NPC 생활세계가 완료되었다는 뜻은 아니다.

후속 구현은 복합 WI 하나씩 다음 순서로 진행한다.

1. 과거 저장·API 계보 고정
2. 새 책임별 Command 또는 AutomaticTransition 계약 추가
3. LocalProcess와 RemoteHost가 같은 Core를 사용하는지 검증
4. save·restore·replay hash migration 검증
5. 기존 WI를 호환 Adapter로만 남김
6. 실제 플레이·NPC 생활세계 증거가 생긴 뒤 승격 판정
