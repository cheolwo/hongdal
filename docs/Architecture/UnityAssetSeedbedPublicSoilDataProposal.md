# Unity 에셋 모판·공공데이터·토양자료 연결 제안

## 1. 목적과 상태

- 기준일: 2026-08-11
- 상태: P0·P1 일부 구현 (`에셋연구-5 감자 토양 모판`), 실제 관측 연결은 제안 단계
- 조사 범위: 공공데이터포털에 공개된 토양·농업기상·농업용수·농기계·온실 자료의 메타데이터와 현재 Unity 신티 에셋 연구소 구조
- 구현 범위: 공공 관측 출처표, 자료 연구 단계, 감자 토양 모판 4개 표본과 한국어 카드까지 구현했다. 활용신청, 인증키 조회, 실제 API 호출과 운영 저장은 수행하지 않았다.

이 제안은 신티 Farm Pack 에셋을 바로 실제 Farm Scene에 배치하지 않고, 모판에서 현실 의미와 공공 관측 후보를 연구한 뒤 검증된 것만 옮겨 심는 절차를 정의한다.

```text
에셋 원본
  ↓
에셋 모판
  ├─ 외형에서 관찰한 사실
  ├─ 현실 의미
  ├─ 공공데이터 후보
  ├─ 실제 관측 또는 미수집 상태
  ├─ 알 수 있는 것과 알 수 없는 것
  └─ Scene 승격 Gate
        ↓
장소 연구
  ↓
작은 Simulation
  ↓
Farm Scene 이식
```

모판은 단순한 prefab 전시장이 아니라 `현실 관측 후보를 검토하는 연구 공간`이다. 공공데이터가 연결됐다는 사실만으로 Scene object의 실제 상태, 특정 농장의 운영 사실 또는 재배 권고가 되지는 않는다.

## 2. 핵심 결론

첫 확장은 하나의 거대한 `공공데이터 모판`보다 다음 네 모판으로 나누는 편이 좋다.

| 모판 | 대표 에셋 | 관측 후보 | 핵심 경계 |
| --- | --- | --- | --- |
| 토양 모판 | Dirt, Dirt Row, Dirt Mound, 밭 구획 | 토양검정·토양특성·작물별 토양적성 | 필지 검정, 지역 통계와 토양도 해석을 합치지 않음 |
| 농업환경 모판 | Greenhouse, Sprinkler, Well, Water Tower, Windmill | 농업기상·강수·저수율 | 외부 관측이 온실 내부 상태나 실제 관수 실행을 증명하지 않음 |
| 생산기반 모판 | Tractor, Harvester, Planter, Barn, Silo | 지역 농기계 보유·온실 및 시설재배 통계 | 지역 통계가 선택한 장비·시설의 소유와 가동 상태를 증명하지 않음 |
| 상품·유통 모판 | 작물, 수확물, Box, Produce Stand | KAMIS 품목·가격 관측 | 에셋 수량과 가격·재고·출하를 연결하지 않음 |

`토양 모판`을 다음 구현 1순위로 권한다. 흙·밭고랑·감자 작물·급수 소품을 한 장소에서 함께 연구할 수 있고, 이미 만든 KAMIS 작물 모판과도 자연스럽게 이어지기 때문이다.

## 3. 공공데이터포털 조사 결과

### 3.1 P0 토양 필지 관측

#### 팜맵기반 토양검정 조회 서비스

- 제공기관: 농림수산식품교육문화정보원
- 포털: [공공데이터포털 15058655](https://data.go.kr/data/15058655/openapi.do)
- 조회 단위: 좌표, PNU, 팜맵 ID
- 응답: JSON·XML
- 좌표 조회 요청 경로: `/B552895/rest/farmmap/getFarmmapSoilAnalysisService/getCoordinateBasedSoilAnalsInfo`
- 좌표 조회 필수 입력: `serviceKey`, `numOfRows`, `pageNo`, `type`, `positionX`, `positionY`; `year`는 선택
- 확인된 값 후보: 팜맵 경계, 판독명, 채취년도·일자, 산도, 유기물, 유효인산, 유효규산, 전기전도도와 일부 비료·석회 관련 값
- 포털 수정일: 2026-06-30
- 포털 표시 조건: 무료, 출처표시 제1유형, 개발·운영 자동승인, 개발계정 10,000건

이 자료는 `밭 구획`과 가장 가까운 관측 후보지만, 응답이 존재한다고 해서 현재 Unity 밭의 실제 토양이라고 간주하지 않는다. 좌표계, 조회년도, 시료 채취일과 팜맵 경계를 함께 보존해야 한다.

#### 토양검정 화학성 상세정보 V2

- 제공기관: 농촌진흥청 국립농업과학원
- 포털: [공공데이터포털 15144647](https://data.go.kr/data/15144647/openapi.do)
- 조회 단위: 지번코드 또는 법정동·리
- 응답: XML
- 범위: 최근 3년 이내 최신 검정 결과 1건
- 확인된 값 후보: 유기물, 산도, 인산, 칼륨, 석회, 마그네슘, 채취년도, 검정일, 경지 구분
- 포털 표시 조건: 무료, 출처표시·상업적 이용금지·변경금지 제4유형, 개발·운영 자동승인, 개발계정 1,000건

`최근 3년 이내 최신 1건`은 현재 시각의 센서값이 아니다. 카드에는 검정일과 최신성 한계를 반드시 표시한다.

### 3.2 P0 토양도·작물 적성

#### 토양도 기반 작물별 토양적성 통계정보 V2

- 제공기관: 농촌진흥청 국립농업과학원
- 포털: [공공데이터포털 15144182](https://data.go.kr/data/15144182/openapi.do)
- 응답: XML
- 요청 경로: `/1390802/SoilEnviron/SoilFitStat/V2/getSoilCropFitInfo`
- 필수 입력: `serviceKey`, 법정동코드 10자리 `STDG_CD`, 토양적성작물코드 `soil_Crop_CD`
- 감자 공식 코드: 흙토람 작물 목록에서 `CR032`
- 확인된 값 후보: 작물명, 토양 유형, 매우 적합·적합·보통·부적합 등급, 등급별 면적과 비율
- 확인된 응답 필드: `stdg_Cd`, `bjd_Nm`, `soil_Crop_Cd`, `soil_Crop_Nm`, `high_Suit_Area`, `suit_Area`, `poss_Area`, `low_Suit_Area`, `etc_Area`
- 포털 표시 조건: 무료, 공공저작물 제4유형, 개발·운영 자동승인, 개발계정 1,000건

이 자료는 KAMIS 작물 모판과 토양 모판을 연결하기에 적합하다. 공식 흙토람 목록에서 감자 `CR032`를 확인했지만, 적성 등급을 실제 생산량, 수익성 또는 재배 권고로 확대 해석하지 않는다.

2026-08-11에 저장소의 기존 `PublicData:DataGoKrServiceKey`로 공개 예시 법정동코드 `5271033024`와 감자 `CR032`를 요청했으나 HTTP 403이 반환됐다. 인증키 인코딩 방식도 구분해 재확인했으므로 현재 공통 키에는 이 API의 활용 승인이 없는 것으로 본다. 실제 응답을 받지 못했으므로 연구 단계는 `메타데이터 확인`을 유지한다.

#### 토양도 기반 토양특성 상세 정보 V3

- 제공기관: 농촌진흥청 국립농업과학원
- 포털: [공공데이터포털 15144225](https://data.go.kr/data/15144225/openapi.do)
- 조회 단위: 19자리 PNU와 토양부호
- 기준 지도: 1:5,000 토양도
- 응답: XML
- 확인된 값 후보: 배수등급, 유효토심, 침식등급, 표토 토성·자갈 함량, 지형, 토지이용 추천, 논·밭·과수·초지·임지 적성과 저해요인 등 27종
- 포털 표시 조건: 무료, 공공저작물 제4유형, 개발·운영 자동승인, 개발계정 1,000건

토양특성 V3는 Dirt·Dirt Row·Dirt Mound 같은 흙 에셋의 색을 실제 토색으로 바꾸는 자료가 아니다. 우선은 카드와 범례로 표현하고, 시각 변화가 필요하면 별도 Interpretation rule과 legend를 검증한다.

### 4.2 카드 구조

```text
토양 관측 카드
├─ 연결 상태
│   ├─ 후보
│   ├─ 메타데이터 확인
│   ├─ sample 응답 확인
│   └─ 실제 관측 연결
├─ 공식 출처와 Dataset ID
├─ 공간 단위
│   ├─ 좌표 / 팜맵 ID / PNU
│   └─ 법정동 / 시군구 / 시도
├─ 시간 단위
│   ├─ 채취일 / 검정일 / 조회년도
│   └─ 갱신·최신성
├─ 관측값과 원문 단위
├─ 이 자료로 알 수 있는 것
├─ 이 자료로 알 수 없는 것
└─ Scene 승격 상태
```

PNU와 정확 좌표는 서버 조회 경계에 머물게 하고 일반 전시장에는 기본적으로 법정동 이하의 정확 위치를 노출하지 않는다. 사용자 소유·임차 농지라는 명시적 권한과 목적이 없으면 특정 필지를 선택한 에셋과 연결하지 않는다.

## 5. 데이터와 표현 경계

```text
공식 원천 응답
  → Server Provider
  → 원문 보관·정규화
  → Observation Snapshot
  → World Interpretation
  → 에셋 모판 Card

별도 흐름
Simulation Snapshot
  → Simulation 비교 Card
```

- 인증키는 서버의 .NET User Secrets에만 두고 Unity·Scene·Catalog·로그에 넣지 않는다.
- 원문 응답에는 source key, operation, request scope, collected time, observed time, unit, license와 raw hash를 보존한다.
- 필지 관측, 지역 통계, 토양도 적성과 농업기상을 하나의 평균 점수로 합치지 않는다.
- 결측과 API 실패는 sample 값으로 대체하지 않는다.
- 색·FX·작물 생육 변화는 Interpretation이며 원문 관측값과 rule revision을 추적할 수 있어야 한다.
- 공공데이터는 읽기 관측이다. 관수, 비료 투입, 파종, 수확 또는 출하 Command를 자동 실행하지 않는다.

## 6. 모판에서 Scene으로 옮겨 심는 Gate

| 단계 | 한국어 상태 | 통과 조건 |
| --- | --- | --- |
| S0 | 자료 후보 | 공식 Dataset URL과 제공기관을 확인 |
| S1 | 메타데이터 확인 | operation, 공간·시간 단위, 값·단위, 이용 조건을 확인 |
| S2 | 표본 응답 확인 | 실제 호출 1건을 server-side에서 받고 source·기준 시각·결측을 보존 |
| S3 | 관측 모델 연결 | Unity가 아닌 서버 contract에서 nullable·provenance·revision 확정 |
| S4 | 모판 장소 검증 | 카드와 에셋이 무엇을 알 수 있고 없는지 Game View에서 확인 |
| S5 | 작은 Simulation 검증 | 관측과 별개인 Preview·Confirm·Tick 효과를 검증 |
| S6 | Scene 승격 | stable-ID mapping과 VisualKey로 실제 Farm Scene에 이식 |

`S2`부터는 활용신청과 인증키가 필요할 수 있다. 사용자의 별도 승인 없이 포털에서 활용신청을 제출하지 않는다.

## 7. 권장 구현 우선순위

### P0 — 토양 모판 계약

1. `공공관측SourceCatalog`에 Dataset ID, operation, 공간·시간 단위, license와 이용 조건을 기록한다.
2. `에셋공공관측Entry`가 하나의 source만 가리키는 구조를 여러 관측 후보를 전환할 수 있게 확장한다.
3. `후보 → 메타데이터 확인 → 표본 응답 확인 → 실제 관측 연결` 상태를 분리한다.
4. PNU·좌표의 공개 수준과 authorized World scope를 먼저 정한다.

### P1 — 감자 토양 모판 첫 세로 단위

```text
Dirt Row
  + 감자 대표 작물
  + Potato Box
  + Sprinkler

KAMIS 품목 관계
  + 토양도 작물적성 후보
  + 팜맵 토양검정 후보
  + 외부 농업기상 후보
```

첫 단계에서는 metadata 카드만 만든다. 토양적성 API의 공식 작물코드에 감자가 존재하는지 확인한 뒤 sample 응답을 호출한다. 지원하지 않으면 이름으로 억지 연결하지 않고 `공식 작물코드 미확인`으로 남긴다.

### P2 — 서버 Provider·보관

먼저 하나의 원천만 연결한다. 추천 순서는 `토양도 기반 작물별 토양적성 통계정보 V2 → 팜맵기반 토양검정 → 팜맵기반 농업기상`이다. 지역 집계에서 시작한 뒤 명시적 필지 선택과 권한 경계가 준비되면 PNU·좌표 조회로 좁힌다.

### P3 — 다른 Farm 에셋 모판

- Greenhouse: 농업기상 + 온실현황
- Water Tower·Well·Sprinkler: 강수·저수율 후보
- Tractor·Harvester·Planter: 지역 농기계 보유와 임대사업소 후보
- Barn·Silo: 생산·저장 관련 공식 자료를 추가 탐색하되 시설 외형만으로 저장량을 추론하지 않음
- Produce Stand·Box: KAMIS 관측과 Cargo·재고 원장을 분리

### P4 — Farm Scene 이식

S6를 통과한 표본 하나만 실제 감자밭 Scene에 이식한다. 다품목·다필지 확장은 첫 object의 출처·상태·오류·재접속 경계가 닫힌 뒤 진행한다.

## 8. 이번 조사에서 하지 않은 일

- 공공데이터포털 활용신청 제출
- 인증키·마이페이지 신청내역·개인정보 조회
- API 실제 호출과 비용·트래픽 소비
- 다운로드 문서 저장
- 서버 options·User Secrets 변경
- Unity Catalog·Scene·prefab·Game View 변경
- commit·push·배포

다음 작업은 P0 계약을 구현하기 전에, 제안서의 첫 원천과 공개 위치 단위를 사용자와 확정하는 것이다.
