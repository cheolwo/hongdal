## 1. 이번 단계의 목적

이번 단계에서는 타로 78장의 세부 효과나 장기 밸런스를 완성하지 않는다. 앞으로 카드와 시나리오가 늘어나도 다시 뜯어고치지 않을 다음 뼈대를 먼저 고정한다.

```text
일반 타로 원형
  ↓
게임용 해석
  ↓
시나리오 덱
  ↓
결정론적 카드 제안 3장
  ↓
카드 1장과 경영 대응 선택
  ↓
영향받는 배치 객체·예상 결과 미리보기
  ↓
명시적 턴 마감 확정
  ↓
다음 날 활성 규칙
  ↓
개별 업무 미리보기·확정
  ↓
서버 기준 상태 사본 재조회
  ↓
Unity World 표현 갱신
```

핵심은 **카드가 결과를 즉시 확정하지 않고, 다음 경영일에 적용할 조건과 대응 선택을 연다**는 것이다. 실제 생산·운송·입고·재고·판매 변화는 기존 시뮬레이션 업무의 미리보기와 확정, 기준 상태 재조회 경계를 그대로 따른다.

## 2. 게임의 중심 문장

> 매 턴 뽑은 일반 타로 카드가 농장·물류·마트·주민 세계의 조건을 바꾸고, 플레이어는 제한된 자원과 선택으로 그 운명을 경영한다.

타로는 미래를 맞히는 점술 판정이 아니라, 복잡한 경영 상황을 기회·부담·갈등·균형의 언어로 제시하는 게임 문법이다.

## 3. 현재 프로젝트에서 재사용할 기반

### 3.1 배치 객체 기반

현재 배치 객체 15개는 모두 O5 모판 실행 검증까지 완료했다. 이 가운데 다음 7개는 `SimulationWorldShell`에 실제로 배치하여 O6 실제 World 배치 검증까지 완료했다.

| 배치 객체 | 고유 식별자 | 현재 표현 의미 |
| --- | --- | --- |
| 감자 수확 상자 | `seedbed-object:farm.potato-harvest-box.a` | 수확 Lot·수확 화물 |
| 농장 출하 Pallet Crate | `seedbed-object:farm.pallet-crate.a` | 출하 대기 화물 |
| Hub 입고 Gate | `seedbed-object:town.hub-inbound-gate.a` | 도착·검수·입고 경계 |
| 화물 배송 차량 | `seedbed-object:town.delivery-truck.a` | 화물 이동·운송 작업 |
| 공용 화물 Pallet | `seedbed-object:shared.cargo-pallet.a` | 화물·창고 인계 |
| 도심마트 Shop | `seedbed-object:city.urban-market-building.a` | 공개 상품·수요 신호 |
| 집단수요 Cart Table | `seedbed-object:town.grouping-cart-table.a` | 개인정보 제거 집단화 미리보기 |

카드 반응은 GameObject 이름이나 배치 순서가 아니라 위 고유 식별자를 사용한다. 배치 객체는 카드 효과나 업무 완료 상태를 소유하지 않고, 서버가 계산한 관점별 조회 결과만 표현한다.

### 3.2 턴 마감 기반

현재 시뮬레이션 서버와 Unity에는 다음 경계가 구현되어 있다.

```text
턴 상황 조회
→ 턴 마감 미리보기
→ 명시적 확정
→ 같은 세션의 기준 상태 사본 재조회
```

기존 API 경로와 `ExpectedRevision`, 멱등 Command, 다음 날 효과, 저장·재생 해시는 유지한다. 일반 타로 뽑기는 이 흐름 앞에 새로운 권위 체계를 만들지 않고 기존 턴 상황에 포함한다.

### 3.3 기존 카드와의 호환

현재 바보·전차는 홍익학당 해석을 가진 개발용 Fixture다. 이 카드의 고유 식별자와 의미를 일반 타로 카드로 덮어쓰지 않는다.

```text
기존 학당 전차
learning:hongik.chariot.integrated-progress

새 일반 타로 전차 예시
tarot:major.chariot
```

일반 타로가 기본 게임 덱을 구성한다. 학당·철학, 지역문화, 공공관측과 경영사건은 이후 선택형 콘텐츠 묶음 또는 별도 모판으로 결합할 수 있다.

### 3.4 시뮬레이션 규칙의 상하 구조

일반 타로 규칙은 기존 생산·소비·운송·창고·시장 규칙 위에서 작동하는 **상위 조율 규칙**으로 둔다. 타로 규칙은 활성 카드와 방향·대응에 따라 하위 규칙이 사용할 허용된 입력이나 계수에 플러스 또는 마이너스 보정을 제공한다. 기존 규칙은 이 보정을 받아 최종 미리보기와 자원 효과 묶음을 계산한다.

```text
활성 타로 카드·방향·경영 대응
  ↓
타로 상위 조율 규칙
  ├─ 적용할 하위 규칙 선택
  ├─ 플러스·마이너스 보정선 생성
  ├─ 적용 기간·대상·상한·하한 지정
  └─ 기회와 부담을 하나의 효과 묶음으로 제공
        ↓
기존 하위 업무 규칙
  ├─ 생산 규칙
  ├─ 소비 규칙
  ├─ 운송 규칙
  ├─ 창고·재고 규칙
  ├─ 시장 규칙
  └─ 시설·시간 규칙
        ↓
보정 전 기준 후보와 보정 후 최종 후보 계산
        ↓
수량·용량·단위·상태 전이 불변 조건 검증
        ↓
미리보기 또는 확정 가능한 자원 효과 묶음
```

여기서 상위라는 말은 타로 규칙이 기존 업무 규칙의 계산 결과를 마음대로 덮어쓴다는 뜻이 아니다. 각 하위 규칙은 자신이 허용하는 **보정 연결 지점**을 명시하고, 타로는 그 연결 지점에만 값을 제공한다. 하위 규칙은 보정된 입력으로 결과를 다시 계산하고 기존 검증을 모두 통과시킨다.

수량 보존, 음수 재고 금지, 차량·창고 용량, 단위 일치, 권한, 현재 업무 상태, 시뮬레이션·실운영 분리는 타로보다 위에 있는 또 다른 게임 규칙이 아니라 전체 규칙 계층을 둘러싼 **불변 안전 조건**이다. 어떤 카드도 이를 완화하거나 우회할 수 없다.

예를 들어 전차 정방향과 빠른 운송 대응은 다음처럼 여러 하위 규칙에 서로 다른 부호로 영향을 줄 수 있다.

| 하위 규칙의 대상 값 | 보정 예시 | 경영 의미 |
| --- | ---: | --- |
| 운송 기간 | `-1턴` | 더 빠른 도착 기회 |
| 운송 처리 용량 | `+20%` | 실제 화물량을 만들지 않고 한 턴의 처리 가능 용량만 확대 |
| 연료 소비 | `+10%` | 속도를 얻는 비용 |
| 노동 소비 | `+10%` | 기사·상하차 부담 증가 |
| 위험 후보 | `+5%p` | 무리한 진행의 부담 |

이 값은 구조를 설명하기 위한 임시 예시이며 최종 밸런스가 아니다. 플러스가 항상 이익이고 마이너스가 항상 손해인 것도 아니다. 운송 기간 `-1턴`은 이익일 수 있지만 재고 `-10kg`은 손실이다. 따라서 보정선에는 부호뿐 아니라 대상 자원, 단위, 계산 방식과 의미 코드를 함께 기록한다.

첫 뼈대에서는 다음 보정 방식만 허용한다.

- 고정값 더하기 또는 빼기
- 비율 곱하기
- 최소·최대 범위 제한
- 기존 대응 행동 열기 또는 차단

보정 적용 순서는 `고정값 → 비율 → 최소·최대 제한`으로 고정한다. 첫 구현은 다음 경영일에 활성 카드 한 장만 허용하므로 여러 타로 카드의 중첩 우선순위는 아직 만들지 않는다. 정방향과 역방향은 같은 값을 단순히 양수·음수로 뒤집지 않고 각각 별도의 보정 묶음을 가진다.

## 4. 타로 상위 규칙 계약

타로 상위 규칙 상태 사본은 최소한 다음을 보존한다.

- 상위 규칙 고유 식별자와 개정 번호
- 원천 카드·방향·선택 대응의 고유 식별자
- 활성 시작·종료 턴
- 대상 하위 규칙 영역과 호환 가능한 규칙 개정 번호
- 보정 연결 지점 코드
- 계산 방식, 값, 단위, 최소·최대 범위
- 이익·부담·위험 의미 코드
- 보정 전 값, 보정값과 보정 후 후보값
- 원천 턴 마감 기록과 데이터 계보

기존 하위 규칙도 자신이 받을 수 있는 보정 연결 지점과 허용 범위를 선언한다. 등록되지 않은 연결 지점, 단위가 다른 보정, 호환되지 않는 규칙 개정 번호, 허용 범위를 넘는 보정은 실패 상태로 닫는다.

서버 미리보기는 다음 세 값을 함께 반환한다.

1. 카드가 없을 때 기존 하위 규칙의 기준 후보
2. 타로 상위 규칙이 제공한 보정선
3. 하위 규칙이 보정을 소비하고 불변 조건을 검증한 최종 후보

따라서 Unity는 단순한 `+10%`만 보여주지 않고, 어떤 카드와 대응이 어떤 기존 규칙의 어느 값에 영향을 주었는지 설명할 수 있다. 확정할 때는 사용한 상위·하위 규칙 개정 번호와 보정선을 저장·재생 해시에 함께 포함한다.

## 5. 반드시 분리할 여섯 가지 데이터

### 5.1 타로 원형 정의

카드 자체의 변하지 않는 정체성이다.

- 카드 고유 식별자
- 대아르카나 또는 문양·숫자
- 한국어 표시 이름
- 일반 상징어
- 참고 체계와 이미지 이용 조건

원형 정의에는 감자 생산량, 연료비, 주민 신뢰 같은 특정 시나리오 수치를 넣지 않는다.

### 5.2 게임용 해석 정의

일반 타로 상징을 경영 게임의 질문으로 번역한다.

- 정방향의 기회와 부담
- 역방향의 기회와 부담
- 반응 가능한 경영 분야
- 열 수 있는 대응 행동의 종류
- 절대로 직접 변경하지 않을 기준 원장 상태
- 해석 개정 번호

정방향을 무조건 보상, 역방향을 무조건 벌칙으로 만들지 않는다.

### 5.3 시나리오 덱 정의

특정 시나리오에서 실제로 뽑을 카드 묶음이다.

- 시나리오와 덱 고유 식별자
- 덱 개정 번호
- 카드 복사본별 고유 식별자
- 카드 수와 가중치
- 정·역방향 허용 여부
- 한 번에 제안할 카드 수
- 선택할 카드 수
- 버린 카드와 재섞기 규칙

첫 목표는 8개 카드 정의와 12칸 시작 덱이지만, 중복 카드 배분은 밸런스 확정값이 아니라 개정 가능한 시나리오 자료로 둔다.

### 5.4 턴 카드 제안 상태 사본

서버가 현재 턴에 제시한 개별 카드 세 장이다.

- 제안 고유 식별자
- 카드 복사본 고유 식별자
- 카드·덱·효과 규칙 개정 번호
- 정방향 또는 역방향
- 표시 순서
- 생성에 사용한 결정 근거
- 선택 가능 여부와 차단 사유

같은 종류의 카드가 여러 장 있을 수 있으므로 선택 요청은 카드 종류가 아니라 제안 고유 식별자를 사용한다.

### 5.5 경영 대응 정의

카드를 고른 뒤 플레이어가 선택할 수 있는 대응이다.

예를 들어 전차는 다음 대응을 열 수 있다.

- 빠른 운송
- 안전 운송
- 화물 합배송

대응 정의에는 예상되는 이익·비용·노동·기간·위험의 계산 규칙 개정 번호가 들어간다. 실제 후보 수치는 현재 세션 상태를 받은 서버가 계산한다.

### 5.6 배치 객체 반응 관점별 조회 결과

현재 세션에서 실제로 영향을 받을 배치 객체를 서버가 계산해 Unity에 돌려주는 읽기 결과다.

- 배치 객체 고유 식별자
- 영향 분야와 이유
- 예상 변화 요약
- 강조 표현 종류
- 관련 업무·화물·Lot·시설의 고유 식별자
- 미확인 또는 적용 불가 사유
- 실제 업무 확정이 별도로 필요한지 여부

정적인 카드표는 영향 가능 대상만 정한다. 현재 재고나 화물이 없는 객체를 Unity가 임의로 영향 대상으로 만들지 않는다.

## 6. 첫 네 장의 뼈대

첫 모판 후보는 여제·전차·정의·절제로 제한한다.

| 카드 | 일반 경영 질문 | 정방향의 기회·부담 | 역방향의 기회·부담 |
| --- | --- | --- | --- |
| 여제 | 무엇을 돌보고 길러야 하는가 | 생산·품질 기회 / 노동·관수·관리 부담 | 투입 축소·휴식 기회 / 생산 저하 위험 |
| 전차 | 얼마나 빠르게, 어떤 통제로 이동할 것인가 | 속도·처리량 기회 / 연료·노동·사고 부담 | 합배송·정비 기회 / 지연·기회비용 부담 |
| 정의 | 무엇을 같은 기준으로 검증하고 나눌 것인가 | 수량·계약·분배 안정 / 검수 비용 | 재검토 기회 / 분쟁·신뢰 저하 위험 |
| 절제 | 어떤 자원을 섞고 아껴 균형을 맞출 것인가 | 재고·노동·관수 균형 / 단기 수익 감소 | 병목 발견 기회 / 손실·과잉 투입 위험 |

이 표는 최종 수치표가 아니다. C0 카드 씨앗과 C2 게임 내용 검수를 시작하기 위한 질문 뼈대다.

## 7. 첫 객체 반응 범위

첫 구현에서는 O6 실제 World 배치 검증을 마친 7개만 강조 대상으로 삼는다.

| 카드 | 우선 반응 객체 | 아직 포함하지 않는 후속 객체 |
| --- | --- | --- |
| 여제 | 감자 수확 상자, 도심마트 Shop | 감자 재배체, 온실 |
| 전차 | 농장 출하 Crate, 화물 차량, 공용 Pallet, Hub Gate | 기사 피로를 표현할 별도 주체 |
| 정의 | 집단수요 Cart Table, 도심마트 Shop, 농장 출하 Crate | 운영자 전용 재고 Shelf |
| 절제 | 감자 수확 상자, 공용 Pallet, 도심마트 Shop | 스프링클러, 재고 Shelf |

O5 객체를 카드에 연결하는 설계는 가능하지만, 실제 `SimulationWorldShell` 강조는 별도의 O6 실제 World 배치 검증 뒤에 연다.

## 8. 무작위성과 저장·재생 원칙

카드 뽑기는 Unity의 현재 시각이나 프레임 순서에 의존하지 않는다. 시뮬레이션 서버가 최소한 다음 입력으로 결정한다.

```text
ScenarioSeed
+ 덱 고유 식별자와 개정 번호
+ 턴 번호
+ 이전 뽑기·선택·버림 기록
+ 재섞기 회차
```

같은 입력과 기록에서는 카드 세 장, 표시 순서와 방향이 같아야 한다. 결과와 사용한 개정 번호는 저장·재생 해시에 포함한다. 클라이언트가 제안받지 않은 카드, 방향 또는 대응을 보내면 서버가 거부한다.

일반 플레이 무작위 뽑기와 현금 결제형 무작위 상품은 서로 다른 문제다. 초기 범위에는 현금 결제, 유료 확률형 상품, 희귀도 판매와 성능 우위 판매를 포함하지 않는다.

## 9. 턴 상태 전이

```text
현재 경영일 진행 중
  ↓ 사용자가 턴 마감 요청
카드 제안 3장 준비
  ↓
카드 선택 대기
  ↓
경영 대응 선택 대기
  ↓
턴 마감 미리보기 준비
  ↓ 명시적 확정
턴 마감 기록 저장
  ↓
다음 경영일 활성 규칙 등록
  ↓
기준 상태 사본 재조회 완료
```

미리보기는 세션 개정 번호와 기준 원장을 변경하지 않는다. 확정에는 `ExpectedRevision`과 멱등 Command가 필요하다. 확정 응답만으로 Unity World를 바꾸지 않고 같은 세션의 더 최신 기준 상태 사본을 다시 조회한다.

## 10. 경영 지표의 첫 적용 경계

기획의 다섯 지표는 유지하되, 뼈대 단계에서 모두 새로운 단일 점수로 만들지 않는다.

| 기획 지표 | 첫 연결 원칙 |
| --- | --- |
| 자금 | 기존 재정 원장의 잔액·예약·가용 금액을 사용 |
| 공급 안정성 | 시장·비축·운송 중 수량과 식량 안정 일수의 관점별 조회 결과로 시작 |
| 노동 여력 | 기존 총 노동·예약 노동·가용 노동을 사용 |
| 지역 신뢰 | 전용 원장과 발생 근거를 설계하기 전에는 임의 점수 생성 금지 |
| 환경·시설 상태 | 환경·시설·스트레스 원인을 개별 상태로 유지하고 임의의 종합 점수로 축약 금지 |

`ARC-1A`에서는 이 지표를 실제로 바꾸지 않는다. 첫 수치 효과는 기존 원장이 있는 운송 기간·연료·노동·자금부터 별도 단계에서 연다.

## 11. 구현 순서

### `ARC-RULE-1` — 타로 상위 보정 공통 계약

- 상태: 완료
- 하위 규칙이 허용할 보정 연결 지점과 방식별 범위를 선언한다.
- 타로 보정선에 원천 카드·방향·대응·활성 턴·대상 규칙·값·단위·의미를 보존한다.
- `고정값 → 비율 → 최소·최대 제한` 순서로 보정 후 후보를 계산한다.
- 카드 없음, 대상·단위·기간·범위 불일치, 여러 활성 카드 중첩과 불변 결과 범위를 검증한다.
- 이 단계는 공통 계약과 순수 계산기이며 실제 하위 업무 규칙이나 턴 세션에는 아직 연결하지 않는다.

### `ARC-RULE-2A` — 전차와 화물운송 규칙 연결기

- 상태: 완료
- 기존 화물운송의 기간·처리 용량·연료·노동·위험을 보정 연결 지점으로 선언하고 실제 화물량은 별도 기준값으로 보존했다.
- 전차 정방향의 빠른 운송 대응을 서버 소유 개발용 Fixture 상위 규칙으로 만들었다.
- 기준 후보와 보정 후 후보를 함께 반환하고 원천 카드·턴 마감·상하위 규칙 계보를 보존한다.
- 처리 용량이 차량 용량을 넘거나 위험이 100%를 넘는 결과는 불변 조건 위반으로 차단한다.
- 기존 배차 추천 작업과 겹치는 화물운송 계산 파일은 수정하지 않았으며 `ARC-RULE-2B`의 별도 통합 미리보기에서 조립한다.

### `ARC-RULE-2B` — 활성 턴 카드와 화물운송 API 조립

- 상태: 완료
- 서버 세션의 활성 카드가 일반 타로 전차 정방향·빠른 운송인지 검증한다.
- 서버가 활성 카드에서 `ARC-RULE-2A` 입력을 만들고 클라이언트의 임의 보정값은 받지 않는다.
- 기존 화물운송 미리보기를 감싸는 `tarot-freight-transport-previews` 응답에 보정 전 후보·보정선·보정 후 후보를 추가한다.
- 일반 전차 카드는 기존 학당 전차의 고유 식별자를 바꾸지 않고 `tarot:major.chariot`로 별도 등록한다.
- 서버 기준 정책 `tarot-baseline-policy:freight.v1`은 검증된 운송 기간·화물량·차량 용량에서 처리 용량·연료·노동·위험 기준값을 결정한다.
- 카드가 없을 때 타로 보정은 `null`이며 기존 화물운송 미리보기와 계산 결과를 그대로 반환한다.
- 하위 화물운송이 차단되면 활성 전차가 있어도 타로 보정을 계산하지 않는다.
- 실제 운송 확정과 자원 효과 적용은 기존 Command·Task·WorldTick을 그대로 사용한다.

### `ARC-F0` — 일반 타로 기반 분리

- 상태: 기획 완료
- 일반 타로를 기본 덱으로 확정한다.
- 학당·철학 카드는 선택형 콘텐츠 묶음으로 분리한다.
- 기존 카드 고유 식별자와 저장 의미를 유지한다.
- 타로 원형, 게임용 해석, 시나리오 덱과 효과 규칙의 개정 번호를 분리한다.

### `ARC-F1` — 카드 뽑기 계약

- 상태: 완료
- 여제·전차·정의·절제를 개발용 일반 타로 Fixture로 등록했다.
- 각 카드 3복사본으로 구성한 `tarot-deck:starter-12.r1` 12칸 시작 덱과 카드 복사본 계약을 추가했다.
- 시나리오 seed·턴 번호·덱 개정 번호·이전 타로 제안 선택 이력에서 같은 3장과 정·역방향을 결정한다.
- 카드 종류, 덱 속 복사본, 이번 턴 제안을 서로 다른 고유 식별자로 보존한다.
- 턴 마감 요청은 제안 고유 식별자·카드 고유 식별자·방향이 모두 일치해야 하며 제안되지 않았거나 변조된 선택을 차단한다.
- 학당·문화 카드의 기존 `AvailableCards` 호환 목록과 일반 타로 `TarotDraw`를 분리했다.
- 선택된 복사본·제안·방향은 턴 마감 기록, 활성 효과, 저장·재생 hash와 복원에 포함한다.

### `ARC-F2` — 객체 반응 미리보기

- 상태: 완료
- 첫 네 장과 O6 실제 World 배치 객체 7개의 영향 가능 관계를 `integrated-seedbed:o6.r1` 구성 대장으로 등록했다.
- 여제는 감자 수확 상자·도심마트, 전차는 농장 출하 상자·배송 차량·공용 화물 Pallet·Hub 입고 Gate, 정의는 집단수요 Cart Table·도심마트·농장 출하 상자, 절제는 감자 수확 상자·공용 화물 Pallet·도심마트와 연결한다.
- 현재 세션의 수확 배정·화물운송·물류 이동·마트 공급·공동주문 상태에서 실제 영향 객체를 계산한다.
- 정적 관계만 있고 현재 관련 상태가 없으면 `StateUnavailable`로 반환하고 강조하지 않는다.
- `tarot-object-reaction-previews`는 현재 3장 제안 각각의 잠재 객체·현재 강조 여부·근거 상태 고유 식별자를 반환한다.
- 요청의 뽑기 고유 식별자와 예상 세션 개정 번호가 현재 서버 제안과 일치해야 한다.
- 미리보기는 후보 조회이며 세션 개정 번호, 기준 원장과 카드 선택 기록을 변경하지 않는다.
- 타로 수치 보정은 `ARC-RULE-1~2B`의 별도 계약을 재사용하며 객체 강조 자체가 업무 완료나 수치 변경을 뜻하지 않는다.

### `ARC-F3` — Unity 최소 화면

- 상태: 완료
- 기존 고정 카드 버튼을 서버 제안 3장 슬롯으로 교체한다.
- 정·역방향, 기회, 부담과 대응 선택을 한국어로 표시한다.
- 고유 식별자로 영향 객체를 강조한다.
- 확정 뒤 기준 상태 사본 재조회가 끝나야 다음 날 화면으로 전환한다.
- 기존 학당·문화 카드 모판은 연구·승격 검증 화면으로 보존하고 실제 일반 타로 경영 화면과 분리한다.
- `SimulationWorldShell` Play Mode에서 로컬 Simulation 서버 제안 선택, 객체 반응 조회, Preview, Confirm과 상태 버전 0→1 재조회를 확인했다.
- 현재 상태가 있는 O6 객체만 황금색 원으로 강조하며 Confirm 뒤 임시 강조를 제거한다.

### `ARC-F4` — 대응 선택과 규칙 미리보기

- 상태: 서버 규칙 완료, Unity 비교 화면 연결 전
- 카드 한 장을 고른 뒤 카드별 경영 대응을 선택하는 별도 단계를 추가한다.
- 전차는 빠른 운송·안전 운송·합배송 가운데 하나를 고르고 `ARC-RULE-2B`의 보정 전 후보·보정선·보정 후 후보를 같은 화면에서 비교한다.
- 다른 세 카드의 수치 규칙은 하위 생산·거래·재고 연결 지점이 확정된 뒤 한 장씩 추가한다.
- 카드 선택과 업무 Confirm을 분리하고, 대응 미리보기도 기준 원장을 변경하지 않는다.
- 서버 요청은 카드나 보정 수치가 아니라 대응 고유 식별자 하나만 추가로 받는다. 서버가 활성 전차, 카드 방향, 하위 운송 기준과 보정값을 결정한다.
- 빠른 운송은 기간 `3→2`, 처리량 `300→360`, 연료 `30→33`, 노동 `3→3.3`, 위험 `6→11` 후보를 만든다.
- 안전 운송은 기간 `3→4`, 처리량 `300→300`, 연료 `30→31.5`, 노동 `3→3.6`, 위험 `6→2` 후보를 만든다.
- 합배송은 기간 `3→4`, 처리량 `300→300`, 연료 `30→25.5`, 노동 `3→2.7`, 위험 `6→5` 후보를 만든다.
- 등록되지 않은 대응은 활성 카드 유무와 무관하게 요청 경계에서 거부하며, 세 후보는 서로 다른 미리보기·보정선 고유 식별자를 가진다.
- 세 대응 모두 후보 조회일 뿐 화물운송·연료·노동 원장을 변경하지 않는다. 관련 서버 집중 시험 20/20과 Simulation 전체 396/396을 통과했다.
- 다음 세로 단위는 Unity에 화물운송 기준 후보 입력 경계를 마련하고, 서버가 반환한 다섯 지표의 보정 전·후 값을 같은 패널에서 비교하는 것이다.

### `ARC-1B` — 첫 실제 규칙

- 전차 한 장과 화물운송 업무를 첫 세로 구현으로 선택한다.
- 전차 상위 규칙이 빠른 운송·안전 운송·합배송의 기간·처리량·연료·노동·위험 보정선을 만든다.
- 기존 운송 하위 규칙이 보정선을 소비해 최종 후보와 자원 효과 묶음을 계산한다.
- 카드 확정과 운송 확정을 분리한다.
- 저장·재생과 멱등 재시도를 검증한다.

### `ARC-2` — 14일 시나리오 완성

- 카드 정의 8개와 12칸 시작 덱을 확정한다.
- 감자 300kg의 수확·출하·운송·Hub 인수·마트 공급 계보를 14턴 동안 연결한다.
- 성공·부분 성공·실패 조건과 사용자 이어하기를 검증한다.

## 12. `ARC-F1~F3` 완료 조건

- 같은 시나리오 seed·덱 개정 번호·턴 기록에서 같은 카드 세 장과 방향이 나온다.
- 저장·재생 뒤에도 같은 제안과 선택 기록이 복원된다.
- 카드 종류가 중복되어도 카드 복사본과 제안 고유 식별자가 충돌하지 않는다.
- 제안되지 않은 카드, 방향 또는 대응은 서버가 거부한다.
- 카드가 없을 때 기존 생산·운송·재고 규칙의 결과가 바뀌지 않는다.
- 타로 규칙은 하위 규칙이 허용한 보정 연결 지점과 범위에만 영향을 준다.
- 플러스·마이너스 보정의 대상 값·단위·적용 순서와 원천 카드가 보존된다.
- 보정 전 기준 후보와 보정 후 최종 후보를 함께 재현할 수 있다.
- 타로 보정 뒤에도 수량·용량·단위·상태 전이 불변 조건을 통과한다.
- 활성 기간이 끝나면 타로 보정이 제거되고 기존 하위 규칙 결과로 돌아온다.
- 미리보기 전후 세션 개정 번호와 기준 원장 값이 같다.
- 카드 선택 기록은 확정 뒤에만 저장된다.
- O6 객체 강조는 배치 객체 고유 식별자로만 연결된다.
- 차량 이동, Gate 개방과 객체 색 변화는 운송·입고 완료를 뜻하지 않는다.
- 확정 뒤 같은 세션의 기준 상태 사본을 다시 조회한다.
- 실제 주문·결제·기사 호출·GPS·운영 재고 쓰기를 발생시키지 않는다.
- Unity 실제 Game View에서 카드 3장, 선택, 대응, 객체 강조와 다음 날 전환을 확인한다.

## 13. 이번 뼈대 단계에서 하지 않는 일

- 타로 78장 전체 입력
- 최종 카드 밸런스 확정
- 지역 신뢰의 임의 점수화
- 환경·시설 상태의 단일 점수화
- 카드 선택만으로 업무 완료 또는 재고 변경
- 하위 규칙이 선언하지 않은 값의 임의 변경
- 수량 보존·용량·단위·권한·상태 전이 조건의 카드 우회
- 여러 활성 타로 카드의 중첩 우선순위
- 학당 콘텐츠의 필수화
- 실제 점술 결과 또는 개인 운명 예측
- 현금 결제형 무작위 상품
- 운영 주문·계약·결제·배차·재고 원장 변경
- 카드 이미지 대량 생성 또는 라이선스가 불명확한 덱 이미지 사용

## 14. 최종 뼈대 판정

첫 완성 목표는 “카드 네 장을 많이 설명하는 화면”이 아니다. 다음 한 문장이 실제 서버와 Unity 사이에서 반복 가능하게 성립해야 한다.

> 같은 시나리오와 턴 기록에서는 같은 세 장이 제안되고, 플레이어가 고른 한 장과 대응은 다음 날 기존 생산·운송·재고 규칙에 허용된 플러스·마이너스 보정을 제공한다. 하위 규칙은 그 보정으로 최종 후보를 다시 계산하되 불변 안전 조건을 유지하며, 카드나 Unity 표현만으로 업무 상태를 직접 바꾸지는 않는다.

이 뼈대가 닫힌 뒤에만 전차의 실제 운송 수치, 나머지 네 장, 14일 승패 조건과 장기 덱 구성을 확장한다.
