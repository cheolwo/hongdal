# 플레이 폐루프와 증거 묶음 개발 체계

## 목적

이 문서는 게임 기획의 플레이어 약속을 개별 WI·H 공간·E 증거와 연결하고, 여러 사람이 같은 기준으로 작업을 인계하기 위한 두 연결 객체를 정의한다.

```text
게임 기획과 플레이어 약속
  → PlayableLoop
  → WI
  → 필요한 H 능력
  → E 단계별 실제 증거
  → EvidencePackage
  → 자동 완료 원장과 다음 작업
```

`PlayableLoop`와 `EvidencePackage`는 E·G·H를 대체하는 새 번호 축이 아니다. `PlayableLoop`는 여러 WI가 시작부터 귀환까지 닫히는 **E 판정 대상**, `EvidencePackage`는 그 판정을 뒷받침하는 **범위가 제한된 증거 기록**이다.

기계 권위는 다음 파일이 소유한다.

- [`playable-loops.json`](../../eng/execution-ledgers/playable-loops.json): 플레이 단위·영역 집계·세계 집계와 Core/Extension 완결 상태
- [`evidence-packages.json`](../../eng/execution-ledgers/evidence-packages.json): 시험·Runtime·화면·Hosted·운영 증거
- [`manage-development-system.ps1`](../../eng/execution-ledgers/manage-development-system.ps1): 참조 정합성 검사와 현재 완료 원장 생성
- [`07_CURRENT_COMPLETION_LEDGER.md`](../AI/authority-maps/07_CURRENT_COMPLETION_LEDGER.md): 위 대장에서 생성한 현재 상태 사본

## PlayableLoop

개별 WI는 의미 있는 권위 전이 하나를 정의한다. PlayableLoop는 여러 WI가 플레이어에게 하나의 약속을 실제로 완성하는지를 판정한다.

```text
진입 상태
  → 상황·선택
  → WI 실행
  → 성공 또는 실패·취소
  → 회복·귀환
  → 다시 선택 가능한 상태
```

따라서 다음은 서로 다르다.

```text
WI-NATURE-06 벌목 시작의 E3
≠
Nature 생존 생활거점 전체 폐루프의 E3
```

폐루프는 v2부터 세 수준으로 관리한다.

```text
WorldAggregate
  └─ AreaAggregate
       ├─ PlayableUnit / Core
       └─ PlayableUnit / Extension
```

`PlayableUnit`은 성공·실패·회복·귀환을 직접 증명하는 최소 단위다. `AreaAggregate`는 필수 Core 자식 상태에서 파생되며 직접 완료 선언하지 않는다. `WorldAggregate`는 독립 영역을 하루 또는 선택적 영역 간 통합으로 조립하되 AreaAggregate를 소유하지 않고 준비 의존으로 참조한다.

완결 상태는 다음 의미로 고정한다.

- `Open`: 다음 반환 또는 필요한 E 증거가 남아 있다.
- `CoreClosed`: Core PlayableUnit이 E5에서 결정적으로 발현됐다.
- `ExtendedClosed`: 선택형 Extension PlayableUnit이 E5에서 발현됐다.
- `PlayClosed`: E7 실제 입력·화면·귀환 증거가 있다.

건물·타로·사용자 배치 같은 Extension은 영역 Core 완결을 막지 않는다. 영역 `CoreClosed`는 모든 필수 Core 자식이 `CoreClosed` 이상일 때만 파생한다. 세부 현재 순서는 [플레이 폐루프 완결 로드맵](플레이폐루프완결로드맵.md)을 따른다.

각 폐루프는 최소한 다음을 가진다.

| 필드 | 의미 |
| --- | --- |
| `loopStableId` | 저장·문서·작업 명세에서 재사용하는 안정 식별자 |
| `loopLevelCode` | `PlayableUnit | AreaAggregate | WorldAggregate` 수준 |
| `completionTierCode` | `Core | Extension | Aggregate` 완결 등급 |
| `parentLoopStableId` | PlayableUnit을 소유하는 AreaAggregate |
| `requiredCoreChildLoopStableIds` | 집계 완결에 필수인 Core 자식 또는 독립 영역 준비 의존 |
| `optionalExtensionChildLoopStableIds` | Core를 막지 않는 선택형 확장 자식 |
| `playerPromise` | 플레이어가 이 폐루프에서 얻는 시작·선택·결과·귀환 약속 |
| `entryStateCodes` | 다른 영역 성과를 암묵적으로 요구하지 않는 시작 상태 |
| `worldInteractionIds` | 폐루프를 구성하는 WI |
| `successStateCodes` | 완료 후 권위 상태 |
| `failureRecoveryWorldInteractionIds` | 실패·취소·후퇴·회복 경로 |
| `returnStateCodes` | 다시 선택 가능한 상태 |
| `requiredHCapabilities` | 특정 Prefab이 아니라 필요한 공간 능력 |
| `saveCheckpointCodes` | 저장·종료·복원 후 의미가 유지돼야 하는 지점 |
| `currentEvidenceStage` | 폐루프 전체가 현재 실제로 가진 E |
| `nextClosureTargetStage` | 현재 가장 가까운 완결 관문의 E |
| `finalEvidenceStage` | 실제 플레이 완결의 최종 목표 E |
| `closureStateCode` | `Open | CoreClosed | ExtendedClosed | PlayClosed` |
| `maturityTracks.logic` | 권위 상태·결정성·저장·재생·Hosted의 논리 성숙도 |
| `maturityTracks.presentation` | 입력·배치·카메라·Synty·HUD·Game View의 표현 성숙도 |
| `openFeedbackItems` | 실제 플레이에서 발견해 다시 연 궤적·E 단계·대상 |
| `evidencePackageRefs` | 현재 판정을 뒷받침하는 증거 묶음 |
| `blockers`, `nextAction` | 다음 최저 누락과 작업 순서 |

Nature·Town·Farm·Hub·City는 각각 `IndependentArea` 영역 집계와 최소 Core PlayableUnit을 먼저 가진다. `CrossAreaIntegration` 폐루프는 양쪽 독립 폐루프의 준비가 확인된 뒤 별도 작업으로 선택한다.

Nature의 첫 현장·거점 상호의존 기준선은 `playable-loop:nature-field-supply-return.v1`이다. 이 폐루프는 현장 원정·영역 운영·영역 제조를 영구 역할로 나누지 않고 한 플레이어가 왕복하는 기회로 묶는다. 보급품이 없을 때도 기본 원정은 열려 있어야 하며, 보급품은 원정 진입 시 명시적으로 선택한 경우에만 한 번 소비되고 해당 원정의 패배 손실 하나만 완화한다.

`Planned` 폐루프는 아직 WI가 없어도 기획 누락을 드러낼 수 있다. `Validated`는 목표 E와 현재 E가 같고 차단 항목이 없을 때만 사용할 수 있다.

## EvidencePackage

EvidencePackage는 “완료했다”는 문장이 아니라 언제, 어떤 환경에서, 어느 revision을, 어디까지 확인했는지를 기록한다.

필수 내용은 다음과 같다.

```text
증거 식별자와 종류
대상 PlayableLoop
관련 E 단계
Source revision
실행 시각·환경
검증 범위
제외 범위
산출물 위치·hash·보존 방식
무효화 조건 `invalidationTriggers`
Current | Stale | Superseded | Blocked
```

증거 종류는 Contract, AutomatedTest, SaveReplay, HttpRuntime, UnityEditMode, UnityPlayMode, GameView, HostedParity, Operations로 분리한다. `UnityPlayMode` 하나가 통과해도 제외 범위에 Hosted나 전체 후속 경로가 남아 있으면 폐루프 전체를 E7로 올리지 않는다.

WI RuleRevision, Save schema, H 정의 hash, 공식 Scene 배선, Runtime Adapter 또는 입력 흐름이 바뀌어 무효화 조건에 걸리면 증거 상태를 `Stale`로 바꾸고 폐루프 E를 다시 판정한다.

## 논리·표현 이중 성숙도

모든 PlayableUnit은 논리 궤적과 표현 궤적을 각각 판정하고 통합 E를 두 값 중 낮은 단계로 계산한다. 논리 E7이 있어도 화면에서 대상과 결과를 읽을 수 없으면 `PlayClosed`가 아니다. 표현 E1~E4 계획은 논리 E5 전에도 가능하지만 표현 E5 이상 증거는 논리 E5 상태 사본을 요구한다. 표현 검증에서 권위 상태나 H 계약 누락을 발견하면 같은 폐루프의 가장 이른 논리 E 단계를 다시 연다. E8 `PlayableUnitStabilityCampaign`은 한 폐루프의 반복 안정성을, E9 `AreaHarmonySet`은 둘 이상의 안정 Core가 이루는 논리·표현 조화와 사람 승인을 같은 후보 revision에서 판정한다.

세부 판정, 피드백 귀속과 Nature 첫 적용 결과는 [플레이 폐루프 논리·시각 이중 순환 체계](플레이폐루프논리시각이중순환체계.md)를 단일 기준으로 사용한다. `EvidencePackage.evidenceTrackCode`는 `Logic`, `Presentation`, `Integrated` 중 하나이며 한 궤적의 증거가 다른 궤적을 자동 승격하지 않는다.

## 작업 명세와 협업 인계

현재 E7 수직 작업 명세 v2는 `playableUnitStableId`, 활성 `WorldInteractionId`, Logic·Presentation 각각의 E7→E1 하향 검토와 E1→E7 상향 검증, 통합 관문을 직접 기록한다. 과거 E9↔E1 작업 명세 v2의 `playableLoopRefs`·협업 정보는 변화 영향 읽기 호환 자료로 유지하고 새 작업의 활성 명세로 사용하지 않는다. 협업 범위가 필요한 작업은 다음 정보를 현재 작업 명세 또는 연결된 작업 흐름 원장에 기록한다.

| 필드 | 책임 |
| --- | --- |
| `primaryWorkstream` | Operations·Simulation·Unity·Integration 중 주 상태 소유 흐름 |
| `participatingWorkstreams` | 실제 생산자·소비자·통합 참여 범위 |
| `ownerRef`, `reviewerRefs` | 작업 책임과 경계 검토 책임 |
| `allowedChangeRoots` | 병행 작업을 침범하지 않는 수정 허용 경로 |
| `dependencyWorkOrderIds` | 먼저 안정돼야 하는 작업 명세 |
| `handoffIn`, `handoffOut` | 입력 계약·기준선과 다음 작업에 넘길 결과 |
| `branchPolicy`, `commitScope` | 짧은 작업 흐름과 되돌릴 수 있는 커밋 경계 |

담당 정보는 상태 권위를 바꾸지 않는다. Integration은 독립 권위가 아니며, Operations·Simulation·Unity 사이 계약과 Adapter 인계를 관리한다.

## 자동 완료 원장

현재 완료 원장은 직접 상태를 반복 작성하지 않는다.

```text
playable-loops.json
evidence-packages.json
WI·E 대장과 작업 명세 참조
        ↓
manage-development-system.ps1 -Mode Write
        ↓
07_CURRENT_COMPLETION_LEDGER.md
```

`CURRENT_WORK.md`는 이번 작업의 상세 snapshot과 검증 로그를 설명하고, 완료 원장은 폐루프·증거·차단·우선순위의 생성 결과를 보여 준다. 두 문서가 서로 다른 현재 E를 수동으로 소유하지 않는다.

## 실제 업무 순서

1. 게임 기획에서 플레이어 약속과 독립 폐루프를 선택한다.
2. 기존 PlayableLoop를 재사용하거나 새 `loopStableId`를 등록한다.
3. 필요한 WI와 H 능력, 성공·실패·귀환·Save 지점을 적는다.
4. E7 수직 작업 명세 v2에서 논리·표현 각각의 E7→E1 영향과 통합 조건을 기록한다.
5. 가장 낮은 미완료 의존성부터 구현하고 두 궤적을 E1부터 상향 검증한다.
6. 실제 실행 결과를 EvidencePackage로 등록한다.
7. 완료 원장을 다시 생성하고 다음 차단과 우선순위를 확인한다.
8. 새 변경이 증거 무효화 조건을 건드리면 관련 EvidencePackage와 E 판정을 다시 연다.

이 연결이 안정된 뒤 경제·전투·NPC·시대 변화 같은 상세 기획 체계를 추가한다. 상세 기획은 새 증거 축을 만들지 않고 해당 PlayableLoop·WI·H·E 작업 명세에 입력된다.
