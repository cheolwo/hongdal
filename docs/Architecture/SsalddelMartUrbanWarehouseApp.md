# 홈달마트 도심형 창고 앱

홈달마트는 음식점 주문 처리와 닮은 속도감을 가지지만, 음식점 앱과 같은 조리 중심 흐름은 아니다. 핵심은 도심 거점의 창고 재고를 고객 주문에 맞게 피킹하고, 포장 완료 후 음식 배달 기사에게 넘겨 고객 배송으로 연결하는 것이다.

## 음식점 앱과의 차이

음식점 앱은 주문 접수, 조리, 조리 완료, 라이더 픽업이 중심이다.

홈달마트는 다음 흐름이 중심이다.

- 도심 거점 입고
- 냉장/상온/즉시 출고 구역 보충
- 창고 재고 기반 주문 피킹
- 고객 주문 단위 포장 완료
- 음식 배달 기사 픽업
- 고객 배송 흐름 연결

즉, 마지막 배송 연결은 음식 배달 기사 흐름과 맞닿아 있지만, 앞단의 업무는 창고 관리와 재고 처리의 성격이 강하다.

## 현재 앱 구조

현재는 별도 MAUI 프로젝트를 복제하지 않고 `WarehouseManagerApp` 안에 `/mart` 하위 화면으로 분리한다.

창고 Domain은 별도 `도심물류센터` Entity를 만들지 않고 기본 `창고` Entity를 그대로 사용한다. 실제 시설의 업무 성격은 `물류대행지분류`의 `UrbanLogisticsCenter`로 표시하고, WarehouseManager 화면은 운영 Profile 상속으로 공통 기능을 조립한다.

```text
일반 입출고 창고
└─ 도심 생활물류센터
   ├─ 마트 도심 창고
   └─ 공동주택 물류 거점
```

- `도심 생활물류센터`는 일반 입고·검수·재고·피킹·포장·운송 인계를 상속한다.
- `마트 도심 창고`는 여기에 상품 재고 보충, 주문 처리와 배달 기사 픽업을 더한다.
- `공동주택 물류 거점`은 공동 물량 반입, 세대별 배분, 주민 수령과 미수령 관리를 더한다.
- 시설 이름만으로 인허가나 영업 자격을 보증하지 않는다. 실제 운영 가능 상태와 취급 능력은 별도 검증한다.

- `/mart`: 홈달마트 홈
- `/mart/work/{processCode}`: 홈달마트 공정 작업자 확인
- `/mart/work-board`: 홈달마트 작업 보드

공통으로 재사용하는 것:

- 작업자 확인 게이트
- 휴대폰 번호 뒤 8자리 확인 흐름
- 창고/물류 HR 역할 코드
- 스캔 스테이션
- 향후 라벨 출력, 포장 증빙, 사진 업로드 흐름

## 공정 코드

- `mart-inbound`: 도심 입고
- `mart-replenishment`: 진열/피킹존 보충
- `mart-picking`: 주문 피킹/포장
- `mart-delivery-pickup`: 음식 배달 기사 픽업
