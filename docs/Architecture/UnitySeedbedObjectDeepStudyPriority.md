# Unity 모판 배치 객체 심층 연구 우선순위

## 1. 목적

이 문서는 모판 배치 객체를 더 많이 만드는 작업보다, 이미 O5 모판 실행 검증을 마친 객체 하나가 **왜 존재하고 무엇을 표현해야 하는지** 깊게 연구하는 순서를 정한다.

오늘의 목표는 15개 객체를 모두 얕게 검토하는 것이 아니다. 모든 객체에 재사용할 10개 질문을 확정하고, 첫 대상인 감자 재배체에 질문 전체를 적용해 이후 연구의 기준 사례를 만드는 것이다.

이 연구는 곧바로 O6 실제 World 배치 검증을 뜻하지 않는다. 연구 결과가 명확해진 객체만 별도 구현 단계에서 Scene·구역·배치 기준점·데이터 연결과 배치 검증 기록을 갖추어 승격한다.

`OBJ-STUDY-*`는 이 문서에서만 사용하는 연구 순번이다. 서버 API 계약, 저장 데이터, 기존 고유 식별자 또는 O0~O6 승격 단계를 새로 정의하지 않는다.

## 2. 배치 객체 하나를 연구하는 10개 질문

각 객체는 다음 순서로 검토한다. 외형과 Synty Prefab 선택은 여섯 번째 질문 전까지 보류한다.

| 순서 | 질문 | 남겨야 할 결과 |
| ---: | --- | --- |
| 1 | 현실에서 무엇이며 왜 존재하는가 | 현실 정의, 사용자, 생성 조건, 존재 이유 |
| 2 | 업무 흐름의 어느 순간에 등장하는가 | 직전 상태, 등장 순간, 직후 상태 |
| 3 | 어떤 데이터를 표현하는가 | 보여줄 항목, 요약 항목, 상세 화면으로 넘길 항목 |
| 4 | 무엇을 소유하거나 결정하면 안 되는가 | 서버 최종 결정 권한, 금지 상태, 금지 Command |
| 5 | 사람이 멀리·가까이·선택 시 어떻게 인식하는가 | 세 거리 단계의 인지 목표 |
| 6 | 데이터가 바뀌면 외형이 어떻게 달라지는가 | 상태→색·형태·수량·표지·효과 변화표 |
| 7 | 주변에 무엇이 있어야 자연스러운가 | 필수 이웃 객체, 바닥, 도로, 작업 공간 |
| 8 | 다른 객체와 어떤 연결 지점을 가지는가 | 연결 지점의 이름보다 먼저 관계와 목적 정의 |
| 9 | 사용자는 무엇을 할 수 있는가 | 관찰·정보·시뮬레이션·실운영 행동 분리 |
| 10 | 실제 World에 반드시 필요한가 | 업무 객체·데이터 표현 객체·상태 표지·순수 배경 판정 |

모든 연구 기록에는 다음 두 문장을 반드시 둔다.

```text
이 배치 객체가 보여주는 것:
이 배치 객체가 결정하지 않는 것:
```

## 3. 전체 15개 연구 순서

순서는 감자 하나가 생육하고 수확·운송되어 수요자에게 이어지는 시간 흐름을 따른다.

각 객체를 같은 질문 열에서 비교하는 작업 가설과 책임 충돌은 [15개 배치 객체 수평 연구 대장](UnitySeedbedObjectHorizontalStudyMatrix.md)에 정리한다. 이 문서는 세로 실행 순서를, 수평 연구 대장은 객체 사이의 같은 질문 비교를 담당한다.

| 순번 | 묶음 | 배치 객체 | 현재 단계 | 핵심 연구 질문 |
| ---: | --- | --- | --- | --- |
| 1 | 생산 | 감자 재배체 | O5 모판 실행 검증 완료 | 실제 생육과 시뮬레이션 생육을 어떻게 구분해 보여주는가 |
| 2 | 생산 | 감자 밭고랑 | O5 모판 실행 검증 완료 | 작물과 토양 중 어느 상태를 밭고랑이 표현하는가 |
| 3 | 생산 | 밭 관수 스프링클러 | O5 모판 실행 검증 완료 | 관측 강수와 시뮬레이션 관수 효과를 어떻게 분리하는가 |
| 4 | 생산 | 농장 온실 | O5 모판 실행 검증 완료 | 시설 자체와 재배 환경 상태를 어떻게 구분하는가 |
| 5 | 생산 | 감자 수확 상자 | O6 실제 World 배치 검증 완료 | 수확 Lot이 언제 물리적 취급 단위가 되는가 |
| 6 | 생산 | 농장 출하 Pallet Crate | O6 실제 World 배치 검증 완료 | 수확물이 언제 출하 준비 화물이 되는가 |
| 7 | 물류 | 공용 화물 Pallet | O6 실제 World 배치 검증 완료 | 농산물 단위와 창고 취급 단위의 경계는 무엇인가 |
| 8 | 물류 | 화물 배송 차량 | O6 실제 World 배치 검증 완료 | 차량 이동과 실제 운송 상태를 어떻게 분리하는가 |
| 9 | 물류 | Hub 입고 Gate | O6 실제 World 배치 검증 완료 | 도착·입고 대기·검수·인수가 각각 언제 성립하는가 |
| 10 | 수요·마트 | 주민 관점 Visual | O5 모판 실행 검증 완료 | 사람의 식별 정보 없이 개인 의향 관점을 어떻게 표현하는가 |
| 11 | 수요·마트 | 집단수요 Cart Table | O6 실제 World 배치 검증 완료 | 개인 수요가 자동 가입 없이 집단화되는 과정을 어떻게 보이는가 |
| 12 | 수요·마트 | 도심마트 Shop | O6 실제 World 배치 검증 완료 | 공개 상품과 후방 재고의 경계를 건물에서 어떻게 읽히게 하는가 |
| 13 | 수요·마트 | 운영자 전용 재고 Shelf | O5 모판 실행 검증 완료 | 마트 재고와 진열 작업을 권한 있는 사용자에게만 어떻게 표현하는가 |
| 14 | 수요·마트 | 마트 운영자 Visual | O5 모판 실행 검증 완료 | 운영자 역할 표현과 실제 권한 소유를 어떻게 분리하는가 |
| 15 | 다른 물류 체계 | 음식 픽업 인계 상자 | O5 모판 실행 검증 완료 | 화물 인계와 음식 픽업 인계가 왜 다른 업무 규칙을 갖는가 |

## 4. 오늘 하루 실행 순서

시간은 고정 시각보다 작업 블록으로 운용한다. 앞 블록의 문서가 끝나지 않으면 다음 객체로 넘어가지 않는다.

| 블록 | 집중 대상 | 수행 내용 | 완료 조건 |
| --- | --- | --- | --- |
| A | 공통 연구 틀 | 10개 질문과 기록 양식 확정 | 이후 모든 객체에 같은 양식을 적용할 수 있음 |
| B | 감자 재배체 1~4번 질문 | 현실 정의, 업무 앞뒤, 표현 데이터, 금지 권한 | 서버 사실과 Unity 표현이 분리된 한 장짜리 초안 |
| C | 감자 재배체 5~8번 질문 | 거리별 인지, 상태별 외형, 주변 구성, 연결 관계 | 시각 변화표와 작은 구성 관계가 설명됨 |
| D | 감자 재배체 9~10번 질문 | 사용자 행동, World 필요성 판정 | 관찰·시뮬레이션·실운영 경계와 최종 분류 확정 |
| E | 감자 밭고랑 비교 검토 | 재배체와 밭고랑이 중복 표현하는 상태 찾기 | 다음 연구에서 풀어야 할 충돌 질문 목록 |
| F | 하루 정리 | 결정·미결정·검증 필요 항목과 다음 연구 대상 기록 | 감자 재배체 구현 제안 또는 추가 조사 판정 |

오늘 반드시 끝낼 범위는 A~D다. E는 남은 시간에 수행하는 두 번째 우선순위이며, 나머지 13개는 오늘 순서를 정하고 핵심 질문만 보존한다.

## 5. 첫 연구 대상: 감자 재배체

고유 식별자는 `seedbed-object:farm.potato-plant-visual.a`이며 현재 O5 모판 실행 검증 완료 상태다. 준비된 데이터 연결은 기준 상품 재배 상태(`CanonicalProductCultivation`)와 농장 환경 생육 턴(`FarmEnvironmentalGrowthTurn`)이다.

감자 재배체의 심층 연구는 [재배 규모·생산 능력·품목 속성 연구](UnityPotatoPlantScaleYieldProductAttributeStudy.md)로 세분한다. 먼저 재배체 하나의 대표 단위를 정하고, 그 단위를 기준으로 생산 능력을 계산한 뒤, 수확 결과가 포장·Pallet·보관·운송·마트 진열로 넘어가는 공통 품목 속성을 분리한다.

```text
재배 규모
    ↓
생산 능력
    ↓
품목 속성
```

### 5.1 오늘 답해야 할 핵심

1. 재배체는 실제 감자 식물 한 포기, 한 이랑의 대표 표현, 또는 밭 전체 생육 상태 중 무엇을 대표하는가
2. 파종 전·출아·영양생장·개화·괴경 비대·성숙·수확 가능 상태를 모두 표현해야 하는가
3. 실제 관측값과 시뮬레이션 계산값이 동시에 있을 때 어느 쪽을 어떤 표시로 구분하는가
4. 수확 가능 여부를 재배체가 결정하지 않고 어떤 서버 기준 상태에서 읽는가
5. 감자 밭고랑이 토양 상태를, 재배체가 작물 상태를 맡는다는 구분이 충분히 명확한가
6. 한 포기의 시각 변화와 6×6 밭 전체의 집계 표현을 어떻게 분리하는가
7. 사용자가 선택했을 때 생육 점수 전체를 보여줄지, 핵심 상태만 보여주고 상세 화면으로 넘길지
8. O6 배치가 필요하다면 Farm의 어느 배치 기준점과 어떤 상태 사본에 연결해야 하는가

여기에 다음 세 묶음의 질문을 반드시 더한다.

- 재배 규모: 한 포기·한 이랑·한 Tile의 군집·밭 전체 대표 중 무엇인가
- 생산 능력: 면적 확장, 환경, 관수, 비료와 시설이 생육 속도와 최종 생산량 중 무엇을 바꾸는가
- 품목 속성: 포장·Pallet 적재·보관·운송·마트 진열 조건을 재배체가 아닌 어떤 공통 Profile에 둘 것인가

### 5.2 임시 권위 경계

이 배치 객체가 보여주는 것:

- 감자라는 품목
- 허가된 생육 단계와 건강 상태의 시각적 요약
- 결측·관측·시뮬레이션 여부의 구분
- 선택 시 출처와 기준 시각으로 이동할 수 있는 읽기 정보

이 배치 객체가 결정하지 않는 것:

- 실제 수확 가능 판정
- 실제 생산량과 품질 등급
- 농약·관수·비료 투입 Command
- 수확 확정과 수확 Lot 생성
- 관측값을 시뮬레이션 입력으로 채택하는 결정

### 5.3 연구 뒤 가능한 판정

| 판정 | 의미 | 다음 행동 |
| --- | --- | --- |
| 배치 객체 유지 | 작물 상태를 독립적으로 알아보게 하는 가치가 있음 | O6 배치 설계로 이동 |
| 밭고랑과 합성 | 한 포기와 토양 표현이 분리되면 오히려 혼란스러움 | 두 객체의 책임을 다시 나눔 |
| 상태 표지로 축소 | 식물 Prefab보다 상태 표시가 핵심임 | 표지 객체 후보로 재분류 |
| 추가 조사 | 실제 감자 생육 단계나 자산 표현 근거가 부족함 | 농사로 근거 검토 뒤 재판정 |

## 6. 두 번째 연구 대상: 감자 밭고랑

감자 재배체 연구 직후에는 `seedbed-object:farm.potato-row.a`를 비교한다. 별도 연구를 시작하기 전에 다음 충돌만 먼저 확인한다.

- 토양 수분·배수·토양 관측은 밭고랑의 책임인가
- 생육 스트레스는 재배체와 밭고랑 중 어디에 나타나는가
- 한 이랑의 바닥 점유 영역과 식물 배치 수는 누가 결정하는가
- 작물이 없는 빈 밭고랑도 독립적으로 의미가 있는가
- 밭고랑을 없애면 사용자가 파종 전·후 상태를 구분하지 못하는가

## 7. 구현으로 넘어가는 조건

심층 연구가 끝났다는 이유만으로 Scene을 수정하지 않는다. 다음이 모두 정리된 뒤에만 구현 작업을 계획한다.

- 현실 존재 이유와 업무 앞뒤가 한 문장으로 설명됨
- 보여줄 데이터와 결정하지 않을 데이터가 분리됨
- 멀리·가까이·선택 시 인지 목표가 정해짐
- 상태 변화가 구체적인 시각 변화로 연결됨
- 주변 객체와 연결 지점의 관계가 설명됨
- 관찰·시뮬레이션·실운영 행동이 분리됨
- 실제 World 필요성 판정이 기록됨
- O6 승격 대상이면 Scene·구역·배치 기준점·데이터 연결 후보가 있음

## 8. 기존 구현 우선순위와의 관계

기존 다음 구현 후보였던 `OBJ-7D 주민 관점 Visual Scene 배치`는 삭제하지 않고 보류한다. 오늘은 먼저 생산 묶음의 감자 재배체를 기준 사례로 연구하고, 15개 객체를 같은 질문으로 다시 이해한 뒤 배치 구현 순서를 재확정한다.

당분간 우선순위는 다음과 같다.

1. `OBJ-STUDY-1`: 감자 재배체 심층 연구
2. `OBJ-STUDY-2`: 감자 밭고랑 비교 연구
3. 생산 묶음의 관수 스프링클러·온실 연구
4. 이미 O6인 수확 상자·출하 Pallet의 역검증
5. [수평 연구 대장](UnitySeedbedObjectHorizontalStudyMatrix.md)에 따라 물류 묶음 연구
6. 수평 연구 대장에 따라 수요·마트 묶음 연구
7. 수평 연구 대장에 따라 음식 픽업 인계 상자와 화물 Pallet 비교
8. 연구 결과에 따라 `OBJ-7D` 또는 생산 객체 O6 배치 재개
