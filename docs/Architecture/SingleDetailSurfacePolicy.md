# Single Detail Surface Policy

하나의 업무 대상에 대한 상세 정보는 가능한 한 하나의 대표 화면에서만 보여준다. 다른 화면은 목록, 요약, 다음 행동, 상태 확인에 필요한 최소 정보만 보여준다.

## 원칙

| 원칙 | 설명 |
| --- | --- |
| 대표 상세 화면 지정 | 의뢰, 추천, 운송, 결제, 기사 같은 업무 대상은 상세 정보를 책임지는 화면을 하나 둔다. |
| 목록은 요약만 표시 | 목록 화면은 식별자, 상태, 다음 행동, 짧은 경로/금액 정도만 보여준다. |
| 작업 화면은 작업 정보만 표시 | 상차/하차처럼 특정 행위를 처리하는 화면은 그 작업에 필요한 정보만 보여준다. |
| 민감 정보는 상세 화면으로 모음 | 상세주소, 연락처, 계좌, 결제/정산 세부 정보는 여러 화면에 반복 노출하지 않는다. |
| 예외는 명시 | 운행 중 안전이나 현장 작업에 필요한 정보는 예외로 허용하되, 같은 이유를 문서에 남긴다. |

## 현재 대표 화면 기준

| 업무 대상 | 대표 상세 화면 | 다른 화면에서 허용되는 요약 |
| --- | --- | --- |
| 추천 운송 | `DriverApp` 추천 상세 | 화물종류, 상차/하차 요약, 거리, 예상수익, 정산 방식 요약 |
| 진행 중 운송 | `DriverApp` 진행 중 운송 | 다음 행동, 현재 단계, 상차/하차 작업 진입 버튼 |
| 상차 작업 | `DriverApp` 상차 화면 | 상차지, 화물 종류, LCL/FCL 확인 항목, 사진 촬영/완료 버튼 |
| 하차 작업 | `DriverApp` 하차 화면 | 하차지, 운송거리, 사진 촬영/완료 버튼 |
| 화주 의뢰 | `HongdalAdmin` 의뢰 관리 선택 상세 | 의뢰ID, 결제상태, 배차상태, 픽업/하차 요약 |
| 배차대기 | `HongdalAdmin` 배차대기 목록 | 상세주소 없이 의뢰ID, 픽업/하차 요약, 상태, 조치 버튼 |

## 이번 점검에서 조정한 항목

| 화면 | 조정 |
| --- | --- |
| `DriverApp/추천목록Page` | 추천 상세 화면과 중복되던 `추천사유`, `상세설명` 노출을 목록에서 제거 |
| `DriverApp/상차Page` | 수입/통관 연계 운송의 현장 안전에 필요한 LCL/FCL 상차 확인 항목만 작업 화면에 예외 노출 |
| `HongdalAdmin/DispatchWait` | 배차대기 목록에서 상세주소를 제거하고 도로명주소 요약만 표시 |

## 추가 점검 후보

| 화면 | 판단 |
| --- | --- |
| `HongdalAdmin/Requests` | 목록과 선택 상세가 한 화면 안에 있으므로 대표 상세 화면 역할로 유지 가능 |
| `HongdalAdmin/Drivers` | 기사 목록과 선택 상세가 한 화면 안에 있으므로 대표 상세 화면 역할로 유지 가능 |
| `OrdererApp/OrderHistory` | 민감 정보가 접힘 목록 안에 모여 있어 현재 방향과 대체로 맞음 |
