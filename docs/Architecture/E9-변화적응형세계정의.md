# E9 변화 적응형 세계 정의

## 목적

E9는 완성된 세계에 기능을 많이 추가한 상태가 아니다.

E9는 E8까지 성립한 플레이어·NPC 생활세계에 새 규칙, 콘텐츠, 공간, 사건, 카드, 역할 또는 시스템을 추가하거나 기존 구조를 변경했을 때, 하위 세계 계약을 임의로 깨뜨리지 않고 영향 범위를 추적·검증·승격해 세계가 계속 변화할 수 있음을 증명한 단계다.

E8의 질문이 **“NPC까지 이 세계에서 실제로 살아가는가?”**라면 E9의 질문은 **“그 살아가는 세계를 이제 안전하게 바꿀 수 있는가?”**다.

## 판정 단위

E9는 저장소 전체에 한 번 부여하는 표시가 아니다. 다음 묶음을 하나의 변화 단위로 판정한다.

```text
기준 E8 세계 revision
+ 변경 제안과 변경된 계약·자료
+ 영향받는 AreaSet·H·WI·플레이어·NPC 폐루프
+ Migration·호환성·회귀 증거
+ 변경 후 안정 revision
```

## G4 변경 순환

1. **변경 제안**: 목적, 대상, 제외 범위와 성공 조건을 고정한다.
2. **하향 영향 분석**: `E8 → E1` 순서로 NPC 생활, 플레이 경험, 세계 의미·공간·WI·계약에 미치는 영향을 추적한다.
3. **개정 계획**: 바뀌는 계약·Revision·Hash·Lineage와 데이터·Save Migration을 명시한다.
4. **호환 실행**: API, 저장 형식, Event, stable ID와 기존 세션의 호환 또는 명시적 비호환 정책을 적용한다.
5. **집중 검증**: 변경 기능의 계약·결정성·저장·재생과 필요한 실제 실행을 검증한다.
6. **상향 재검증**: `E1 → E8` 순서로 영향받는 하위 계약과 기존 플레이어·NPC 폐루프가 닫히는지 확인한다.
7. **승격**: 증거 묶음과 새 안정 revision을 기록한 뒤에만 E9로 판정한다.

```text
새로운 변화
  ↓
E8 → E7 → E6 → E5 → E4 → E3 → E2 → E1  하향 영향 분석
  ↓
Revision · Migration · 구현 · 집중 시험
  ↓
E1 → E2 → E3 → E4 → E5 → E6 → E7 → E8  상향 재검증
  ↓
새 안정 revision
  ↓
E9 증거
```

## E9 목표를 먼저 쓰는 신규 작업

신규 기능도 최종 변화 적응 경계를 잊지 않도록 E9 목표부터 E1 계약까지 첫 하향 검토를 작성할 수 있다. 이후 E1부터 상향 조립·검증하고, 그 결과에서 새 영향이 생기면 다시 하향 검토하는 왕복을 반복한다. 이것은 `NewVerticalSlice`의 장기 목표 선언과 작업 방식이며 E9 증거가 아니다.

```text
E9 목표 봉투
  → E8 NPC 영향
  → E7 플레이어 수용 흐름
  → E6 근거·설명
  → E5 AreaSet·배치
  → E4 WI 공간 모판
  → E3 시험
  → E2 코드 소유 위치
  → E1 불변 계약
```

하향 분해 뒤에는 가장 낮은 미완료 의존성부터 구현하고 `E1 → E9`로 증거를 다시 확인한다. 변경 전 E8 안정 revision이 없는 신규 세로 조각은 E8까지 완성해도 그 자체로 E9가 되지 않는다. 실제 후속 변화, Migration·호환·회귀와 새 안정 revision이 있어야 한다.

작업 명세와 검사 규칙은 [E9↔E1 반복 왕복 구현 체계](E9하향식수직구현체계.md)를 따른다.

## 완료 관문

선정된 변화 단위는 다음을 모두 만족해야 한다.

1. 변경 전 기준 E8 revision과 변경 후 revision이 식별된다.
2. 영향받는 E1~E8 계약·증거와 영향받지 않는 범위가 근거와 함께 구분된다.
3. stable ID, API, Event, 저장 형식과 데이터의 호환 또는 Migration 정책이 명시된다.
4. 같은 seed·Command·Tick 순서에서 요구되는 결정성이 유지된다.
5. 변경된 기능의 새 폐루프가 닫힌다.
6. 영향받는 기존 플레이어 E7 폐루프와 NPC E8 폐루프가 회귀 검증을 통과한다.
7. 필요한 실제 서버·저장 `SimulationWorldShell`·Play Mode·Game View 증거가 다시 확보된다.
8. 실패 시 이전 안정 revision으로 되돌리거나 중단할 경계가 준비된다.

## E9로 판정하지 않는 것

- 기능·카드·NPC·AreaSet 수만 늘린 상태
- 새 기능 단위 시험만 통과한 상태
- 기존 Save를 읽지 못하지만 Migration 또는 명시적 비호환 정책이 없는 상태
- API·Event 소비자 영향을 조사하지 않은 상태
- E7 플레이어 폐루프 또는 E8 NPC 폐루프 회귀를 생략한 상태
- hash만 갱신하고 실제 입력·계보·실행 증거를 다시 확인하지 않은 상태
- Unity 화면이 정상으로 보인다는 이유로 서버 결정성·저장 호환성을 완료로 간주한 상태

## 권위와 범위

- 변경 승인과 새 안정 revision의 최종 권위는 서버·Simulation 계약과 승인 원장에 있다.
- Unity는 변경된 서버 상태와 행동을 표현하며 Migration이나 성공 판정을 독자적으로 수행하지 않는다.
- 운영 효과, 외부 Provider 호출, 실제 계약·결제·배차·발주는 별도 운영 승인 없이는 G4 검증에 포함하지 않는다.
- 영향받지 않는 E 증거까지 기계적으로 모두 재실행하지 않는다. 제외 판단에는 의존 관계와 hash 근거가 있어야 한다.
- E9 증거 하나가 모든 AreaSet·WI·NPC 세계를 E9로 올리지 않는다.
