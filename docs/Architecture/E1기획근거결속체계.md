# E1 기획 근거 결속 체계

## 목적

게임 기획 문서와 E1의 관계를 추적하되, 문서가 있다는 이유만으로 실행 계약이나 증거를 자동 생성하지 않는다. 기획은 플레이어 약속과 맥락을 제공하고, E1은 그 약속을 한 `PlayableUnit`과 WI가 구현·검증할 수 있는 계약으로 동결한 상태다.

조회 시작점은 [기획–E1 결속 인덱스](../AI/generated/playable-loop-planning-e1-index.md)다. 기계 입력은 [`playable-loop-planning-e1-policy.json`](../../eng/execution-ledgers/playable-loop-planning-e1-policy.json), 생성·검사는 [`manage-playable-loop-planning-e1-index.ps1`](../../eng/execution-ledgers/manage-playable-loop-planning-e1-index.ps1)가 소유한다.

기획 문서를 실제 검증 가능한 원자 단위로 나누고 E1로 조립하는 순서와 리뷰 관문은 [기획 원자 분해와 E1 조립 체계](기획원자분해와E1조립체계.md)가 소유한다.

## 기획과 E1의 관계

| 분류 | 의미 | 자동 효과 |
| --- | --- | --- |
| `ContractOwner` | 상세 기획서가 한 `PlayableUnit.planningGate.designDocumentRef`와 일치 | 계약 완결성을 검사하지만 E 승격은 하지 않음 |
| `SupportingContext` | 기획서가 `sourcePlanningDocumentRefs`에 명시됨 | 해당 E1의 근거로 조회 |
| `CrossCuttingContext` | 여러 폐루프가 공유하는 목적·문답·메타데이터 | 단독 WI·E1 생성 없음 |
| `NoDirectE1Impact` | 관리·Graph Map·자료·표현 조사 | 소비 기획이 선택하기 전 E1 영향 없음 |
| `E1CandidateNeeded` | 기획 목차에는 있으나 E1 결속이 없음 | 기존 PlayableUnit 재사용 또는 새 상세 기획 필요 |

일반 기획을 E1로 바꿀 때는 먼저 기존 `PlayableUnit`과 WI를 재사용할 수 있는지 확인한다. 새 플레이어 약속이 정말 독립 폐루프일 때만 새 StableId·상세 기획·WI 후보를 제안하고, 사용자 승인 전에는 원장에 자동 등록하지 않는다.

## E1 성립 관문

E1은 Logic과 Presentation 각각에서 다음 항목을 같은 기획 revision과 hash로 설명할 수 있어야 한다.

1. 승인된 상세 기획과 정확히 하나의 `PlayableUnit`
2. 플레이어 약속과 진입 상태
3. 대표 WI와 입력 주체·대상·의도
4. 성공 상태와 완료 조건
5. 실패·중단·회복·귀환 또는 사유 있는 `NotApplicable`
6. 서버·Simulation·Unity 중 권위 소유자와 읽기·쓰기 경계
7. Logic E1의 상태 변화·멱등성·오류 의미
8. Presentation E1의 판독 순간·표현 책임·권위 불변
9. 출처 기획 ID·문서·revision·hash와 열린 미정

하나라도 빠지면 `Conditional` 또는 `Blocked`다. E1 성립은 코드 준비(E2), 자동시험(E3), 문맥 결속(E4), 실제 배치(E5)를 뜻하지 않는다.

## 업계 관행을 반영한 교차 품질 프로필

E1~E10 번호를 늘리지 않고 다음 품질을 필요한 폐루프에 선택적으로 붙인다. 각 프로필은 E1에서 요구와 예산을 선언하고 이후 단계에서 누적 검증한다.

| 프로필 | E1에서 정할 것 | 주 검증 구간 |
| --- | --- | --- |
| 성능·부하 | 목표 플랫폼, 프레임·지연·메모리·동시성 예산 | E3 자동 측정, E7 실제 플레이, E8 반복, E10 관측 |
| 접근성 | 입력 대안, 읽기·색상·자막·시간 압박 완화 요구 | E4 표현 문맥, E6 정제, E9 사람 평가 |
| 현지화 | 언어·문자열·단위·문화 표현 경계 | E3 형식 시험, E6 화면 정제, E9 사람 평가 |
| 플랫폼 호환 | 지원 장치·해상도·입력·네트워크 행렬 | E3 대상 시험, E8 환경 반복 |
| 보안·개인정보 | 권한·민감정보·동의·보존·외부 효과 경계 | E2 구현, E3 위반 시험, E10 제한 운영 |
| 관측 가능성 | 사건·오류·진행 지표와 개인정보 없는 진단 범위 | E3 기록 시험, E8 trace 안정, E10 관측 |
| 저장·Migration·rollback | 저장 판본·호환·복구·되돌림 조건 | E3 시험, E8 Save/Replay, E10 rollback |
| 콘텐츠·권리 | 자산·자료 출처, 사용 범위, 재배포·가공 허용 | E4 후보 동결, E6 최신성·권리 재검토 |

이 프로필은 모든 WI에 같은 무게로 강제하지 않는다. 적용하지 않을 때는 이유 있는 `NotApplicable`을 남기며, 적용 대상인데 누락되면 가장 이른 E1을 다시 연다.

## 인계

- 기획 스레드: 기획 ID·판본·hash, 지금·여기·나·너·이렇게, 성공·실패·회복·귀환과 E1 영향만 확정한다.
- Graph Map·배치 담당: 공간 관계와 제약을 추가하되 새 플레이 의미를 만들지 않는다.
- 개발: 승인된 상세 기획과 E1 계약을 받아 E2 이상을 구현한다.
- 검증: 단계별 증거를 누적하되 하위 단계 누락을 상위 실행 결과로 덮지 않는다.
