# 플레이 폐루프 엔진 상호작용 검증 체계

## 목적

`PlayableLoop`의 논리와 표현이 각각 동작한다는 사실을 넘어, 한 WI 명령이 실제 권위 결과를 만든 뒤 필요한 공간·대기·배치 표현을 거쳐 다음 선택으로 돌아오는지 검증한다.

이 체계는 세 번째 성숙도 궤적을 만들지 않는다. 기존 `Logic`과 `Presentation`을 유지하고 엔진 상호작용은 두 궤적을 같은 `PlayableLoopStableId + WorldInteractionId + CommandId + AuthorityRevision`으로 묶는 `Integrated` 관문이다.

## 기본 흐름

```text
플레이어 입력
  → WI Preview
  → WI Confirm
  → 집중 근거 수집 또는 사유 있는 미적용
  → Simulation Authority Core
  → 권위 상태 사본과 Revision
  → 행위 기록 추가
  → 분야 성장·명상 성장 적용 또는 사유 있는 미적용
  → LH 지면·셀 준비 또는 기존 결과 재사용
  → Sky 상태 투영
  → 실외 배치 투영
  → 실내 배치·생활 상태 투영
  → 화면 결과와 다음 선택
```

모든 WI가 모든 엔진을 요구하지는 않는다. 폐루프별 프로필은 필요한 구성 요소와 순서를 선언하며, `Executed`, `Reused`, `NotApplicable`, `Blocked`를 구분한다. 이미 준비된 LH 셀이나 실외 배치는 다시 생성하지 않고 `Reused`로 기록할 수 있다.

## 권위 경계

- `Simulation.AuthorityCore`만 권위 Revision을 변경할 수 있다.
- 권위 변화 WI는 같은 Command·Revision 계보의 `ActionRecordAppend`를 남긴다. 플레이어 분야 성장과 명상 성장은 적용 또는 판본화된 `NotApplicable`이어야 한다.
- 집중 판정은 기본 WI 성공을 재정의하지 않으며, 명상 기여를 표현 엔진이 계산하지 않는다.
- LH·Sky·실외·실내·World Presentation 단계는 같은 Revision을 읽어 표현하며 `BeforeAuthorityRevision == AfterAuthorityRevision`이어야 한다.
- Trace는 진단·시험용 비권위 기록이다. Session Save, Command Log, Replay canonical hash와 운영 상태에 포함하지 않는다.
- 벽시계 시각, Unity instance ID, 프레임 순서는 결정적 Trace 입력에 넣지 않는다.
- 실제 Play Mode와 Game View 증거는 자동 Trace를 대신하지 않고, 자동 Trace도 실제 화면 판독을 대신하지 않는다.

## 첫 적용: Nature 보관·수면·Day2 반환

| WI | 권위 결과 | 요구 표현 흐름 |
| --- | --- | --- |
| `WI-NATURE-13` | 소지 통나무가 오두막 Container로 이동 | 실내 보관 상태 → 다음 행동 |
| `WI-NATURE-14` | 수면과 Nature 시계 가속 준비 | LH 재사용 → Sky → 실외 재사용 → 실내 수면 상태 → 새벽 반환 |
| `WI-NATURE-15` | 확장 계획 고정과 `Day2Ready` | 실내 계획 상태 → 다음 선택 |

공통 Logic 순서는 `Preview → Confirm → FocusEvidenceCollect → AuthorityCommit → ActionRecordAppend → PlayerProgressionApply → MeditationProgressionApply → ReturnProjection`이다. 집중 Profile이 없는 WI는 두 집중 단계에 `NotApplicable`을 남기며, 임의의 명상 보상을 만들지 않는다.

단일 기준 대장은 [playable-loop-engine-interaction-validation.json](../../eng/execution-ledgers/playable-loop-engine-interaction-validation.json)이다. 현재 프로필과 구성 요소는 [생성 상태판](../AI/generated/playable-loop-engine-interaction-validation.md)에서 확인한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File eng/execution-ledgers/manage-playable-loop-engine-interaction-validation.ps1 -Mode Validate
```

## 실패와 재개

| 실패 | 기본 재개 |
| --- | --- |
| 계약 구성 요소 또는 순서가 없다 | E2~E3 |
| WI·Command·PlayableLoop 결속이 없다 | E4 |
| 권위 결과 뒤 표현 인계가 없다 | E5 |
| 차단 원인과 상태 차이를 읽기 어렵다 | 표현 E6 |
| 실제 입력·화면·귀환이 닫히지 않는다 | 표현 E7, 권위 원인이면 해당 Logic E |
| 표현 엔진이 AuthorityRevision을 변경한다 | 즉시 차단하고 E2~E4 경계 재검토 |

실패는 기존 Logic 또는 Presentation 증거 전체를 지우지 않는다. 변경의 영향을 받은 가장 이른 책임 단계만 다시 열고 같은 `PlayableLoop` Goal 안에서 재조립한다.
