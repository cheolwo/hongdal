# Unity 마트 주문 피킹·포장 World 설계

## 1. 목적

마트의 확정 주문에 포함된 상품을 실제 적재 위치에서 찾아 피킹하고 포장 구역까지 운반하는 과정을 서버 업무와 Unity 공간 표현으로 연결한다.

```text
확정 주문과 재고 할당
    ↓
피킹 작업 생성
    ↓
NPC가 상품 적재 위치로 이동
    ↓
상품·수량 확인과 피킹
    ↓
운반 Tote 또는 Cart에 적재
    ↓
포장 구역으로 이동
    ↓
포장 작업 인계
    ↓
포장 완료 뒤 출고·기사 인계 대기
```

Unity의 NPC 이동과 애니메이션은 업무 완료의 근거가 아니다. 피킹·포장 완료 여부는 서버 작업 상태와 기준 원장을 다시 조회해 확인한다.

## 2. 현재 재사용할 수 있는 기반

현재 서버에는 다음 정보가 이미 존재한다.

- 창고 재고: 상품명, SKU, 가용·예약 수량, `StorageLocation`
- 피킹 작업: 작업 고유 식별자, 주문 참조, 상품, 수량, `RackCode`, 상태
- 포장 작업: 상품, 수량, 적재 위치, 포장 유형, 포장 가능 여부
- 창고 World 상태 사본: 재고, 작업, Picker NPC, 현재·목적지 이동 지점
- 운영 권한: 창고 관리자 역할과 접근 가능한 창고 범위

현재 `창고WorldSnapshot조회UseCase`는 피킹 작업을 `warehouse.rack-to-outbound` 경로와 연결하지만, 출발점을 `warehouse.rack-zone`, 목적지를 `warehouse.outbound-staging`으로만 표현한다. 따라서 정확한 상품 위치, 피킹 접근점, 포장 대기열과 포장대가 아직 구분되지 않는다.

## 3. 업무를 시작시키는 주문 기준

모든 주문 표시가 NPC 피킹을 시작시키면 안 된다.

- 비구속 주문 의향·집단화 미리보기: 수요 표현만 허용하며 재고 예약, 피킹 작업, NPC 이동을 만들지 않는다.
- Simulation 확정 주문: 시뮬레이션 세션 안에서 재고 할당과 피킹 작업을 만들며 실제 결제·출고·기사 배정을 만들지 않는다.
- 실운영 확정 주문: 인증·권한·재고 예약과 실제 업무 정책을 통과한 서버 Command만 피킹 작업을 만든다.

시작 조건은 단순한 주문 수신이 아니라 다음 조건을 모두 충족한 `PickingReady`다.

```text
주문 확정
AND 상품 라인 확정
AND 재고 할당 성공
AND 적재 위치 확인
AND 피킹 작업 생성
= PickingReady
```

## 4. 서버 상태와 Unity 표현

| 단계 | 서버 상태 | 의미 | Unity 표현 |
| --- | --- | --- | --- |
| 1 | `PickingReady` | 상품·수량·Rack 위치가 지정된 작업 | NPC 작업 표지, 대상 Rack 강조 |
| 2 | `PickingInProgress` | 권한 있는 작업자가 시작 | NPC가 Rack 접근점으로 이동 |
| 3 | `AtPickLocation` | 위치 도착 관측, 완료 아님 | 정지·방향 전환·피킹 준비 |
| 4 | `Picked` | 상품·수량 확인을 서버가 기록 | 상품 표현이 Rack에서 Tote로 이동 |
| 5 | `MovingToPacking` | 포장 구역 인계 대상으로 이동 | NPC 또는 Cart가 포장 대기점으로 이동 |
| 6 | `PackingReady` | 피킹 결과와 포장대가 연결됨 | 포장대 입력 연결 지점에 Tote 배치 |
| 7 | `PackingInProgress` | 포장 작업 시작 | 포장 애니메이션·상자 조립 표현 |
| 8 | `Packed` | 포장 수량·유형·표지 확인 완료 | 봉인된 상자와 출고 표지 |
| 9 | `HandoffReady` | 출고 또는 기사 인계 대기 | 출고 대기 구역으로 이동 표현 |

`AtPickLocation`과 `MovingToPacking`은 공간 해석 상태다. NPC가 도착했다고 자동으로 `Picked` 또는 `Packed`를 확정하지 않는다.

## 5. 주문과 상품 위치 연결

한 주문은 여러 상품 라인을 가질 수 있으므로 주문 하나를 Rack 하나와 직접 연결하지 않는다.

```text
주문
 ├─ 감자 2봉 → 재고 할당 A → Rack A-03-02
 ├─ 양파 1망 → 재고 할당 B → Rack B-01-04
 └─ 우유 2개 → 재고 할당 C → Cold-C-02-01
```

각 피킹 작업에는 주문 라인, 재고 항목, 상품·SKU, 수량, 적재 위치, 포장 묶음, 대상 포장대와 작업 개정 번호가 연결되어야 한다. Unity 공개 상태 사본에는 주문자 이름·주소·연락처·결제 정보를 포함하지 않는다.

## 6. 마트 내부 공간 계약

문자열 Rack 코드만으로 NPC를 이동시키지 않는다. 서버의 적재 위치를 Unity 배치 기준점과 연결하는 공간 대장을 둔다.

| 공간 역할 | 배치 기준점 예시 | 용도 |
| --- | --- | --- |
| 운영자 대기 | `market.operator.home` | 작업이 없을 때 대기 |
| Rack 접근점 | `market.rack:A-03-02:approach` | NavMesh 도착점 |
| 상품 피킹점 | `market.rack:A-03-02:pick` | 손·상품 애니메이션 기준 |
| Cart 연결점 | `market.cart:picker-01:load` | 피킹 상품 임시 적재 |
| 포장 대기점 | `market.packing:queue` | 포장대가 찼을 때 대기 |
| 포장대 입력 | `market.packing:station-01:input` | Tote·Cart 인계 |
| 포장 상자점 | `market.packing:station-01:package` | 포장 결과 표현 |
| 출고 대기점 | `market.outbound:handoff` | 기사·출고 인계 준비 |

`StorageLocation` 또는 `RackCode`가 공간 대장에 없으면 임의의 Rack으로 보내지 않는다. `LocationUnmapped`로 표시하고 위치 대장 보완을 요구한다.

## 7. 모판 배치 객체

이 흐름은 완성 Scene 하나가 아니라 다음 배치 객체의 조합으로 만든다.

1. 운영자 전용 재고 Shelf: 재고 항목과 적재 위치를 표현하고 `InventoryAccess`, `PickPoint` 연결 지점을 가진다.
2. 마트 Picker NPC: 서버 작업을 표현하지만 완료를 소유하지 않으며 `Carry`, `LookTarget`, `Home` 연결 지점을 가진다.
3. 피킹 Tote 또는 Cart: 여러 주문 라인의 피킹 결과를 포장 묶음 단위로 모은다.
4. 포장 작업대: `PackingInput`, `PackageOutput`, `OperatorStand` 연결 지점을 가진다.
5. 포장 상자: 포장 전·진행·봉인·인계 대기 시각 상태를 제공한다.
6. 경로·상태 표지: 위치 누락, 작업 대기, 포장대 점유를 설명한다.

기존 O5 모판 실행 검증 완료 객체인 운영자 전용 재고 Shelf와 마트 운영자 Visual을 먼저 재사용한다. Tote·포장 작업대·포장 상자는 새로운 배치 객체 후보로 등록한다.

## 8. NPC 이동 규칙

```text
Idle
 → MoveToRack
 → FaceRack
 → PickAnimation
 → CarryToPacking
 → DropAtPacking
 → ReturnOrNextTask
```

NavMesh는 이동 가능한 경로만 계산한다. 어떤 상품을 몇 개 피킹하고 작업을 시작·완료할 수 있는지는 서버가 결정한다.

- 작업 취소: 현재 표현을 정리하고 상품을 마지막 서버 상태로 복원
- 개정 번호 역행: 새 응답을 무시하고 마지막 성공 상태 유지
- 다른 작업자가 선점: 이동 중단과 `AssignmentChanged` 표시
- 수량 부족: Tote 적재를 확정하지 않고 `ShortPick` 표시
- 위치 미등록: 이동하지 않고 `LocationUnmapped` 표시

## 9. 다품목 주문

- 소량·인접 Rack: 한 Picker가 서버가 제공한 순서로 처리
- 냉장·상온 혼합: 보관 조건별 작업 분리
- 구역이 멂: 여러 Picker에게 작업 분할
- 모든 피킹 완료: 같은 포장 묶음 고유 식별자로 포장대에서 합류

초기 버전은 Unity가 최단 경로를 독자적으로 확정하지 않고 서버가 제공한 피킹 순서를 재현한다.

## 10. 모판 검증 순서

1. 계약 모판: 주문 라인 → 재고 할당 → 적재 위치 → 피킹 작업 → 포장 묶음 연결과 개인정보 경계 확인
2. 배치 객체 모판: Shelf, Picker, Tote, 포장 작업대, 포장 상자를 각각 독립 검증
3. 피킹·포장 조합 모판: Rack 하나, 상품 하나, NPC 하나, 포장대 하나의 최소 흐름 검증
4. 다품목 조합 모판: 감자·쌀·양파와 냉장·상온 분리, 여러 작업의 포장대 합류 검증
5. 실제 World 배치: `SimulationWorldShell/MarketDistrict`에 O6 실제 World 배치 검증

## 11. 첫 구현 범위

```text
Simulation 확정 주문 1건
감자 주문 라인 1개
재고 위치 Rack A-03-02
Picker NPC 1명
Tote 1개
포장 작업대 1개
PickingReady → PickingInProgress → Picked → PackingReady
```

첫 단계에서는 포장 완료·기사 배차·실운영 재고 변경까지 연결하지 않는다. 서버 상태 사본을 읽어 NPC가 Rack과 포장대로 이동하는 표현, 개정 번호 보존, 취소와 위치 누락 처리까지 검증한다.

## 12. 완료 조건

- 비구속 주문 의향은 피킹을 시작시키지 않는다.
- 피킹 작업이 주문 라인·재고 항목·적재 위치와 추적 가능하게 연결된다.
- NPC는 검증된 배치 기준점으로 이동한다.
- NPC 도착과 애니메이션이 서버 업무 완료를 자동 확정하지 않는다.
- 피킹 완료 뒤 같은 포장 묶음이 포장대 입력 연결 지점에 나타난다.
- 새로고침 실패와 개정 번호 역행 때 마지막 성공 상태를 보존한다.
- 개인정보와 운영 전용 데이터는 권한 있는 관점별 조회 결과에만 포함된다.
- 모판 검증과 실제 World 배치 검증을 별도로 기록한다.
