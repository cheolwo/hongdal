# Unity 규칙 실험 모판 구현

## 1. 목적

통합 전시관의 배치 객체를 완성된 장면처럼 감상하는 데서 끝내지 않고, 같은 객체에 서로 다른 규칙을 적용했을 때 어떤 값과 표현이 달라지는지 확인하는 공통 실험대를 둔다.

이 실험대는 규칙을 새로 계산하는 서버가 아니다. 서버 또는 결정적 Simulation Fixture가 제공한 기준 상태 사본과 예상 효과 미리보기를 보여주고, 명시적 확정 뒤 서버의 최신 상태 사본을 다시 조회해 전후 값을 비교한다. Unity의 애니메이션, 카메라 이동, 색상 변화는 업무 완료의 근거가 아니다.

## 2. 전시관에서의 이용 순서

```text
규칙 실험대 선택
    ↓
배치 객체와 적용 규칙 확인
    ↓
서버 기준 상태 사본 불러오기
    ↓
예상 효과 미리보기
    ↓
이전 값 · 증감값 · 예상 이후 값 비교
    ↓
Simulation 확정 요청
    ↓
서버 Command 처리
    ↓
최신 기준 상태 사본 재조회
    ↓
예상값과 실제 재조회값 대조
    ↓
같은 기준에서 초기화하거나 다음 시나리오 선택
```

표현 규칙 실험대는 미리보기까지만 수행한다. 카메라·그래픽·애니메이션·조명·오디오·UI 변화는 서버 자원을 바꾸지 않으므로 Simulation 확정과 기준 원장 재조회를 제공하지 않는다.

## 3. 수평 배치할 다섯 실험대

| 실험대 | 함께 전시할 배치 객체 | 관찰 단계 | 확정 가능 여부 |
| --- | --- | --- | --- |
| 생산 규칙 | 감자 재배체, 감자 수확 상자 | 면적, 환경, 수확 작업, 수확 Lot | Simulation만 가능 |
| 소비 규칙 | 주민 관점 Visual, 도심마트 Shop | 수요, 예약, 주문 이행, 실제 소비 | Simulation만 가능 |
| 운송 규칙 | 공용 화물 Pallet, 배송 차량, Hub 입고 Gate | 상차, 이동, 도착, 하차, 인수 | Simulation만 가능 |
| 창고 규칙 | Hub 입고 Gate, 공용 화물 Pallet, 운영자 재고 Shelf | 인수, 검수, 적치, 감모, 피킹, 출고 | Simulation만 가능 |
| 표현 규칙 | 감자 재배체, 배송 차량, 운영자 재고 Shelf | 그래픽, 카메라, 애니메이션, 조명, 오디오, UI | 미리보기만 가능 |

각 실험대는 기존 배치 객체의 고유 식별자를 그대로 참조한다. 업무 흐름 전체를 하나의 Prefab으로 만들거나, 실험용 복제 객체가 서버 원장을 소유하게 하지 않는다.

## 4. 공통 상태

| 상태 코드 | 사람이 보는 의미 | 허용 행동 |
| --- | --- | --- |
| `Ready` | 기준 상태 준비 | 예상 효과 불러오기 |
| `PreviewLoaded` | 미리보기 표시 | 비교하거나 Simulation 확정 요청 |
| `AwaitingCanonicalRefresh` | 확정 요청 뒤 서버 재조회 대기 | 최신 상태 사본 적용 |
| `Reconciled` | 예상값과 재조회값 대조 완료 | 초기화 또는 다음 실험 선택 |
| `Failed` | 조회·검증 실패 | 원인 표시 후 초기화 |

미리보기는 규칙 고유 식별자, 기준 개정 번호, 단계, 대상 원장, 이전 값, 증감값, 예상 이후 값, 단위와 출처를 갖는다. 업무 규칙 효과는 서버 재조회 대상 원장과 대조할 수 있어야 한다. 표현 규칙 효과는 기준 원장 효과를 주장할 수 없다.

## 5. 현재 구현 범위

`RULE-SEEDBED-0`에서 다음 공통 계약과 조정기를 구현했다.

- 생산·소비·운송·창고·표현 규칙 시나리오 대장
- 서버 기준 상태 사본, 예상 효과, 전후 비교 결과
- 미리보기 → Simulation 확정 요청 → 서버 재조회 → 대조 → 초기화 상태 전이
- 실운영 API 호출 금지 표식
- 표현 규칙의 기준 원장 변경과 Simulation 확정 차단
- 미리보기 이전 값과 서버 기준 상태 사본의 원장·값·단위 일치 검증
- 서버 재조회 개정 번호, World Tick, 단위와 예상값 일치 검증

집중 단위 테스트 11개로 다섯 영역, 비권위 미리보기, 기준값 일치, 확정 전 원장 불변, 서버 재조회 후 대조, 불일치 거부와 초기화를 검증했다.

아직 구현하지 않은 것은 다음과 같다.

- 기존 생산·소비·운송·창고 서버 API를 각 실험대에 연결하는 변환기
- 실제 Unity Scene의 실험대 Prefab, 버튼, 카드, 카메라와 배치 기준점
- Play Mode와 Game View 실행 검증
- 실운영 API 연결

따라서 현재 상태는 규칙 실험 모판의 코드 계약과 결정적 검증이 완료된 단계이며, 실제 전시관 화면에서 사용할 수 있는 단계는 아니다.

## 6. 다음 구현 우선순위

1. `RULE-SEEDBED-1`: 감자 생산 규칙을 첫 서버/Fixture 변환기로 연결해 기준 상태와 예상 효과를 만든다. — 완료
2. `RULE-SEEDBED-SCENE-1`: 공통 실험대 Prefab과 한국어 상태·효과 비교 Panel을 전시관 Scene에 배치한다.
3. 생산 실험대에서 Preview·Confirm·재조회 폐루프를 Play Mode로 검증한다.
4. 같은 공통 틀에 소비, 운송, 창고 변환기를 수평 확장한다.
5. 표현 실험대에 카메라·그래픽 규칙을 연결하되 확정 버튼은 제공하지 않는다.
6. 각 실험대의 대표 Game View와 배치 검증 기록을 남긴다.

## 7. 감자 생산 변환기

`RULE-SEEDBED-1`은 서버 감자 생산 결과의 최소 API 사본을 다음 흐름으로 변환한다.

```text
서버 감자 생산 기준 상태와 Pending 효과
    ↓ Unity용 데이터 변환
생산 실험대 기준 상태 사본 + 예상 효과
    ↓ Simulation 확정 요청
서버 Command
    ↓ 최신 상태 재조회
적용 효과 묶음이 기록된 수확 재고 300kg
    ↓
예상 300kg과 실제 300kg 대조
```

Unity 변환기는 면적·환경·투입·시설·손실 계수를 다시 계산하지 않는다. 서버가 제공한 유효 재배 면적, 기본 수확량, 예상 수확량과 생산 효과선을 그대로 보존하고 서로 일치하는지만 검증한다.

현재 첫 사본은 다음 경계를 요구한다.

- `rule:potato-production.fixture.v1` 규칙 고유 식별자
- `Production` 업무 규칙 영역과 `Simulation` 실행 모드
- 적용 전 `Pending` 효과
- 수확 재고 원장의 `0kg → +300kg → 300kg` 생산 효과
- 서버 권위, 기준 개정 번호, World Tick, 출처와 Fixture 한계
- 확정 뒤 재조회 상태에 같은 효과 묶음의 적용 기록 존재

집중 테스트 10개로 300kg 기본 예시, 187.11kg 계수 적용 결과의 값 보존, 전체 대조 폐루프, 서버 권위·개정 번호·실운영 모드·수량·규칙 식별자 불일치 거부, 적용 기록 누락과 차단 사유 처리를 검증했다.

이 구현은 API 사본과 변환기까지다. 실제 HTTP endpoint와 UnityWebRequest, 전시관 Scene Panel, 버튼, Play Mode와 Game View는 아직 연결하지 않았다.

## 8. 감자 외 품목과 서버 업무 API 확장

`MULTI-PRODUCT-SEEDBED-1`에서는 기존 도심마트 표본의 감자·쌀·양파와 운영 API가 반환하는 임의 품목을 하나의 모판 투영기로 처리한다. 감자는 생산 Fixture 규칙까지 연결된 품목으로, 쌀·양파와 동적 운영 품목은 공개 상품·가격·판매 가능 수량·비구속 주문 의향까지만 연결된 품목으로 구분한다.

Unity는 서버의 비구속 주문 의향 API 계약을 그대로 보존한다. 미리보기에서 인증·개인정보 동의·수량·안내 확인을 점검하지만 실제 기록은 서버에 요청하고, 등록 응답 뒤 같은 주문 의향 상세를 다시 조회해야 조화 완료가 된다. 주문 의향은 재고 예약·결제·주문 확정이 아니다.

구현 범위와 API별 상태는 [Unity 서버 업무 API 모판 연결](UnityServerBusinessApiSeedbedIntegration.md)을 따른다.
