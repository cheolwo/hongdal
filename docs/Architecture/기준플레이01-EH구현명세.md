# 기준 플레이 01 — E/H 구현 명세

플레이어 경험은 [수확과 출하의 날](../Content/기준플레이01-수확과출하의날.md)을
기준으로 하고, 이 문서는 그 경험을 만드는 서버 권위와 공간 증거만 다룬다.

## 권위 흐름

`작업 계획 편집 → Preview → 계획 전체 Confirm → Task → Tick → Effect →
canonical 상태 재조회` 순서다. Unity는 안정 고유 식별자와 예상 개정만 보내며
생산량, 노동·체력 비용, 소요 Tick, 성공 여부를 계산하지 않는다.

새 작업 계획 경로는 다음과 같다.

- `POST /api/simulation/sessions/{sessionStableId}/farm-survival/work-plans/preview`
- `POST /api/simulation/sessions/{sessionStableId}/farm-survival/work-plans/confirm`

Confirm은 모든 항목을 선검증한 뒤 한 개정으로 원자 적용한다. 같은 Command ID
재시도는 같은 canonical 결과를 반환하고, 명령 자료는 Save/Replay 복제·검증·
해시에 포함된다.

## 장면별 E/H 연결

| 플레이 장면 | WI·행동 | 현재 증거 | 공간 연결 |
| --- | --- | --- | --- |
| 밭 상태 확인·수확 계획 | `WI-FARM-04`, `Harvesting` | E3 계약·HTTP·Save/Replay, E4 Scenario 재실행 | H1 농장 생산 모판 |
| 현장 수확 | `Harvesting` Task/Tick/Effect | 300kg 수확 Lot 결정 시험 | H1 생산 구역, H2 후보 생산 구역 |
| 작업마당 집하 | `WI-FARM-05`, `HarvestCollection` | 기존 E3/E4 공급선 재사용 | H1 작업마당 모판, H2 후보 작업마당 |
| 포장·출하 준비 | `WI-FARM-06`, `OutboundPacking` | 기존 E3/E4 공급선 재사용 | H1 작업마당 모판, H2 후보 작업마당 |
| 저녁·턴 마감 | 기존 턴 마감 Preview/Confirm | 서버 canonical 개정과 진행 작업 관문 | 공간 승격과 독립 |

Unity 시작 Session의 두 공간 정의는 `EvidenceKindCode=Scenario`다. 생산 구역은
수확 작업 능력, 작업마당은 집하·포장 작업 능력과 각각 `WorkArea 1 slot`을
제공한다. 이는 동시 업무 한 건의 시험 용량이지 실제 면적 근거가 아니다.

## E5 지역 배치 후보와 승격 금지선

`eng/world-seedbeds/landscape-block-candidates/daegwallyeong-harvest-day.v1.json`
은 “Farmhouse에서 감자밭까지 90초”를 시작 문제로 삼아 생산 구역, 작업마당,
창고 앞, Farm Gate의 이동 순서를 제안한다. 이 작성 공간의 성립에 DEM이나
실제 도로 Network를 공통 필수 조건으로 두지 않는다.

따라서 이 파일은 승인 H 설계를 실제 대관령 공간에 적용하기 위한
`ReadyForAuthoredPlacementReview` 상태의 E5 후보이며 H2 설계 정의가 아니다.
다음 관문 전에는 다음을 주장하지 않는다.

- H1 인스턴스의 실제 Block 배치
- H2→H3→H4 이동 폐루프 또는 E5 완료
- 공공데이터 계보 E6 완료

E5에서는 사람이 작성하고 승인한 도로 역할·경계로 H1을 Block에 배치하고 대관령
Farm LandscapeGraph와 평창 Farm–Hub–Town AreaSet의 이동 관계를 검증한다.
현실 정합을 선택한 경우에만 실제 도로·경계·지형 원본, 좌표계, 원본·파생 해시를
해당 E6 프로필의 별도 계보로 연결한다.

## Unity 조립

단일 실행 Scene `SimulationWorldShell`의 기존 런타임 루트에
`오늘작업계획Presenter`와 `오늘작업계획SceneCompositionRoot`를 연결한다.
표현기는 전술 초안, 직접/NPC 선택, 상태 문구, 밭 색, 감자 Lot 가시성만 맡고
서버의 WorldTick이나 개정을 직접 바꾸지 않는다. 서버 연결 구성은 기존
`UnityClientRuntimeSettings`와 턴 마감 Session bootstrap을 재사용한다.

## 자동 검증

- 작업 계획 전체의 원자 적용·차단 시 무변경·중복 행위자 차단
- 작업 계획 Command Save/Replay 해시 일치
- Preview/Confirm HTTP 경로
- 수확·집하·포장 공간 능력과 300kg 공급선
- Unity 조정자의 Preview 선행, 한 개정 Confirm, Tick 뒤 canonical 재조회
- H2 후보가 실제 H2로 등록되지 않았고 필수 원본 관문을 유지하는지 검사

Play Mode와 Game View는 실제 서버 연결·저장 Scene·사람 입력을 함께 확인해야
E7 증거가 된다. 컴파일 또는 EditMode 시험만으로 E7을 주장하지 않는다.
