# LH 공간 실행계층

## 목적

LH 엔진은 의미 공간을 새로 설계하는 도구가 아니라, 이미 정의된 세계에서 지금 필요한 셀을 거리·시간·메모리 예산에 맞춰 준비하는 실행계층이다. 현재 단계는 시나리오 절차생성으로 실행 구조를 시험한 상태이며, 실제 E5·E6 자료를 읽는 공급자는 후속 결속 대상이다.

## 두 책임

| 한국어 역할 | 코드 이름 | 책임 |
| --- | --- | --- |
| 스트리밍 범위 계산기 | `ISimulationLhWindowPlanner` | 플레이어와 보조 관심점을 기준으로 실행 셀의 상세·활성·선행 준비 반경과 이동 방향 우선순위를 계산한다. 현재 L3 Adapter의 기본 프로필은 3×3·5×5·9×9다. |
| 셀 공간 공급자 | `ISimulationLhCellContentSource` | 계산된 셀에 H 계보, 지면 상태, 연결구, 능력 근거를 결합한다. r1의 `Placements` 필드는 호환 인계 자료이며 LH의 생성 책임이 아니다. |

스트리밍 범위 계산기는 셀 안의 의미를 결정하지 않는다. 셀 내용 공급자는 범위와 우선순위를 다시 계산하지 않는다. 서버의 `SimulationLhWorldService`는 두 결과를 순서대로 조정하고 기존 Preview 계약을 반환한다.

## 일반 동적 맵 창

`3×3·5×5·9×9`은 LH의 불변 법칙이 아니라 현재 보행 PC 기준 호환 프로필이다. 일반 계산기는 중심 정수 좌표, `상세 ≤ 활성 ≤ 선행` 반경과 이동 방향만 읽으며 L 단계, H 단계, 셀 키 형식과 셀 내용은 알지 않는다. 서버의 `SimulationLhWindowPlanner`와 Unity 로컬의 `공간동적MapWindowPlanner`는 같은 포함 순서와 방향 우선순위를 사용한다.

- 기본값 `1·2·4`는 기존 저장 Scene과 API 소비자를 위해 유지한다.
- 다른 프로필은 `0·1·2`처럼 반경을 줄이거나 측정 결과에 따라 늘릴 수 있다.
- 반경이 음수이거나 `상세 ≤ 활성 ≤ 선행` 순서를 어기면 명시적으로 거부한다.
- 창 크기는 H 의미 계층을 바꾸지 않으며 H 주 조회 단계도 창 크기를 바꾸지 않는다.
- 현재 `FocusL3CellKey`와 125m 배선은 호환 Adapter다. 다른 실행 셀 단계나 원형·회랑·예산형 선택은 새 계약과 성능 증거가 생기기 전까지 구현 완료로 간주하지 않는다.

## 동적 셀과 객체 배치의 인계 관문

동적 맵 창에 셀이 포함됐다는 사실과 그 셀 안의 나무·바위·소품이 올바르게 배치됐다는 사실을 분리한다. LH는 표면 상태와 셀 Root를 준비해 Coordinator에 인계한다. 실외배치엔진은 `월드 seed + 셀 좌표 + 배치 규칙 revision`으로 후보를 만들고, LH가 제공한 표면·간격 정책을 통과한 결과만 실외 배치 기록으로 올린다.

- 평면 표면 공급자를 기본 호환값으로 유지하되 계획기는 월드 좌표로 표면을 조회한다. 선택형 `결정적ValueNoise공간표면Provider`는 같은 계약을 구현하며 특정 노이즈 알고리즘을 셀 생명주기에 노출하지 않는다.
- 셀 내부 객체 간 최소 간격과 셀 경계 여유를 함께 적용한다. 경계 여유의 두 배가 최소 간격보다 작으면 정책을 거부한다.
- 표면 누락·배치 금지·과도한 경사·간격 충돌은 명시적 원인 코드로 남기며, 요청한 수를 만들지 못한 셀 계획은 조용히 승인하지 않는다.
- Unity `실외자산배치Runtime`이 Prefab을 조립할 때 승인 표면과 Renderer 가시 하단을 다시 맞춘다. 표면 여유 검증에 실패하면 Coordinator가 해당 셀을 `VisualPrepared` 이후로 승격하지 않는다.
- 고정 H 기준점은 기존 호환 배치로 유지하고 절차형 표면 배치만 새 규칙 revision과 검증 코드를 갖는다.

첫 불규칙 표면은 월드 seed 기반 다중 옥타브 결정적 값 노이즈로 구현한다. 각 125m 셀은 월드 좌표에서 표본한 `17×17` 높이 상태 사본과 표면 mode·규칙 revision·설정 hash·grid hash를 갖는다. 따라서 인접 셀의 공통 경계 표본이 일치하고 저장된 셀 계획만으로 같은 Mesh와 Collider를 다시 조립할 수 있다. 나무와 고정 H 기준점도 동일 표면의 높이·경사를 읽으며 최대 경사를 넘으면 셀 준비를 실패시킨다.

Unity LH는 비평면 상태 사본에 한해 통행 바닥 Mesh와 `MeshCollider`를 생성한다. 이후 `World공간표현조립Coordinator`가 Sky 적용, 실외 접지, 실내 Root 준비 순서로 실행한다. 평면 모드는 기존 Cube 바닥과 Scene 동작을 그대로 사용한다. 노이즈 모드는 저장 Scene 기본값을 바꾸지 않고 구성 값 또는 `SSALDDEL_LH_NOISE_SURFACE=1`에서만 선택한다.

Game View 임시 실행에서는 불규칙 지면과 지면을 따라 선 나무를 확인했지만 어두운 조명, 셀 경계선과 기존 Editor Console 오류 때문에 시각 E7 완료 증거로 승격하지 않는다. 다음 표현 우선순위는 셀 경계 법선·재질 연결, 이동 가능한 경사와 오브젝트 하단의 가까운 구도 확인이다. 이후 Perlin·Simplex·DEM은 동일 표면 계약의 교체 구현으로 비교하며 DEM은 계속 선택 입력으로 둔다.

## L과 H의 관계

L은 실행 해상도이고 H는 의미 구조다. 현재 호환 프로필은 `L0 8km / L1 2km / L2 500m / L3 125m`를 제공하지만, 동적 맵 창 계산기는 이 단계와 크기를 직접 요구하지 않는다. 각 단계의 `주 조회 H 단계`는 조회 기본값일 뿐 등식이나 완료 조건이 아니다.

- L0에서는 H4 지역 세계를 주로 조회한다.
- L1에서는 H3 경관·구역을 주로 조회한다.
- L2에서는 H2 기능 블록을 주로 조회한다.
- L3에서는 H1 행동·상호작용 공간을 주로 조회한다.

한 L3 셀이 H1뿐 아니라 H2 경계, H3 연결구와 H4 정책을 함께 참조할 수 있다. 반대로 하나의 H1이 여러 L3 셀에 걸칠 수도 있다. 기존 `DefaultHLevelCode`는 직렬화 호환을 위해 유지하고, 새 설명과 구현은 `PrimaryHQueryLevelCode`를 주 조회 단계로 사용한다.

## 셀 내용 공급 경로

현재 시험용 `ScenarioProceduralSimulationLhCellContentSource`는 기존 결정적 배치, 계절 표현, H 계보와 연결구 생성을 보존한다. 이 결과는 시나리오 절차생성 자료이며 실제 E5나 E6 증거가 아니다.

후속 실제 세계 공급자는 같은 인터페이스에서 다음 입력을 결합한다.

1. E5 실제 공간 결속: 실제 `AreaSet`, `LandscapeGraph`, Node, Edge, Connector
2. E6 현실 근거 결속: 지형, 토지피복, 도로, 건축물과 공간 파생 산출물의 계보
3. 시뮬레이션 현재 상태: 서버 세계 개정 번호, 업무·위협·계절 상태와 셀별 변경분

실제 자료가 부족하거나 개정이 맞지 않으면 증거 부족으로 반환한다. 실제 세계 조회 실패를 시나리오 절차생성으로 조용히 대체하지 않는다.

## 기본 조립과 플레이어 조립

LH가 셀을 준비했다는 사실과 그 공간을 누가 형성했는지는 다르다. LH 기본 조립은 `LhComposed`, 플레이어 Confirm으로 성립한 공간은 `PlayerComposed`, LH 기본 공간에 플레이어 변경분이 누적된 경우는 `HybridEvolving`으로 구분한다. LH가 플레이어 공간을 다시 스트리밍해 조립해도 형성 계보는 바뀌지 않는다.

H 단계별 직접 조립·성장 판정과 계보 필드는 [LH 조립 공간과 플레이어 조립 공간 구분](LH조립공간과플레이어조립공간구분.md)을 따른다.

## E7 완료 기준

LH 실제 실행 검증 완료는 화면에 셀이 보이는 것만 뜻하지 않는다. 실제 E5·E6 입력으로 셀을 조립하고, 플레이어 또는 NPC가 연결구를 통과하며, 서버 확인 지점에서 상태와 세계 개정 번호가 바뀌고, 새 개정에 따라 LH가 다시 계획하는 폐루프가 필요하다.

현재 리팩터링은 공급자 교체 경계, L/H 독립과 가변 동심 창 계산까지 완료한다. 실제 E5·E6 공급자, 원형·이동 회랑·예산형 선택 정책, Unity의 현실 지형·능력 조립, 서버 개정 재계획 폐루프와 Play Mode·Game View 증거는 후속 E7 작업이다.
