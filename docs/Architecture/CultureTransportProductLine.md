# 문화교통 0.0~1.5

## 이름

살뜰의 `0.0`, `1.0`, `1.5` 제품군 이름은 **문화교통**입니다.

문화교통은 운송 서비스를 문화적으로 포장한 이름이 아닙니다. 음식과 생활의 문화를 이해하고, 재료와 사람의 필요가 어디에서 생겨 어디로 이어지는지 근거와 함께 살피며, 당사자가 원할 때만 공동 수요와 공급·이동 준비로 확장하는 흐름입니다.

숫자 버전, 기존 HTTP route, 원장 ID와 기능 플래그는 그대로 유지합니다.

| 버전 | 문화교통 단계 | 사용자 결과 |
| --- | --- | --- |
| `0.0` | 문화와 근거 | 공식 음식·재료 자료, 사람의 경험과 질문을 출처와 함께 나눔 |
| `1.0` | 함께 구하려는 마음 | 여러 재료의 비구속 수요와 수령 조건을 모으고 역할·비용·위험을 드러냄 |
| `1.5` | 공급과 이동 준비 | 공급 근거, 가격 기준, 포장·수량, HS·HTS 후보와 사람의 인계 질문을 준비함 |

`2.0`의 실제 국내 화물·운송 이행은 문화교통의 다음 단계입니다. 문화교통이라는 이름만으로 배차, 계약, 신고, 선적이나 운송 수행이 활성화되지는 않습니다.

## 콘텐츠 흐름

```text
음식과 사람의 문화
  → 재료·가격의 공식 근거
  → 함께 구하려는 비구속 수요
  → 공급·통관·이동 전에 확인할 질문
  → 사람의 선택과 전문 검토
```

콘텐츠는 구매 전환율보다 이해와 대화를 먼저 돕습니다.

1. **음식과 사람의 문화:** 언제 누구와 먹는지, 지역·가정별 차이, 번역에서 빠지는 맥락을 묻습니다.
2. **재료와 가격의 근거:** 원천, 기준 시각, 지역, 시장 단계, 통화와 단위를 함께 보여 줍니다.
3. **함께 구하려는 마음:** 한 가지 재료로 제한하지 않고 희망 수량, B2B/B2C 목적, 수령 권역과 철회 가능 상태를 설명합니다.
4. **재료가 이동하기 전의 준비:** 산지, 포장, 보관, MOQ, 가격 기준, HS·HTS 후보와 포워더에게 확인할 질문을 보여 줍니다.

공용 계약은 `CultureTransportContentCatalog`가 소유합니다. 새 콘텐츠 Source는 이 카탈로그의 버전, `WorkflowTag`, 필수 근거와 발행 경계를 재사용합니다.

## 자동 글 원칙

- 운영자가 승인한 공식 음식 메타데이터만 자동 문화교통 질문의 후보로 사용합니다.
- 원문 레시피·영상·글 전문을 복제하지 않고 이름, 지역, 분류, 제공기관, 확인 시각과 원문 링크를 사용합니다.
- KAMIS와 USDA 가격은 서로 다른 시장 단계와 단위를 합쳐 하나의 가격처럼 표현하지 않습니다.
- 시스템 글에는 `문화교통`, 자동 작성, 출처, 기준 시각과 해석 한계를 표시합니다.
- 한 사람의 경험을 국가·민족·문화 전체의 설명으로 일반화하지 않습니다.
- 콘텐츠가 공동구매 참여, 판매자 추천, 수입 가능성, 계약 또는 운송 실행을 자동으로 만들지 않습니다.

자동 글의 선택·중복 방지·일정은 `CommunityEditorialBatch`가 소유합니다. 공동구매 OS는 수요 원장과 필요한 근거 수집 상태를 조율할 뿐, 게시글을 고르거나 작성하지 않습니다.

## 코드 기준

| 책임 | 기준 코드 |
| --- | --- |
| 제품 이름과 버전 범위 | `SsalddelProductRoadmapCatalog` |
| 콘텐츠 기둥·필수 근거·경계 | `CultureTransportContentCatalog` |
| 승인된 음식 기반 시스템 글 | `CommunityCultureTransportPostSource` |
| 음식 탐색의 문화교통 화면 | `OfficialFoodCultureTransportPanel` |
| Quartz 등록·중복 경로 차단 | `CommunityEditorialBatchRegistrationPlan` |

운영 기본값은 문화교통 자동 발행도 비활성입니다. 관리자가 공식 자료와 권리를 확인하고 `CommunityEditorialBatch:CultureTransportEnabled`를 명시적으로 켠 경우에만 Quartz 작업을 등록합니다.
