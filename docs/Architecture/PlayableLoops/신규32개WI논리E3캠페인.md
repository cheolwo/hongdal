# 신규 32개 WI 논리 E3 순차 구현 캠페인

## 승인과 완료 조건

2026-08-30 사용자가 남은 32개 전체를 목표로 잡아 하나씩 E3까지 계속 구현하도록 요청했다. 이 문서는 그 요청의 실행 관리 경계다. 단일 PlayableLoop를 32개 기능으로 확장하거나 32개 WI를 동시에 활성화하지 않는다.

- 권위 목록: [32개 캠페인 원장](../../../eng/execution-ledgers/remaining-32-wi-logic-e3-campaign.json).
- Q001~339와 기존 WI 책임을 읽고 WI별 좁은 기획·작업 명세를 먼저 결속한다.
- 실제 C# 계약, 무변경 Preview, 권위 Confirm/자동 전이, 멱등·revision·행위 기록·거부·결정성 시험이 있어야 Logic E3 완료다. 이름·JSON·PS1·빈 메서드만으로 완료하지 않는다.
- 비용·확률·보상 미정은 출시 수치로 발명하지 않는다. 명시적인 신뢰 정책 주입과 고정 Fixture 시험이 가능한 경계만 구현하고 미정 분기를 남긴다.
- 한 WI가 E3에 도달하면 증거를 보존하고 다음 WI로 이동한다. 현재 WI의 E4/표현 승인을 기다리는 것과 다음 WI의 승인된 Logic E3 작업은 분리한다.
- 순서는 의존성 검토를 위한 초안이다. 필요한 결정이 없으면 해당 하위 범위만 보류하고 다른 가능한 WI를 계속한다. 보류를 E3 완료로 계산하지 않는다.
- 캠페인 전체는 32개 모두 실제 E3로 검증됐을 때만 완료한다. 불가피한 보류가 남으면 개수·결정을 명시하며 Goal을 거짓 완료하지 않는다.

## 실행 경계

Codex의 상위 지속 목표는 이 캠페인을 추적한다. [확정 결정 D-284](../../AI/DECISIONS.md)에 따라 저장소의 PlayableUnit Goal·WI 실행 개수에 고정 상한을 두지 않는다. 각 실행 묶음은 승인 기획·작업 명세·기준 hash·쓰기 소유권·실제 의존성을 확인한 뒤 독립적으로 진행할 수 있다. 열원 및 Farm 귀환의 기존 증거를 덮어쓰거나 캠페인 항목을 일괄 자동 활성화하지 않는다.

상한은 Logic E3이며 Presentation은 요구 E1까지만 기록한다. 통합 E는 낮은 값을 사용한다. Save/Replay·RemoteHost·Unity·Scene·Game View·운영 DB·Provider·공간 지원 worktree 통합·commit·push는 이번 승인에 포함하지 않는다. 명상·분야 성장량이 미정이면 사유 있는 NotApplicable을 기록한다.

## 첫 순서

개인 계획 설정 → 세계 자원 재생 → 자연 흔적 조사 → 약초 채집·달이기·섭취 → 건설 단일 행동 → 권한·고용·파견 → Farm 토양·용수·밭 → 전투·공동체 → Town 입고·보충 → Hub 할당·조달 → 배급·비축 미달 판매.

질문 번호가 실행 우선순위를 결정하지 않는다. Town·Farm·Hub는 각각 독립 Fixture로 시험하며 다른 영역의 실제 실행을 선행 조건으로 요구하지 않는다.
