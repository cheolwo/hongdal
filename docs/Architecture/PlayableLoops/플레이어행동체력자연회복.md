## 플레이어 약속과 폐루프

플레이어는 Farm에서 작업해 체력이 줄어도 시설이나 포션을 먼저 구할 필요 없이 걷거나 잠시 대기하여 다음 행동의 여력을 되찾는다. 노동·질주·전투 중에는 자연 회복이 멈춘다. 충분히 회복되면 플레이어가 다음 유효 작업을 직접 선택한다.

`작업으로 체력 감소 → 다음 작업의 부족량 확인 → 걷기/대기 선택 → 실제 시간 경과로 회복 → 최신 상태 조회 → 작업 재선택 → 다음 수확 결과`

- 선택: 계속 가능한 다른 행동을 하거나 걷기/대기를 선택한다. 강제 경로·강제 휴식 버튼·거처 방문은 없다.
- 대가: 실제 회복 시간을 기다리며, 현재 허용되지 않는 작업은 여전히 거부된다. 회복을 위한 별도 재료 비용은 없다.
- 실패·중단: 노동·질주·전투 중에는 해당 시간 구간 회복0. 이미 정상 회복한 체력은 취소하지 않고 이후 작업 비용·피해는 기존 규칙을 따른다.
- 반환: 회복만으로 작업을 자동 실행하지 않는다. 동일 Session에서 기존 재료·Task·수확 Lot을 유지하며 다음 작업을 직접 시도한다.

## 확정 규칙

1. 대상은 행동 체력 `Stamina`다. Health·전투 `StaminaPermille`·마나·내면 회복/위협과 임의 통합하지 않는다.
2. 걷기·대기 중 자연 회복한다. 노동·질주·전투 중에는 중단하며, 전투 중 대기/걷기라는 이유로 회복하지 않는다.
3. 금지 활동이 모두 끝나 실제 걷기/대기 상태가 되면 지연 없이 재개한다. 전환 시점 이후의 허용 구간만 누적하며 금지 시간 소급이나 전환 고정 보상은 없다.
4. 최대치를 넘지 않는다. 현재 Farm 행위 비용15·초기 최대치100을 변경하지 않는다. 이미 회복한 값과 기존 수확 결과를 초기화하지 않는다.
5. 개발은 [권위 시간·속도 후보 보고](../../Reports/행동체력-권위시간과회복속도후보-2026-08-30.md)의 자연0.25 Stamina/권위 진행초를 첫 시험 후보로 사용하고 반복 작업 시험으로 조정할 수 있다. 출시 고정 수치가 아니며 숫자마다 재승인을 기다리지 않는다. 허용 활동 정책을 수치 조정으로 바꾸지는 않는다.

## 권위·시간·호환

- Solo `LocalProcess`와 Hosted `RemoteHost`는 같은 Core 규칙을 사용한다. Unity Update/deltaTime이나 UI가 체력을 직접 변경하지 않는다.
- Farm WorldTick의 일 단위를 초로 바꾸지 않는다. 공통 권위 경과 시간과 같은 Actor의 실제 활동을 연결하고 Nature 수면6배를 회복에 자동 적용하지 않는다. 오프라인 종료 시간 회복은 이번 범위 밖이다.
- 시간 분할과 소수 회복 잔여량을 결정적으로 처리한다. 동일 총 허용 시간이면 호출 분할에 따라 체력이 늘거나 줄지 않아야 한다. 중복/과거 시간 구간·음수 경과·범위 초과를 안전하게 거부 또는 기존 멱등 계약으로 처리한다.
- 상태·시간·활동 검증, 회복 결과, WorldRevision 및 필요한 행위/명령 기록을 기존 Session의 원자적 경계에 결속한다. Preview/조회는 무변경이며 중복 요청/Load로 회복을 반복하지 않는다. 자동 회복에 매번 플레이어 Confirm을 요구하는 UI를 새로 만들지 않는다.
- 기존 WI/자동 진행 계약을 먼저 재사용한다. 새 식별자가 기술적으로 필요하면 개발이 이 승인 범위에 한정해 기존 원장·명세·workItem에 등록하고 충돌을 검증한다. 활동 시점 신뢰가 확보되지 않으면 해당 연결만 차단 사유로 반환하고 임의 대기 상태로 대체하지 않는다.
- 저장 시 체력·회복 시간/잔여량·필요 활동 상태를 보존하여 재생 결과를 맞춘다. 개발이 현행 Save와 v30 예약을 재확인하고 공통 writer 아래 통합한다. 과거 v1~v29 읽기·기존 hash 의미를 보존하며 새 필드를 과거 hash에 소급 삽입하지 않는다.

## E 왕복 명세와 시험

개발은 현행 E7 작업 명세 형식으로 기존 Farm 작업과 자연 회복의 의존·비중첩 경로·승인 hash를 결속한다. 최종 E7 방향/이번 Logic E5 상한을 분리하고, 미검증 표현 E를 올리지 않는다.

- E7→E1 영향 검토: 반복 Farm 선택, 표현의 체력 조회, 기존 H 영향 없음, Host/저장, 활동·권위 시간, 회복 조건 순으로 검토한다.
- E1→E3: 걷기/대기 회복, 노동/질주/전투 중단, 겹친 금지 상태, 재개 지연0·경과0, 상한, 분할 시간·잔여량·중복 처리 시험.
- E4: Local/Remote 공통 Core 결과 동등성, 실제 Actor 활동 조회와 권위 시간 연결. 비공간 규칙이므로 새 공간/건물/배치/애니 연구는 `NotRequired` 사유를 기록한다. 기존 Farm 연구는 유지한다.
- E5: 실제 Session의 비용 차감→허용 시간 회복→최신 상태 재조회→다음 작업을 검증한다. 새 밭 01→02→03→04→02→03→04 두 주기를 같은 Session에서 수행하고 이전 Lot·식별자 계보를 보존한다. 회복 없을 때의 체력 부족 거부 시험도 유지한다.
- 저장/재생: 허용 구간 및 중단 경계 전후 Save/Load, 동일 명령·시간 기록 Replay, Local/Remote 결과 hash를 대조한다. 순수 서비스 시험만으로 Session/Save 완료를 주장하지 않는다.
- 표현: 새 화면 구현은 이번 범위 밖. 기존 Farm E5 화면 검증과 연결할 때 개발이 실제 상태·입력을 공간 담당에 인계하고 View 캡처는 공간 담당이 수행한다. 통합 E는 Logic/Presentation 중 낮은 값이다.

## 제외와 인계

제자리 휴식, 불·오두막 우대, 포션, 마나, 최대치 성장, 명상, 새 상태 UI는 이번 실행 범위에 포함하지 않는다. 이들의 종합 기획상 확정을 취소한 것은 아니며 다음 실행 묶음으로 분리한다. Q-347과 작업 진척 보존의 미답변도 그대로 둔다.

개발은 명세·workItem·관련 원장 결속을 검사한 뒤 구현한다. 기존 지식·방문자·Farm 작업은 계속 병행하며 공통 Session/Save 쓰기는 개발이 조정한다. CURRENT_WORK와 개발 통합 상태판에 등록·실제 증거·남은 경계를 갱신해 기획으로 반환한다. 이번 승인에 commit·push는 포함되지 않는다.
