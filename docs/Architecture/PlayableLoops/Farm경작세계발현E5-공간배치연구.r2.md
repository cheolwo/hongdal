## 확인된 문제

실측 보고의 identity Wrapper, native Scale1, yaw0 기준 Barn01 외곽 X/Z는 약13.494844/14.157824m, Barn02는 약13.494844/7.435112m다. 원 후보의 Barn 예약 외곽12×10m에 두 후보 모두 맞지 않는다. 이 값은 모델 Renderer 외곽이며 실제 출입 폭·Player 통행을 증명하지 않는다.

176/176 보존·실측 검사와16/16 예상 거부는 전문 담당의 검사 근거다. 기획은 보고서 hash를 확인했으며 이번에 Editor 측정을 재실행하지 않았다. 성공 배치가 나온 것으로 바꾸지 않는다. 개발이 확인한 전체 UniformScale은 예약 외곽과 모델을 함께 키우므로 상대적인 불일치를 해결하는 방법이 아니다.

## 선택한 변경

1. Barn01을 주 후보, Barn02를 기존 대체 후보로 유지한다. 부지에 맞추기 위해 건물 또는 Player를 축소하지 않는다. 기준 자세는 실측의 native Scale1이며 공급자 Prefab·Importer·Mesh를 변경하지 않는다.
2. Barn의 예약 외곽을 실제 회전된 Renderer/Collider 외곽에 맞추고 Player 접근 여유를 추가한다. 필요한 작업마당·내부 작업로·인접 배치도 함께 조정할 수 있다. 전체 H2를 일괄 확대하거나 모델을 왜곡하는 대신 해당 배치 문맥을 명시적으로 개정한다.
3. 여유 폭과 최종 부지 치수는 실제 Player Collider/이동 설정, 문 방향, 지지면, 주변 배치에 근거해 공간 담당이 산출·시험한다. 사용자에게 임의 미터 값을 다시 고르게 하지 않는다. 단순히 건물 외곽과 같은 크기의 사각형만 만드는 것으로 통행을 증명하지 않는다.
4. 진입·Barn 작업마당·내부 작업로·출구의 접근 관계는 보존하되 고정 이동 순서를 강제하지 않는다. 건물 뒤편을 포함한 자유 접근은 기존 지형·충돌 규칙 안에서 검증한다.
5. 기존 단일 주 하천 보존 마스크·자연 완충·지형 경사/지지·Cell/H 소유 경계를 유지한다. 여유가 부족하면 기존 허용 후보 위치/배치를 조정해 검토하고, 적합하지 않으면 사유를 남긴다. 강을 지우거나 지형을 자동 평탄화하거나 소유 경계를 조용히 넘지 않는다.
6. 넓히는 것은 건물·마당·통행의 배치 예약 공간이다. 생산100㎡, 표시 흙두렁 약25.29㎡, H1 WorkArea는 각각 별도 의미로 유지한다. 생산량·재료비·성장 규칙을 부지 확대에 비례해 바꾸지 않는다. H1 모판 허용 범위를 넘겨야만 해결되는 경우에는 그 변경 필요만 별도 반환한다.
7. Barn은 기존 외형 랜드마크다. 문 방향·문 앞 접근을 확인하되 실내 진입·인테리어·새 건설 WI를 추가하지 않는다. 감자 모델의 Collider0을 해결했다고 간주하지 않으며 H1 InteractionAnchor/통행 결속은 기존 E5 범위에서 별도 검증한다.

## 후보 개정과 책임

- 원후보16파일·r1 JSON·기존 해시/거부 증거는 보존한다. 별도의 새 후보 revision으로 변경된 예약 외곽·위치·회전·작업마당/통로를 기록하고 이전 후보·실측·연구 r2를 부모 근거로 남긴다.
- 새 후보 hash, Adapter 측정 hash, 변환/배치 계획 정규형 hash는 각각 계산한다. 기존 hash 문자열만 바꾸거나 소비 검사기의 외곽 거부를 끄지 않는다. 구형 불일치 후보의 거부 시험은 유지한다.
- 개발이 연구 hash·기획 추가 승인·E7 작업 명세·작업 목록·표현 준비/엔진 결속을 일관되게 갱신한 뒤 비중첩 쓰기 경로를 공간 담당에게 배분한다. r1의 승인 의도는 r2로 보완되지만 실제 후보 승인은 자동 발생하지 않는다.
- 공간 담당은 후보 외곽·배치 조정과 실측 검증, 개발은 공통 계약/Adapter·원장·최종 통합을 맡는다. 기존 자연 회복·지식·방문자 작업은 독립적으로 계속한다.

## 수용 기준

- 실제 Barn 모델을 축소하지 않은 채 회전·pivot을 반영한 외곽이 새 예약 영역 안에 들어간다. 건물/작업마당/통로 사이 충돌·끼임·매몰·부유와 보호 영역 침범을 검사한다.
- 평지·완만한 노이즈·낮은 단차 표본은 새 후보로 재검증하고 급경사·보존 마스크 침범 등 실패 표본은 계속 거부한다. 이번 부지 확대가 Q316 전체 적응 탐색을 구현한 것은 아니다.
- Player 실제 Collider와 지원 카메라로 문 앞·마당·밭·출구 접근을 확인한다. Collider 표본 검사와 실제 이동/Game View 결과를 구분한다.
- 같은 입력의 후보/배치 hash가 결정적이고 Partition/LH Prepare/Activate/Cache/Release가 위치·자산·계보를 보존한다. 공간 변경은 생산 권위 상태·WorldRevision을 임의 수정하지 않는다.
- 실제 Scene 반입은 기존 D-286 절차와 새 연구/명세 결속·개발 인수 이후 진행한다. canonical `SimulationWorldShell`만 사용하고 기존 dirty Scene을 저장/폐기하지 않는다. 해결되지 않은 dirty 소유권은 해당 실행만 조정한다.
- View 캡처는 D-298에 따라 공간 담당이 수행한다. 개발이 같은 WI/상태 revision·재현 입력을 넘긴 뒤 실제 화면을 확보하며, 배치만 확인한 그림을 플레이 폐루프 완료로 보고하지 않는다.

## 반환·무효화

공간 담당은 새/구 후보 차이, 실제 치수·여유의 근거, 후보/실측/배치 hash, 통과·거부·미검증, 실제 이동·화면 여부를 개발에 반환한다. 개발은 공통 소비와 시험을 통합해 CURRENT_WORK·개발 통합 상태판에 반영한다.

사용자 선택으로 남길 것은 기존 보호/소유 영역을 바꿔야 하거나 다른 건물·실내·생산 규모가 필요해지는 경우다. 단순 치수 산출·충돌 수정은 승인된 기술 검증 안에서 처리한다. 연구 승인만으로 패턴 `ApprovedReference`나 E5/E7을 승격하지 않으며 commit·push는 하지 않는다.
