## 플레이어 약속

혼자 농사를 시작하고, 수확 시기를 살피며, 감당하기 어려워지면 적합한 NPC에게 정해진 일을 맡긴다. 플레이어는 탐험을 계속할 수 있고 돌아와 성과·중단 사유·다음 일을 확인한다. NPC 고용이나 City·Town·Hub 방문은 첫 농사의 필수 조건이 아니다.

## 첫 구현과 후속 확장

1. 기존 Farm 수확·인벤토리·집하·작업 배정 계약을 재사용해 수용량/권한/예외 판정과 결과 요약의 좁은 Core 시험부터 진행한다. 후보 계산만으로 실제 수확·운반 완료를 기록하지 않는다.
2. 예산 구매·외상 기본 OFF와 모드별 피해·훈련 여부를 명시적 정책 입력으로 분리한다. 기존 거래·채무·장착·전투 계약의 실제 연결 가능성을 확인한다. 구매/채무 생성은 승인된 Simulation 명령의 권한·잔액·한도 검증을 거치며 현실 금융·상품 주문을 실행하지 않는다.
3. 수확 지연·밟힘 피해의 수치가 필요하면 개발은 판본 있는 비교 Fixture를 만들 수 있다. 이는 시험값이며 미정인 곡선이나 즉시 전량 손실을 실제 게임 규칙으로 고정하지 않는다. 부족한 선택은 해당 항목만 기획으로 반환하고 다른 승인 작업을 막지 않는다.
4. 트럭을 이용한 Town 또는 City 판매 위탁은 `ConfirmedDirection / FutureExtension`이다. 가격·운송비·적재·위험·판매 조건을 별도 결속한 뒤 확장한다. 이번 첫 농사 구현에 영역 간 경로를 필수화하지 않는다. 씨앗 자동 생산도 이번 실행 범위 밖이다.

## 결속·검증과 담당

- 개발 통합 담당이 기존 WI와 명세/경로 소유를 대조한 뒤 추가 승인을 결속한다. 질문마다 새 WI를 만들지 않는다. 업무 배정·구매·장착·수확의 절차 조합은 별개 명령이며 상위 보편 WI를 중복 실행해 비용/행위 기록을 두 번 남기지 않는다.
- 첫 증거는 관련 Core의 Logic E3 범위부터 모은다. 기존 Farm E5 전달 상한을 높이지 않는다. Runtime·Save·표현의 기존 승인/연구 조건을 충족한 범위만 이어가며 이 문서로 현재 E를 승격하지 않는다.
- Preview 무변경, Confirm 멱등·ExpectedRevision·같은 개정의 행위 기록, 부분 수확 총량 보존, 예산 초과/외상 기본OFF/타인 재고 거부, 모드별 세 Actor 피해 구분, 훈련·무기·안전 접근 없는 전투 전환 거부, 중복 알림/조회 무변경을 시험한다. 순수 정책 시험과 실제 Session 거래·NPC 이동 증거를 분리한다.
- Solo LocalProcess와 RemoteHost는 같은 Core를 사용한다. 공통 Save 판본 예약·기존 hash 호환은 개발이 소유하며 별도 저장 체계를 만들지 않는다.
- 공간 담당은 승인 연구·실제 자산을 바탕으로 집하점/작업로/피난·무기고 접근을 검토하고 실제 Scene·Game View 캡처를 맡는다. 애니 담당은 작업 중단·후퇴·장착·이동/전투 상태의 실제 결속을 확인한다. 배치/애니 준비를 실행 완료로 취급하지 않는다.
- 결과는 전문 담당→개발 통합→기획으로 반환한다. 기존 HB01·방문자·Farm 승인 개발과 병행 가능한 범위를 나누고 공유 파일 writer를 중복 지정하지 않는다.

## 현재 증거

이번 문서는 사용자 답변과 개발 범위의 기획 결속이다. FB-01 새 규칙 코드·Runtime·Save·실제 이동·Scene·Game View 검증은 이 문서 작성으로 수행되지 않았다. 구현 원장의 Q268 과거 Deferred 및 E는 기획 답변 Confirmed와 분리해서 갱신한다.
