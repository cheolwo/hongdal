# PlayableLoop 오디오 요구사항 대장

## 목적

이 문서는 기획 문답·PlayableLoop·WI·H 공간 검토에서 발견한 효과음, 환경음, 배경음과 음성 요구를 한곳에서 누적한다.

오디오 파일을 실제로 보유하고 있다는 대장이 아니다. 다음 세 사실을 분리한다.

1. 플레이어 경험상 어떤 소리가 필요한가.
2. 그 소리를 만들거나 구할 후보가 있는가.
3. Unity에서 실제로 연결하고 사람이 들으며 검증했는가.

- 대장 revision: `playable-loop-audio-requirements.r2`
- 기준 시각: `2026-08-30`
- 상태: `Active`
- 상위 표현 기준: [플레이어 감각 표현축](../플레이어감각표현축.md)

이 대장은 E·H·WI를 대신하지 않는다. 요구사항을 기록하거나 음원 후보를 확보한 것만으로 Presentation E를 승격하지 않는다.

## 등록 단위

새 문답에서 소리가 필요하다고 확인되면 주제 기획 문서에는 결정과 이 대장의 `AudioRequirementStableId`만 남기고, 상세 제작·확보 상태는 이 문서에서 관리한다.

| 필드 | 의미 |
| --- | --- |
| `AudioRequirementStableId` | 요구사항의 변하지 않는 식별자 |
| `AudioCueCode` | Unity 표현 계층이 요청하는 의미 기반 Cue |
| 종류 | `ObjectSfx`, `PlayerCue`, `UiCue`, `Ambient`, `Music`, `Voice` |
| 발생 문맥 | 어떤 WI 상태·세계 상태·H 공간에서 들리는가 |
| 공간 방식 | `2D`, `3D`, `Area`, `MusicBus` |
| 재생 규칙 | 일회·반복·변형 수·중복 억제·복원 시 재생 여부 |
| 접근성 | 음량 채널, 끄기, 자막·시각 대체, 반복 피로도 |
| 출처 계보 | 생성·구매·녹음 출처와 이용조건·hash |
| 자산 상태 | 실제 파일 또는 절차형 생성기의 확보 상태 |
| 결속 상태 | Unity `AudioSource`·Emitter·상태 사본 연결 상태 |
| 청취 검증 | 실제 재생 장치·Play Mode·Game View에서 사람이 들은 상태 |

## 상태 흐름

```text
Discovered
→ Specified
→ CandidateSourced
→ PrototypeBound
→ RuntimeAudible
→ Accepted
```

- `Discovered`: 문답이나 설계에서 필요성이 발견됨
- `Specified`: 발생 순간·공간 방식·플레이어에게 전달할 의미가 정해짐
- `CandidateSourced`: 생성·구매·녹음 후보와 이용조건을 확인함
- `PrototypeBound`: 절차형 대체음 또는 후보 파일을 Unity 표현 경계에 연결함
- `RuntimeAudible`: 실제 재생 장치에서 Play Mode로 들었음
- `Accepted`: 반복 피로도·음량·공간감·접근성을 사람이 승인함
- `Deferred`: 현재 폐루프 범위 밖으로 보류함
- `Rejected`: 후보의 품질·계약·이용조건이 맞지 않아 사용하지 않음

`PrototypeBound`와 `RuntimeAudible`은 다르다. `AudioSource`가 존재하거나 자동시험이 통과해도 실제로 들었다는 뜻은 아니다.

## 제작·구매·AI 생성 계보

최종 파일은 제작 방법과 무관하게 다음 정보를 함께 보존한다.

| 필드 | 기록 내용 |
| --- | --- |
| `SourceType` | `ProceduralGenerated`, `AiGenerated`, `LicensedPack`, `FieldRecording`, `VoiceTts` |
| `ProviderOrTool` | 생성 서비스·도구·판매처·녹음 장비 |
| `ModelOrPackRevision` | 사용 모델 또는 팩 판본 |
| `PromptOrRecipeHash` | AI 프롬프트 또는 절차형 생성 Profile의 hash |
| `GeneratedOrAcquiredAt` | 생성·구매·녹음 시각 |
| `LicenseAndUsageReview` | 상업적 게임 사용·재배포·편집 허용 검토 상태 |
| `RawFileSha256` | 원본 파일 hash |
| `ProcessedFileSha256` | 잘라내기·정규화·Loop 가공 뒤 파일 hash |
| `AttributionRequirement` | 표시 의무와 표시 위치 |

- API key·로그인 정보·결제 정보는 대장이나 Unity 자산에 기록하지 않는다.
- AI 생성 서비스 이름은 구현 권위가 아니다. 같은 `AudioCueCode`를 유지한 채 승인된 다른 파일로 교체할 수 있다.
- 서비스 약관과 모델 이용조건은 음원을 생성하거나 가져오는 시점에 다시 확인한다.
- 출처나 이용조건이 불명확한 파일은 `CandidateSourced`로 올리지 않는다.

## 문답에서 새 요구를 발견할 때

1. 주 상태 소유 주제의 문답에 플레이어가 들어야 할 원인·상태·결과를 기록한다.
2. 이 대장에 새 `AudioRequirementStableId`를 추가하거나 기존 Cue 재사용 여부를 판단한다.
3. `WI`, H 공간, Authority 상태 사본과 재생 순간을 연결한다.
4. 2D·3D·Area·MusicBus, Loop, 동시 재생 상한과 복원 시 재생 여부를 정한다.
5. 소리를 끈 경우의 자막·아이콘·진동·방향 표시 같은 대체 판독을 남긴다.
6. 생성·구매·녹음 후보가 생기면 출처 계보와 이용조건을 기록한다.
7. Unity 연결, Play Mode 청취와 사람 승인 상태를 각각 별도로 올린다.

## E 증거와 권위 경계

- Logic은 오디오 파일 재생 결과를 읽어 세계 상태를 변경하지 않는다.
- Audio Cue는 Simulation 상태 사본과 같은 revision을 읽어 표현하되 `WorldRevision`을 증가시키지 않는다.
- 저장 복원 시 과거의 일회성 완료음·타격음을 다시 재생하지 않는다.
- Presentation E4는 필요한 Cue·발생 순간·H·접근성·자산 후보를 검토한다.
- Presentation E5~E6는 실제 Emitter·Mixer·파일 또는 절차형 Profile·중복 억제와 품질 예산을 결속한다.
- Presentation E7은 canonical `SimulationWorldShell`의 실제 입력과 재생 장치에서 청취하고, Game View·Console·설정별 동작을 별도 EvidencePackage로 남긴다.
