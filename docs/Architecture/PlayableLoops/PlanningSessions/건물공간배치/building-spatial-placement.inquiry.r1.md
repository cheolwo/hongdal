## 현재 한 문장

- 플레이어 약속 후보: 플레이어는 적합도 탐색과 도구 조사를 거쳐 지형을 따르는 밭 경계를 정하고, 구획별 장애물을 직접 또는 프로젝트 작업으로 정비한다. 완료 구획은 보존되며 토양 상태와 수원 거리의 대가를 감수하면서 관수 시설을 성장시킨다.
- 현재 가장 큰 미정: 방문 NPC의 호혜 기여가 어느 시점에 관계 변화나 다음 참여 의향으로 이어지는지, 실제 수치·감쇠·보답 선택은 어떻게 판정할지다.
- 다음 처리: 공통 작업 참여 정책 뼈대를 기존 Farm 작업·NPC 배정·협동 기여 코드에 단계적으로 결속하고, 후속 문답에서는 관계 원장의 호혜 균형을 정한다.

### NPC 방문자와 멀티플레이 사람 방문자 경계

- `NpcVisitor`: Simulation이 Farm 복구 상태·세계 규칙·결정적 후보에 따라 출현시키며 행상인·이웃·일손 후보 역할을 가질 수 있다.
- `PlayerVisitor`: Hosted Multiplayer에서 다른 사람이 명시적으로 접속·이동해 도착한 Player Actor다. NPC 출현 후보나 자동 역할을 사용하지 않는다.
- 둘은 Farm 외곽 연결로, 이동 가능 공간, 근접 알림 같은 표현 기반을 공유할 수 있다.
- 사람 방문자의 출입·시설 사용·수확·건설·거래는 소유자 동의와 권한 계약을 별도로 검사한다. Farm에 들어왔다는 사실만으로 상태 변경 권한을 얻지 않는다.

### Nature 야영지와 NPC Farm의 후속 연결 후보

```text
Nature 독립 폐루프
작물 확보·재배 → 수확
        ↓ 플레이어가 직접 이동·납품
NPC Farm 독립 폐루프
입고·사용·반환
        ↓
인연·상호 인지 원장
        +
Nature 야영지 ↔ Farm 실제 거리·간선
        +
몬스터 제거·위협 억제에 따른 RouteSafety
        ↓
NPC 왕래 후보 → 실제 이동 → 교류·후속 거래
```

- 이 연결은 Nature와 Farm 각각의 독립 폐루프를 대체하지 않는 후속 통합 PlayableLoop다.
- 작물 납품 성공은 인연을 만들 수 있지만 길을 자동으로 안전하게 만들지 않는다.
- 몬스터 제거는 RouteSafety의 한 입력이며 영구 삭제를 자동 의미하지 않는다. 재출몰·시간대·계절·거점 방어 상태는 후속 규칙으로 남긴다.
- NPC는 순간 이동하지 않고 승인된 연결 간선을 실제로 이동한다. 간선이 위험해지면 출발 보류·호위 요청·회항 같은 결과 후보가 필요하다.
- 후보 H 결속은 Nature 야영지 H1, Farm 입고 H1, 각 영역 내부 H2~H3, 두 AreaSet 사이 연결 회랑으로 나누며 현재 문답만으로 승인 H를 만들지는 않는다.

### NPC Farm과 플레이어 Farm의 후속 성장 후보

```text
NPC Farm ↔ Nature 야영지 인연·안전로
        ↓
플레이어가 별도 낡은 Farm을 복구
        ↓
NPC Farm ↔ 플레이어 Farm 간선 조사·위협 억제
        ↓
NPC 실제 방문
        ↓
업무 필요 + NPC 역할·의향 + 플레이어 제안
        ↓
고용 계약 Confirm
        ↓
플레이어 Farm의 업무 참여·생활 이동
```

- Farm 간 길 연결은 접근 가능성을 만들 뿐 NPC를 자동 고용하지 않는다.
- 방문, 단기 도움, 고용 후보, 고용 계약, 업무 배치와 이탈은 서로 다른 상태로 관리한다.
- NPC Farm과 플레이어 Farm은 같은 Farm 공간 문법과 Synty 표현 후보를 재사용할 수 있지만 소유·운영·재고·업무 원장은 공유하지 않는다.

### 멀티플레이 사람 방문 후보

```text
공간 소유자가 공개 범위 선택
        ↓
다른 Player가 Hosted 공간에 방문
        ↓
관람 + 허용된 NPC 도움
        ↓
소유권·훼손·철거·임의 반출은 차단
        ↓
선택적 쪽지 남기기 → 퇴장
        ↓
별도 친구 요청·수락
        ↓
플랫폼 친구 연계 후보
```

- `공간 공개`, `방문 허용`, `업무 도움`, `쪽지 수신`, `친구 요청·수락`은 하나의 동의 값으로 합치지 않는다.
- 사람 방문자는 기본적으로 건물 훼손·철거, 배치 변경, 저장고 임의 반출, 작물 소유권 변경을 할 수 없다.
- NPC 도움은 소유자가 허용한 안전한 업무 Command만 사용하며, 방문자 Unity 객체가 권위 상태를 직접 바꾸지 않는다.
- 쪽지는 공동 상태 변경 Command와 분리된 사회적 기록이며 공개 범위·차단·신고·삭제 경계가 필요하다.
- Steam 친구 기능은 후속 플랫폼 Adapter 후보로만 두며 게임 안의 명시적 친구 요청·수락 없이 자동 연결하지 않는다.

## 확정 후보

- Farm 기본 골격은 건물 목록만이 아니라 길·출입구·밭·작물 구역·작업 동선과 건물군의 관계를 포함해야 한다.
- 배치 엔진은 골격의 필수 기능과 통행을 바꾸지 않고 승인된 Slot·Surface·밀도 범위에서 변주해야 한다.
- E6 공공데이터 결속은 현실 근거와 표현 조건을 제공하지만 Simulation의 건물 위치·작물 상태·수확량을 직접 확정하지 않는다.
- Farm의 길과 작업 구역은 권장 흐름과 판독성을 제공하되 통과 순서를 강제하는 관문으로 사용하지 않는다.
- 밭·울타리·마법진은 같은 위치의 장식 변형이 아니라 개간·보호·성장 선택의 권위 상태에서 파생되는 별도 배치 역할이어야 한다.
- 농지 적합도는 추천·정보이며 토지를 자동 점유하거나 개간 Confirm을 대신하지 않는다.
- 강·수원 거리는 수계 Anchor 근거가 있을 때만 표시하고, 근거가 없으면 임의 거리를 만들지 않고 미확인으로 남긴다.
- 적합도 개선은 원인을 없앤 권위 상태 변화로 저장하며 단순히 화면 점수만 올리지 않는다.
- 비료·퇴비·석회는 작물과 진단 결과에 맞춰 투입하며 많이 넣을수록 항상 좋아지는 선형 효과로 만들지 않는다.
- 피복작물·윤작·잔재 피복은 즉시 수치 회복보다 여러 WorldTick에 걸친 장기 토양 회복 수단으로 둔다.
- 토양 회복 마법진은 모든 토양 축을 즉시 최적으로 만드는 만능 수단이 아니라 일정 범위의 문제를 부분 완화하는 선택으로 둔다.
- 상세 토양 화면을 열지 않아도 소규모 생산은 가능해야 하며, 상세 정보는 대규모 생산의 손실 감소와 최적화에 기여한다.
- 상세 정보는 규모 숫자만으로 강제 표시하지 않고 플레이어가 관련 행동·시설·자료를 선택했을 때 자연스럽게 열린다.
- 지식의 획득처 안내는 현재 World에서 실제 접근 가능한 자원·상점·시설·채집 위치를 조회하며 존재하지 않는 획득처를 고정 문구로 약속하지 않는다.
- 실제 경작 가능 면적은 경계 내부 총면적에서 과도한 경사·잔존 장애물·필수 통로·가장자리 여유를 제외해 계산한다.
- 같은 경계·지형·장애물·작물 규칙 revision에서는 같은 면적·수용량·배치 hash가 나와야 한다.
- 같은 작물이라도 텃밭·노지·고랭지·기계파종처럼 재배 문맥이 다르면 별도 간격 프로필을 가질 수 있으며 하나의 숫자로 합치지 않는다.
- 공식 자료 원문은 현실 근거이고 실제 식재 후보·수용량은 승인된 규칙 revision을 읽은 Simulation이 결정한다.

## Q-126 농지 조사·개간의 사람 중심 협력

- 초기 농지 후보 판독과 소규모 개간은 플레이어 혼자 완결할 수 있어야 한다. 초반부터 NPC·다른 플레이어·대형 장비를 필수 조건으로 두어 Farm 진척을 차단하지 않는다.
- 농지와 생산 규모가 커지면 플레이어 개인의 도구 능력만으로 닫지 않는다. 농업 경험자, 토양·수리 기술자, 장비 운용자 같은 사람을 초청하고 관계를 형성하는 과정이 조사 정밀도·작업 속도·안전성과 실행 가능한 면적을 높인다.
- Solo에서는 적합한 역할·숙련·관계를 가진 NPC가 참여하고, Hosted Multiplayer에서는 같은 참여 역할을 다른 플레이어도 맡을 수 있게 한다. NPC용 규칙과 Multiplayer용 규칙을 별도 게임 엔진으로 만들지 않는다.
- 플레이어 혼자서 육안 관찰과 기본 도구를 이용해 경사·토양·수원 거리의 기본 적합도를 판독하고 첫 밭을 선택할 수 있다. 이 판독은 초반 플레이에 필요한 수준에서는 충분히 유효하다. 협력자는 더 넓거나 까다로운 토지에서 세부 토질·관수 설계·장비 요구·예상 노동량을 정밀하게 판독하고 실제 개간 단계의 인력·기술·장비 Capability를 확장한다.
- 트랙터 같은 대형 장비를 초반 필수 조건으로 고정하지 않는다. 대상 면적과 난이도가 커질 때 장비 운용자·장비 확보가 선택 가능한 확장 조건으로 등장한다.
- 인간관계는 단순 호감 수치가 아니라 `초청 가능 여부`, `참여 의향`, `신뢰 가능한 역할`, `필요 보수·보급`, `일정`, `현장 접근`을 결정하는 협력 조건으로 사용한다.
- 이 결정은 향후 `농지 조사 Preview → 참여자·장비 계획 → Confirm → 현장 조사/개간 Task → 결과 기록` 계약으로 구체화하며, 아직 NPC 자동 고용이나 Multiplayer 초대 API를 승인한 것은 아니다.

## Q-127 협력 필요성의 증가 조건

- 협력 필요성은 농지 면적 하나로만 결정하지 않고 `작업 면적 + 현장 난도`를 함께 보는 혼합형으로 정한다.
- 기본 면적·완만한 경사·일반 토양·가까운 수원의 첫 밭은 플레이어 혼자 충분히 조사하고 개간할 수 있다.
- 면적이 커지거나 급경사·큰 바위·배수 불량·먼 수원 같은 문제가 겹칠수록 필요한 노동량·피로·소요 시간·실패 위험이 증가하고, 농업 경험자·토양/수리 기술자·장비 운용자가 제공하는 Capability의 가치가 커진다.
- 협력자나 장비가 없다는 이유만으로 모든 작업을 즉시 금지하지 않는다. Preview가 혼자 시도할 때의 예상 시간·피로·위험과 협력 계획을 사용했을 때의 차이를 보여주고 플레이어가 선택하게 한다.
- 다만 현재 장비로 물리적으로 처리할 수 없는 거대 암반처럼 명백한 불가능 조건은 별도 차단 사유를 반환할 수 있으며, 이는 단순히 NPC가 없다는 사유와 구분한다.

## Q-128 혼자 수행하는 어려운 개간과 자연스러운 지원

- 어려운 농지를 혼자 개간할 때는 점진적 부담 방식을 사용한다. 작업 진척은 보존되지만 예상 시간·피로·도구 내구도 소모와 부상 위험이 증가한다.
- 중단·휴식·장비 교체·협력자 합류 뒤 같은 개간 작업을 이어갈 수 있어야 하며, 이미 수행한 유효 진척을 임의로 초기화하지 않는다.
- 시스템은 현재 부담이 커졌거나 더 적합한 사람·장비가 있다는 사실을 문맥 알림으로 알려줄 수 있다. 이 알림은 작업을 강제로 중단시키지 않는다.
- 플레이어의 Nature 거점이나 농장과 NPC 생활권 사이에 안전한 길이 연결되고 관계·일정·접근 조건이 맞으면, NPC가 농장을 방문해 진행 중인 작업을 발견하고 도움을 제안하거나 참여할 수 있다.
- NPC 방문 지원은 공간에 갑자기 생성되는 보너스가 아니라 `관계 → RouteSafety/길 연결 → 방문 이동 → 현장 참여 → 기여 기록`의 계보를 가진다. Multiplayer의 다른 플레이어 참여도 향후 같은 작업 참여 계약을 재사용할 수 있다.
- 구체적인 자동 참여·확인 방식, 보수와 호혜 기록은 다음 문답에서 결정한다.

## Q-129 방문 NPC의 작업 참여 권한

- 권한 설정형을 사용한다. 기본 설정에서는 신뢰·접근·일정 조건을 충족한 방문 NPC가 가벼운 도움에 자동 참여할 수 있다.
- 가벼운 도움의 초기 범위는 잡초 제거, 떨어진 작업물 정리, 가까운 위치로 소량 운반, 이미 Confirm된 작업의 보조처럼 플레이어의 계획·소유권·지형을 바꾸지 않는 행위로 제한한다.
- 자원 소비, 작물 수확·처분, 지형 변경, 건설·철거, 새 작업 Confirm처럼 되돌리기 어렵거나 세계 상태의 의미를 바꾸는 행위는 방문 NPC가 임의로 시작하지 않고 플레이어의 명시적 승인 또는 사전에 지정한 작업 위임이 필요하다.
- 플레이어는 설정 또는 농장별 권한에서 가벼운 도움 자동 허용을 끄거나 허용 범주를 줄일 수 있다. Multiplayer 방문자에게도 같은 원칙을 적용하되 NPC 신뢰와 플레이어 접근 권한은 별도 상태로 관리한다.
- 자동 참여도 권위 Command·행위 기록·기여 기록을 남기며, Unity의 NPC 애니메이션만으로 작업 완료를 만들지 않는다.

## Q-130 방문 도움의 호혜와 전문 노동 보수

- 방문 NPC의 가벼운 도움은 매번 즉시 결제하지 않고 `호혜 기여`로 기록한다. 관계가 있는 이웃이 자연스럽게 돕는 생활감을 유지하되 기여를 공짜 노동으로 지우지 않는다.
- 플레이어는 이후 식사·선물 제공, 상대 농장 돕기, 공동 작업 참여, 필요한 물품 제공 등으로 보답할 수 있다. 어떤 보답을 선택할지는 플레이어에게 맡긴다.
- 전문 기술, 장시간 노동, 장비 운용, 위험 작업은 가벼운 호혜 도움과 구분하고 시작 전 보수·보급·시간·위험 부담을 Preview에서 합의한다.
- 호혜 기여 기록은 즉시 화폐 채무와 동일하지 않지만, 장기간 도움만 받고 되돌려주지 않으면 관계·다음 참여 의향에 영향을 줄 수 있다. 구체 수치와 감쇠는 아직 확정하지 않는다.
- Solo NPC와 Hosted Multiplayer 참여자는 같은 `작업 기여 기록`의 기본 구조를 재사용할 수 있지만, NPC 관계 원장과 실제 플레이어 간 권한·보상 합의는 별도 정책으로 유지한다.

## Q-136 개간 애니메이션과 지면 변화

- 플레이어가 개간 입력을 유지하면 삽·괭이 등 현재 도구의 작업 애니메이션이 반복되고, 도구가 지면에 닿는 checkpoint에서만 한 단위의 개간 진척을 권위 상태로 확정한다.
- Unity는 같은 상태 사본을 읽어 자유형 밭 경계 안의 완료 구획부터 흙·이랑 Terrain 또는 Decal을 점진적으로 확장한다. 애니메이션이나 Decal이 Simulation Revision을 직접 변경하지 않는다.
- 작업 중단 시 마지막으로 확정된 구획까지만 개간된 모습이 남고, 미확정 동작 구간은 되돌린다. 저장·재진입에서도 같은 완료 구획을 복원한다.
- HUD는 전체 진행을 간결하게 보조하지만, 주된 피드백은 Actor의 도구 동작과 실제 지면 변화다.
- Presentation E5 전에는 도구별 손·지면 접촉점, Animation Event 오차 허용, Terrain/Decal 경계 연결, 카메라 가림과 Game View 판독성을 검증해야 한다.

## Q-146 수원 거리와 관수 시설 비용

- 비용 기준은 수원과 밭의 단순 직선거리만 저장하지 않고 승인된 `WaterServiceRoute`를 기준으로 계산한다.
- 건설 비용 후보: 호스·배관·수로 길이, 연결부, 고저차에 필요한 Pump 단계, 지형 장애물 횡단, 중간 저수조와 작업 지점 수.
- 운영 비용 후보: 수동 운반 시간·피로, Pump 에너지·정비, 개방 수로의 손실, 파손·누수 점검 노동.
- Preview는 가까운 수원 사용, 장거리 직접 연결, 중간 저수조 설치 같은 대안을 같은 단위로 비교하고 재료·노동·운영 부담을 분리해 보여 준다.
- 장거리라고 농사를 자동 금지하지 않는다. 플레이어는 작은 면적을 수동 운반으로 시작하거나, 가까운 후보지를 선택하거나, 기반시설에 투자해 같은 땅을 사용할 수 있다.
- H 결속: H1 급수구간이 경로 단위를, H2 초기관수작업장이 한 밭의 공급을, H3 Farm용수망이 여러 수원·저수조·Pump와 우선순위를 관리한다.
- 권위 경계: 배치 엔진은 경로와 자산 후보를 만들고 Simulation이 승인된 경로의 비용·용량·손실·공급 결과를 확정한다.

## Q-147 실제 경로 기반 비용 계산

- 배치 엔진은 수원 Anchor에서 저수·Pump·밭 급수 Anchor까지 연결 가능한 복수의 `WaterServiceRouteCandidate`를 만든다.
- 각 후보는 실제 경로 길이, 구간별 고저차, 총 양정, 경사, 암석·도로·건물·하천 횡단, 연결부와 중간 설비 위치를 포함한다.
- Preview는 후보별 재료 길이, Pump 단계, 시공 노동, 예상 손실, 유지 접근성과 차단 이유를 같은 단위로 비교한다.
- 플레이어가 후보를 선택해 Confirm하면 후보 revision·hash와 ExpectedRevision을 검증하고 그때 비용과 배치 예약을 확정한다.
- 지형이나 건물이 변경되어 후보 경로가 무효화되면 조용히 다른 경로로 바꾸지 않고 Preview를 다시 요구한다.
- 직선거리는 빠른 탐색·대략적 안내에만 사용할 수 있고 최종 비용이나 건설 가능 판정의 권위 근거가 아니다.

## Q-155 관수 경로 3인칭 Preview

- 후보 경로는 현재 지형 위에 반투명 선·띠로 투영하고, 확정된 시설이나 일반 탐색 중에는 기본적으로 숨긴다.

### 패턴 수명주기와 권위 경계

```text
IdeaInventory
→ 시험 월드 반복 생성
→ 자동 통행·충돌 검사
→ 낮·밤 실제 이동과 Game View 검토
→ CandidateForReview
→ 사람 승인
→ ApprovedReference
→ 결정적 H3 조립
```

- 패턴은 의미·관계·허용 변형을 소유하고 Synty Prefab 경로를 직접 소유하지 않는다.
- LH는 이미 생성된 공간 계획의 준비·활성·캐시·해제만 담당하며 활성화 때 재설계하지 않는다.
- 기본 LH 생성은 지형을 조용히 평탄화하지 않는다. 플레이어의 개간·평탄화는 별도 WI와 Delta다.
- 질문 확인과 기획 이미지는 E 증거가 아니다. 실제 E5는 동결 후보의 Prefab·World 배치·Renderer·Collider·WI 상태 발현이 필요하다.
