## Hub가 읽는 욕구와 권위 경계

Hub는 다른 영역의 내면 상태를 직접 소유하거나 임의로 계산하지 않는다. 각 영역 또는 결정적 Fixture가 발행한 욕구·요청 상태 사본을 읽고, Hub 내부 재고의 예약·할당·피킹·출고 준비만 Hub 권위에서 확정한다.

```text
영역의 욕구·부족 상태
→ DemandSignal 상태 사본
→ Hub 수요 카드
→ 재고·입고 예정·기한·대체 가능성 비교
→ 할당 Preview
→ 플레이어 Confirm
→ 피킹·출고 묶음 준비
→ 충족·부분 충족·미충족 결과 귀환
```

`욕구 신호`, `요청`, `확정 할당`, `출고 준비`는 서로 다른 상태다. 카드가 표시됐다는 이유만으로 재고를 예약하거나 다른 영역의 욕구를 충족하지 않는다.

몬스터 핵은 단일 고정 상품이 아니라 에너지·마법진, 장비 제작, 약품·연구 또는 격리 대상이라는 용도 후보를 가진다. 실제 용도·위험 등급·검수 규칙은 후속 상품·위험물 기획에서 확정한다.

첫 폐루프는 실제 Nature·Farm·Town·City Runtime을 요구하지 않는다. 판본화된 영역별 Demand Fixture와 Hub 내부 Inventory Fixture를 사용하고, 각 영역이 준비되면 같은 입력 계약의 Adapter를 실제 상태 사본으로 교체한다.

## Hub 입지의 효율성 문맥

Hub 후보지는 단순히 빈 땅인지로 평가하지 않는다. 공급지·수요지·예상 물동량과 다음 요소를 같은 기준 시각의 상태 사본으로 비교한다.

- 공급지와 수요지까지의 경로 거리·예상 시간
- 물품군별 수요량·긴급도·신선도 또는 시간창
- 운송 수단의 용량·왕복 가능성·하역 시간
- 도로·철도·수로 등 이용 가능한 연결망과 병목
- 지형 경사·건설 가능 면적·확장 여유
- 건설·유지·보관·냉장·경비 비용
- 날씨·몬스터·도로 손상 등 구간별 위험과 우회 비용
- 기존 Hub·창고와의 중복 범위와 미충족 수요 감소량

입지 평가기는 후보별 `예상 총비용`, `평균/최악 배송 시간`, `시간창 충족률`, `위험 노출`, `확장 여유`와 계산 근거를 반환한다. 평가 결과는 추천일 뿐 건설을 확정하지 않는다. 플레이어가 위치·규모·예산·연결 경로를 Preview한 뒤 Confirm해야 Hub 건설 또는 확장 Task가 생긴다.
