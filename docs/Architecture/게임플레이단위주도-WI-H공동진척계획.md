# 게임 플레이 단위 주도 WI–H 공동 진척 계획

상태: 실행 기준·기계 대장 r2 적용
기준일: 2026-08-19

## 1. 목적

이 계획은 세계 상호작용 단위(`WI`)를 기능 목록으로 따로 구현하고 H1~H3 공간을 별도 재고로 쌓는 방식을 피한다. 플레이어가 실제로 경험하는 연속 행위를 먼저 **게임 플레이 단위**로 정하고, 그 단위를 성립시키는 WI와 H1·H2·H3를 함께 설계·구현·검증한다.

핵심 원칙은 다음과 같다.

> H는 플레이가 일어날 장소와 동선을 제공하고, WI는 그 장소에서 가능한 행위의 상태 변화를 확정한다. 우선순위는 개별 WI나 개별 H 카드가 아니라 플레이어가 처음부터 결과까지 이해할 수 있는 연속 플레이를 기준으로 정한다.

게임 플레이 단위는 새 Domain 객체나 공개 API가 아니다. 기존 WI·H·AreaSet·경관 그래프·증거 단계를 묶어 작업 순서와 완료 판정을 관리하는 설계·실행 단위다.

## 2. 현재 기준

현재 원장을 기준으로 다음이 확인된다.

| 항목 | 현재 상태 | 계획에서의 의미 |
| --- | --- | --- |
| WI | 41개 모두 행위 구현 E3 | 새 WI를 대량 추가하기보다 공간 통합 우선순위를 정한다. |
| H1 행동 공간 | 52개 인지 부품 | 직접 행위 공간과 경관 지원 공간을 구분해 사용한다. |
| H2 | 24개 이론 적격 블록 | 6개 작성 조립법과 18개 결정적 유도 조립법을 같은 이론 관문으로 검사한다. |
| H3 | 13개 이론 적격 경관 | H2 사이의 이동·사건 인계와 입출구가 결정적으로 닫혀 있다. |
| 이론 E5 | 팩별 전용 AreaSet 4개 | Nature·Farm·City/Hub·Town 세계 의도를 위치 독립 인스턴스로 생성한다. 실제 지역·공공데이터·Runtime 증거는 아니다. |
| 첫 기준 플레이 | Nature↔Farm 수확과 회복의 하루 | 이론 H3·E5 생산 뒤 E6 근거와 E7 실제 플레이 폐루프가 남는다. |
| 후속 플레이 | Farm→Hub 공급선, Hub→Town 시장·수령 | 앞 플레이의 결과를 입력으로 받도록 순차 진행한다. |

H는 증거 단계가 아니다. H1·H2·H3가 존재해도 WI의 E단계가 자동으로 오르지 않으며, E3 WI가 존재해도 플레이 가능한 공간이 자동으로 생기지 않는다.

### 2.1 네 축은 서로 독립적으로 판정한다

| 축 | 기록하는 사실 | 현재 사용하는 상태 |
| --- | --- | --- |
| H 공간 조립 | 공간 자원의 종류와 포함 깊이 | H1 인지 부품 → H2 블록 → H3 `LandscapeGraph`급 경관 → H4 `AreaSet`급 지역 설계 |
| 게임플레이 추적 | 해당 H가 연속 플레이에 어떻게 기여하는지 | `Unlinked → Supporting / DirectAction → SequenceMapped → LoopMapped → RegionalCausalityMapped` |
| E 증거 | WI 구현·통합·실제 배치·근거·실행 증거의 깊이 | E0~E7, 구현과 통합 대기열은 별도로 기록 |
| 플레이 가능한 완성 단위 | 이론 공간 공급부터 실제 완주까지 어느 관문에 있는지 | `Planned → TheorySpatiallyComposed → SpatiallyComposed → FunctionallyClosed → ExperienceValidated → PlayableSliceComplete` |

어느 한 축의 상승도 다른 축을 자동 승격하지 않는다. H2가 `TheoryQualified`이면 게임플레이 추적이나 사람 검토를 기다리지 않고 H3·이론 E5 생산에 사용할 수 있다. 다만 Nature·Farm 엄격 대상이 `Unlinked`이면 게임플레이 우선 대기열에는 올리지 않는다. 반대로 이동 안내·시야·완충·분위기·상태 표현에 기여하는 지원 경관은 직접 WI가 없어도 `Supporting`으로 유지할 수 있다.

첫 엄격 관문은 `NatureHomeThreatRecovery`와 `FarmProductionSurvival`에만 적용한다. Town과 City/Hub에 기준 플레이가 아직 없는 상태는 경고로 보존하며 기존 H 후보를 삭제하거나 조합 검토를 막지 않는다.

## 3. 게임 플레이 단위의 표준 형식

각 게임 플레이 단위는 다음 항목을 가진다.

| 구분 | 반드시 답할 질문 |
| --- | --- |
| 플레이어 약속 | 플레이어가 이 묶음에서 무엇을 해보고 어떤 결과를 이해하는가? |
| 시작 상태 | 어떤 세계·재고·사건 상태에서 시작하는가? |
| 핵심 선택 | 직접 수행, NPC 위임, 안전 처리, 방치 등 어떤 선택이 있는가? |
| WI 인과선 | 어떤 명시적 명령과 자동 전이가 어떤 순서로 이어지는가? |
| 직접 H1 | Preview·Confirm·예약·작업이 실제로 일어나는 장소는 어디인가? |
| 지원 H1 | 시야, 경계, 분위기, 상태 표시, 이동 안내를 맡는 장소는 어디인가? |
| H2 | 여러 H1이 어떤 작업·사건 블록으로 조립되는가? |
| H3 | H2 사이의 이동·Gate·사건 인계가 어떻게 닫히는가? |
| 보이는 결과 | 재고·위협·경로·시설 상태 변화가 공간에 어떻게 드러나는가? |
| 목표 E단계 | 이번 묶음에서 E4·E5·E6·E7 중 어디까지 증명하는가? |
| 다음 플레이 입력 | 이 결과가 어떤 후속 게임 플레이를 여는가? |

### 3.1 카드·턴 조건은 공간 연결점만 먼저 둔다

현재 단계에서는 구체 카드 목록이나 수치 균형을 확장하지 않는다. 기준 플레이에는 다음 날 관리 조건 슬롯 하나를 두고 `Normal`, `Opportunity`, `Threat`, `Recovery` 네 상태만 허용한다.

- 조건 슬롯은 영향을 받는 플레이 단계와 상태를 표현할 H1만 가리킨다.
- 기회·위협·회복에 따른 실제 수치, 비용, 확률과 플러스·마이너스 효과는 서버 턴 규칙이 확정한다.
- Unity와 H 대장은 서버가 확정한 상태를 공간·표현으로 보여줄 뿐 카드 결과를 계산하거나 업무·Simulation 상태를 바꾸지 않는다.
- 구체 카드 설계가 시작되더라도 안정 카드 ID와 예상 개정을 사용하고, 현재 공간 추적 대장에는 효과 수치 사본을 넣지 않는다.

## 4. WI와 H의 연결 규칙

### 4.1 직접 공간과 지원 공간을 분리한다

- **직접 H1**: WI의 공간 능력·업무 용량·예약 대상이 되는 장소다.
- **지원 H1**: 이동 안내, 시야, 경계, 분위기, 위험 가독성, 상태 표현을 제공한다.
- 지원 H1은 플레이 완성도에 기여하지만, 공간 능력이나 WI 완료 권위를 자동으로 갖지 않는다.

### 4.2 모든 WI에 물리 공간을 강제하지 않는다

주문 확정, 재고 예약, NPC 역량 위임, 작업 취소, 턴 마감처럼 주로 규칙·원장에 속하는 WI는 H1을 억지로 만들지 않는다. 피킹·포장·수령처럼 플레이어 또는 행위자가 실제 장소를 사용하는 시점에서만 직접 공간을 연결한다.

### 4.3 H1은 부품, H2는 첫 판단 단위다

H1은 “이런 장소 부품이 있다”를 인지하는 수준으로 관리할 수 있다. H2부터는 사람이 매번 검토하는 대신 승인된 이론 관문을 기계가 반복 적용한다.

H2 이론 적격 판정에는 다음이 필요하다.

1. 필수 H1 조합
2. 상대 위치와 위상
3. 내부 이동·작업 관계
4. 외부 연결구
5. 게임 플레이 맥락에서 구분 가능한 입구·목표·위험·출구
6. 같은 입력에서 같은 식별자·배치·해시를 만드는 결정성

표준 시점 이미지와 사람 검토는 후속 일괄 품질 검토 자료다. 생산을 막지 않으며, 검토하지 않은 결과를 `사람 승인`으로 기록하지 않는다.

### 4.4 H3는 이동과 인과를 닫는다

H3는 보기 좋은 H2 모음이 아니다. 선행 WI의 결과가 후속 WI의 공간 입력으로 이동할 수 있어야 한다.

```text
WI-A 결과
→ 직접 H1-A
→ H2 내부 동선
→ H3 Edge 또는 Connector
→ 직접 H1-B
→ WI-B Preview 입력
```

경로 중 하나라도 미해결이면 H3는 설계 후보로 남기고 해당 플레이를 E5로 올리지 않는다.

## 5. 공동 승격 관문

게임 플레이 단위는 다음 순서로 진행한다.

| 관문 | 공간 쪽 결과 | WI·증거 쪽 결과 |
| --- | --- | --- |
| G0 플레이 선정 | 필요한 장소 후보만 선별 | 시작·선택·결과·후속 플레이 확정 |
| G1 H1 충족 | 직접·지원 H1과 연결구 확인 | WI별 공간 요구와 H1 대응 확인 |
| G2 H2 이론 적격 | 필수 H1·상대 배치·충돌·내부 관계·입출구·결정성 자동 검사 | 같은 블록에서 선행·후속 WI가 모순 없는지 확인 |
| G3 H3 이론 적격 | 이론 적격 H2와 입구→행위→결과→출구 이동 구조 완결 | WI 결과가 다음 WI 입력으로 전달됨을 확인 |
| G4 E4 재검증 | 위치 독립 시험 공간 모판 | Preview→Confirm→예약→Task→Effect→Save/Replay 재통과 |
| G5 이론 E5 결속 | 명시적 H4 세계 의도에서 전용 `area-set:theory:*`와 Graph 관계를 결정적으로 생성 | 실제 지역·공공데이터·Runtime을 주장하지 않는 이론 공간 공급 결과 |
| G6 E6 근거 | 선정 WI에 꼭 필요한 공공데이터만 결속 | 출처·기준일·원본/파생 hash와 한계 확인 |
| G7 E7 플레이 | `SimulationWorldShell`에서 이동·선택 가능 | 실제 서버 재조회로 플레이 폐루프 확인 |

H1~H4 정의에는 공공데이터를 넣지 않는다. 공공데이터는 E5 지역 인스턴스가 생긴 뒤 선택한 WI의 공간 판정에 필요한 것만 E6에서 연결한다.

## 6. 우선순위 산정 기준

각 후보 플레이를 다음 순서로 평가한다.

1. **주인공 체류성**: Nature 상시 체류 세계와 자주 만나는가?
2. **인과 완결성**: 시작·선택·실패·회복·다음 행동이 닫히는가?
3. **후속 해제력**: 완료 결과가 다음 공급선·시장·생활 플레이를 여는가?
4. **공간 준비도**: 기존 H1·H2 조립법·촬영 근거를 재사용할 수 있는가?
5. **WI 준비도**: E3 규칙과 저장·재생을 재사용할 수 있는가?
6. **재사용성**: 다른 AreaSet과 사건에서도 같은 H2·H3를 쓸 수 있는가?

시각적으로 멋지지만 플레이 인과가 없는 조합은 우선순위를 낮춘다. 반대로 중요한 WI라도 플레이어가 공간에서 읽을 결과가 없다면 먼저 상태 표현 H1·H2를 보완한다.

## 7. 실행 우선순위

### P0. 원장 정합성과 자동 생산 관문 정리

목표는 작업 시작점의 모순을 없애는 것이다.

- `WI-NATURE-01~04`는 현재 E3인데 과거 H 정책의 WI 증거 대기열에는 E1 대상으로 남은 항목이 있으므로 최신 원장을 기준으로 바로잡는다.
- H2 24개는 작성·유도 조립법의 출처를 구분하되 같은 `TheoryQualified` 관문을 통과시킨다.
- 공식 H1, 인지 H1, H2 이론 적격, 사람 일괄 검토 여부를 서로 다른 상태로 표시한다.
- 게임 플레이 단위마다 WI·H1·H2·H3 누락 보고서를 만든다.

완료 조건: 같은 WI와 H 카드가 서로 다른 문서에서 상충하는 단계로 표시되지 않는다.

### P1. Nature↔Farm 수확과 회복의 하루

플레이어가 가장 오래 머무는 Nature와 현재 가장 준비된 Farm 행위를 하나의 하루로 닫는다.

#### 핵심 WI

- `WI-WORLD-05` 지역 발견
- `WI-FARM-04` 수확
- `WI-FARM-05` 집하
- `WI-FARM-06` 출하 준비·포장
- `WI-NATURE-01` 위협 관찰
- `WI-NATURE-02` 긴급 후퇴
- `WI-NATURE-03` 경로 복원
- `WI-NATURE-04` 파티 회복

#### H 우선순위

| 단계 | 먼저 닫을 항목 |
| --- | --- |
| H1 | Nature 안전 생활핵·탐색 입구·위협 감시·사건 흔적·긴급 후퇴·복원 작업, Farm 생산구획·수확 적치·작업마당·사건 점검·격리·복원 물자 인계 |
| H2 | 자연 위협 대응·자연 복원 회복·농장 사건 통제·농장 손실 복원 인계와 자연 탐색·대피·고지대 생산·농장 세척 선별 포장을 모두 이론 적격 블록으로 자동 생산한다. |
| H3 | 자연 위협·회복 경관, 자연 탐색망, 고지대 농장, 농장 후처리 경관, Nature↔Farm 경계 인계를 하나의 이동 폐루프로 묶는다. |

#### 목표

- 1차: H2 이론 적격 자동 판정과 H3 이동 폐루프 생성
- 2차: 관련 WI의 E4 공간 모판 재검증
- 3차: Nature↔Farm 선택 경로를 E5 후보로 결속
- E6·E7은 P1의 공간 폐루프가 닫힌 뒤 별도 실행한다.

### P2. Farm→Hub 300kg 공급선

P1에서 준비된 수확·포장 결과를 Hub 보관까지 운반한다.

#### 핵심 WI

- `WI-LOG-01~05`
- `WI-001` 입고 검수
- `WI-002` 창고 적재

#### H 우선순위

| 단계 | 먼저 닫을 항목 |
| --- | --- |
| H1 | Farm 상차 영역·Gate, 화물 회랑, Hub 하차·인수·검수·창고·적재 작업 영역 |
| H2 | 농장 작업·출하, Farm–Hub 회랑, Hub 입고·창고 블록 |
| H3 | Farm Gate→회랑→Hub Inbound Gate→검수→창고의 연속 경관 |

#### 목표

- 기존 E4 공급선 증거를 실제 H2·H3 이동 구조와 대조한다.
- Farm 출구와 Hub 입구를 직접 Node 참조가 아니라 양쪽 Connector와 Graph 관계로 연결한다.
- 위치 독립 조합 검토 뒤 E5 후보로 승격한다.

### P3. Hub 출고와 물류 회복력

보관된 재고가 다시 이동 가능한 화물이 되는 과정을 닫는다.

#### 핵심 WI

- `WI-HUB-03` 출고 요청
- `WI-HUB-04` 피킹
- `WI-HUB-05` 출고 준비
- `WI-HUB-06` 차량 상차
- 필요 시 `WI-WORLD-04` 시설 수리

#### H 우선순위

| 단계 | 먼저 닫을 항목 |
| --- | --- |
| H1 | 피킹, 출고 대기, 상차, 차량 대기, 격리, 반품 처리, 시설 정비 |
| H2 | Hub 출고·차량 블록을 중심으로 장기·저온 보관, 검역·격리, 반품 처리 블록을 선택적으로 결합 |
| H3 | 입고 창고와 출고 영역이 충돌하지 않는 Hub 내부 순환 경관 |

자동 전이 WI에는 별도 공간을 남발하지 않고, 사람이 이동하거나 화물이 실제로 점유·예약하는 장소만 직접 H1로 둔다.

### P4. Hub→Town 시장·수령의 하루

물류 결과가 주민의 수령과 소비로 이어지는 첫 생활권 플레이를 닫는다.

#### 핵심 WI

- `WI-MARKET-01~05`
- `WI-ORDER-03~07`
- `WI-ORDER-01~02`는 비공간 선행 규칙으로 지원

#### H 우선순위

| 단계 | 먼저 닫을 항목 |
| --- | --- |
| H1 | 마트 하차·입고 검수·후방 창고·진열·피킹·포장·수령, 주민 접근·생활 광장 |
| H2 | 마트·생활상권, 저층 주거, 생활권 오염 통제, 회수 안내·구호, 반품·폐기물 블록 |
| H3 | Town Receiving Gate→후방→진열→수령→생활권 출구와 오염 시 우회·격리 경로 |

기존에 촬영된 생활권 오염 통제·회수 구호 H2를 먼저 검토하되, 정상 시장 플레이 H2가 빠진 채 사건 공간만 완성하지 않는다.

### P5. 전체 생산 주기와 반복 플레이

첫 하루와 공급선이 닫힌 뒤 작물 생산의 시작과 반복 조건을 확장한다.

- `WI-FARM-01` 밭갈기
- `WI-FARM-02` 파종
- `WI-FARM-03` 재배 관리
- `WI-WORLD-01~03`, `WI-WORLD-06~08` 중 실제 플레이 흐름에 필요한 공통 규칙

목표는 기능 수를 늘리는 것이 아니라, 다음 날 조건·NPC 위임·취소·턴 마감이 P1~P4 경관의 상태 변화로 읽히게 만드는 것이다.

## 8. 한 우선순위 묶음의 실제 작업 순서

각 P단계는 다음 순서로만 진행한다.

1. 기준 플레이 문장을 한 줄로 고정한다.
2. 시작 상태, 정상 분기, 실패 분기, 회복 분기를 적는다.
3. 기존 WI만으로 인과선이 닫히는지 감사한다.
4. 직접 H1과 지원 H1을 나눈다.
5. 기존 H1을 최대한 재사용하고 정말 없는 장소만 추가한다.
6. H1을 승인 조립법 또는 결정적 유도 조립법으로 묶는다.
7. 기계가 H2의 입구·목표·위험·출구·충돌·연결·결정성을 검사한다.
8. 이론 적격 H2를 H3 Node·Edge·Connector로 연결한다.
9. 같은 WI를 위치 독립 모판에서 다시 실행해 E4를 확인한다.
10. 선택된 플레이만 AreaSet·경관 그래프에 결속해 E5로 올린다.
11. 꼭 필요한 공간 판정 자료만 E6에 연결한다.
12. 마지막에 `SimulationWorldShell`과 실제 서버로 E7을 검증한다.

중간에 H2 이론 관문이 실패하면 H1을 무조건 늘리지 않는다. 먼저 상대 배치, 동선, 연결구와 플레이 가독성 규칙을 수정한다.

## 9. 후속 일괄 검토 단위

사람 검토는 생산 관문이 아니라 나중의 품질 개선 대기열이다. 휴대폰에서 확인할 수 있을 때 H2 하나 또는 플레이 분기 하나씩 검토하되, 미검토 상태에서도 공장은 H3와 이론 E5까지 계속 생산한다.

H2 검토 카드는 다음만 보여준다.

- 이 공간에서 일어날 핵심 플레이 한 문장
- 포함 H1과 핵심 WI
- 입구·목표·위험·출구
- 표준 시점 이미지
- 정상 흐름과 실패 흐름
- 승인, 수정 필요, 보류

H1 개별 이미지는 부품 존재 확인용이며 승격 판단의 주 화면으로 사용하지 않는다. H3 검토는 H2별 미감보다 전체 이동·인과 폐루프를 우선한다.

## 10. 작업 원장에 필요한 상태

게임 플레이 단위별로 다음 상태를 별도 기록한다.

```text
PlayPlanState
H1CoverageState
H2CompositionState
H2TheoryQualificationState
DeferredHumanReviewState
H3ClosureState
WiImplementationStage
WiIntegrationStage
AreaSetBindingState
PublicDataEvidenceState
PlayableLoopState
```

하나의 `완료` 값으로 합치지 않는다. 예를 들어 H2 이미지 검토 완료는 E5나 실제 플레이 완료가 아니다.

## 11. 바로 이어갈 권장 작업

이론 공간 생산과 작성 Scenario의 실제 E5 결속은 완료했으므로 다음 작업은 P1의 Runtime·증거 관문을 닫는 데 제한한다.

1. 정상 귀환·후퇴 회복·복원 회복을 실제 서버 재조회·Save/Replay와 canonical `SimulationWorldShell`에서 E7로 검증한다.
2. 처음 접한 플레이어가 20~40분 안에 목표·선택·결과를 이해하는지 관찰한다.
3. 현실 정합이 필요한 대표 목표만 `Required` 또는 적용할 `Optional` E6 프로필로 선택하고, 해당 프로필의 자료만 출처·기준 시각·해시와 함께 연결한다.
4. 작성 Scenario E5/H5는 DEM·도로 없이도 권위 공간으로 유지한다. 현실 정합 revision을 별도로 만들 때만 실제 자료를 연결하고 기존 AreaSet·Graph·양쪽 연결구 계보를 보존한다.
5. 사람 검토는 생산과 병행하는 후속 일괄 품질 대기열로 유지하고, 수정 결과는 다음 이론 공간 개정에 반영한다.

P1이 닫히기 전에 P3·P4의 H 카드를 대량 추가하지 않는다. 다만 이미 존재하는 H1과 H2 후보는 삭제하지 않고 후속 대기열로 유지한다.

## 12. 완료 판정

이 계획의 첫 성과는 “H 카드가 몇 개 늘었는가”가 아니다. 다음 관문을 순서대로 실제 증거로 통과해야 한다.

| 완성 상태 | 필수 증거 | 현재 |
| --- | --- | --- |
| `Planned` | 플레이어 약속, 12단계 인과선, 정상·후퇴·복원 3분기, H·WI 추적 | 충족 |
| `TheorySpatiallyComposed` | 추적된 H2·H3와 H4 세계 의도가 결정적 전용 `area-set:theory:*`에 결속되고 실제 권위를 주장하지 않음 | 충족: Nature·Farm `E5TheoryQualified` |
| `SpatiallyComposed` | 승인된 H가 실제 지역 `LandscapeGraph`·`AreaSet`에 결속된 E5 이동 폐루프 | 충족: Nature·Farm 실제 AreaSet 2개와 Nature↔Farm Network 관계가 `ActualE5Bound` |
| `FunctionallyClosed` | 정상·실패·회복 분기를 실제 서버 상태 재조회와 저장·재생까지 완주한 Runtime 증거 | 미충족: `FullNormalAndRecoveryRuntimeEvidenceMissing` |
| `ExperienceValidated` | 처음 접한 플레이어가 Windows PC에서 20~40분 안에 목표·선택·결과를 이해하고 완주한 관찰 기록 | 미충족: `FirstTimePlayerEvidenceMissing` |
| `PlayableSliceComplete` | canonical `SimulationWorldShell` 저장 배선, Play Mode·Game View, 시각·음향·성능 마감 증거 | 미충족: 두 마감 증거 없음 |

따라서 현재 `reference-play:nature-farm-day.v1`의 정직한 상태는 `SpatiallyComposed`다. 작성 `ScenarioLocalMeters` 근거의 실제 E5 결속은 닫혔지만 공공데이터 E6, 정상·회복 Runtime 완주, 처음 접한 플레이어 관찰, Play Mode·Game View와 마감 증거를 대신하지 않으므로 실제 게임 완성을 선언하지 않는다. 위 관문이 모두 닫힌 뒤에만 다음 문장을 완료 사실로 기록한다.

> 플레이어가 Nature 안전 생활핵에서 하루 목표를 확인하고 Farm으로 이동해 감자를 수확·집하·포장한 뒤, 사건을 안전하게 처리하거나 위협을 관찰해 후퇴·복원·회복하며, 각 선택과 결과가 WI 상태와 H1·H2·H3 공간에서 함께 읽히고 다음 날 또는 Farm→Hub 공급선을 연다.

이후에는 같은 구조를 Farm→Hub, Hub 내부 출고, Hub→Town 시장·수령 순서로 확장한다.
