# 프로젝트 규칙 계층·영역 분류

## 1. 목적

이 문서는 Ssalddel과 Unity에 존재하는 규칙을 역할별로 나누는 기준이다. 생산량 계산, 운송 진행, 창고 입고, 그래픽 상태, 카메라 초점과 사용자 입력을 모두 `규칙`이라고 부를 수 있지만, 이들이 바꾸는 대상과 권위는 서로 다르다.

규칙을 한 목록에 섞으면 카메라 이동이나 애니메이션 완료가 생산·운송·입고 완료를 확정하거나, 서버 원장의 상태가 특정 Prefab·카메라 구성에 의존할 위험이 있다. 따라서 먼저 규칙 계층을 나누고, 각 계층 안에서 세부 영역을 분류한다.

## 2. 전체 분류

```text
프로젝트 규칙
├─ 업무·Simulation 규칙
│  ├─ 생산
│  ├─ 소비
│  ├─ 운송
│  ├─ 창고
│  ├─ 시장·주문
│  ├─ 시설·용량
│  └─ 시간·Turn
│
├─ 해석 규칙
│  ├─ 역할·권한별 조회
│  ├─ 공개 범위
│  ├─ 집계·요약
│  └─ 상태→표현 모델 변환
│
├─ 표현 규칙
│  ├─ 그래픽·Material·색상·LOD·FX
│  ├─ 카메라·초점·거리·전환
│  ├─ 애니메이션·이동 표현
│  ├─ 조명·시간대 표현
│  ├─ 오디오
│  └─ UI 배치·강조
│
└─ 상호작용 규칙
   ├─ 선택·해제
   ├─ 입력·이동
   ├─ 정보 열기
   ├─ Preview 요청
   └─ 명시적 Confirm 요청
```

## 3. 계층별 권위

| 계층 | 주된 소유자 | 바꿀 수 있는 것 | 바꾸면 안 되는 것 |
| --- | --- | --- | --- |
| 업무·Simulation 규칙 | 운영 서버 또는 Simulation 서버 | 원장 상태, Task, 자원 효과, 업무 상태 전이 | Unity Prefab·카메라·Renderer 구성 |
| 해석 규칙 | 서버 조회 결과 생성기와 Unity용 변환기 | 권한에 맞는 관점별 조회 결과, 요약·표현 모델 | 기준 원장과 실제 업무 결과 |
| 표현 규칙 | Unity 표현 계층 | 그래픽, 카메라, 애니메이션, 조명, 오디오, UI | 생산량·재고·운송·입고·수령 완료 |
| 상호작용 규칙 | Unity 입력 계층과 UseCase | 선택 상태, Preview·Confirm 요청 구성 | 서버 응답 전 실제 업무 상태 확정 |

표현 규칙은 업무 규칙의 결과를 읽어 보여줄 수 있지만, 업무 규칙의 입력이나 완료 근거가 되지 않는다.

## 4. 업무·Simulation 규칙 영역

### 4.1 생산 규칙

생산 규칙은 재배·제조·조리·가공처럼 새로운 출력 Lot이나 생산 상태를 만드는 인과를 다룬다.

| 포함 | 제외 |
| --- | --- |
| 생산 용량, 입력 자원, 작업 기간, 환경·시설 계수, 생산 손실, 출력 Lot | 작물 Mesh 크기, 수확 애니메이션 길이, 카메라 확대 정도 |

감자 생산에서는 재배 면적, 생육 상태, 관수·비료·온실 효과, 수확 노동과 수확 Lot 생성이 이 영역에 속한다.

### 4.2 소비 규칙

소비 규칙은 주민·시설·작업이 자원을 실제로 사용한 결과를 다룬다. 수요, 예약, 주문 이행과 실제 소비를 분리한다.

| 포함 | 제외 |
| --- | --- |
| 소비 주체, 대상 자원, 요구량, 반복 주기, 부족 결과, 소비 누계 | 음식이 사라지는 애니메이션, UI의 감소 숫자 전환 |

### 4.3 운송 규칙

운송 규칙은 화물의 원천 예약부터 경로 진행과 목적지 도착 후보까지 다룬다.

| 포함 | 제외 |
| --- | --- |
| Cargo·Lot, 원천·목적지, 차량 용량, 적재 조건, 기간·경로, 연료·노동, 이동 손실, 인계 경계 | 차량 Wheel 회전, NavMesh 위치, 카메라 추적, 도착 FX |

차량이 목적지에 보이는 것과 Cargo가 서버 원장에서 도착 상태가 되는 것은 다른 사실이다.

### 4.4 창고 규칙

창고 규칙은 도착 화물의 검수부터 입고, 적재, 보관, 피킹, 포장, 출고 인계까지 다룬다.

| 포함 | 제외 |
| --- | --- |
| 입고 조건, 검수 합격·손실, 저장 용량, 위치 배정, 보관 기간·감모, 피킹·포장·출고 Task | Shelf 색상, 지게차 애니메이션, 창고 카메라 구도 |

운송의 `도착`은 창고의 `입고 승인`을 자동 확정하지 않는다.

### 4.5 시장·주문 규칙

시장·주문 규칙은 공개 판매 가능 상태, 가격, 주문 수요, 재고 예약, 주문 이행과 취소를 다룬다. 공개 상품과 후방 재고의 권한을 분리한다.

### 4.6 시설·용량 규칙

시설·용량 규칙은 밭 면적, 온실 수용량, 창고 저장 용량, 차량 적재 한도와 시설 유지 상태를 다룬다. 시설 건설은 용량을 늘릴 수 있지만 곧바로 생산물이나 재고를 만들지는 않는다.

### 4.7 시간·Turn 규칙

시간·Turn 규칙은 `1 Tick = 1 Game Day`, Task 진행, 반복 소비, 감모와 예약 만료 같은 공통 시간 인과를 다룬다. 카메라 시간대나 태양 애니메이션은 이 시간을 진행시키지 않는다.

## 5. 해석 규칙 영역

해석 규칙은 서버 기준 원장을 현재 사용자와 상황에 맞는 관점별 조회 결과로 만든다.

```text
서버 기준 원장
    ↓ 역할·권한·공개 범위
관점별 조회 결과
    ↓ Unity용 데이터 변환
표현 모델
```

예:

- 주민에게는 공개 상품·판매 가능 여부만 제공
- 마트 운영자에게는 재고·진열 작업 제공
- 화물 후보에는 대략 위치만 제공하고 확정 기사에게만 허가된 인계 정보 제공
- 여러 개인의 의향을 개인정보가 제거된 집단수요 요약으로 변환

해석 규칙은 정보를 추리고 계산하지만 원장을 변경하지 않는다.

## 6. 표현 규칙 영역

### 6.1 그래픽 규칙

그래픽 규칙은 상태를 어떤 모델·색·Material·LOD·아이콘·FX로 보여줄지 정한다.

```text
생육 단계
    → 감자 재배체 크기·잎 상태 Variant

창고 검수 대기
    → 황색 상태 표지

화물 손실 기록
    → 손상 아이콘·상세 정보 연결
```

색이나 FX가 바뀌었다고 서버 상태가 바뀌지는 않는다.

### 6.2 카메라 규칙

카메라 규칙은 무엇을 어느 거리와 구도로 보여줄지 정한다.

| 상황 | 카메라 책임 |
| --- | --- |
| 멀리 보기 | Farm·Town·City의 공간 관계와 주요 상태 표지 인지 |
| 가까이 보기 | 선택한 배치 객체와 주변 작업 공간 확인 |
| 선택 상태 | 대상 외곽 범위, 연결 지점과 정보 패널을 읽을 수 있는 초점 |
| 업무 흐름 보기 | 생산→운송→창고→마트 관계를 순서대로 따라가는 전환 |

카메라 도착, 줌 완료와 컷 전환은 업무 Task 완료가 아니다.

### 6.3 애니메이션·이동 표현 규칙

애니메이션은 서버·Simulation 상태를 재생하거나 다음 상태를 예상하는 표현이다. 차량 이동, 지게차 상차, 주민 수령과 작물 흔들림은 원장 값을 직접 변경하지 않는다.

### 6.4 조명·오디오·UI 규칙

조명과 시간대는 표현 시각이고 WorldTick과 분리한다. 오디오는 상태 알림과 공간감을 제공하며, UI는 플러스·마이너스·차단·근거를 사람이 이해하도록 배치한다.

## 7. 상호작용 규칙 영역

상호작용 규칙은 사용자가 무엇을 보고 어떤 요청을 만들 수 있는지 정한다.

```text
선택
    → 정보 조회
    → 예상 효과 Preview
    → 명시적 Confirm
    → 서버 Command
    → 최신 상태 사본 재조회
    → 표현 갱신
```

관찰·정보·Simulation·실운영 행동을 분리한다. 클릭 한 번으로 운영 발주·배차·입고·재고·수령을 자동 확정하지 않는다.

## 8. 규칙 영역 사이의 연결

| 앞 영역 | 뒤 영역 | 전달하는 것 | 전달하지 않는 것 |
| --- | --- | --- | --- |
| 생산 → 해석 | 생육·수확 상태, 생산 효과, 출처 | Prefab·색상·카메라 좌표 |
| 운송 → 해석 | Cargo·경로·도착·인계 후보 | 차량 Transform 위치를 기준 사실로 사용하지 않음 |
| 창고 → 해석 | 검수·입고·재고·작업 상태 | Shelf Renderer 상태를 재고로 사용하지 않음 |
| 해석 → 표현 | 허가된 표현 모델·시각 자산 키 | 서버 원장 쓰기 권한 |
| 상호작용 → 업무 | Preview·Confirm Command | Unity가 미리 정한 성공 결과 |
| 업무 → 표현 | 최신 상태 사본 | 애니메이션 완료를 역으로 업무 완료로 사용하지 않음 |

## 9. 감자 흐름의 규칙 영역 배치

```text
생산 규칙
    재배 면적·환경 생육·수확 Lot
        ↓
운송 규칙
    포장·상차·경로 이동·도착 후보
        ↓
창고 규칙
    검수·입고·보관·피킹·출고
        ↓
시장·주문·소비 규칙
    공개 상품·주문 예약·이행·주민 소비

각 단계의 상태
    ↓ 해석 규칙
사용자별 표현 모델
    ↓ 표현 규칙
그래픽·카메라·애니메이션·UI
```

## 10. 코드 적용 기준

자원 효과 묶음에는 업무·Simulation 규칙 영역만 기록한다.

```text
Production
Consumption
Transport
Warehouse
Market
Facility
Time
```

표현 규칙은 별도 Unity 계약과 시각 자산 대장에서 관리한다.

```text
Presentation.Graphics
Presentation.Camera
Presentation.Animation
Presentation.Lighting
Presentation.Audio
Presentation.UI
```

`Presentation.Camera` 같은 표현 규칙 코드는 `Simulation자원효과묶음Snapshot.RuleDomainCode`에 들어갈 수 없다. 표현 규칙이 자원 효과를 만들 필요가 있으면 직접 적용하지 않고 해당 업무 규칙의 Preview·Confirm을 요청해야 한다.

2. `POTATO-PRODUCTION-RULE-1`을 첫 생산 규칙 세로 단면으로 연결한다. — 완료
3. 기존 물류 이동·화물운송을 `Transport` 영역의 독립 효과 규칙으로 연결한다. — 완료
4. Hub 검수·창고 인계·비축 재고를 `Warehouse` 영역의 독립 효과 규칙으로 연결한다. — 완료
5. 기존 Unity 시각 규칙 개정 번호를 그래픽·애니메이션·UI 영역에 분류하고 카메라·조명·오디오 계약을 준비한다. — 완료
6. 각 독립 효과 규칙과 표현 규칙 대장을 기존 session aggregate·Unity 조립부에 연결한다. — 다음 단계

## 12. 표현 규칙 대장 구현 상태

`PRESENTATION-RULE-0`에서는 기존 클래스명과 시각 규칙 개정 번호를 변경하지 않고 다음처럼 분류했다.

| 영역 | 기존 규칙 분류 | 현재 상태 |
| --- | --- | --- |
| 그래픽 | 커뮤니티 광장, 공공데이터 Marker·Surface, 창고, 도심마트 관리자 | 기존 규칙 5개 분류 완료 |
| 카메라 | 배치 객체 초점·거리·구도·전환 계약 | 계약 준비, 실제 카메라 구현 미연결 |
| 애니메이션 | NPC 이동, 운송 Corridor 이동 표현 | 기존 규칙 2개 분류 완료 |
| 조명 | Light·Ambient·Fog·시간대 시각 계약 | 계약 준비, 실제 조명 구현 미연결 |
| 오디오 | 상태 Cue·Volume·Spatial Blend 계약 | 계약 준비, 실제 오디오 구현 미연결 |
| UI | 역할 강조, 개념 카드 | 기존 규칙 2개 분류 완료 |

모든 대장 항목은 `MutatesCanonicalState=false`, `ConfirmsBusinessCompletion=false`를 요구한다. 업무 영역 코드를 표현 대장에 넣거나, 영역에 허용되지 않은 출력 채널을 사용하거나, 표현 규칙이 기준 원장 변경·업무 완료 확정을 선언하면 검증에서 차단한다.

기존 시각 규칙 개정 번호 9개는 그대로 보존했다. 카메라·조명·오디오는 분류 계약만 준비했으며 Unity Scene, Component wiring, Game View로 구현 완료를 주장하지 않는다.

## 13. 통합 전시관의 규칙 실험 모판

`RULE-SEEDBED-0`에서는 생산·소비·운송·창고·표현 규칙을 같은 전시관에서 수평 비교하기 위한 공통 계약을 추가했다. 업무 규칙 실험은 서버 기준 상태 사본을 읽고 예상 효과를 보여준 뒤, 명시적 Simulation 확정과 서버 재조회를 거쳐서만 예상값과 실제값을 대조한다. 표현 규칙 실험은 기준 원장 효과를 만들지 않으며 확정 기능도 갖지 않는다.

현재 구현은 시나리오 대장과 상태 전이·검증 계약까지다. 기존 서버 규칙 변환기, 실제 실험대 Prefab·Scene 배치, Play Mode와 Game View는 아직 연결하지 않았다. 상세 사용 순서와 다섯 실험대 구성은 [Unity 규칙 실험 모판 구현](UnityRuleExperimentSeedbedImplementation.md)을 따른다.
5. Unity의 기존 `VisualRuleRevision`·카메라·애니메이션 규칙을 표현 영역 대장으로 분류한다.
6. 표현 규칙이 서버 자원 Effect를 생성하지 않는 의존성 검증을 추가한다.
