# API 업무 의미 분류

## 목적

Controller를 `0.0`, `1.0`, `2.0` 같은 제품 버전으로 설명하는 대신, 현재 어떤 사용자가 무슨 업무를 수행하는지 한국어로 찾을 수 있게 한다.

제품 버전은 기능의 현재 책임이 아니라 **처음 도입된 시점**을 남기는 이력이다. 기능의 운영 노출 여부는 Feature 경계에서 별도로 판단한다.

## 분류 기준

| 분류 | 답하는 질문 | 예시 |
| --- | --- | --- |
| 업무 영역 | 무슨 일을 위한 기능인가 | 인연 형성, 공동구매 수요·모집, 운송 의뢰, 배차, 창고 이행 |
| 사용자 | 누가 사용하는가 | 커뮤니티 참여자, 주문자, 화주, 기사, 창고 관리자 |
| 업무 동작 | 무엇을 하는가 | 둘러보기, 요청하기, 판단하기, 실행하기, 기록하기, 관리하기 |
| 업무 흐름 | 여러 앱 사이에서 어디로 이어지는가 | 공동구매 수요·모집, 국내 화물 운송, 커뮤니티 신뢰 |
| Feature 경계 | 현재 운영에서 노출되는가 | 국내 운송, 창고 이행 등의 활성화 상태 |
| 도입 이력 | 언제 처음 제품에 들어왔는가 | 0.0, 1.0, 2.0 |

권한과 개인정보 동의는 이 분류로 대신하지 않는다. 실제 접근은 기존 인증·권한 정책이 검사하며 연락처 공개와 실행 동의도 기존 상태 전이를 따른다.

## 01~05 기준

| 앱 | 기본 사용자 | 대표 업무 영역 |
| --- | --- | --- |
| 01 Community | 커뮤니티 참여자 | 정보 둘러보기, 공동 원장, 인연 형성 |
| 02 Orderer | 주문자 | 상품·재료 발견, 공동구매 수요·모집, 주문 참여 |
| 03 Shipper | 화주 | 운송 의뢰, 무역 준비, 결제 |
| 04 Driver | 기사 | 기사 근무, 배차, 운송 실행, 예약, 정산 |
| 05 Warehouse | 창고 관리자 | 입고, 재고 관리, 창고 이행 |

역할별 Controller는 공통 기반에서 사용자를 물려받는다. 업무 영역을 명시한 Controller는 그 값을 사용하고, 아직 전환 중인 Controller는 기존 Workflow를 같은 한국어 업무 영역으로 해석한다.

여기서 `Common`은 별도의 06 앱이나 기술 helper 집합이 아니라 01~05가 같은 의미로 수행하는 공동 업무 경계다. 01 Community의 공개 탐색·참여·공동 원장·인연 형성 API는 `Controllers/Common`에 포함하고, Admin 권한이 필요한 커뮤니티 작성·운영 API는 `Controllers/Admin`에 둔다. version·Feature, push installation, file transport와 외부 callback처럼 실행을 지원하는 기술 API는 `Controllers/Platform`에 둔다. 세부 project 경계는 [커뮤니티 0.0 기반 제품 원칙](CommunityFoundationV0Policy.md#common과-community-코드-경계)을 따른다.

## 전환 원칙

1. 새 Controller는 버전보다 업무 영역·사용자·업무 동작을 먼저 표시한다.
2. 운영 Feature Key는 도입 버전 정보에 넣지 않고 Feature 경계에 둔다.
3. 기존 버전 표시는 제거를 서두르지 않고 도입 이력으로 해석한다.
4. 같은 역할 폴더에 있는 Controller는 역할별 공통 기반을 사용해 중복 표시를 줄인다.
5. 한 Controller가 여러 업무를 실제로 조율할 때만 업무 영역을 여러 개 표시한다.
6. 분류가 권한 검사나 상태 전이 검증을 대신하지 않도록 테스트에서 별도로 확인한다.
7. 여러 앱에서 호출된다는 이유만으로 Common에 넣지 않고, 역할을 넘어 동일한 업무 의미를 공유하는지 확인한다.

## 현재 적용 범위

- 01의 `CommunityTrust` 주요 Controller와 02~05가 함께 쓰는 Common 커뮤니티 진입점
- 02 Orderer 전체 Controller
- 03 Shipper 전체 Controller
- 04 Driver 전체 Controller
- 05의 창고 작업 및 입출고 관점 조회 진입점
- API 목록 조회에서 업무 영역·사용자·업무 동작과 Feature 경계를 별도 필드로 제공

Admin과 나머지 공통 기술 Controller는 실제 운영 책임을 확인한 뒤 플랫폼 운영·공공데이터·인증 같은 업무 영역으로 후속 전환한다.
