# Unity 운영자 전용 재고 Shelf 심층 연구

## 1. 결론

`seedbed-object:city.operator-inventory-shelf.a`는 창고 전체나 상품 한 종류를 대표하는 장식물이 아니다. **운영자가 주소로 찾아갈 수 있는 하나의 적재·피킹 위치**를 표현하는 모판 배치 객체다.

같은 위치에 여러 재고 항목이 있으면 한 Shelf 배치 인스턴스가 함께 요약할 수 있다. 반대로 서버 재고에 `StorageLocation`이 없으면 Unity가 임의 위치를 만들지 않고 배치 대상에서 제외한다. 이때 관련 피킹 작업은 `LocationUnmapped`로 남아 위치 대장 보완을 요구한다.

## 2. 업무 흐름 속 위치

```text
창고 입고·검수·적치 완료
  → 위치가 부여된 실제 재고
  → [운영자 전용 재고 Shelf]
  → 마트 주문의 피킹 작업
  → Tote 또는 Cart 이동
  → 포장 작업대 인계
```

Shelf가 생기기 전에는 상품이 검수되었더라도 아직 주소 지정 가능한 피킹 위치가 없을 수 있다. Shelf 다음에는 서버가 승인한 피킹 작업을 가진 운영자 또는 NPC가 접근점으로 이동하고 상품 피킹점을 사용한다.

## 3. 열 가지 질문에 대한 현재 답

| 질문 | 현재 답 |
| --- | --- |
| 현실에서는 무엇인가 | 상품을 보관하고 운영자가 주소로 찾아가 피킹하는 적재 위치다. |
| 언제 등장하는가 | 재고 항목에 창고와 `StorageLocation`이 확정된 뒤 등장한다. |
| 어떤 데이터를 표현하는가 | 위치 코드, 가용·예약 수량, 품목 이름, 연결 재고 고유 식별자, 진행 중 피킹 작업, 마지막 수정 시각을 표현한다. |
| 무엇을 결정하면 안 되는가 | 재고 증감, 예약, 피킹 시작·완료, 주문 완료를 결정하지 않는다. Unity 애니메이션도 완료 근거가 아니다. |
| 사람이 어떻게 알아보는가 | 멀리서는 위치 표찰, 가까이서는 재고·피킹 상태, 선택 시 품목과 연결 작업 수를 본다. |
| 상태 변화가 외형에 미치는 영향 | 출고 가능, 피킹 대기, 피킹 진행 중, 피킹 후 포장 이동 중, 예약 재고만 있음, 재고 소진을 서로 다른 표찰·강조 상태로 표현할 수 있다. |
| 주변에 무엇이 필요한가 | 통로, 운영자 접근점, 피킹점, Tote 또는 Cart 이동 경로, 포장대 방향 표지가 필요하다. |
| 다른 배치 객체와 어떻게 연결되는가 | `Inventory`, `ShelfTask`, `Operator` 연결 지점으로 재고·작업·운영자 표현을 묶고, 공간 대장의 Rack 접근점·피킹점으로 이동 경로를 잇는다. |
| 사용자가 무엇을 할 수 있는가 | 재고 요약과 연결 피킹 작업을 조회할 수 있다. 현재는 피킹 완료나 재고 변경을 확정할 수 없다. |
| World에 정말 필요한가 | 필요하다. 주문 상품의 서버 재고 위치를 3D 이동과 연결하는 기준점이므로 단순 배경과 구분된다. |

## 4. 서버 사실·해석·Unity 표현 분리

| 계층 | 책임 |
| --- | --- |
| 서버 기준 원장 | 재고 항목, 가용·예약 수량, 적재 위치와 피킹 작업 상태의 최종 사실을 가진다. |
| 관점별 조회 결과 생성기 | 같은 위치의 재고를 Shelf 하나로 묶고 연결 작업에 따라 표현 상태를 정한다. 운영자 권한에 필요한 최소 정보만 보낸다. |
| Unity 표현 계층 | 모판 배치 객체, 표찰, 강조, 접근점과 피킹점으로 상태를 보여준다. 서버 값을 재계산하거나 변경하지 않는다. |

주문 참조번호, 주문자, 작업자 이름, 연락처, 주소와 결제 정보는 Shelf 계약에 포함하지 않는다. 공개 마트 Shop과 달리 `AccessScopeCode`는 `OperatorOnly`다.

## 5. 배치 단위와 고유 식별자

- 배치 단위: 한 창고 안의 주소 지정 가능한 적재·피킹 위치 한 곳
- 모판 배치 객체 고유 식별자: `seedbed-object:city.operator-inventory-shelf.a`
- 상태 인스턴스 고유 식별자: 창고 ID와 정규화한 위치 코드의 SHA-256 값으로 생성
- 연결 가능한 재고: 같은 위치를 가진 한 개 이상 재고 항목
- 배치 금지: 위치가 비어 있거나 다른 창고의 재고인 경우

이 결정으로 한 상품이 여러 위치에 나뉘면 여러 Shelf가 생기고, 한 위치에 여러 상품이 있으면 한 Shelf가 여러 재고 항목을 요약한다.

## 6. 표현 상태 우선순위

1. `PickingInProgress`: 피킹 진행 중
2. `PickingReady`: 피킹 대기
3. `PickCompleted`: 피킹 후 포장대로 이동 중
4. `ReservedOnly`: 가용 수량은 없고 예약 수량만 있음
5. `Depleted`: 가용·예약 수량 모두 없음
6. `Available`: 출고 가능한 재고가 있음

이 코드는 Unity 업무 명령이 아니라 서버 상태를 운영자 관점에서 읽기 쉽게 만든 표현 상태다.

## 7. 거리별 정보 밀도

| 관찰 거리 | 표시 내용 |
| --- | --- |
| 멀리서 | `재고 Shelf A-03-02`처럼 위치를 우선 표시 |
| 가까이서 | `피킹 후 포장 이동 중 · 가용 8 · 예약 2`처럼 현재 상태와 수량 표시 |
| 선택했을 때 | 품목 목록, 연결된 피킹 작업 수와 상세 조회 진입점 표시 |

현재 허용한 행동 코드는 `InspectInventory`, `InspectPickTasks` 두 가지다. `CompletePicking`, `ChangeInventory` 같은 쓰기 행동은 포함하지 않는다.

## 8. 연결 지점과 공간 대장

기존 프로젝트용 Prefab의 연결 지점은 유지한다.

- `Inventory`: 재고 묶음 표현
- `ShelfTask`: 피킹 작업 표찰과 상태
- `Operator`: 운영자 또는 NPC의 상호작용 기준
- `Interaction`: 선택·조회 범위
- `Label`: 위치·상태 표찰
- `CameraFocus`: 가까이 보기 기준

NPC 이동은 Prefab 내부 연결 지점만으로 확정하지 않는다. 서버 위치 코드를 공간 대장에 연결해 `market.rack:{위치}:approach`와 `market.rack:{위치}:pick`을 사용한다.

## 9. 현재 구현과 검증 단계

- 서버 마트 피킹·포장 상태 사본에 위치별 Shelf 목록 추가
- 기존 창고 상태 사본의 실제 가용·예약 수량 사용
- 위치별 재고 항목과 활성 피킹 작업 연결
- Unity 운영 API 변환과 관계 검증 추가
- 읽기 전용 표현 모델과 기존 연결 지점 요구 목록 추가
- 서버 집중 테스트 6/6 통과
- Unity C# EditMode assembly 빌드 통과
- Unity Editor EditMode 집중 테스트 7/7 통과

기존 Prefab과 모판 외형은 바꾸지 않았으므로 상태는 O5 **모판 실행 검증 완료**로 유지한다. 특정 운영자 구역의 배치 기준점, 공간 대장 연결, NPC 실제 이동과 Game View를 확인해 배치 검증 기록을 남겨야 O6 **실제 World 배치 검증 완료**로 승격할 수 있다.

## 10. 다음 최소 조합 모판

```text
Shelf A-03-02
  → Picker NPC
  → Tote
  → 포장 작업대
  → 포장 상자
```

첫 검증에서는 감자 한 품목과 피킹 작업 하나만 사용한다. 이후 쌀·양파와 위치 분할, 여러 상품의 같은 Tote 합류, 냉장·상온 구역 분리를 추가한다.
