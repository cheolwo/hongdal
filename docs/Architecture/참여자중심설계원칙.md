# 참여자 중심 설계 원칙

## 목적
홍달에서 우리는 사용자를 고정 역할로 나누지 않고, 지금 여기 업무 맥락에서 역할을 수행하는 참여자로 본다.

## 핵심 정의
- 참여자: 플랫폼 안에서 거래/운송/입출고/정산/교육/모임에 참여하는 사람
- 역할: 참여자가 현재 수행 중인 업무 맥락
- 역할 전환: 한 참여자가 시점과 상황에 따라 주문자/판매자/기사/창고관리자/운영자 역할을 바꿔 수행하는 것

## 설계 원칙
1. 사람 식별자는 하나(`참여자Id`)로 유지한다.
2. 역할은 다중 부여 가능하며, 활성/비활성 상태를 가진다.
3. Command 실행 시 `참여자Id`와 `실행역할`을 함께 기록한다.
4. 역할은 권한 벽이 아니라 업무 맥락 값으로 다룬다.
5. 핵심 상태 변경은 CommandHandler, 사후처리는 EventHandler로 분리한다.

## IdentityRole과 참여자역할 경계
- IdentityRole은 인증/접근 제어(보안) 목적으로 사용한다.
- 참여자역할은 도메인 실행 맥락(업무 역할) 목적으로 사용한다.
- 컨트롤러 진입은 `[Authorize]` 정책으로 통제한다.
- CommandHandler 내부에서는 `참여자Id + 실행역할`을 별도 권한검사로 검증한다.
- 동일 의미의 역할명을 두 계층에서 직접 1:1 비교하지 않고, 명시적 매핑 규칙으로 연결한다.

## 창고 관점
- 창고는 특정 도메인 전용 객체가 아니라 참여자의 물류 거점이다.
- 참여자는 가상창고/실제창고/차량창고/임시보관소를 상황별로 가질 수 있다.

## 점진 적용 원칙
1. 기존 `ApplicationUser`/프로필 모델과 공존한다.
2. 신규 흐름은 참여자 컨텍스트를 우선 적용한다.
3. 기존 흐름은 어댑터/매핑으로 단계 전환한다.
4. 데이터 마이그레이션은 기능 안정화 이후 진행한다.

## 문화 원칙
홍달은 고정된 갑을 구조가 아니라, 서로 역할이 바뀔 수 있는 참여자들의 물류 네트워크를 지향한다.
