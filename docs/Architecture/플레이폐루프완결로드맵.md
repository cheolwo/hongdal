# 플레이 폐루프 완결 로드맵

## 목적

이 문서는 현재 흩어진 게임 기획·WI·Simulation·공간·Unity 작업을 **플레이어가 시작해서 결과를 얻고 다시 선택 가능한 상태로 돌아오는 단위**로 닫기 위한 실행 순서를 정의한다.

완결 순서는 다음과 같다.

```text
Nature → Farm → Hub → Town → City
     각 영역 Core E5 완결
              ↓
     E6 설명·체감 정제
              ↓
     E7 실제 입력·화면·귀환
              ↓
     Solo 하루 세계 집계
              ↓
     선택적 영역 간 통합
```

이 순서는 영역 사이의 업무 의존 관계가 아니다. 현재 구현 준비도에 따른 작업 순서이며 Farm·Hub·City는 서로의 결과 없이 실행되는 독립 Fixture와 내부 반환 상태를 먼저 가져야 한다.

## 완결 단위

### 세 수준

| 수준 | 의미 | 예 |
| --- | --- | --- |
| `PlayableUnit` | 한 가지 플레이 약속을 성공·실패·회복·귀환까지 닫는 최소 단위 | Nature 황혼 대응, Farm 경작·수확 |
| `AreaAggregate` | 영역의 필수 Core 단위를 모아 파생 판정하는 집계 | Nature 생존 생활거점, Town 주민 생활복구 |
| `WorldAggregate` | 독립 영역의 결과를 하루 또는 선택적 이동으로 조립하는 집계 | Solo 하루, Nature↔Farm 왕복 |

`PlayableUnit`만 영역 집계 하나를 부모로 가진다. `WorldAggregate`는 AreaAggregate를 소유하지 않고 준비 의존으로 참조하므로, 같은 독립 영역이 Solo 하루와 선택적 왕복 양쪽에 참여할 수 있다.

### 핵심과 확장

| 등급 | 의미 | 영역 집계 영향 |
| --- | --- | --- |
| `Core` | 영역의 최소 플레이 약속에 반드시 필요한 단위 | 하나라도 열려 있으면 영역 Core는 열림 |
| `Extension` | 건물 발전·타로·사용자 배치처럼 선택 가능한 확장 | 열려 있어도 영역 Core를 막지 않음 |
| `Aggregate` | 자식 상태에서 파생되는 집계 | 직접 완료 선언 금지 |

건물이나 타로를 구현했다는 사실로 Nature 또는 Town 전체를 완료 처리하지 않는다. 반대로 선택형 확장이 미완료라는 이유만으로 핵심 생존·생활 폐루프를 영구 차단하지 않는다.

## 완결 상태

| 상태 | 판정 기준 |
| --- | --- |
| `Open` | 다음 반환 또는 필요한 E 증거가 남아 있음 |
| `CoreClosed` | Core 단위가 E5에서 발생→권위 전이→Task/Effect→결과→귀환까지 결정적으로 발현됨 |
| `ExtendedClosed` | Extension 단위가 E5에서 같은 기준으로 발현됨 |
| `PlayClosed` | E7에서 실제 입력·화면·실패/회복·귀환이 확인됨 |
| `WorldClosed` | E8을 통과한 둘 이상의 Core가 E9 영역 조화·사람 승인을 통과한 집계 |

영역 `CoreClosed`는 모든 필수 Core 자식이 `CoreClosed` 이상일 때만 파생된다. `ExtendedClosed` 영역은 필수 Core와 등록된 선택 확장이 모두 닫혔을 때 사용할 수 있다. `PlayClosed`는 필수 Core 자식이 모두 E7 `PlayClosed`일 때만 사용한다.

## 영역별 폐루프

### Nature

```text
Nature 생존 생활거점 영역 집계
├─ Core: 도끼·벌목·오두막 기초
├─ Core: 황혼 위협 대응·귀환
├─ Core: 보관·수면·Day2 반환
├─ Core: 작업대 기반
├─ Core: 현장 성과·거점 제작·다음 원정 왕복
├─ Extension: 거점 성찰·다음 원정 준비
├─ Extension: 건물 발전·NPC 배움
└─ Extension: 지역 위협 후퇴·복원·회복
```

- 도끼·벌목·오두막 기초: `WI-NATURE-05~10`, `WI-NATURE-12`
- 황혼 대응: `WI-NATURE-01~04`, `WI-NATURE-11`
- 밤·Day2: `WI-NATURE-13~15`
- 현장 보급·왕복: `WI-NATURE-16~17`과 기존 원정·귀환 WI
- 거점 성찰: `WI-REFLECT-01`, [개별 설계](PlayableLoops/nature-base-reflection.v1.md)
- 건물·배움: `WI-CON-01`, `WI-NATURE-12`

현재 단계·차단·다음 WI는 이 문서에 복제하지 않고 `eng/execution-ledgers/playable-loops.json`을 단일 기준으로 삼는다. 거점 성찰·건물 배움·지역 위협 회복은 각각 E7까지 닫는 독립 Extension이다. 각 PlayableUnit의 반복 안정은 E8, 둘 이상의 안정 Core와 관련 NPC 연속성의 영역 조화·사람 승인은 E9에서 별도로 판정한다.

### Town

```text
Town 주민 생활복구 영역 집계
├─ Core: 욕구→주문→경쟁→수령→소비→다음 욕구
└─ Extension: 메이저 아르카나 활성화·방향 영향
```

- 핵심 주문·소비: `WI-ORDER-01~07`
- 타로 확장: `WI-CARD-01`

`WI-CARD-01`은 기존 `WI-WORLD-06 역할 카드 장착`과 다른 메이저 아르카나 전용 WI다. 카드 방향은 카드 속성이 아니라 활성화 인스턴스의 판정 사본이며, 타로가 없어도 핵심 주문·소비 폐루프는 Neutral 문맥으로 실행돼야 한다.

변동 단계와 차단은 이 문서에 복제하지 않는다. Town의 다음 E5 기준선은 타로 배율을 끈 상태에서도 주민 두 명의 물품 경쟁, 실패자의 대체 선택, 소비 결과와 다음 목표가 결정적으로 닫히는 것이다.

### Farm

```text
Farm 독립 생산·보관 영역 집계
├─ Core: 경작·성장·수확 Lot
├─ Core: 집하·포장·내부 보관·재생산 반환
└─ Extension: 플레이어 조정형 배치
```

- 생산: `WI-FARM-01~04`
- 집하·포장: `WI-FARM-05~06`
- 배치 확장: `WI-CON-01`, `WI-WORLD-03`

`WI-FARM-07~09`는 지역 발전 작업을 위해 예약되어 있으므로 내부 보관 반환에 재사용하지 않는다. 우선 `WI-FARM-06` 완료 뒤 내부 보관·다음 생산 선택의 상태 계약을 확정하고, 별도 WI가 정말 필요한지는 그 계약을 구현하면서 판단한다.

### Hub

```text
Hub 독립 창고 영역 집계
├─ Core: 독립 입고 Fixture→검수→적치→작업 선택
└─ Core: 재고 할당→피킹→출고 준비→작업 선택
```

- 입고·적치: `WI-001`, `WI-002`
- 출고 준비: `WI-HUB-03~05`
- 외부 연결: `WI-HUB-06 차량 적재`

Hub Core는 차량 적재 직전 `OutboundReady`에서 닫는다. `WI-HUB-06`은 Farm·운송·외부 차량과 연결하는 선택적 통합 경계이며 독립 Hub 시작 조건이나 Core 완료 조건으로 쓰지 않는다.

### City

```text
City 독립 도심 서비스 영역 집계
└─ Core: 수요 확정→지역 재고 배정→서비스→결과 확인→다음 선택
```

- `WI-CITY-01`: 도심 수요 확정
- `WI-CITY-02`: 지역 재고 배정
- `WI-CITY-03`: 서비스 처리 또는 부족 복구
- `WI-CITY-04`: 결과 확인과 다음 운영 선택

기존 도심마트 수요·공급 엔진과 Fixture는 재사용 후보지만 아직 권위 폐루프는 아니다. City WI는 현재 E1 계약이며, 별도 City 명령 Aggregate와 Save/Replay를 E2/E3로 구현한 뒤 E4·E5로 올린다. 기존 CityHub 결합 식별자는 호환용으로만 남기고 새 City 완료 판정은 Hub와 분리한다.

## Solo 하루와 영역 간 연결

`playable-loop:solo-world-day.v1`은 다섯 영역 CoreClosed 뒤 조립한다. 한 날에 모든 영역을 강제 완주한다는 뜻이 아니라, 서버 없는 `LocalProcess`에서 영역 선택·권위 진행·저장·복원·다음 선택이 같은 Simulation Core로 이어지는 상위 반환 계약이다.

`playable-loop:nature-farm-roundtrip.v1`은 Nature와 Farm의 독립 E7 `PlayClosed` 뒤에만 재개한다. Farm→Hub, Hub→City, Farm→Hub→City도 같은 원칙으로 별도 통합 폐루프로 등록하며 독립 영역의 선행 조건으로 두지 않는다.

## E5 우선 구현 순서

1. Nature 도끼·벌목·오두막 성공·취소·재선택 Fixture를 닫는다.
2. Nature 보관·수면·새벽 계획·Day2Ready 반환 Fixture를 닫는다.
3. Nature 영역 집계의 모든 Core 자식이 닫혔는지 자동 파생 판정한다.
4. Farm 생산과 포장·내부 보관을 별도 Core로 닫는다.
5. Hub 독립 입고와 출고 준비를 차량 적재 없이 닫는다.
6. Town 주문·소비·다음 욕구를 타로 없이 먼저 닫는다.
7. City 권위 명령 Aggregate·Save/Replay를 만든 뒤 독립 서비스를 닫는다.
8. 모든 Core Goal 뒤 Nature·Farm·Town의 Extension Goal을 순서대로 닫는다.
9. 다섯 영역 CoreClosed 뒤 Solo 하루 집계를 조립한다.

각 단위는 최소한 다음 증거를 요구한다.

```text
독립 결정적 Fixture
+ Preview 무변경
+ Confirm 멱등성·ExpectedRevision
+ 성공 결과
+ 실패·취소·부족 복구
+ 다시 선택 가능한 반환 상태
+ Save/Replay canonical hash
+ 외부 Provider 호출 0
```

## E6와 E7

E5 CoreClosed 뒤에는 기능 수를 늘리기 전에 E6와 E7을 같은 단위로 이어 간다.

- E6: 플레이어가 원인·대가·결과·회복을 이해할 수 있는지 정제한다. 현실 자료가 없으면 `NotApplied`를 명시한다.
- E7: canonical `SimulationWorldShell`에서 실제 입력, 실패·취소, 저장·복원, 귀환, Game View와 Console을 검증한다.
- Solo는 `LocalProcess`, Hosted는 `RemoteHost`에서 같은 Core·명령열·WorldRevision별 canonical hash를 사용한다.

코드·자동시험 E5를 Play Mode나 Game View로 표현하지 않고, 과거 PlayMode 증거가 규칙·Adapter·Scene 변경으로 무효화되면 `Stale`로 유지한 뒤 다시 검증한다.

## 기계 장부와 변경 절차

- [`playable-loops.json`](../../eng/execution-ledgers/playable-loops.json): 계층·Core/Extension·완결 상태의 권위 대장
- [`evidence-packages.json`](../../eng/execution-ledgers/evidence-packages.json): 범위·제외·revision·무효화 조건을 가진 증거 묶음
- [`manage-development-system.ps1`](../../eng/execution-ledgers/manage-development-system.ps1): 부모·자식·E 단계·거짓 완결·증거 참조 검사
- [`07_CURRENT_COMPLETION_LEDGER.md`](../AI/authority-maps/07_CURRENT_COMPLETION_LEDGER.md): 자동 생성 현재 상태

새 기능을 추가할 때는 먼저 기존 Core/Extension 자식 중 어디에 속하는지 결정한다. 기존 플레이 약속과 다른 시작·결과·귀환을 가진 경우에만 새 PlayableUnit을 만들고, UI·Prefab·문서가 추가됐다는 이유로 새 폐루프를 만들지 않는다.
