# 지도구성과 세계자산배치 분리

## 목적

기존 LH 셀 공급 안에 섞인 지도 골격과 객체 배치 책임을 분리한다. 지도구성은 지면·셀·통로·H 결속·배치 Anchor를 만들고, 실외자산배치와 실내공간조립은 각각 건물 밖과 안의 계획을 만든다. LH는 지면과 셀만 준비하며 자산 Prefab 생성·배치·해제를 소유하지 않는다.

```text
Simulation 권위 상태
  -> 공간변화 Projection
  -> 지도구성Engine
  -> LH 지면·셀 준비
  -> Sky 대기 표현 적용
  -> 실외자산배치Engine + 실내공간조립Engine
  -> World공간표현조립Coordinator
  -> Unity VisualKey 표현·셀 활성
```

이 순서는 Unity 조립 순서다. Simulation의 세계 대기 상태 계산은 LH에 의존하지 않으며, Coordinator가 동일 revision의 이미 계산된 상태 사본을 지면 준비 뒤 적용한다.

## 배치 고도화 우선순위 — D-363 (2026-08-30)

사용자는 LH 자체의 확장보다 **배치 엔진 고도화**를 먼저 진행하고, LH는 그 결과가 필요한 곳에서 원활히 나타나도록 지원하는 방향을 선택했다. 이는 개발 우선순위와 책임 구분이며 위의 실행 순서를 뒤집는 결정은 아니다.

| 책임 | 우선 다룰 내용 | 넘겨받은 결과를 임의로 바꾸지 않는 경계 |
| --- | --- | --- |
| 지도구성 | 지형·하천·길·H 공간과 배치 기준점 제공 | 배치 장식 때문에 생산 면적·지형 권위를 변경하지 않음 |
| 실외·실내 배치 엔진 | 자산의 실제 크기, 점유·통행·작업 접근, 군집·여백·가림과 기능별 조립을 반영한 재사용 가능한 계획 | 자산 모양만으로 재고·작물·NPC·조명 기능을 확정하지 않음 |
| LH | 계획에 필요한 셀의 선행 준비·활성·캐시·해제 및 재진입 지원 | 승인된 배치 구도를 다시 설계하거나 셀 로드로 세계 상태를 초기화하지 않음 |
| Unity 조립·표현 | 배치 계획과 같은 상태 사본을 소비하여 객체·Renderer·Collider·조명·LOD 등을 실제 화면으로 연결 | 실제 렌더링 책임을 LH의 계획·수명 관리와 혼동하지 않음 |

현재 첫 적용은 기존 Farm 부지 확대 및 LS-01 승인 범위를 유지한 A/B 후보 준비다. 실외 배치의 크기·통행·하천·작업 공간 보존과 경관 구성을 먼저 확인하고, 검증된 규칙을 재사용한다. 실내 책임도 유지하지만 이번 결정만으로 실내 추가 제작을 승인하지 않는다.

LH는 전면 개편하지 않는다. 배치 소비를 막는 오류, 실제 능력과 준비 표시의 차이, 경계 통과·재진입의 중복/누락은 필요한 기술 연결로 계속 검증한다. 높은 시점의 원경 표현이나 새 거리·성능 수치는 별도 확인 사항이며 자동 확정하지 않는다.

기존 연구·기획의 동결 판본/hash, 후보 승인·실제 조립·Game View의 구분을 보존한다. 새 알고리즘·계약 변경이 필요하면 개발이 영향과 작업 명세를 결속하며 이 우선순위 결정을 새 Scene·Save 변경이나 E 승격 근거로 사용하지 않는다. 관련 정적 조사: [LH 현행 연결과 경관 공백](../Reports/LH공간실행-현행결속과경관공백조사-2026-08-30.md).

## 하나의 공간 실행 파이프라인 — D-364 (2026-08-30)

사용자는 Simulation·배치·LH를 하나의 파이프라인에서 조율하고 실행·해제를 통합 관리하는 방향을 선택했다. **외부 진입과 진행 상태는 통합하고, 내부 책임과 권위는 분리한다.** D-363 배치 고도화 우선순위와 기존 조립 순서는 유지한다.

- Simulation은 권위 상태·시간·WI 결과를 소유한다. 파이프라인은 검증된 상태 사본을 읽거나 기존 권위 명령 경계를 호출하며 독자적인 세계 원장을 만들지 않는다.
- 지도·실외/실내 배치는 해당 상태와 지형에 맞는 계획을 제공한다. 계획 작성/검증과 실제 Unity 객체 조립을 분리한다.
- LH는 필요한 셀과 관심 범위를 준비·유지·캐시·해제한다. Unity 조립·표현은 그 범위의 계획과 상태 사본을 소비한다.
- 통합 조율은 요청 세대, 공간 식별자, 권위 개정, 계획 판본/hash를 연결해 준비·적용·실패·해제·재진입을 추적한다. 구체 계약은 기존 필드와 조율 객체를 우선 재사용한다.

통합 관리에서 관찰할 흐름은 다음과 같다. 이는 새 enum/API의 확정이 아니라 구현 수용 방향이다.

| 상황 | 파이프라인이 조율할 일 | 보존할 경계 |
| --- | --- | --- |
| 지역 접근·관심 등록 | 상태 사본/계획 확인, 필요한 셀 준비, Sky·실외·실내 표현 적용 | 기존 조립 순서 유지. 준비와 실제 통행·상호작용 성공을 구분 |
| WI 결과·계획 변경 | 해당 개정의 필요한 변경만 반영 | 배치 재계산이나 재조회가 명령·비용·행위 기록을 중복 생성하지 않음 |
| 지역 이탈 | 다른 플레이어/NPC/관심 요청의 필요 여부 확인 후 표현 캐시·해제 | 한 카메라의 이탈만으로 공유 관심 공간 전체를 해제하지 않음 |
| 늦은 응답·취소·실패 | 낡은 요청의 적용 차단, 자신이 소유한 미완성 표현/자원 정리, 단계별 실패 기록 | 표현 실패를 이유로 성공한 Simulation 명령을 되돌리지 않음 |
| 재방문 | 보존된 계획 식별자와 최신 권위 상태로 표현 재구성 | 작물·재고·NPC 업무 상태를 초기화하거나 새 발생 원인을 만들지 않음 |
| 세션 종료 | 기존 세션 저장·종료 경계와 표현 자원 정리 순서를 조율 | 셀 해제와 세션 종료를 같은 동작으로 취급하지 않음 |

공간 해제는 렌더링·충돌 등 표현 자원의 수명 관리다. 화면 밖의 작물 성장·NPC 업무는 기존 Simulation 시간/진행 규칙을 따르며, 이를 위해 모든 셀에서 프레임별 연산을 계속해야 한다는 의미도 아니다. 게임이 실행되지 않는 동안의 진행 규칙을 새로 승인하지 않는다.

기술 적용은 기존 `World공간표현조립Coordinator`, LH 실행 경로, 계획/표현 정합 처리와 권위 명령 경계의 호출 관계부터 대조한다. 기존 Coordinator에 Simulation 권위 코드를 흡수하거나, 새 최상위 관리자를 무조건 추가하지 않는다. 중복 조율 책임만 좁게 정리하고 구체 코드 소유는 개발이 작업 명세에 결속한다.

첫 적용은 진행 중인 Farm/LS-01 배치 소비 검증과 연결한다. 원A·승인 원문/hash·연구 기준선을 보존하고 후보·결속 검증·지면/통행·실제 조립·Game View 증거를 나눈다. 이 결정은 통합 운영 방향이며 신규 Save 규칙·게임 효과·Scene 적용·후보 시각 승인·E 승격을 자동 허용하지 않는다. 기존 승인 코드 작업을 새 이름/문서 대기로 중단하지 않는다.

## 권위 경계

- 채집 가능한 자원, 적대 개체와 WI 대상은 Simulation Core가 WorldTick에서 확정하고 Save/Replay한다.
- 그루터기·공사 자재·보관 소품처럼 권위 상태에서 파생되는 배치는 계획 hash를 갖지만 별도 게임 효과를 만들지 않는다.
- 풀·야생화·작은 돌 같은 주변 표현은 `PresentationOnly`이며 Unity나 LH가 재고·확률·개체 수 권위를 만들지 않는다.
- 확률은 정수 가중치로 표현하고 `WorldSeed + CellStableId + SpawnEpoch + RuleRevision + CandidateStableId + ProjectionHash`에서 결정적으로 판정한다.
- Spawn Epoch는 WorldTick·주기 경계·관련 권위 개정에서만 바뀌며 셀 재진입이나 Save Load는 새 발생 원인이 아니다.
- Sky·지면 상태는 첫 판본에서 `ExteriorEnvironmentPresentation`만 바꾼다. 비가 와도 나무·건물의 Stable ID와 기본 위치, 채집량, 이동 비용과 Spawn 결과는 바뀌지 않는다.

## 실내 결속

기존 `I실내공간조립Engine`의 v1·v2 고정 계획을 별도 실내 실행 경계가 소비한다. 기본 Fixture 계획과 변화 기반 LooseItem Overlay는 서로 다른 hash를 가진다. 보관량이나 안전 상태가 바뀌어도 침대·싱크대·선반이 자동 이동하지 않는다. 날씨는 실내 조명·창문 노출·강수 차폐만 바꾸며 실내 계획 hash에 들어가지 않는다. 증축·개조는 별도 WI와 새 Definition revision을 요구한다.

## 첫 Nature 결속

- `Standing`, `Stump`, 지면 통나무와 조우는 기존 Nature 권위 상태를 그대로 투영한다.
- 소음은 적대 흔적 가중치를 올리고 오두막 안전 반경은 적대 후보를 억제한다.
- 벌목 압력은 온전한 수목 주변 표현을 낮추고 그루터기·가지·개방 초지 후보를 높인다.
- 오두막 보관량은 빈 상태·부분 적재·가득 찬 소품 Overlay로 표현한다.
- 작업대 건설 중과 운영 가능 상태는 서로 다른 외부 공구·자재 소품을 사용한다.

## 호환

새 배치 상태를 사용하지 않는 세션은 기존 `lh-world.v1`, Interior v1·v2와 `simulation-save.v25` 이하 canonical hash를 유지한다. 새 상태가 있는 세션만 `simulation-save.v26`을 사용한다. 최신 규칙이나 Catalog로 기존 저장 세계를 자동 재생성하지 않는다.

v26은 세션이 원래 선택했을 기반 저장 스키마를 `WorldAssetPlacementBaseSchemaVersion`으로 함께 봉인한다. 기존 스키마 replay hash와 `WorldAssetPlacement.StateHashSha256`를 합성하므로 대기 상태가 없는 세션을 v25로 오인하지 않고 v1~v25 hash 계산도 바꾸지 않는다.

## 현재 구현 상태

- `SimulationScenario지도구성Engine`: H 결속·연결구·고정 Anchor만 생성한다.
- `Simulation결정적세계자산배치Engine`: 기존 LH 절차 배치 호환 모드와 Nature 변화 기반 모드를 제공한다.
- `Simulation분리세계자산배치Coordinator`: 기존 v26 통합 계획을 한 번 계산한 뒤 `Simulation실외자산배치Plan`과 `Simulation실내자산배치Plan`으로 파생하고 통합 계획은 Save/Replay 호환 Facade로 보존한다.
- `Simulation결정적실외환경표현Engine`: 실외 Stable ID·위치를 유지하면서 Sky·지면 상태에 따른 건조·젖음·적설·바람 표현 hash만 만든다.
- `SimulationNature공간변화ProjectionBuilder`: 자원 Node·지면 통나무·오두막·보관·소음·방어·건물 발전·조우를 revision이 있는 변화 사실로 투영한다.
- `NatureCabinInteriorGrammar`: 휴식·보관·작업 Zone의 고정 기본 실내를 생성하고, 보관량은 별도 LooseItem Overlay로만 반영한다.
- `SimulationSeparatedLhCellContentSource`: 기존 `lh-world.v1` 셀 내용과 base/presentation hash를 보존한 채 분리 엔진을 기본 LH 공급 경로에 연결한다.
- `SimulationNatureWorldCellAssemblyEngine`: 공통 Simulation Application에서 LH 셀 하나와 Nature 권위 상태를 같은 `WorldRevision`의 `WorldAssetAssembly`로 조립한다. LocalProcess와 RemoteHost는 이 엔진을 각각 로컬 Repository와 HTTP Controller 경계에서 호출하며 Unity가 같은 규칙을 다시 구현하지 않는다.
- Unity `공간LHStreamingEngine`은 지면 Mesh·Collider와 셀 능력만 준비하고 `World공간표현조립Coordinator`에 인계한다. `실외자산배치Runtime`과 `실내자산배치Runtime`이 자산 생성·캐시·해제를 각각 소유한다.
- Unity 로컬 경로의 `Nature세계자산배치LHRepository`는 Nature 표현 원점이 속한 L3 셀과 셀 내부 offset을 계산해 공통 조립 엔진에 전달한다. 권위 좌표의 원점은 Controller GameObject가 아니라 기존 Nature `visualRoot`다.
- `World공간표현조립Coordinator`는 배치 고유 식별자로 실외 객체를 멱등 조정하고, 표면 높이에 보이는 하단을 정렬하며, 오두막 아래에 고정 실내 본문과 변화 Overlay를 별도 Root로 만든다. 선택형 주변 표현 실패는 셀 통행을 막지 않고 같은 경고를 반복하지 않는다.
- `simulation-save.v26`: 배치 상태를 로컬 Save 요청으로 전달하고 봉인·복원한다.

## 2026-08-27 검증 결과

- Simulation 집중 시험은 공통 조립의 결정성·고유 식별자·표면 hash·실외/실내 분리와 RemoteHost HTTP 응답 계약을 포함해 `21/21` 통과했다.
- Unity 생성 프로젝트 `Ssalddel.Unity.Bootstrap.csproj`와 `Ssalddel.Unity.Tests.EditMode.csproj`는 각각 오류 `0`으로 빌드됐다. 이는 실제 Unity Test Runner 실행 결과는 아니다.
