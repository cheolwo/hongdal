# Q-001~Q-130 개발 뼈대 인계

## 목적

Q-001~Q-130 문답은 하나의 거대한 기능 명세가 아니다. 질문은 플레이어 경험을 정밀화하는 자료이며, 실제 개발은 주제별 승인 기획서와 활성 PlayableLoop Goal을 통해 한 WI씩 진행한다.

이 문서는 지금까지 확인된 내용을 기존 코드에 연결할 때 무엇을 공통 뼈대로 먼저 쓰고, 무엇을 아직 실행 규칙으로 승격하지 않는지 정리한다.

## 이번 공통 작업 참여 뼈대

`work-participation-policy.r1`은 다음 세 기존 구조를 대체하지 않고 같은 의미로 연결한다.

```text
Farm 작업 Preview·Task
NPC 작업 배정·이력
협동 건설 기여 원장
          │
          ▼
비실행 작업 참여 정책
├─ 기본 규모는 SoloFriendly
├─ 면적·난도 증가는 CollaborationHelpful
├─ 현재 도구로 물리적으로 불가능할 때만 PhysicallyBlocked
├─ 가벼운 도움은 기본 자동 허용, 사용자가 해제 가능
├─ 중요한 세계 변경은 Confirm 또는 사전 위임 필요
├─ 가벼운 도움은 호혜 기여 원장
└─ 전문 노동은 사전 보수 합의
```

이 정책은 `MetadataOnly`다. 자체 Preview·Confirm·Task·Effect를 만들지 않고 WorldRevision을 변경하지 않는다. 실제 Farm WI나 NPC 방문이 이 정책을 소비하는 작업은 해당 PlayableLoop가 활성화된 뒤 수행한다.

## 현재 구현한 코드 경계

- 계약: `Simulation작업참여PolicyContracts.cs`
- 결정적 판정기: `Simulation작업참여PolicyCatalog.cs`
- 집중 시험: `SimulationWorkParticipationPolicyTests.cs`
- 재사용 대상으로 명시한 기존 상태:
  - `SimulationFarmWorkPreviewSnapshot`
  - `SimulationNpcTaskAssignmentSnapshot`
  - `SimulationNpcWorkRecordSnapshot`
  - `SimulationCoopContributionSnapshot`

현재 판정기는 면적·현장 난도·도구 가능성을 받아 Solo 가능 여부와 협력 권장·부담·차단 사유를 반환한다. 구체 면적 임계값, NPC 관계 수치, 호혜 감쇠, 보수 금액은 추정하지 않는다.

## 증거와 제외 범위

- 이 뼈대는 공통 계약 E1, 순수 판정 E2, 자동시험 E3 수준의 코드 근거다.
- 활성 `playable-loop:nature-basic-herbal-recovery.v1`의 Goal·WI·E를 변경하지 않는다.
- Farm 폐루프 E3 달성이나 실제 NPC 방문·도움 구현을 의미하지 않는다.
- Save revision, LocalProcess/RemoteHost Adapter, Unity Scene, Synty 배치, Play Mode, Game View를 변경하거나 검증하지 않는다.
- 이후 실제 실행 결속은 `농지 조사 Preview → 참여 계획 → Confirm → Task → 진척/기여 기록 → 귀환`을 한 WI씩 승인해 진행한다.
