# Simulation 생산·소비 공통 규칙 제안

## 1. 제안 목적

이 문서는 [프로젝트 규칙 계층·영역 분류](ProjectRuleDomainClassification.md) 가운데 업무·Simulation 규칙의 공통 자원 변동만 다룬다. 그래픽·카메라·애니메이션 같은 표현 규칙은 자원 효과 계약에 포함하지 않는다.

농장 확장, 관수, 비료, 온실, 수확, 포장, 운송, 보관, 판매와 주민 소비는 모두 어떤 자원을 늘리고 다른 자원을 줄인다. 그러나 모든 변화를 단순한 `플러스`와 `마이너스` 한 숫자로 합치면 다음 차이를 잃는다.

- 감자 100kg 생산과 창고에서 마트로 감자 100kg 이동
- 시장재고 20kg 차감과 주민 소비 누계 20kg 증가
- 노동 5 예약과 노동 5 실제 소모
- 창고 용량 100kg 증가와 창고재고 100kg 증가
- 수확물 100kg을 상자 5개로 포장하는 변환과 부패로 5kg가 사라지는 손실

따라서 프로젝트 공통 규칙은 부호만 기록하지 않고 **무슨 자원이 왜, 어느 원장에서, 어떤 유형으로 변했는지** 기록해야 한다.

이 문서에서 프로젝트는 농장 확장, 시설 건설, 생산 작업, 운송, 판매, 보관, 공동행동처럼 사용자가 선택하거나 WorldTick이 진행하는 Simulation 업무를 뜻한다.

## 2. 현재 구현에서 재사용할 기반

현재 `SimulationDecisionWorkContracts`에는 다음 기반이 이미 있다.

```text
Decision
    무엇을 하기로 확인했는가

Task
    어떤 시설과 용량으로 몇 Tick 동안 수행하는가

Effect
    어느 원장의 값이 실제로 얼마나 바뀌었는가
```

`SimulationValueProjection`과 `SimulationEffectRecord`는 `BeforeValue`, `Delta`, `AfterValue`, `UnitCode`, `TargetLedgerStableId`, 원인 Decision·Task와 출처를 보존한다. 정착지 경제에는 현금, 노동, 저장 용량, 상품별 시장 공급, 비축 Lot, 주민 소비 누계와 예약량이 분리돼 있다.

이 제안은 이 계약을 폐기하지 않는다. 기존 `Delta`에 **자원 변동 유형, 자원 종류, Lot 계보, 규칙 개정 번호와 묶음 단위**를 더해 의미를 분명하게 만드는 확장안이다.

## 3. 핵심 원칙

### 3.1 한 프로젝트는 하나의 점수가 아니라 효과 묶음이다

온실 건설을 `+20`으로 표현하지 않는다.

```text
온실 건설 프로젝트
    현금          - 50,000 Simulation KRW
    노동 가용량   - 8 예약
    건설 자재     - 20단위
    재배 가능 면적 + 100m²
    유지보수 수요 + 1/Turn
```

각 효과는 서로 다른 단위와 원장을 유지한다. 사용자는 생산성 증가와 비용·노동·유지 위험을 함께 보고 판단한다.

### 3.2 플러스와 마이너스는 결과이고 업무 의미는 별도다

`Delta > 0`이라고 모두 생산은 아니다. 예약 해제, 외부 유입, 반품, 복구와 용량 증가도 양수다. `Delta < 0`도 소비뿐 아니라 이동 반출, 예약, 변환 입력과 손실일 수 있다.

### 3.3 예상과 실제 적용을 분리한다

```text
규칙 평가
    → 예상 효과
    → 명시적 Confirm
    → Task 예약·진행
    → 완료 WorldTick
    → 실제 Effect 적용
    → 상태 사본 재조회
```

예상 효과는 설명과 선택을 위한 관점별 조회 결과다. 실제 자원 변화는 완료 WorldTick에서 검증된 효과 기록이 적용될 때만 성립한다.

### 3.4 Simulation과 실운영 규칙을 구분한다

Simulation Fixture의 생산량·소비량·비용·기간은 운영 농업 처방, 실제 재고 차감, 결제 또는 계약이 아니다. 규칙은 실행 모드, 출처, 개정 번호와 한계를 보존한다.

## 4. 공통 자원 변동 유형

| 유형 | 원장 변화 | 의미 | 예시 |
| --- | --- | --- | --- |
| 생산 | 대상 재고 증가 | 업무 결과로 새 자원이 생김 | 수확 완료로 감자 수확 Lot 생성 |
| 소비 | 가용 자원 감소, 소비 원장 증가 가능 | 목적을 위해 자원을 사용함 | 주민이 수령한 감자를 소비 |
| 예약 | 전체량 유지, 가용량 감소·예약량 증가 | 후속 작업을 위해 자원을 잠금 | 주문 20kg, 노동 5, 저장 용량 100kg 예약 |
| 예약 해제 | 전체량 유지, 예약량 감소·가용량 증가 | 취소·실패·완료 뒤 잠금을 풂 | 실패한 수출 준비 수량 반환 |
| 이동 | 원천 감소와 대상 증가를 한 묶음으로 기록 | 같은 자원의 위치·책임 원장이 바뀜 | 창고 Pallet을 마트로 이동 |
| 변환 | 입력 감소와 출력 증가를 변환 비율로 묶음 | 형태·단위·품목 상태가 바뀜 | 수확 Lot을 포장 Lot으로 변환 |
| 손실 | 자원 감소와 손실 원장 증가 | 부패·파손·감모처럼 회수되지 않음 | 보관 중 감자 5kg 감모 |
| 복구 | 손실 또는 차단 상태 일부를 회복 | 재작업·수리로 사용 가능량이 돌아옴 | 재검수 뒤 격리 물량 일부 복구 |
| 유입·유출 | 현재 시스템 경계 밖과의 교환 | 내부 생산·소비와 구분되는 외부 출입 | Simulation 외부 교역 도착·반출 |
| 용량 증감 | 재고가 아니라 수용 한계가 바뀜 | 시설·토지·노동의 가능한 최대치 변화 | 밭 면적·창고 용량·차량 적재 한도 증가 |

`생산`, `소비`, `이동`, `변환`, `손실`은 서로 대체할 수 없다. 같은 `-20kg`이라도 소비, 출고 이동과 부패 손실은 이후 계산과 설명이 다르다.

## 5. 규칙 정의에 필요한 정보

### 5.1 규칙 머리말

```text
RuleStableId
RuleRevision
RuleDomainCode
RuleKindCode
ModeCode
ScopeCode
SourceCapabilityKey
SourceContractRevision
SourceStableIds[]
EffectiveFrom / EffectiveTo?
Limitations[]
```

`RuleDomainCode`는 `Production`, `Consumption`, `Transport`, `Warehouse`, `Market`, `Facility`, `Time` 중 하나다. `Presentation.Camera` 같은 표현 영역은 자원 효과 묶음에서 거부한다.

규칙 고유 식별자와 개정 번호는 저장된 효과를 나중에 같은 계산으로 재현하는 기준이다. API 경로, Unity Prefab 이름과 GameObject 이름은 규칙의 정체성으로 사용하지 않는다.

### 5.2 적용 조건

| 항목 | 의미 |
| --- | --- |
| 대상 종류 | 재배 단위, 시설, Lot, Cargo, 주문, 주민 집단 등 |
| 상태 조건 | 수확 가능, 포장 완료, 입고 승인, 수령 준비 등 |
| 시간 조건 | 적용 Tick, 기간, 반복 주기, 마감 |
| 권한·모드 | Simulation 전용, 운영 권한 필요, 읽기 전용 |
| 입력 자원 | 필요한 재고·현금·노동·용량과 단위 |
| 시설 조건 | 온실, 창고, 차량, 마트 등 필요한 능력 |
| 차단 조건 | 결측 자료, 부족, 중복 적용, 낮은 개정 번호 |

### 5.3 계산과 효과선

한 규칙은 여러 자원 효과선을 가진다.

```text
ResourceEffectLine
    EffectLineStableId
    MutationKindCode
    ResourceTypeCode
    ProductStableId?
    LotStableId?
    SourceLedgerStableId?
    TargetLedgerStableId
    BeforeValue
    Delta
    AfterValue
    UnitCode
    FormulaCode
    RuleRevision
    SourceStableIds[]
```

이 구조는 현재 `SimulationValueProjection`과 `SimulationEffectRecord`를 감싸거나 확장하는 방향으로 검토한다. 기존 공개 필드와 저장 데이터는 근거 없이 이름을 바꾸지 않는다.

## 6. 생산 규칙

### 6.1 생산은 세 단계를 분리한다

```text
생산 능력
    이론상 얼마를 만들 수 있는가

생산 진행
    환경·노동·시설·시간 조건을 얼마나 충족했는가

생산 확정
    완료 Tick에서 실제 출력 Lot이 얼마 생성됐는가
```

밭 면적이나 온실이 늘었다고 즉시 감자 재고가 증가하지 않는다. 먼저 생산 가능한 용량이 늘고, 파종·생육·수확 Task가 완료돼야 수확 Lot이 생산된다.

### 6.2 권장 생산식

```text
기준 생산량
    = 단위 생산성
    × 활성 생산 용량
    × 작업 기간

생산 후보량
    = 기준 생산량
    × 환경 충족 계수
    × 투입 효과 계수
    × 시설 효과 계수
    × 손실 계수

확정 생산량
    = 완료 Tick에서 검증된 생산 후보량
```

모든 계수에는 상한·하한과 개정 번호가 있어야 한다. 같은 효과를 환경과 시설에서 중복 계산하지 않는다.

### 6.3 생산의 플러스와 마이너스

| 항목 | 플러스 가능성 | 함께 기록할 마이너스·제한 |
| --- | --- | --- |
| 밭 확장 | 재배 가능 면적·동시 작기 수 증가 | 건설비, 노동, 물 수요, 유지 면적 |
| 관수 | 물 부족 완화 | 물·에너지·노동 소비, 과습 위험 |
| 비료 | 검증된 범위 안에서 생산성 또는 손실 완화 | 비료 재고·비용·노동 소비, 과다 투입 제한 |
| 온실 | 환경 변동·작기·손실 완화 | 건설비, 용량, 에너지·유지 노동 |
| 숙련·장비 | 작업 처리량·손실 완화 | 장비 용량, 연료·정비·노동 |

플러스 효과만 있는 프로젝트를 기본값으로 만들지 않는다. 비용이 없는 Fixture라면 `SimulationCostExcluded` 같은 한계를 명시한다.

## 7. 소비 규칙

### 7.1 수요와 소비를 분리한다

```text
수요
    필요하거나 희망하는 양

예약
    이행을 위해 확보한 양

이행
    원천 재고에서 실제로 차감된 양

소비
    사용자·시설·작업이 실제로 사용한 양
```

수요가 생겼다는 이유만으로 재고를 줄이지 않는다. 예약은 전체량을 줄이지 않고 가용량만 줄인다. 주문 이행에서 이미 시장재고가 차감됐다면 주민 소비 완료 시 같은 시장재고를 다시 차감하지 않는다.

### 7.2 소비 규칙에 필요한 값

| 값 | 의미 |
| --- | --- |
| 소비 주체 | 주민, 시설, 차량, 작업, 주둔군 등 |
| 대상 자원 | 품목, 물, 에너지, 연료, 노동, 현금 등 |
| 요구량 | Tick당·작업당·건당 필요한 양 |
| 우선순위 | 부족할 때 어떤 소비를 먼저 지킬지 |
| 최소 충족량 | 부분 소비를 허용할 최소치 |
| 부족 결과 | 지연, 부분 생산, 품질 저하, 중단, 손실 |
| 대체 가능성 | 다른 품목·자원으로 바꿀 수 있는지와 환산 규칙 |
| 반복 주기 | 1회, 매 Tick, 기간 종료 시 등 |

### 7.3 소비가 만드는 플러스 효과

소비는 단순한 마이너스가 아니다. 자원을 소비해 다른 상태나 가치가 생긴다.

| 소비 | 감소 | 증가 또는 변화 |
| --- | --- | --- |
| 주민 식품 소비 | 주민에게 인계된 식품 | 주민 소비 누계·충족 상태 |
| 관수 | 물·에너지·노동 | 토양수분, 물 부족 완화 |
| 포장 | 포장재·노동 | 포장 Lot, 운송 가능 후보 |
| 차량 운행 | 연료·시간·노동 | 경로 진행, 목적지 도착 후보 |
| 시설 유지 | 현금·자재·노동 | 시설 가용성 유지, 고장 위험 완화 |

이때 출력 효과가 생겼다고 입력 소비를 숨기지 않는다.

## 8. 이동과 변환 규칙

### 8.1 이동

이동은 전체 수량이 늘거나 줄지 않는다.

```text
원천 위치 100kg → 대상 위치 100kg
전체 100kg 유지
```

검수 손실이 있다면 이동과 손실을 별도 효과선으로 기록한다.

```text
원천 반출 100kg
대상 합격 96kg
검수 손실 4kg
100 = 96 + 4
```

### 8.2 변환

변환은 입력과 출력의 관계를 보존한다.

```text
감자 수확 Lot 100kg
    → 포장 감자 100kg
    + 상자 5개 소비
    + 포장 노동 소비
```

감자 질량은 보존되지만 포장 단위와 취급 상태가 바뀐다. 세척·가공처럼 질량 손실이나 부산물이 있으면 변환 규칙에 수율과 손실 원장을 함께 둔다.

## 9. 공통 검증식

### 9.1 단일 효과선

```text
BeforeValue + Delta = AfterValue
```

### 9.2 예약

```text
전체량 = 가용량 + 예약량
```

예약과 해제는 전체량을 바꾸지 않는다.

### 9.3 이동

```text
원천 감소량 = 대상 증가량 + 운송 중 명시적 손실량
```

### 9.4 변환

```text
입력량 × 규칙 수율 = 출력량 + 부산물량 + 손실량
```

서로 다른 단위는 명시적인 환산 규칙 없이는 더하거나 비교하지 않는다.

### 9.5 적용 안전성

- 같은 효과 고유 식별자는 한 번만 적용한다.
- 예상 효과와 실제 효과의 규칙 개정 번호가 다르면 Confirm 또는 적용을 차단한다.
- 효과 묶음 일부만 적용하지 않고 하나의 transaction에서 모두 적용하거나 모두 거부한다.
- 적용 결과가 음수 재고, 초과 예약, 용량 초과를 만들면 차단한다.
- 입력 Lot과 출력 Lot의 데이터 계보를 보존한다.
- save·replay는 규칙 개정 번호, Command와 실제 효과 묶음을 검증한다.

## 11. Unity 표현 원칙

Unity에서는 효과 묶음을 다음처럼 보여줄 수 있다.

```text
온실 확장 Preview

+ 재배 가능 면적 100m²
+ 환경 변동 완화 후보
- 현금 50,000 Simulation KRW
- 노동 8 예약
- 유지 노동 1/Turn
! 실제 효과는 완료 WorldTick 뒤 적용
```

화면의 `+`와 `-`는 이해를 돕는 표현일 뿐 권위가 아니다. 각 항목은 대상 원장, 단위, 계산 근거, 규칙 개정 번호와 Simulation/실운영 구분을 선택 시 확인할 수 있어야 한다.

GameObject 수, 상자 개수, 차량 이동, 작물 Mesh 크기로 실제 자원량을 다시 계산하지 않는다.

## 12. 구현 우선순위

### RESOURCE-RULE-0: 용어와 계약 — 완료

- `Simulation자원변동유형Codes`, `Simulation자원효과역할Codes` 정의
- 자원 효과 묶음·효과선, 원장 상태와 적용 결과 계약 구현
- 단위·원장·품목·Lot·규칙 개정 번호·출처를 효과선에 보존
- 기존 `SimulationValueProjection`·`SimulationEffectRecord`는 변경하지 않고 유지하며, 실제 세션 연결 adapter는 첫 생산·소비 세로 단면에서 추가

### RESOURCE-RULE-1: 순수 검증기 — 완료

- 단일 효과선, 예약, 이동, 변환 수량 보존 검증
- 역할과 부호 불일치, 보존 묶음 불균형·필수 역할 누락, 음수 원장과 중복 원장·효과선 차단
- 전체 효과선을 복제본에 적용한 뒤 결과를 반환해 부분 적용을 방지
- 현재 원장 이전 값·자원·단위·품목·Lot 불일치와 이미 적용된 효과 묶음 차단
- 외부 저장이나 Unity 의존성이 없는 검증기·적용기와 업무 영역 분류 검증을 포함한 집중 테스트 22/22 통과

저장 용량의 `사용량 + 예약량 ≤ 전체 용량`처럼 서로 다른 원장 세 개를 함께 비교하는 용량 전용 검증은 첫 시설 세로 단면에 남아 있다. 이번 공통 적용기는 개별 원장의 음수, 이전 값 불일치와 효과 묶음 수량 보존까지만 책임진다.

검증 기준선은 다음과 같다.

- 자원 효과 규칙 집중 테스트: 22/22 통과
- `Ssalddel.Simulation.Tests` 전체: 292/292 통과
- 변경 경로 빠른 검증: Simulation Contracts·Domain·Tests build 통과
- 작업 수준 `Ssalddel.v0.0.slnx` build: 통과
- 작업 수준 전체 테스트: 4,536/4,543 통과. 실패 7개는 이번 경로와 무관한 기존 CSS·WebApp route 분류·Controller metadata 기준선이다

### POTATO-PRODUCTION-RULE-1: 첫 생산 세로 단면 — 완료

- 단일 `TileStableId`에 대응하는 재배 단위와 물리 면적·유효 재배 면적 비율 계약을 추가했다.
- 단위면적 Fixture 생산성에 환경·투입·시설·손실 계수를 곱해 수확 후보량을 계산한다.
- 재배 단위가 수확 준비 상태이고 Decision이 확정됐으며 수확 Task가 완료된 경우에만 `Production` 영역의 대기 중인 생산 효과 묶음을 만든다.
- 생산 효과선은 새 수확 Lot 원장을 0kg에서 계산된 수량으로 증가시키고 재배 단위·Tile·환경 상태 사본·Decision·Task·규칙 출처를 보존한다.
- 기존 300kg Fixture는 테스트에서 `100m² × 3kg/m² × 계수 1`로 재현하지만, 이 면적과 생산성은 실제 농업 기준이나 운영 수확량이 아니다.
- 집중 테스트 9/9와 `Ssalddel.Simulation.Tests` 전체 301/301을 통과했다. 기존 Unity 감자 재배 Lifecycle과 서버 session aggregate에 대한 adapter 연결은 후속 범위다.

### CONSUMPTION-RULE-1: 첫 소비 세로 단면 — 완료

- 수요는 효과를 만들지 않는 의향·요청으로 유지하고, 주문 확정 시 시장 가용량과 주문별 예약량 사이의 예약 효과 묶음을 만든다.
- 주문 이행 완료 시 예약량을 주민 수령량으로 옮겨 시장 보유량에서 한 번만 제외한다.
- 별도 수령·소비 Confirm과 Task 완료 뒤에는 주민 수령량을 줄이고 주민 소비 누계를 올리는 `Consumption` 효과 묶음만 만든다.
- 소비 단계에는 시장 가용·예약 원장 효과선이 없으며, 기존 `AdditionalMarketSupplyDeductionApplied=false`와 주문 이행 후 시장 잔여 수량 일치를 요구한다.
- 300kg에서 20kg을 예약·이행·소비하면 시장 가용 280kg, 주문 예약 0kg, 주민 수령 0kg, 주민 소비 누계 20kg으로 수렴한다.
- 집중 테스트 9/9와 `Ssalddel.Simulation.Tests` 전체 310/310을 통과했다. 반복 주기·부족 시 대체·폐기·환불은 후속 개정으로 남긴다.

### RESOURCE-RULE-2: 이동·변환 확장

- 수확 Lot→포장 Lot→Cargo→창고→마트의 이동·변환 효과 묶음
- 포장재·노동·연료·저장 용량과 손실 원장 연결

### TRANSPORT-RULE-1: 첫 운송 세로 단면 — 완료

- 기존 화물운송과 물류 이동 상태를 상차, 운송 자원 소비·손실, 하차, 별도 인수 확인의 자원 효과 단계로 연결했다.
- 상차는 원산지 Cargo를 차량 Cargo로 옮기며 차량 적재 용량과 단위를 먼저 검증한다.
- 운송 완료 시 연료·노동을 소비하고 Cargo 손실이 있으면 차량 Cargo 감소와 운송 손실 원장을 같은 보존 묶음에 기록한다.
- 목적지 도착은 하차 가능 상태일 뿐 인수 완료가 아니다. 하차는 차량 Cargo를 목적지 대기 Cargo로 옮기고, 별도 인수 Confirm·Task 완료 뒤에만 인수 Cargo로 옮긴다.
- 300kg Fixture에서 연료 5L·노동 2시간·손실 3kg을 적용해 297kg 인수와 3kg 손실로 수렴했다. 이 수치는 운임·연료 소비율·현실 감모 기준이 아니다.
- 집중 테스트 9/9와 `Ssalddel.Simulation.Tests` 전체 319/319를 통과했다. 기존 session aggregate에 효과 묶음을 저장하는 adapter와 경로별 현실 비용·연료·손실 Profile은 후속 범위다.

### WAREHOUSE-RULE-1: 첫 창고 세로 단면 — 완료

- 운송 인수 Cargo를 창고 입고 완료로 바로 보지 않고 입고 대기, 검수, 적치, 보관 감모, 피킹, 출고의 자원 효과 단계로 분리했다.
- 검수는 인수 수량을 합격량과 거부량으로 보존하며 합격량만 적치할 수 있다.
- 적치는 검수 합격 Cargo를 창고 재고로 옮기는 동시에 가용 저장 용량을 점유 용량으로 예약한다.
- 보관 감모는 창고 재고 감소와 손실 원장 증가를 기록하고 같은 양의 점유 용량을 해제한다.
- 피킹은 창고 가용 재고를 출고 예약으로 옮기며, 출고 완료 시 출고 인계 Cargo를 만들고 점유 용량을 해제한다.
- 297kg Fixture는 검수 합격 290kg·거부 7kg, 보관 감모 10kg, 출고 100kg을 거쳐 창고 재고 180kg·출고 100kg·보관 손실 10kg·점유 용량 180kg으로 수렴했다.
- 집중 테스트 9/9와 `Ssalddel.Simulation.Tests` 전체 328/328을 통과했다. 현실 검수 기준·보관 감모율·위치별 용량과 기존 session aggregate adapter는 후속 범위다.

## 13. 이번 제안에서 확정하지 않는 것

- 감자 Tile의 실제 면적과 현실 수확량
- 비료·관수·온실의 실제 농업 효과 수치
- 주민별 현실 식품 필요량이나 영양 처방
- 실제 비용, 운임, 전기·연료 사용량
- 운영 재고·결제·계약에 Simulation 규칙을 직접 적용하는 방식
- 모든 자원을 하나의 종합 효율 점수로 환산하는 방식

첫 구현은 Simulation Fixture로 규칙 구조와 수량 보존을 검증하고, 실제 수치는 출처와 사람 검토를 통과한 별도 규칙 개정 번호로만 승격한다.
