# 영역별 건물 발전 테크트리 계획

## 목적

Ssalddel의 Nature·Farm·Town·Hub·City를 서로의 선행 조건이 아닌 독립 영역으로 발전시킨다. 플레이어는 각 영역에서 재료와 시간을 들여 H1 건물을 조립하고, Simulation은 누적된 H1과 플레이 폐루프를 근거로 H2·H3의 성장을 판정한다.

이 문서는 다섯 영역의 공통 발전 규칙과 첫 실제 세로 조각인 Nature 건물 발전을 함께 관리한다. Farm·Town·Hub·City의 건물 목록은 후속 구현을 위한 결정적 카탈로그이며, 현재 실제 건설 폐루프가 구현된 영역은 Nature뿐이다.

## 플레이어 약속

플레이어는 다음 흐름을 반복한다.

1. 현재 영역의 부족한 생활 기능을 확인한다.
2. 해금된 청사진의 비용·시간·배치 조건을 비교한다.
3. `Preview → Confirm`으로 건설을 시작한다.
4. 취소하면 예약 재료를 돌려받고, 계속하면 권위 시계가 작업을 완료한다.
5. 완성된 건물의 기능을 사용하고 다음 건물을 선택한다.

건물은 경험치 숫자로 자동 승격되지 않는다. 어떤 갈래를 선택해도 다른 갈래를 영구 잠그지 않으며, 선행 건물이 운영 상태이면 여러 갈래를 누적해 건설할 수 있다. 카드·현실자료·Synty 자산은 건설 권위가 아니다. 카드는 허용된 문맥과 효과 연결만 제공하고, 현실자료는 설명·검토 근거로만 쓰며, Synty는 승인된 범주형 외형을 표현한다.

## 공통 발전 계층

| 단계 | 의미 | 공통 상태 |
| --- | --- | --- |
| Foundation | 영역의 생존·업무 시작점 | `Locked`, `Available`, `Planned`, `Building`, `Operational` |
| Operations | 반복 업무를 안정화하는 기본 시설 | 위 상태와 `Damaged`, `Suspended` |
| Specialization | 영역의 정체성을 드러내는 전문 시설 | 동일 |
| Resilience | 위협·사건·고장 뒤 회복을 돕는 시설 | 동일 |
| Landmark | 여러 갈래가 누적돼 성립하는 대표 공간 | 동일 |

`Operational`은 H1 건물 기능이 사용 가능한 상태다. 이것만으로 H2·H3가 자동 완성되지는 않는다. H2는 필요한 H1 집합과 내부 업무 흐름, H3는 H2 폐루프와 공간 관계를 Simulation 규칙이 별도로 판정한다.

## 영역별 카탈로그

| 영역 | Foundation | Operations | Specialization | Resilience | Landmark |
| --- | --- | --- | --- | --- | --- |
| Nature | 오두막 | 작업대·보관대·방책 | 자연 배움터 | 위협 감시소·복원 작업장 | 공동 사색원 |
| Farm | 소형 농장 창고 | 종자·도구 준비소 | 세척·선별·포장소 | 외부 노출 점검소·사건 격리소·기상 보호소 | 농장 회복 복합구역 |
| Town | 공동상점 | 주문 포장·수령소 | 근린 생활서비스소 | 회수·구호 안내소 | 생활서비스 복합구역 |
| Hub | 반입·임시 적치소 | 검사·격리소 | 냉장·피킹 창고 | 정비·비상전력소 | 회복력 물류거점 |
| City | 공동수령소 | 생활시장 | 도시 정보·서비스관 | 기반시설 복구소 | 도시 생활서비스 복합구역 |

이 목록은 영역별 독립 폐루프를 위한 계획 기준이다. Farm의 기존 창고·사건 대응 기능은 해당 영역의 기존 규칙을 유지하며, 공통 카탈로그에 이름이 보인다는 이유만으로 새 건설 권위가 생기지 않는다. Town·Hub·City도 현재 조회 가능한 정의일 뿐 실제 재료 원장·작업·완성 효과는 후속 세로 조각에서 구현한다.

## Nature r3 실제 세로 조각

Nature r3는 기존 첫날 폐루프와 Day 2 확장 선택을 보존하면서 실제 누적 건설을 추가한다.

| 건물 | 선행 | 목재 | 재건 부품 | 권위 시간 | 기능 |
| --- | --- | ---: | ---: | ---: | --- |
| 오두막 | 없음 | 6 | 0 | 30초 | 피난·보관·수면 |
| 작업대 | 오두막 | 4 | 1 | 20초 | 제작 갈래 시작 |
| 보관대 | 오두막 | 6 | 1 | 24초 | 보관 갈래 시작 |
| 방책 | 오두막 | 8 | 1 | 30초 | 방어 갈래 시작 |
| 자연 배움터 | 작업대 | 10 | 1 | 60초 | 승인된 보편 학습 자료 방문 |
| 위협 감시소 | 방책 | 8 | 1 | 45초 | 위협 관찰 기능 후보 |
| 복원 작업장 | 작업대 | 10 | 1 | 50초 | 복원 기능 후보 |
| 공동 사색원 | 자연 배움터·복원 작업장 | 12 | 2 | 75초 | 학습·안전 회복의 대표 공간 후보 |

Day 2에서 선택한 작업대·보관대·방책은 첫 우선 갈래만 뜻한다. 선택하지 않은 갈래도 선행 조건과 자원이 충족되면 이후 건설할 수 있다. 건설은 오두막 생활핵 반경 25m 안에서만 허용하며 운영 중이거나 건설 중인 다른 H1 발자국과 겹치면 거부한다. 비용은 플레이어 소지품과 오두막 보관함에서 결정적으로 소비하며, 작업 취소는 이 작업에 예약된 목재와 재건 부품을 반환한다.

건설 명령은 기존 `WI-CON-01`을 사용한다. Unity나 HTTP 소비자는 청사진 고유 식별자와 예상 revision, 배치 좌표만 제출하며 비용·해금·완료를 직접 계산하지 않는다.

## 자연 배움터의 중립성 경계

자연 배움터는 선택 건물이다. 특정 신앙을 요구하거나 NPC 자격·신뢰·능력치를 종교로 판정하지 않는다. 현재 승인 Fixture는 다음 세 주제만 제공한다.

- 계절의 순환
- 자원의 회복
- 보편 가르침과 성찰

마지막 주제는 서로 다른 철학·종교적 관점을 우열 없이 비교하는 성찰 자료다. 운영자 승인 여부가 `true`인 자료만 Unity 읽기 결과에 나타난다. NPC 방문은 `Approaching → Learning → Completed`로 진행되며, 완료 기록은 어떤 말을 했는지가 아니라 어느 승인 자료를 어느 건물에서 학습 완료했는지만 남긴다.

외부 영상 Provider, 추천 알고리즘, 실시간 인터넷 조회는 Simulation 세션·시계·Unity 조회에서 호출하지 않는다. 향후 영상 자료를 연결하더라도 운영 승인 사본과 출처·revision·hash를 거친 별도 자료 계약으로 추가해야 한다.

## 권위·저장·조회

- Solo는 `LocalProcess`, Hosted는 `RemoteHost`에서 같은 Simulation Core 규칙을 실행한다.
- 새 Nature r3 상태는 `simulation-save.v19`에 카탈로그 revision/hash, 건물 노드, 배치, 작업, 학습 방문을 봉인한다.
- v18 이하 저장의 정규형과 replay hash는 변경하지 않는다.
- 통합 조회는 `GET api/simulation/v1/sessions/{sessionStableId}/nature-survival/building-progression/{areaCode}`다.
- Unity 읽기 모델은 카탈로그와 권위 상태를 표시할 뿐 건설 완료나 학습 효과를 확정하지 않는다.

## 구현·검증 상태

| 범위 | 상태 | 증거 |
| --- | --- | --- |
| 다섯 영역 결정적 카탈로그·의존 순환/hash 검증 | 구현·시험됨 | Simulation 집중 시험 |
| Nature 작업대→자연 배움터→NPC 학습→v19 저장·재생 | 구현·시험됨 | Simulation 집중 시험 |
| 취소 재료 반환과 갈래 비잠금 | 구현·시험됨 | Simulation 집중 시험 |
| HTTP 영역 조회 | 구현·시험됨 | Simulation 집중 시험 |
| Unity 승인 자료 필터·표시용 읽기 모델 | 구현·시험됨 | Unity .NET 소비자 시험 |
| Farm·Town·Hub·City 실제 건설 작업·효과 | 카탈로그만 구현 | 후속 독립 세로 조각 필요 |
| `SimulationWorldShell` 실제 배선·Play Mode·Game View | 미검증 | 이번 범위에서 Scene을 수정하지 않음 |
| 외부 영상·상품 Provider 및 운영 배포 | 미구현 | 별도 승인 필요 |

현재 자동 검증 기준은 Simulation 집중 시험 `5/5`, Unity 읽기 모델 시험 `1/1`, `Ssalddel.Simulation.slnx` 빌드 경고·오류 `0/0`이다. 이 결과는 실제 Unity 화면이나 Hosted 네트워크 동등성 증거가 아니다.

## 후속 구현 순서

1. canonical `SimulationWorldShell`에서 Nature 건설 팔레트와 배치 Preview를 기존 배치 통제 계층에 결속한다.
2. 실제 입력으로 작업대와 자연 배움터를 완성하고 NPC 방문을 Game View에서 확인한다.
3. LocalProcess와 RemoteHost의 revision별 canonical hash를 비교한다.
4. Nature landmark 효과를 E6에서 정제한 뒤 H2·H3 성장 판정을 별도 규칙으로 연결한다.
5. Farm·Town·Hub·City 중 하나를 독립 Fixture로 선택해 해당 영역의 재료·작업·효과를 세로로 구현한다.

영역 간 경로는 양쪽 독립 폐루프가 준비된 뒤 별도 통합 조각으로 다룬다. Farm을 구현했다고 Hub나 City가 자동으로 다음 선행 단계가 되지는 않는다.
