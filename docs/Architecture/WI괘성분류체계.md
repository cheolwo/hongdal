# WI 괘성 분류 체계

## 목적

이 문서는 기존 World Interaction(WI)을 `나의 행위`, `작용 방식`, `너인 대상`, `보조 발현`으로 읽기 위한 기획 분류를 정의한다. 괘성은 기존 WI 고유 식별자, 권위 상태, E/G/H 성숙도, 실행 순서와 구현 승인을 대체하지 않는다.

## 표기

사람이 읽는 문서와 생성 목록에서는 괘 이름 뒤에 괘상만 괄호로 표시한다.

- 진괘(☳)
- 태괘(☱)
- 리괘(☲)
- 감괘(☵)
- 간괘(☶)

내부 데이터에서는 글꼴과 직렬화 호환을 위해 `JIN`, `TAE`, `RI`, `GAM`, `GAN` 코드를 사용한다.

## 나와 너의 구분

| 괘 | 나: 플레이어가 발휘하는 역량 | 너: 플레이어가 대하는 주요 대상 |
| --- | --- | --- |
| 진괘(☳) | 행동, 농사, 채집, 벌목, 사냥, 개척 | 작물, 약초, 나무, 동물, 자연자원 |
| 태괘(☱) | 배치, 건축, 시설 이용, 공간 정비 | 집, 창고, 울타리, 농장, 성벽, 공간시설 |
| 리괘(☲) | 질서, 지휘, 역할 분담, 동행대 편성, 약속 이행 | 질서, 규율, 역할, 지휘 체계와 그 상태 |
| 감괘(☵) | 학습, 조사, 추론, 계획, 물류 판단 | 지식, 단서, 재고, 화물, 제조법, 물류정보 |
| 간괘(☶) | 대화, 공감, 집중, 명상, 직관, 위협 극복, 정신 회복 | NPC, 동행자, 주민, 조직, 공포·불안·정신적 압박 |

### 나와 상대의 순환 목적

게임의 상위 목적은 나와 상대의 오행 항목을 모두 같은 수치로 채우는 것이 아니라, 현재 관계에서 필요한 행위·작용·대상·보조가 실제 WI 결과와 회복·귀환으로 이어지게 하는 것이다. 여기서 상대는 사람·집단뿐 아니라 사물·자원·시설·환경·공간·생태도 포함한다. 사람에게는 주체성·동의·거절을 보존하고, 사물·환경에는 의도나 감정을 부여하지 않는다. 나와 상대가 각각 다섯 괘 수치를 가진다고 가정하지 않으며, 관계에 적용되지 않는 괘를 채우기 위해 가짜 WI·대상·상태를 만들지 않는다.

완료된 WI에서 실제 순환 개선까지 확인되면 [게임 기획 통합 기준](게임기획통합기준.md#나와-상대의-오행-순환이-회복역량을-높인다)에 따라 관련 회복역량 기여 후보를 남길 수 있다. 그러나 괘성 자체가 회복량을 계산하거나 광복기를 판정하지 않는다. 구체 결과는 기존 개인·공동체 회복, 관계, 내구·기능·용량, 생산·경로·생태 상태와 판본화된 Profile이 소유한다. `actionGwae`·`targetGwae`가 맞거나 WI가 완료됐다는 이유만으로 회복을 지급하지 않으며, 실행 Actor·직접 대상·영향 범위·회복 판정 대상과 실제 권위 결과·중복 방지 근거가 필요하다. 같은 결과가 대상별로 개선·유지·손실을 함께 만들 수 있고, 괘성은 그 불리한 결과를 숨기지 않는다.

## WI 분류 필드

- `subjectKind`: 행위 주체. 플레이어, NPC, 세계 또는 가변 주체를 구분한다.
- `actionGwae`: WI에서 행위 주체가 수행하는 주된 행위괘. 필수다. 플레이어가 주체일 때 UI에서 `나의 괘`로 표시할 수 있다.
- `operationGwae`: 도구·속성·방법이 의미를 바꿀 때 쓰는 작용괘. 선택이다.
- `targetGwae`: WI가 직접 대하는 대상괘. 필수다.
- `supportGwae`: 집중·지휘·조사처럼 주행위를 보조하는 괘. 선택이다.

예를 들어 벌목은 자연 획득 행위이므로 행위괘가 진괘(☳)이고, 금속 도끼의 절단을 사용하므로 작용괘가 태괘(☱)이며, 대상 나무는 진괘(☳)다. 집중을 선택했을 때만 간괘(☶)를 보조괘로 붙인다.

## 기획에서 쓰는 정리 순서

괘성은 별도의 기획 주제가 아니라 `지금·여기·나·너·이렇게`로 정리한 플레이 경험에 붙는 조회 메타데이터다. 기획 문서는 아래 순서로 먼저 플레이 의미를 닫고, WI를 고르거나 새 WI 필요성을 검토할 때 괘성을 붙인다.

1. `지금`: 시간·절기·위기·진행 상태
2. `여기`: Area·Graph Map 노드·접근 가능한 공간
3. `나`: 실제 행위 주체와 현재 역량·소유·상태
4. `너`: 상대·사물·환경과 관측 가능한 상태
5. `이렇게`: 선택할 WI, 입력, 대가, 실패·중단·회복 방식
6. `결과`: 같은 판본에서 확인할 권위 결과와 플레이어가 읽는 변화
7. `다음 선택`: 결과 때문에 새로 열리거나 닫히는 선택

그 뒤 선택한 WI에 다음 다섯 칸을 붙인다.

| 괘성 칸 | 기획에서 답하는 질문 | 작성 책임 |
| --- | --- | --- |
| 주체 | 누가 실제로 행위를 일으키는가 | 기획이 확정하고 분류기가 `subjectKind`로 기록 |
| 행위괘 | 이 WI가 직접 수행하는 주행위는 무엇인가 | 기존 WI 의미에서 자동 분류, 의미가 달라질 때만 질문 |
| 작용괘 | 어떤 도구·속성·방법이 행위 성격을 바꾸는가 | 없으면 생략, 실행 객체나 작업 코드에 따라 승계 가능 |
| 대상괘 | 무엇을 직접 대하는가 | 대상 객체 분류를 우선 승계 |
| 보조괘 | 집중·조사·지휘처럼 선택적으로 돕는 것은 무엇인가 | 실제 선택이나 조건이 있을 때만 기록 |

사용자는 장면의 약속, 선택, 대가, 결과와 다음 선택을 결정한다. Codex는 기존 WI 대조와 괘성 부착을 기본적으로 자동 수행하고, 둘 이상의 분류가 플레이 의미를 실제로 바꿀 때만 한 가지 질문으로 돌려준다. 따라서 사용자가 공식 WI 105개나 괘성 표를 매번 다시 검토할 필요는 없다.

Graph Map 인계에서는 레벨 1 엣지가 WI 안정 식별자와 괘성 참조만 가진다. 레벨 2 배치 제약과 레벨 3 코드·컴포넌트 결속은 괘성에서 자동 생성하지 않는다. 개발도 승인 기획이 괘성을 실제 규칙으로 채택하지 않는 한 이를 검색·설명 메타데이터로만 소비한다.

## 기획·Graph Map·배치 맵의 산출물 괘상

WI에 붙는 `actionGwae`·`operationGwae`·`targetGwae`·`supportGwae`와 문서·맵 산출물에 붙는 괘상은 서로 다른 메타데이터다. 산출물에는 `artifactGwae`를 사용하며 다음 대응을 기본으로 한다.

| 산출물 종류 | `artifactGwae` | 뜻 |
| --- | --- | --- |
| 기획 | `RI` · 리괘(☲) | 플레이 의미와 선택·결과를 밝혀 구분하는 불의 관점 |
| Graph Map | `GAN` · 간괘(☶) | 안정 노드·엣지·경계와 전파 중단점을 세우는 산의 관점 |
| 배치 맵 | `TAE` · 태괘(☱) | 시설·통행·시야·상대 배치를 구체 공간으로 펼치는 못의 관점 |

여기서 **계획을 세우는 행위**와 **그 행위로 동결된 기획 결과물**을 구분한다. 계획·청사진을 세우는 행위는 목표와 경계를 산처럼 멈춰 세우므로 간괘(☶)다. 반면 검토·승인되어 다른 작업이 읽는 기획 결과물은 플레이 의미와 선택 기준을 밝혀 후속 Graph Map·배치 맵·개발의 질서를 잡으므로 `artifactGwae: RI`·리괘(☲)로 둔다. 따라서 하나의 기획 과정 안에서 `계획 행위 GAN → 기획 결과물 RI`가 성립할 수 있으며 이는 모순이 아니다.

기획 결과물의 리괘는 후속 작업에 질서를 제공하는 **해석·참조 관점**이다. 명령 권위, 실행 순서, 상태 전이 또는 자동 개발 승인을 뜻하지 않는다. 이 대응은 [Graph Map 기획 인계 순환 체계](GraphMap기획인계순환체계.md)의 삼중 균형을 탐색하고 표시하기 위한 비권위 메타데이터다. 기획 결과물이 리괘(☲)라는 이유로 개별 WI의 행위괘를 리괘로 바꾸지 않으며, 계획·청사진을 대상으로 하는 WI의 기존 간괘(☶) 분류도 유지한다. 마찬가지로 Graph Map의 간괘나 배치 맵의 태괘만으로 노드·제약·개발 작업·E 성숙도를 자동 생성하거나 승격하지 않는다.

### 관계에 따라 달라지는 괘상

괘상은 객체의 영구하고 유일한 본질값이 아니라 **현재 관계에서 읽히는 역할 메타데이터**다. 같은 안정 객체나 문서라도 관계가 달라지면 서로 다른 괘상 관점을 함께 가질 수 있으며, 이를 이유로 안정 ID나 권위 상태를 복제하지 않는다.

- `artifactGwae`: 문서·맵 산출물이 현재 파이프라인에서 맡는 주 역할
- `relationGwae`: 두 객체·공간·산출물을 잇는 특정 관계가 나타내는 흐름이나 작용
- `dataSourceKind`: 그 관계 근거가 공공 데이터, 플레이 기록, Simulation 상태, 수동 기획 중 무엇인지 나타내는 출처 구분

예를 들어 승인 기획은 결과물로서 리괘(☲)이고, 이를 관계와 경계로 구조화한 Graph Map은 간괘(☶), 그 관계를 실제 공간 구도로 펼친 배치 맵은 태괘(☱)다. 두 공간 사이의 이동·운송·관측·교환처럼 흘러가는 정보는 엣지 또는 오버레이에서 `relationGwae: GAM`·감괘(☵)로 읽을 수 있다. 이 감괘 데이터는 공공 데이터일 수도 있고 플레이 기록일 수도 있으므로 `dataSourceKind`와 출처·판본·시각·hash를 별도로 기록한다.

감괘 표시는 데이터가 흐른다는 의미일 뿐 정확성·최신성·공개 권리·Simulation 권위·플레이 성공을 보증하지 않는다. 같은 공간 노드는 배치 대상으로는 태괘, 경로망의 경계점으로는 간괘, 이동 기록의 출발·도착점으로는 감괘 관계에 참여할 수 있다. 조회 화면은 이 관점을 겹쳐 보여 줄 수 있지만 한 값을 다른 값으로 덮어쓰지 않는다.

### 기본 출력 정책

괘상은 내부 분류·검색·관계 대조·Graph Map 및 배치 맵 검증에 사용하는 메타데이터다. 사용자에게 제공하는 일반 기획 질문, 진행 보고, 이야기 설명에서는 괘 이름·코드·기호를 전면에 반복 노출하지 않고 플레이 의미와 선택지를 평이한 언어로 먼저 설명한다.

괘상 표시는 사용자가 직접 요청했거나 분류 충돌·인계 검증·상세 메타데이터 조회처럼 표시 이유가 있을 때만 펼친다. 기본 출력에서 숨기더라도 원장의 `actionGwae`·`artifactGwae`·`relationGwae`와 출처 계보는 유지하며, 숨김을 미분류나 근거 부재로 해석하지 않는다.

### WI와 진괘의 관계

기획·Graph Map·배치 맵으로 이어지는 순환을 읽을 때 WI는 플레이어·NPC·세계가 일으킬 수 있는 행위 계약이므로 진괘(☳) 계열의 실행 가능성을 나타낸다. 이는 `pipelineGwae`라는 새 저장 필드나 권위 상태를 추가한다는 뜻이 아니다. 기획 문서는 WI를 재사용·복합화·신규 검토하면서 플레이 의미를 밝히고, 기획 결과물 자체의 `artifactGwae`는 계속 리괘(☲)다.

WI의 순환상 역할, 개별 의미, 실제 실행 근거는 다음처럼 구분한다.

- 순환상 역할: WI 정의·후보는 실행 가능한 행위 계약이라는 의미에서 진괘 계열로 읽는다. 아직 실행 증거가 아니다.
- 개별 WI 의미: 기존 `actionGwae`·`operationGwae`·`targetGwae`·`supportGwae`를 그대로 사용한다. 계획·명상처럼 개별 행위의 주 괘가 진괘가 아닐 수 있다.
- 실제 실행 판독: 같은 WI·Actor·대상·Session·Revision에 결속된 기존 행위 기록, 권위 상태 변화와 EvidencePackage로 판정한다. 이를 위해 `realizedGwae`라는 두 번째 실행 필드나 별도 원장을 만들지 않는다.

실제 실행은 성공만 뜻하지 않는다. 확인된 실패·중단·부분 결과도 결과 코드와 상태 차이를 보존하면 실행 근거가 된다. 반대로 버튼 표시, 계획 문서, Graph Map 엣지, 배치 인스턴스, 자동 시험 fixture만으로 실행을 선언하지 않는다. 실행 뒤 생성된 행위 기록·상태 사본·이동 기록은 감괘(☵) 관계 데이터로 다음 조회와 기획에 흐를 수 있다.

## 오행 균형 순환

다섯 괘는 음양오행의 다섯 작용을 나타내는 내부 설계 점검 관점으로 함께 사용한다. 다음 도식은 자료의 존재와 추적 결손을 찾는 **설계 순환**이며, 실제 Runtime 사건의 시간순서나 실행 스케줄러가 아니다.

| 오행 | 괘상 | 개발 순환에서의 주 역할 |
| --- | --- | --- |
| 목 | 진괘(☳) | 새 WI 후보가 자라고 실제 행동·상태 변화가 발생하는 단계 |
| 화 | 리괘(☲) | 기획 결과물이 플레이 의미·선택·결과를 밝혀 질서를 제공하는 단계 |
| 토 | 간괘(☶) | Graph Map이 안정 노드·엣지·경계와 전파 중단점을 세우는 단계 |
| 금 | 태괘(☱) | 배치 맵이 자산·시설·통행·시야를 선택하고 구체 공간으로 다듬는 단계 |
| 수 | 감괘(☵) | 이동·운송·관측·공공 데이터·플레이 기록이 출처와 계보를 가진 채 흐르는 단계 |

```text
목·진괘 WI
  → 화·리괘 기획 결과물
  → 토·간괘 Graph Map
  → 금·태괘 배치 맵
  → 수·감괘 이동·관측·결과 데이터
  → 다음 목·진괘 WI와 상태 변화
```

실제 Runtime의 인과는 `WI 실행 → 행위 기록·권위 상태·관측 데이터 → 후속 기획 또는 선택`처럼 나타날 수 있다. 이는 위 상생 도식과 경쟁하는 두 번째 파이프라인이 아니라, 실행 사건이 남기는 실제 시간순서다. 공공 데이터·Simulation 상태·플레이 기록도 필요에 따라 E1·E4·E6 등 서로 다른 시점에 들어올 수 있으므로 감괘 자료를 언제나 배치 뒤에만 생성되는 것으로 강제하지 않는다.

균형은 모든 WI에 다섯 객체를 억지로 만드는 뜻이 아니다. 한 PlayableLoop나 작은 개발 slice에서 필요한 단계가 서로 역추적되고, 적용 불가능한 단계에는 사유 있는 `NotApplicable`이 있으며, 어느 한 단계의 양으로 다른 단계의 결손을 가리지 않는 상태를 뜻한다.

- 목만 과다하면 실행 후보와 기능이 늘지만 기획·관계·배치 근거가 부족하다.
- 화만 과다하면 기획 문서는 많지만 구현 가능한 구조가 부족하다.
- 토만 과다하면 Graph 구조는 정교하지만 플레이 선택과 실제 공간이 비어 있다.
- 금만 과다하면 자산과 배치는 풍부하지만 WI·권위 결과와 연결되지 않는다.
- 수만 과다하면 데이터는 많지만 어떤 선택과 변화에 쓰는지 불명확하다.

기본 개발 단위는 하나의 대표 WI가 필요한 화·토·금·수 관점을 역추적할 수 있는 가장 작은 폐순환이다. 공간·시각 표현이 필요 없는 WI에는 Graph Map·배치 맵·자산을 강제하지 않고 사유 있는 기존 `NotApplicable` 판정을 사용한다. 다음 WI가 없는 종결·귀환도 유효한 폐루프가 될 수 있다.

각 문서·Graph Map·배치 맵·Evidence 원장의 기존 상태 코드는 그대로 사용한다. 오행 관점별 현황표를 만들 때는 그 상태를 인용할 뿐 `Ready`·`Conditional`·`Blocked`를 오행 공통 성숙도 축으로 새로 정의하지 않는다. 오행 균형 자체를 E/G/H 승격이나 실제 Unity 성공으로 사용하지 않는다.

[E1~E7 수직 폐루프](E1-E7수직폐루프와E8-E10수평증거체계.md#e1e7과-오행-설계-순환의-관계)는 같은 WI·Goal·Session·Revision의 PlayableLoop가 계약부터 실제 입력·결과·귀환까지 성립했는지 입증한다. 오행은 설계 균형과 결손을 찾는 보조 관점이고, Evidence는 PlayableLoop의 실제 성숙도를 판정한다. 둘은 서로를 대체하지 않는다.

## 분류 원칙

1. 기존 WI를 괘별로 복제하거나 새 WI로 치환하지 않는다.
2. 실제 수행을 직접 일으키는 행위는 대체로 진괘(☳)로 두고 계획·지휘·학습·명상처럼 행위 자체의 본질이 다른 경우에만 해당 괘를 행위괘로 둔다. 세밀한 성격은 작용괘로 구분한다.
3. 범용 WI의 대상이나 도구가 실행 객체에 따라 바뀌면 하나의 괘를 강제하지 않고 `대상 객체 승계`로 둔다.
4. 점화·연료 보충·소화처럼 같은 WI 안에서 작업 코드가 의미를 바꾸면 `작업 코드별 작용괘`로 둔다.
5. 작용괘와 보조괘는 의미가 명확할 때만 둔다. 보조괘가 선택에 따라 발현되면 `상황별`로 표시한다.
6. 영역 의미가 균일한 WI는 검토된 영역 규칙을 재사용하고, 의미가 다른 WI는 개별 예외로 기록한다.
7. 괘성은 검색·비교·그래프 표시를 위한 메타데이터다. 상생·상극을 효율·품질·위험 수치로 계산하지 않으며 권위 판정 입력으로 사용하지 않는다.
8. 그래프 맵은 괘성을 WI 엣지의 탐색 메타데이터로 사용할 수 있지만, 괘성만으로 노드·배치·개발 작업을 자동 활성화하지 않는다.
9. 산출물 괘상은 `artifactGwae`로 분리하며 WI 괘성 필드에 복사하거나 WI 의미 판정에 사용하지 않는다.
10. 관계별 괘상은 `relationGwae`로 기록하고, 데이터의 출처·권위·품질은 `dataSourceKind`와 근거 필드로 별도 판정한다.
11. 사용자 기본 출력에서는 괘상을 접어 두고 플레이 의미·선택·대가·결과를 먼저 보여 주며, 요청·진단·검증 시에만 상세 괘상 메타데이터를 펼친다.
12. WI는 순환 관점에서 진괘 계열 실행 가능성으로 읽을 수 있지만 이를 새 schema 필드로 중복 저장하지 않는다. 실제 실행은 같은 판본의 기존 행위 기록·권위 상태·EvidencePackage로 판정한다.
13. 오행 균형은 작은 폐순환의 결손을 찾는 내부 관리 관점이며, 단계 수나 자료량을 같게 맞추거나 Evidence를 자동 승격하는 점수로 사용하지 않는다.
