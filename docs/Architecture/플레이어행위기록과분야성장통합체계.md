# 플레이어 행위 기록과 분야 성장 통합 체계

## 목적

플레이어 또는 NPC의 행위가 권위 세계 상태에 반영된 뒤 그 사실을 중립적인 `행위 발현 기록`으로 남기고, 플레이어 분야 성장은 그 기록과 효과 계보를 근거로만 적용한다. LH·실외 배치·실내 배치·Sky 같은 엔진은 이 파이프라인의 종속 단계가 아니라 자신의 생명주기에서 필요한 기록을 읽는 독립 소비자다.

이 체계는 플레이어의 행동을 기록하고 이해도·현장 숙련도·운영 숙련도로 해석하는 E1~E3 기반이다. Unity 화면, Synty 표현, 실제 Game View와 E7 완료를 주장하지 않는다.

## 권위 흐름

1. WI의 Preview는 후보와 비용을 계산하며 상태를 변경하지 않는다.
2. 명시적 Confirm과 기존 권위 규칙이 Task·Effect를 확정한다.
3. Effect 적용과 같은 권위 결과 계보에서 `Simulation행위발현Record`를 멱등 추가한다.
4. 분야 성장 규칙은 검증된 기록과 효과 수령 근거를 읽어 플레이어 Profile을 갱신한다.
5. 각 표현·배치 엔진은 `ISimulation행위기록Reader`를 자신의 준비·활성·재조립 시점에 조회한다.
6. 엔진은 자신의 파생 상태와 표현만 바꿀 수 있고 Simulation `WorldRevision`은 바꾸지 않는다.

행위 기록에는 엔진 이름을 넣지 않는다. 대신 `SurfaceChanged`, `ExteriorPlacementChanged`, `InteriorFixtureChanged`, `AtmosphereChanged`, `PlayerProgressChanged` 같은 변화 의미와 영향 공간을 남긴다. 따라서 새 엔진이 추가되어도 과거 권위 기록을 다시 작성하지 않는다.

## 행위 원장

`Simulation행위발현Ledger`는 다음 불변선을 가진다.

- `WorldRevision → WorldTick → 행위기록StableId` 순서의 추가 전용 tail을 유지한다.
- 기록 내용과 앞 기록 hash를 SHA-256 체인으로 묶는다.
- 같은 고유 식별자와 같은 내용의 재처리는 기존 기록을 반환한다.
- 같은 고유 식별자와 다른 내용은 충돌로 거부한다.
- 소비자는 WI, 변화 의미, 영향 공간과 cursor로 독립 조회한다.
- 체크포인트 이전 기록은 통합 세계 상태 hash와 마지막 기록 hash로 압축하고 이후 tail만 저장한다.
- 오래된 cursor는 조용히 누락시키지 않고 `RequiresCheckpointRebuild`를 반환한다.

외부 Provider 조회, 엔진 호출과 운영 DB 쓰기는 원장 책임이 아니다.

## 플레이어 분야 성장

첫 카탈로그 `player-domain-catalog.r1`은 16개 분야와 기존·신규 WI 65개의 결속을 가진다. 사람이 읽는 분야명과 세부 숙련은 한국어를 우선하고 Stable Code는 저장·호환에 사용한다. 기계 요약은 `eng/execution-ledgers/player-domain-proficiencies.json`에 둔다.

진척은 세 축을 섞지 않는다.

| 축 | 인정 근거 | 첫 Nature 사례 |
| --- | --- | --- |
| 이해도 | 승인 자료의 판본·hash·효과선과 적용 행위 기록 | 승인된 사냥 안전 자료 성찰 |
| 현장 숙련도 | 플레이어가 직접 수행한 권위 행위 기록 | 조우 전투 성공 또는 의미 있는 후퇴 |
| 운영 숙련도 | 플레이어 위임, NPC 완료, 플레이어 검토의 연결 계보 | NPC 현장 보급 제작 결과 검토 |

현장 결과는 성공 `+2`, 의미 있는 실패·후퇴/복구 `+1`, 취소·차단·기술 실패 `0`이다. 서로 다른 유효 행위에는 일일 상한이나 반복 감쇠를 적용하지 않는다. 같은 기록 또는 같은 기여 고유 식별자의 재처리는 중복 지급하지 않는다.

NPC가 업무를 완료한 사실만으로 플레이어 숙련도를 올리지 않는다. 플레이어가 명시적으로 위임했고, NPC 완료 기록이 그 위임을 참조하며, 플레이어의 `WI-REVIEW-01` 검토 기록이 위임과 완료를 모두 참조해야 운영 숙련도 기여가 성립한다.

## 개인화 경계

이해도는 승인된 사실을 숨기거나 권한을 확대하지 않는다. 모든 권한 있는 사실은 그대로 제공하고 강조 순서, 설명과 선택형 기회 후보만 조정한다. 전투·사냥 이해도가 기준에 도달하면 Nature 사냥 제안 후보를 만들 수 있지만 주변 몬스터의 기본 생성량이나 세계 난이도를 직접 바꾸지 않는다.

설비·에너지처럼 아직 실행 WI가 부족한 분야는 `AssetSeed`, 교역·수출처럼 계약만 있는 분야는 `ContractSeed`로 표시한다. 준비 상태는 플레이어 수치가 아니라 구현 증거 상태다.

## 저장·재생

`simulation-save.v28`은 바로 이전 저장 schema를 감싸며 다음 두 상태를 함께 봉인한다.

- `Simulation행위기록LedgerSnapshot`: 통합 체크포인트 + 이후 tail + 원장 상태 hash
- `Simulation플레이어분야ProfileSnapshot`: 분야·세부 숙련 진척 + 기여 계보 + Profile 상태 hash

둘 중 하나만 있는 저장은 거부한다. Replay hash는 기반 저장 hash와 두 상태 hash를 함께 포함한다. 복원할 때 원장 체인, 체크포인트, 분야 카탈로그 판본과 Profile hash를 검증하며 복원 후 같은 요청으로 재저장해도 같은 hash가 나온다. 과거 v1~v27 저장은 기존 방식으로 계속 읽는다.

## E와 Codex Goal 통합 관문

행위 기록 파이프라인은 Logic·Presentation과 별개인 세 번째 성숙도 축이 아니다. 모든 `PlayableUnit`의 `Loop-WI` 결속은 다음 순서를 가진 공통 통합 관문을 사용한다.

`Preview → Confirm → AuthorityCommit → ActionRecordAppend → PlayerProgressionApply/NotApplicable → ReturnProjection → 표현 엔진 ActionRecordRead → 표현`

- 논리 E5는 권위 Revision과 같은 Command 계보의 행위 기록이 있어야 통과한다.
- 분야 성장이 없는 WI도 단계를 생략하지 않고 판본화된 사유가 있는 `NotApplicable`을 남긴다.
- 표현 E5는 엔진이 권위 상태 사본 또는 행위 원장을 cursor로 읽고 WorldRevision을 바꾸지 않았음을 요구한다.
- 관문 실패는 새 Goal을 만들지 않고 같은 Goal의 가장 이른 Logic 또는 Presentation E를 다시 연다.
- E8은 원장·조건부 성장 hash와 비권위 trace digest의 LocalProcess·RemoteHost 반복 동등성을 확인한다.
- E9는 여러 폐루프의 행위 계보와 엔진 cursor 연속성을 확인하고, E10은 중복 기록·hash 불일치·cursor 재조립 실패를 제한 운영 지표로 관찰한다.

권위 대장은 `eng/execution-ledgers/playable-loop-engine-interaction-validation.json`이며 현재 16개 `PlayableUnit`, 55개 `Loop-WI` 프로필을 결정적으로 파생한다.

## 현재 구현 판정과 다음 관문

- 구현·시험됨: 중립 원장, 독립 cursor 조회, 멱등·충돌, 체크포인트+tail, 분야 세 축, Nature 세 fixture, v28 저장·복원·재저장 hash, Nature·Farm 일부·지역 위협 Application Adapter의 권위 결과 자동 append, 55개 파이프라인 프로필 소급 검증.
- 부분 구현: `WI-REVIEW-01`은 계약·대장·계보 판정까지이며 실제 Session Preview/Confirm Adapter는 후속 E3 조립 대상이다.
- 부분 구현: 공통 실행 파이프라인을 아직 사용하지 않는 WI Adapter는 프로필만 존재하며 E5에서 차단된다.
- 미구현: Unity 상태창과 강조 표현, 각 엔진의 실제 cursor 영속·재조립 연결, 새 파이프라인 revision의 Play Mode·Game View 검증.

다음 구현은 현재 Goal을 유지하고 `WI-NATURE-15`의 표현 엔진 cursor 소비를 연결한 뒤 v28 실제 입력·Save 재진입·Game View를 같은 revision에서 검증한다. 다른 미연결 WI는 각 Goal이 활성화될 때 같은 공통 실행 경계로 옮긴다.
