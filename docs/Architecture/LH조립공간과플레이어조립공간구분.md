# LH 조립 공간과 플레이어 조립 공간 구분

## 목적

H1~H4는 공간의 포함 깊이다. LH 조립과 플레이어 조립은 공간이 성립한 방식이다. 두 축을 섞지 않는다.

```text
공간 깊이: H1 → H2 → H3 → H4
형성 방식: LhComposed / PlayerComposed / HybridEvolving
```

기계 기준은 [`spatial-formation-modes.v1.json`](../../eng/world-seedbeds/spatial-formation-modes.v1.json)이다.

## 세 형성 방식

| 코드 | 의미 |
| --- | --- |
| `LhComposed` | 승인된 H 정의와 조립 계획을 LH가 셀 결과물로 준비한 기본 공간 |
| `PlayerComposed` | 플레이어의 권위 있는 Confirm으로 처음부터 성립한 공간 인스턴스 |
| `HybridEvolving` | LH 기본 공간 위에 플레이어의 배치·제거·복구·연결 변경이 누적된 공간 |

`originModeCode`는 H 설계 지식의 출처다. `ContentSourceCode`는 LH 셀 공급원이고 `PlacementAuthorityCode`는 배치 근거다. 어느 것도 플레이어가 공간을 만들었다는 이력을 대신하지 않는다.

## H 단계별 플레이어 조립 범위

| H | LH | 플레이어 |
| --- | --- | --- |
| H1 작업공간 | 직접 조립 가능 | 오두막·작업대·울타리·밭처럼 직접 Preview·Confirm 가능 |
| H2 블록 | 직접 조립 가능 | 필요한 H1과 연결구가 모이면 성립 판정 |
| H3 경관 | 직접 조립 가능 | 여러 H2와 플레이 폐루프가 유지되면 성장 판정 |
| H4 지역 | 초기 세계 구성에 필요 | 새 지역을 직접 배치하지 않고 기존 지역 내부만 변화 |

따라서 플레이어가 오두막 하나를 설치하면 즉시 H3를 만들었다고 하지 않는다.

```text
H1 오두막 Confirm
→ 휴식·보관 능력 활성화
→ 다른 H1과 연결
→ H2 안전 생활핵 조건 충족
→ 채집·위협·회복의 반환 흐름 유지
→ H3 생활·조우·방어 경관 성장 판정
```

플레이어는 H2·H3의 목표를 선택하고 필요한 H1 조합을 유도할 수 있다. 다만 상위 공간의 이름과 성립 여부는 H1 집합·연결구·용량·통행·반환 폐루프를 검사한 권위 판정으로 남긴다. 이 구분 덕분에 플레이어의 창작 자유와 Save/Replay 가능한 세계 상태를 동시에 유지할 수 있다.

## 재료 선택에서 공간 성장까지

플레이어 조립은 Prefab 선택이 아니라 자원과 행동의 권위 있는 흐름이다.

```text
필요와 목표 인지
→ 조립법·대안 비교
→ 세계 자원·Lot 획득
→ 운반·보관·배정
→ 위치·회전·연결 Preview
→ Confirm과 자원 예약
→ Task·권위 시간 진행
→ H1 공간 인스턴스 성립
→ H2/H3 조건 재평가
→ 능력·안전·동선 변화와 다음 선택 피드백
```

| 항목 | 의미 | 다른 항목과 혼동하지 않을 것 |
| --- | --- | --- |
| 세계 자원·Lot | 나무·돌·작물처럼 획득·소비·이동하는 상태 | Synty 메시나 장식 Prefab |
| 조립법·비용 | 필요한 자원·도구·시간·장소 조건 | 완성 H1 정의 |
| 배치 Preview | 아직 상태를 바꾸지 않는 후보 형상 | Confirm·완료 결과 |
| H1 공간 인스턴스 | 작업 완료 뒤 세계에 남은 권위 상태 | Unity GameObject 하나 |
| H2/H3 성장 판정 | H1 집합과 폐루프가 충족한 상위 의미 | 플레이어가 임의로 붙인 이름 |
| 시각 자산 | 공간 상태를 표현하는 Prefab·재질·애니메이션 | 자원·공간 능력의 권위 |

LH가 준비한 자원 위치와 기본 H1을 플레이어가 발견해 활용할 수 있고, 플레이어가 만든 H1을 LH가 다시 스트리밍할 수도 있다. 이때 자원 획득·비용·공간 형성 계보와 화면 조립 책임은 합쳐지지 않는다.

## LH의 책임

LH는 H 의미를 새로 발명하지 않는다. 승인된 기본 조립과 현재 Simulation 변경분을 결합해 필요한 셀을 준비한다.

```text
H 정의·조립 계획
      +
LH 기본 셀 계획
      +
플레이어 공간 변경분
      ↓
현재 셀 조립 결과
```

플레이어가 만든 오두막을 LH가 다시 스트리밍해 보여줄 수는 있지만, 그 오두막의 형성 방식은 계속 `PlayerComposed`다. LH가 화면에 다시 조립했다는 이유로 `LhComposed`로 바뀌지 않는다.

## 권위와 계보

Unity GameObject 배치는 공간 성립 근거가 아니다. 플레이어 조립은 다음 계보를 가진 Simulation 상태여야 한다.

- 공간 인스턴스 고유 식별자
- 참조한 H 정의
- 부모 H 공간 인스턴스
- 실행한 Actor와 Command
- 기본 조립 hash와 누적 변경분
- 성립한 `WorldRevision`

이후 Save/Replay가 같은 공간 형성 결과를 재현하고 Unity가 그 상태를 투영한다. 형성 방식만 기록했다고 E5·E7이 자동 완료되지는 않는다.
