# Ssalddel 2.0 Checklist

- [ ] 운송 의뢰는 확인된 원천 구매·출고 원장을 참조합니다.
- [ ] 화주, 기사, 운송사와 플랫폼의 책임이 구분됩니다.
- [ ] 허가·보험·약관 확인 전 운영 실행이 차단됩니다.
- [ ] 추천·배차 판단 이유와 거절 사유를 감사할 수 있습니다.
- [ ] 상태 전이는 권한, 현재 상태와 멱등성을 검증합니다.
- [ ] 상차·하차·인수 증빙이 원장과 같은 stable ID로 연결됩니다.
- [ ] 주소·연락처·위치와 계좌는 필요한 단계에만 최소 노출됩니다.
- [ ] 실제 결제 보관·운임 수취·기사 지급은 별도 승인 없이 실행되지 않습니다.
- [ ] 운송 완료 뒤 `2.5` 입고·배분 대상에 안전하게 인계됩니다.
- [ ] 운송 API·기사 명령 메타데이터가 제품 버전 `2.0`을 사용합니다.

## Web 배포 후보 화면

- [x] 화주 운송 의뢰 작성은 화물·운송·절차·최종 확인 화면으로 책임을 분리합니다.
- [x] CSV 대량 의뢰 화면은 형식 미리보기만 제공하고 등록 가능 상태나 서버 저장을 가장하지 않습니다.
- [x] 화주 의뢰 상세는 요약·이력·결제 상태·증빙 화면으로 책임을 분리합니다.
- [x] 기사 추천은 목록·상세·수락/거절 판단 화면으로 책임을 분리합니다.
- [x] 운행 시작 화면은 운행 세션과 사용자가 확인한 위치 갱신만 맡고 추천 수신 연결은 추천 목록으로 분리합니다.
- [x] 현재 운송 화면은 조회·다음 단계 안내만 맡고 현장 상태 Command는 실행하지 않습니다.
- [x] 운송 이력 화면은 완료·취소·중단 기록만 조회하고 상차·하차 Command route를 노출하지 않습니다.
- [x] 기사 상차와 하차는 서로 다른 stable 운송 ID route와 ViewModel을 사용합니다.
- [x] 이전 통합 증빙 route는 상태를 바꾸지 않고 전용 상차·하차 화면만 안내합니다.
- [x] 브라우저 추천 타이머는 만료를 표시할 뿐 자동 거절 Command를 보내지 않습니다.
- [x] 알림 연결 화면은 고정 샘플을 최근 알림으로 가장하지 않고 실제 payload만 전용 화면으로 연결합니다.
- [x] 레거시 결제·정산 진입 화면은 결제·입금·후불·현장지급 Command를 직접 실행하지 않습니다.
- [ ] 영속 기사 알림 목록 API와 읽음 상태 원장을 연결합니다.
- [ ] 인증된 화주→기사 전체 흐름을 실제 브라우저와 서버 원장으로 다시 검증합니다.
- [ ] 허가·보험·약관과 운송 수행자 운영 승인을 갖추기 전 `Operational` 전환을 금지합니다.
