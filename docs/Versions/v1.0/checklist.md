# 문화교통 1.0 Checklist

- [x] 로그인 없이 가상 이웃과 저장 없는 체험 공동구매를 진행하고, 실제 수요는 별도 화면에서 다시 확인합니다.
- [x] 음식·재료 상세에서 공동구매 수요 등록까지 한 흐름으로 이동합니다.
- [x] 비로그인 탐색과 로그인 후 수요 저장 경계가 분리됩니다.
- [x] 수요 등록·변경·철회가 사용자 소유 범위와 멱등 키를 검증합니다.
- [x] 동일 품목·지역·수령 조건의 수요가 결정적 규칙으로 집단화됩니다.
- [x] B2B와 B2C가 구매 의향별로 선택되고 거래유형·가격 기준·수량 단위별로 분리 집계됩니다.
- [x] 기존 B2C 자동집단 ID를 유지하며 B2B는 구매 조직 문맥과 계약 전 검증 상태를 보존합니다.
- [x] 집단화 미리보기는 저장 전 입력·배치 이유와 예상 결과를 설명합니다.
- [x] 공개 응답에 개인 주소, 연락처, 결제 정보와 내부 식별자가 노출되지 않습니다.
- [x] 목표 수량 미달, 모집 종료, 철회와 오류 상태가 구분됩니다.
- [x] 결제·계약·수입 신고·운송 의뢰·자동 배차가 실행되지 않습니다.
- [x] Web과 미국 판매 페이지가 같은 서버 집단화 계약을 사용합니다.
- [x] 핵심 API·화면 메타데이터가 제품 버전 `1.0`을 사용합니다.
- [x] `Simulation` 전용 1.0 배포 프로필이 1.5 이후 기능을 명시적으로 차단합니다.
- [x] 서버 image·Web·Compose·배포 script를 하나의 CI 산출물로 만드는 절차가 있습니다.
- [ ] 원격 CI에서 1.0 배포 산출물과 통합 test의 첫 녹색 증적을 확보합니다.
- [ ] 보호된 staging에서 migration·backup 복구·rollback rehearsal 증적을 확보합니다.
