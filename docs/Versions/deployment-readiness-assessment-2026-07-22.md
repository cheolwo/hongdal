# 버전별 배포 준비도 평가

평가 기준일은 2026-07-22이다. 이 문서는 코드, 버전 체크리스트, 기능 플래그, 빌드·테스트 결과와 운영 문서를 근거로 한 내부 공학 평가이며 법률·인허가 적합 판정은 아니다.

## 결론

- 지금 배포 목표는 `0.0 커뮤니티 기반 + 1.0 비구속 공동구매 수요 모집`으로 제한한다.
- `1.0`은 결제·계약·주문 확정·수입 신고·운송 지시를 만들지 않는 `Simulation` 폐쇄형 베타까지만 허용한다.
- `1.5` 이후 기능은 관리자 연구·시뮬레이션 화면으로만 배포하고 운영 기능 플래그는 계속 끈다.
- 실제 금전 수취, 구매 확정, 수입, 운송, 창고, 배달은 각 버전의 운영 게이트와 별도 법무·인허가 검토를 통과한 뒤 연다.

## 평가 방법

총점은 100점이며 다음 다섯 항목을 평가한다.

| 항목 | 배점 | 판단 기준 |
| --- | ---: | --- |
| 빌드·산출물 | 20 | 버전 솔루션, 경고 없는 재현 빌드, 배포 산출물 |
| 제품 흐름 | 25 | 버전 목표의 시작부터 종료까지 이어지는 사용자 흐름 |
| 데이터·안전 | 20 | 권한, 소유권, 멱등성, 개인정보 최소화, 기능 차단 |
| 테스트 근거 | 20 | 단위·통합·E2E·회귀 테스트와 전체 녹색 상태 |
| 운영 준비 | 15 | CI/CD, 마이그레이션, 헬스체크, 비밀, 백업·복구, 관측 |

점수와 무관하게 금전·계약·인허가·개인정보 운영 게이트가 열려 있으면 실제 영업 배포는 `No-Go`로 판정한다.

## 측정 근거

- `Ssalddel.v0.0.slnx`와 `Ssalddel.v1.0.slnx`는 격리된 `Release` 산출물 경로와 `UseSharedCompilation=false` 조건에서 각각 경고 0개, 오류 0개로 통과했다.
- `v1.0` 솔루션은 핵심 주문자 앱인 `OrdererApp`을 포함하고 후속 운송 단계의 `DriverApp`, `DriverApp.NaverMaps.Android`를 제외한다. 이 구성을 고정하는 아키텍처 테스트도 통과했다.
- 전체 테스트 2,788개가 실패·건너뜀 없이 모두 통과했다. 이전 커뮤니티 ViewModel 실패 2건도 해결됐다.
- 음식·재료 문맥에서 실제 `공동구매실행Service`를 지나 API 메서드·경로·멱등 헤더까지 이어지는 미리보기 → 비구속 저장 → 철회 세로 흐름 테스트가 추가됐다.
- `GroupPurchaseDemandWorkflow`가 `1.0` 수요 모집만 열고 `CustomsAndTradeDataWorkflow`, 운송, 창고, 판매·인력 기능은 열지 않는 분리 계약과 호환 별칭 테스트가 통과했다.
- 테스트 프로젝트에서는 여전히 `WebApplicationFactory`, Testcontainers, Playwright 같은 실제 API·브라우저 E2E 기반을 확인하지 못했다. 새 세로 흐름도 프로세스 내부 계약 테스트이며 실제 DB·브라우저 E2E를 대체하지 않는다.
- Docker Compose, MySQL·MongoDB·Redis, Serilog, `/health/live`, `/health/ready`, 일회성 DB 초기화 명령과 155개 마이그레이션 관련 파일은 존재한다.
- `.github/workflows/release-readiness.yml`이 두 버전의 워크로드 복원, 격리 `Release` 빌드, 전체 테스트, 서버·최적화 WebAssembly 게시, 산출물 업로드, Compose 검사와 Docker 이미지 빌드를 강제한다. 같은 명령은 로컬에서 모두 통과했지만 GitHub 호스티드 러너의 첫 실행 증적은 아직 없다.
- `global.json`은 .NET 10 SDK 계열을 고정하고, 서버와 최적화 WebAssembly 게시 산출물 및 `ssalddel:release-readiness` 이미지가 생성됐다.
- 기본 운영 설정은 `CommunityTrustWorkflow=true`, 나머지 후속 기능은 `false`, `SsalddelExecution:Mode=Simulation`이므로 미완성 기능의 우발 실행은 기본적으로 차단된다.

## 이번 보완 완료

1. `Ssalddel.v1.0.slnx`에서 운송 앱을 제거하고 `OrdererApp`을 포함했다.
2. `GroupPurchaseDemandWorkflow`를 `1.0` 수요 모집 전용으로 분리하고 기존 `GroupPurchaseImportWorkflow`는 호환 별칭으로 제한했다.
3. 커뮤니티 실패 테스트를 해결하고 전체 2,788개 테스트를 녹색으로 만들었다.
4. 음식·재료 탐색 수요의 미리보기·저장·철회를 실제 UI 서비스와 API 경계까지 검증했다.
5. 버전별 `Release` 빌드·테스트·게시·Compose·Docker 이미지 생성을 GitHub Actions 게이트로 추가했다.

## 남은 공통 P0

1. `1.5`, `2.0`, `2.5`, `3.0`, `3.5`도 독립 솔루션 슬라이스로 만든다.
2. MySQL·MongoDB·Redis를 실제로 띄운 API 통합 테스트와 브라우저 E2E를 추가한다. 샘플 fallback은 릴리즈 검증에서 반드시 끈다.
3. 스테이징에서 일회성 마이그레이션, `/health/ready`, 로그·알림, 외부 백업과 복구 훈련을 한 번의 릴리즈 리허설로 검증한다.
4. 운영 환경에서 `AllowedHosts`, TLS, Key Vault 또는 동등한 비밀 저장소, 속도 제한, 관리자 권한 검토와 개인정보 삭제·보유기간 작업을 강제한다.

## 버전별 보완 순서

### 0.0

1. 게시·댓글·신고·차단·이의·삭제와 동의 철회를 실제 DB·브라우저 E2E로 검증한다.
2. 공개 게시물에서 주소·연락처·정확한 위치가 노출되지 않는 회귀 검사를 추가한다.
3. 스팸·반복 요청 속도 제한과 운영자 감사 로그를 릴리즈 게이트에 넣는다.

### 1.0

1. 현재 구성·계약 테스트로 완성된 음식 탐색 → 음식 상세 → 재료 상세 → 비구속 신청 → 모집 현황 → 철회를 실제 브라우저로 반복 검증한다.
2. 동일 사용자 재시도, 여러 사용자 동시 신청, 목표 충족, 마감 미달과 철회를 실제 MongoDB 통합 테스트로 검증한다.
3. 공개 집계 응답에 사용자 식별자·주소·결제 정보가 절대 포함되지 않는 계약 테스트를 유지한다.
4. 폐쇄형 베타에서는 결제·주문 확정·수입·운송 기능 플래그를 모두 끄고 화면에도 비구속 경계를 반복 표시한다.

### 1.5

1. 기업·공급자 자료에 원출처 URL, 확인 시각, 국가, 사업자 식별 근거와 검토자를 저장한다.
2. 견적을 통화·단위·MOQ·포장·납기·유효기간·Incoterms 후보 단위로 버전 관리한다.
3. HS·HTS는 확정 코드가 아니라 후보·근거·신뢰도·전문가 검토 상태로 관리한다.
4. 한국 MFDS와 미국 FDA·CBP 관련 준비 항목, 판매자·수입자·관세사·플랫폼 책임을 국가별로 분리한다.

### 2.0

1. 확인된 구매·출고 원장 없이는 운송 의뢰를 만들 수 없게 한다.
2. 운송주선·운송 수행 주체의 허가, 보험, 약관과 책임 확인을 운영 설정과 승인 기록으로 만든다.
3. 배차·수락·상차·하차·인수·취소 상태를 stable ID, 권한, 멱등성, Outbox와 감사 이벤트로 검증한다.
4. 실제 운임 수취·기사 지급·정산은 별도 승인 전까지 비활성 상태를 유지한다.

### 2.5

1. 재고 총량, 예약, 가용, 불량, 출고 수량 불변식을 DB 동시성 테스트로 닫는다.
2. 창고 소유·배정 범위와 작업자 역할을 모든 쓰기 명령에서 검증한다.
3. `2.0` 운송 인계부터 입고·검수·적재·피킹·포장·출고까지 실제 DB 통합 흐름을 만든다.
4. 내부 재고 원장과 외부 판매상품·채널 발행을 계약과 기능 플래그로 분리한다.

### 3.0

1. 음식점 주문 접수, 조리, 픽업 준비, 기사 인수, 고객 완료의 독립 상태 전이를 만든다.
2. 음식 배달 배차와 `2.0` 화물 운송의 차량·요금·SLA·정산 정책을 분리한다.
3. 취소·품절·조리 지연·배달 실패와 환불 책임을 운영 시나리오로 검증한다.

### 3.5

1. 마트 주문 전에 `2.5` 재고 예약과 가용 수량 차감을 원자적으로 처리한다.
2. 보충·피킹·포장·배차 대기의 인계 조건과 묶음 배송 판단 근거를 검증한다.
3. 음식점 일반 배달과 마트 즉시배송의 재고·수수료·정산·취소 정책을 분리한다.

## 권장 릴리즈 순서

1. `0.0` 커뮤니티 기반을 내부 파일럿으로 안정화한다.
2. `1.0`만 켠 폐쇄형 베타에서 비구속 수요 모집의 전환율, 철회율, 모집 충족률과 운영 문의를 측정한다.
3. 수요가 반복적으로 확인된 재료에만 `1.5` 공급·가격·HS 검토를 붙인다.
4. 실제 확정 구매와 이동 필요가 검증된 뒤에만 `2.0` 운송 준비로 넘어간다.
5. 반복 입고·배분 수요가 확인된 뒤 `2.5`, 음식점 배달은 `3.0`, 마트 즉시배송은 마지막 `3.5`로 연다.

현재 최우선 릴리즈 후보는 **85점의 `1.0 Simulation 폐쇄형 베타`**다. 버전 솔루션 재구성, 전체 테스트 녹색과 자동 빌드·게시·이미지 게이트는 완료했다. 실제 DB 통합 테스트, 음식·재료부터 철회까지의 브라우저 E2E, GitHub 호스티드 러너 첫 녹색 실행과 스테이징 복구 리허설이 끝나기 전에는 일반 공개 운영으로 승격하지 않는다.
