## 수용된 HTTP 계약

기존 `국제농수산가격수집Controller`의 0.0·CommunityTrust·Community·Authoring 메타데이터와 `서버관리자전용` 정책을 재사용했다. 인접 Controller의 `exception.Message` 응답 방식은 비밀 노출 위험 때문에 복제하지 않았다. 개발에 아래 계약을 먼저 반환하고 수용 회신 후 전용 구현을 마쳤다.

| 요청 | 기존 서비스 소비 | 결과 |
| --- | --- | --- |
| `POST /api/v1/admin/content/nongsaro-potato/collections` | `CollectAndArchiveAsync(false, cancellationToken)` 한 번 | 서비스 반환 후 200 상태 요약. 요청 본문/승인 flag 인자는 없음. 기존 승인본 재사용 여부는 서비스 결과를 그대로 표시하며 false 호출 자체가 새 승인/기존 승인 취소를 뜻하지 않음 |
| `GET /api/v1/admin/content/nongsaro-potato/latest-approved` | `최신자료승인조회Async(cancellationToken)` 한 번 | 승인 자료는 200, null 또는 승인되지 않은 반환은 고정404. 자체 수집이나 과거 승인본 fallback 없음 |

200 응답은 같은 파일의 `농사로감자자료상태Response` 5필드: `ArchiveId`, `Revision`, `ApprovedForSimulationContext`, `RetrievedAtUtc`, `ArchivedAtUtc`다. 대상은 기존 감자 Profile 하나이고, 전체 Entity·ProfileJson·원문·URL 쿼리·hash·예외 문자열은 반환하지 않는다. 승인 Boolean은 기존 보관 상태이며 게임 규칙/제품 재표시 승인 의미를 새로 부여하지 않는다.

요청 취소는 시작 전과 await 이후 확인하고, 요청 토큰이 취소된 `OperationCanceledException`은 전파한다. 요청 취소가 아닌 제공처 timeout/검증/기타 서비스 실패는 고정 503 ProblemDetails로 응답한다. POST 오류는 commit 전후를 확정할 수 없어 **저장되지 않았다고 단정하지 않으며 자동 재시도도 하지 않는다**. GET 오류503과 미확보404를 구분한다. 예외 원문 로깅은 추가하지 않았다.

## 작성한 시험과 실제 검증

시험 파일은 **직접 호출 17사례 + 루프백 HTTP 6사례**, 총23사례를 작성했다. 직접 호출은 인증 검증 증거가 아니다.

- 직접 호출: 정책/route/version 선언·입력 계약, false/토큰 단회 전달, 안전한 5필드 요약, 승인 조회, 미확보/보류404, 시작 전/처리 중 취소, 제공처·검증·timeout·예기치 않은 오류의 고정503/비노출/재시도 없음.
- 루프백 HTTP: 빈 시험 호스트의 Kestrel/MVC/인증 미들웨어와 가짜 Archive를 사용하여 GET/POST 각각 익명401·비관리자403·관리자200을 확인하도록 작성. POST에 승인 true 쿼리/본문을 보내도 서비스에는 false가 전달되는지 검사한다. 시험 인증 정책은 기존 관리자 역할 요구를 재현하지만 production 인증/DI/로그인·외부 제공처·DB 검증은 아니다. 새 TestServer 패키지/프로젝트 수정은 없다.

**23사례 실행과 소비 컴파일은 아직 하지 않았다.** 현재 구 worktree의 최신 참조 부재와 공유 빌드 금지 때문에 테스트 통과 수로 보고하지 않는다. 로컬 PowerShell에 포함된 Roslyn 5.0 구문 파서로 두 C# 파일의 문법 진단0을 확인했으며 이것은 타입/DI/HTTP 실행 검증이 아니다. 처음 SDK Roslyn을 직접 로드하려던 시도는 이미 로드된 어셈블리와 버전 충돌했으므로 사용하지 않고, PowerShell의 Roslyn을 명시적으로 로드해 재검증했다.

세 파일의 실제 hash·길이/공백·문서 링크, 입력/응답 제한, 기존48파일 보존을 전용 로그로 검사한다. 이전 D424/D425를 비롯한 연구 파일·원자료는 그대로다. 로컬 보존/검증 기록은 `artifacts/local/game-data-research/d424-server-collection-r1/` 아래만 쓰고 공유 기록은 만들지 않는다.

## 실제 축적을 이어갈 실행 순서와 남은 조건

1. 개발이 두 C# 파일을 최신 서비스와 함께 소비 컴파일하고, 위 전용 시험을 실행한다. 작성한 HTTP시험의 fake 정책과 실제 서버의 관리자 인증/기능 관문을 구분해 확인한다.
2. 개발이 기존 ASP.NET 실행 주소, **명확히 격리된 승인 시험 DB**와 스키마/마이그레이션 준비, 사용 가능한 관리자 인증 방식, 농사로 자격의 안전한 서버 설정 여부를 비밀값 없이 결속한다. 운영 DB를 대신 사용하지 않는다. 최신 승인 상태 설정은 별도 기존 검토 경계에서만 수행하며 POST에 승인 입력을 추가하지 않는다.
3. 자료 전문이 승인된 주소/범위에서 감자 기존 수집 경로를 단회 호출하고, 실제 수신·저장 결과를 각각 확인한다. 이 경로가 Profile 이외의 재해 조회도 호출한다는 서비스 범위를 실행 전에 함께 확인한다.
4. 독립 재조회로 같은 자료의 식별·판본·보관 시각을 대조한다. 수집만 하고 보류 상태이면 GET404가 정상일 수 있다. 미승인 자료의 저장 확인은 개발이 결속한 관리자 내부 검증 경계로 하고, 승인 없는 조회를 위해 GET 관문을 느슨하게 하지 않는다.
5. 동일 범위 재수집 후 내용 판본/저장 행이 불필요하게 늘지 않는지 확인한다. 오류·취소는 저장 여부를 먼저 별도 확인하며 자동 반복하지 않는다. 실제 API 수신, 실제 MySQL 저장, 독립 조회, 중복 방지에 각각 근거를 남긴다.

현재 실제 서버 주소/시험 DB·자격·관리자 실행 경로가 이 담당에 결속되지 않아 **외부 수집0·DB/MySQL0·독립 실재조회0·실제 재수집0**이다. 이 실행 단계만 미완료이며 코드 준비는 계속 진행해 반환했다. 사용자에게 반복 로그인이나 비밀값 전달을 요구하지 않는다.

MFDS 브라우저 1회 성공 보고는 서버 축적 근거로 사용하지 않았다. 노출된 키·결과 탭·이전 도구 출력·실응답·보안 observation 파일을 탐색/추출/공유하지 않았으며 MFDS 호출0이다. 마감 중 개발이 전달한 사용자 정정에 따라 기존 키 계속 사용 선택은 재발급 필수 조건을 대체했다. 그러나 키 전달/탐색/추출/재사용 승인은 아니며 전용 옵션·안전 입력/실행 경계도 미결속이다. 공용 키를 덮어쓰지 않고 승인된 서버 비밀 설정과 별도 한정 실행 배분을 기다린다. 운영 r4 읽기 hash는 당시 이력이고 후속 운영문서 hash 변화는 validation에 별도 기록하며 농사로 소유 확대 근거로 삼지 않는다.

구현 준비 인계는 전문→개발 통합→기획 순서다. 전체 축적 완료를 선언하지 않으며 다음 단계는 개발이 결속할 승인 환경의 제한 실행이다. 공용 서비스/시험·Program/DI/DbContext/프로젝트 파일·운영 SQL·Unity/Scene/Save/E·commit/push 변경0.
