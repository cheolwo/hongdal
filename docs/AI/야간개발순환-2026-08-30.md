## 한 회차의 완료 형태

현 상태·기준선/파일hash 확인 → 가장 영향 큰 결함 하나와 수용 기준 선정 → 소유 경로의 작은 수정 → 집중 시험/소비자 컴파일 → 필요 실제 Play·입력·Game View → 변경 전후 비교·결함 상태 갱신 → 재사용 모듈/패턴 문서에 적용 범위·제약·판본/검증 연결 → 다음 결함.

- 결함 기록은 기존 보고서/개발 통합 상태판을 재사용한다. 원인 미확정·재현·수정·자동시험 통과·실제 화면 확인을 구분하고 시험 횟수를 플레이 성공으로 대체하지 않는다.
- 화면은 같은 카메라/시간/배치 조건으로 전후 비교한다. 원자료는 artifacts/local에 두고 대표 근거의 경로/hash를 기록한다. 플레이어 입력, 건물 진입, 길 막힘, 나무/소품 겹침, 도구 접촉, 취소 후 복귀처럼 보이는 결함을 우선한다.
- 패턴의 재사용 검증은 승인된 조건 안에서 결정성·원본 불변·반복 조립/해제·중복 객체/리스너·지지/통행·누락 자산 거부를 확인한다. 고정 사례 통과를 임의 지형 전체 지원으로 주장하지 않는다.

## Unity·Blender와 안전 경계

- Unity Editor는 한 담당만 점유한다. 시작/종료 상태, Scene/Save/Packages hash와 dirty 원인을 확인한다. 본인 변경만 분리 가능한 경우만 저장하며 기존 미소유 dirty를 일괄 저장/폐기하지 않는다. canonical Scene을 추가 공식 Scene으로 대체하지 않는다.
- 사용자가 이번에 실제 반복 확인을 요청했으므로 화면 관련 수정에는 실제 Play/Game View 근거를 목표로 한다. 자동시험만 가능한 경우 그 차단을 기록하고 다른 진행 가능한 범위로 이동한다.
- Blender 보완은 복사본·전용 산출물·기존 연구/사용조건 범위에서만 수행한다. 보유 원본/공급사 파일을 덮어쓰지 않는다. 기존 Clip 재생·블렌딩·상태 연결을 우선하고 신규 키프레임/bake 등 기존 별도 조건이 미확인인 제작 방식은 자동 해제하지 않는다. 복귀 가능한 이전 후보를 보존한다.
- 새 플레이 의미·연구 기준선·생산 면적/자산 허용변환 변경, 권리 미확인 가공, 파괴적 Editor 복구는 해당 범위만 기획 판단 대기로 남긴다. 기술 연결에 새 게임 선택을 요구하지 않는다.
- 같은 실패를 같은 방법으로 세 번 반복하지 않는다. 로그·재현 조건·다음 안전 대안을 남기고 원인을 좁히거나 독립 작업으로 전환한다. 강제 종료·Scene 폐기·광범위 삭제·패키지 업그레이드·새 모델 다운로드·외부 유료 호출·Apify·운영 DB 변경·게시·commit/push는 하지 않는다.
- 기존 E 상한/연구·기획 hash는 유지한다. 밤이 끝났거나 시험을 많이 돌렸다는 이유로 E/패턴 사람 승인을 올리지 않는다.

## 아침 반환

실제로 바뀐 플레이/코드, 새로 검증한 패턴과 조건, 수정 전후 화면 경로, 자동시험과 실제 화면의 차이, 미완료/차단, 다음 우선순위를 개발이 종합해 기획으로 반환한다. 예약은 PC/Codex 실행 환경과 사용량 한도 안에서 동작하며 무중단 실행을 보장하지 않는다.
