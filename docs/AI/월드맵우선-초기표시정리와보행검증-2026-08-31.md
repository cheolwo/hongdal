# 월드맵 우선 — 초기 표시 정리와 실제 보행 검증

- 판본: `world-map-first-playable-ground.plan.r1`, D406, 2026-08-31.
- 상태: `ApprovedScopedWork`. 사용자 요청에 따른 현재 화면 정리·월드맵 기반 우선·실제 이동/화면 검증 범위 승인이다. 아직 대상 식별·정리·지도 완성·실제 이동을 수행한 결과는 아니다.
- 기준: [지도/배치/LH 역할](../Architecture/지도구성과세계자산배치분리.md), [D390 개별 성립과 전체 배치 분리](E5개별성립과전체배치책임분리-2026-08-31.md).

## 1. 사용자가 원하는 변화

Play 전 Game View에 사람·집·창고 등이 듬성듬성 흩어져 보이는 상태를 정리한다. 먼저 산·지면·길 등 공간의 큰 틀을 가진 월드맵을 마련하고 플레이어가 그 위를 돌아다닐 수 있음을 확인한다. 농장·Town·City 등의 건물/시설은 지도와 배치 역할을 나누어 그 위에 이어서 구성한다.

이는 기능이나 구매 자산을 폐기하자는 뜻이 아니다. 세계와 관계없이 노출되는 임시 전시·중복·초기 표시를 정리하고 실제 지역·상태·배치에 결속된 표현과 구별한다. 이번에는 첫 지형/보행 결과를 우선하며, 모든 건물과 계절 표현 완성을 선행 조건으로 만들지 않는다.

## 3. 먼저 현재 화면과 정확한 대상을 확인한다

개발은 현재 Scene/dirty·Editor 점유를 확인한 뒤 기존 공간 담당에게 단독 슬롯을 배분한다. 사용자가 말한 화면은 우선 **Stopped 상태 Game View**로 확인하고 Scene View는 객체 식별 보조로 사용한다. 초기 화면과 Play에서 실제 상태 공급 후 보이는 화면을 분리한다.

공간 담당은 화면상 대상의 경로/식별자·생성 주체·원본/복사본·Renderer/Collider·기존 WI/Actor 참조·재생성 경로를 조사해 다음으로 분류한다.

- 임시 전시/진단·중복·비결속 표시: 프로젝트 소유 표시 정책에서 가역 분리·비활성 또는 확인된 생성 복사본 제거.
- 실제 게임 대상이나 필요한 플레이어/기반: 원본·상태·연결을 보존하고 잘못된 초기 표시/위치만 수정.
- 소유/기능 불명: 사진과 정확 후보를 반환. 흩어져 보인다는 이유만으로 전체 Root·MissingScript·Actor를 삭제하지 않음.

기존 D378 구름/회랑 정리와 현재 대상을 같은 것으로 추정하지 않는다. 과거 이미지·hash는 참고 이력이며 현행 화면을 새로 확인한다. GameObject 표시 정리는 Simulation 객체 삭제나 Save 초기화가 아니다.

## 4. 월드맵의 큰 틀을 먼저 실행 가능하게 한다

월드맵/지도구성은 지형·지역/H·연결구·기준점을 제공하고, LH는 필요한 셀과 유효 지지면/관심 범위를 준비한다. 배치 엔진은 그 위의 산·식생 표현과 이후 건물·시설 배치 계획을 담당하며 Unity 조율자가 같은 판본을 적용한다. 산 지형의 높이/통행과 장식용 산 Prefab의 외형을 혼동하지 않는다. Sky는 빛·안개·기상 표현을 맡는다.

- 첫 대상으로 기존 지도 공급자·지형·AreaSet/계보·승인 공간계획과 기존 플레이어 입력을 재사용한다. 큰 구도에서 연속 공간을 보고, 그 안의 실제 통행 구간을 작은 실행 단위로 확인한다. 단순 평면이나 먼 배경 산만으로 탐험 가능한 월드맵 완료를 주장하지 않는다.
- 구체 크기·첫 범위는 현행 지형/셀/성능과 기존 승인 자료에서 찾아 정확 값·단위·판본·근거를 개발이 반환한다. ‘큼지막하게’라는 말로 임의 km 크기·새 도시 위치·seed·현실 지형 대응을 확정하지 않는다. 현행 범위에서 가능한 부분은 먼저 진행하고 새 지리/플레이 선택이 필요한 부분만 후보로 보고한다.
- 지도/상태 공급·셀 연결·지지면·표시/카메라/이동의 기술 결손은 기존 책임 안에서 좁게 수정한다. 배치 엔진을 우회하는 영구 수동 산개 배치나 모든 셀 무제한 상주로 연결 문제를 감추지 않는다.
- 후속 Farm·Town·City는 각자의 독립 업무 영역이다. 이 작업 순서가 영역 간 필수 경로나 전체맵 완성 전 개별 WI 구현 금지를 뜻하지 않는다. 이미 안정된 기능·후보·원문은 보존한다.
- D405 절기 색감은 후속 품질/표현 연결로 유지한다. 24절기 전체 팔레트 제작이나 새 Blender 자산 제작을 첫 지형·보행의 선행 조건으로 삼지 않는다.

## 5. 수정·저장 범위

이번 요청은 이 목표에 필요한 **현재 화면 진단, 제한된 코드/표시·배치 연결 수정, Editor/Play/실제 입력/캡처**를 허용한다. 개발은 실행 전에 기존 Approved 기획·필요 Accepted 연구·작업 명세에 D406 추가 승인과 정확 수정 경로·담당을 결속한다. 기존 세계 이동/공간 책임과 맞는 지원 작업을 재사용하며, Farm 명칭이라는 이유만으로 무관한 영역 권위를 그 Goal에 합치지 않는다.

프로젝트 소유 생성 경로/설정에서 초기 전시를 분리하여 다음 조립 때 불필요한 표시가 되살아나지 않도록 한다. 공급사 원본 Prefab/재질·캐릭터 파일·기존 실험 산출물 삭제는 제외다. 필요한 기본 Player·지면 Collider·WI 상태/소유 참조를 보존한다.

저장 Scene 변경은 시작 기준선·기존 dirty 원인·변경 전 바이트 사본·정확 대상 차이를 확보하고 **자기 변경만 분리되는 경우 해당 Scene만 저장**할 수 있다. 기존 미소유 dirty를 일괄 저장/폐기하거나 전체 Builder/SaveAssets를 실행하지 않는다. 예상 밖 차이·복구/덮어쓰기 대화가 있으면 그 저장만 보류한다. 분리 가능한 비저장 진단/다른 독립 작업은 계속할 수 있다.

삭제/비활성/위치 변경은 정확 대상과 이유·복구 방법을 보고한다. 새로운 게임 규칙/권위 상태 주입·Save 데이터 변경·새 공식 Scene·패키지 교체·강제 종료·미확인 가공·commit/push는 제외다. r129/야간 자동화 및 무관한 중지 작업은 재개하지 않는다.

## 6. 실제 완료를 보여줄 최소 증거

| 결과 | 확인할 내용 |
| --- | --- |
| 정지 초기 화면 전후 | 같은 카메라/조건에서 불필요한 표시가 사라졌는지. 가림·기능 누락도 함께 보고 |
| 월드맵 큰 구도 | 실제 지형의 첫 범위, 주변 산/숲/길과 현재 통행 가능한 범위. 원경 장식은 별도 표시 |
| 실제 보행 | 기존 Player가 실제 입력으로 이동·회전·경계 접근/가능한 통과·귀환. 입력/위치 변화와 지면 지지 확인 |
| 재진입 | Play 종료·재진입 또는 표현 해제/재적용 때 표시 중복·누락·셀 틈·낙하·초기 전시 재출현 여부 |
| 기술 결과 | 관련 집중 회귀/소비자 빌드, Console 신규 문제, 셀/객체·프레임 시간 등 확보한 성능 관측과 미측정 항목 |

Game View는 UI 포함 실제 출력으로 공간 담당이 캡처한다. 카메라 단독 Render/Scene View/정지 이미지로 실제 보행을 대신하지 않는다. 개발은 대표 PNG를 직접 열어 입력/구도/조건·미완료와 함께 기획에 반환한다. 한 회차에 모든 문제가 해결되지 않아도 정리·지형·입력의 실제 부분 성과를 먼저 반환한다. 이미 확인한 실패는 원인 또는 방식 변화 없이 반복하지 않는다.

## 7. 인계와 우선순위

- 기획: 이 승인 원문·기존 책임 문서·결정 기록. 구현·시험·Editor 직접 수행 안 함.
- 개발: 명세·수정 경로/소유/회귀/통합. 공간에서 현재 대상과 지도 입력을 받은 뒤 작은 수정→실제 화면으로 이어감.
- 월드·공간·배치: 현재 화면 식별, 필요한 공간 후속 연구, 단독 Editor·실제 입력/캡처. 애니는 실제 동작 문제가 별도로 생길 때만 요청.
- 첫 부분 반환은 `현재 대상 분류 + 기존 지도/플레이어 소비 경로 + 정확 첫 실행 범위`다. 이어서 `실제 정리 전후 + 지도 구도 + 보행 근거`를 반환한다. 기획 선택이 필요 없는 기술 연결을 새 사용자 재승인 대기로 만들지 않는다.
- D363의 배치 고도화 우선순위는 **이번 실행에서는 지도 기반/보행 우선, 건물 배치 후속**으로 조정한다. D364 역할·실행 순서와 D390 개별 성립은 유지한다. D403 자료조사/D404 접근 보고/D396 비의존 준비는 병행한다.
