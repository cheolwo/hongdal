## 1. 목적

[기획 목차](PLANNING.md)에 분리 등록된 현행 기획 판본을 읽어 기존 Graph Map 레벨 1·2·3에 증분 통합한다. D 번호 범위를 새 Graph Map 입력 원본으로 사용하지 않는다. 관련 D는 과거 결정 이력과 공통 원칙 대조에만 사용하고, 사건 의미는 이 문서가 지정한 기획 문서가 소유한다.

기존 안정 노드·엣지·제약·코드 결속은 유지한다. 최신 기획 때문에 의미가 실제로 바뀐 부분만 수정하고, 새 사건은 독립 하위 맵 또는 기존 하위 맵의 명시적 증분으로 추가한다.

## 3. 먼저 복구할 순환 결함

새 노드를 추가하기 전에 다음을 고친다.

1. `Superseded` 기획 인계의 당시 해시는 역사로 보존하고 현재 파일 바이트와 다시 같을 것을 요구하지 않는다.
2. 현재 활성·통합 인계만 현행 기획 판본과 SHA-256으로 신선도를 검사한다.
3. Graph Map 회귀의 공식 기대값을 현행 r6의 17노드·16엣지·15제약과 맞춘다.
4. 대체된 기획 인계 r5와 Graph Map r5를 가리키는 개발 인계는 현행 판본 기준으로 재판정한다.
5. 과거 해시를 현재 해시로 덮어써서 검사를 통과시키지 않는다.

복구 뒤 본체, 기획 인계, 개발 인계와 각각의 회귀가 함께 통과해야 한다.

## 4. 통합할 하위 맵

### 4.1 Farm 경계 순찰 — 첫 우선순위

기존 `gm-node:hans-mission-life-base` 뒤에 다음 플레이 관계를 증분한다.

```text
첫 경계 순찰 준비
  → 동물형·야수형 마수 무리 조우
  → 대응 / 이탈·귀환
  → 비정상 이동·상처·영역 흔적 조사
  → 더 깊은 위협 관문
```

별도 선택형 단서:

```text
한스 집의 관리된 검 관찰
  → 정체 의심 후보
  → 첫 순찰에서는 검 미사용
  → 이후 진짜 위기까지 공개 보류
```

레벨 2는 동물형·야수형 의미, 사람형 대체 금지, 자산 미확보, 한스의 검 지연 공개, 흔적이 배후 정답을 자동 확정하지 않음, 중단·귀환을 보존한다.

### 4.2 Hub 미도착 화물·회복·명상

기존 Hub 입고·차량·출고 노드를 재사용하고 다음 관계를 별도 사건 하위 맵으로 추가한다.

```text
도착 예정 확인
  → 미도착 인지
  → 기록·기사·도로·날씨·몬스터 단서 수집
  → 플레이어 가설과 근거 선택
  → 현장 확인
  → 문제 예방·NPC 안도·개인 회복
  → 선택적 명상
  → 실제 획득 조건을 통과한 영감·편린 증폭
```

기록이 정답을 계산하지 않고, 회복·명상·편린을 같은 결과에서 중복 복제하지 않는 제약을 둔다.

### 4.3 Town 견습 공방

기존 Town 생활 광장과 연결하되 공방을 Hub나 Farm의 필수 후속으로 만들지 않는다.

```text
실패한 작업대 관찰
  → 재료·가열·투입 순서에서 원인 후보 직관
  → 견습과 작은 시험 batch
  → 결과와 원인 확인
  → 다음 학습 / 떠나기
```

완제품 대리 제작, Recipe·편린·숙련·공방 소유 자동 지급을 금지한다.

### 4.4 거대 마수·적대 조직·분할 대응

첫 Farm 순찰 안에 조직 전체를 펼치지 않는다. `더 깊은 위협 관문` 뒤의 독립 하위 맵으로 두고 지휘·호위·지원·증원·회복·보급 노드와 실제 연결을 모델링한다. 연결을 실제로 차단하거나 분리했을 때만 종합 역량 재판정 후보가 생긴다.

## 5. 레벨별 통합 규칙

### 레벨 1

- 각 노드에 지금·여기·나·너·이렇게·결과·다음 선택을 기획 문서 절 참조로 연결한다.
- 기존 노드를 재사용할 수 있으면 새 노드를 만들지 않는다.
- 사건 순서와 실제 이동 가능성을 분리한다.
- Farm·Hub·Town의 독립 플레이를 영역 간 필수 순서로 바꾸지 않는다.

### 레벨 2

- 기존 배치 규칙과 제약을 먼저 재사용한다.
- 정확 거리·수량·시간·확률이 미정이면 새 수치를 만들지 않는다.
- 절기·집중·위협은 topology 노드가 아니라 조건 또는 overlay로 우선 검토한다.
- 자산 후보와 실제 배정, 파일 확인과 Scene 검증을 분리한다.

### 레벨 3

- 현재 코드 파일·assembly·심볼을 직접 확인한 결속만 추가한다.
- 승인된 계약이 없으면 `NoApprovedUnityBinding` 또는 가장 이른 재개 E와 함께 미결속으로 남긴다.
- 코드 파일 존재를 Scene wiring·Runtime·Game View 근거로 승격하지 않는다.

## 6. 반환 조건

Graph Map 작업은 다음을 기획에 한 번만 반환한다.

- 새 Graph Map 판본과 SHA-256
- 재사용·추가·수정한 레벨 1 노드·엣지
- 레벨 2 제약과 기존 배치 규칙 결속
- 레벨 3 코드 결속과 미결속
- 하위 맵·port·connector 변경
- 기획 인계·개발 인계·회귀 검사 결과
- 기획 선택이 필요한 차단과 기술 차단의 분리

중간 진행을 기다리지 않는다. 최종 상태는 `Integrated`, `Blocked`, `NoImpact` 중 하나다.
