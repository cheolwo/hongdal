# E5 개별 성립과 전체 배치 책임 분리 — 적용 계획

- 결정: D-390
- 판본: e5-local-realization-scope.design.r1
- 상태: Approved
- 승인: 사용자가 전체 배치 기준·개별 기능 E5·여러 기능 조화의 책임 분리 설명에 대해 2026-08-31 「그렇게 좀 리팩토링을 진행」하도록 요청했다.
- 기준: [논리·표현·결과 순환 방법론의 D390 절](../Architecture/플레이폐루프논리시각이중순환체계.md#전체-배치-기준과-개별-e5-성립의-책임-분리-d-390).
- 선행: [E5 준비 상태 검토](../Reports/E5성립조건과현재준비상태-2026-08-31.md), [D389 연결 사전 검사](Presentation-E4-E5연결사전검사-2026-08-31.md). 기존 승인 원문·hash는 변경하지 않는다.

## 1. 리팩토링 목적과 범위

전체 세계의 미완성 때문에 개별 기능의 실제 연결까지 무기한 대기하지 않도록 작업·의존성·증거의 범위를 정리한다. E5 정의를 낮추거나 배치만 되면 통과시키는 변경은 아니다. 게임 규칙·Simulation·Save·공개 API·기존 E값을 변경하지 않는다.

새 공간 엔진, 범용 조립기, E5.1 같은 단계, 중복 원장, 새 Goal을 만들지 않는다. 기존 명세와 작업 목록·표현 모듈·피드백에 책임 분리를 연결한다. 기존 E9는 E8 Core 둘 이상을 전제로 하는 영역 조화·사람 승인 단계로 유지한다.

## 2. 이번 반영 산출물

| 담당 | 산출물 | 완료 범위 |
| --- | --- | --- |
| 기획 | 기존 방법론의 책임 분리와 잔존 단일 WI WIP 문구 정합화, D390 승인 기록 | 운영 기준·추가 승인 문서 |
| 개발 | 기존 명세·작업 목록에 아래 정보가 어디에 있는지 대응하고 Farm 첫 단위에 결속 | 영향·의존성·부분 성과가 보이는 인계. 실제 Farm E5 아님 |
| 개발 | 필요한 경우에만 기존 관리자/생성 안내·검사의 좁은 보완과 회귀 | 문서·관리 검사와 게임 실행 검증을 분리 |
| 공간/애니 | 이번에는 기존 조사·근거를 읽기 재사용 | 새 Editor·가공·캡처를 자동 배분하지 않음 |

코드·시험·관리자·생성물·CURRENT_WORK/통합 상태판은 개발 스레드가 소유한다. 기획은 게임 코드나 관리 스크립트를 직접 수정·실행하지 않는다.

## 3. 기존 구조에 연결할 최소 정보

다음은 정보 요구이며 새 JSON 필드를 전부 추가하라는 뜻이 아니다. 이미 있는 필드를 먼저 사용하고, 부족한 부분만 선택적 설명/참조로 보강한다. 과거 명세에는 새 필드 부재만으로 일괄 실패를 만들지 않는다.

| 정보 | 기존 연결 위치 우선 | 필요한 의미 |
| --- | --- | --- |
| 소비할 전체 공간 기준 | 기획/Accepted 연구·명세의 공간 참조와 판본 | 현재 기능에 적용되는 영역·앵커·예약·접근·공유 제약. 새 좌표나 제약 발명 금지 |
| 작은 실제 성립 단위 | 기존 WI·workItem·명세 범위/제외 | 어떤 대상·행동·결과까지 처리하는가. 부모 폐루프 전체와 구분 |
| 실제 선행 의존성 | `dependsOnWorkItemIds`와 명세의 계약/차단 | 현재 단위가 소비하는 상태·공간·소유 조건만 선행으로 결속 |
| 후속 조화 항목 | 기존 피드백·다음 작업 설명 | 현재 실행에 영향 없는 장식·후속 품질/조화의 담당·검토 위치·영향 판단 근거 |
| 부분 성과 | 모듈 연결·구현/시험 참조·EvidencePackage | 준비/조립/입력/결과 중 실제 확인한 범위와 아직 미확인인 범위 |
| 변경 영향 | 기준 revision/hash·무효화 조건·피드백 대상 | 기준 변경 시 다시 확인할 소비자와 유지할 근거 |

‘후속 조화’ 분류는 차단 면제권이 아니다. 필수 통행·접근·상태 연결을 깨는 결함은 현재 단위의 차단으로 남겨야 한다. 영향 미확인은 영향 없음으로 취급하지 않는다.

## 4. 첫 적용: Farm 한 재배의 수확 상태 표현

기존 Farm Goal·WI-FARM-04 지원 범위를 재사용하고 현재 활성 WI/승격 상태를 임의 변경하지 않는다. D386 상태 준비, D388 후보 조사, D389 사전 검사와 같은 명세에서 연결한다.

개발은 기존 승인 자료에서 적용 공간·대상·판본 참조를 확인한다. 현재 세계와 고정 후보의 계보가 다르거나 참조가 부족하면 차이를 그대로 남긴다. 전체 Farm의 새 배치 완성이나 모든 시설 활성화를 선행으로 요구하지 않되, 현재 대상의 실제 지지면·접근·컴포넌트·권위 상태 결손은 제거하지 않는다.

현재 알려진 Logic E5 사본·제품 소비·상태/정확 자산 계열 대응·밭 컴포넌트 결손은 해당 범위의 실제 공백이다. D390에서 이를 해결했다고 간주하지 않는다. 주변 경관·다른 독립 WI의 미완성과 구별하는 것이 첫 적용의 목적이다.

방문자 등 다른 기능은 기존 계약/명세를 비교 입력으로 재사용할 수 있지만 새 Session·실제 배치까지 이번 범위를 넓히지 않는다. 한 재배 대상의 부분 증거로 전체 Farm 폐루프 E5를 선언하지 않는다.

## 5. D389와의 연결

D389 원문·판정 의미는 유지한다. Ready는 준비, Conditional은 필수 관측 미확보, Blocked는 확인된 필수 결손/불일치다. 이번 변경은 **어느 단위에 어떤 조건이 필수인지 명확히 하는 것**이지 Ready를 쉽게 만드는 것이 아니다.

진행 중 D389 묶음을 안전한 통합 경계에서 먼저 마칠 수 있다. 이후 이번 승인·hash와 실제 수정 경로를 결속한다. 공통 런타임 API를 반드시 변경하지 않으며 명세·작업 의존성·생성 설명만으로 표현 가능하면 그 범위에서 끝낸다.

## 6. 개발 검증과 수용 기준

기존 검사·Fixture를 우선 재사용한다. 관리 도구 변경이 없다면 코드 변경 없이도 명세 대조 결과를 반환할 수 있다. 필요한 자동 회귀는 개발이 수행한다.

1. 현재 대상의 필수 Session/판본/컴포넌트·접근 결손은 차단으로 유지된다.
2. 현재 기능을 깨는 공간 간섭을 후속 E9 항목으로 분류해 우회할 수 없다.
3. 영향 없음이 확인된 다른 장식·독립 WI의 미완성은 현재 작업의 허위 선행 의존성이 되지 않는다.
4. 준비·조립 등 부분 성공을 보존해도 부모 폐루프의 현재 E·모듈 Passed·통합 완료를 자동 변경하지 않는다.
5. 기준 변경은 영향받는 대상/증거에 한정해 재검토하고, 영향 미확인은 미검증으로 남긴다.
6. 선택적 보완이 없는 과거 명세의 읽기 호환과 기존 유효한 검사를 유지한다. 기존 ProtocolRevisionInvalid 같은 별개 실패를 숨기거나 이번에 무단 해결하지 않는다.
7. 다른 승인 작업의 진행 가능 여부를 개수나 전체 맵 완성 여부가 아니라 실제 계약·소유·승인으로 판단한다.

인계에는 변경 파일, 재사용/추가 정보의 대응, 검사 결과, 실제 E5 미연결 항목을 포함한다. 현재 시점의 소스/시험 검증과 실제 Scene·입력·Game View 증거를 분리한다.

## 7. 변경 전후와 유지 경계

| 이전에 혼동할 수 있던 표현 | 이번 기준 |
| --- | --- |
| 전체 맵이 미완성이므로 개별 E5도 대기 | 적용되는 전체 배치 기준은 준수하되 현재 대상의 필수 의존성만 차단 |
| 하나의 WI가 막히면 다음 구현도 대기 | 기존 Goal 안의 독립 승인 작업은 계속, 같은 파일 쓰기만 조율 |
| 한 밭이 보이면 농장 E5 | 작은 실제 성립 범위의 증거이며 부모 E5 판정은 별도 |
| 주변 문제는 전부 E9에서 해결 | 현재 기능에 영향을 주면 가장 이른 원인 E에서 해결, 실제 조화 판정만 기존 E9 관문 적용 |

이 승인은 위 범위의 기획·작업 관리 리팩토링과 개발 검증에 한한다. r129·야간 자동화·Editor·실제 캡처·Scene 저장/수리·신규 Blender 가공·외부 호출·commit/push는 재개하지 않는다. 승인된 플레이어 약속이나 공간 연구 기준을 바꿔야 한다면 해당 부분만 기획으로 반환한다.
