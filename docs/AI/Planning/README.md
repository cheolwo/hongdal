# 현행 기획 정본 경로

> 기획 표시명과 기존 내부 식별자를 구분한다. 사용자에게 보이는 이름은 관행적 `-001`을 생략하지만 기존 폴더·링크·기계 식별자는 유지한다. 새 일반 기획 ID는 `PLAN-{분야}-{주제}`로 만들며 세부 기준은 [기획 문서 독립 관리 체계](../../Architecture/기획문서독립관리체계.md#기획-표시명과-호환-식별자)를 따른다.


이 경로는 기존 기획 문서·문답·Q/D 이력을 삭제하거나 일괄 이동하지 않으면서, 앞으로 현행 기획의 정본 주소를 일정하게 만드는 진입점이다. 전체 목차와 현재 판본은 [기획 목차](../PLANNING.md), 운영 원칙은 [기획 문서 독립 관리 체계](../../Architecture/기획문서독립관리체계.md)가 소유한다.

## 표준 경로

새로 독립되는 기획과 단계적 이관을 마친 기획은 다음 주소를 사용한다.

```text
docs/AI/Planning/<기획 분야>/<PLAN-ID>/README.md
```

필요한 경우에만 같은 디렉터리에 `lineage.md`를 두어 과거 문서·Q·D·의미 ID와 유지·부분 대체·참조 관계를 설명한다. 빈 계보 파일이나 판본별 본문 복제는 만들지 않는다. 판본은 정본 `README.md`의 머리말과 Git 이력으로 관리한다.

분야 디렉터리는 `공통`, `스토리`, `게임플레이`, `시간`, `월드`, `그래프맵`, `배치맵`, `자료`, `표현`, `시스템`을 기본으로 한다. 기획 분야가 더 세밀해져도 안정 `PLAN-*` ID와 정본 주소를 불필요하게 바꾸지 않는다.

## 기존 경로를 존중하는 전환 규칙

현재 [기획 목차](../PLANNING.md)에 등록된 기획은 47개다. 기존 경로에서 관리하는 43개는 그 파일이 계속 정본이고, Town·City 첫 발견·Presentation E4 후보 풀·운영 서버→Unity 이관 4개는 이 표준 경로에서 새로 시작한 정본이다. 이 디렉터리를 만들었다는 이유만으로 기존 문서를 복사·이동하거나 링크를 바꾸지 않는다.

기획 하나를 새 경로로 이관할 때만 다음을 함께 수행한다.

1. 기존 본문의 안정 기획 ID·분야·판본·상태와 계보를 확인한다.
2. 새 표준 경로에는 현행 본문 하나만 둔다.
3. 기존 경로는 역사 원문으로 보존하거나 새 정본을 가리키는 짧은 호환 포인터로 남긴다.
4. [기획 목차](../PLANNING.md)의 현재 문서 링크를 새 정본으로 바꾼다.
5. 저장소 내부 역링크와 문답·Graph Map·개발 인계의 판본/hash 결속을 다시 검증한다.
6. 생성 색인은 해당 소유 작업에서 재생성하며, 갱신 전에는 `generated refresh pending`을 표시한다.

본문을 두 경로에 복제해 동시에 수정하지 않는다. 이관되지 않은 기존 기획은 `ExistingCanonical`, 새 경로로 이관을 준비한 것은 `CanonicalPathPrepared`, 목차와 역링크까지 검증한 것은 `CanonicalPathMigrated`로 구분한다.

## 현재 상태

- 표준 경로와 호환 전환 규칙: 확정
- 기존 경로 정본 43개: `ExistingCanonical`
- 표준 경로에서 새로 시작한 정본 4개: `StandardPathCanonical`
- 기존 문서를 새 경로로 실제 이관 완료한 기획: 0개
- 기존 문답·역사 자료: 원래 경로에서 보존
- 코드·Graph Map·Unity·Evidence 성숙도 변화: 없음

첫 실제 이관은 기획 의미가 아니라 경로·링크만 바뀌는 작은 표본 하나로 수행하고, 결과를 확인한 뒤 나머지 기획을 같은 방식으로 순환한다.
