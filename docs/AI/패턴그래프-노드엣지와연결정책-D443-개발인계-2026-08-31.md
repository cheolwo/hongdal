## 2. 노드와 엣지의 의미

노드는 해당 검토 규모의 **배치 인스턴스**를 나타낸다. 같은 농장 패턴 A를 두 번 사용하면 같은 패턴 정의를 참조하되 서로 다른 두 노드다. 구성 키/Prefab 이름을 개별 노드 식별자로 사용하지 않는다. 복합 농장의 내부를 펼칠 때는 기존 부모·자식/포함 관계를 사용하며 새 H 레벨을 만들지 않는다.

| 관계 | 의미 | 혼동하면 안 되는 것 |
| --- | --- | --- |
| 포함 | 어떤 작업 공간/객체가 어떤 패턴 안에 속하는가 | 포함 관계만으로 이동 경로나 H 성립을 만들지 않는다. |
| 이웃 | 외곽과 명시된 주변 범위에서 가까운가 | 가까워도 길·문·접근이 연결됐다고 보지 않는다. |
| 경계 접촉/전환 | 서로 맞닿는 면·완충 공간·경관의 전환이 호환되는가 | 경계 호환은 통행 허가나 실제 길의 존재가 아니다. |
| 통행 연결 | 출입/접근 지점을 어떤 방향·이동 종류의 경로로 연결하는가 | 장식 선, 공간 이름, 포함/이웃 엣지를 통행 엣지로 사용하지 않는다. |

관계 코드는 위 의미에 맞는 기존 계약 값을 우선 재사용한다. 부족할 때만 검토 전용의 선택적 관계/관측 정보를 추가하고 구형 엣지의 의미를 바꾸지 않는다. 지형·패턴 외곽·보호 영역과 관계 근거를 함께 기록한다. 미확인 외곽에서 파생한 이웃은 확인된 관계로 승격하지 않는다.

큰 패턴 외곽과 그 안의 자식 객체 외곽을 같은 레벨의 독립 점유로 중복 계산하지 않는다. 포함 그래프의 오류/순환은 거부하되, 정상적인 통행 순환로·귀환로는 순환이라는 이유만으로 거부하지 않는다.

## 3. 길이 없는 경우와 연결 의도

연결 **의도/요구**와 연결 **관측/검사 결과**를 분리한다. 개발은 기존 필드로 표현 가능하면 재사용하고, 검토 입력에 부족한 의미만 명시한다.

| 검토 정책/상황 | 처리 |
| --- | --- |
| 연결 필수, 경로와 필요한 근거 확인 | 해당 범위의 계획상 연결 검사 통과. 실제 Player 통행 증거는 아님. |
| 연결 필수, 알려진 막힘/끊김 | 실패. 다른 장식 점수로 상쇄하거나 기준을 낮추지 않는다. |
| 연결 필수이나 문·높이·폭·지지 정보 부족 | 미검사/불완전. 정보 부족을 실제 단절로 단정하지 않는다. |
| 연결 선택, 경로를 두지 않음 | 없음 자체는 실패가 아니다. 경로가 선언됐다면 그 경로의 정상성은 검사한다. |
| 명시적으로 분리된 구간 | 그 기획 범위에서 단절을 허용한다. 단절 사유와 관계를 보존하며 자동 도로를 만들지 않는다. |
| 연결 의도가 미정 | 미정으로 남긴다. 엣지가 없다는 이유로 선택형/의도된 단절로 자동 판정하지 않는다. |

명시적 통행 금지 관계가 있다면 검토 후보가 이를 연결하는지도 검사하되, 새 통행 금지 게임 규칙을 여기서 만들지 않는다. 기존 `AccessRequired` 같은 전체 입력의 단일 기본값만으로 모든 패턴 쌍에 동일 연결 요구를 부여하지 않는다. 새 검토 경로에서 관계별 요구를 구분하고 구형 기본 동작은 호환한다.

전체 노드가 하나의 연결 성분이어야 한다는 보편 조건을 추가하지 않는다. 기존 승인된 폐루프/작업이 요구한 시작→대상→복귀 경로, 필수 출입·접근 경로만 통행 그래프에서 검사한다. 전체 AreaSet의 필수 역할/기존 성립 조건을 약화하는 변경은 아니며 이번 검토가 그 전체 성립을 대신하지 않는다.

## 4. 그래프와 공간 형상을 함께 검사

엣지 한 줄이 존재하는 것만으로 길이 이어졌다고 하지 않는다. 통행 경로의 출입 방향·폭·높이/경사·지지와 점유/보호 구간을 D442 공통 검사에 연결한다. 지원하지 않는 대각/곡선·불완전 표본은 미검사로 남기며 강제로 직선화해 통과시키지 않는다. 새 길/교량을 만들거나 World 지형을 고치는 것은 이번 범위가 아니다.

규칙은 순서대로 연결하되 앞선 검증을 소급 과장하지 않는다.

1. 노드/엣지 식별·참조·관계 의미/중복과 검토 범위 확인.
2. 공간상 이웃·경계 호환 및 D442의 지지·점유·간격 검사.
3. 관계별 연결 의도와 실제 제공 경로·출입/통행 근거 대조.
4. 필수 경로의 도달/복귀와 선언된 단절 확인. 통행 가능한 것으로 검사된 엣지만 이 도달성 계산에 사용한다.
5. 같은 공간 이웃의 반복·군집·여백·판독 지표를 비교하고 그래프상의 문제 노드/엣지와 위치를 연결한다.

각 규칙의 판본·적용 범위·근거·필수 입력·측정값/허용값·통과/실패/미검사·대상 노드/엣지를 결과에 남긴다. 새 규칙을 추가할 때 정상/부정/정보부족 사례와 기존 판본 회귀를 함께 추가한다. 그래프는 공간 관계의 표현이며 형상·지지·시각 검토를 대체하지 않는다. 기하학적으로 적합한 그래프가 곧 아름다운 경관이라는 판정도 하지 않는다.

## 5. 첫 사례와 구현 인계

사용자의 ‘농장과 농장’ 예시는 D442의 기존 Farm 패턴 두 인스턴스를 재사용하여 관계 검토의 첫 사례로 넣는다. 완성된 Farm/AreaSet 두 개를 새로 생성하는 뜻이 아니다. 새 자산이나 H 등록 없이 다음 비교를 먼저 만든다.

- 연결 필수인 두 노드에 정상 경로가 있는 경우와 막힘이 있는 경우.
- 서로 이웃하지만 길을 두지 않는 선택형 관계, 근거가 있는 의도된 단절.
- 연결 요구는 있으나 문·폭/높이 정보가 없는 불완전 관계.
- 내부 포함 관계는 같으나 통행 경로만 다른 후보.
- 세 번째 패턴을 추가하면서 기존 통로가 가려지거나 새 이웃 반복이 생기는 경우.

기존9개 문법키의 연결점이 비어 있다는 개발 보고를 근거로 문 위치/폭/높이를 임의 생성하지 않는다. 규칙 시험에는 합성 자료를 사용할 수 있지만 실제 자산 연결 근거와 구분한다. 격리 미리보기에서는 노드 식별과 관계 종류·실패/미검사 위치를 도식/보조 표시로 설명하며 그 선을 실제 도로나 통행 성공으로 표시하지 않는다.

개발은 기존 D442 서비스·계약·시험/기술 보고 안에 이 추가 승인을 결속하고 정확 추가 수정 경로만 반환한다. 기존 구현/시험을 중단하고 별도 작업을 처음부터 만들지 않는다. 기존 D442 고정 판본/hash와 실패 이력은 보존하고 새 요청 때문에 변경되는 부분만 추가 판본으로 대조한다. 현재 코드 작성 중인 파일은 기획이 수정하지 않는다.

기술 결과는 기존 D442 보고의 D443 후속절과 같은 산출물 디렉터리에 둔다. CURRENT_WORK/통합판/필요 명세·기존 검색 신선도는 개발이 소유한다. 필수 회귀는 배열 순서 독립성, 같은 패턴의 다른 인스턴스 식별, 잘못된/중복/자기 참조, 포함과 통행 구분, 방향성 도달·복귀, 선택형/단절/미정/필수 실패·미검사 구분, 주변 노드 추가에 따른 재검사, 구형 결과 불변이다.

완료는 노드·관계·연결 의도가 구분된 패턴 검토 입력, 재현 가능한 규칙 결과, 필요한 격리 설명 이미지다. 전수 그래프 DB·새 엔진·경로 자동 개설·실제 월드/공식 Scene/Session·Save·권위 규칙·H/WI/E 승격·외부 게시/비용·r129/야간·commit/push는 확대하지 않는다.
