# 야간 개발: 막힌 벌목에서 다른 플레이 구간으로 전환

## 사용자 선택과 목적

벌목 개발이 오래 걸리면 벌목만 고집하지 않고 농장 관리 또는 약초를 달여 먹는 플레이로 옮겨도 된다. 목적은 밤 동안 실제로 조작하고 결과를 확인할 수 있는 구간을 늘리는 것이다. 게임 안의 벌목 소요 시간·비용·타격 횟수를 줄이라는 요청으로 해석하지 않는다.

## 전환 기준과 실행

- 현재 수행 중인 검증은 안전한 경계에서 마감한다. 같은 차단에서 새 원인 근거·실제 입력 진전 없이 조사만 길어지면 벌목의 다음 Editor 슬롯을 자동 반복하지 않는다. 기존 동일 실패 반복 금지를 유지하며 고정 시간 제한은 새로 만들지 않는다.
- 개발이 기존 승인된 Farm 관리/경작/수확 작업과 약초 채집·달이기·섭취 작업의 명세, 상태 공급, UI·Scene 준비를 비교한다. 공통 입력 차단이 후보에도 영향을 주는지 확인한 뒤 남은 연결이 적고 실제 검증 가능한 작은 구간을 선택한다. 농장→약초 순서를 강제하지 않는다.
- 전환할 때 벌목의 현재 성공 범위, 미완료, 마지막 재현·다음 안전 대안, 보존 파일과 담당 소유를 기존 상태판에 남긴다. 전환을 벌목 완료나 포기로 표시하지 않는다.
- 새 선택 규칙·미승인 연구·Save 변경 범위를 자동 승인하지 않는다. 해당 후보의 기존 승인 범위를 넘으면 다른 준비된 후보를 선택하거나 부족한 결속을 명시한다. 단순 계산 시험을 약초차 실제 제작·음용 또는 농사 완주로 보고하지 않는다.
- 공간은 선택된 구간의 실제 입력·Game View, 애니는 독립 가능한 승인 연구/시험, 개발은 통합을 담당한다. 중복 Editor 점유와 기존 작업의 미소유 변경을 피한다.
- 아침에는 전환 이유, 실제로 가능해진 행동, 결과 화면, 남은 차단을 함께 반환한다. 기존 09:00 안전 마감·E 상한·권리·원본 보존·외부 효과 및 commit/push 금지를 유지한다.
