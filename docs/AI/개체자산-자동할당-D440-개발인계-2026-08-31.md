## 1. 목적과 추가 승인 범위

Codex가 개체의 목적·WI·역할과 실제 자산 근거를 대조하고, 근거가 충분한 자산을 **역할별 구성 초안으로 자동 저장**한다. 사용자는 매번 후보를 고르지 않고 결과와 예외를 확인한다. 서버는 자연어 의미를 다시 결정하지 않고 참조·권한·판본·저장 정합성을 검사한다.

기존 [로컬 검토 웹 제안](개체자산-로컬검토웹-제안-2026-08-31.md)의 매번 사용자 선택 중심 흐름은 **자동 할당 결과·근거·보류 항목을 확인하고 필요할 때 교체하는 흐름**으로 대체한다. 첫 DB 할당 결과를 웹 완성·전수 사진 준비까지 기다리지 않는다. 로컬 우선/추가 VM·Azure 업로드 제외는 유지한다.

[D432 이미지 비교](개체자산-이미지비교와할당검토-2026-08-31.md)의 근거 검토는 사용자 전수 열람 대신 Codex의 실제 근거 검토로 수행할 수 있다. [D434 구성 저장](게임객체-다중자산구성과공방-개발인계-2026-08-31.md), [D437 자산 목록](Synty전수자산목록-조사와MySQL축적-2026-08-31.md), [D438 개체](WI전수객체조사-유휴담당분담과DB인계-2026-08-31.md), [D439 로컬 반입](../Architecture/기획판본-서버반입파이프라인.md)의 기존 상태를 보존하면서, 미지원이던 **근거 기반 자산 구성 반입·자동 초안 할당**을 추가 승인한다. 과거 미선정/미승인 사실을 소급 변경하지 않는다.

자동 할당은 실제 World 배치, 제품 사용 승인, 모든 자산의 적합성 승인, E 승격이 아니다. 기존 `Draft`/`NotApplied`와 실제 검증 상태를 보존한다. 자동 선택이라는 출처와 역할 적합성 근거를 별도로 기록하고 사람이 검토한 것으로 위장하지 않는다.

## 2. 판단 절차와 고정 기준

| 단계 | 처리 | 필수 보호 |
| --- | --- | --- |
| 역할 파악 | 현재 정의·WI/문답에서 외형·설비·도구·동작을 추출 | 시간·상태·권한·가격을 실물로 복제하지 않음. 미정 의미는 보류 |
| 후보 축소 | 종류·용도·팩·이름을 검색 | 이름 유사성은 검색 수단이며 단독 선정 근거 아님 |
| 근거 확인 | 원본 판본, 기존 이미지/구성/크기, 역할상 필요한 컴포넌트·동작 근거 대조 | 현재 후보와 정확히 대응하는 근거만 사용 |
| 자동 선택 | 필수 조건을 충족한 후보 중 역할별 하나 선택 | 필수 조건 누락·불일치는 다른 점수로 상쇄하지 않음 |
| 저장·검증 | 기존 구성 저장 경계로 새 판본을 만들고 독립 재조회 | 이전 선택·다른 슬롯·이력/원천 보존 |

선택 우선순위는 같은 문맥·역할에서 검증된 기존 대응, 용도·형상이 직접 일치하는 후보 순이다. 추가 조사가 필요한 후보는 아직 선택하지 않는다. 필수 조건을 통과한 후보 사이에서 팩·색감의 조화를 고려한다. 동일 팩이라는 이유로 다른 용도 자산을 할당하지 않는다.

동등한 외형 변형만 남으면 기존 대표형을 우선한다. 대표형이 없고 기능적 동등성이 확인된 경우 고유 식별자 순으로 하나를 고정한다. 의미·기능이 다른 후보의 동률은 보류한다. 모델의 임의 신뢰도 백분율은 검증 근거로 쓰지 않는다.

- 기존 선택은 기본 보호 대상이며 미선정 슬롯부터 채운다. 사용자 고정/교체 선택을 다음 자동 실행에서 되돌리지 않는다. 출처가 없는 과거 선택도 보호한다.
- 같은 자산 판본·역할·사용 조건의 근거는 재사용한다. 다른 판본이나 용도로 자동 확대하지 않는다.
- 냄비는 열린 입구·내부 형상, 진열대는 용도·규모 등 해당 역할에 필요한 조건만 확인한다. 장식용 외형에 불필요한 동작 검증까지 요구하지 않는다.
- 캐릭터 외형과 대기·걷기·작업 Clip은 분리한다. FBX 내부 Clip은 파일 GUID와 하위 자산 식별자로 구분하며 이름/정지 썸네일만으로 동작 적합성을 확정하지 않는다.
- 기술 근거가 부족하면 Codex가 추가 조사한다. 한 묶음의 추가 조사에서도 해결되지 않은 항목은 사유·필요 근거와 함께 보류하고 독립 후보로 진행한다. 같은 실패를 무한 반복하거나 전수 사용자 재질문으로 돌리지 않는다.
- 새 게임 의미 선택·권리·추가 접근 권한이 필요한 해당 항목만 기획에 반환한다. 자료 부족을 권리 허용이나 사용자 승인으로 해석하지 않는다.
- 원본 또는 기획 조건이 바뀌면 이력을 보존하고 재확인 필요로 표시한다. 선택을 조용히 새 자산으로 치환하지 않는다.

## 3. 데이터·코드 연결

개발은 현재 코드와 테이블을 먼저 확인하고 **정확한 수정 경로·공유 계약·필요한 최소 DDL**을 선언한 뒤 구현한다. 별도 중복 할당 DB/테이블·서버 LLM·유료 분류 API·상시 데몬을 만들지 않는다.

1. 기존 기획 `visuals` 관계를 판본화하여 개체·역할·슬롯·자산·판단 근거·보류 사유·자동/사용자 선택 출처를 기록한다. 구형 문서 읽기와 D439의 기존 참여 반입을 보존한다. 새 업무 규칙·WI를 자동 창작하지 않는다.
2. D439 로컬 반입의 자산 구성 미지원 경계를 명시적으로 확장하고 기존 [구성 UseCase](../../Ssalddel/Services/Content/게임객체시각구성UseCase.cs)를 호출한다. SQL 직접 삽입·관리자 사칭·기존 판본/권한 검사 우회는 하지 않는다.
3. 기존 개체 → 구성 판본 → 역할별 항목을 재사용한다. 한 역할/슬롯에는 선택 자산 하나, 같은 역할의 다른 위치에는 별도 슬롯을 사용한다. 대안 후보를 모두 선택하거나 실제 수량·위치를 임의 생성하지 않는다.
4. 전체 목록 중 미연결 후보는 현재 자산판본/검토 참조 경계를 최소 확장한다. 현재 Prefab 등록에 가짜 `VisualKey`를 만들거나 FBX/Clip을 `.prefab`으로 위장하지 않는다. 기존 후보 FK와 단일 대응의 승인 선택 정책은 보존한다.
5. 필요할 때 종류별 검토 참조·하위 자산 식별을 선택적으로 추가한다. 기존 자산 참조 또는 새 검토 참조 중 하나만 선택하며 미선정은 둘 다 비어 있을 수 있다. 첫 정적 후보 결과가 전수 애니메이션 추출을 기다리지는 않는다.
6. 선택·판단 근거·실행 주체·입력 판본·재처리 키를 연결해 조회 가능하게 한다. 동일 입력은 추가 저장0, 입력 충돌은 거부한다. 동시에 수정됐으면 최신 구성을 재조회하며 다른 선택을 덮어쓰지 않는다.
7. 실제 대상은 기존 로컬 Docker MySQL 개발 DB를 재확인한다. 필요한 제한적·추가적 DDL과 UseCase 저장은 승인 범위지만 전체 Migration/초기화·원격 운영 DB·원천 자료 변경은 제외한다. 비밀정보는 문서/로그/화면에 출력하지 않는다.

웹은 자동 할당·보류·표현 불필요·사용자 고정과 이유를 기존 API/계약으로 조회할 수 있게 연결한다. 전체 웹 구현·로그인·이미지 표시 완료를 첫 저장 결과로 대신 보고하지 않는다. 최초 반환은 기존 문서/구조화 결과로도 가능하며 별도 비용/공개 웹은 시작하지 않는다.

## 4. 첫 실행 묶음

현재 DB의 등록 정의·역할/기존 선택·자산 목록을 읽고 시각 역할과 미선정 슬롯을 분류한다. 보고상 71개 정의·14,461개 메타데이터 중 Prefab4,221은 이전 검증 시점 값이므로 실행 때 재확인한다. 미선정 자산을 실제 연결 완료로 보지 않는다.

첫 실제 반입은 **최대 10개 역할**이며 동일 개체의 여러 역할도 포함할 수 있다. 근거가 준비된 정적 사물·도구·설비를 우선하고, 이후 건물·캐릭터 외형·동작으로 확장한다. 분야는 독립적으로 진행할 수 있다. 적합 후보가 적으면 수량을 맞추려고 조건을 낮추지 않는다.

첫 묶음은 정확 후보/판본/근거와 수정 경로를 결속한 뒤 **자동 선정 → 구성 초안 저장 → 독립 재조회 → 멱등/충돌 검증 → 기획 반환**까지 닫는다. 실제 저장이 가능한 항목이 없으면 구현·시험과 보류 근거를 반환하되 가상 Fixture를 실제 선정으로 세지 않는다.

기존 이미지·캡처·원본/meta의 파일 근거를 우선 재사용한다. 이번 첫 묶음의 기본은 Editor 없는 조사/검증이며 새 캡처·원본 가공·Scene 배치는 포함하지 않는다. 추가 시각 근거가 필요한 경우 별도 기존 캡처 승인과 소유를 확인하고 요청 범위를 기획에 반환한다. r129·야간·무관한 중지 작업은 재개하지 않는다.

## 5. 검증과 결과 반환

다음 사례를 실제 코드 회귀로 검증한다.

- 이름은 비슷하지만 형상/종류가 다른 자산 거부, 용도 불일치·미정 객체/정보형 분리.
- 판본/원본 해시 불일치, 이미지 근거 누락·다른 후보 이미지, Rig/동작 조건 미확인 보류.
- 한 개체 복수 역할, 같은 자산의 여러 개체/슬롯 재사용, 대안과 동시 구성 구분.
- 사용자/기존 선택 보호, 미선정 슬롯만 반입, 입력 반복/내용 충돌/개정 경합 처리.
- 선언된 근거와 저장된 선택의 일치, 입력 중 일부 실패를 숨기지 않는 명시적 묶음 결과.
- 구형 D439 문서/참여 반입·D434 구성·D431 단일 대응과 기존 DB 기록 보존.
- 자동 선택이 `Approved`/실제 배치/E 성숙도·게임 기능 상태를 자동 변경하지 않음.

범위 Fast·영향 계약/소비자 시험·Task와 제한 로컬 DB 저장/독립 재조회를 구분한다. 타경로 기존 실패를 이번 통과로 덮지 않는다. 표준 검증 미완료 사유도 반환한다.

결과에는 자동 할당 수/개체·역할·정확 자산, 선정 이유·근거, 보류 수와 필요 자료, 표현 불필요 수, 기존 선택 보존 수, DB 저장·독립 재조회·재처리 결과를 기록한다. 실제 웹·이미지 열람·Unity 실행 여부는 별도다.
