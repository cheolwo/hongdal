# 절기 전략 턴·타로 카드 기획

- 기획 ID: `PLAN-TIME-SOLAR-TERM-TAROT-TURN-001`
- 기획 분야: `시간 / 절기 전략 턴`
- 기획 판본: `solar-term-tarot-turn-planning.r2`
- 상태: `ApprovedForHandoff / TimingAndBalancePending`
- 상위 기획: `PLAN-TIME-SEASONAL-001`
- 관련 하위 기획: 없음
- 관련 기획: `PLAN-GRAPH-HUB-LOGISTICS-CIRCULATION-001`, `PLAN-STORY-HUB-DISCOVERY-001`
- 관련 결정·기준: D-399, D-403, [WorldTick과 실시간 실행 경계](../Architecture/WorldTick과실시간실행경계.md), [Unity 일반 타로 기반 지역 경영 게임 뼈대](../Architecture/UnityTarotManagementGameFoundationPlan.md), [Unity 턴 카드 모판 설계](../Architecture/UnityTurnCardSeedbedDesign.md)
- 관련 WI·PlayableLoop: 미선정
- Graph Map 영향: 절기 마감에서 각 레이어의 누적 상태를 읽고 다음 절기의 계획·카드 문맥만 갱신하는 시간 오버레이 후보
- 다음 질문 또는 인계 상태: 개발이 기존 일 단위 WorldTick·턴 마감·카드 catalog/제안/선택/다음 날 효과 계약을 대조해 호환 리팩터링하고, 새 Goal·WI·E7 없이는 실제 Unity·E 승격을 하지 않는다.

## 목적

NPC와 진영의 장기 행동을 Unity 프레임마다 동적으로 계산하지 않고, 플레이어의 현장 활동은 부드럽게 유지하면서 큰 세계 반응을 결정적인 시간 경계에서 묶어 처리한다. 한국 24절기는 전략 턴의 문맥과 마감 단위를 제공하며, 타로 카드는 다음 절기의 운영 화두와 대응 선택을 연다.

## 세 시간층

### 실시간 현장 플레이

- 이동, 카메라, 대화, 탐색, 채집, 짧은 작업과 직접 전투
- Unity 표현 시간과 기존 권위 실시간 시계·BattleTick 경계를 유지
- NPC 장기 전략·전체 물류·상대 진영 계획을 매 프레임 다시 계산하지 않음

### 일 단위 WorldTick

- 기존 `OneTickOneDay` 호환 경계를 유지
- 확정된 NPC 업무, 생산, 운송, 도로 공사, 위임 작업의 진행과 일 단위 결과를 결정적으로 누적
- NPC가 프레임마다 자유롭게 새 목표를 만들지 않고 승인된 작업 계획·역할·역량·자원·기한을 소비

### 절기 마감 전략 턴

- 한 절기 동안 누적된 일 단위 결과와 미완료 업무를 같은 상태 판본에서 읽음
- 상대·적대 진영 활동, 지역 위협, 시장·물류 수요, 작물·기상 국면, NPC 장기 변화와 다음 절기 계획 후보를 일괄 정산
- 절기 이름만으로 생산·가격·사건·몬스터·승패를 자동 확정하지 않음
- 정확 절기 길이와 현실 날짜 동기화는 별도 판본에서 결정

## Solo 절기 마감

Solo에서는 절기 마지막 경계에 정산 미리보기를 보여 주고 플레이어가 명시적으로 `절기 마감`을 확정한 뒤 다음 절기로 넘어간다. 미리보기에는 최소한 다음을 구분한다.

- 완료·진행·중단된 운송·공사·위임 업무
- 아직 해결되지 않은 화물·도로·위협·NPC 상태
- 다음 절기에 이어질 계획과 예상 변화
- 절기 마감 시 확정되는 상대 진영·경제·생태·공동체 계산 범위
- 차단·불확실·자료 신선도 부족

미리보기만으로 WorldTick·WorldRevision·재고·사건 결과를 변경하지 않는다. Hosted의 자동 마감·접속자 합의·현실 시각 정책은 이번 판본에서 정하지 않는다.

## 절기 전환 타로 흐름

```text
절기 정산 미리보기
  → 명시적 절기 마감
  → 동결된 덱·규칙 판본에서 결정론적 카드 3장 제시
  → 각 카드의 정방향 효과와 역방향 효과를 함께 판독
  → 카드 1장 선택
  → 선택하지 않은 2장은 버림 더미
  → 선택 카드에 허용된 대응 방식 선택
  → 다음 절기 적용 후보 활성화
  → 기존 하위 업무 규칙의 Preview·Confirm·불변 검증
```

세 장 중 한 장을 선택한다. 선택하지 않은 카드는 이번 덱 순환의 버림 더미로 보내고 덱을 모두 사용한 뒤에만 동결된 규칙으로 다시 섞는다. Save/Replay는 덱 판본·순서·제안·선택·버림 더미·재섞기 입력을 보존해 다시 불러오기로 유리한 카드가 나올 때까지 반복하는 일을 막는다.

카드 후보에는 정방향·역방향의 기회와 부담을 함께 보여 준다. 세계 문맥형 절기 카드는 기존 `RecoveryShare51` 정책을 재사용한다. 활성화 시점의 권위 회복·위협 상태에서 `회복 출력 ÷ (회복 출력 + 위협 출력)`을 백만분율 고정 정밀도로 계산해 `510000` 이상은 정방향, `509999` 이하는 역방향으로 판정한다. 분모가 0이거나 근거 hash가 없으면 활성화를 거부한다.

Preview는 현재 상태에 따른 방향 후보와 양쪽 효과 설명을 보여 주고, Confirm은 선택 카드의 방향·회복 비중·근거 revision/hash·정책 revision을 새 활성화 사본에 동결한다. 활성 수명 동안 회복 수치가 달라져도 방향을 다시 계산하지 않는다. 교체·해제·다음 절기 재활성화는 기존 값을 수정하지 않고 과거 활성화를 종료한 뒤 새 활성화와 계보를 만든다. 기존 seed 기반 세션은 호환을 위해 `SeededHash` 정책을 보존하며, 절기 프로필 결속 없이 전역 정책을 조용히 바꾸지 않는다. 정방향을 순수 보상, 역방향을 순수 벌칙으로 만들지 않는다.

## 카드의 책임

카드는 다음 절기의 운영 질문과 대응을 연다.

- 전차: 빠른 운송, 안전 운송, 합배송
- 정의: 검수 강화, 공정 배분, 분쟁 재검토
- 여제: 생산 확대, 품질 관리, 노동 부담 완화
- 절제: 재고 균형, 자원 절약, 병목 완화

이는 의미 예시이며 최종 덱·수치·효과가 아니다. 카드는 재고·화물·사고·NPC 성장·전투 결과를 직접 만들지 않는다. 선택한 대응은 기존 생산·운송·창고·시장·도로·전투·NPC 업무 규칙이 받을 수 있다고 선언한 연결 지점에만 판본화된 보정 후보를 제공한다. 기존 권한·용량·수량 보존·음수 재고 금지·Preview·Confirm·상태 재조회 경계를 우회할 수 없다.

## NPC·적대 진영 연산 통제

- NPC의 일상 업무는 확정된 작업 계획을 일 단위 WorldTick에서 누적한다.
- 장기 목표 갱신과 적대 진영의 큰 행동은 절기 마감 입력으로 묶는다.
- 현장 전투는 기존 BattleTick으로 처리하고 결과만 World 상태에 합류한다.
- 로컬 LLM 대사는 허용된 상태 사본을 필요할 때 읽는 비권위 표현이며 NPC 전략 계산·카드 선택·턴 결과를 대신하지 않는다.
- 같은 입력·규칙·덱·WorldRevision은 같은 후보와 마감 결과를 만들어야 한다.

## 기존 시스템 리팩터링 인계

개발은 새 턴 원장이나 두 번째 카드 권위를 만들기 전에 다음 기존 경계를 대조한다.

- 턴 상황 조회 → 턴 마감 미리보기 → 명시적 확정 → 상태 사본 재조회
- `ExpectedRevision`, 멱등 Command, Save/Replay hash
- 기존 일 단위 WorldTick과 다음 경영일 활성 효과
- 타로 원형·게임 해석·시나리오 덱·카드 제안·대응·배치 객체 반응 계약
- 현재 활성 카드 한 장과 보정 연결 지점·상한·하한·불변 검증
- Unity 카드 서랍과 턴 마감 UI의 읽기 전용 책임

리팩터링은 `일 단위 효과`와 `절기 범위 효과`를 조용히 같은 값으로 합치지 않는다. 기존 공개 ID·Fixture·저장 판본을 보존하고, 절기 문맥·제안·버림 더미·재섞기·활성 기간을 기존 계약으로 표현할 수 있는지 먼저 조사한다. 계약이 부족하면 정확 호환 경계와 Migration을 제안하고 새 schema를 최소화한다.

## E와 실행 경계

- 이 문서는 승인된 기획 기준선이며 코드·Runtime·Unity 완료 증거가 아니다.
- 개발은 정적 계약·결정성·저장·회귀를 먼저 검증한다.
- 실제 절기 마감 입력, 카드 선택 화면, 다음 절기 결과, Game View는 별도 PlayableLoop·Goal·E7 작업 명세와 실행 증거가 필요하다.
- 외부 LLM·유료 호출·운영 DB·Scene 저장·E 자동 승격·commit·push를 자동 포함하지 않는다.

## 남은 질문

- 첫 절기 덱의 카드 종류·복사본·가중치와 재섞기 규칙 세부
- 카드 없음·선택 유예·마감 취소의 허용 여부
- 상대 진영 전략 계산의 정확 입력·출력과 가시성
- Hosted의 절기 마감 권한·시간·합의·미접속 처리
- 첫 실제 WI·PlayableLoop·UI·Graph Map 표본
