## 1. 기존 D435를 전수 조사로 이어간다

[D435 객체 추출 원문](WI문서-게임객체추출과MySQL연결-2026-08-31.md)의 객체 정의·WI 참여 역할·판본/근거·중복 방지·로컬 MySQL 등록 경계를 그대로 적용한다. 그 첫3 WI 기술 검증을 유지하면서 **공식 WI 전체의 내용 검토와 객체 정의 정리를 별도 담당이 지금 병행**한다. 기존 코드/추출 기능을 폐기하거나 같은 기능을 재구현하지 않는다.

현재 [공식 WI](../../eng/execution-ledgers/world-interactions.json)는 r43/105개로 읽었다. 실행 시작/종료에 현행 식별자 집합과 원문 판본을 확인하며 수량을 고정 상수로 사용하지 않는다. WI는 행위이고 객체는 그 행위의 주체·대상·도구·재료·결과·장소 등이다. 105 WI를 객체105개로 복제하지 않는다.

[D437 Synty 전수 목록](Synty전수자산목록-조사와MySQL축적-2026-08-31.md)은 프리팹 조사 담당이 별도로 계속한다. **게임 객체 의미 조사와 자산 재고 조사는 서로 독립**이며, 존재하는 프리팹에 맞춰 기획 객체의 의미를 바꾸거나 전체 자산 조사를 객체 등록의 선행 조건으로 삼지 않는다.

## 3. 모든 WI에 내용 대조 결과를 남긴다

공식 WI 각 항목과 연결된 기획/문답·명세를 읽고 다음을 정리한다. [기존 문답 관계 입력](../../eng/planning-inquiries/spatial-relations.json)과 [WI 준비 조회](generated/planning-inquiry-wi-preparation.md)는 탐색 출발점이며 원문을 대신하지 않는다. 현재 검색의 판본 불일치를 자동 수정하지 않고 영향 부분의 현행 원문을 직접 대조한다.

- WI 식별자·판본, 지금/여기/나/너/이렇게·결과/다음 선택에서 직접 드러나는 객체와 해당 WI의 역할.
- 기존 객체 정의 재사용 여부, 동의어/종류·개별 기록/상태와 별도 결과물의 차이, 안정된 기존 식별자와 신규 정의 후보.
- 원문 경로/절·행/필드, 직접 근거와 기획 결정 상태, 원문 hash/판본·검토 시점. 조회용 해석과 확정 원문을 분리한다.
- 실물/Actor/시설·자원/도구·재료와 정보형 대상·상태/시간/능력 조건을 분류한다. 같은 플레이어/NPC의 ‘나·너’는 역할이며 서로 다른 객체 정의로 자동 분리하지 않는다.
- 관계가 명확한 정의/추가 등록 후보, 기존 정의에 역할만 추가할 대상, 미정/충돌·비객체·자료 누락과 사유.

단순 목록 조회를 내용 검토로 세지 않는다. 모든 WI에 검토 결과가 있어야 전수 대조 완료이며, 누락/모호한 항목은 해결된 것처럼 채우지 않는다. 관련 기획에만 있고 공식 WI가 없는 공방 등은 별도 미연결 후보로 남기며 정식 WI를 만들지 않는다. `WI-CRAFT-BREW`의 배합물 달이기를 발효 양조로 전용하지 않는다.

같은 객체를 여러 WI가 사용하는 관계와 하나의 객체를 여러 자산으로 표현하는 구성은 분리한다. 기존 D434 공방/개발의 첫3 WI 정의를 중복 생성하지 않는다. 제공받은 DB 식별자/판본 조회 결과는 개발의 저장 상태 근거로 표시하며 자료 담당의 직접 DB 검증으로 주장하지 않는다.

## 4. 분야별 인계와 실제 등록

먼저 현재 전체 WI 식별자/분야별 분할 목록을 개발에 반환한다. 첫3 WI의 기존 구현/입력과 겹침을 조정하고 검토가 끝난 분야부터 개발에 넘긴다. 전수 완료까지 작은 실제 저장·재조회 결과를 대기시키지 않는다.

개발은 D435 가져오기/관리 권한·판본·이력·현재 정의를 재사용하여 확정 근거가 있는 객체 정의와 참여 관계를 기존 `hongdal-mysql-1/hongdal_dev`에 추가한다. 모호한 후보는 검토 필요로 분리한다. 해당 API가 기획 원문 근거를 아직 지원하지 않으면 미지원 상태를 그대로 남기고 원문의 의미를 우회 입력으로 위장하지 않는다.

같은 조사 입력 재처리의 정의/관계 중복 방지, 여러 WI의 객체 재사용, 판본 변경/충돌·고아 참조, 독립 DB 조회의 식별자 집합·원문 근거 일치를 확인한다. 기존 D431/D434/D435 데이터와 원천 자료를 보존한다. 정의 추가는 실제 플레이어/NPC/재고·World 인스턴스 생성 또는 게임 규칙 승인/활성화가 아니다.
