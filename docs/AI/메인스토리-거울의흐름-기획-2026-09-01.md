## 원작 결속 상태

사용자는 ChatGPT 개인 프로젝트 `흑막상인`의 스토리를 이 프로젝트의 메인 스토리 원작으로 삼기를 원한다. 현재 저장소에는 그 원문이 없고, 확인한 브라우저 세션도 로그인되지 않아 원작 본문을 아직 읽지 못했다. 따라서 아래 `거울의 흐름`은 원작을 대신하는 확정 서사가 아니라, 기존 플레이 기획을 나중에 원작과 안전하게 결속하기 위한 **임시 이야기 골격**이다.

원작을 읽기 전에는 다음을 확정하지 않는다.

- 플레이어가 흑막상인 본인인지, 기존 흑막상인을 추적·협력·경쟁하는 인물인지
- 원작의 주인공·조력자·적대자·세계 규칙·핵심 반전·결말
- 원작 사건의 순서와 Nature·Farm·Town·Hub·City 대응
- 원작 고유 명칭을 새 WI·퀘스트·Area·권위 상태로 자동 등록하는 것

원작 확인 뒤에는 `원작 사실 → 게임 각색 → 하위 지금·여기·나·너·이렇게 → PlayableLoop/WI → 표현 근거` 대응표를 만들고, 서로 다른 부분은 조용히 합치지 않고 `유지/각색/보류/제외`로 판정한다.

## 이야기의 중심 의미

> 플레이어는 흩어져 보이던 사람·물품·자연·업무의 흐름을 직접 발견한다. 자기 삶을 회복하는 작은 선택이 다른 사람과 공동체의 회복에 어떻게 이어지는지 알아가고, 게임 속 문제와 선택적으로 연결된 현실 자료를 거울처럼 비춰 보며 다음에 관여할 일을 스스로 정한다.

`거울`은 현실을 그대로 복제하거나 게임을 업무 교육으로 강제한다는 뜻이 아니다. 게임은 재미와 선택 가능한 플레이로 완결되고, 현실 자료는 관심이 생겼을 때 근거와 차이를 살펴보는 별도 층이다.

이 중심 의미 역시 흑막상인 원작을 읽은 뒤 유지·각색·제외 여부를 다시 판정한다.

## 플레이어의 장기 변화

```text
낯선 세계를 관찰한다
→ 실행 가능한 작은 일을 발견한다
→ 직접 행동하거나 다른 방법을 선택한다
→ 결과와 원인을 확인한다
→ 개인의 회복과 타인의 필요가 연결됨을 안다
→ 공동체의 흐름을 이해하고 더 넓은 책임을 선택한다
→ Nature·Farm·Town·Hub·City 사이에서 자기 방식의 다음 장을 연다
```

이 변화는 직업·영역 순서를 강제하지 않는다. 각 영역은 독립 폐루프를 유지하고, 스토리는 이미 성립한 결과의 의미와 다음 선택을 연결한다.

## 첫 장기 목표 — 요동성을 방어한다

요동성 방어는 Nature·Farm·Town·Hub·City를 한 줄로 강제하는 진행 순서가 아니다. 플레이어는 각 영역의 독립 활동을 계속하면서 정찰·식량·제조·물류·협상·건설 결과를 남긴다. `Construction`은 별도 Area가 아니라 성벽·성문·망루·창고·병영의 건설·손상·수리 상태를 표현하는 공유 계층으로 사용한다. 방어 세계의 기본은 내정과 전투의 혼합 대응이지만 플레이 유형을 먼저 선택하지 않는다. 물약 제조·시장 공급, 농사, 수리, 운송, 정찰·전투 같은 실제 완료 기록이 방비를 바꾸고, 플레이어는 첫 방어에서 평소 역량에 맞는 전선·의무·공병·병참·정찰·연락/지휘 역할로 직접 참여한다. 완화 난이도는 한 축 중심 기록을 허용하고, 표준은 다른 축의 최소 준비를 요구하며, 고난도는 두 축의 독립 관문과 실제 인계를 모두 요구한다.

장기 목표는 초반부터 알 수 있지만 즉시 실패하는 countdown으로 압박하지 않는다. 이상 징후와 취약점을 발견하고, 후퇴로·보급로·예비대와 연락/도착 조건을 실제 활동으로 마련해 방어 계획에 반영한 뒤, 첫 방어의 결과와 피해·복구·다음 선택을 확인한다. 준비는 모든 항목을 채우는 체크리스트가 아니라 전투 중 남겨 둘 선택과 감수할 결손을 정하는 전략이다. 첫 표면 위협은 Nature에서 성 방향으로 밀려오는 몬스터·야생 생물의 비정상 이동으로 정하며, 정확 원인과 흑막상인의 역할은 원작 확인 뒤 다음 장에서 밝힌다.

## 서장 사건 마디 후보 — 자연에서 첫 밤을 넘긴다

이 사건은 흑막상인 원작의 첫 장면으로 확정한 것이 아니다. 원작 확인 전에도 독립 실행 가능한 Nature 폐루프가 어떤 이야기 의미를 가질 수 있는지 검토하는 비정사 후보다.

| 항목 | 현재 내용 |
| --- | --- |
| `StoryBeatStableId` | `story-beat:nature-first-night-day2.v1` |
| 이야기 약속 | 플레이어는 처음부터 큰 세계 문제를 해결하지 않고, 확보한 자원을 안전하게 보관하고 하룻밤을 넘겨 다음 날의 선택을 스스로 연다. |
| 시작 지식 | 현재 보유 자원, 이용 가능한 오두막과 보관처, 공개된 수면 조건, 관찰 가능한 자연 자원 상태뿐이다. 숨은 재생 시각이나 미래 결과는 미리 알지 못한다. |

| 여기 | Nature의 오두막·보관 지점과 그 주변 자원 노드다. |
| 나 | 자원을 확보했지만 아직 장기 계획과 넓은 지역 운영을 정하지 않은 플레이어다. |
| 너 | 보관 가능한 자원, 오두막, 열원 상태, 밤의 시간, 다음 날 재생할 수 있는 자연 노드다. |
| 이렇게 | 자원 보관 → 수면 가능 여부 확인 → 명시적 수면 → Day2 전환 → 재생 결과와 다음 선택 재조회로 이어진다. |

| 다음 선택 | 개인 계획 선택, 열원·거처 보완, 재생 자원 확인, Nature 탐색 지속, 다른 독립 Area로 이동한다. |

| 표현 경계 | 오두막·보관물·밤/아침·재생 노드가 같은 권위 상태를 읽어야 하며, 연출만으로 Day2나 재생을 만들지 않는다. |

### 서장 후보의 완료 증거 계약

이 사건은 한 장면이 보기 좋게 재생되는 것만으로 성립하지 않는다. 다음 증거가 같은 동결 판본과 권위 계보를 가리켜야 한다.

| 관문 | 성립에 필요한 증거 | 대신할 수 없는 것 |
| --- | --- | --- |
| 권위 전이 | 자원 보관, 수면 Confirm, Day2 전환, 자원 재생, 다음 선택이 같은 Session revision 계보와 행위 기록으로 이어진다. | 서로 다른 Fixture의 성공 결과를 합쳐 한 실행처럼 설명하는 것 |
| 실패·멱등 | 보관 부족, 낡은 `ExpectedRevision`, 경합, 동일 명령 재시도가 상태를 중복 변경하지 않고 명시 결과를 남긴다. | 성공 경로 단위 시험만 통과한 것 |
| 결과 재조회 | 명령 응답뿐 아니라 재조회한 상태 사본에서 보관량·Day2·재생 노드·다음 선택이 같은 committed revision으로 확인된다. | 명령 직후 메모리 객체만 검사한 것 |
| Save/Replay | 저장→복원과 Replay가 같은 상태·행위 기록·재생 결과·다음 선택 및 결정적 hash를 재현한다. | 직렬화 가능 여부나 Save DTO 단독 시험 |
| Local/Hosted | LocalProcess와 RemoteHost가 같은 입력·동결 판본에서 같은 권위 결과를 만들고 다시 조회한다. | 공통 Core 단위 시험만으로 두 실행 위치를 추정하는 것 |
| Unity 표현 | Unity가 권위 사본을 읽어 보관물·밤/아침·재생 노드·선택 가능 상태를 실제 대상과 결속한다. 표현은 revision을 변경하지 않는다. | Prefab 존재, 정적 자산 조사, EditMode 시험만 통과한 것 |
| 실제 플레이 | 실제 입력으로 보관·수면·다음 선택을 수행하고 Game View에서 전후 차이를 판독하며 Console 신규 오류가 없고 결과 재조회가 화면과 일치한다. | 자동 시험 PNG, Scene View, 합성 목업, 코드상 이벤트 호출 |
| 귀환 | 실패·중단 뒤 안전한 상태로 돌아가 다시 시도하거나 다른 선택으로 이동할 수 있다. | 성공 뒤 화면을 닫는 것만 확인한 것 |

각 관문은 서로 다른 증거다. 앞 단계가 통과해도 뒤 단계를 자동 승격하지 않으며, 하나라도 같은 판본을 가리키지 않으면 사건 전체 완료가 아니라 가장 이른 책임 단계의 재검토로 돌아간다.

### 다음 선택은 한 버튼이 아니다

Day2 뒤의 `다음 선택`은 서로 다른 권위와 의미를 가진 선택을 한 목록으로 합성한 읽기 결과다. 화면에는 현재 실행 가능한 것만 보여 주고, 잠긴 후보를 실행 가능한 것처럼 꾸미지 않는다.

| 선택 층 | 기존 계약 | 이야기 의미 | 노출 조건 |
| --- | --- | --- | --- |
| Nature 특화 확장 | `WI-NATURE-15 / SelectExpansionPlan`, 현재 알려진 선택은 `Workbench`, `StorageRack`, `Palisade` | 첫 밤을 넘긴 뒤 거점에서 무엇을 먼저 보완할지 정한다. | 해당 Session이 선택 가능하고 아직 확장 선택을 확정하지 않았다는 권위 판정 |
| 보편 개인 계획 | `WI-ACTOR-PLAN-SET` | 영역과 시간에 묶이지 않고 플레이어가 발견한 실행 가능 후보 중 관심 목표를 세우거나 바꾼다. | 후보가 실제 실행 가능하거나 추적 가능한 이유와 함께 재평가되었다는 계획 계약 |
| 재생 자원 활용 | 재생된 Nature node와 기존 `BeginHarvest` 기회 | 밤을 넘기며 세계가 변했고, 같은 장소에서 새로운 행동 가능성이 생겼음을 알아차린다. | 같은 committed revision에서 node가 실제 `Standing`이며 필요한 능력·도구·접근 조건을 충족한다는 재조회 |
| 자유 탐색·다른 Area | 기존 이동·Area 독립성 | 메인 사건을 강제하지 않고 현재 장면을 떠나 다른 활동을 고른다. | 이동·접근이 실제 허용되며 현재 강제 전투·모달·작업 잠금이 없다는 판정 |

Nature 특화 확장과 보편 개인 계획은 이름이 비슷해도 같은 상태가 아니다. `WI-NATURE-15`를 보편 계획 편집기로 조용히 바꾸거나, 개인 계획을 정했다는 이유로 확장 건물을 자동 선택하지 않는다. 반대로 재생 노드가 존재한다는 사실도 채집 명령의 자동 실행이나 계획 자동 변경을 뜻하지 않는다.

### 플레이어가 알아차리는 화면 인과

실제 E5 이상에서는 다음 순서가 같은 권위 사본을 읽어야 한다. 정확 카메라 연출·색·자산 선정은 E5 검증 대상이며 이 표가 미리 확정하지 않는다.

| 순간 | 기존 표현 키·대상 | 플레이어가 알아야 할 사실 | 금지되는 오해 |
| --- | --- | --- | --- |
| 보관 전후 | `Nature.Shelter.Storage.Empty/Partial/Full`, `StorageInteractionAnchor` | 손에 있던 자원이 거점 보관 상태로 옮겨졌고 수면 조건에 어떤 영향을 주는지 | 상자 모양만 바뀌었는데 권위 보관량도 바뀌었다고 추정하는 것 |
| 수면 선택 | `Nature.Shelter.Sleep.Bed`, `SleepInteractionAnchor` | 지금 수면이 가능한지, 부족한 조건이 무엇인지, 수면이 명시적 선택이라는 점 | 침상 선택만으로 성공을 확정하거나 열원·보관 조건을 화면이 대신 판정하는 것 |
| 밤→새벽 | `Nature.Shelter.Dawn.Return`, 기존 Sky/Interior 경계 | 시간이 실제 Day2로 넘어갔고 플레이어가 다시 조작 가능한 상태로 돌아왔다는 점 | 페이드·햇빛 효과만으로 시간 전이를 합성하는 것 |
| 자원 재생 | `Nature.Tree.Stump → Nature.Tree.Standing`, 동일 ResourceNode StableId·좌표 | 어제 소진한 같은 자원 자리가 다시 행동 가능한 상태로 바뀌었다는 점 | 새 나무를 다른 위치에 생성하거나 화면에서만 Stump를 숨기는 것 |
| Nature 확장 | `Nature.Day2Plan.Workbench/Storage/Barricade`, `DawnPlanChoiceAnchor` | 현재 고를 수 있는 특화 확장과 아직 선택하지 않은 상태 | 미리보기 배치가 실제 건물 배치·완료라고 보이게 하는 것 |
| 보편 개인 계획 | `Nature.PersonalPlan.Board`, 기존 읽기 전용 UI | 언제든 수정 가능한 관심 목표와 현재 판본·실행 가능 상태 | 새벽 전용 선택으로 제한하거나 특화 확장을 자동 선택하는 것 |
| 열원 상태 | `Nature.HeatSource.Off/Burning`, `HeatSourceInteractionAnchor` | 현재 꺼짐·연소·접근 가능 상태와 별도 조작 가능성 | 캠프파이어 외형만으로 온도·연료·수면 성공을 확정하는 것 |

수면 전환에 짧은 화면 암전이나 시간 압축 연출을 사용할 수는 있지만, 연출이 끝난 뒤 반드시 새 권위 사본을 재조회해 Day2·재생 노드·다음 선택을 갱신한다. 실패·경합이면 성공 화면을 먼저 보여 주지 않고 기존 상태와 차단 이유를 유지한다.

### 실패에서 다음 행동으로 돌아가는 방법

차단은 이야기 진행 실패나 강제 재시작이 아니라, 플레이어가 현재 상태를 이해하고 가장 가까운 보완 행동으로 돌아가는 갈래다. 내부 오류 코드를 그대로 노출하지 않고 아래 의미로 번역하되 진단 기록에는 원 코드를 보존한다.

| 권위 차단 | 플레이어에게 보이는 의미 | 안전한 귀환·다음 행동 | 보존할 것 |
| --- | --- | --- | --- |
| `CabinRequired` | 이용 가능한 오두막이 아직 준비되지 않았다. | 기존 건설·완료 조건을 확인하거나 다른 활동으로 돌아간다. | 보유 자원·시간·기존 작업 상태 |
| `CabinAccessRequired` | 오두막 밖에서는 해당 보관·수면 행동을 할 수 없다. | 실제 출입 행동으로 내부에 들어간 뒤 다시 미리 본다. | 선택 대상과 현재 권위 판본 |
| `TimberNotCarried` | 현재 손에 보관할 자원이 없다. | 수집 가능한 자원·드롭·인벤토리를 다시 확인한다. | 보관 상태와 기존 거점 상태 |
| `CabinStorageFull` | 현재 거점 보관 용량이 가득 찼다. | 다른 자원 관리 또는 이후 저장 확장 후보를 검토한다. | 초과 자원과 기존 보관량; 자동 폐기 금지 |
| `CabinStoredResourceRequired` | 밤을 넘기기 전에 거점에 실제 보관된 자원이 필요하다. | `StoreAtCabin`의 실행 가능 조건으로 돌아간다. | Day1·비수면 상태; 화면만 보관된 것처럼 바꾸지 않음 |
| `NightRequired` | 아직 수면으로 다음 날을 열 시각이 아니다. | 현재 실행 가능한 활동을 계속하거나 권위 시간이 밤이 된 뒤 다시 확인한다. | 현재 시간과 자원; UI가 시간을 앞당기지 않음 |
| `ActionBlocked` | 전투·기존 수면·진행 중 작업 등 현재 우선 해결할 상태가 있다. | 공개 가능한 원인을 보여 주고 해당 상태의 해결·중단·귀환 경로로 이동한다. | 활성 작업·전투·수면 상태와 그 원인 기록 |
| `ExpectedRevisionMismatch` | 보고 있던 상태보다 세계가 먼저 바뀌었다. | 최신 사본을 재조회하고 같은 선택이 여전히 가능한지 다시 판정한다. | 중복 명령 방지와 사용자의 입력 의도; 성공 연출 금지 |
| `ExpansionPlanInvalid` | 현재 고를 수 없는 확장 후보다. | 권위가 반환한 현행 `Workbench/StorageRack/Palisade` 후보만 다시 보여 준다. | 미선택 상태; 임의 기본 선택 금지 |
| `ExpansionPlanAlreadySelected` | Nature 특화 확장이 이미 정해졌다. | 현재 선택을 읽고 보편 개인 계획이나 다른 실행 가능 행동으로 돌아간다. | 기존 선택과 그 행위 기록; 자동 덮어쓰기 금지 |

재시도는 같은 실패를 숨기는 반복이 아니다. 최신 판본과 조건을 다시 읽은 뒤에만 활성화하며, 조건이 그대로면 같은 차단 의미를 일관되게 보여 준다.

### 중단·저장·재접속의 이야기 연속성

저장과 접속 위치가 바뀌어도 플레이어가 겪은 밤은 한 번만 성립해야 한다. 저장 파일, 네트워크 응답, 화면 연출은 권위 전이를 대신하지 않으며 아래 기준으로 현재 사건을 다시 구성한다.

| 중단 시점 | 복원 뒤 성립해야 할 상태 | 플레이어 경험 | 금지되는 처리 |
| --- | --- | --- | --- |
| 수면 Confirm 전 | Day1, 비수면, 기존 보관량과 현재 실행 가능 조건 | 보관·밤·차단 조건을 다시 확인하고 수면을 선택할 수 있다. | 저장했다는 이유로 Day2나 자원 재생을 선적용하는 것 |
| 수면 Confirm 성공 뒤 새벽 전 | 수면이 시작된 committed revision과 해당 행위 기록 | 이미 받아들여진 수면을 중복 요청하지 않고 권위 시간 전이를 이어간다. | 로딩 화면이나 페이드를 수면 명령으로 다시 발행하는 것 |
| Day2·재생 commit 뒤 | Day2, 비수면, 동일 자원 `StableId`의 현행 상태, 재생 행위 기록과 다음 선택 | 아침 상태를 즉시 읽고 현재 실행 가능한 선택만 다시 보여 준다. | 접속할 때마다 Day2 증가·자원 추가 재생·기본 계획 자동 선택을 반복하는 것 |
| 명령 응답이 불확실한 때 | 서버 또는 로컬 권위의 최신 Session revision과 동일 `CommandId` 처리 결과 | 먼저 결과를 재조회하고, 미적용이 확인된 경우에만 최신 판본으로 다시 시도한다. | timeout을 실패로 단정해 새 명령으로 같은 수면·재생을 중복 적용하는 것 |
| 낡은 저장·손상된 Replay | 검증 가능한 마지막 저장점 또는 명시적 복원 차단 | 복원할 수 없는 이유와 보존된 선택지를 보여 주고 안전한 저장점 선택으로 돌아간다. | hash 불일치를 무시하거나 현재 Session 위에 조용히 덮어쓰는 것 |

LocalProcess와 RemoteHost는 전송 방식만 다르고 사건의 의미는 같아야 한다. 같은 시작 사본·명령 순서·동결 규칙에서는 다음 항목이 일치해야 한다.

- 최종 Session revision과 시간·Day2 상태
- 오두막 보관량과 수면 종료 상태
- 동일 자원 노드의 `StableId`, 위치 계보, `Stump/Standing` 상태
- 보관·수면·확장 선택·세계 자원 재생 행위 기록
- 실행 가능한 플레이어 기회와 다음 선택
- Save schema, Replay hash와 복원 뒤 재조회 결과

현재 코드의 `보관수면Day2자원재생은_한Session계보로조회되고_중복과경합을거부한다` 시험은 이 계약의 서버·로컬 권위 경계를 직접 겨냥한다. 이는 Local/Remote 상태·관측 결과·Replay hash, 동일 재생 명령의 멱등, 낡은 판본과 동시 경합 차단, 저장 슬롯 복원 뒤 Day2·재생 기록 보존을 검사한다. 다만 이 자동 시험은 Unity 실제 입력, Game View, Console, 접속 단절을 실제로 발생시킨 수동 재진입 증거를 대신하지 않는다.

Unity는 저장하지 않는 페이드 진행률·카메라·선택 강조·임시 애니메이션을 권위 상태로 복원하지 않는다. 로딩 뒤 최신 관측 사본을 읽어 보관 표현, 밤/새벽, 자원 노드와 선택 UI를 다시 조립하고, 같은 revision을 이미 표시했다면 성공 연출을 중복 재생하지 않는다. Hosted 연결이 끊겼을 때 Local 권위로 조용히 전환하는 것도 금지하며, 제품이 명시적으로 지원하는 전환 계약이 없다면 연결 끊김·재조회·재시도 상태를 보여 준다.

## 현재 금지선과 미정

- 메인 스토리를 이유로 Farm→Hub→City를 필수 순서로 만들지 않는다.
- 스토리 표식·대사·컷신만으로 권위 결과·퀘스트 완료·회복을 만들지 않는다.
- 현실 자료 열람, 외부 로그인, 구매·계약을 진행 조건으로 만들지 않는다.
- 장면을 보지 않았거나 다른 경로를 택한 플레이어에게 숨은 사실을 자동 공개하지 않는다.
- 정확 첫 메인 퀘스트, 적대자, 결말, 장별 수치·보상·필수 WI 수는 미정이다.
- 흑막상인 원작의 인물·사건·결말을 읽기 전에는 이 문서의 인물 관계와 장 순서를 정사로 승격하지 않는다.
- 이번 문서는 기획 기준선이며 코드·DB·Scene·Play·Game View·E 승격·commit/push를 승인하지 않는다.

## 다음 문답의 한 질문

흑막상인 원문을 확인한 뒤 첫 질문은 다음 하나로 좁힌다.

**지금** 플레이어가 세계의 숨은 물자·정보 흐름을 처음 알아차리고, **여기** Nature 또는 Hub의 공개된 흔적 앞에 있으며, **나**는 아직 배후를 모르는 플레이어이고, **너**는 흑막상인 또는 그가 남긴 영향일 때, **이렇게** 플레이어가 `이미 존재하는 흑막상인의 흔적을 추적하고 선택에 따라 협력자·경쟁자·감시자가 되는 구조`가 원작에 맞는가?

현재 추천은 이 구조다. 자유로운 Area 선택과 운영 플레이를 유지하면서 흑막상인을 공통 인과로 사용할 수 있기 때문이다. 다만 원작에서 플레이어 자신이 흑막상인이라면 추천을 폐기하고 원작 관점에 맞춰 다시 질문한다.
