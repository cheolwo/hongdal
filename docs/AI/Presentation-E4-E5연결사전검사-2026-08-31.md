# Presentation E4→E5 연결 사전검사·인계 공통화

- 결정: D-389
- 판본: presentation-connection-preflight.design.r1
- 상태: Approved
- 승인: 사용자가 공통화 범위로 「사전검사·인계 공통화」를 선택한 뒤 2026-08-31 `Implement the proposed plan.`으로 계획 구현을 승인했다.
- 선행: [D386 최소 모듈](Presentation단계별최소모듈-2026-08-31.md), [D387 자산 조사](Presentation단계별Synty자산조사-2026-08-31.md), [D388 기존 기능 균형 계획](Logic선행기능-Presentation균형계획-2026-08-31.md). 기존 원문·hash를 보존한다.

## 목적

후보 준비→자산 조회→상태 연결→배치·표시→해제 사이의 누락을 E5 진입 전에 확인한다. 새 E 단계·중복 대장·범용 조립 실행기는 만들지 않는다. 사전검사와 인계를 공통화하고 실제 적용·해제는 기존 분야별 코드가 담당한다.

## 공통 검사

기존 E4 준비 정보와 실제 연결 대상의 관측 결과를 읽어 다음을 검사한다.

| 검사 | 확인할 내용 |
| --- | --- |
| 후보 일치 | 승인한 Prefab·VisualKey·후보 판본과 실제 조회 결과의 일치 |
| 상태 공급 | 필요한 상태 사본·대상 식별자·Session·판본 연결과 E5에 필요한 논리 증거 |
| 대상 건전성 | 필요한 컴포넌트·Renderer·Collider·Bounds의 유효성 |
| 배치·입력 연결 | 적용 부모·위치·기준점과 필요한 상호작용 대상 |
| 소유·해제 | 생성·표시·구독의 소유자와 취소·전환 때 해제할 대상 |

공간·Collider·Actor가 필요 없는 표현은 해당 항목과 비적용 사유를 분리한다. 기존 WorldVisualCatalog, 상태 준비 소비자, StableIdReconciler, 분야별 표시 소유권 코드를 재사용한다. 검사는 읽기 전용이며 누락을 발견해도 상태 주입·자동 대체 자산 선택·Scene 수리를 하지 않는다.

## 입력·출력과 기존 체계 연결

내부 표현 계약에 검사 입력과 불변 결과를 추가한다. 공개 게임 API·Simulation 계약·Save 형식은 변경하지 않는다.

- 결과는 실제 연결 준비를 대상으로 기존 `Ready / Conditional / Blocked` 용어를 사용한다. 필수 관측 미확보는 Conditional, 확인된 불일치·결손은 Blocked, 필수 조건을 모두 확인했을 때만 Ready다.
- 결과마다 대상·후보/상태 판본·확인 근거·누락 사항·담당·가장 이른 재개 E를 남긴다. Ready도 실제 적용 성공이나 E5 완료는 아니다.
- 기존 `presentation-binding`과 `visual-source-bounds`에 연결한다. 과거 명세에 결과가 없으면 미검증으로 읽고 기존 E를 보존한다.
- 적용 직전 판본이 달라졌으면 다시 검사한다. 동일 대상·판본의 기존 근거는 재사용하고 전체 자산·전체 Scene 재검사를 기본 절차로 요구하지 않는다.

## 첫 소비자

Farm 한 밭 상태 표현을 첫 대상으로 고정한다. D386 준비 소비자와 D388 조사 결과를 입력으로 사용한다. 현재 논리 E5 상태 공급 미완료와 기존 밭 컴포넌트 결손을 정확히 반환하는 것부터 검증하며, 우회해 실제 배치 성공으로 만들지 않는다.

방문자의 기존 준비 계약을 두 번째 시험 입력으로 사용하여 농장에만 종속된 검사인지 확인한다. 방문자 실제 Scene 연결이나 두 분야의 공통 조립 실행기까지 확대하지 않는다. D388 조사 결과가 아직 없으면 미확보 결과를 검증할 수 있으며 그 결과를 실제 후보 검증으로 대체하지 않는다.

## 시험과 수용 기준

개발이 정상 준비, 후보·Session·판본 불일치, 자산 조회 실패, 필수 컴포넌트 누락, 비적용 사유, 소유권 충돌, 입력 불변, 재검사 결정성을 시험한다. 실패해도 기존 표현을 지우거나 변경하지 않아야 한다. 단위 시험의 관측 입력을 실제 Editor 관측으로 보고하지 않는다.

공통 검사 구현·관련 회귀·Farm 첫 소비 결과·기존 명세/생성 상태판 연결을 반환한다. 상태판에서 무엇이 빠져 E5로 못 가는지 확인할 수 있어야 한다. 기존 논리 E5 및 승인 조건이 준비된 대상의 실제 E5 적용과 화면 검증은 후속 단계다.

## 담당과 소유

기획 스레드는 승인 원문과 결정, 플레이어 선택을 맡는다. 개발 전문 스레드는 기존 코드 조사→정확 수정 경로/명세·추가 승인 결속→공통 검사/첫 소비자 구현→시험→생성물·상태판 통합을 맡는다. 기존 작업과 공유 경로가 겹치면 개발이 순서를 조율하며 기획은 코드·시험을 직접 실행하지 않는다. 공간/애니메이션 전문 자료는 기존 조사부터 재사용한다.

## 유지 경계

Logic·게임 규칙·Save·공개 API·기존 E 정의와 E5 선행 조건은 불변이다. 이번 구현 승인만 수행하며 중지된 r129/야간 작업, Editor 점유·Scene 저장·신규 Blender 가공·구매/다운로드·실제 입력/캡처·commit/push·자동 E 승격을 재개하지 않는다. 기존 문서 판본 차단은 해당 문제로 분리하고 검사를 완화해 통과시키지 않는다.
