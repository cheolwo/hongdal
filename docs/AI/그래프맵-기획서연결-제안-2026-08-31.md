## 1. 제안 요약

**기획서는 ‘왜, 어떤 조건에서 무엇을 할 수 있는가’를 설명하고, 그래프 맵은 ‘그 경험을 어느 장소·대상·연결 관계가 받쳐 주는가’를 보여준다.** 둘을 같은 기획 판본과 고유 식별자로 연결한다.

기획을 그래프 안에 통째로 복사하거나 그래프의 모든 선을 WI로 바꾸는 방식은 추천하지 않는다. 공간 관계와 행동의 인과관계는 의미가 다르므로 구분하되, 하나의 검토 화면이나 문서에서 서로 찾아볼 수 있게 한다. 같은 장소에서도 시간·플레이어 준비·대상 상태에 따라 다른 WI가 가능하고, 한 WI가 여러 장소와 대상을 사용할 수 있다.

이 연결을 통해 다음 질문에 답할 수 있어야 한다.

- 이 장소는 어떤 기획 때문에 필요한가? 플레이어는 여기서 무엇을 발견하거나 선택하는가?
- 이 WI를 하려면 어느 대상·작업 위치·접근 경로가 필요한가?
- 같은 장소에서 춘분/다른 절기, 준비됨/준비 부족에 따라 무엇이 달라지는가?
- 이 길이나 패턴을 바꾸면 어느 플레이와 귀환 경로를 다시 확인해야 하는가?
- 기획에는 있지만 공간이 없는 기능, 공간은 있지만 역할이 미확인인 요소는 무엇인가?

## 3. 같은 그래프 맵을 두 상세 수준으로 읽는다 — D445

**레벨 1은 왜 필요한 관계인가를, 레벨 2는 그 관계를 어떤 공간 조건으로 실현할 것인가를 설명한다.** 별도 지도 두 개를 수기로 관리하지 않고 같은 노드·엣지·기획 판본에서 상세를 펼쳐 본다. 레벨 2가 새 H 계층이나 레벨 1보다 높은 완성도를 뜻하지 않는다.

| 그래프 맵 상세 수준 | 중심 질문·내용 | 농장 출입구와 길의 예 |
| --- | --- | --- |
| 레벨 1 — 플레이·공간 관계 | 지금·여기·나·너·이렇게, 장소의 목적·대상·WI·결과·다음 선택, 포함·이웃·필수/선택 연결 | 플레이어가 농장에 접근하고 출입구를 알아보며 드나든다. 농장·출입구·외부 길의 관계와 필요한 접근을 표현 |
| 레벨 2 — 공간·배치 규칙 | 관련 노드/엣지/경계/구간의 기준점·방향·거리·점유·지지·간격·통로·자산 역할과 검사 근거 | 출입구에서 바깥으로 이어지는 선택한 길의 가장자리에, 지정 구간만 울타리를 배치하는 조건을 표현 |

농장 노드가 기존 H2를, 내부 작업 공간 노드가 H1을 참조할 수는 있지만 **그래프 맵 레벨 1 = H1, 레벨 2 = H2**가 아니다. H1도 두 상세 수준으로 읽을 수 있고 H2도 마찬가지다. 내부를 펼칠 때 기존 부모·자식 관계를 재사용하고 동일 인스턴스를 별개의 중복 노드로 등록하지 않는다.

레벨 1에서 모든 치수·울타리 부품을 보여주지 않아도 되지만, 관련 WI의 필수 통로가 막혔거나 규칙 입력이 부족하다는 요약은 숨기지 않는다. 레벨 2의 문제는 원래 노드/엣지·WI로 되돌아가 볼 수 있어야 한다.

### 3.1 배치 규칙은 적용 대상에 연결한다

규칙을 그래프 이름에만 붙이거나 모든 노드에 동일하게 적용하지 않는다. **노드 내부, 두 노드의 관계, 엣지의 일부 구간, 경계, 선택한 하위 조합** 중 어디에 적용되는지 명시한다. 울타리의 경우 농장 노드뿐 아니라 출입구 기준점·선택한 길 엣지·적용 구간을 함께 참조한다. 하나의 규칙이 여러 요소를 다룰 수 있으므로 규칙마다 가짜 노드나 통행 엣지를 만들지 않는다.

같은 의미의 규칙은 기존 배치 구조·제약 체계의 재사용 가능한 규칙을 참조하고 적용 구간·허용 값만 문맥에 결속한다. 현재 지원하지 않는 규칙은 문서상 후보로 남긴다. 문서에 썼다는 이유로 배치 엔진이 이미 계산할 수 있다고 보지 않는다.

| 규칙 기록 | 담을 내용 |
| --- | --- |
| 목적·근거 | 어느 기획/WI를 돕는지, 원문과 규칙 판본·승인/제안 상태 |
| 적용 대상·조건 | 노드·엣지·경계/구간, 적용되는 패턴/시간·상태 문맥. 규칙 정의와 개별 적용을 구분 |
| 기준과 측정 | 기준점·선택한 방향/분기, 거리의 측정선·좌표 기준·단위, 시작/끝과 포함 범위 |
| 배치 내용 | 자산 역할/후보 판본, 편측/양측, 간격·방향·높이/지지·규모와 허용 변형. 미선정 값 표시 |
| 보호·종료 | 출입·문 작동·필요 통로·보호 공간, 교차로/경계/짧은 구간 등의 처리와 예외 근거 |
| 성격·충돌 | 반드시 지킬 제약인지 비교용 미관 선호인지. 적용 근거·예외 범위와 충돌 반환 방식 |
| 결과·미확인 | 검사 가능/미지원, 통과/실패/미검사, 실제 적용 여부, 관련 노드·엣지·측정값·근거 |

물리적 지지·필수 통로 같은 필수 조건을 장식 선호 점수로 상쇄하지 않는다. 구체 규칙이 공통 조건을 자동 덮어쓴다고 가정하지 않으며, 충돌 시 적용 범위와 근거를 보여 주고 수정할 책임으로 반환한다. 승인된 예외가 없다면 길을 옮기거나 통로를 줄이거나 울타리를 늘여 맞추지 않는다.

### 3.2 울타리 규칙의 문서화 예시

사용자 예시는 **‘농장 출입구에서 바깥쪽 길 가장자리에 일정 거리까지만 울타리를 둔다’**는 공간 규칙의 형태다. 발화의 거리 표기 `2~30m`는 예시로 보존하며, 정확한 구간이나 모든 농장의 공통 상한으로 확정하지 않는다. 다음 항목은 이 예시를 해석 가능한 규칙으로 만드는 제안이지 배치 승인이나 새 게임 규칙이 아니다.

| 항목 | 이번 문서의 표현 |
| --- | --- |
| 레벨 1 의도 | 농장과 바깥 길의 출입 관계를 읽고 접근·귀환할 수 있도록 한다. 울타리는 그 관계를 표현하는 자산 역할 후보 |
| 레벨 2 기준 | 특정 출입구 기준점에서 특정 길의 외향 방향을 선택한다. 출입구/길이 여러 개면 적용 대상을 따로 적음 |
| 거리 측정 제안 | 출입구 주변 원형 반경이 아니라 **선택한 길 중심선을 따라 누적한 수평 거리**를 추천. 실제 경사면 길이와 구분하고 정확 시작·종료 거리는 미정 |
| 가장자리 배치 | 중심선 거리로 구간을 정하되 실제 울타리는 그 길의 좌/우 가장자리와 여유 폭을 기준으로 놓음. 편측/양측·여유 폭·부품 간격·길이·종류는 미정 |
| 보호·종료 조건 | 출입구·문 작동 범위·필수 통로를 침범하지 않도록 검토. 교차로·다른 출입구·하천/경계·짧은 길에서 끊을지/보류할지는 별도 조건으로 명시 |
| 미확인/실패 | 출입구나 길 형상이 없으면 미검사. 선언된 배치가 필수 통로를 막으면 실패. 원래 길을 자동 연장하거나 울타리 스케일을 바꿔 길이를 맞추지 않음 |

예를 들어 길이 목표 구간보다 짧다면 ‘남은 길까지만 배치’라는 예외가 명시적으로 채택됐을 때만 그 범위로 처리한다. 예외가 없으면 충돌/미정으로 남긴다. 갈림길에서 어느 분기를 따를지, 마지막 울타리 부품이 종료 지점을 넘어갈 때 어떻게 마감할지도 자동으로 결정하지 않는다. 구간 제한이 적용된 울타리의 실제 외곽까지 끝점 안에 들어오는지 이후 배치 검사에서 확인한다.

### 3.3 상세 수준과 별개로 구분할 관점

두 레벨 모두 아래 의미 구분을 유지한다. 이는 세 번째 레벨이나 새 엔진/저장소가 아니다.

| 읽는 관점 | 중심 내용 | 연결하되 혼합하지 않을 것 |
| --- | --- | --- |
| 공간 관계 | 패턴/작업 공간의 인스턴스, 포함·이웃·경계·통행과 필수/선택/분리/미정 | 길이 있다는 사실과 특정 WI의 실행 허용은 별개 |
| 플레이 상황 | 지금·여기·나·너, 가능한 WI, 조건·대가·결과·다음 선택 | 행동의 인과 연결을 도로로 만들지 않음. 반복·중단·분기는 정상적으로 표현 |
| 준비·검증 | 원문 근거, 자산 후보, 공간 제약, 검사 결과, 실제 배치/입력 증거 | 설계된 장소·예상 결과와 실제 세계 상태를 구분 |

공간 노드는 선택한 검토 규모의 **개별 사용 인스턴스**다. 같은 농장 패턴을 두 번 써도 두 노드이고, 같은 NPC/물체 정의를 참조해도 실제 개체가 같다는 뜻은 아니다. H1/H2 등은 기존 의미·포함 관계를 참조하며 그래프 맵을 새 H 단계로 두지 않는다.

사람·도구·자원·정보를 전부 공간 노드로 늘리지 않는다. 움직이는 NPC는 현재/계획 위치와 개체 참조를 연결하고, 가방 속 물건·정보·자기 상태는 WI 참여 역할로 연결할 수 있다. 플레이어의 현위치를 매번 설계 그래프를 다시 쓰는 이유로 삼지 않는다.

## 4. 일곱 칸과 그래프 맵의 대응

| 기획 칸 | 그래프 맵과 연결할 내용 | 예시와 경계 |
| --- | --- | --- |
| 지금 | 해당 상황의 절기·시간대·날씨·작업 진행 조건과 적용 범위 | 같은 숲 노드를 춘분/다른 절기 문맥으로 비교. Sky는 표현이고 게임 시간·출현·효과 권위는 기존 Simulation 규칙 |
| 여기 | 시작·작업·대상·복귀 위치의 노드 참조, 접근 경로/경계의 엣지 참조 | 현위치와 원격 위임 대상 위치를 구분. 허용된 원격 행동에 가짜 보행 경로를 강제하지 않음 |
| 나 | 실행 주체·선택 주체, 시작 위치, 지식·도구·자원·권한 조건 | 플레이어 선택과 위임받은 NPC 수행은 별개. 능력 조건은 노드 장식으로 대체하지 않음 |
| 너 | 참여 객체 정의/개체 참조, 역할, 연결 장소·상호작용 위치 | 대상·도구·재료·환경을 구분. 대상 종류와 실제 개체, Prefab은 각각 별개 |
| 이렇게 | 기존 WI와 구체 상황의 연결, 실행 위치·필요 대상·공간 조건 | ‘채집’은 행위이고 ‘숲에서 채집 위치로 가는 길’은 공간 연결. 하나의 WI가 복수 노드/대상을 참조할 수 있음 |
| 결과 | 기존 규칙이 바꾸는 상태와 그것을 읽을 장소/표현, 실패·중단 시 보존 상태 | 음식 획득·관계 변화는 실제 규칙/결과 근거가 필요. 그래프에 결과 문장을 적었다고 발생하지 않음 |
| 다음 선택 | 결과 후 조건별 가능한 WI·관련 노드/엣지, 보류·귀환·다른 활동 | 고정 퀘스트 순서나 자동 실행이 아님. 해당 조건을 알 수 없으면 미정으로 남김 |

연결은 **다대다**다. 하나의 문답이 여러 장소를 설명하고, 한 장소에 여러 WI가 걸리고, 같은 WI가 여러 절기·대상·시점에서 재사용될 수 있다. WI ID만으로 특정 위치·조건을 식별하지 말고 기존 문서의 상황/구간 식별도 함께 참조한다.

## 5. 문서에 추가할 최소 연결표 제안

공통 기획서의 일곱 칸 뒤에 작은 **‘그래프 맵 연결’ 절**을 둔다. 레벨 1에서 상황·WI·공간 관계를 읽고, 해당 노드/엣지에 연결된 레벨 2 규칙을 펼쳐 본다. 본문의 선택·대가·효과를 다시 복사하지 않고 원문 구간을 참조한다. 아래는 제안 항목이며 현재 파서에 넣을 실행 JSON이나 새 필수 스키마가 아니다.

| 묶음 | 최소 기록 |
| --- | --- |
| 출처와 판본 | 기획 문서/구간, Q 또는 의미 ID, 결정 상태, 기획 판본. 실행에 결속할 때 정확 원문 해시·인용 근거 |
| 행위 대응 | 기존 WI ID·재사용 이유. 미선정이면 후보/미연결이며 새 ID를 임의 생성하지 않음 |
| 공간 대응 | 그래프 맵/판본, 관련 노드·엣지 또는 노드 집합, 시작·작업·대상·복귀 역할. 정확 ID가 없으면 후보 역할로 남김 |
| 객체 대응 | 기존 객체 정의와 필요한 경우 개체 참조, Actor/대상/도구/재료/결과/장소 역할, 어느 노드와 어떤 이유로 연결되는지 |
| 상황과 제약 | 지금·나·너의 적용 조건 원문, 필요한 접근·지지·통행·판독 조건과 필수/선택/미정. 값의 단위·근거·적용 범위 |
| 레벨 2 규칙 연결 | 같은 노드/엣지에 적용되는 기존 규칙·판본과 구간별 값, 기획 근거·예외/충돌·미정. 레벨 1 관계와 별개 ID로 복제하지 않음 |
| 결과와 분기 | 정상·거부·실패·중단·복귀·다음 선택의 원문 구간, 관련 상태·위치와 미정 |
| 표현과 검증 | 기존 자산 구성/후보 판본·이미지·E4 준비 참조, 검사 결과/문제 노드·엣지. 근거 없는 항목은 미검사 |

기획 본문이 플레이 의미를, 기존 패턴/그래프 데이터가 공간 구조를, Simulation이 실행 상태를 소유한다. 관계 색인과 그림은 이들을 읽은 파생 조회다. 동일 사실의 원문을 두 군데에서 별도로 수정하지 않는다. 역방향 조회도 같은 관계에서 생성하고 역방향 수기 원장을 만들지 않는다.

기존 문답 공간 색인의 단일 관계 입력을 확장할 수 있는지 개발이 먼저 검토한다. 공간 데이터와의 정확 대응에 필요한 항목만 추가하고, D439 문서 표준/로컬 저장 지원을 조용히 확장하지 않는다. 초기에는 파일 기반 대응표와 조회만으로 시작할 수 있으며 새 MySQL 테이블·그래프 DB·API는 선행 조건이 아니다.

## 6. 기존 ‘봄 농장 발견’ 사례에 적용한 설명

기획 원문은 [눈 없는 춘분의 농장 발견·먹거리 나눔](북부춘분-굶주린농장발견-기획보완-2026-08-31.md)과 [첫 인과 기록](../Architecture/PlayableLoops/PlanningSessions/첫플레이체감/first-play-experience.inquiry.r1.md)을 재사용한다. 아래 장소 표기는 **설명용 역할**이지 새 노드/H/WI 등록이나 실제 자산·위치 선정이 아니다. 과거 북부 강추위·잔설은 대표 장면의 필수 설정으로 되살리지 않는다.

| 공간 역할 후보 | 함께 읽을 기획 | 남겨 둘 공백 |
| --- | --- | --- |
| 숲 가장자리 | 봄 풍경·생활 흔적에서 농장을 발견하고 더 살필지 판단 | 발견 대상·실제 시야·가시거리·카메라·좌표 |
| 농장 외곽/만남 위치 | 먹거리 부족을 겪는 NPC와 단서를 나누고 가방·준비를 확인 | 정확 NPC·위치·상호작용 범위·농장 소유. 대화만으로 고용/소유권 획득 아님 |
| 주변 사냥/채집 위치 | 가용 도구·지식·위험을 보고 가능한 방법을 선택 | 동물/식물·먹거리 가용량·접근·개별 WI 대응. 두 방법이 항상 가능하다는 보장 아님 |
| 나눔/복귀 위치 | 확보한 재료로 가능한 준비·나눔 또는 보류·다른 활동 | 같은 농장 공간 재사용 여부·조리/이전·회복량·관계 변화. 새 시설 설치를 자동 요구하지 않음 |

그래프 맵에서는 ‘어디에서 어디로 접근할 수 있어야 하는가’를 연결한다. 플레이 설명에서는 ‘단서를 얻고 → 준비를 확인하고 → 사냥/채집/보류 중 선택하고 → 결과를 보고 다시 선택한다’를 연결한다. **NPC에게 들은 단서가 사냥 위치를 가리키는 참조는 도로가 아니다.** 같은 장소에서 가방을 확인하거나 상대와 대화하는 WI에는 별도 이동 엣지가 필요하지 않을 수 있다.

예를 들어 필수로 선정된 먹거리 확보 경로가 알려진 장애물에 막혔다면 관련 WI와 경로를 함께 문제로 표시한다. 아직 식물이나 출입점이 미선정이면 실패 확정이 아니라 미검토/미정이다. NPC를 돕지 않고 떠날 선택과 귀환을 보존하며, 압박감을 줄이려는 기존 방향을 새 제한시간·강제 전투로 바꾸지 않는다.

개발용 전체 지도를 플레이어에게 그대로 노출하지 않는다. 미발견 장소·숨은 대상 상태와 플레이어가 실제 알고 있는 단서는 기존 지식·발견 규칙에 따라 별개로 취급한다. 이 제안은 플레이어 미니맵/자동 해금 UI의 승인이 아니다.

## 7. 그래프와 기획을 함께 검토하는 기준

| 확인 순서 | 확인할 질문 | 결과 해석 |
| --- | --- | --- |
| 근거·참조 | 연결한 기획 구간·WI·노드·엣지가 존재하고 같은 판본인가? | 연결 누락·오래된 판본·직접 근거와 해석 후보를 구분 |
| 플레이 요구 | 선택한 WI에 필요한 대상·준비·공간이 설명돼 있는가? | 공간은 있지만 실행 조건이 없거나, 기획만 있고 장소가 없는 공백을 찾음 |
| 조건별 도달·복귀 | 그 상황과 이동 종류에서 필요한 곳에 접근하고 돌아올 수 있는가? | D443의 필수/선택/분리/미정 유지. 모든 노드 전체 연결을 강제하지 않음 |
| 상태·다음 선택 | 결과 이후 선택이 실제 전제와 맞는가? 실패/중단 때 막다른 강제 진행이 생기는가? | 정상 반복을 오류로 처리하지 않음. 자원/해금 전제의 모순과 단순 순환을 구분 |
| 공간 형상 | 실제 제공한 치수·지지·경사·통로·출입 조건과 양립하는가? | 그래프 도달성을 실제 보행으로 확대하지 않음. 모르는 치수는 채우지 않음 |
| 표현·판독 | 자산/배치가 필요한 단서·대상·동선을 구분해 보여 주는가? | 그림·격리 미리보기·Game View·입력 성공은 서로 다른 증거 |

‘지금’과 ‘나/너’의 조건은 공간 경로 위에 적용해 비교한다. 기획 단계의 “가능할 것으로 의도함”, 규칙을 이용한 “이 조건의 검사 결과”, 실제 세션에서 “수행해 확인함”을 각각 표시한다. 제안 도구가 기존 규칙을 대신해 허기·성장·비용·해금·길 통행 상태를 확정하지 않는다.

변경 영향은 해당 참조에서 역으로 찾는다. 길을 옮기면 그 길을 요구한 WI·복귀 조건을, 자산을 교체하면 크기·접촉·판독 근거를, 계절 조건을 바꾸면 그 조건을 읽는 상황을 재검토한다. 무관한 모든 기획을 무효화하거나 기존 성공 근거의 해시만 자동 갱신하지 않는다.

D447의 E6 정제에서는 같은 노드/엣지·WI에 장소의 이유·Actor/물건 이동·상태 변화·회복/귀환 질문과 필요한 현실 근거를 연결한다. 출처·대상 대응·지역/기간·단위·판본·이용/해석 한계와 실제 소비 여부를 함께 읽되, 공공자료를 레벨 3으로 분리하거나 별도 그래프/DB를 만들지 않는다. 기존 자료의 수집·저장, 게임의 간접 표현, 선택형 원문 상세는 서로 다른 근거다. 자료 미사용과 미확보를 구별하며 상세 절차는 공통 방법론만 소유한다.

## 8. 검토 화면과 단계적 적용 제안

검토 화면은 장차 **그래프 맵 / 선택한 장소의 플레이 설명 / 근거·공백**을 함께 읽는 형태를 추천한다. 레벨 1을 기본으로 노드를 선택하면 관련 일곱 칸과 WI, 엣지를 선택하면 연결 이유·필요한 WI를 읽는다. 레벨 2를 펼치면 선택한 요소의 규칙·적용 구간·필수/선호 조건·미정/충돌을 보여 준다. 기획 구간을 선택하면 관련 장소·관계만 강조한다. 레벨 2에서 필수 실패가 확인되면 레벨 1에도 해당 관계/플레이의 차단 요약을 남긴다. 색상만으로 관계/검증 상태를 표현하지 않고 이름·종류·근거를 함께 표시한다. 이는 화면 제안이며 이번 UI 구현은 없다.

처음부터 모든 문답과 모든 자산을 하나의 거대한 그림에 펼치지 않는다. 기존 승인된 작은 상황을 골라 작성하고 영역→패턴→필요 대상 수준으로 펼쳐 본다. 다른 분야는 전체 지도의 완성을 기다리지 않고 같은 연결 형식으로 독립 정리할 수 있다.

| 적용 묶음 | 산출물·종료 기준 | 아직 하지 않을 일 |
| --- | --- | --- |
| 첫 기획 대응 | 기존 사례 하나의 일곱 칸·소수 공간 역할·WI 후보/기존 근거·미정을 연결한 문서 | 새 WI/노드 실제 등록·효과 확정 |
| 파일 조회 연결 | 기존 공간/순환 색인에서 기획→노드/엣지, 노드/엣지→기획의 양방향 조회 | 별도 검색기/DB·전체 의미 자동 확정 |
| 계획 검토 연결 | 승인된 같은 기획·그래프 판본과 제약을 배치 후보/검사 결과에 추적 가능하게 연결 | 실제 월드 조립·게임 성공/E 자동 승격 |
| 후속 실제 적용 | 별도 승인된 작은 범위에서 정확 자산·지면·상태·입력·결과 및 적용/해제 검증 | 전체 맵 완성이나 타 영역 실행을 필수 선행으로 삼지 않음 |
| E6 정제와 필요한 근거 | 현재 E5 기준선에서 해당 정제 질문·전후 비교·현실 근거/한계·미완료를 연결 | 자료 저장을 정제 합격으로 세거나 필수 H3/교차 관계 검토를 생략하지 않음. E7 전체 플레이는 별도 |

초기 성공 기준은 **사용자가 한 장소를 보고 ‘왜 있는지·무엇을 할 수 있는지·무엇이 아직 미정인지’를 이해하고, 한 WI를 보고 ‘어디와 무엇이 필요한지’를 찾을 수 있는 것**이다. 문서 대응이 늘어났다는 이유로 E를 올리지 않는다.

## 9. 현재 작업과 승인 경계 — D446·D447

사용자는 D446에서 채택한 E5 준비·입증 절차를 D447에서 **E6 정제·필요한 공공/현실 근거 결속까지 확장**했다. 공식 절차는 [공통 방법론](../Architecture/플레이폐루프논리시각이중순환체계.md#e6-focused-workflow)에 두고 [플레이어 중심 공통 기획](../Architecture/플레이어중심게임개발업무구조.md)에 연결한다. 이 문서의 상세 형식·규칙 수치/측정·조회 UI·개별 신규 실행 범위·새 플레이 규칙은 미승인으로 남긴다. 8절의 파일 조회/검토 화면 제안은 이 절차를 쓰기 위한 필수 구현 선행이 아니다.

배치 엔진은 승인된 두 수준의 의도/규칙과 실제 지형·자산 정보를 함께 읽어 후보를 계산하고, 규칙·그래프 판본 및 결과 대응을 남기는 책임을 유지한다. 그래프 검사만으로 실제 World 연결이나 E5를 입증하지 않으며 E6에는 현재 E5 기준선과 정제 근거가 필요하다. 선택하지 않은 GIS/공공자료를 강제하지 않고 원자료나 의미 신호로 게임 권위를 바꾸지 않는다. E7 전체 실제 플레이는 이번 공식 절차 밖의 별도 검증이다.

기획은 공통 방법론·플레이어 중심 문서·이 제안서·DECISIONS를 소유하고, 개발은 최종 판본을 읽어 CURRENT_WORK/통합 상태판에 인수한다. 별도 기술 구현이나 자료 조사가 필요하면 해당 승인·명세·필수 연구·정확 소유와 검증 범위를 먼저 확인·결속한다. D442/D443 동결 문서·실행 명세·코드·검색 입력은 이번 기획 변경에서 수정하지 않으며 해당 독립 작업을 다시 배분하지 않는다. 이번 변경은 공식 문서에 한정하며 새 DB/Provider/서버 실행·Unity/Scene/World·Save·E 승격·r129/야간·commit/push 확대는 없다.
