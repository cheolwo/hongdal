# WI 전체의 E4 문서·코드·자산 준비

- 판본: `wi-wide-e4-preparation.plan.r1` / 2026-08-31 / D396
- 상태: 작업 방향·범위 승인. 개별 미정 규칙·새 자산 설계와 모든 WI의 E4 달성을 승인/확인한 것은 아니다.
- 사용자 요청: 공통 기획 문서를 바탕으로 WI 전체를 중심에 두고 지금·여기·나·너·이렇게와 결과·다음 선택을 문서화하며, E4까지의 문서·코드·시험·Synty/Prefab 준비를 시간에 쫓기지 않고 진행한다.
- 기준: [공통 기획 구조](../Architecture/플레이어중심게임개발업무구조.md), [논리·표현 E 정의](../Architecture/플레이폐루프논리시각이중순환체계.md#궤적별-e-판정). 기존 단계·권위·승인 관문을 변경하지 않는다.

## 1. WI를 중심 문서로 삼는다

‘이렇게’에 해당하는 WI를 찾아서 그 행동이 언제·어디서·누구에게·무엇을 대상으로·어떤 결과를 만드는지 한곳에서 읽는다. [D392 전체 기획 이관](전체기획-네관점순환이관-2026-08-31.md)은 취소하지 않고 WI 문서의 근거와 양방향 조회로 연결한다.

- 대상 목록은 [공식 WI 대장](../../eng/execution-ledgers/world-interactions.json)과 기존 등록·성숙도·폐루프 관계에서 개발이 확정한다. 현행 revision과 실제 항목 수, 별칭/보류/과거 호환 항목을 구분하며 과거 수량을 고정 목표로 쓰지 않는다.
- 모든 공식 WI는 목록에 포함한다. 미등록 보편 행위/후속 아이디어는 ‘후보’로 따로 추적하고 정식 WI 수에 합산하거나 자동 등록하지 않는다.
- 문답에서 WI를 찾고, WI에서 문답·H·자산·코드·증거로 돌아갈 수 있게 한다. 공통 정책·비공간 질문은 관련 원문으로 유지하고 억지 WI로 만들지 않는다.
- 중심 문서는 WI별 읽기 단위다. 기존 작업 명세와 원문을 복사한 수기 파일을 WI 수만큼 새로 만들도록 강제하지 않는다. 기존 문서·색인에서 WI별 절/페이지를 생성하거나 연결할 수 있으면 우선 재사용한다.

## 2. WI별 문서의 필수 읽기 항목

| 묶음 | 내용 |
| --- | --- |
| 식별·근거 | WI ID/이름·보편/특화 관계·관련 폐루프, Q/의미 ID·기획/연구·명세의 원문 위치·판본·결정 상태 |
| 지금 | 허용 시간·진행/경과·중단/재개·기한·대기, 실제 시간 원천과 미정; Sky 체감 표현과 권위 시간을 구분 |
| 여기 | 필요한 H1·H2/상위 포함·접근·통행·지지·차폐, LH/배치 소비 또는 비공간 사유 |
| 나 | 플레이어 목표·판독 정보·권한·능력·지식·소지/장착·직접/위임 선택과 실제 Actor |
| 너 | NPC·몬스터·물품·약초·시설·환경 등 대상 식별·상태·능력·반응; 복수/자기 대상 포함 |
| 이렇게 | 선택/WI의 입력·Preview/Confirm·비용·허용/거부·실패·중단 규칙; 읽기 UI와 권위 변경 분리 |
| 결과·다음 선택 | 실제 권위 변화·보존/손실·피드백·회복/귀환·다음 가능 행동, 원문에 없는 분기는 미정/제안 |
| 코드·시험 | 기존 계약/규칙/Service/Adapter/표현 준비 코드와 시험·검증 범위·미연결 |
| Synty/Prefab | 플레이어 판독 순간·VisualKey·주/대체/fallback 후보와 역할·GUID/판본/hash·필요한 치수/Collider/Anchor·Rig/Clip·연구·조사 근거 |
| 성숙도·다음 작업 | 실제 Logic/Presentation/통합 E, 이번 E4까지 남은 항목·담당·차단·재개 지점, 부분 성과와 실제 E5 미연결 구분 |

과거 자료에 빈 필드가 있다는 이유만으로 즉시 전부 실행 불가로 바꾸지 않는다. 누락을 조사해 해당 없음·미정·미검토·근거 문제·실제 기술 결손을 구분한다.

## 3. 이번 목표의 E1~E4 범위

| 단계 | Logic | Presentation |
| --- | --- | --- |
| E1 | 기존 의도·명령·상태·오류 계약 확인/승인 범위 내 보완 | 보여야 할 조건·대상·선택·결과 정보 계약 |
| E2 | 기존 규칙·비용·차단·반환 코드 재사용/부족분 구현 | 상태 투영·자산 조회·View 연결 준비·수명/도구 코드 |
| E3 | 결정적 Core와 해당 범위 자동시험 | 판본/중복·상태·준비·조립/해제·오류/보존의 해당 자동시험 |
| E4 | 해당 WI의 H 문맥·Actor·권위 실행 결속 | 후보 적합성·VisualKey·주/대체/fallback·배치/InteractionAnchor 의도·E5 연결 준비 결속 |

현재 E4보다 높은 WI는 낮추거나 재구현하지 않고 유효한 기존 근거를 재사용한다. 낮은 WI는 문서 작성만으로 승격하지 않는다. 각 궤적의 검증과 기존 증거/명세 관문을 통과한 범위만 반영하며 통합 E는 기존 규칙을 따른다.

## 4. ‘Prefab 준비 마무리’의 의미

E4에서 어떤 상태를 어떤 보유 자산/구성으로 표현할지 선택 근거와 사용 조건을 갖춘다. 파일 존재만 확인하고 적합성 완료라 하지 않는다.

- 기존 조사/미리보기는 대상·판본·역할이 같으면 재사용하고 바뀐 부분만 확인한다.
- 필요할 때 기존 전문에게 좁은 격리 확인을 배분한다. 실제 Bounds·Collider·계층·지지/접근·Rig/Clip 등은 해당 역할에 필요한 것만 확인하며 모든 항목에 불필요한 전수 검사를 강제하지 않는다.
- 직접 재사용 / 연결 보완 / 소유된 조합 필요 / 가공 또는 신규 제작 필요 / 미검사 / 해당 없음으로 구분한다. 가공 권리나 새 디자인이 필요한 항목은 그 부분만 연구·기획에 반환한다.
- 승인된 소유 조합의 좁은 준비 코드·Prefab 작업이 필요하면 기존 연구/명세와 정확 경로를 먼저 결속한다. 보유 원본 수정·미확인 Blender 가공·새 구매는 일괄 허용하지 않는다.
- 비시각 WI에는 사유 있는 해당 없음을 사용한다. UI로 표현하는 WI에 억지 3D 물체·H1을 만들지 않는다.
- **실제 제품 Scene에 배치하고 권위 상태·입력/결과를 연결한 E5 및 E6/E7 시각 마감은 이번 전체 목표와 별도다.** E4 후보/격리 준비를 실제 Game View 또는 기능 완료로 설명하지 않는다. 기존 별도 승인된 H1 캡처는 그 범위에서 독립 진행한다.

## 5. 진행 순서와 병렬 배분

1. 현재 문답·공간 색인 작업을 안전한 검증 경계에서 통합하고, 최신 WI 전목록과 기획/코드/자산/증거의 빈칸을 드러낸다.
2. 모든 WI의 중심 읽기 문서를 먼저 마련하되, 자동 목록과 원문 대조 완료를 구분한다. 같은 원문·공통 모듈은 참조하고 복제하지 않는다.
3. 승인 근거와 선행 상태가 준비된 WI부터 E1~E4의 실제 코드/시험/후보 준비 부족분을 진행한다. 준비된 기능의 표현 격차, 재사용 효과와 실제 의존성을 기준으로 여러 분야를 나눠 다룬다.
4. 개발이 기존 Goal/작업 목록·명세 안에 범위/상한/경로 소유를 결속하고 공간·애니 전문을 배분한다. 공유 계약 파일은 단일 작성자가 통합한다. 항목 수 때문에 전역 단일 WIP를 강제하지 않는다.
5. 일부 완료 때마다 해당 WI 문서를 갱신하고 기획으로 반환한다. 실패가 나면 해당 책임·가장 이른 E를 보완하고 독립 WI는 계속한다.

전체 대상으로 한다는 요청은 미정 규칙을 개발이 고르거나 이미 보류된 개별 권리/파괴 작업을 해제한다는 뜻이 아니다. 승인된 규칙의 기술 연결은 불필요하게 재질문하지 않고 수행하고, 실제 새 플레이 선택·서로 충돌하는 원문·권리 문제만 기획에 반환한다. 기존 명세가 더 좁거나 이번 목표와 충돌하면 그 차이를 명시하고 정상적인 추가 결속 절차를 따른다.

## 6. 완료·차단 보고

- **문서 범위 완료:** 공식 WI 전목록이 중심 문서에서 조회되고, 각 항목의 원문/현재 구현/표현 준비·미정/차단이 설명된다. 빈 제목과 자동 목록만으로 완료라고 하지 않는다.
- **개별 E4 목표 달성:** 해당 WI의 Logic/Presentation E4 관문과 근거 결속이 실제로 충족된다. 한쪽만 준비됐으면 각각의 단계를 기록한다.
- **전체 E4 목표:** 전체 대상의 개별 상태를 집계한다. 미정·차단 WI를 조용히 제외해 전부 완료라고 하지 않으며, 전부 E4가 아니면 남은 수와 이유를 반환한다. 높은 단계의 기존 근거는 유효 범위를 보존한다.
- 코드·시험·Prefab 조사·Unity 격리·실제 Scene/Game View를 별도 집계한다. 생성 문서의 분량이나 코드 줄 수를 플레이 완성도로 바꾸지 않는다.
- 각 반환은 이번 완료 WI, 부분 성과, 열린 문제, 원문/코드/자산/시험 링크, 다음 작업과 사용자 선택 필요 여부를 짧게 포함한다.

## 7. 담당과 비포함

기획은 공통 구조·기존 답변 의미·새 선택을 소유한다. 개발은 WI 전목록 확인·문서 구조적 이관·승인된 코드/시험·명세/근거/색인 통합·문서 검증과 CURRENT_WORK/개발통합상태판을 맡는다. 공간은 공간/Prefab 적합성과 View 근거, 애니는 Actor/Rig/Clip·동작 적합성을 개발을 통해 인계한다.

이번 요청으로 **이 WI 전체 E4 준비 작업은 진행 대상**이 된다. 다만 r129/야간 자동화·무관한 중지 작업을 되살리거나, E5 제품 Scene 일괄 적용·Save 의미 변경·운영 DB/외부 유료 호출·자료 대량 수집·원본 삭제·미소유 dirty 덮어쓰기·강제 복구·commit/push를 수행하지 않는다. 새 구현에는 기존 승인 주제/필수 연구/작업 명세 관문과 소비자 검증이 계속 적용된다.
