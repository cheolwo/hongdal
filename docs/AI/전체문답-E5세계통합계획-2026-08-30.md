# 전체 문답 기반 E5 세계 통합 계획

- 판본: `inquiry-world-e5-delivery-plan.r1`, D377, 2026-08-30.
- 상태: `ApprovedPlanningAndDispatchPolicy`. 사용자 요청에 따른 전체 조사·우선순위·기존 승인 구현의 추진 계획이다. 모든 질문/새 WI/보류 규칙/하위 명세의 상한을 일괄 승인하는 문서가 아니다.
- 목적: 문답의 확정 의도를 WI와 플레이 폐루프로 묶어, 가능한 범위를 Logic·Presentation·통합 E5까지 연결한다. 하나의 canonical `SimulationWorldShell`에서 공간·행동·결과를 읽을 수 있게 하며, 새 기능 수보다 실제 세계 발현을 우선한다.
- 실행 창: [D375 야간 순환](야간개발순환-2026-08-30.md)과 [D376 경계 보완](야간월드경계보완-2026-08-30.md)을 포함한다. 2026-08-31 09:00 KST 이후 새 묶음 없이 안전 마감한다. 12시간은 구현 소요 추정이나 전체 완료 보장이 아니다. 남은 Queue는 아침에 다음 실행 계획으로 반환한다.

## 1. 사용자 의도의 해석과 완료 의미

Q 번호별로 코드를 한 개씩 만드는 대신 확정 문답→기존/추가 WI 후보→승인된 폐루프→같은 세계 안의 실제 실행으로 연결한다. 사용자의 '조화'는 우선 배치·시야·동작·UI의 충돌을 줄이는 통합 품질 목표다. E9의 영역 조화·사람 승인과는 구별하며 이번에 E9로 올리지 않는다.

E5는 물건이 보이는 것만으로 달성되지 않는다. Logic의 권위 반영·행위 기록과 같은 판본의 상태를 읽는 Presentation이 함께 충족되어야 한다. 통합 E는 두 축 중 낮은 값이다. 실제 Game View/입력은 이번 사용자 요청의 추가 검증 산출물이며 E7 전체 완료와 같지 않다. 공통 기준은 [E1~E10 체계](../Architecture/E1-E7수직폐루프와E8-E10수평증거체계.md)를 따른다.

## 2. 조사 범위와 지금 확인한 사실

기획이 현재 검색 색인 Validate를 재실행해 437 질문/811 발췌 검증을 확인했다. 구성은 Q001~339 339개, Q340~403 64개, 별도 의미 식별 후속 질문34개이며 원천22개다. 이는 검색 기록 수이지 원문 소실이 없다는 증거나 437개 기능 승인 수가 아니다. 기존 소실·중복·대체·FutureExtension/Asked/Deferred 경계를 보존한다.

- 검색 원천: `eng/planning-inquiries/sources.json` 및 연결 원문. 검색 색인에는 구현 권위가 없다.
- 기존 구현 추적: `eng/execution-ledgers/playable-loop-inquiry-implementation-scope.json` r65는 아직 Q001~339 범위다. 이를 Q403 전체 구현 대장으로 보고하지 않는다.
- 실행 권위: 기존 Goal 작업 목록, WI/PlayableLoop/Evidence 원장, 각 작업 명세·Approved 주제·Accepted Required 연구다.
- 조사 범위에는 Q340~403 및 후속34개와 D375~377 실행 결정을 함께 포함한다. 전체 원문별 WI/E5 가능성 전수 판정은 이번 계획 작성만으로 끝난 것이 아니며 개발의 첫 Queue 정리 산출물로 요구한다.

## 3. Queue 정리 — 진행 중 구현을 멈추지 않는다

개발이 기존 구현 추적 대장/도구를 재사용·호환 확장할 경로를 먼저 정한다. 기획 소유 질문 원문·검색 색인을 수정하거나 별도 경쟁 상태 대장을 만들지 않는다. Q001~339 및 기존 조회 호환 시험을 보존한다. 기존 스키마가 확장 불가하면 후속 연결표를 기존 대장에 참조시키고, 어떤 대장이 어떤 범위를 소유하는지 명시한다.

각 질문/후속 항목은 정확한 원문 판본·결정 상태와 함께 다음을 연결한다.

- 관련 기존 WI/폐루프/작업, 공통 모듈·후속 확장 여부. 여러 질문→한 WI와 한 질문→여러 WI를 허용한다.
- Approved 기획·Required 연구·작업 명세 hash와 기존 상한, 담당·수정 경로·공유 계약·실제 선행 의존성.
- 현재 Logic/Presentation/통합 E, 근거와 재검증 필요 여부. 코드/시험만 있는 항목은 실제 연결 완료와 분리한다.
- 실행 가능 / 기술 선행 대기 / 기획·연구 결속 필요 / 명시 보류 / 대체 또는 공통 원칙으로 분류한다. 이는 기존 상태를 설명하는 조회 분류이며 새 실행 상태 값 도입을 강제하지 않는다.
- 다음 최소 작업과 E5까지의 누락: Session·시간·권한·Save/Replay·실제 자산·입력·화면·인수 등.

질문 번호는 누락 검사·출처 추적에 사용하고 구현 우선순위로 강제하지 않는다. 기존 r65의 판정과 새 분류가 다르면 대체 근거를 남긴다. 첫 전수 분류 중에도 이미 승인된 실행 가능 작업은 계속한다.

## 5. 하나의 장면 안에서의 조립 원칙

canonical `SimulationWorldShell`에 기존 영역 모듈로 통합한다. Farm/Hub/City는 독립 내부 루프를 유지하고 모든 것을 한 장소에 밀집시키거나 Farm→Hub→City 필수 동선으로 묶지 않는다. 미구현 기능을 장식으로 놓은 경우 기능 사용 가능 표시를 하지 않는다.

배치 엔진은 계획/검증, LH는 필요한 셀의 준비·유지·해제, Simulation은 상태·행위 권위, Unity는 표현을 맡는다. 기존 Coordinator 인계를 재사용하고 표현 해제로 작물/NPC/Session을 삭제하지 않는다. 카메라·빛·수목·통행·상호작용 거리의 겹침을 같은 시점에서 확인하되 별도 승인된 지형/연구 기준선을 변경하지 않는다.

## 6. 전문 배분과 수용

- 기획: 전체 의도·순위·미정 판단, 추가 주제/연구 승인. 공유 코드/Scene·개발 상태판 직접 수정 없음.
- 개발: Queue 전수 대조·작업 명세/소유권·공통 Session/Save·권위/통합·검증. 기존 공유 Save 예약을 먼저 재확인하고 서로 다른 판본 구현을 병렬 생성하지 않음.
- 공간: 실제 지면/자산·통행·View 검증·반복 조립/해제. Editor 단독 점유를 개발이 조율.
- 애니: 기존 보유Clip 우선, 실제 상태에 따른 동작·중단·복귀. Editor 없이 가능한 분석/독립 코드부터 병행.
- 자료: 기존 승인 수집·권리·출처 검토만. 공공 자료 부재로 무관한 가상 게임 Fixture 구현을 막지 않으며 외부 호출 범위 확대 없음.

전문→개발의 인수는 실제 파일·hash·시험·화면을 확인한 뒤 이뤄진다. 새 명세/수정 경로와 Required 연구가 필요한 실행 묶음은 결속 후 착수한다. 이 전체 계획은 개별 E7 작업 명세를 대신하지 않는다.

## 7. 회차와 아침 산출물

1. 실행 가능한 다음 한 묶음을 고르고 원문/명세·변경 소유를 재확인한다.
2. 작은 구현→집중 시험/소비자 검증→필요 실제 Play/입력→같은 상태의 표현 확인→검증 근거/남은 차단을 기존 대장에 반영한다.
3. 가능하면 같은 후보의 해제·재적용·재진입 및 저장 복원을 확인한다. 불가능하면 E5 주장에 필요한 빠진 근거를 명시한다. 기존 Save 호환은 해당 작업 명세의 요구를 따른다.
4. 중요한 시각 수정은 UI 포함 실제 Game View 전후·조건/입력·Console·성능·실패를 묶어 반환한다. Prefab 렌더나 미수정 Nature 화면을 새 기능 성공으로 대체하지 않는다.

아침에는 (a) 전체 질문/후속 항목의 분류 커버리지·누락·소실 (b) 실제 통합 E5 달성 묶음과 근거 (c) 부분 구현/시험만 통과한 묶음 (d) 실제 변경 전후 이미지 (e) 미완료 이유·다음 Queue를 받는다. 완료 수를 약속하거나 작업 시간을 소요 추정으로 쓰지 않는다. 전수 대조가 미완료라면 완료한 범위와 잔여를 명시한다.

## 8. 이번 계획 작성 검증과 제외

기획은 검색 Validate 437/811, Goal r66 및 활성 작업/하위 상한, E 체계, 기존 야간/배경 보완 문서를 확인했다. 이번 계획만으로 전체 원문/코드를 전수 검토했다고 보고하지 않는다. 계획 문서 검증은 게임 시험·Scene 통합 증거가 아니다.

공급사 원본/미소유 dirty 보존, 강제 종료·복구/광범위 삭제·패키지 업데이트·유료 API/자료 대량 수집·운영 DB/게시·commit/push 금지와 기존 승인 경계는 유지한다. 09:00 이후 지속 실행이나 새로운 자동화는 이 문서로 추가하지 않는다.
