- 기획 ID: `PLAN-PLANNING-DECISION-READING-001`
- 기획 분야: `기획 관리 / 역사 결정 조회`
- 기획 판본: `planning-decision-reading-guide.r1`
- 상태: `ReadyForReview`
- 상위 기획: `PLAN-PLANNING-MIGRATION-001`
- 관련 하위 기획: 없음
- 관련 결정·기준: [결정 원장](DECISIONS.md), [기획 문서 독립 관리 체계](../Architecture/기획문서독립관리체계.md)
- 관련 WI·PlayableLoop: 없음; 과거 결정에서 현행 기획·WI 근거를 찾는 읽기 안내
- Graph Map 영향: `NoImpact`; 과거 D 범위를 Graph Map 입력으로 사용하지 않음
- 다음 질문 또는 인계 상태: 새 과거 결정이 현행 기획으로 이관될 때 목적별 시작점과 호환 포인터를 갱신

## 1. 왜 D 번호만으로 기획 시작점을 찾기 어려운가

`D-001`, `D-400`, `D-500`의 숫자는 기획 깊이나 기능 순서가 아니라 **결정이 기록된 전역 시간 순서**다. 아키텍처·자료·Unity·운영·표현·게임플레이·스토리 결정이 같은 번호열을 공유한다.

따라서 `D-400부터 기획`, `D-500부터 메인 스토리`처럼 번호 하나를 경계로 읽지 않는다. 무엇을 보려는지에 따라 아래 시작점을 사용한다.

현행 기획은 이제 [기획 목차](PLANNING.md)에서 별도로 관리한다. 아래 D 시작점은 과거 결정 이력을 읽기 위한 안내이며 새 기획의 목차를 대신하지 않는다.

## 2. 목적별 시작점

| 읽고 싶은 것 | 권장 시작 | 의미 |
| --- | --- | --- |
| 프로젝트 전체 기반 | D-001 | Unity World, 서버 권위, Simulation/Operational 분리 등 기술·제품 기반 |
| 플레이 구조의 공식화 | D-231 | WI, PlayableLoop, H, E를 플레이어 행동과 결과 중심으로 묶기 시작한 지점 |
| 기획→개발 공식 절차 | D-269 | 승인된 주제 기획, 문답, 전문 연구, 개발 인계를 공식화한 지점 |
| 현재 기획 문답 방식 | D-391 | 시간·공간·나·대상·이렇게와 결과·다음 선택으로 기존 기획을 다시 읽기 시작한 지점 |
| 발견형 첫 이야기 | D-408 | 숲 가장자리·Farm 외곽에서 발견하며 알아가는 첫 인과를 이야기로 구체화한 지점 |
| Graph Map 인계 | D-488 | 승인된 기획을 Graph Map 레벨 1·2·3으로 옮기고 개발 slice로 반환하는 절차의 시작 |
| 현행 메인 스토리 | D-490 | 빙의 대상, 소가주·모험가, 요동성, 한스, 호송과 이데아를 하나의 이야기 축으로 묶기 시작한 지점 |

가장 이른 게임플레이 결정은 D-096에도 존재하지만 타로라는 개별 기능에 관한 초기 결정이다. 현재 프로젝트의 **체계적인 플레이 기획 출발점**은 D-231, **현재 사용하는 문답형 기획 출발점**은 D-391, **현행 메인 스토리 출발점**은 D-490으로 보는 편이 정확하다.

## 3. 기획의 발전 구간

### A. 기반 구간 — D-001~D-230

- Unity와 서버의 책임
- World·Simulation·Data·Presentation 구조
- H와 E의 초기 경계
- 자료와 외부 자산을 권위에서 분리하는 원칙

이 구간은 이후 기획이 지켜야 할 바닥 규칙이다. 플레이 장면을 순서대로 설명하는 메인 스토리 구간은 아니다.

### B. 플레이 구조화 구간 — D-231~D-286

- WI가 한 의도와 주요 결과를 소유
- 여러 WI를 PlayableLoop로 조립
- Logic과 Presentation을 분리
- 기획 승인 뒤 개발·전문 연구로 인계

여기서부터 현재의 게임 기획을 코드와 증거 단계로 연결할 수 있는 공식 골격이 만들어졌다.

### C. 세부 플레이 규칙 구간 — D-287~D-390

- 체력·마나·명상·휴식
- 건설·농사·상호작용
- 표현 E4→E5 준비와 개별 배치 성립

각 기능의 선택·대가·실패·회복을 세밀하게 정한 구간이다.

### D. 현재 문답 체계 구간 — D-391~D-407

- `지금·여기·나·너·이렇게`
- 결과와 다음 선택
- 한 회차 한 질문
- 절기, 시점, 월드맵과 배치 책임

현재 기획 스레드에서 문답을 이어갈 때 사용하는 직접적인 출발점이다.

### E. 발견형 이야기 구간 — D-408~D-485

- Nature에서 Farm을 발견하는 첫 흐름
- 절기·날씨·시점과 집중 행동
- 게임 객체·Synty 자산·현실 자료
- Hub 발견, 요동성 방어, 전투 위험과 준비

기능별 결정이 플레이어가 겪는 사건 순서로 바뀌기 시작한 구간이다.

### F. 메인 스토리·Graph Map 구간 — D-486 이후

- D-486~D-487: 분야별 결정 ID와 WI 관계 색인
- D-488~D-489: 기획→Graph Map→개발 인계
- D-490 이후: 모험가·소가주, 요동성, 영지 수급, 한스, 호송, 이데아, 공방·Hub·마수 이야기

현재 새 이야기와 Graph Map을 검토할 때 가장 많이 읽게 되는 구간이다.

## 5. 번호와 분야별 ID를 함께 읽는 법

예를 들어 D-553은 전역 시간 순서 번호이고, `D-GAMEPLAY-COMBAT-DIVIDE-CONQUER-001`은 게임플레이/전투 분할 대응 분야의 첫 결정이라는 뜻이다.

```text
D-553
  └─ 전체 결정 이력에서 553번째 번호

D-GAMEPLAY-COMBAT-DIVIDE-CONQUER-001
  └─ 게임플레이 / 전투 분할 대응 / 해당 세부주제의 첫 결정
```

이 두 식별자는 과거 결정 원장을 읽을 때만 함께 표시한다. 현행 기획 문답과 진행 상황은 `[기획 · 분야 · PLAN-* · 판본]`으로 표시하며 일반 기획 선택에 새 D 번호를 부여하지 않는다. 과거 D에서 가져온 내용은 현행 기획 문서의 계보·대체표에서 `유지 / 부분 대체 / 참조 전용 / 충돌 / 제외` 범위를 확인한다.
