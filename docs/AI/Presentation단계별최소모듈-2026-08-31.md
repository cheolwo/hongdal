# Presentation 단계별 최소 모듈

- 결정: D-386
- 판본: presentation-minimum-modules.design.r1
- 상태: Approved
- 승인: 2026-08-31 사용자의 「Presentation 단계별 최소 공통 모듈 정비」 계획에 대한 `Implement the proposed plan.`

## 목적

별도 E 축이나 제작 대장을 만들지 않고 기존 Presentation E1~E7에 필요한 책임, 구현 경로, 시험 및 실제 증거를 연결한다. 첫 소비자는 기존 Farm의 한 밭 수확이다. 공통 도구와 모듈 준비를 실제 수확·Game View 완료로 표현하지 않는다.

## 플레이어 약속

기존 수확 가능한 밭을 선택하고 기존 Preview/Confirm을 통해 수확 결과를 읽는 표현을 준비한다. 현재 단계의 첫 산출물은 이 흐름에 필요한 공통 뼈대와 누락 판정이며, 실행 상태가 공급되지 않으면 미연결로 표시한다. 전체 농장·운반·판매·부분 수확·새 성장 규칙은 추가하지 않는다.

## 단계별 최소 책임

| E | 책임 | 최소 근거 |
| --- | --- | --- |
| E1 | 표현 요구·상태·오류·귀환 계약 | 승인된 판독 기준 |
| E2 | 상태 투영·자산 조회·표현 수명·도구 코드 | 실제 구현 참조와 입력·출력 |
| E3 | 표현 및 도구 회귀 | 중복·오래된 상태·조립/해제·실패 중단·보존 시험 |
| E4 | 자산·필요 가공·Rig/Clip·배치 후보 인계 | 준비 상태·판본·미해결 사항 |
| E5 | 권위 상태와 실제 장면 결속 | 필요한 Renderer/Collider/Bounds·상태 변화 |
| E6 | 판독·공간·동작·피드백 정제 | 동일 조건 비교와 결함 처리 |
| E7 | 실제 입력·결과·회복·귀환 | 저장 Scene·Game View·Console·재진입 |

## 재사용과 조건부 적용

기존 WorldVisualCatalog·공용AnimationAdapter·표시 소유권·분야별 상태 투영을 먼저 대조한다. 모듈은 책임 단위이지 E별 새 클래스가 아니다. 캐릭터·건물·지면·음향은 실제로 사용하는 기능에만 적용한다. 빈 구현이나 항상 성공하는 검사를 완성으로 세지 않는다.

## 관리 계약

기존 표현 검증 모듈 대장에 E1~E3 최소 책임과 입력·출력·구현/시험 참조를 추가한다. 작업 명세의 Presentation 모듈 연결은 선택적 확장으로 읽고, 없는 과거 명세는 미확인으로 표시한다. 검증 상태와 존재하는 소스 파일을 구분한다. Passed는 판본에 결속된 증거가 필요하며 자동 검사는 실제 화면을 대신하지 않는다. 단계 판정과 원장 승격은 자동 실행하지 않는다.

## 권위·호환 경계

Logic 코드·게임 규칙·Save·공개 게임 API를 변경하지 않는다. 필요한 권위 정보가 없으면 해당 문제를 보고한다. E 정의·Logic/Presentation 최솟값·Presentation E5의 Logic E5 선행 조건과 기존 승인 상한을 유지한다. 기존 동결 기획·연구는 덮어쓰지 않고 이 승인을 추가 연결한다.

## 검증

대장/명세 호환, 단계 누락, 잘못된 구현 참조, 근거 없는 Passed, 후보/증거 판본 불일치, 비적용 사유를 검증한다. 공통 도구는 소수 표본 선행 검사와 첫 실패 중단을 시험하고, Farm은 실제 상태 주입 없이 누락을 판정한다. 코드·시험과 Editor·Game View·수확 성공을 분리한다.

## 담당·소유

이번 기획 구현 담당은 Hongdal의 표현 대장·관리기·시험·템플릿·기준 문서·상태판을 소유한다. 개발 담당은 별도 지시된 좁은 Unity 표현/시험 경로만 소유하며 Logic·공통 원장·Scene·Packages를 변경하지 않는다. 실제 캡처는 별도 입력/판본을 받은 공간 담당의 단독 Editor 점유로 진행한다.

## 중지·재개

이번 승인만 실행한다. 중지된 야간 자동화와 r129 잔여 작업, 다른 전문 작업, 실제 Scene 수리·저장·대량 촬영을 자동 재개하지 않는다. commit/push·외부 호출·자산 다운로드·새 Blender 가공은 포함하지 않는다.
