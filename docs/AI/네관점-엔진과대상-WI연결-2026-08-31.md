# 네 관점에 엔진·플레이어·대상을 연결하는 기획

- 판본: r1 / 2026-08-31 / D393
- 상태: 기획 방향 확인. 엔진 재구현·상태 권위 이전이나 실제 연결 완료가 아니다.
- 기존 기준: [D391 네 관점](시간공간플레이어대상-WI기획정리-2026-08-31.md), [D392 전체 이관](전체기획-네관점순환이관-2026-08-31.md). 두 원문을 대체하지 않는 추가 대응 기준이다.

## 1. 사용자가 제안한 구조

시간성과 공간성 속에서 플레이어인 나와 대상인 상대·사물·환경이 만나고, 그때 내가 어떻게 할지를 WI로 설명한다. 이제 네 관점을 추상적인 질문에만 두지 않고 기존 시스템과 시각 자료까지 연결해 읽는다.

| 기획 관점 | 함께 찾아볼 기존 시스템·자료 | 책임 경계 |
| --- | --- | --- |
| 시간성 | Sky 관리 문맥, 시간대·날씨·빛·계절 관련 기획, 해당 Simulation 시계·Task·기한 규칙 | Sky가 시간·대기의 체감을 담당하더라도 모든 작업 시간의 권위는 아니다. 실제 경과·성장·중단·완료는 각 Simulation 규칙이 판정한다. |
| 공간성 | H1~H5·AreaSet, LH 셀 준비/스트리밍, 실내외 배치·조립 계획과 소비, 접근·통행·지지·차폐 | LH는 필요한 공간의 준비/유지/해제, 배치 계층은 기존 계획에 따른 배치·조립을 담당한다. 같은 공간 파이프라인에서 조율하되 의미 설계·권위 공간 조건과 Unity 표현을 합치지 않는다. |
| 나 — 플레이어 | Actor 상태·능력·지식·체력/마나, 인벤토리·장착 상태, 상태창·카드·입력 | 상태창은 상태를 읽고 선택하게 하는 표현이다. 장착·소비·성장 등의 확정은 기존 Simulation 계약을 따른다. 준비된 시스템과 미구현 구상을 구분한다. |
| 대상 — 상대·사물·환경 | NPC·몬스터·약초·나무·물·불·시설 등의 상태/역할, 상호작용 가능한 성질과 표현 | 대상은 단일 엔진이 아니라 여러 기존 기능의 조회 관점이다. NPC/몬스터의 행동 주체성과 사물/환경의 성질을 구분하고, 대상별 상태 권위를 유지한다. |

여기서 주객 구분은 **플레이어가 세계를 이해하고 행동을 고르는 관점**이다. 다른 NPC도 자기 행동의 주체가 될 수 있으며, 이 분류로 Actor/대상 원장이나 클래스 체계를 새로 나누지 않는다. 자기 자신을 대상으로 하는 회복·장착 등도 별도 외부 대상을 억지로 만들지 않고 설명할 수 있다.

## 2. 엔진의 관리 묶음과 실제 권위

### 시간성과 Sky

[Sky Engine 세계 대기 표현 계층](../Architecture/SkyEngine세계대기표현계층.md)은 이미 관측 자료·입력 프로필·Simulation 대기 상태·Unity 표현을 하나의 관리 문맥으로 안내한다. 이 구조를 시간성의 주요 탐색 경로로 사용한다.

- Simulation의 시간/대기 상태 → Sky의 하늘·빛·날씨·음향 표현이라는 경계를 유지한다.
- 제작 시간, 재배 기간, 회복 구간, 채무 기한은 각각 해당 규칙도 연결한다. Sky 하나에 모든 타이머를 옮기지 않는다.
- 현실 시간·권위 초·게임 일·WorldTick·애니메이션 시간은 단위와 원천을 구분한다. 밤낮 연출만으로 성장·완성·기한 경과를 확정하지 않는다.
- 시간성에 날씨를 함께 연결하더라도 날씨가 시간 그 자체는 아니다. 비·바람·빛이 행동에 미치는 영향은 기존 환경 규칙의 근거를 따른다.

### 공간성과 LH·배치

[LH 공간 실행계층](../Architecture/LH공간실행계층.md)은 의미 공간 설계와 셀 준비를 구분한다. 기획 목차에서 공간 아래 LH·배치 엔진을 함께 보여주되 코드 상속·호출 계층이나 엔진 병합 승인으로 해석하지 않는다.

- 기존 H/AreaSet 의도와 배치 계획을 기준으로 LH의 실행 셀 준비와 배치·조립 소비를 연결한다.
- 같은 대상/판본의 준비·적용·유지·해제·재적용을 추적한다. 관련 실행 순서와 조율 주체는 개발이 기존 계약을 대조한다.
- LH가 표현을 해제했다는 이유만으로 화면 밖 NPC·제작·작물의 권위 상태를 삭제하거나 시간을 멈추지 않는다. 실제 지속·중단은 해당 기획 규칙이다.
- 배치된 Prefab의 외형이 공간 능력·접근 가능·WI 성공을 자동 보장하지 않는다.

## 3. 네 조건에서 WI와 다음 선택으로

예를 들어 약초를 발견한 상황을 정리할 때, 시간/날씨와 행동 가능성의 관계, 약초가 있는 위치와 접근, 플레이어의 지식·도구·소지 여유, 약초의 식별·채집 가능 상태를 함께 찾는다. 원문에 정해진 조건만 WI의 허용/거부에 연결한다. 밤이나 비가 어떤 페널티를 준다는 새 규칙은 이 예시에서 만들지 않는다.

행동 결과는 플레이어와 대상의 상태를 바꾸거나 정보를 늘릴 수 있다. 그 결과로 운반·제작·회복·거래 등 어떤 다음 선택이 가능한지 기존 문답과 연결한다. 대상이나 조건이 바뀌면 선택도 달라질 수 있으며 유일한 고정 순서는 아니다.

상태창 열기·인벤토리 보기·대상 정보 읽기 등 표현 입력과, 물품 획득·장착·채집·거래 등 권위 변화 행위를 구분한다. 모든 UI 입력을 WI로 새로 등록하지 않는다. WI의 현재 등록 여부와 보편 행위 후보도 분리한다.

## 4. 전체 기획 이관에 추가할 연결

D392의 기존 일곱 칸(시간/공간/플레이어/대상/선택WI/결과/다음선택)은 유지한다. 각 칸에서 관련 모듈·상태 원천·표현 소비와 미연결 근거를 찾아볼 수 있게 한다. 별도 엔진별 병렬 문답/DB를 만들지 않는다.

- 시간 칸: Sky 표현과 해당 권위 시간/행동 규칙을 구분해 참조한다.
- 공간 칸: H 역할·포함 관계와 LH·배치 소비를 구분해 참조한다.
- 플레이어 칸: 권위 상태/소지·장착과 이를 보여주는 UI를 구분한다.
- 대상 칸: 실제 대상 식별·역할·상태 공급과 Prefab/애니메이션/표시를 구분한다.
- WI 이후: 어떤 조건이 달라졌는지, 권위 결과가 어떤 화면·소리로 읽히며 어떤 다음 선택을 여는지 확인한다.

하나의 모듈은 여러 관점에 등장할 수 있다. 환경의 빛·비는 시간 체감과 대상/공간 조건에 함께 연결될 수 있지만 원본 상태를 중복 소유하지 않는다. 목록에 연결됐다는 사실을 구현/E 완료로 표시하지 않는다.

## 5. 담당과 범위

기획은 위 대응 방향과 문답 의미를 소유한다. 개발은 D392 전체 이관을 이어가며 기존 엔진·계약·색인/생성 문서와의 실제 연결을 조사·검증하고 필요한 최소 조회 보완을 맡는다. 구체 클래스·엔진 호출 순서·상태 공급이 다른 경우 실제 근거와 차이를 기획으로 반환한다.

이번은 문서 관점과 시스템 대응의 추가 방향이다. Sky/LH 권위 이전·엔진 병합/재구현·새 상태창/대상 기능·시간 규칙·WI/H/E·Scene/Save·외부 호출·commit/push를 승인하지 않는다. 기존 H1 시각조사는 별도 승인 범위로, r129/야간/다른 기능은 중지 상태로 유지한다. D391/D392 전체 이관은 새 구조로 다시 시작하지 않고 위 연결을 추가하며 계속 진행한다.
