## 1. 사용자 의도와 승인 범위

사용자는 기존 KAMIS·AMS 자료를 MySQL에 보관했던 서버처럼, 농사로·한약재 관련 자료·온라인 쇼핑 자료도 축적하여 활용할 수 있기를 원한다. 기존 Ssalddel ASP.NET 서버를 활용하고 자료조사 담당이 이 자료 축을 맡으며, Unity 배치와 독립적으로 진행한다.

| 의미 식별자 | 상태 | 범위 |
| --- | --- | --- |
| `reality-data-existing-server-mysql-archive` | `Confirmed` | 기존 서버·MySQL에 현실 자료의 저장·조회 기반을 단계적으로 갖춘다. 새 병렬 서버/게임 DB를 만들지 않는다. |
| `reality-data-agriculture-herbal-market-domains` | `ConfirmedDirection` | KAMIS/AMS 재사용을 바탕으로 농사로·한약재 참고·온라인 상품 자료를 다룬다. 모든 제공처의 수집·보관·재표시 허용을 확정하지 않는다. |
| `reality-data-research-owner-development-integration` | `Confirmed` | 자료조사 담당이 자료 관리·전문 조사, 개발이 서버/DB 구현·검증·인수를 맡아 기획으로 반환한다. |

이번 요청은 과거 D366/D371/D403/D413의 문서 조사 범위보다 서버 축적을 확장하는 후속 승인이다. 과거 표본의 권리·제품 반입·상품 대응 미확정을 소급 해제하지 않는다. 실제 운영 서버 접속 정보·쓰기 대상·백업/이관 조건이 확정되지 않았으므로 운영 DB 조작은 첫 묶음에서 하지 않는다.

## 4. 저장과 조회의 최소 구분

한 개의 만능 테이블에 서로 다른 뜻을 섞기보다 기존 분야별 테이블·공통 식별자/자료 출처를 재사용한다. 아래는 개념 구분이며 새 테이블 여섯 개나 새 DB 생성 요구가 아니다. 개발이 기존 계약으로 충족되는지 먼저 대조한다.

| 구분 | 최소 보존 정보 |
| --- | --- |
| 출처와 이용조건 | 기관·제공처·자료/서비스 식별자·공식 URL·확인일·접근/보관/재표시 범위·조건 근거·재검토/만료 필요 |
| 입수 기록 | 수집 실행 식별자·요청 범위·성공/부분/실패·수집 시점·건수·재시도/중복 관계. 비밀값과 개인정보는 제외 |
| 원자료/근거 | 허용된 원자료 또는 기존 비공개 저장 위치·실제 확보 hash·원자료 식별자/판본. 원문 보관이 불허/미확인이면 허용된 메타데이터/참조만 |
| 정리된 자료 | 원자료와 변환 판본·원본/정규화 값 구분·지역/단위/통화·기준 시점·누락/불확실성. 가격 미확인을 0으로 채우지 않음 |
| 품목 대응 | 내부 품목과 외부 코드/식물 종/상품의 대응 근거·동일/유사/미확정·검토자/시점. KAMIS·AMS·농사로 코드는 별개 |
| 검토와 제공 | 확보/내용 검토/이용조건 확인/기획 참고/게임 연결/사용자 게시를 별개로 관리. 개정 시 영향받는 승인의 재검토 필요 표시 |

MySQL에는 검색·관계·판본·이력 등 조회 가능한 정보를 우선 보관한다. 대용량 원문·이미지를 무조건 DB 안에 넣거나 전량 보존하지 않고, 기존 비공개 저장소와 허용된 보관 기한·삭제/만료 절차를 적용한다. 같은 원자료 재수집은 중복 행을 만들지 않되 관측 시간에 의미가 있는 가격 이력을 덮어쓰지 않는다. 소스에서 제거되었거나 정정된 자료도 기존 정책에 맞게 이력을 남기고 이용 가능 여부를 다시 판정한다.

첫 관리 조회는 출처·분야·품목/외부 ID·지역·기준 날짜·검토/이용 상태로 찾고 원자료 근거까지 이어질 수 있으면 된다. 기존 관리자 조회/API/화면을 우선 활용하며 별도 대규모 관리 UI 제작은 선행하지 않는다.

## 5. 담당별 배분과 첫 작은 실행 묶음

### 자료조사 담당

기존 task `01a0524f-72e7-75e1-986a-d149951e1240`을 재사용한다. 개발이 정확 전용 경로를 배분한다. 제안 경로는 전문 worktree의 `docs/Research/GameData/D424/README.md`, `evidence.r1.json`, `manifest.r1.json`이며 공유본 통합은 개발이 한다.

기존 KAMIS/AMS·농사로·D371/403/413을 먼저 대조한다. 추가 공식 출처는 첫 묶음 총 3건 이내로 농사로/한약재/쇼핑의 공백을 설명하는 데 필요한 것만 선택한다. 새 표본은 출처당 최대 3레코드이며 무료 공개·허용 범위에서만 확보한다. 수를 채우기 위해 수집하지 않는다. 공개 페이지 안내만 확보한 경우 실제 데이터 표본으로 세지 않는다.

제출에는 자료별 필드·자연 식별키 후보·변경/갱신 방식·단위/시점·보관/재표시 조건과 미확인 항목, 기존 저장 경로 대응을 남긴다. 약재는 명칭/학명·사용 부위·가공 상태·출처 표현을 구분하며 의료 처방·복용량/치료 효과 추천이나 게임 포션 수치를 만들지 않는다. 로그인/API 신청·비용이 필요하면 D404 절차로 해당 자료만 먼저 보고한다. Apify 유료 실행·새 계정/키·접근 제한 우회는 하지 않는다.

### 개발 담당

1. 기존 서버의 수집기·DbContext·Entity/설정·마이그레이션·관리자 조회·권한·실행 차단·자료 카탈로그를 읽고 ‘코드 있음 / 저장 검증 있음 / 실제 운영 미확인’을 구분한다. 원본 접속 문자열·비밀값을 읽거나 보고서에 노출하지 않는다.
2. 정확 수정 경로와 공용 소유를 선언하고, 우선 기존 감자 저장/조회 등 가장 작은 기존 경로 하나에서 공백을 채운다. 이미 충족된다면 새 수집기를 만들지 않고 기존 경로의 검증과 부족한 분야별 저장 연결을 선택한다. 결과를 문서 조사만으로 마감하지 않는다.
3. 개발/시험 환경에서 가져오기 검증 → MySQL 저장 → 재조회 → 같은 자료 재입력의 중복 방지 → 변경 자료 개정 → 권한·보류 자료 비노출을 확인하는 작은 묶음을 구현한다. 자료 권리가 미확인이면 합성 Fixture로 기술 시험하고 실제 자료와 명확히 구분한다.
4. 필요한 스키마/마이그레이션 코드는 작성·검토할 수 있다. 실제 적용은 명확히 분리된 시험용 DB에만 허용한다. 기존 시험 환경이 없으면 운영 DB를 대신 쓰지 않고 필요한 로컬 준비를 반환한다. 새 DB 서버 설치·운영 스키마 변경은 임의로 하지 않는다.
5. 관리자용 가져오기/조회가 기존 API에 없으면 그 좁은 연결을 만들고 인증·역할 검사를 적용한다. 신규 정기 수집·Provider 연결·게시/통지·D374 전체 운영 UI는 자동으로 켜지 않는다.
6. 관련 단위/통합 회귀·빌드·범위 Fast/Task 결과와 실제 MySQL 사용 여부를 반환한다. InMemory/SQLite 시험을 MySQL 검증으로 보고하지 않는다. 중단/부분 실패 시 재실행과 마지막 성공 자료 조회도 구별한다.

자료 전문은 자료 의미·이용조건을 맡고 실제 서버 변경은 개발에 반환한다. 연구 역할 배정은 관리자 권한 부여가 아니며 전문의 직접 운영 SQL/DB 접속은 없다. 개발은 병행 중인 Farm D422/D423과 비중첩으로 진행하고 공용 `Program.cs`/DbContext/생성물 쓰기만 조율한다.

## 6. 자료 축과 게임 축의 연결

자료를 서버에 저장했다는 이유로 Simulation 시각·성장/수확·약효·가격·NPC 행동을 자동으로 바꾸지 않는다. 자료를 기획에 해석하고 내부 품목/규칙에 대응한 뒤 승인된 상태 사본/조회 경계를 통해 연결한다. 현실 자료는 관심이 생겼을 때 보는 선택형 참고이며 게임 진행의 필수 조건이 아니다.

국가·상품이 비슷하거나 환율/무게 환산이 가능하다는 이유만으로 동일 상품·차익·수익성을 확정하지 않는다. 실제 구매·계약·건강 조언·사용자 알림/게시와 게임 내부 결과는 분리한다. 이번 DB 축적을 Unity E5, 실제 운영 업무 성공 또는 제공처 권리 승인으로 계산하지 않는다.

## 7. 반환·후속 운영 경계

첫 반환에는 분야별 ‘기존 코드/자료 / 새 저장·조회 구현 / 실제 저장 시험 / 남은 접근·이용조건’을 한 목록으로 제시한다. 코드/시험·MySQL·운영 적용·게임 소비·외부 공개는 각각 표시한다. 자료 권리/계정 차단은 다른 독립 구현을 멈추지 않는다.

실제 운영 적용 전에는 대상 환경/스키마·마이그레이션 차이·백업/복구·수집량/주기·비용·권한·보관/삭제 조건과 사용자가 해야 할 조치를 반환한다. 이번에 새 자동화나 반복 수집을 예약하지 않는다. 기획 원문은 기획, 코드/시험·기존 등록/상태판·기술 보고는 개발이 갱신한다. r129/야간/다른 중지 작업·Scene/Save·새 게임 규칙·commit/push는 재개하지 않는다.
