# 농장 정돈과 상점 실내 진열 — 시각 배치 보완

- 날짜: 2026-08-31
- 기획 판본: `farm-orderly-layout-shop-indoor-display.plan.r1`
- 결정: D427 / `AcceptedPlanningDirection`
- 근거: 사용자가 제시된 농장 사진의 헛간·건물·밭을 서로 이격하여 질서 있게 정렬하고, 두 번째 상점 사진의 야외 진열대를 실내에 두도록 요청했다.
- 현재: 배치 방향 확정. 이번 문서 작성으로 실제 배치·상점 실내 적합성·Game View 확인이 완료된 것은 아니다.

## 1. 참고 화면과 적용 대상을 구분한다

참고는 [2026-08-09 그래픽 배경 기록](../Changes/2026-08-09-unity-farm-city-graphical-showcase.md)의 [농장 화면](../assets/changes/2026-08-09-unity-farm-city-showcase-farm.png)과 [상점 화면](../assets/changes/2026-08-09-unity-farm-city-showcase-market.png)이다. 과거 별도 Showcase에서 촬영한 것으로 현재 canonical World나 D426의 8개 후보 개별 캡처가 아니다. 원본 사진·실험 Scene을 덮어쓰거나 해당 Scene을 새 공식 World로 채택하지 않는다.

개발은 현재 World의 해당 역할·자산·조립 경로와 대응을 먼저 확인한다. 같은 객체가 없으면 과거 화면에 있었다는 이유로 생성·이동하지 않고, 기존 기획의 역할에 맞는 후보/계획으로 연결한다. [D426 대응 계획](개체레코드-시각자산대응-확장과개발인계-2026-08-31.md)의 데이터·자산 대응 승인과 이번 공간 배치 적합성은 별개다.

## 4. 기존 배치 구조를 통해 반영한다

[D422 Farm 점진 구성](Farm월드맵-배치계층경유-점진구성-2026-08-31.md)과 [D423 책임 구분](../Architecture/지도구성과세계자산배치분리.md)을 재사용한다. **구조·제약 → 배치 계획 → 계획 검사 → 월드 조립 → 실제 대조·해제/재적용**을 거치며 Prefab을 먼저 수동 이동한 뒤 검사된 것으로 기록하지 않는다.

- 농장: 기존 Farm 기획·Accepted 공간 연구의 Barn 원본 크기/예약 외곽·생산 면적·마당·자연 여백을 보존하고 이번 정돈 방향을 추가 연결한다. 상위 지도 전체 완성을 기다리지 않고 해당 작은 구간부터 검증한다.
- 상점: 기존 실내 배치/구성 경로와 보유 건물·선반을 먼저 조사한다. 외피뿐인 건물이나 막힌 내부라면 선반을 벽 속에 넣지 않는다. 실제 내부를 제공하는 기존 후보·실내 구성 대안을 비교하고 필요한 전문 연구와 명세를 결속한다. 건물 외관만으로 내부 공간/상점 능력이 있다고 추정하지 않는다.
- 두 구간은 독립적으로 진행한다. Farm 완료나 Farm 물품 운송을 상점 준비의 필수 선행으로 추가하지 않는다. 이번 방향으로 새 H/WI·게임 규칙·거래/재고 권위를 만들지 않는다.

## 5. 개발 인계와 반환 기준

기획은 이 원문과 DECISIONS/CURRENT의 인계 지점만 소유한다. 개발은 현행 문서·대상·원본/GUID·역할/VisualKey·판본·실제 호출을 대조하여 기존 명세와 담당/정확 쓰기 경로·검증 범위를 결속하고, 공간 담당에게 후보/배치 연구와 단독 Editor·캡처를 배분한다. 일반 코드/시험·생성물·통합 상태 갱신은 개발이 맡는다.

첫 반환은 현재 적용 대상과 가장 작은 개선안, 재사용 자산·실내 가능 여부·필수 결손이다. 기존 승인/Accepted 연구 범위의 Farm 기술 후속은 D422에 이어가며, 상점은 해당 실내 연구/명세가 갖춰진 범위부터 진행한다. 새 플레이 선택·건물 신규 제작이나 권위 변경이 필요하면 그 부분만 기획으로 반환한다.

결과는 (1) 조사/계획, (2) 코드·자동시험, (3) 실제 월드 적용, (4) 입력/통행·UI 포함 Game View로 나눈다. 같은 카메라/시간·날씨의 가능한 전후와 실제 접근 장면을 남기고, 원본 이미지나 과거 캡처를 새 개선 결과로 쓰지 않는다. 적용 후 기대 객체·활성 외곽·필요 Collider·출입/작업 통로, 해제/재적용의 중복·누락을 확인한다.

기존 자산 원본·미소유 dirty·실험 자료·세계/Save 상태는 보존한다. 새 공식 Scene·전체 Builder 재생성·일괄 삭제·패키지 변경·DB/외부 호출·미확인 Blender 가공·E 자동 승격·r129/야간/무관한 중지 작업·commit/push는 승인하지 않는다. Scene 저장은 기존 승인에서 자기 변경을 정확히 분리/복구할 수 있는 조건을 충족할 때만 별도로 기록한다.
