## 1. GPT가 먼저 이해할 목적

64괘의 정식 순서를 **스토리 제작 순서**로 사용한다. 제1괘 건과 제2괘 곤은 전체 이야기의 능동적·수용적 거시 흐름을 정하는 기반층이며, 제3괘 수뢰둔부터 그 흐름을 인물·장소·사건의 구체 서사로 만든다. 한 번에 한 괘만 연구·기획하고, 그 괘의 여섯 효 국면 또는 이야기를 모두 기획 승인한 뒤 다음 괘를 연다. 다만 제작 순서가 곧 runtime 플레이 순서나 384개의 강제 선형 퀘스트를 뜻하지는 않는다.

```text
현재 Active 괘의 원문·괘상·앞뒤 관계 확인
  → Mirror의 하나의 큰 이야기 주제로 번역
  → 건·곤은 초효부터 상효까지 여섯 거시 국면 설계
  → 제3괘부터는 여섯 구체 이야기 설계
  → 각 효에서 기존 스토리·사건을 먼저 대조하고 부족한 부분만 새로 기획
  → 여섯 효와 괘 전체 인과를 기획 승인
  → 다음 괘 하나를 Active로 전환
  → 승인된 효부터 Story Beat·PlayableLoop·WI·H·Graph Map·개발로 개별 인계
```

핵심 방향은 다음과 같다.

- 괘는 하나의 큰 상황이자 하나의 `Hexagram Arc`다.
- 건·곤의 여섯 효는 전체 스토리가 따라야 할 거시 국면이며 직접 Story Beat나 WI를 요구하지 않는다.
- 제3괘 이후의 여섯 효는 인물·장소·사건으로 나타나는 `Line Story`다.
- 효사는 퀘스트 명령이나 정답이 아니라 그 위치에서 던질 **서사적 질문**이다.
- 상효는 단순한 엔딩이 아니라 현재 상황이 극점에 이르러 다음 괘의 상황으로 넘어갈 수 있는 문이다.
- 64괘의 이름·순서·육효 슬롯은 먼저 만들되 이야기 내용은 현재 Active 괘 하나만 채운다.
- 제작은 제1괘부터 순서대로 진행하고, 실제 플레이 순서와 분기는 별도 기획 전까지 강제하지 않는다.

| 건·곤의 여섯 효 | 이후 구체 서사가 따라야 할 여섯 거시 국면 | 직접 퀘스트·Story Beat·WI가 아님 |

| 효사 | 이야기의 다음 판단을 깊게 하는 해석 질문 | 퀘스트 Command·Simulation 판정·정답이 아님 |
| PlayableLoop | 성공·실패·회복·귀환이 닫히는 실제 플레이 단위 | 한 괘와 반드시 1:1일 필요 없음 |

| WI | 플레이어·NPC·사물 등이 실제로 수행하는 행위 | 효사의 문장만으로 새 WI를 만들지 않음 |

| Graph Map | 승인된 주체·대상·행위·조건·결과 관계 | 괘 배정만으로 노드·엣지를 자동 생성하지 않음 |
| 배치 맵·H1~H5 | 사건이 일어나는 공간 구성과 포함 관계 | 괘를 건물·공간 계층으로 취급하지 않음 |
| E1~E10 | 기획·논리·표현·실행 증거의 성숙도 | 초효~상효와 번호가 비슷해도 직접 대응시키지 않음 |

특히 현재 프로젝트의 `WI 괘성 분류`는 금(태괘)·목(진괘)·수(감괘)·화(리괘)·토(간괘)를 행위 메타데이터로 사용한다. 새 64괘 체계는 **스토리 상황 색인**이므로 두 체계를 같은 필드나 같은 판정으로 합치지 않는다.

## 7. GPT가 수행할 정식 작업

1. 자유롭게 나온 새 기획이면 [역경 자유 기획 씨앗 분류 색인](generated/hexagram-story-seeds.md)에 먼저 보존하고, 정식 공부 작업이면 [64괘 스토리 제작 색인](generated/hexagram-story-production.md)에서 현재 `Active` 괘 하나를 확인한다.
2. 해당 괘의 괘상·괘사·육효와 앞뒤 괘 관계를 검증된 한문 원문에서 확인한다.
3. 원문과 프로젝트 자체 한국어 요약을 분리하고, 해석의 근거와 불확실성을 표시한다.
4. 자유 기획에는 괘 전체의 강한 의미를 기준으로 주괘 하나와 보조 후보를 이유와 함께 제안하고, 사용자 확인 전에는 확정하지 않는다.
5. 주체·상황·변화·결과가 충분히 구체화된 기획에만 `고전 의미 요약 → 서사 질문 → 필수 주 이야기 → 기존 기획 참조 → 부족한 정보`로 효 후보를 제안한다.
6. 기존 이야기를 먼저 대조하되 현재 괘에 맞지 않는 이야기를 억지로 끌어오지 않고 빈 자리는 새 기획 질문으로 남긴다.
7. 모험가와 소가주는 같은 괘·세계 변화를 공유하고, 효 내부의 접근·역할·행동 규모만 변형한다.
8. 정식 제작에서는 여섯 효의 이야기·참조·공백과 괘 전체 인과가 승인되기 전에는 다음 괘를 제작하지 않는다. 자유 기획 씨앗은 이 순서와 무관하게 어느 괘 후보로도 보존할 수 있다.
9. 승인된 효는 Story Beat·PlayableLoop·WI·H·Graph Map 인계 후보가 될 수 있지만 자동 생성·활성화·E 승격하지 않는다.
10. 건괘 `用九`와 곤괘 `用六`은 보충 해석으로만 다루고 일곱 번째 이야기를 만들지 않는다.

## 9. 고전 자료 사용 경계

현재 저장소에는 64괘의 순서·괘상·육효 슬롯 대장이 있으며, 각 괘의 괘사·효사 전문과 Mirror 해석은 해당 괘 제작 때 검증한다. 따라서 다음을 지킨다.

- 정확한 괘사·효사를 기억으로 만들어 쓰지 않는다.
- 고전 한문 원문, 번역, 현대 해설을 서로 구분하고 출처·판본·번역자를 기록한다.
- 현대 번역·해설의 긴 문장을 복제하지 않고 의미를 요약한다.
- 하나의 해설을 게임의 유일한 정답으로 만들지 않는다.
- 한스=`수뢰둔`은 `PrototypeReference`로만 두고 제3괘 승인 근거로 사용하지 않는다.
- 외부 조사는 이 문서의 프로젝트 내부 연결 정리와 별도 작업으로 수행한다.

## 11. 이번 문서에서 확정한 것과 아직 확정하지 않은 것

### 확정

- 64괘 정식 `01→64` 순서를 스토리 제작 순서로 사용한다.
- 한 번에 `Active` 괘 하나만 제작하고, 육효와 전체 인과 승인 뒤 다음 괘를 연다.
- 건·곤은 전체 이야기의 기반 흐름이며 효는 거시 국면이다.
- 제3괘부터 인물·장소·사건의 구체 서사가 시작되고 효는 각각 하나의 필수 주 이야기다.
- 각 효 안에서는 기존 이야기를 먼저 재사용하고 부족한 부분만 새로 기획한다.
- 효사는 서사적 질문으로 사용한다.
- 기존 `PLAN-*`, PlayableLoop, WI, Graph Map, H, E, 오행 분류를 유지한다.
- 한스·수뢰둔 배정은 제3괘 `PrototypeReference`로 보존한다.
- 실제 플레이 순서와 runtime 해금은 제작 순서와 분리한다.
