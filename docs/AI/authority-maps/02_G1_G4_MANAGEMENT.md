# G1~G4 관리 체계 지도

이 파일은 전달 묶음 안의 빠른 진입점이다. 상세 정의의 단일 기준은 [E 성숙도와 G 관리 체계](../../Architecture/E성숙도와G관리체계.md), 기계 기준은 [`evidence-management-systems.json`](../../../eng/execution-ledgers/evidence-management-systems.json)이다.

| 체계 | 주 구간 | 관리 질문 | 대표 작업 |
| --- | --- | --- | --- |
| G1 세계 성립 관리 | E1→E6 | 이 세계가 제대로 성립했는가? | WI, H1~H5, AreaSet, Graph, 현실 근거, Revision·Hash·Lineage |
| G2 플레이어 경험 관리 | E6→E7 | 사람이 실제로 플레이할 수 있는가? | HUD, 카드 서랍, 입력, 카메라, 이동, Preview·Confirm, Game View |
| G3 NPC 생활세계 관리 | E7→E8 | 플레이어가 없어도 다른 주체가 살아갈 수 있는가? | NPC 목표·이동·업무·경쟁·협력·연속성 |
| G4 변화·확장 적응 관리 | E8→E9 | 세계를 안전하게 변화시킬 수 있는가? | 영향 분석, Revision, Migration, 호환성, 회귀, 재승격 |

## 새 아이디어 routing

1. 세계의 의미·규칙·공간·근거를 바꾸면 G1부터 본다.
2. 플레이어 입력·UI·카메라·피드백을 바꾸면 G2다. 서버 계약이 함께 바뀌면 G1도 포함한다.
3. NPC가 스스로 선택하고 이동·경쟁·협력하게 만들면 G3다.
4. 이미 E8인 세계에 실제 변화를 적용하고 호환·회귀까지 관리할 때만 G4다.
5. G 작업 상태는 E 증거가 아니다. 최종 완료는 [E1~E9 정의](01_E1_E9_DEFINITION.md)의 해당 관문으로 판정한다.

## E9 우선 작업 routing

모든 의미 있는 새 게임 작업은 장기 완결 목표를 E9 관점에서 먼저 쓰고 E8~E1의 영향을 빠짐없이 분해할 수 있다. 이때 G4가 신규 기능의 현재 관리 단계가 되거나 E9가 자동 승격되는 것은 아니다. 실제 미완료 구간은 G1·G2·G3로 routing하고 E1부터 증거를 닫는다.

- 작업 명세: [E9↔E1 반복 왕복 구현 체계](../../Architecture/E9하향식수직구현체계.md)
- E9 승격: 실제 E8 기준선에 후속 변화를 적용하고 G4 회귀를 통과할 때만 가능
