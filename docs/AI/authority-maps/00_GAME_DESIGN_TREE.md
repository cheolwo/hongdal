# 게임 기획 최상위 권위 트리

> 기준일: 2026-08-22
> 역할: 새 아이디어가 어떤 플레이를 위해 존재하고 어떤 WI·H·E 증거를 요구하는지 판단하는 최상위 routing 지도다. 세부 규칙의 권위는 연결된 계약·대장·결정 문서에 있다.

핵심 의미 추적은 **플레이 목적 → WI → H → E → G**다. 실제 새 작업은 이 의미를 E9 목표 봉투에 넣고 `E9→E1`로 하향 분해한 뒤 `E1→E9`로 증거를 닫는다.

## 플레이어 약속

플레이어는 **Nature에서 도구를 얻고 자원을 채집해 생활 거점을 만들며 위협을 견디고, 그 결과에 심리 회복을 결합한다. Farm·Hub·Town·City에서는 독립 업무를 선택하고, 결과가 다음 날의 세계 상태와 가능한 행동을 실제로 바꾸는 생활세계를 플레이한다.**

```text
하루 목표와 현재 세계 상태 확인
  ↓
Nature 안전 빈터에서 도구 획득·벌목·생활 거점 건설
  ↓
황혼 위협에 전투 또는 후퇴하고 회복·재출발
  ↓
업무 영역 하나의 내부 플레이 선택
  ├─ Farm: 생산 → 수확 → 집하 → 포장·보관 → 다음 생산 조건
  ├─ Hub: 입고 → 검수 → 적재 → 내부 보관·출고 → 다음 처리 조건
  ├─ Town: 시장 입고 → 진열 → 주문 → 수령·소비 → 다음 생활 수요
  └─ City: 도심 물류·마트 운영의 독립 업무 폐루프
  ↓
정상·기회·위협·회복 결과
  ├─ 직접 업무 효과는 발생 업무 영역에 남음
  └─ 심리 영역은 회복력·위협 반응을 완충하지만 업무 원인을 대신 해결하지 않음
  ↓
턴 마감 → Save/Replay → 다음 날 또는 명시적으로 선택한 영역 간 통합
```

## 최상위 트리

```text
Ssalddel 플레이 세계
├─ 1. 세계 기반 [G1 / E1~E6]
│  ├─ 서버 권위 Session·Revision·WorldTick
│  ├─ WI Preview → Confirm → Task → Effect
│  ├─ Save·Replay와 결정성
│  ├─ H1~H5 공간·AreaSet·Graph
│  └─ 선택형 현실 문맥·출처·Hash·Lineage
│
├─ 2. 플레이어 생활과 업무 [G2 / E6→E7]
│  ├─ Nature 생존 생활거점 첫 기준 플레이
│  │  ├─ 도끼 획득·벌목·목재·오두막
│  │  └─ 황혼 조우·전투/후퇴·회복·재출발
│  ├─ Nature↔Farm 선택적 통합
│  ├─ Farm 독립 내부 폐루프
│  ├─ Hub 독립 내부 폐루프
│  ├─ Town 독립 내부 폐루프
│  ├─ City 독립 내부 폐루프
│  └─ 양쪽 영역 준비 뒤의 선택적 영역 간 통합
│
├─ 3. 플레이 방식
│  ├─ 생산: 토양 → 파종 → 관리 → 수확 Lot
│  ├─ 건설: 자재 예약 → 단계 진행 → Facility·Capacity 활성화
│  ├─ 탐험: 발견 → 위협 관찰 → 대응 또는 후퇴 → 복귀
│  ├─ 전투: 현장 전투 또는 파생 전장, DirectAction/TacticalCommand
│  ├─ 카드: 문맥·설명·역할·행동 수정 제안, 서버 규칙이 실제 Effect 확정
│  ├─ 심리: 같은 업무 사실에 대한 플레이어별 회복·위협 해석
│  └─ 시대: 같은 사실에 적용되는 결정적 시대 규칙과 표현
│
├─ 4. NPC 생활세계 [G3 / E7→E8]
│  ├─ 지속 정체성·역할·목표
│  ├─ 생활 이동과 업무 이동
│  ├─ 공간·자원 예약 경쟁
│  ├─ 협력·인계
│  └─ Effect가 다음 행동을 바꾸는 연속 폐루프
│
└─ 5. 변화 적응 [G4 / E8→E9]
   ├─ 새 규칙·콘텐츠·공간·카드·역할 제안
   ├─ E8→E1 하향 영향 분석
   ├─ Revision·Migration·호환성
   ├─ E1→E8 상향 재검증
   └─ 새 안정 Revision 승격
```

## 영역별 독립 역할

| 영역 | 플레이어에게 주는 핵심 약속 | 내부 폐루프 | 다른 영역과의 관계 |
| --- | --- | --- | --- |
| Nature | 숲에서 도구와 자원을 얻고 생활 거점을 만들어 위협을 견딘다. | 도끼 → 벌목 → 오두막 → 황혼 조우 → 전투/후퇴 → 회복·재출발 | 심리 회복을 함께 제공하지만 Farm 사건을 대신 해결하지 않는다. |
| Farm | 작물과 시설을 관리해 눈에 보이는 Lot·Capacity·다음 날 조건을 만든다. | 준비 → 생산 → 수확 → 집하 → 포장/보관 → 반복 | Hub 없이도 내부 플레이·Fixture·Save/Replay가 닫혀야 한다. |
| Hub | 들어온 자원을 검수·보관·가공·출고하며 병목과 회복을 관리한다. | 입고 → 검수 → 적재 → 내부 보관/피킹 → 출고 준비 | Farm 성과를 시작 조건으로 강제하지 않고 독립 Fixture를 가진다. |
| Town | 주민 수요와 시장 재고가 주문·수령·소비로 이어지는 생활권을 운영한다. | 시장 입고 → 진열 → 주문 → 수령 → 소비 → 다음 수요 | Hub 연결 전에도 독립 시장 Fixture로 실행 가능해야 한다. |
| City | 도심 마트·물류와 더 큰 밀도의 업무를 독립적으로 운영한다. | 도심 입고/운영 → 처리 → 서비스 결과 → 다음 운영 상태 | Hub와 목적·상태·완료 증거를 합치지 않는다. 기존 `CityHub` 안정 ID만 호환 목적으로 보존한다. |

## 필수 코어와 후속 확장

### 필수 코어

1. 서버 권위 Session·Revision·WorldTick과 `Preview → Confirm → Task → Effect`.
2. Command 멱등성, Save/Replay 결정성, canonical 상태 재조회.
3. Nature 도끼·벌목·오두막·황혼 조우·회복의 첫 E7 실제 플레이.
4. Farm 내부 생산·수확·집하·포장/보관 폐루프.
5. canonical `SimulationWorldShell` 하나와 실제 서버 기준 입력·UI·Game View.
6. 카드·카메라·애니메이션이 서버 결과를 재계산하지 않는 권위 경계.

### 후속 확장

- Hub·Town·City 각각의 독립 내부 폐루프와 E7 증거.
- 양쪽 독립 준비가 확인된 뒤의 Farm↔Hub, Hub↔Town 등 영역 간 통합.
- NPC 지속 생활세계 E8.
- 새 계절·경제·역할·카드·AreaSet을 실제로 적용하는 E9 변화 단위.
- 대규모 군중, 대화형 AI, 운영 계약·결제·자동 배차와 외부 효과.

## 아이디어 분류 순서

```text
아이디어
  ↓  어떤 플레이어 행동·선택·결과를 만드는가?
플레이 문장
  ↓  어떤 안정 세계·호환·rollback을 목표로 하는가?
E9 목표 봉투
  ↓
E8 NPC → E7 플레이어 → E6 정제·근거 → E5 WI 세계 발현
  → E4 WI 실행 문맥 → E3 시험 → E2 코드 → E1 계약
  ↓  가장 낮은 미완료 의존성부터 구현
E1 → E2 → E3 → E4 → E5 → E6 → E7 → E8 → E9 검증
```
