# E1~E9 증거 성숙도 정의

> 기계 권위: [`eng/execution-ledgers/evidence-stages.json`](../../../eng/execution-ledgers/evidence-stages.json) `simulation-evidence-stages.r10`
> E는 기능 목록이나 개발 순서가 아니라 **선정된 판정 단위가 실제로 확보한 증거 깊이**다.

## 전체 계단

| 단계 | 이름 | 무엇이 존재해야 하는가 | 이것만으로 주장할 수 없는 것 |
| --- | --- | --- | --- |
| E0 | 후보 | 실행 후보와 목적이 식별됨 | 계약 확정, 코드, 실행 |
| E1 | 계약·결정 완료 | 행위·자료·권위 경계와 완료 조건이 확정됨 | 구현 또는 자동 시험 |
| E2 | 코드 준비 | 서버·Simulation 또는 도구 코드가 준비됨 | 규칙·저장·재생의 통과 |
| E3 | 자동 시험 통과 | 계약·코드·저장 재생과 관련 자동 시험이 통과함 | 실제 H 공간, 현실 문맥, 플레이 |
| E4 | WI 실행 문맥 결속 | 허용 발생원·발의/수행 주체·대상·자료·자원·시간과 공간 적용 여부가 결속됨 | 실제 Simulation 세계 발현 |
| E5 | WI 세계 발현 | 허용 발생원에서 WI가 생겨 권위 상태 전이·Task·Effect·결과·후속/복귀 WI로 이어짐 | 현실 문맥 E6 또는 실제 플레이 E7 |
| E6 | WI 세계 정제·필요 근거 결속 | E5 WI 또는 WI 폐루프를 E7에 올리기 전에 의미·인과·결과 표현·권위·최신성을 검토하고 필요한 공간·현실 문맥의 출처·판본·Hash·한계를 연결함 | 실제 서버 조작·Game View |
| E7 | 실제 플레이 폐루프 | 사람이 실제 서버와 저장 `SimulationWorldShell`에서 이동·선택·Preview·Confirm·Tick·재조회를 수행하고 Game View·Console로 확인함 | NPC 자율 생활세계 |
| E8 | NPC 생활세계 폐루프 | 지속 NPC가 H 공간에서 생활·업무 이동, WI, 경쟁·협력, 후속 선택을 이어가며 Save/Replay와 실제 서버·Unity에서 검증됨 | 안전한 변화·Migration 능력 |
| E9 | 변화 적응형 세계 | 실제 E8 세계에 변화를 적용하고 E8→E1 영향 분석, Revision·Migration·Save/API 호환성, E1→E8 재검증을 거쳐 새 안정 상태를 만듦 | 모든 세계·기능의 일괄 E9 |

## 단계별 핵심 판정 질문

```text
E1  무엇을 왜 만들며 누가 확정하는가?
 ↓
E2  그 계약을 실행할 코드가 존재하는가?
 ↓
E3  규칙·저장·재생이 자동으로 재현되는가?
 ↓
E4  그 WI의 발생원과 실행 문맥이 빠짐없이 결속됐는가?
 ↓
E5  실제 Simulation 세계에서 그 WI가 발생하고 결과·다음 선택으로 이어지는가?
 ↓
E6  발현한 WI를 실제 플레이 전에 정제했고 필요한 근거·계보·한계를 설명할 수 있는가?
 ↓
E7  사람이 실제 서버 세계를 끝까지 플레이할 수 있는가?
 ↓
E8  NPC도 그 세계에서 연속적으로 살아갈 수 있는가?
 ↓
E9  그 생활세계를 안전하게 바꾸고 다시 안정화할 수 있는가?
```

## E와 G의 관계

| 주 전이 | 관리 체계 | 필요한 대표 증거 |
| --- | --- | --- |
| E1→E6 | G1 세계 성립 관리 | WI 발생원·계약·실행 문맥·발현·H·Revision·Hash·Lineage·현실 문맥 |
| E6→E7 | G2 플레이어 경험 관리 | 실제 서버, 입력·UI·카메라, `SimulationWorldShell`, Play Mode·Game View |
| E7→E8 | G3 NPC 생활세계 관리 | 지속 정체성·목표·생활/업무 이동·경쟁/협력·Save/Replay |
| E8→E9 | G4 변화·확장 적응 관리 | 영향 분석·Migration·호환성·회귀·새 안정 Revision |

`G2 구현 완료` 같은 관리 상태는 E7이 아니다. 같은 원칙으로 자동 시험 E3, 공간 조립 호환 출력, E6 정제 질문표 합격, Unity Fixture 화면은 서로를 대신하지 않는다.

## 판정 단위

- E1~E6: WI 또는 서로 이어지는 좁은 WI 묶음 단위. 공간 WI만 H·AreaSet·Graph 증거를 함께 요구한다.
- E7: 사람이 완주하는 실제 플레이 폐루프 단위.
- E8: `AreaSet + H 경로 + WI 묶음 + NPC 역할군` 단위.
- E9: 기준 E8 Revision에 적용한 한 변화 묶음 단위.

모든 WI의 목표를 E8이나 E9로 일괄 변경하지 않는다. 현재 WI 기계 대장의 기본 구현 목표는 E3, 통합 목표는 E7이다.

## 작업 계획 방향과 증거 방향

새 기능은 E9의 최종 변화·호환·rollback 목표를 먼저 선언하고 `E9 → E1`로 하향 분해한다. 구현은 가장 낮은 미완료 의존성부터 시작하고, 증거는 `E1 → E9`로 다시 검증한다.

`targetEvidenceStage = E9`는 장기 완결 방향이며 현재 E9 판정이 아니다. 신규 기능은 변경 전 E8 기준선이 없으므로 `promotionEligible = false`를 유지한다. 기계 작업 명세는 하향 검토와 상향 조립을 반복하는 [E9↔E1 반복 왕복 구현 체계](../../Architecture/E9하향식수직구현체계.md)를 따른다.
