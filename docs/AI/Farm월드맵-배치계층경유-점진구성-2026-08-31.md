# Farm부터 만드는 월드맵 — 기존 배치 계층을 거치는 점진 구성

- 날짜: 2026-08-31
- 기획 판본: `farm-world-map-placement-layer.plan.r1`
- 결정 식별: D422
- 상태: `ApprovedScopedWork`. 사용자 요청에 따른 Farm 우선 자산 조사·배치 계획·검증 후 제한된 실제 월드맵 적용 범위다. 현재 자산 선정·배치·보행 완료를 뜻하지 않는다.
- 원문 소유: 기획. 코드·시험·명세·현재 상태/조회 통합: 개발. 실제 자산/공간 연구·Editor와 캡처: 개발이 조율하는 월드·공간·배치 담당.
- 공통/DECISIONS 추가 연결은 진행 중인 D419~421 동결 검증 종료 뒤 한다. 그동안 이 원문을 추가 승인 근거로 인수하되 진행 중인 검색 검증 입력에는 섞지 않는다.

## 1. 사용자 의도와 이번 승인

사용자는 보유 에셋을 다채롭게 활용한 월드맵을 원하지만, Prefab을 바로 Scene에 놓는 방식은 원하지 않는다. 기존 배치 계층을 먼저 살펴보고 영역에 맞는 자산을 조사·계획한 뒤 그 계층의 검사를 거쳐 실제 월드맵에 배치하기를 요청했다. 첫 대상은 상대적으로 기획이 많이 준비된 Farm이다.

| 의미 식별자 | 상태 | 이번 범위 |
| --- | --- | --- |
| `farm-first-world-map-through-placement-layer` | `Confirmed` | Farm부터 기존 지도·배치 계층과 조율 경로를 재사용해 조사→계획→검사→작은 실제 적용으로 진행한다. |
| `farm-world-map-diverse-owned-assets` | `ConfirmedDirection` | 보유 Synty 자산의 지형·수목·낮은 식생·길·농장 건물 등 적합한 역할을 조합해 풍부하면서 읽기 쉬운 농장 풍경을 만든다. 정확 후보/배치 수치는 조사·연구에서 정한다. |

Farm 우선은 개발 순서다. Nature 출발·농장 방문을 모든 플레이어의 필수 루트로 만들거나 Town·Hub·City를 Farm 완료에 종속시키지 않는다. 네 영역 전체를 동시에 만들거나 새 City 진입을 승인하는 범위도 아니다. [D416 다영역 방향](다영역-선택형플레이와병행개발-2026-08-31.md)은 유지한다.

## 4. '배치 계층을 거친다'의 구체적인 의미

다음은 신규 계층/엔진을 만드는 설계가 아니라 기존 책임의 연결이다.

1. **지역/H 의도:** [AreaSet 구성 패턴](../Architecture/AreaSet구성패턴.md)에서 Farm 역할 슬롯·H3/H2·H1 의도를 찾는다. H는 공간의 의미/포함 관계이지 배치 성공이나 E 번호가 아니다.
2. **상위 외곽 제약:** [상향식 배치 성립 통제 계층](../Architecture/상향식배치성립통제계층.md)의 World/Area 외곽→H3/H2/H1 외곽·통로/설비 제약을 계획에 적용한다. Player 크기·활성 Renderer/Collider 외곽·지지면·접근·간섭을 실제 소비 검사로 연결한다.
3. **기능 성립:** H1의 능력/연결/검증 근거로 H2/H3/H4 준비도를 판정하는 상향 흐름은 Simulation 책임이다. 지붕이나 밭 모델이 보인다는 이유로 H를 Formed로 변경하지 않는다. 환경 장식마다 신규 H1을 만들지 않는다.
4. **감각 표현:** 실제 소스 [배치통제계층Root](C:/Users/user/ssalddel/Assets/Ssalddel/Presentation/World/배치통제계층Root.cs)에는 v1~v4와 감각 표현 교차축이 있다. v3로 고정/되돌리지 않고 현행 호출·배선을 개발이 대조한다. Root 기록 존재만으로 그래픽·카메라·애니·빛·소리·UI 검사를 모두 실행했다고 보지 않는다.

개발의 이번 읽기 반환에 따르면 `Root.Validate`는 식별자·판본·부모 레벨·Player 참조·비율/단계/채널 등의 구조검사다. 별도 `H공간배치규칙증거Root`는 기존 평탄 지면/여러 영역 실증 조건을 포함하므로 작은 Farm 한 구간에 그 전체 실증 조건을 강제하지 않는다. 구조검사를 실제 배치검사로 과장하거나 현행 검사를 완화하는 대신, 아래 기존 Farm 변환/소비·표면/통행 검사의 필요한 책임을 명시적으로 연결한다. v3/v4는 이 소스의 판본 상수이며 별도 JSON 파일로 추정하지 않는다. 저장 Scene의 실제 적용 판본은 아직 미관측이다.

실제 조립은 [지도/배치/LH 파이프라인](../Architecture/지도구성과세계자산배치분리.md)을 사용한다.

```text
같은 판본의 세계/지역 상태와 지도 기준
 → 필요한 지면·셀 준비(LH), 같은 상태의 Sky 표현
 → Farm 실외 배치 계획 + 외곽·지지·통로·자산 결속 검사
 → 기존 World 조율자와 실외 배치 실행부로 적용
 → 기대 객체/위치/접근 확인 → 실제 보행 → 해제·재적용 확인
```

계획은 실제 적용 전에 작성·봉인하며 지면 조사와 후보 비교를 왕복할 수 있다. Prefab을 먼저 임의로 놓고 사후에 '검증됨' 라벨만 붙이는 흐름은 아니다. LH는 셀 준비·관심/수명 관리를 맡고 자산 선택/게임 권위는 맡지 않는다. Unity 조립부는 승인된 계획을 무단 재추첨·축소·표면 보정하지 않는다. 허용 보정이 필요하면 원 계획/보정값·검사 결과를 명시하고 그 계획과 실제 결과를 다시 대조한다.

## 5. 자산 조사와 Farm 경관 구성

다채로움은 많은 팩을 억지로 섞거나 일정 간격으로 흩뿌리는 방식이 아니다. 기능을 알아볼 큰 윤곽, 군집과 여백, 가까운 세부가 서로 보완해야 한다. 아래는 역할별 조사 범위이며 전부 배치해야 한다는 목록이 아니다.

[13팩 기능 대장](../../eng/execution-ledgers/synty-asset-functional-modules.json)과 기존 E4 조사·D388/D396 후보, D412·D414 경관 자료를 먼저 재사용한다. 기존 파일/meta·측정 문맥이 같으면 같은 자산을 다시 전수 렌더하지 않는다. 새 후보는 필요한 역할의 소수만 조사한다. 눈 후보는 이전 자료로 보존하고 이번 눈 없는 봄을 눈 경관으로 되돌리지 않는다.

각 후보는 정확 경로/GUID·원본/meta/의존 판본, 역할/VisualKey·단일 Prefab인지 구성 묶음인지, 축척/pivot·활성 외곽/LOD·재질·Collider, 지지/접근·주변 간섭과 확인/미검사를 기존 명세에 연결한다. 원본 파일명을 추측해 최종 선정하지 않는다. 필요 이상의 랜드마크·다른 시대감/색·기능 없는 사람/창고를 추가하지 않는다.

| B. 첫 구간 계획 | 기존 기준점을 유지한 Farm 한 구간의 역할·자산·좌표/축·보호/통로·기대 ID와 판본/hash. 필요 연구를 좁게 보완해 개발이 Accepted/명세 결속 | 원A/B 후보를 덮어쓰거나 등록 상태만 바꾸어 실제 승인 계획으로 만듦 |
| C. 배치 소비 검사 | 잘못된 H/셀·손상/낡은 hash·미등록 키·지지/통로/소유 결손 거부, 원본/다른 배치 보존·같은 입력의 결정성. 누락된 실제 호출을 기존 계약/조율자에 좁게 연결 | 계층 기록/Adapter 단위 시험을 실제 Scene 조립으로 세지 않음 |
| D. 제한된 실제 적용 | 검사된 계획을 기존 canonical World의 해당 구간에만 적용. 실제 대상/판본·활성 Renderer·필요 Collider·위치·지지·접근 대조 | 수동 배치만 저장하거나 셀 Active만으로 기대 자산 전체 성공 선언 |

이는 새 Evidence 단계 A~E를 만드는 것이 아니라 작업 묶음이다. 현재 Logic/Presentation/통합 E 및 Farm 상한은 기존 명세를 따른다. 첫 작은 지도·배치·보행 성과를 먼저 반환하고, 전체 Farm/모든 농사 기능/소리·동작의 완성을 기다려 아무 결과도 내지 않는 방식은 피한다.

이번 요청은 **A만 조사하고 무기한 대기하는 요청이 아니다.** 개발이 정확 소유·현행 기획/필요 Accepted 연구·명세를 결속하고 각 묶음 조건을 통과하면 다음 작은 코드 수정·검증·실제 적용으로 이어간다. 같은 기술 후속마다 사용자에게 새 승인 질문을 되돌리지 않는다. 다만 기존 생산/소유/보호 경계나 플레이 선택을 바꾸는 해결책이 필요하면 그 부분만 근거와 대안을 반환한다.

## 7. 알려진 결손은 그대로 드러내고 분리 해결한다

- [D406 관찰02](../Reports/월드맵우선-D406-진단과실행인계-2026-08-31.md)는 12:23경 실제 정지 화면/부분 대상 분류다. 이후 큰 지도 구성·정리 전후·보행 완료 증거가 아니며 현재 Editor 정상 여부도 새 슬롯에서 확인한다. 첫 관찰의 No Pipeline을 지금도 연결 불가라고 단정하지 않는다.
- [LS01 소비 검토](../Reports/Farm경관-LS01-배치소비경계-개발검토-2026-08-30.md)는 실제 셀/H4와 고정 Farm 후보 계보의 불일치·지면 공급/Collider 값 차이·단일 자산 키 해결/자동 Align 공백을 기록했다. 값을 바꿔 위장 결속하지 않고 실제 입력의 출처/좌표·계보를 해결한다.
- Farm의 과거 null 컴포넌트/표시 비활성·상태 공급 공백은 해당 작업 표현의 결손이다. 이를 삭제하거나 전체 Root를 켜서 우회하지 않는다. 지도·환경 경관이 독립적으로 성립하면 그 부분은 진행하되 농사 기능 연결 완료로 보고하지 않는다. 필수 지지/상태·접근에 얽히면 그 구간을 차단한다.
- 기존 평지 합성 A/B·실측 Preview·코드 시험은 각각 재사용 근거이지 현재 지형에 놓인 실제 결과가 아니다. 새 지형/후보 판본은 별도 계획으로 기록하며 원본과 실패 증거를 보존한다.

개발이 이번에 좁은 파일 대조로 반환한 첫 기술 묶음은 **실제 한 Farm 셀의 계보·지면/보호·통로 사본 → 정확 단일 Prefab 해결 → 기존 고정 변환/검사 → 계획 분리 → 기존 World 조율자의 기대 ID·보정/경고·해제 대조**다. [Farm 고정 변환](../../Ssalddel.Simulation.Application/SimulationFarm경관고정배치Service.cs), [소비 검사](../../Ssalddel.Simulation.Application/Simulation경관배치소비검증Service.cs), [계획 분리](../../Ssalddel.Simulation.Application/SimulationWorldAssetPlacementPlanPartitioning.cs)를 재사용 출발점으로 삼는다. 기존 A5+B8은 이전 검토 단위이지 이번 무조건13개 배치 승인/성공 기준이 아니다. 자산 다양화는 이 연결에 새 후보 판본을 연결하며 기존 원A/B를 바꾸지 않는다.

이번 개발 읽기에서는 D406 관찰02의 보호11파일이 현행과 동일했고 추가 적용 기록을 확인하지 못했다. 이것은 그11파일의 결과이며 전체 코드/메모리/현재 Editor 상태의 불변 보장이 아니다. 현행 명세와 Farm 기획/연구4개 hash 일치도 개발 인수 범위로 구별하며 이 기획에서 시험이나 live 검증을 재실행하지 않았다.

## 8. 역할·수정·보존 경계

개발은 A에서 정확 코드/설정/계획 입력 경로를 반환하고 기존 Farm 명세/지원 작업에 이번 원문을 연결한다. 세계 지도·표현 조율자는 개발이 소유하고, 공간 담당에게 자산/배치 후보·필요 연구·단독 Editor 측정/입력/캡처 경로를 배분한다. 일반 빌드/시험·CURRENT/통합판/생성물은 개발 책임이며 애니 담당을 일반 검증 대행으로 쓰지 않는다. 동작·Rig·접촉 결손이 실제로 필요할 때만 해당 전문 범위를 분리한다.

우선 기존 D406 진단 인계와 LS01 개발 검토 보고의 D422 후속절을 재사용한다. 새 승인 계획/측정·이미지·검사 로그는 `artifacts/local/validation/farm-world-map-d422/` 아래 각 실행의 고유 폴더에 둔다. 긴 원자료를 중복 대장으로 만들지 않고 원문·명세·근거 링크로 연결한다. 신규 공간 연구가 필요한 경우 개발이 전용 경로와 범위를 먼저 선언해 기존 동결 연구를 보존한다.

실제 적용 전 프로젝트/Scene·기존 dirty·점유·복구 대화와 기준선을 확인한다. 기존 공식 `SimulationWorldShell`만 사용하고 검사된 계획의 프로젝트 소유 인스턴스/표현 경로를 수정한다. D406과 같이 자기 변경만 분리·원바이트 복구본/정확 차이가 확보된 경우 해당 Scene만 저장할 수 있다. 구분 불가한 dirty, 예상 밖 차이/복구·폐기 대화는 그 저장만 중단해 반환한다. 전체 Builder 재생성·SaveAssets·원본/실험/미소유 객체 일괄 삭제는 하지 않는다.

권위 상태/Save 데이터 초기화·신규 생산/성장/수원/통행 권한 규칙·새 H/WI·새 공식 Scene·패키지 업그레이드·외부 구매/수집/운영 호출·미확인 Blender 가공·강제 종료·commit/push는 제외다. r129/야간 자동화 및 다른 중지 작업을 포괄 재개하지 않는다. 새 지역/지형 규칙이 필요하면 별도 승인 경계로 반환한다.

## 9. 사용자에게 반환할 결과

1. 첫 반환: Farm 한 구간의 기존 지도·배치 경로, 재사용 자산/추가 후보와 정확 가장 작은 수정·차단. 파일 조사만이면 그렇게 표시한다.
2. 계획 반환: 큰 구도와 첫 구간의 관계·주후보/대체·빈 공간·보호/통행을 읽을 수 있는 계획. 외형 Preview와 실제 배치 사진은 구별한다.
3. 실제 결과: UI 포함 Game View의 Farm 전체 맥락 한 장과 눈높이 접근/밭·마당 판독 장면, 실제 이동/귀환·해제/재적용 근거. 필요한 경우 같은 카메라/시간·날씨 전후 비교와 실시간 이동 비교를 별도 표시한다.
4. 부분 완료·실패: 생성/기대 ID 대조, Console/프레임·셀/객체 관측 범위, 보존과 미완료를 함께 보고한다. 잘 된 한 구간은 먼저 전달하고 같은 실패를 같은 방식으로 반복하지 않는다.

자산 다양성·배치 계층의 실제 검사·세계 내 조립·보행은 서로 다른 결과다. 기획 승인이나 예쁜 한 장을 전체 월드맵·Farm E5/생산 기능 완료로 올리지 않는다.
