# Graph Map 현행 검증과 구체화 기획

- 상태: `ReadyForReview`
- 작성일: 2026-09-01
- 대상: `graph-map:mirror:northern-life-hub-discovery.v1`
- 기준: [Graph Map 기획 인계 순환 체계](../Architecture/GraphMap기획인계순환체계.md), [Graph Map 개발 인계 체계](../Architecture/GraphMap개발인계체계.md)

## 1. 결론

현재 Graph Map은 아이디어 문서만 있는 상태가 아니다. 레벨 1 플레이 관계, 레벨 2 배치 제약, 레벨 3 코드 결속, 하위 맵 분할, 기획 인계, 개발 인계와 각각의 검사기가 구현돼 있다.

다만 최신 기획이 반영된 현재 판본으로 순환 전체가 통과하지는 않는다. Graph Map 본체는 검사에 통과하지만, 기획 원문이 계속 발전한 뒤 기획 인계와 개발 인계의 판본·해시·회귀 기대값이 함께 갱신되지 않아 순환이 중간에서 차단된다. 따라서 다음 단계는 노드를 무작정 늘리는 것이 아니라 **현행 판본 복구 → 작은 사건 그래프 구체화 → 개발 가능한 slice 분리** 순서가 적절하다.

## 2. 직접 확인한 현재 구조

| 구분 | 현재 확인값 | 해석 |
| --- | ---: | --- |
| 레벨 1 노드 | 17 | Nature·Farm·Hub·Town, 한스의 첫 신뢰·집 수리·생활 거점, 요동성 외부 관문 |
| 레벨 1 엣지 | 16 | 발견·작업 인계·화물 이동·미해결 외부 연결 |

| 배치 규칙 | 21 | 기존 배치 규칙 대장과 결속하며 Graph Map이 새 수치를 발명하지 않음 |

본체 `Check`는 `nodes=17, edges=16, constraints=15, placementRules=21, subgraphs=5, connectors=4, codeBindings=6, unresolved=7/7`로 통과했다. 이는 파일 기반 계획 구조의 정합성 근거이며 Unity Scene, 실제 이동, 입력, Game View 또는 E5 성립 근거가 아니다.

## 3. 현재 순환에서 발견한 결함

### 3.1 기획 인계의 현재 원문 판본 불일치

현재 통합 인계 `r6`은 메인 스토리 `r58`을 기준으로 하지만, 메인 스토리는 현재 `r74`까지 발전했다. 관리자는 이전 `Superseded` 항목도 현재 파일 바이트와 직접 비교하여 `PlanningSource ... HashMismatch`로 중단한다.

과거 인계의 당시 해시를 이력으로 보존하는 일과 현재 활성 인계의 신선도를 검사하는 일을 분리해야 한다. 과거 기록을 현재 파일 해시로 다시 통과시키거나 과거 해시를 현행 값으로 덮어써서는 안 된다.

### 3.2 Graph Map 회귀 기대값이 현재 구조보다 오래됨

공식 본체는 17노드·16엣지·15제약인데 회귀시험 일부는 14노드·13엣지·11제약을 기대한다. 그래서 본체 직접 검사는 통과하지만 공식 회귀의 `OfficialCheck`는 실패한다. 새 한스 집 흐름을 추가한 뒤 시험 기대값이 동기화되지 않은 상태다.

### 3.3 개발 인계가 대체된 판본을 가리킴

현재 개발 인계 한 건은 기획 인계 `r5`와 Graph Map `r5`를 참조한다. 둘 다 `r6`으로 대체됐기 때문에 `PlanningHandoffNotIntegrated`로 차단된다. `ReadyForDevelopment` 표시는 현재 판본에서 유효한 실행 준비가 아니다.

### 3.4 최신 스토리 결정이 아직 Graph Map에 없음

현재 Graph Map은 한스의 제한 생활 거점에서 멈춘다. D-538~D-555에서 확정된 다음 내용은 아직 레벨 1~3에 구조화되지 않았다.

- 한스와 첫 경계 순찰, 숨은 실력과 검 단서
- 깊은 숲에서 밀려 내려온 동물형·야수형 마수 무리
- 거대 마수와 요동성 적대 조직의 간접 연결
- Town 견습 공방의 실패 원인 직관
- Hub 미도착 화물의 단서 수집·추론
- 안도·회복에서 명상 증폭으로 이어지는 순환
- 강적 위협, 집중 타이밍, 지원 연결 분리

이 항목을 모두 한 Graph Map에 즉시 넣기보다 플레이 장소와 인과가 닫히는 작은 하위 맵으로 나누는 편이 안전하다.

## 4. 구체화할 Graph Map 묶음

### 4.1 우선 묶음 — Farm 경계 순찰

기존 `한스 생활 거점` 이후를 다음 레벨 1 후보로 잇는다.

```text
한스 생활 거점
  → 첫 경계 순찰 준비
  → 농장 경계의 동물형·야수형 마수 무리
  → 함께 대응하거나 이탈·귀환
  → 비정상 이동·상처·영역 흔적 조사
  → 더 깊은 위협 관문
```

선택형 단서는 별도 가지로 둔다.

```text
한스 집의 관리된 검 관찰
  → 정체 의심 후보
  → 첫 순찰에서는 검 미사용
  → 훨씬 뒤의 진짜 위기까지 공개 보류
```

레벨 2에서는 다음을 우선 제약으로 삼는다.

- 사람형 Demon/Undead를 첫 마수의 동물형·야수형 의미에 억지 배정하지 않는다.
- `적합 자산 미확보`는 미해결 표현 상태이지 기획 의미 변경이 아니다.
- 한스의 강함은 첫 순찰 행동으로 드러나지만 검 사용과 정체 공개를 자동 실행하지 않는다.
- 흔적은 배후를 즉시 확정하지 않고 다음 조사 가능성만 연다.
- 순찰 시작·중단·귀환과 마수 대응 결과를 분리한다.

레벨 3에서는 승인된 실제 계약이 없는 노드와 엣지를 `NoApprovedUnityBinding`으로 남긴다. Prefab 후보나 애니메이션 파일이 있다는 이유로 권위 계약을 만든 것으로 기록하지 않는다.

### 4.2 두 번째 묶음 — Hub 미도착 화물과 명상

```text
Hub 도착 예정 확인
  → 미도착 인지
  → 기록·기사·도로·날씨·몬스터 단서 수집
  → 플레이어 가설 선택
  → 현장 확인
  → 문제 예방과 NPC 안도
  → 선택적 명상
  → 실제 획득 조건을 충족한 영감·편린 증폭
```

재고 기록이 원인을 대신 계산하지 않고, 회복·명상·편린의 중복 복제를 막는 제약이 필요하다.

### 4.3 세 번째 묶음 — Town 견습 공방

```text
실패한 작업대 관찰
  → 재료·가열·투입 순서에서 원인 후보 직관
  → 견습과 작은 시험 batch
  → 성공·실패 원인 확인
  → 다음 학습 또는 떠나기
```

완제품 대리 제작, Recipe 자동 획득, 공방 소유를 결과로 만들지 않는다.

### 4.4 장기 묶음 — 거대 마수와 분할 대응

지휘·호위·지원·증원·회복·보급 노드와 연결을 실제로 분리했을 때만 종합 역량이 내려가는 전투 그래프로 둔다. 첫 Farm 경계 순찰과 같은 작은 사건 그래프에 적대 조직 전체를 직접 펼치지 않고 `더 깊은 위협 관문`을 통해 별도 하위 맵으로 연결한다.

## 5. 권장 작업 순서

1. Graph Map 담당이 과거 인계 이력 검증과 현재 활성 판본 검증을 분리한다.
2. 현재 17/16/15 구조에 맞게 회귀 기대값을 갱신하고, 대체된 `r5` 개발 인계를 현재 `r6` 기준으로 재판정한다.
3. 기획에서 첫 구체화 묶음을 하나 확정한다.
4. Graph Map 담당이 그 묶음만 레벨 1·2·3에 증분 반영하고 새 판본·해시·미결속을 반환한다.
5. 개발 인계는 실제 Goal·WI·작업 명세가 있는 작은 slice만 만든다. 나머지는 기획 또는 기술 공백으로 남긴다.
6. Unity 실행이 필요한 때에만 월드·공간·배치 담당이 실제 Scene·입력·Game View를 검증한다.

## 6. 이번 검증의 상한

이번 작업은 현재 Graph Map 파일과 검사기의 읽기 검증 및 기획 구체화다. Graph Map JSON·검사기·개발 인계 원장을 수정하지 않았고, Unity Editor·Scene·Prefab·Play Mode·Game View·E 승격·commit·push를 수행하지 않았다.
