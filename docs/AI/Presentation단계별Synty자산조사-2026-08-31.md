# Presentation 단계별 Synty 자산 조사

- 결정: D-387
- 판본: presentation-synty-survey.design.r1
- 상태: AcceptedPlanningDirection
- 근거: 2026-08-31 사용자가 보유 신티(Synty) 자산 조사 과정을 적절한 Presentation 단계에 포함하도록 요청했다.
- 관계: [D386 최소 모듈 계획](Presentation단계별최소모듈-2026-08-31.md)의 추가 기획이다. 기존 승인 원문·hash는 보존한다.

## 목적과 기준

새 모델이나 동작을 제작하기 전에 보유 자산을 조사하여 그대로 재사용할 것, 연결·설정만 보완할 것, 가공할 것, 실제로 새로 제작할 것을 구분한다. 조사 자체를 모델링·배치·실제 동작 완료로 세지 않는다. 세부 자산 기준은 기존 [Synty 표현 모듈 체계](../Architecture/플레이폐루프Synty표현모듈체계.md)를 재사용하며 별도 자산 원장을 만들지 않는다.

## 기존 단계 안의 위치

| 단계 | 조사와 후속 책임 | 결과 |
| --- | --- | --- |
| Presentation E1 | 어떤 상태·행동을 무엇으로 읽게 할지 정하고 필요한 자산 종류를 식별한다. | 표현 요구와 자산 조사 범위 |
| Presentation E2 | 기존 자산 목록·동작 목록·공통 Adapter를 먼저 파일로 조회한다. 제작·연결 코드 설계에 재사용 가능성을 반영한다. | 잠정 후보와 기존 구현 경로. 실제 적합성 확정은 아님 |
| Presentation E3 | 경로·GUID·참조·판본과 조사/준비 도구의 자동 검사를 수행한다. | 자동 확인과 실제 외형·동작 미검증을 분리한 기록 |
| **Presentation E4** | **자산 조사의 주 단계.** 대상 WI와 역할에 맞는 보유 Prefab·재질·Clip·Rig/Avatar를 대조하고 필요한 소수 후보의 외형·크기·pivot·Collider·접촉/전환을 확인한다. | 주/대체 후보, 재사용·보완·신규 제작·미검사 구분, 준비 상태·열린 결함·revision/fingerprint |
| Presentation E5 | 동결한 후보를 실제 권위 상태·World·Prefab/대체 표현에 연결하고 실제 대상에서 확인한다. | 파일 존재가 아닌 실제 결속 근거 |
| Presentation E6~E7 | 크기·색감·동작·접촉·소리의 어색함을 정제하고 필요한 실제 입력·결과·중단·귀환을 검증한다. | 비교/회귀 근거. 후보 변경 시 관련 조사와 결속을 다시 연다 |
| E8~E10 | 기존 반복 안정성·영역 조화·제한 운영 관찰에서 재사용 문제와 변경 영향을 확인한다. | 별도의 자산 조사 성숙도 축을 만들지 않는다 |

E2 조사는 가벼운 선행 조회이며 모든 자산 실측을 코드 작성의 일괄 선행 조건으로 만들지 않는다. 자산을 사용하는 범위는 E4에서 조사 결과를 명시하며, 비시각·비자산 범위는 사유 있는 NotApplicable로 분리한다. E8~E10은 기존 수평 증거 단계이지 Presentation 제작을 열 단계로 다시 나누는 체계가 아니다.

## 최소 조사 결과

- WI·플레이어 판독 순간·표현 역할과 원천 팩, 실제 경로·GUID·revision/fingerprint.
- 주 후보와 가능한 대체 후보. 후보 수를 고정하지 않고 없으면 미확보로 남긴다.
- 그대로 재사용 / 연결·설정 보완 / 형상·리깅·동작 가공 필요 / 신규 제작 필요 / 미검사 구분과 근거.
- 소품·공간은 외형·크기·pivot·Renderer/Collider·지지·통행 의도, Actor는 Clip·Rig/Avatar·root motion·Controller·접촉·중단 복귀를 필요한 범위만 확인한다.
- 파일 확인·격리 미리보기·실제 대상/Scene 검증을 구별하고, 가공 필요와 사용조건 확인을 별개로 기록한다. 파일명 검색만으로 자산이나 동작의 부재를 확정하지 않는다.

기존 조사와 같은 자산/판본/사용 문맥이면 근거를 재사용하고 변경분만 확인한다. 매 WI마다 전체 팩을 재조사하거나 대량 촬영하지 않는다. 후보와 문맥이 바뀌었을 때만 영향받는 검증을 다시 연다. 자산의 겉모양에서 생산량·용량·가열 능력 같은 게임 규칙을 만들어내지 않는다.

## 담당과 적용 경계

기획은 표현 요구·조사 기준과 제작 우선순위를 정한다. 개발은 기존 E4 preparation·모듈·작업 명세에 연결하고, 공간 담당은 환경/소품/배치 후보, 애니메이션 담당은 Actor/Clip/Rig/접촉 후보를 조사하여 개발에 반환한다. 일반 코드·테스트·통합은 개발 담당이다.

이번에는 조사 절차의 기획을 추가한다. 개발의 D386 구조 정비에 이 방향을 결속하되, 실제 자산 전수 조사·Editor 점유·새 Blender 가공·Scene 저장·구매/다운로드·E 승격·중지된 야간 작업 재개를 일괄 승인하지 않는다. 실제 조사 실행은 해당 작업의 기존 승인 범위와 소유 경로에 맞춰 개발이 배분한다. 이 기획 스레드는 코드와 시험을 실행하지 않는다.
