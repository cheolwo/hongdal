- 날짜/판본: 2026-08-31 / `pattern-composition-placement-rules.plan.r1`.

## 1. 승인된 목표와 이전 계획의 대체 범위

이번 목표는 **실제 월드맵에 놓기 전에 여러 패턴을 준비하고, 패턴끼리 조합할 때 지켜야 할 규칙을 엄밀하게 검사하는 것**이다. 흐름은 `기존 자산·패턴 확인 → 조합 후보 생성 → 배치 규칙 검사 → 격리 미리보기 → 규칙·패턴 보완`에서 끝난다.

앞서 제안했던 실제 Farm 구간 조립·보행·월드 재적용까지의 진행은 사용자의 정정으로 이번 작업에서 제외한다. [D422 Farm 월드맵](Farm월드맵-배치계층경유-점진구성-2026-08-31.md)·[D406 실제 지도/보행](월드맵우선-초기표시정리와보행검증-2026-08-31.md)의 과거 승인·근거는 보존하되, 이를 이유로 이번 패턴 검토 뒤 실제 World 적용을 자동으로 이어가지 않는다. 실제 적용은 별도 후속 지시 대상이다.

사용자는 기본형을 매번 직접 승인하는 대신 **예외만 확인**을 선택했고, 공식 월드와 분리한 **격리 미리보기 포함**을 선택했다. 기존 기획 안의 기본형·변형·검토용 시각 기준은 Codex가 근거와 결과를 기록하며 선택한다. 새 게임 규칙, 기존 사용자 선택/권리·안전 기준 변경, 확인되지 않은 가공이나 파괴적 조치가 필요하면 그 부분만 반환한다. 기술 세부를 매번 사용자 질문으로 돌리지 않는다.

[D440 자동 할당](개체자산-자동할당-D440-개발인계-2026-08-31.md)·[D441 분류 검색](Synty자산-분류검색과자동할당-D441-개발인계-2026-08-31.md)은 별도 승인 범위로 보존한다. 자산이 DB에 있거나 분류가 일치한다는 사실은 용도·실물 크기·조합 적합성이 확인됐다는 뜻이 아니다. D440 전체 완료/전수 자산 촬영을 이번 첫 패턴 준비의 선행으로 만들지 않고, 현재 확인된 판본과 기존 근거를 재사용한다.

## 2. 기존 H·배치 책임과 연결

- [H1~H5 정의](../Architecture/H1-H5공간포함계층조사.md)와 [AreaSet 구성 패턴](../Architecture/AreaSet구성패턴.md)을 재사용한다. 위치 독립 패턴과 지도에 놓이는 개별 배치를 구분한다. 이번에는 검토용 상대 배치만 만든다.
- 외형만 묶은 것은 자산 구성이고, 업무·플레이 의미와 접근 공간을 가진 정의는 기존 H1 기준에 대응한다. 기존 표현 H1을 임의 삭제/재분류하지 않으며 새 외형 조합마다 H/WI를 자동 등록하지 않는다.
- [배치 구조·제약 / 계획 / 검증 / 조립 책임](../Architecture/지도구성과세계자산배치분리.md)은 유지한다. 새 최상위 엔진·병렬 규칙 체계·E/H 축을 만들지 않는다. 기존 계획 생성 경로가 공통 검사를 호출하고 검토용 결과를 반환하게 최소 보완한다.
- H 성립·게임 능력·WorldTick·시간/생산/재고 권위는 Simulation에 남긴다. 검토 공간이나 미리보기는 그 권위 상태를 생성하지 않는다. H 조합 크기와 Logic/Presentation/통합 E를 구분한다.

## 4. 규칙을 정의하고 검사하는 방법

검사 범위는 **패턴 내부 → 두 패턴의 접점 → 여러 패턴의 주변/전체 관계**다. 충돌이 없는 단독 패턴도 조합 뒤 다시 검사한다.

| 규칙 묶음 | 검사 내용 |
| --- | --- |
| 크기·지지·점유 | 실제 외곽·원본 축척, 경사·높이 차이·부유/매몰, 건물/밭 겹침, 예약 공간/기존 대상 침범. |
| 출입·동선 | 출입구 방향·문 앞 여유·작업 공간·통로 폭, 연결점 방향/높이·폭 호환, 끊김/막힘. |
| 패턴 경계 | 농장·숲·길·수변 등 기존 경계 유형의 호환, 급격한 높이·폭 변화, 필요한 완충/전환 구간과 보호 영역. |
| 밀도·여백 | 실제 이웃 범위에서의 점유·군집·열린 구간, 과밀/균일 흩뿌림·과한 공백, 작업 대상/접근 공간 가림. |
| 반복·방향 | 가까운 곳의 동일 변형 반복, 장소와 맞지 않는 방향 통일, 허용하지 않은 회전·반전. |
| 장소별 구도 | 농장은 건물·마당·밭의 정돈, 숲은 군집과 빈터, 농장/숲 접점은 점진적인 전환. 농장의 정상 정렬을 숲의 반복 결함과 같은 규칙으로 거부하지 않는다. |
| 시각적 일관성 | 확인된 크기·재질/계절 문맥·주요 대상/입구 판독성. 팩 이름만으로 시대·용도·색감 적합성을 확정하지 않는다. |

필수 제약은 후보를 거부한다. 시각적 비교 기준은 통과 후보 사이의 밀도·반복·여백 등 개별 측정/관찰 지표를 반환한다. 하나의 종합 점수로 통로 차단 같은 실패를 상쇄하지 않는다. 기존 기획이 명시한 금지 조합·필수 여백은 시각 문제라는 이유로 단순 경고로 낮추지 않는다.

접촉 허용 범위는 구분한다. 지면 점유·작업/통행 외곽과 수관/장식 외곽을 혼동하여 모든 시각 겹침을 금지하지 않는다. 자연스러운 수관 겹침은 해당 역할/근거의 명시 허용 조건 안에서만 허용하고, Collider가 없다는 이유로 시각적으로 막힌 길을 통과시키지 않는다.

각 규칙에는 고유 식별자, 적용 범위/장소, 필수 입력, 판본·출처, 단위와 허용값, 실패/미검사 사유가 필요하다. 기존 측정값·정책을 우선한다. 새 미관 수치는 격리 검토 전용 판본으로 정의하고 정상/문제 후보 비교에 따른 선정 이유를 기록한다. 값이 없을 때 0·무한대 등으로 채우거나 ‘문제 없음’으로 바꾸지 않는다. 표본 기반 지지 검사는 연속 지면 전체 또는 실제 보행 증거가 아니다.

## 5. 계약·코드·호환 범위

입력은 기존 패턴·자산 구성의 고유 식별자/판본, 상대 위치·방향, 측정 외곽/출입·연결점, 공간상 이웃·검토 경계, 규칙 판본, 검토 지면/시점·환경과 그 근거다. D440 구성이나 기존 후보를 읽되 미선정/불충분 대응을 실제 자산으로 위장하지 않는다.

출력은 검토용 후보 계획, 입력·규칙 판본/hash, 규칙별 통과/실패/미검사, 문제 위치와 대상 패턴, 측정값/허용값, 보완 이유다. 위치 독립 패턴과 해당 검토의 배치 고유 식별자는 구분한다. 미관 통과가 Runtime 사용 승인·H 성립·E 승격이 되는 상태 전이는 추가하지 않는다.

개발은 기존 계획/검사 계약을 최소 확장하고, 공통 검사를 계획 후보 선정 전후에 연결한다. 원래 경관 문법의 고정 개수/구형 읽기·기존 결정성/저장 hash는 그대로 회귀한다. 새 의미가 추가되는 계산은 명시적인 검토 판본·호출 경로로 분리하고, 원본 불변 판본에 새 수치나 결과를 끼워 넣지 않는다. 원본 JSON에 값을 추가했을 때 구형 읽기 경로에서 무시되는 것을 신판본 검증 성공으로 표시하지 않는다.

새 공개 API·운영 서버 작업·H 전수 복제 DB·별도 세계 생성기·상시 자동 실행은 만들지 않는다. 기존 저장형 `JobShell`을 호출하여 실제 경관 원장이나 World 상태를 갱신하지 않고 순수 계획/검사 결과를 전용 산출물에 남긴다. D440/D441 DB/공유 계약과 충돌하면 개발이 소유와 실행 슬롯을 조율한다.

## 6. 첫 패턴 묶음과 격리 미리보기

첫 대상은 기존 원본에 실제 존재하는 다음 세 패턴군이다. 이름을 새 H 정의로 사용하지 않고 기존 H/역할 대응을 기록한다.

| 패턴군 | 기존 구성 키 | 현재 위상 |
| --- | --- | --- |
| 헛간 작업마당 | `farm:헛간 작업마당:A/B/C` | `landmark` |
| 혼합 작물밭 | `farm:혼합 작물밭:A/B/C` | `area` |
| 숲 가장자리 | `nature:숲 가장자리:A/B/C` | `detail` |

`A/B/C`는 각 끝문자가 다른 기존 3키의 축약 표기다. 문법 키 존재는 실제 Prefab/검토 결과 확보를 뜻하지 않는다. 기존 변형을 먼저 활용하고 역할 근거가 부족한 부분만 보완한다. 첫 검토는 각 단독, 헛간↔밭·밭↔숲·헛간↔숲의 접점, 세 패턴의 전체 조합을 포함한다. 전체 조합은 농장 내부 정돈/통로와 숲 외곽의 군집·여백을 함께 판독한다. 조합 가능성이 없으면 억지 후보를 추가하지 않고 제한 사유를 남긴다.

격리 미리보기는 공식 Scene/World와 분리한 임시 검토 공간에서 기존 자산의 전용 복사본만 사용한다. 새 공식 Scene/영속 검토 Scene은 만들지 않는다. 위에서 본 구성과 플레이어 눈높이 카메라로 정상 후보와 문제 조합을 같은 조건에서 비교한다. 도식·Prefab 외형·조합 렌더를 각각 표시하고 Game View/실제 플레이 성공으로 설명하지 않는다. 일부 자산 미대응 때 도식/미완성 표시를 사용한 결과는 실물 미리보기 완료가 아니다.

개발이 기존 주제 기획·동결 연구를 읽고 필요한 후보/규칙/검토 연구를 좁게 분리하여 Accepted 기준선·작업 명세·정확 쓰기 경로·검증 상한에 결속한다. 이후 공간 담당이 단독 Editor 슬롯에서 도구/호환·상태를 확인한다. 새 연구/슬롯 결속은 전문의 기술 책임이며 매번 새 사용자 선택을 요구하는 것이 아니다.

기존 Preview 도구와 성공/실패 근거를 재사용하고, 첫 대표 렌더의 인물/대상·실제 변화 반영·오류 여부를 확인한 뒤 필요한 비교만 확장한다. 빈 이미지/새 렌더 오류가 발생하면 그 배치를 중단하고 원인을 분리한다. 같은 실패를 같은 설정으로 반복하거나 수백 장을 먼저 생성하지 않는다. 거부된 조합의 그림은 진단용으로만 표시하고 적용 후보와 분리한다.

실행 전 현재 Scene·dirty·미소유 객체/Preview·원본·패키지의 기준선과 자기 생성 소유를 기록한다. Play로 실제 Session을 시작하거나 화면 준비를 위해 기존 World를 켜거나 숨기지 않는다. 공식 Scene 저장·미소유 dirty 처리·복구/폐기/강제 종료는 하지 않는다. 종료 시 자기 임시 자원만 해제하고 전후 차이/잔존/오류를 사실대로 반환한다. 현재 Editor가 없거나 복구 선택이 필요하면 해당 live만 보류하고 순수 코드·시험은 독립 진행한다.

## 7. 필수 검증과 완료 기준

1. 같은 입력/규칙판본/명시 seed에서 같은 계획·규칙 결과·hash를 생성한다. 입력 배열 순서를 바꿔도 같은 결과이며, 공간상 이웃 판단을 이름/식별자 정렬의 근접성으로 대체하지 않는다.
2. 회전/허용 반전 뒤 외곽·출입/연결점·경계 방향을 함께 검사한다. 지원하지 않는 변환은 명시 거부한다.
3. 단독 정상인 두 패턴의 조합에서 충돌·통로 막힘·높이/폭·경계 불일치를 찾아낸다. 세 패턴 조합에서 이웃 반복·전체 동선/여백도 다시 검사한다.
4. 농장의 정상 정렬, 숲의 과도한 반복·균일 배치, 명시 허용 수관 겹침, 작업 공간 침범을 구별하는 긍정/부정 사례를 둔다.
5. 필요한 자산/지면/외곽·주변 정보·규칙값 누락과 오래된 판본을 통과로 처리하지 않는다. 합성 수치는 실측으로 바꾸지 않으며, 정확 범위가 같은 기존 근거만 재사용한다.
6. 필수 실패가 시각 비교 점수에 상쇄되지 않는다. 후보가 모두 탈락하면 명시 미해결로 끝내며 규칙 완화·무한 재추첨·무단 크기 보정을 하지 않는다.
7. 기존 경관 결정성/연결/Farm 검사·계약 소비자 및 구형 입력/hash를 회귀한다. 원본 규칙 읽기·계산 전달·실제 결과 사이의 누락을 별도 시험한다.
8. 격리 미리보기에서 동일 카메라·지면·환경 조건과 정확 후보/규칙판본을 기록한다. 원본/공식 Scene/게임 상태 불변, 자기 자원 해제와 오류/한계를 반환한다. 이미지 없는 시험을 시각 검증으로 세지 않는다.

최종 산출물은 재사용 패턴 목록, 판본화된 검토 규칙, 조합별 검사 결과와 문제 위치, 정상/문제 조합 비교 이미지다. 기본형·대안 선택 이유와 아직 확인하지 못한 기능/실물 조건을 함께 보여준다. 자동 검사 통과는 미관 근거이지 완벽한 자연스러움 보장이 아니다. 실제 월드 배치·플레이·E 성립은 이번 완료 기준이 아니다.

## 8. 소유·인계·반환

기획 소유는 이 원문, [DECISIONS](DECISIONS.md)의 D442, 공통 배치 문서의 현재 범위 안내다. 개발은 이 세 파일을 읽기로 인수하고 정확 코드/계약/시험·규칙 입력·명세/연구·생성물 경로를 먼저 선언한다. 기존 소스/공유 계약을 재사용하며 근거 없이 전체 모듈을 리팩토링하지 않는다. 애니메이션/Rig 문제가 실제로 필요한 경우에만 별도 전문 범위를 배분하고 일반 시험을 애니 담당에게 넘기지 않는다.

기술 보고는 `docs/Reports/패턴조합-배치규칙-D442-개발통합-2026-08-31.md`, 상세 산출물은 `artifacts/local/validation/pattern-composition-rules-d442/`를 사용한다. 개발이 CURRENT_WORK/개발통합상태판·필요 명세와 기존 조회/생성물 freshness를 관리한다. 본 승인 문서 편집 때문에 과거 source hash를 조용히 치환하거나 검사를 완화하지 않는다.

첫 구현 인수에서는 재사용/누락 규칙, 첫 정확 경로와 변경 호환, 코드/시험 결과를 반환하고 준비된 소수 격리 이미지부터 이어 보낸다. 문서·코드·시험·격리 시각·실제 World를 각각 구분한다. D440/D441 마감 중 소유 중첩이 있으면 안전 경계에서 조율하며 중복 DB 실행을 하지 않는다.

새 게임/생산·재고·시간 규칙, 실제 World/AreaSet 생성·배치, 운영 DB/공개 게시·외부 수집/구매·유료 호출·새 VM/업로드, 원본 자산 가공, Scene/Save 변경, H/WI/E 자동 등록·승격, r129/야간 자동화·다른 중지 작업의 포괄 재개, commit/push는 제외다. 이번 격리 검토 승인은 이전 실제 지도/보행 작업을 재개하는 승인이 아니다.
