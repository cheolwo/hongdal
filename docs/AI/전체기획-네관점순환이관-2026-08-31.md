## 1. 우선순위와 구조

사용자는 대표 사례만 정리하는 데서 머무르지 않고 기존 전체 기획을 먼저 같은 구조로 이관한 뒤, 그 구조를 따라 문답과 후속 기획을 계속하기를 원한다. D391의 작은 사례는 이관 방식 확인용으로 유지하되 전체 범위의 최종 산출물을 대신하지 않는다.

```text
현재 상황
  시간·공간·플레이어·대상 조건
        ↓
판독 가능한 정보와 가능한 선택 / WI
        ↓
선택·행동·시간 경과에 따른 결과
  성공 / 거부 / 실패 / 중단·재개 / 대기 — 해당하는 것만
        ↓
달라진 시간·공간·플레이어·대상 상태
        ↓
회복·귀환 또는 다음 선택들
```

네 관점은 같은 상황을 설명한다. 시간을 먼저 수행하고 공간을 나중에 수행한다는 순서가 아니다. 시간적 흐름은 행동 전후의 상태와 선택 가능성으로 표현한다. 기다리거나 행동하지 않은 경우의 변화도 원문 규칙이 있을 때만 연결한다. 한 줄의 강제 퀘스트나 Farm→Hub→City 필수 진행을 만들지 않는다.

## 2. 전체 범위와 원문 보존

- 기존 문답의 번호 질문·의미 후속, 주제 기획, 연결 연구·WI·H·자산/이미지 근거를 조사 대상으로 한다. 최신 색인 집계와 색인 밖 관련 주제 기획의 목록을 개발이 확인해 범위에 남긴다. 이전 관찰 437항목을 검증 없이 고정 총수로 사용하지 않는다.
- 전체란 모든 기존 원문을 복사하거나 새 필드로 덮어쓴다는 뜻이 아니다. **원문을 보존한 채 전체 항목의 위치·상태·관계를 찾을 수 있고, 검토 결과와 남은 공백을 구별할 수 있는 것**이다.
- 승인 답변·연구·명세의 ID·판본/hash·결정 의미는 유지한다. 삭제·소실·충돌·후속 대체·보류 자료는 그대로 추적하고 새 확정 답변을 지어내지 않는다.
- 하나의 Q에 여러 관점·WI·공간이 연결될 수 있고, 하나의 WI를 여러 Q가 설명할 수 있다. 비공간·공통 정책·자료 참고는 해당 없음 또는 참조 관계로 남긴다. 각 질문을 독립 WI/별도 H1로 바꾸지 않는다.

## 3. 이관 순서

1. **범위 목록 확보**: 주제별 원문과 기존 질문/의미 ID를 나열하고 색인 밖 자료·중복·소실을 표시한다. 이 단계는 의미 검토 완료가 아니다.
2. **주제별 재정리**: 원문의 확정·미정·제안을 네 관점, WI, 결과·다음 선택에 대응시킨다. 기존 문답/공간 색인의 단일 관계 입력·생성 문서를 재사용한다. 자동 추출은 검토 후보이며 개발의 원문 대조 없이 확인됨으로 올리지 않는다.
3. **시간적 분기 연결**: 명시된 행동 전후 조건과 결과, 중단/실패 뒤 가능한 복귀를 연결한다. 다른 주제로 이어지는 선택은 근거가 있는 경우에만 선택 가능한 연결로 기록한다. 임의 시간 환산·새 보상·추정 선행 조건을 추가하지 않는다.
4. **개발 검증·부분 반환**: 주제별로 원문 대응·참조·판본·검색 호환을 검증해 반환한다. 미정 하나 때문에 다른 주제의 이관을 중단하지 않고, 부분 반환을 전체 완료로 표시하지 않는다.
5. **기획 통합**: 기획은 해석 충돌과 새 선택을 검토한다. 전체 범위의 검토를 마친 뒤 빠진 선택을 중요도에 따라 문답으로 묶고 이후 답변도 같은 구조에 이어 붙인다.

현재 진행 중인 조회 도구는 안전한 검증 경계에서 합친다. 이관과 관계없는 새 게임 기능 확장보다 문서 연결을 우선한다. 기존 H1 시각 목록은 공간을 이해하기 위한 독립 자료로 연결하되 전체 캡처 완료를 문서 이관의 필수 선행으로 삼지 않는다.

| 다음 문답 목록 | 이미 답한 내용과 기술 공백을 제외한 실제 플레이 결정의 부족분 |

위 결과는 가능하면 기존 생성 문서의 목차·절로 제공하며 새 수기 대장을 병렬로 관리하지 않는다. 기획에서 읽는 정리 문서와 원문 권위를 구분한다.

## 5. 완료 기준과 보고

- 최신 범위의 모든 항목이 목록에 있고 누락/중복 검사가 수행되어야 한다.
- 각 항목이 원문 대응 검토됨, 사유 있는 해당 없음, 근거 소실/충돌, 미정/추가 기획 필요 등으로 설명돼야 한다. 미검토를 미정과 합치지 않는다.
- 전체 항목 수·원문 대조 검토 수·미검토 수·근거 문제 수를 구분한다. 단순 목록 확보만으로 전체 기획 이관 완료라고 하지 않는다. 전체 검토 후에도 해결되지 않은 원문 문제는 이관 결과의 명시적 한계다.
- 시간 단위·NPC 수행자·복수 대상·비공간 행동·실패/중단 분기·기존 선택권과 승인 상태를 보존해야 한다. 원문에 없는 다음 선택은 제안 또는 공백으로 남긴다.
- 기존 검색과 공간 조회, 판본 신선도·잘못된 연결 거부·생성 문서 링크를 개발이 검증한다. 기술검증 결과를 기획으로 반환한다.
- 실제 Logic/Presentation E, H 승인, 게임 플레이·Scene·캡처 완료 여부는 문서 이관과 별개다.

## 6. 역할과 실행 경계

기획은 이관 기준·기획 해석·새 질문과 승인, 개발은 전체 원문 조사·구조적 이관·조회/생성 도구·검증·CURRENT_WORK/통합판을 소유한다. 전문 자료가 필요하면 개발이 기존 담당에 좁게 배분한다. 의미 변경이 필요한 원문은 개발이 수정하지 않고 기획에 돌려보낸다.

이 요청은 전체 기획의 구조적 정리와 파일 기반 조회를 허용한다. 새 게임 규칙·WI/H 자동 등록·실행 명세 의미 변경·운영 DB·외부 게시·Scene/Save·E 승격·commit/push는 포함하지 않는다. r129/야간/다른 기능 중지와 기존 별도 승인된 H1 시각조사의 경계를 유지한다.

## 7. 잔여 389항목의 원문 대조와 관점별 리팩토링 (D410)

사용자는 D408/409 결과의 미검토 389항목도 현재 관점으로 검토하고 다시 정리하도록 요청했다. 대표 사례나 자동 목록화에 머무르지 않고 **잔여 항목 모두를 원문과 대조하여 사람이 읽는 플레이 문맥으로 연결하는 작업**을 개발 통합 담당에게 인계한다. 기획은 해석 충돌과 실제 새 선택을 받아 문답을 이어간다.

### 7.1 시작 범위와 집계

- 시작 관찰은 [D408/409 검증 보고](../Reports/D408-발견형인과기록-조회검증-2026-08-31.md)의 전체 454항목·관점 대조 65·미검토 389다. 기존 소실 Q272~274의 3항목은 정상 답변 대조와 구분한다. 이 숫자는 시작 기준이며 이후 원문 추가를 포함한 영구 총수가 아니다.
- 개발은 현행 색인에서 잔여 389개의 정확한 Q/의미 ID·주제·원문 판본/hash 목록을 먼저 고정한다. 목록은 기존 검증 산출물에 보존하고 별도 답변 원장으로 운영하지 않는다. 시작 집계가 다르면 차이와 추가/대체 항목부터 보고한다.
- 기존 65항목을 삭제하거나 다시 미검토로 돌리지 않는다. 실제 원문 변경이나 잘못된 대응이 확인된 해당 항목만 사유와 함께 재검토한다. 새 문답 유입과 기존 검토의 재개방은 시작 389의 처리 수와 분리한다.
- 각 반환에는 시작 389 중 검토를 마친 고유 항목 수·남은 미검토 수·근거 문제 및 현재 전체 집계를 함께 적는다. 같은 질문의 복수 WI/공간 연결을 별도 검토 항목으로 중복 집계하지 않는다.

### 7.3 분야별 진행과 소유권

- 개발이 실제 주제 목록에 따라 탐색·생존, 농업·건축·공간, 약초·지식·명상, NPC·관계·전투, 거래·물류·신용, 공통 정책·운영 등 의미가 이어지는 묶음으로 나눈다. 이 구분은 검토 편의를 위한 것이며 새 영역/필수 테크트리가 아니다. 한 분야만 계속 심화하여 다른 항목을 남기지 않는다.
- 묶음 크기는 원문 복잡도에 맞춰 조절하고 관련 선행·후속 답변을 함께 읽는다. 전문 담당에는 비중첩 ID 범위의 원문 읽기·대응 제안을 배분하고, 공통 관계 입력·생성물의 최종 쓰기와 검증은 개발 한 소유자가 통합한다.
- 기존 `eng/planning-inquiries/spatial-relations.json`의 검토 관계와 기존 검색기·순환 문서·WI 읽기 뷰를 재사용한다. 새 DB·병렬 검색기·수기 답변 대장을 만들지 않는다. 정확한 쓰기 경로와 필요한 최소 도구 보완은 개발이 착수 전에 알린다.
- 주제별 완료 묶음은 검증 뒤 바로 기획에 반환하고 다음 독립 묶음을 이어간다. 일부 충돌·소실·새 선택 때문에 전체 잔여 검토를 멈추지 않는다. 중간 보고는 전량 완료와 구분한다.
- 원문 편집과 검증이 겹치면 해당 입력의 변경을 조율하고 최종 판본으로 검증한다. 대조하지 않은 변경분의 hash만 자동 치환하거나 같은 실패를 반복하지 않는다. 새 문답은 가능하되 진행 중 묶음과 유입을 분리한다.

### 7.4 완료와 기획 반환

시작 389개의 고유 ID마다 원문 근거가 있는 일곱 칸 검토 또는 사유 있는 근거 문제 처분이 있고, 누락·중복·원문 상태·신선도·기존 조회 호환을 개발이 검증했을 때 **잔여 문답 검토 완료**라고 보고한다. 근거 소실은 소실로 확인한 것이며 복구나 의미 확정을 뜻하지 않는다. 전량 검토 완료와 전량 기획 확정·구현 완료는 다르다.

사용자가 읽는 결과는 기존 생성 순환 문서에서 **분야별 상황 → 선택 → 결과 → 다음 선택**, 관련 Q/WI/H와 공백을 따라갈 수 있게 구성한다. 기술 검증 보고와 별개로 이미 답한 내용, 원문 충돌, 아직 정하지 않은 플레이 선택, 단순 기술 연결 공백을 나눠 기획에 반환한다. 기존 근거로 답할 수 없는 중요한 플레이 선택만 우선순위를 정해 한 번에 질문 하나로 이어간다.

이번 기획 쓰기는 이 계획과 [D410 결정](DECISIONS.md#d-410-잔여-문답을-현재-관점으로-전량-대조하고-리팩토링한다) 두 파일이다. 개발은 기존 조회·문서·검증과 CURRENT_WORK/통합판을 맡고, 승인된 게임 원문·Logic/Presentation E·H/WI 등록·실행 명세 의미는 보존한다. D406 화면 정리·보행은 독립 승인 범위로 유지하며 이번 이관을 그 선행 대기로 만들지 않는다. r129/야간·무관한 중지 작업의 재개, Scene/Save·외부 자료 수집·운영 DB·commit/push는 포함하지 않는다.
