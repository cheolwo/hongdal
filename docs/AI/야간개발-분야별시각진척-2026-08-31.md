# 야간 개발: 분야별 시각 진척을 넓게 확인하기

- 판본: `overnight-cross-domain-visual-review.r1`
- 결정: D382 / 2026-08-31 / `AcceptedDirection`
- 사용자 요청: 문답으로 정한 여러 분야를 조사하고, 완전한 완주보다 여러 분야의 진행 모습을 이미지로 폭넓게 확인하는 것을 이번 야간 목표로 둔다.
- 관계: [D375 야간 순환](야간개발순환-2026-08-30.md)과 [D381 구간 전환](야간개발-플레이구간전환-2026-08-31.md)의 우선순위 보완. 기존 원문/hash는 보존한다.

## 1. 이번 밤의 목표 변경

한 분야의 입력·완주 문제만 계속 해결하는 것보다 **여러 분야에서 현재 무엇이 보이고 무엇이 아직 없는지**를 비교 가능한 화면과 설명으로 전달한다. 이때 '수평적으로 넓힌다'는 작업 폭의 의미이지 E8~E10 캠페인 승인이나 여러 분야의 E5 달성을 뜻하지 않는다.

기존 전체 문답 조회와 기획 원문을 이용해 분야별 대표 장면/패널을 고른다. 새 질문을 늘리거나 미정 규칙을 발명해서 빈 화면을 채우지 않는다. 분야마다 한 장면을 먼저 확보한 뒤 여유가 있을 때 조작·전환을 보완한다. 수량은 보장이 아니며 준비 상태에 따라 조정한다.

## 2. 첫 시각 검토 후보

다음은 조사·검토 순서의 후보다. 현재 실행 가능하다는 판정이 아니다. 개발은 각 원문·기존 명세·실제 자산/소비 코드를 대조하여 가장 준비된 분야부터 공간 슬롯에 배분한다.

| 분야 | 문답/기획 근거 | 사용자가 확인할 장면 또는 패널 | 주의할 차이 |
| --- | --- | --- | --- |
| 농장 관리 | Farm 경작 승인, FB01 / Q378~386 | 밭·작물·작업 대상과 관리/위임 정보 | 한 밭 실제 상태와 경관 배치만 있는 후보를 구분 |
| 약초·회복 | Q347~352 및 HB01 | 약초·냄비·불·컵의 작업 공간, 내용물/제작·음용 정보 | 소품이 놓였다고 달이기·섭취·회복 구현 완료 아님 |
| 방위·전투 | [Farm 병영·방위 Q223~239](../Architecture/PlayableLoops/PlanningSessions/Farm병영방위/farm-barracks-defense.inquiry.r1.md) | 외곽 초소·분대 카드·경계 상태·영웅과 분대의 구분 | 정지 분대 배치가 자동 전투·피해·귀환 증거는 아님 |
| 외상·상환·신용 | [방문·거래 Q355~359](../Architecture/PlayableLoops/PlanningSessions/공동체편입방문/community-membership-visitor.inquiry.r1.md) | NPC 거래 제안과 채무/상환/신용을 읽는 상세 패널 | 구체 확정은 물품 외상이다. 현금 대출·담보·이자 수치를 새로 만들지 않음 |
| NPC 교류·공동체 | 기존 방문자 기획, 관심·인연 문답 | 방문자·인사·제안 카드와 현재 선택 상태 | 실제 Session 연결, 독립 Fixture, 정적 UI 시안을 구분 |
| 월드·거점 경관 | LS01 / Q387~396, D363·D376·D378 | Farm·물길·작업로·식생·영역 경계의 전체 모습 | 후보 배치와 승인된 실제 세계 배치를 구분; 미검증 지지/통행 표시 |

기존 벌목 화면도 전체 목록에 포함하되, 같은 입력 차단 재시도를 이 목록의 필수 선행으로 두지 않는다. Town·Hub·City를 무조건 새 지형에 완성하거나 Farm→Hub→City 경로를 만들 필요는 없다. 독립 영역의 현재 표현 또는 미구현 공백을 보여준다.

## 3. 화면마다 증거 종류를 명시한다

| 표기 | 허용되는 설명 | 완료로 간주하지 않는 것 |
| --- | --- | --- |
| 실제 플레이 화면 | 실제 Runtime 상태와 입력을 연결해 UI 포함 Game View 확인 | 보여주지 않은 성공·실패·저장·귀환 |
| 격리 검토 화면 | 소유가 분리된 임시 Preview/검토 컨테이너에서 보유 자산·명시적 Fixture를 조립해 확인 | canonical 세계 반입, 실제 생산/전투/채무 상태 |
| UI 검토 시안 | 확정된 정보 구성을 비실행 패널로 표시. 예시/미정 값을 명시 | 실제 거래·상환·위임·성장 실행 |
| 아직 화면 없음 | 준비물·누락 연결·다음 한 작업을 기록 | 이미지 개수를 채우기 위한 성공 연출 |

이번 요청은 기존 기획·자산에 근거한 **비권위 시각 검토 준비**도 허용한다. 실행 상태가 없는 분야는 정적 UI/격리 후보로 보여줄 수 있지만 기존 연구 기준을 임의 변경하거나 미정 게임 수치를 확정하지 않는다. 기존 Required 연구가 필요한 실제 조립은 해당 검토·결속을 지키며, 미결속 범위는 시안으로 한정한다.

실제 Unity 화면은 공간 담당이 캡처한다. 생성 이미지를 구현 증거로 대체하지 않는다. 기존 캡처 재사용은 촬영 시점·구현 판본을 적고 최신 상태와 차이를 확인한다. 시안/검토본에는 이미지 내부 또는 바로 옆에 종류를 표시하여 실제 게임 화면과 섞이지 않게 한다.

## 4. 배분과 순환

1. 개발: 기존 문답 색인→원문→WI/명세→자산/상태/화면을 읽어 위 후보의 가능 수준을 짧게 분류한다. 구현 원장의 분류값만으로 기능 부재를 단정하지 않는다.
2. 공간: 실제 화면 가능한 후보부터 단독 Editor 슬롯에서 한 장면씩 확인·캡처한다. 사용 중인 canonical의 미소유 dirty·원본을 보존한다. 격리 검토물을 공식 Scene으로 추가하거나 일괄 저장하지 않는다.
3. 애니: 보유 Actor/Clip·도구의 재사용 가능성과 시각적 부족을 병렬 조사한다. D380 신규 제작 미승인은 그대로이며 이번 요구가 Blender 신규 가공 허용으로 바뀌지 않는다.
4. 개발: 각 분야의 이미지·표기·파일/hash·실행 조건을 직접 검토하고 다음 분야로 이동한다. 깊은 차단 하나가 전체 시각 목록을 막으면 공백을 남기고 독립 후보를 진행한다.
5. 기획: 반환된 분야별 비교를 통해 다음 실제 구현 우선순위를 사용자와 결정한다. 새 기능·수치를 밤중에 자동 확정하지 않는다.

공통 입력 결함을 고치는 일은 여러 분야의 화면 접근을 열 때 우선할 수 있다. 다만 새로운 증거 없는 동일 진단 반복은 기존 제한을 따른다. 진행 중 시험·Play는 안전 경계에서 마감한 뒤 슬롯을 전환한다.

## 5. 아침 전달물

기존 개발 통합 상태판과 전용 인계 보고에 **분야별 시각 목차**를 만든다. 각 항목은 다음을 포함한다.

- 대표 이미지 링크와 증거 종류, 원문 Q/기획 참조.
- 보이는 것과 실제로 조작 가능한 것.
- 미구현/미검증, 원본·상태 보존 결과와 실행 시각/판본.
- 다음에 연결할 작은 작업 하나.

이미지를 모은다는 이유로 상태를 생성·시간 진행·거래/전투 완료 처리하지 않는다. 기존 승인 안에서 실제 실행하거나 명시적 격리 Fixture를 사용한다. 정상적인 실제 입력의 결과와 시안 데이터를 혼합하지 않는다.
