## 1. 기획 기준 달력

한국에서 사용하는 24절기의 이름과 순서를 공통 기준으로 삼는다. 다음은 읽기 편의상 입춘부터 정렬한 순환 목록이며 게임의 새해·시작일·지역별 실제 기온을 결정하는 표가 아니다.

| 계절 문맥 | 절기 순서 |
| --- | --- |
| 봄 | 입춘 → 우수 → 경칩 → 춘분 → 청명 → 곡우 |
| 여름 | 입하 → 소만 → 망종 → 하지 → 소서 → 대서 |
| 가을 | 입추 → 처서 → 백로 → 추분 → 한로 → 상강 |
| 겨울 | 입동 → 소설 → 대설 → 동지 → 소한 → 대한 |

연도별 정확 날짜·시각은 별도 공식 달력 자료로 확인한다. 매년 같은 날짜, 한 절기 고정 15일 또는 현실 하루=게임 하루로 확정하지 않는다. 계절 이름이 같아도 가상 지역과 재배 시설에 따른 조건은 다를 수 있다.

### 절기 변화는 주민 복장과 식생으로 먼저 읽힌다

절기가 바뀌면 플레이어는 달력이나 카드만이 아니라 주민 복장과 주변 식생의 변화로도 시기를 알아차린다. 24절기마다 서로 다른 캐릭터 Prefab과 식생 Prefab을 하나씩 만드는 방식은 기본안으로 삼지 않는다. 먼저 봄·여름·가을·겨울의 큰 표현군을 재사용하고, 각 절기는 같은 표현군 안에서 밀도·색·생육 단계·겉옷과 작업 장비의 조합이 점진적으로 달라지는 전환으로 읽히게 한다.

| 표현 대상 | 기본 방향 | 지켜야 할 경계 |
| --- | --- | --- |
| 주민 복장 | 기온·강수·바람·작업 종류에 맞춰 겉옷, 모자, 장갑, 신발과 작업 소품의 조합을 바꾼다. | 절기 이름만으로 모든 주민에게 같은 옷을 강제하지 않는다. 직업·실내외·지역·개인차를 보존한다. |
| 봄 식생 | 겨울 뒤 낮은 밀도에서 새순·어린 풀·초기 꽃이 점차 나타나게 한다. | 봄 전체를 황량하게 고정하거나 춘분 즉시 여름 밀도로 바꾸지 않는다. |
| 여름 식생 | 잎과 하층 식생의 밀도·채도를 높여 무성함을 읽게 한다. | 밀도 증가가 통행·채집량·생산 성공을 자동 변경하지 않는다. |
| 가을 식생 | 수종별 단풍·마른 풀·수확 뒤 흔적을 조합한다. | 모든 수종을 같은 색으로 바꾸거나 낙엽 여부를 일괄 적용하지 않는다. |
| 겨울 식생 | 낙엽·휴면·마른 지면과 상록수의 지속을 구분한다. | 적설은 지역·고도·날씨 상태가 있을 때만 별도 표현하며 겨울의 필수 고정 배경으로 두지 않는다. |

계절 표현은 서버·Simulation이 확정한 절기·기상·지역 상태를 읽어 보여 주는 Presentation이다. 옷이나 나뭇잎 색 자체가 시간, 체온, 성장, 채집 가능, 안전 또는 생산 결과의 권위가 되지 않는다. 미발견 지역은 첫 관측 전까지 해당 지역의 실제 계절 Profile을 노출하지 않는다.

### Synty 조사와 Blender 보완 판정 인계

개발 조사는 기존 Synty 기능 대장과 보유 원본을 먼저 재사용하여 `주민 기본 몸체/복장 부품/작업 소품`, `수종/관목/풀/꽃/농작물`, `재질·색 Variant`, `LOD·Rig·Avatar·Renderer 구조`를 파일 근거로 대응한다. 결과는 다음 세 등급으로 구분한다.

1. **그대로 재사용:** 기존 Prefab·재질 Variant 조합만으로 의도가 읽힌다.
2. **Unity 조립 보완:** 원본을 수정하지 않고 프로젝트 소유 wrapper, 자식 활성 조합, 재질·색 Profile 또는 밀도 배치로 해결 가능하다.
3. **Blender 계획 필요:** 실루엣·의복 겹·낙엽/가지 구조·손상 또는 계절 형태처럼 메시 변경이 불가피하다. 이때도 입력 원본, 프로젝트 소유 전용 복사본, 변경 부위, 출력 파일, Rig/LOD/Collider/재질 보존 조건과 되돌림 방안을 계획으로만 남긴다.

조사 판정은 자산 존재·파일 구조·시각 후보의 근거이며 실제 Scene 배치나 Game View, 계절 전환 성공, E5 성립을 대신하지 않는다. 이번 인계는 조사와 가공 계획 수립까지이며 Synty 원본 수정, Blender 실행, 새 자산 구매, Scene 저장, 시간·성장 규칙 변경은 포함하지 않는다.

### 점진 전환 우선과 턴 경계 fallback

절기는 변화의 방향을 정하고, 최근 며칠의 권위 기온·강수·바람 Profile은 복장과 식생이 그 방향으로 이동하는 속도를 보정하는 안을 우선한다. 이를 구현할 수 있으면 봄이 되자마자 잎과 옷이 한 프레임에 교체되는 대신, 주민의 다음 외출·작업 일정과 식생 표현 보간을 통해 서서히 달라진다. 날씨 자료가 없거나 품질이 부족하면 절기의 기본 전환 Profile만 사용하며 외부 응답을 플레이 도중 직접 권위로 삼지 않는다.

현재 코드·자산 구조가 이 점진 전환을 안전하게 지원하지 못하면 첫 구현은 **절기 턴 마감 뒤 다음 턴 시작 경계에서 표현 Profile을 교체**하는 방식으로 축소한다. 이 경우에도 검은 화면의 즉시 교체보다 짧은 시간 경과 연출, 로딩 경계 또는 안전한 재진입 뒤 새 풍경을 보여 주어 변화가 자연스럽게 읽히게 한다. 이후 점진 전환이 검증되면 같은 권위 절기 상태를 유지한 채 Presentation만 개선한다.

- 우선안: `권위 절기/날씨 상태 사본 → 계절 표현 목표 Profile → 주민 일정 경계의 복장 조합 변경 + 식생 시각 보간`.
- fallback: `절기 턴 마감 → 상태 사본 고정 → 다음 턴 시작/안전한 재진입에서 복장·식생 Profile 교체`.
- 금지: 화면의 보간 진행률로 절기나 날씨를 변경하거나, 실제 날짜와 무관한 외부 실시간 응답이 진행 중인 턴의 풍경을 임의로 바꾸는 것.

저장소 정적 조사에서는 연속된 일별 날씨 상태 사본 검증과 `WorldTick` 사이의 시각 보간 원칙을 재사용할 근거가 확인된다. 그러나 절기별 주민 복장 및 식생 Presenter, 실제 Synty Variant 결속, 저장·재진입과 동일 화면 검증은 아직 확인되지 않았다. 따라서 **구조상 구현 가능한 후보**와 **현재 제품에 구현되어 검증됨**을 구분하며, 개발 조사가 이 공백을 판정한다.

### 개발 조사 최종 반환

[24절기 주민 복장·식생 Synty/Blender 보완 개발 조사](../Reports/24절기-주민복장-식생-Synty-Blender보완-개발조사-2026-09-02.md)는 현행 기획을 `Conditional`로 판정했다.

- Farm 주민 기본 몸체, 일부 모자·작업 도구와 Birch/Pine/관목/풀/꽃/작물은 보유 후보가 있다.
- 주민 우비·작업복·귀마개·City 코트/재킷은 다른 팩과의 Rig·Avatar·재질 계보를 확인한 뒤 프로젝트 소유 wrapper에서 조립할 후보이며 현재 착용 성공 근거가 아니다.
- 독립 장갑·신발/장화와 겨울 휴면 Birch는 현재 조사 범위에서 적합 후보를 확인하지 못했다. `Dead Birch`를 휴면 수목으로 오인하지 않으며 Unity 조립으로 부족함이 입증된 뒤에만 Blender 제작 계획을 다시 연다.
- 기존 일별 날씨·WorldTick·대기 전환·계절 표현 구조는 부분 재사용할 수 있지만, `24절기+최근 날씨 상태 사본 → 결정적 표현 Profile → 주민 일정 경계/식생 adapter`의 완전한 제품 연결은 없다.
- 따라서 첫 개발 후보는 `절기 턴 마감 → 권위 상태 사본과 목표 Profile hash 고정 → 다음 턴 시작 또는 안전한 재진입에서 주민·식생 표현을 원자적으로 교체`로 제한한다.
- 점진 보간은 시작/목표 Profile·revision·전환 epoch·adapter 판본을 저장하고 LocalProcess/RemoteHost 및 중간 Save/Replay에서 같은 화면을 재구성할 수 있을 때 후속으로 연다. 프레임 시간만으로 진행률을 계산하지 않는다.

이 반환은 파일·계약·자산의 정적 조사다. Unity Editor·Scene·Play Mode·Game View·Blender 제작·실제 결속·E 승격은 수행되지 않았다.

### 절기에 맞는 주민 생활 작업

주민은 복장과 식생뿐 아니라 실제로 보이는 생활 작업을 통해 새 절기를 드러낸다. 첫 표현군은 농사·운송·수리로 나눈다.

| 작업군 | 화면에서 먼저 읽힐 행동 | 계절·절기 문맥 예시 | 필요한 표현 조사 |
| --- | --- | --- | --- |
| 농사 | 밭 준비, 파종·정식, 물주기, 생육 관리, 수확 뒤 정리 | 봄의 밭 준비·파종, 여름의 관리, 가을의 수확·건조, 겨울의 시설·도구 정비 | 주민 작업복·괭이·물뿌리개·바구니·작물 단계, 굽힘·들기·작업 반복 동작 |
| 운송 | 적재, 운반, 하역, 덮개·바퀴·화물 점검 | 파종 자재 반입, 수확물 출하, 겨울 비축과 기상 전 선행 운송 | 마차·손수레·트럭·상자·포대·팔레트, 들기·밀기·상하차·승하차 동작 |
| 수리 | 울타리·지붕·도로·농기구 점검과 보수 | 농번기 전 시설 정비, 장마·태풍 뒤 복구, 겨울 전 방풍·난방 준비 | 망치·목재·사다리·비계·공구 벨트, 망치질·조립·점검·중단/귀환 동작 |

절기가 바뀌었다고 진행 중인 작업을 같은 순간에 취소하거나 모든 주민을 같은 업무로 이동시키지 않는다. 주민은 현재 안전한 작업 단위를 마친 뒤 다음 외출·교대·업무 선택 경계에서 새 절기 작업 후보를 받는다. 생명 구조, 화재, 붕괴, 방어처럼 긴급한 사건은 절기 업무보다 우선할 수 있으며, 계절에 맞지 않는 작업도 시설·재고·의뢰·위기 사유가 있으면 허용한다.

이 작업 모습은 업무 완료의 권위가 아니다. Actor의 반복 동작, 소품과 이동만 보였다고 파종·입고·수리 결과를 지급하지 않으며, 실제 상태 변화는 해당 WI·Task·Simulation 결과와 같은 revision으로 다시 표현해야 한다.

### 생활 작업 표현 조사 인계

개발은 기존 Synty 기능 대장과 Animation inventory를 우선 대조하고 농사·운송·수리 각각에서 다음을 반환한다.

1. 사용할 수 있는 Actor 몸체·복장·소품·차량·시설 Prefab과 GUID·원본 hash.
2. `AnimationRole`, `ActionCue`, Clip 후보, Rig/Avatar, root motion, 손·발·도구 접촉점, 반복·중단·귀환 가능 여부.
3. `그대로 재사용 / Unity 조립 보완 / Blender 계획 필요 / 후보 없음` 판정.
4. Blender 계획이 필요하면 실제 가공 없이 입력 원본·전용 복사본·변경 부위·출력·Rig/LOD/Collider/재질 보존·복구 조건.
5. 한 Actor가 계절 복장과 작업 동작을 함께 사용할 때 생기는 Skeleton·재질·도구 Slot 충돌과 가장 작은 안전 표본.

첫 조사는 각 작업군을 대표하는 한 장면 후보까지만 다룬다. 전 주민·24절기·전 직업 조합을 한꺼번에 조사하거나 신규 Clip·Prefab 제작, Blender 실행, Scene 배치, 실제 재생, 구매, E 승격을 수행하지 않는다.

### 설명은 관심 있는 플레이어가 주민을 선택할 때만 연다

새 절기가 시작되어도 안내 창이나 해설을 자동으로 띄우지 않는다. 플레이어는 바뀐 복장, 식생, 작업 소품과 주민의 행동을 먼저 보고 계절 변화를 스스로 알아차릴 수 있다. 더 알고 싶을 때 작업 중이거나 이동 중인 주민을 선택하면 그 주민이 현재 알고 있고 관여하는 범위에서만 짧은 설명을 들을 수 있다.

- 주민 선택은 설명 열람 요청이며 대화·퀘스트 수락·작업 중단을 자동 실행하지 않는다.
- 설명에 관심이 없는 플레이어는 주민을 선택하지 않고 그대로 이동·탐험·작업할 수 있다.
- 주민은 자신의 직업·현재 장소·관측 범위에 맞는 내용만 설명한다. 농장 주민이 도시 전체 물류 상황이나 미발견 지역의 상태를 전지적으로 알려 주지 않는다.
- 작업 중인 주민은 안전한 동작 경계에서 짧게 응답하거나, 멈출 수 없는 작업이면 `지금은 작업 중`이라는 상태와 나중에 대화할 수 있는 시점을 보여 준다.
- 이동 중인 주민은 길을 막거나 목적지를 잃지 않는 범위에서 응답한다. 설명을 열었다는 이유로 운송·농사·수리 결과를 완료 처리하지 않는다.
- 별도 퀘스트가 실제로 열려 있을 때만 기존 색상 표식을 사용한다. 절기 설명만 가능한 주민에게 퀘스트 표식을 억지로 붙이지 않는다.

첫 열람은 한두 문장의 현재 맥락으로 제한하고, 출처·일정·물자·작업 이유 같은 상세 정보는 플레이어가 추가로 선택할 때만 연다. 정확 대화 길이·음성·시간 정지/감속·반복 열람·접근성 UI는 후속 질문으로 남긴다.

### 일반 주민 말풍선과 퀘스트 대화창을 분리한다

일반 주민을 선택해 현재 복장·절기·작업의 생활 맥락을 확인할 때는 화면을 크게 점유하는 대화창을 열지 않고 주민 가까이에 짧은 말풍선을 표시한다. 말풍선은 한두 문장으로 현재 관측 가능한 내용만 전하며 플레이어 이동과 주민의 안전한 작업 진행을 불필요하게 막지 않는다.

실제로 열린 퀘스트의 제안·조건·대가·수락·거절, 중요한 인물 관계나 선택이 필요한 대화는 기존 표식과 함께 별도 대화창을 사용할 수 있다. 대화창을 열었다고 퀘스트를 자동 수락하지 않고 명시적 선택 전에는 상태를 바꾸지 않는다.

| 상호작용 | 기본 표현 | 포함하는 것 | 포함하지 않는 것 |
| --- | --- | --- | --- |
| 일반 주민 선택 | 짧은 말풍선 | 현재 절기 체감, 복장·작업 이유, 가까운 생활 변화 | 퀘스트 자동 생성·수락, 상세 원장, 미발견 정보, 세계 시간 강제 정지 |
| 퀘스트 주민 선택 | 대화창 | 제안·목표·대가·선택·거절과 필요한 상세 설명 | 창을 열기만 한 상태에서의 자동 수락·보상·업무 완료 |

같은 주민도 평상시에는 말풍선으로 응답하고 실제 퀘스트가 열렸을 때만 대화창 진입 후보를 제공할 수 있다. 정확 말풍선 유지 시간, 거리, 겹침 처리, 음성 유무, 이동 중 표시 위치와 접근성 대체 표현은 미정이다.

### 생활 작업 개발 조사 최종 반환

[24절기 생활 작업 Synty·Animation·Blender 개발 조사](../Reports/24절기-생활작업-Synty-Animation-Blender-개발조사-2026-09-02.md)는 다음 대표 장면을 `Conditional`로 판정했다.

- 운송: Town 주문 차량 도착 뒤 손수레 하역. 정차 트럭·팔레트·상자는 재사용 후보이고 손수레 grip/load·바퀴·화물 수명은 Unity 조립 보완, Carry/Lift/Load/Unload Clip과 anchor는 후보 없음이다.

- 일반 말풍선은 Actor 안정 식별자의 Presentation 전용 선택 proxy와 머리 위 기준점, 퀘스트 대화창은 실제 Quest 상태에 결속된 별도 진입 기준점이 필요하다. 둘 다 현재 제품 결속은 확인되지 않았다.
- 계절 복장 교체는 Task 종료·도구 해제·안전 자세 뒤에만 수행하며 Farm과 Construction 완성형 Actor의 Skeleton을 섞지 않는다.

## 4. 첫 조사 묶음과 반환

- **절기 기준:** 위 24개 명칭·순서를 공식 자료와 대조하고 연도별 날짜를 확보할 경로·공식/예비 판본·접근 조건을 기록한다. 정확한 연도별 24개 시각 확보에 막혀도 다른 조사까지 멈추지 않는다.
- **농산물 최대 3종:** 기존 게임/품목 자료에 있는 감자를 우선 검토하고, 위 농사로 식재료 중 출처가 명확한 두 종 이내를 고른다. 제철과 파종/수확 차이가 드러나는 소수 근거만 확인한다.
- **수산물 최대 3종:** 확인한 해수부 자료의 대하·흰다리새우·한치를 첫 후보로 검토한다. 새우류를 모두 같은 상품으로 병합하지 않고 근거가 부족하면 미확인 행으로 반환한다. 한 지역에 모두 적용하지 않는다.
- 자료마다 필요한 공식 상세 페이지 소수만 조회한다. 24절기×전 품목을 채우기 위한 대량 수집·추정 채우기를 하지 않는다. 수산물의 실제 채취 허용/금어기 규칙 조사는 후속이며 제철이 곧 채취 허가라는 뜻이 아니다.
- **전문 산출물:** 기존 자료조사 전용 worktree의 `docs/Research/GameData/D403/` 아래 조사 요약·작은 구조화 목록·출처/제약·manifest를 묶어 개발에 반환한다. 원자료는 기존 `artifacts/local/game-data-research/` 범위에만 두고 기존 동결 조사물은 덮지 않는다. 실제 쓰기 파일명은 개발이 배분 전에 고정한다.
- **개발 인수:** 원문/기간 의미·ID·중복·hash·자료 권리 미확인·직접/파생 대응을 검토한 뒤 공유 조사 폴더에 통합한다. 기존 문답 색인에 D403 상태와 자료 링크를 연결하며 새 검색기/DB를 만들지 않는다.
- **기획 반환:** 실제 확보/미확보와 게임 활용 제안을 구분한 작은 표로 먼저 돌아온다. 이후 근거가 있는 품목 하나로 지금·여기·나·너·이렇게의 단일 질문을 이어간다.

## 5. 실행·승인 경계

기획 → 개발 → 기존 자료조사 담당 → 개발 검증 → 기획 반환을 따른다. 현재 담당 ID는 `01a0524f-72e7-75e1-986a-d149951e1240`이며 새 작업을 중복 생성하지 않는다. 공개 공식 페이지의 제한적 조사와 로컬 연구 자료 정리를 요청한다. 로그인/유료 호출/키 발급·운영 DB·자동 게시/알림·새 게임 코드/시간/Save·Scene·E·commit/push는 포함하지 않는다. 권리·접근이 막힌 자료만 보류하고 가능한 독립 표본을 진행한다.

## 6. 춘분 무렵의 약초·식물·농작물 사전 조사 (D413)

### 목적과 범위

사용자는 [D412 춘분 기준 사례](../Architecture/PlayableLoops/PlanningSessions/첫플레이체감/first-play-experience.inquiry.r1.md#기준-절기--춘분-무렵-d412)의 경관 조사와 함께, 그 무렵 자라는 약초·농산물도 먼저 조사해 이후 종합 기획에 활용하기를 요청했다. 조사 의미 ID는 같은 문답의 `spring-equinox-herb-crop-research`이며 상태는 `Confirmed`다. 연구 자료 확보 요청이고 특정 종의 게임 채택·약효·수확 가능 판정은 아니다.

‘자라는’ 것을 다음처럼 분리한다. 한 식물이 여러 과정에 해당하더라도 같은 사실로 합치지 않는다.

| 조사 관점 | 확인할 원천 사실 | 기획에서 사용할 때의 구분 |
| --- | --- | --- |
| 야생 약초·식물 | 자생 환경과 시기, 새순·잎·꽃 등 생육 단계, 종 식별 근거 | 보이는 식물과 채집/식용/약용 가능한 식물은 다름 |
| 농작물 파종·정식 | 작물·품종·지역·작형별 준비와 심는 시기 | 춘분에 심는 작물이 그때 수확되는 것은 아님 |
| 생육·수확·채집 | 해당 시기에 보이는 단계, 수확/채집 기간과 대상 부위의 출처 | 생육 중·꽃 핌·상품 수확·야생 채집을 분리 |
| 유통·제철 참고 | 출하·시장 공급·월별 추천 등 실제 자료의 의미 | 매장에서 보이는 품목이 주변 야생이나 밭에 자란다는 근거로 쓰지 않음 |

국내 자료부터 조사하되 게임의 지역은 아직 확정하지 않는다. 중부/남부·평지/고지대·야생/재배·노지/시설처럼 출처가 명시한 조건을 각각 보존하고, 지역 미기재를 전국 적용으로 바꾸지 않는다. 3월 또는 봄이라는 자료만으로 춘분의 정확 날짜·기간을 확정하지 않는다. 직접 절기 언급, 날짜 범위와의 검토 대응, 월/계절 수준 참고, 대응 불가를 구분한다.

### 첫 조사 묶음

- 기존 [D403 인수 자료](../Research/GameData/D403/development-intake.r1.md), 농사로 감자 작형·생육 자료 및 자료조사 재사용 목록을 먼저 읽는다. 기존 표본/원본은 보존하고 같은 자료를 대량 재수집하지 않는다. KAMIS/AMS 가격은 이번 목적에 필요하지 않아 호출하지 않는다.
- 첫 묶음은 **최대 8종**으로 제한한다. 야생 약초/식물 후보와 농작물을 각각 4종 이내로 살피되, 실제 확인한 공식 근거의 적합성에 따라 수를 줄일 수 있다. 식용 나물을 약초로 재분류하여 수를 채우지 않는다. 근거 있는 약용식물 후보가 없으면 그 공백을 반환한다.
- 감자는 기존 자료 재사용 후보이며 게임 최초 작물 선택을 바꾸지 않는다. 달래는 아래 이른 봄 자료의 조사 후보로만 제시한다. 나머지는 농촌진흥청·농사로·국립수목원/산림청·지역 농업기술기관 등 공식 자료에서 기간/서식지 근거가 있는 소수를 전문 담당이 선정한다.
- 종/통칭/품종과 대상 부위, 근거 기간·지역·생육 단계, 확인 가능한 서식 환경·외형 특징을 조사한다. 직접 대응되지 않는 상품/원천 코드는 미연결로 남긴다. 일반 식물 Prefab을 특정 약초 종의 실제 외형 증거로 삼지 않는다.

### 기획의 사전 열람 — 전문 검증과 구분

2026-08-31 아래 두 공식 페이지의 본문을 열었다. 전문의 최종 종 판별·지역/시기 대조·권리 검사나 제품 반입 근거가 아니라 조사 시작점이다. 신규 원자료/사진 다운로드는 하지 않았다.

- [농촌진흥청 그린매거진 달래](https://rda.go.kr/webzine/2022/04/sub4-1.html): 이른 봄과 밭이랑·논둑의 생육 설명을 확인했다. 정확 춘분 날짜·지역별 생육/채집 기간·약용 분류·학명은 이 설명만으로 확정하지 않는다. 페이지의 건강효능·조리/섭취 부분은 이번 게임 조사에 전용하지 않는다.
- [농사로 감자 농작업 일정](https://www.nongsaro.go.kr/portal/ps/psb/psbl/workScheduleDtl.ps?cntntsNo=30699&menuId=PS00087&sKidofcomdtySeCode=FC): 봄·여름·가을·겨울 시설 재배의 작업 구분을 확인했다. 정확 기간은 기존 D403 기록과 원표를 다시 대조하며 추출된 표의 열 위치만 보고 날짜를 추정하지 않는다. 기존 코드 대응 미확정·자료 권리 경계를 유지한다.

### 산출물과 경관 조사 연결

기존 자료조사 스레드 `01a0524f-72e7-75e1-986a-d149951e1240`의 전용 작업 위치에서 `docs/Research/GameData/D413/README.md`, `evidence.r1.json`, `manifest.r1.json`을 작성하도록 개발이 배분한다. 임시 조사·허용된 소표본은 기존 `artifacts/local/game-data-research/d413/` 범위이며 원자료를 공유 폴더로 자동 반입하지 않는다. 개발이 검토 후 공유 경로로 인수하고 인수 판정·현재 상태를 별도로 남긴다.

각 행은 기존 원천 사실/절기 대응/게임 해석의 세 층을 재사용하며 다음을 연결한다.

- 종/품목 명칭과 공식 식별 근거·미확정, 기간 원문과 정밀도, 지역/재배 방식/생육 단계, 기관·URL·제목·발표/열람 시점.
- 실제 확보 범위와 파일 hash(파일이 있을 때만), 출처/저장/재표시 권리 상태, 로그인·활용신청 필요 여부. 공개 페이지 접근을 제품 재사용 허락으로 간주하지 않는다.
- **지금:** 춘분과의 관계·조건. **여기:** 숲 가장자리·밭둑·습지 등 출처가 뒷받침하는 환경. **나/너:** 발견·재배를 고려하는 플레이어와 식물 후보. **이렇게/결과/다음 선택:** 기존 관찰·채집·파종·관리 등 기획 활용 제안과 미결정 사항. 실행 WI/효과 승인이 아니다.
- D412의 경관 역할과 연결할 수 있는 문맥은 제안으로만 적는다. 폭포 근처이므로 모든 약초가 자란다거나 기존 범용 풀 Prefab이 해당 종이라고 추정하지 않는다. 구체 Prefab 대응은 개발·공간이 별도 자료와 대조할 때까지 미연결이다.

첫 소수 근거가 확보되면 부분 반환하고 조사한 종·주장 수, 직접 절기 근거와 월/계절 참고, 미확인·권리/접근 차단을 구분한다. 목록 수만으로 전체 조사/기획을 완료했다고 하지 않는다. 기획은 경관 자료와 식물 자료가 도착한 뒤 근거가 만나는 후보부터 종합한다.

### 보호 경계

현실 건강효능·처방·복용량·채취 식별/식용 안전 조언은 이번 범위 밖이다. 약초라는 명칭만으로 실제 치료 효과나 게임 회복 수치를 만들지 않는다. 게임의 채집 허용·희귀도·수량·성장 시간·발생 위치·소유/환경 훼손·상거래는 별도 승인 사항이다.

로그인/키/활용신청/비용이 실제 필요하면 D404에 따라 필요 근거·사용자 조치·공개 대안을 먼저 반환하고 가능한 다른 자료는 계속 조사한다. 계정 생성·유료 호출·권한 우회·대량 수집·실제 운영 DB/수집기·새 상품/WI/H·게임코드/Scene/Save/E·commit/push는 포함하지 않는다. D410 전량 검토·D412 경관 파일 조사·D406 독립 승인 범위를 막지 않으며 r129/야간은 재개하지 않는다.
