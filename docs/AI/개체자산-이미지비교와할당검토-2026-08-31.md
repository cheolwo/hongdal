## 1. 데이터 구축과 이미지 검토를 병행한다

[D431 MySQL 목록/관계 구현](Synty자산-MySQL목록과개체관계-구현승인-2026-08-31.md)과 [D430 실태 감사](기존개체-KAMIS-시각대응-재검증과축적-2026-08-31.md)를 유지한다. 데이터 목록·후보 관계의 저장은 이미지가 없어도 진행하고, 구체적인 외형 할당을 확정할 때는 대상·역할에 대응하는 이미지 근거를 확인한다. 전체 자산 촬영을 DB 구축의 선행 조건으로 만들지 않는다.

[D426 공통 대응/검토](개체레코드-시각자산대응-확장과개발인계-2026-08-31.md)의 개별/기본 구분, Draft·검토·승인·제외와 권한/판본 검사를 재사용한다. 새 승인 시스템을 병렬로 만들지 않으며 이번 지시 자체를 모든 후보의 승인으로 기록하지 않는다.

## 2. 사람이 확인할 최소 비교 화면

| 표시 부분 | 필요한 내용 |
| --- | --- |
| 대상 정보 | 개체 종류·식별자 또는 종류 기본형, 실제 표시명, KAMIS/공통 품목 관계가 있으면 그 코드/검토 상태, 현재 상태와 표현 목적 |
| 후보 이미지 | 실제 자산 미리보기, 자산명·팩·표현 키, 후보별 이미지와 원본 확대 보기. 없는 이미지는 준비 중/미확보 표시 |
| 판단 근거 | 해당 사용 장면, 개별 정확 표현/범주 대체, 미검토·적합/부적합 사유, 원자료 확인 시점과 자산 판본 |
| 현재 대응 | DB에 등록된 후보인지 승인 선택인지, 개별/종류 기본 적용 범위, 대체/미연결·충돌 사유 |

첫 묶음은 D426/D431의 기존 8키 후보 범위에서 준비된 이미지부터 보여준다. 한 대상에 후보가 둘 이상이면 나란히 비교하고, 후보가 하나뿐이면 억지로 대안을 만들지 않는다. 감자 포장품·밭 표면·건물·실내 진열대처럼 다른 목적을 동일한 종류 기본형으로 합치지 않는다.

개발은 기존 관리 조회/API와 UI·미디어 컴포넌트를 먼저 재사용해 제한된 읽기 전용 비교 보기를 제공한다. DB 준비 중인 초기 비교는 현행 자산 목록/감사 입력을 사용할 수 있으나 반드시 `파일 근거/DB 미연결`을 표시한다. 이를 MySQL 조회 화면 완료로 보고하지 않는다. 후속 실제 DB 연결은 D431의 관계 조회 결과를 소비한다.

사용자는 대화에서도 대상/이미지/적용 범위를 보고 의견을 줄 수 있다. 최초 보기는 승인 버튼 구현을 기다리지 않되, 실제 승인 저장은 사용자 선택의 정확 대상·역할·자산/관계 판본을 기존 관리자 검토 경로에 결속한 뒤 수행한다. 그림을 열었다는 사실이나 ‘전체가 좋다’는 모호한 응답으로 모든 개체/용도에 자동 적용하지 않는다.

## 3. 이미지 확보 비용을 낮춘다

1. 기존 PNG/manifest·보고·공식 제공 미리보기부터 찾고 현재 자산 GUID/원본·meta fingerprint와 관계를 확인한다. 같고 근거가 충분하면 재촬영하지 않는다.
2. 여러 자산이 섞인 과거 Showcase는 배치 맥락 참고로 표시한다. 특정 Prefab만의 외형·현재 판본을 증명하지 못하면 개별 자산 미리보기로 쓰지 않는다.
3. 이미지가 없는 후보만 공간 담당이 정확 대상·출력 경로·사용조건·보호 기준과 Editor 단독 슬롯을 개발에 결속한 뒤 격리 미리보기를 만든다. 첫 범위는 기존 8키의 고유 자산, 기본 1장과 형태 판독에 필요한 보조 각도만이다.
4. 원본 Prefab/재질·canonical Scene·미소유 dirty를 저장/변경하지 않는다. 자산 외형을 위한 Preview는 실제 Game View나 업무 실행 성공과 구분한다. 새 공식 Scene/불필요한 Play·Builder 전체 재생성·패키지/모델 설치·AI 이미지 생성으로 대체하지 않는다.
5. 실제 장면에서만 판단할 수 있는 크기/지지·접근·통행·상호작용은 미검증으로 남겨 후속 배치 검사에서 확인한다. 이번에는 외형과 표시 목적의 검토 근거를 확보한다.

## 4. DB 자산과 이미지의 관계

이미지는 파일/기존 비공개 미디어 저장 경계에 두고 D431 목록에 이미지 식별/참조·파일 hash·증거 종류·대상 자산 식별/판본·촬영 또는 확인 시점의 관계를 연결한다. 실제 Prefab/텍스처 원본을 DB에 업로드하지 않으며 새 외부 호스팅·공개 게시를 하지 않는다.

이미지 종류는 개별 자산 미리보기, 여러 자산의 배치 참고, 실제 게임 화면, 공급자 참고를 구별한다. 이미지가 없어도 목록 등록은 가능하다. 파일이 없거나 연결이 잘못됐거나 자산 판본이 바뀌면 이미지 미확보/재검토로 표시하고, 예전 이미지를 현재 자산 승인 근거로 조용히 재사용하지 않는다.

이미지 제공은 기존 관리자 권한과 매체 접근 경계 안에서 수행한다. 클라이언트가 임의 서버 파일 경로를 지정해 읽게 하거나 원천 레코드의 주소·연락처/개인정보를 비교 화면에 노출하지 않는다. 지역 파일 링크와 localhost만 준비된 것을 다른 기기/모바일 수신 완료로 표현하지 않는다. 대화에 이미지를 반환할 때는 실제 확인한 원본을 직접 표시하고 수신 검증 범위를 나눈다.

## 5. 검증·소유·완료 기준

- 개발: 기존 D431 코드/목록/관계/조회에 이미지 근거를 추가 재사용하고 정확 비중첩 코드·테이블·뷰 경로를 선언한다. 실제 DB·API·읽기 비교/화면과 이미지 연결/고아 참조·접근·오래된 판본·미검토 비선택을 검증한다.
- 공간: 개발이 배분한 기존 이미지 대조와 필요한 소수 격리 촬영을 수행하고 manifest/hash·조건·원본 보존·미검증을 반환한다. 미리보기를 계기로 배치/가공을 재개하지 않는다.
- 기획: 이 원문과 DECISIONS만 작성하고 사용자와 외형/문맥을 검토한다. 공통 코드·DB·Editor를 직접 수정하지 않는다.
- 결과 보고 기본 경로: `docs/Reports/개체자산-이미지검토-D432-개발통합-2026-08-31.md`. 임시 근거는 담당 저장소의 `artifacts/local/validation/entity-asset-image-review-d432/` 아래이며 실제 소유/충돌을 착수 전에 확인한다.

첫 결과는 사용자가 볼 수 있는 정확 대상과 대표 이미지, 실제 연결된 데이터 출처, 미검토/후보/승인 상태를 함께 반환한다. 이미지 목록 준비·비교 화면·MySQL 연결·사용자 할당 결정·실제 Unity 배치를 구별하고 부분 결과를 전체 완료로 올리지 않는다. D431 데이터 작업은 독립적으로 계속하며 원천/권위·원본/Scene·E·r129/야간·commit/push·외부 공개는 이번 요청으로 재개하지 않는다.
