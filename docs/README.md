## 게임 개발 업무 순서

게임 개발과 리팩토링이 공통으로 보존할 기준은 [프로젝트 불변 개발 골격](Architecture/프로젝트불변개발골격.md)에 둔다. 파일·모듈·표현은 바꿀 수 있지만 권위·공통 Core·명령·시간·E/G/H·공간 성장·단일 공식 Scene·호환 경계를 바꾸려면 새 확정 결정과 호환 근거가 필요하다.

Simulation·Unity 게임 작업은 [플레이어 중심 게임 개발 업무 구조](Architecture/플레이어중심게임개발업무구조.md)에 따라 플레이어가 보는 상황·욕구·선택·재료·조립·결과·다음 선택을 먼저 닫고, [게임 개발 업무 순서 기준](Architecture/게임개발업무순서기준.md)에 따라 현재 목표와 차단점에서 시작한다. 의미 있는 새 작업은 [E9↔E1 반복 왕복 구현 체계](Architecture/E9하향식수직구현체계.md)로 E9 목표부터 E1 계약까지 영향을 검토하고, 가장 낮은 미완료 의존성을 구현한 뒤 E1부터 E9까지 조립·검증한다. 그 결과에서 새 영향이 나오면 같은 명세로 다시 내려가며 안정 상태 또는 명시적 차단까지 왕복한다. 새 작업은 [게임 개발 작업 단위 템플릿](ProjectOverview/templates/게임개발작업단위템플릿.md)에 플레이어 약속, 선택 폐루프, 재료·조립, WI·H, 권위 소유자, 목표 E, 포함·제외와 검증 범위를 기록한다.

과거의 [E9 리팩토링 모듈 골격](Architecture/E9리팩토링모듈골격.md) 경로는 기존 링크를 위한 호환 안내다. 모듈 이름·상태를 별도 기준으로 다시 확장하지 않는다.

작업 문서나 코드가 있다는 사실을 E 증거, 서버 실행, Play Mode·Game View 또는 운영 완료로 대신하지 않는다. 각 증거는 확인한 수준 그대로 구분한다.

시간 기반 기능은 [WorldTick과 실시간 실행 경계](Architecture/WorldTick과실시간실행경계.md)를 따른다. Unity 프레임 표현, Nature 권위 실시간 시계, 큰 세계 시간인 WorldTick, 전투 BattleTick과 모든 권위 변경의 판본인 WorldRevision을 서로 대신하지 않는다.

## 문서 유형

### 기준 문서

현재 판단의 단일 기준이다. 동일한 정책이나 로드맵을 설명하는 새 문서를 만들기 전에 기존 기준 문서에 절을 추가한다.

### 제안서와 구현 계획

아직 확정되지 않은 선택지, 단계별 구현안과 검증 계획을 기록한다. 문서 첫부분에 어떤 기준 문서를 따르는지와 무엇을 결정하지 않는지를 적는다.

### 변경 기록과 페이지 증빙

특정 시점에 무엇이 바뀌었고 무엇을 검증했는지 남기는 기록이다. 현재 코드와 달라질 수 있으므로 삭제하거나 기준 문서에 합치지 않는다. 현재 상태를 판단할 때는 실제 route, contract, test와 기준 문서를 함께 확인한다.

## 새 문서 작성 기준

1. 먼저 이 문서와 대상 폴더의 `README.md`에서 같은 책임의 기준 문서를 찾는다.
2. 기존 기준을 보완할 수 있으면 새 문서를 만들지 않고 해당 절을 갱신한다.
3. 별도 제안서가 필요하면 기준 문서와의 책임 차이, 확정되지 않은 범위와 종료 조건을 명시한다.
4. 파일을 대체할 때는 기존 경로를 바로 삭제하지 않고 짧은 호환 안내를 남긴다.
5. 변경 기록과 페이지별 캡처 증빙은 중복처럼 보여도 이력 추적을 위해 보존한다.
6. 문서 링크와 `git diff --check`를 검증하고, 코드 상태를 문서만으로 완료했다고 표현하지 않는다.
